游戏玩法与链路拆解

定义性概念：

本游戏属于roguelike游戏。不同于传统的roguelike游戏，本游戏在路线上的抉择体现在地图上的岔路选择。（F01）
传统肉鸽游戏案例：以撒的结合、杀戮尖塔、元气骑士

本游戏的路线选择在于时间上的抉择。
地图允许在未锁定区域自由探索，玩家可以通过交互发现大量事件，这些事件都有预设的*入口开放窗口期*和*持续时间*，这要求玩家像在传统肉鸽当中抉择路线一样抉择事件日程表(F02)

传统：完成一个房间的探索→抉择下一个房间选哪个→完成下一个房间的探索，存在一些固定的不容抉择的特殊房间，如boss房，剧情房

本游戏：在一个时间段内完成一个事件→抉择下一个事件触发哪个（通过不同的条件，如时间地点前置事件）→经历完下一个事件，存在一些固定的不容抉择的特殊事件，会在达到特定要求后强制触发boss事件和剧情事件(F03)
不同事件的前置条件各不相同，严格程度也不同。在设计时，事件的触发条件需要预留充分的可扩展空间，以根据剧情要求在游戏制作过程中来安自由组合触发条件（F04）
玩家一般通过在地图上的行为来触发事件，此处也应当预留可扩展空间，触发方式包括但不限于：进入区域，特定对话选项等。在进入那些会推进时间段的事件之前，玩家会收到直接的ui提示，来避免误触发（F04）


每一场游戏都是一条不同的“if世界线”，只有依据引导通过最终事件之后才能进入下一个大关。if世界线是游戏社区讨论的常用语，指的是与主线剧情不同，但是在特定条件变化时可能会发生的剧情走向。（F05）
每场游戏的随机种子会影响玩家决策，玩家的决策直接影响一局游戏当中触发的剧情事件的内容。在玩家视角来看，每一场游戏都讲了一个走向有所差异的故事。（F05）
“引导”所包含的内容极其多样，包括但不限于对话中的暗示，线索树当中的提示等。这里的引导更倾向于对玩家在文字和视觉层面的提示，而非需要解锁的游戏机制（F05）

最终事件和关底事件含义相同（F06）

在完成一个大关的内容（无论失败还是成功，是真结局还是差结局）都算一局游戏结束。如果是首次通过本大关的真结局，那么下一大关将会解锁。单局通关时长预期不在本文档的考虑范围内。有关大关之间的关卡切换，详见线索树的部分（F06）
目前提及的内容当中，只有线索树和线索树中解锁的东西是局外资源（F06）



游戏内的机制：

游戏以不断通过关底事件和在if当中收集各种线索和信息来补全世界观故事线为两大目标。
这两个目标互不冲突，不断通过关底事件，也就是将一局游戏通关，能够帮助解锁更多的线索和信息，让线索树更加完整。（F07）
而线索和信息收集的越多，也越能帮助玩家更轻松地通过关底事件，甚至是触发隐藏的，与默认关底事件不同的隐藏关底事件。“将线索和信息收集齐全”不是通关的强制要求，只是游戏当中鼓励玩家去探索的内容。（F07）

关于游戏目标的设定背景：
游戏中的主角在一个*不向玩家具体交代*的剧情位置遇到了困难，然后受到了某种高位存在的帮助。高位存在提出让主角无限制地重新体验经历自己的冒险生涯，发掘曾经在冒险过程当中被忽略的，或者因不可抗力错过的细节和真相。作为辅助，高位存在还提供了“线索树”这一工具来帮助主角在诸多可能性当中梳理信息。（F09）

剧情性的世界观背景暂时不关注，本文档的目的主要是为游戏玩法开发服务（F09）

运营：

模拟经营与解谜
这里的解谜主要指的是通过剧情当中已有的视觉和文字引导，推断出做好那些前置条件准备可能会触发一个曾经没触发过的事件，也可以包含事件内的谜题（机关、对话推理）（F08）
主角的身份类似赏金猎人与商人的结合，非战力相关的运营资源主要为：钱、货和委托
钱，货和委托的关系见下：（F10）
根据事件提示在货物买卖中盈利，在事件当中接取委托赢取报酬。获得的金钱用于达成一些前置条件或直接转变为战斗力（见战斗机制部分）探索新的事件。
达成前置条件 / 转变战斗力 / 探索新事件互为并列关系（F12）

事件提示主要指的是玩家在事件当中获取到的信息，来源广泛，通常定义为对游戏内置数据的间接描述，比如某物的行情，有特殊事件会发生的事件地点等。（F11）

货物：（F10）
来源（买入、事件掉落、委托报酬、制造）与去向（卖出、交付、消耗）
委托：（F10）
随机的事件，完成条件，结算评价标准，奖励内容（钱、货还是下一个事件）都各不相同

对于一个游历世界的商人来说，背包和仓库中的空间资源是模拟经营的管理核心，信息差也十分重要
背包的机制上打算设计丰富的拓展。底层上，计划采取“类塔科夫”的背包管理系统，具象化物品的尺寸和携带难易度，同时引入诸如“打捆”“包扎”“装瓶”等物品收纳管理方式
但是在初步研发阶段，背包暂时采取原始的“一格一物”策略，并留好接口，后续再拓展开发（F13）
值得注意的是，金钱也将作为物品中的一种，而不是一个单独的数字，就算是存入银行，也有储值卡、支票等物品需要管理（F13）
（这部分有关背包机制的拓展需要和策划进一步研判，是否让游戏机制过于冗杂了）


战斗：

半回合制战棋
（详细见附加内容）（F14）

主控虽然是单个角色，但是也会有战斗小队的配置。即探索和剧情部分单主控，战斗部分多主控。（F09）

战斗是半数以上事件的直接内容。这个半数以上是游戏设计预期（F16）

不是所有战斗都以全面获胜为目标，战斗的结果和结束方式就是这场事件的直接结果
举例：
存在显式目标，如全歼敌方，击败精英目标，破坏指定道具等。也存在隐藏目标，在全歼战斗中如果全歼除了敌方头目目标以外的目标，也会触发对方头目的投降获胜，相比全歼获胜能获取更多情报（战斗前玩家可以通过其他事件了解到本次战斗的敌方头目有胆小的特性，此例展示了更多的情报收集和支线探索行为能降低战斗难度，且能得到额外奖励）
战斗失败也是战斗结果之一，与战斗成功之间的战利品、信息等差异都是失败惩罚的一部分。当然也可能存在死亡结局，本场游戏直接结束。（F17）

战斗力的生成抛弃掉传统的等级提升和数值增加
道具（药剂等），工具（武器等）乃至信息差（敌方弱点和行动规律等）都会增加玩家在战斗中的强度。这些要素也更加和运营部分的内容相辅相成，不单独成体系（F09）

流程简述：

玩家操控主控角色，在传统的rpg瓦片地图当中探索（预期做成无缝的2d大世界地图，采用预加载等技术）

在世界当中探索，以一些引导和提示，或者一些强制性开场事件为引子，引出一系列后续事件。包括简单生成的可重复性资源获取事件和推进性的特殊事件。事件之间在时间上会有冲突，玩家需要决策本场游戏当中走哪条故事线，并在过程当中运营发育，通过关底事件

除非触发事件，否则游戏当前所处的游戏时间段不会推进，只有在与事件交互并确认进入事件后事件才会推进

线索树：

在局外全局记录玩家在游戏当中解锁的全部内容的系统。相当于gallary，但是会标注各个物品，事件，任务等节点之间的关系和解锁条件，将故事和关系串联成树或者图标，便于玩家一目了然地回顾主线剧情和支线剧情的关系，人物之间的关系和来往经历，以及在不同位置解锁的同一节点的不同情报。

线索树中还会标记提醒，某些节点后续还有可连接节点，提示玩家进一步探索，已完成的哪些节点导向了后续内容，构成剧情解谜的一部分。是重要的局外引导系统

附加内容（战斗机制）（F14、F15）：
1. 局外技能配置
你可以携带：

4个基础技能，必须分别属于 A、B、C、D 四类，每类恰好一个。
👉 可以替换同类技能，但不能改变类别结构。

5个连携技能，类别不限，自由选择。

连携技能的效果会受到对应基础技能类别的影响（例如：连携里含 A，则基础技能 A 的部分效果会生效）。

2. 局内：行动槽（上限10）
战斗中，每次行动都会在行动槽末尾添加字母：

使用 A类基础技能 → 加 A

使用 B类基础技能 → 加 B

以此类推

使用 移动 → 加 M

3. 连携技能的释放条件
每个连携技能包含：

COST：一串字母（如 ABA）

PRODUCE：一串字母（如 C）

只有当行动槽末尾的字母序列与 COST 完全一致时，才能释放该连携技能。
释放后，会从槽尾删掉 COST，并在末尾加上 PRODUCE。

举例：
行动槽 = A B A，末尾正好是 ABA，可释放 COST=ABA 的连携。
释放后 → 删掉 ABA → 槽变空 → 加上 PRODUCE（如 C） → 新行动槽 = C。

4. 移动的打断规则
移动会添加 M 到槽尾。

如果槽内已经有 M，再执行任何行动（包括再次移动），都会清空 M 及其之前的所有字母，连招中断。

举例：
槽 = A B M。
再放一个基础技能（加 C）→ M 及之前的 A B 被清 → 槽最终 = C。

半回合制：
所有角色（敌我双方）的行动顺序由一个时间轴决定。
当时间轴推进到某个角色标记的时候，这个角色开始行动。
角色行动结束之后，根据行动的内容和一些属性补正，决定行动条被移动到什么位置（也就是下一次行动的时机）

战斗会在大世界原地展开，常规情况下，我方主控单位有2-4个，敌人数量视强度而定（这部分是数值策划应当负责的），视情况可能存在非主控的右方单位和场地道具等


零散问题解答：
F21：
同一时间段内的事件可能互斥，这由事件的入口窗口期大小和事件的持续时间决定。有可能进入A事件之后就会错过B的进入窗口，有可能结束A之后还来得及在B事件的窗口结束前进入B事件
整体上，只有一个故事主线，但是有许多支线。整体上故事线的互斥程度可以很自由地安排，能做到来回穿梭于多个支线事件之间来同时完成两条支线
运营发育时基于事件来进行的，两者不互斥。就像传统肉鸽游戏也要在不同房间当中发育，而不是什么探索房间与发育成长互斥
F22
时间的代价来自事件之间本身的冲突。就像以撒的结合进入曾去过的房间一般不需要任何代价，本游戏当中玩家在没有经历事件时可以在未锁定区域自由探索来决策下一个时间段触发哪个事件。
在没有进入事件的时候，玩家无法通过挂机和游荡队游戏进度进行任何实质性的推进
F23
线索树系统会收集记录玩家在局内的行为，然后在游戏结算的时候一并解锁线索树中的内容。也就是说，玩家只有不在游戏中的时候才能在线索树中查看到新的信息，不能一边游戏一边通过线索树获取新的信息。
线索树的提示通常类似于：“这个事件没有结束，还有后续或分支”并不会直接提示后续的内容和解锁条件。如果玩家在游戏内获取到了必要的提示，但是自己没有注意到或者跳过了剧情，作为辅助系统，线索树会记录这些提示
F24
线索树之所以被我称为树，是因为其基于主线剧情绘制，也就是树的主干，并非数学意义定义的树图。但是因为有角色，事件，物品等诸多元素存在，势必会出现网状的结构。
线索树只是一个暂时的代称，其在游戏中的命名还需再依据世界观背景等因素定夺
节点的完整类型清单还需再后续持续讨论补全
单个节点可以展开为一个类似维基百科页面的结构，可以详实记录各类信息
