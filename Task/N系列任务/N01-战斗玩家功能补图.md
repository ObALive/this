# 任务背景

用户已在 `Tool/项目网络图/` 中绘制战斗系统的增量构建图，准备先完整构建一个“启动就玩”的战斗系统，其他系统及其与战斗系统的交互暂不实现。现有图覆盖了瓦片地图、角色移动、属性、技能、行动槽、时间轴和敌人行动等内容，但部分条目只写了名称或占位说明，需要从玩家实际能够经历的战斗过程出发，检查设计文档中的功能是否都有可验收的落点。

本任务参考系统设计文档，识别玩家功能的遗漏与不完整落点，并按原图的表达方式拆成最小验收单位补入一份新图。技术选型与技术依赖的专项补全由另一份独立任务书 N02 承接；本任务直接依据原图与系统设计文档作出判断。

# 核心指导理念

## 一、以完整的战斗内体验确定范围

“启动就玩”指直接以预置战场、参战单位和战斗配置进入可操作的战斗，完成战斗内规则与交互，形成可观察的战斗结果及适用的战斗内收尾。完整性以系统设计文档中属于本阶段的战斗功能为准，最小验收单位只是拆分粒度，不意味着把目标缩成移动、攻击与扣血的演示。

功能边界按实际职责判断，不单凭目录或架构模块名称判断。装备、遗物、物品、容器和角色数据涉及战斗内行为时，保留战斗内必要的效果、操作和状态变化；其来源可由固定战斗配置或战斗局部数据提供。战斗外获取、交易、招募、地图探索、事件流转、世界时间结算、局生成、局末结算和元进度写入等外部流程列为本阶段范围外。

对混合了战斗规则与外部联动的条款，分别说明本阶段承接的战斗部分与延期部分。例如撤退条件及战斗退出判定属于战斗内功能，撤退后的地图事件锁定与窗口期调整属于外部联动。固定输入用于隔离外部系统，不能用来跳过玩家应当操作的战斗内行为，也不能改变正式游戏规则。

## 二、以玩家行为与可观察结果判定落点

玩家功能包括可执行的操作、需要理解的规则，以及用于判断和决策的信息与反馈。落点判断须读条目完整正文、依赖、对象说明和备注；同名节点、技术对象声明或宽泛的“制作某系统”不能自动视为已经覆盖。

最小验收单位应能在已具备前置能力的条件下单独判断通过或失败。条目应写清触发条件或玩家操作、发生的行为及可观察结果；适用时包含取消、拒绝与失败反馈。一个条目存在可以分别验收的多种行为时应拆分；只服务于同一行为的内部步骤保留在该条目说明中。

## 三、沿用设计结论与原图表达

沿用现行系统设计文档的规则、术语和原图的增量构建风格。对原图与设计文档不一致的内容，记录差异与依据；明确属于中间构建阶段的简化，应在后续条目中补齐正式规则。存在上游冲突、未决条件或必须由用户决定的游戏设计时，明确标记，已有资料能够确定的部分继续完成。

本任务不创造新的玩法、数值平衡、目标条件或界面键位。必要的验收示例使用已有配置；临时测试输入须标明用途。建议与未决项同已确定功能区分，不能作为已完成覆盖计算。

# 工作方向指导

## 一、建立玩家功能与原图落点的对照

从系统设计库的战斗域索引进入，覆盖战斗域各系统及相关配置表，并按战斗体验追查必要的通用规则。核对范围包括战斗进入与布置、行动与空间规则、技能与效果、单位状态、行动槽与连携、战斗内装备与物品行为、敌方行动及读招破招、信息呈现、目标与结束处理等。该范围用于指导查漏，具体功能由现行设计文档确定。

交付功能覆盖对照，能够追溯到设计依据和原图条目，区分已有完整落点、已有但不完整、没有落点、本阶段范围外及上游未决。已写名称但缺少行为说明的条目应按实际内容判定。对范围外条款写明延期理由及其战斗内部分是否已承接。

## 二、在新图补齐最小验收单位

沿用原图的路线、编号条目、概要、正文、依赖和对象说明格式，优先完善或拆分不完整落点，缺失功能再新增条目或必要路线。保留原图有效内容和已有技术说明，避免重复声明同一功能。新条目的玩家目标与验收结果应能直接从图中读取，详细溯源与变更对照放在本任务输出文档中。

为使新增功能在图中可构建，可以补充其必要的直接前置引用，并处理拆分引起的引用变化。技术选型、程序集和完整技术依赖审计不属于本任务。沿用同路线自动形成的递进依赖时，应确认排列符合实际构建顺序。

## 三、授权范围与完成判据

本任务授权在 `Output/N01-战斗玩家功能补图/` 中保存原图备份、创建并编辑新图、生成分析与核验产物，并按规范编写本任务报告。原图数据库、工具代码、系统设计文档、架构设计文档、代码设计案及其他任务成果均为只读资料。本任务交付网络图设计，不实现 Unity 战斗程序。

成果满足以下状态后，才可判定补图完成：

- 范围内的已确定玩家功能均有具体、可验收的图上落点；对照文档能够说明遗漏检查的覆盖范围。
- 原图的不完整落点已明确处理，新增和拆分条目符合最小验收单位判据，功能来源、原落点与新落点可追溯。
- 战斗内功能与外部联动的边界明确，没有借补图引入其他完整系统，也没有因依赖其他系统而漏掉战斗内功能。
- 原图备份可恢复，新图可由现有工具独立打开，导出内容与新图一致；没有未解析依赖、依赖环或误指向的引用。
- 未决与冲突如实列出。影响范围内必要功能落点或验收的事项尚未解决时，交付已完成部分并说明阻塞，不宣称完整覆盖已达成。

## 二、原图备份与独立交付

本任务与 N02 必须以同一版本的用户原图为基线，各自在自己的输出目录保存一份一致性备份，先完成备份，再从该备份创建新的编辑库。基线版本、取样时点和模型校验信息在报告中登记；两项任务基线模型应一致。执行期间原图发生变化时，先核实基线，不能悄悄改用另一版本。

本任务不读取或采用 N02 的分析、补图、技术决策或其他产物，完成与否不以 N02 执行完成为前提。编号 N01、N02 只用于区分任务，不表示前后依赖。

原图备份保持不变，新图有独立文件与标题。可利用现有工具的 `PN_DB` 配置打开本任务新库，写入走工具支持的模型操作，不直接改数据库行。不得在默认原图库上执行导入、重置或替换。具体备份和编辑方式由执行者选择，需保证备份一致、原图未被本任务修改。

交付物包括原图备份、新图 SQLite 库及 Markdown 导出、功能覆盖与变更对照、未决事项和核验结果。均保存于本任务输出目录，并在报告中给出文件位置及直接打开新图的入口或启动命令；导出操作也须将成果放在本任务目录。滚动快照不替代用户要求的原图备份，Markdown 不替代可继续编辑的图。
