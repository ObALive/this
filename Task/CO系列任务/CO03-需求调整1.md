## 一、任务目标

参照 Git 提交 `aabc375cb04d8027d60ff6737f21dcaddc4ba043` 以来上游设计案（架构设计案、系统设计案）的变更，对现有代码设计案进行调整，确保其与最新的上游设计保持一致。

本次调整的核心变化是**项目选用 Unity 引擎，并要求使用 C# 实现游戏功能**。应充分利用 Unity 提供的对象模型、生命周期、资源管理及其他原生能力，废弃原有代码设计中不再必要的重复造轮子方案。

## 二、执行步骤

1. **宏观审查**：结合上游设计变更与 Unity 技术选型，审查现有代码设计案的整体文档结构、设计思路和依赖关系，判断是否需要调整整体结构或推翻重做，并说明判断依据。
2. **逐项调整**：在宏观审查的基础上，逐份检查并修改代码设计文档，落实上游设计变更，合理采用 Unity 原生能力，明确必要的自建功能及其理由。
3. **完整性检查**：检查调整后的文档之间是否存在职责冲突、依赖错误、设计遗漏或与上游设计不一致的问题。

## 三、执行约束

- 任务执行标准、系统设计稿的设计边界与编写要求，以 `Rules` 目录中的规则为准。
- **仅有权修改代码设计文档**，不得擅自修改架构设计案、系统设计案及其他非授权文件。
- 严格遵守各层级文档的职责边界，不得越界设计或擅自改变上游已确定的需求与架构约束。
- 不要机械保留旧设计，也不要为了使用 Unity 而盲目引入其功能。应根据实际需求判断哪些设计需要保留、调整或废弃。
- 所有修改均应有明确依据，最终代码设计案应能指导后续功能需求拆分与代码实现。
