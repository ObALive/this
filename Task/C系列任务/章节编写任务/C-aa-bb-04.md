## 一、任务背景与目标

现行设计稿中存在“技能的效果一律以元效果表达”“技能提供的伤害、状态与增益统一以元效果的形式表达”“任何系统产生效果时都使用本模型”等表述。这些句子将一般意义的行为结果与特定的元效果概念混用，可能使执行者误将即时伤害、移动、物品操作等一次性行为全部接入元效果系统。元效果表中的一次性投掷条目及相关生命周期描述也需要按同一边界核查。

本任务将用户已定的元效果职责落实到设计稿，纠正定义、引用、表格和架构约束中的泛化表述，使下游能够区分行为的一次性执行、元效果的施加，以及元效果存续期间的作用。任务目标是完成必要的原稿修订和一致性核验，不停留在问题清单或修改建议。

## 二、核心指导理念

### 1. 元效果的职责定义

**元效果是用于表达和管理持续性规则影响的统一模型。此类影响在其生效条件成立的存续期间保持作用，持续参与相关规则的计算、判定或触发结算；其作用受自身的生效条件、来源、叠加规则及终止条件约束。元效果系统负责这类影响的施加、生效管理、叠加求值与移除。**

Buff、Debuff、光环是这一职责的典型实例，用于帮助执行者理解本任务；正式设计正文应归纳其共同语义，不以举例代替定义。

“持续”描述的是规则影响的存续，不要求逐帧计算，也不要求固定倒计时。来源存在期间保持作用、在有关规则事件发生时参与结算，均应按已有设计判断是否属于持续性影响。具体期限、触发频率、范围更新和叠加算法沿用各效果的已定规则，本任务不补造这些玩法。

### 2. 一次性执行与持续影响的边界

行为的一次性执行由该行为及其能力组件承担；持续性影响的存续与生效管理由元效果承担。一次移动完成坐标改变、一次攻击结算即时伤害，都是行为执行结果。坐标或生命值的改变长期保留，并不使该次执行成为持续生效的元效果。动作具有动画、执行时长或后摇，也不足以判定它属于元效果。

同一行为可以同时产生一次性结果并施加持续性影响，应分别说明两部分的职责。元效果在存续期间触发伤害、位移或其他一次性结算时，持续影响的管理与具体结算能力仍应保持可辨认的边界；不得因结算结果是即时的就排除其持续来源，也不得反过来把全部即时结果都归为元效果。

“效果”“技能效果”“法术效果”“投掷效果”“继承效果”等名称本身不构成元效果归属依据。以实际规则是否存在持续生效的影响为判断标准，避免把所有技能执行结果统一称为元效果。

### 3. 行为生命周期与元效果生命周期的边界

元技能统一管理角色行为的触发、执行、生效、完成及终止交接；时间轴负责行动机会和行动后的调度；元效果管理持续性影响自身的生效与终止。行为施加元效果后，二者分别按已定规则推进各自的生命周期。具体效果与来源或行为结束的关联条件，应由已有规则说明。

统一元效果模型与统一效果服务的约束，适用于上述持续性影响的表达和管理。架构不得据此要求所有行为结果都必须通过元效果服务，也不得将“持续生效”解释为必须新建一套覆盖全部动作的通用执行机制。

## 三、授权范围与工作方向

本任务授权在执行工作区内修订以下设计库中与本次语义纠正直接相关的内容：

| 对象 | 应达到的结果 |
| --- | --- |
| `系统设计文档/` | 元效果主稿建立准确的权威定义；元技能、技能、物品、装备、遗物、投掷及其他实际引用方按持续性影响的边界表述职责与关系 |
| 相关扩展配置表 | 条目名称、作用方式、生命周期和归属与正文一致；泛化条目中的一次性行为内容有明确的职责承接 |
| `架构设计文档/` | 元效果服务的能力、统一入口约束、调用关系及生命周期边界与系统稿一致，保留已有正确的模块职责和数据所有权 |
| `Code_Design/` | 核对并纠正直接承接错误语义的职责说明、需求映射和上游摘录；保留有效技术约定，区分文字可消歧义与需要另行技术重设计的事项 |
| 受影响的术语、索引及库级台账 | 权威定义、概括和引用一致，读者能够追溯到正确来源 |

范围按相关语义及其实际引用链确定，不以文件数量限制必要修订，也不扩展为全库措辞清理。允许为本次职责纠正调整相关段落、表格条目及引用，并将误归到元效果中的既有规则内容归纳到其实际负责的系统中，保留其有效玩法含义与引用关系。

涉及投掷、继承效果等混合内容时，根据实际作用拆清边界，不能只删条目、删引用或改标题而丢失原有规则。名称相同或同处一个条目，不代表全部内容属于同一职责。既有规则无法确定承接方或需要新增技术方案时，登记具体缺口及影响，继续处理可以依据本任务确定的部分。

本任务仅授权设计稿语义纠正及必要的一致性同步。`Rules/`、`Input/`、既有其他任务的过程记录及 `Tool/` 均只读；不修改项目网络数据库、实际代码、Unity 场景或运行期资产，不启动设计工具服务。不得借机新增效果种类、修改数值或伤害结算规则、设计完整光环机制、重划无关模块或展开新的代码实现方案。

## 五、交付成果与完成判据

交付物包括修订后的原设计稿、相关表格及必要台账，以及按执行规范生成的本任务报告与必要过程记录。报告需能追溯主要歧义、采用结论、修改位置、既有规则的承接位置和未决影响；不再另写一套平行设计。

完成应满足以下可检查状态：

1. 元效果的权威定义及各层引用均明确以持续性规则影响为职责范围；统一入口约束具有同一适用边界。
2. 读者能判断普通移动由移动行为完成、即时伤害由相应结算能力完成，均不因属于技能结果而被强制包装为元效果。
3. 读者能判断持续属性修正、持续伤害来源及光环类持续影响属于元效果职责；持续期间参与事件结算的影响不会因并非逐帧执行而被排除。
4. 一项行为同时具有即时结果和持续影响时，两者的执行、施加与后续生效职责清楚；行为生命周期、效果生命周期及时间轴调度各有准确归属。
5. 元效果表、技能与法术描述、投掷及继承效果的相关条目与正文一致；移出某一职责的既有规则具有明确承接，引用与标识不会悬空或误指。
6. 已修改内容通过上下文语义复核，术语、引用与相关索引一致，未引入无依据的新规则、设计沿革或跨层越界内容。
7. 报告区分已完成修订、已完成核验和仍受未决问题影响的部分。存在影响上述判据的未决项时，如实交付部分完成状态，不以检索无命中或文件已保存代替语义验收。
