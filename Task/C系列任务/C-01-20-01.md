# 对话
这是最基础的信息传递方式
采取文字冒险游戏式的对话框来记录对话内容。
使用json配置文件来配置对话状态分支图。要求在设计的时候约定一套相匹配的解析代码和对应的配置文件格式
对对话分支图的解释：在对话的过程当中，有一些需要玩家参与选择的对话选项，这些选项会影响对话的结果和一些文本上的差分。由结构化的对话分支图来保存“下一句话是什么”“不同的回答会发生什么”等问题。同理，玩家当前所处的游戏进度也会影响对话的分支走向，包括但不限于身上携带的物品，健康状态等游戏数值。需要预留高扩展性的接口。
对话过程当中包含的UI要素：
1. 大的文本框格，像其他文字冒险类游戏一样，参考案例很多，不过多描述。单击文本框内任意位置以继续播放。
在文本展示上，会引入富文本。即文字效果，包括但不限于彩色，粗体，斜字，抖动，打字机式的文字逐个出现等。在富文本播放完毕之前再次单击不会播放下一段文本，而是立刻结束富文本动画，显示这一段文本全部内容。
目前先不做这富文本部分的扩展开发，先预留实现接口。
2. 对话主主体的称呼和头像展示：都包括在文本框格当中，直观展示对话主体。可能会有旁白内容的情况，所以要处理好头像位置留空的准备。
3. 快进按钮。
剧情文本分为两类：阅读过的文本和没有阅读过的文本。评判标准为全局范围，即在过去的游戏场次中也都没遇到过的文本才能算没阅读过的文本。
点击后：如果在显示阅读过的文本的时候点击，跳过对话内容到下一个需要手动选择选项的对话分支或者下一段在全局没有阅读过的文本。
如果在显示没有阅读过的文本的时候点击，跳过对话到下一个需要手动选择选项的对话。
在设置页面可以手动选择是否跳过没有遇到过的文本，默认不跳过。若设置跳过，则所有文本都按照阅读过的文本来处理（但是还是要记录文本的阅读状态，方便玩家后续将设置回调）
所有情况下，被跳过的未阅读过的文本都不会被标记为已阅读的文本。在显示未阅读过的文本的时候点击跳过，这一段文本也不会被标记为已阅读。（即：在文本展示结束，进入下一段文本或者整段对话结束的时候（点击跳过按钮不算在内），文本的阅读状态才会被设置）
文本的阅读状态不受线索树剪枝的影响，是由文本库单独保存的状态。
4. 自动按钮（倍速）
自动播放对话，每一段对话的播放时间取决于文本量。可以通过多次点击按钮来调整播放速度。如：不自动-点击-一倍速播放-点击-二倍速播放-点击-不自动，如此循环。在播放到需要手动选择分支的位置时暂停，分支选择完毕之后继续自动播放。
5. 回顾按钮
回顾对话内容。点击后显示这轮对话当中播放过的所有文本，支持滚轮浏览。和对话框一样，显示对话内容，说话主体的名称，头像。不能显示还未播放的文本
6. 简洁模式按钮
开启后关闭富文本效果，新一段文本出现时会立刻全部展现而不是随动画效果出现。但是保留彩色文字和字体等效果。同样先不做这一部分的扩展开发，在富文本开发完毕之后再考虑
