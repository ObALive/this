## 1. 分析范围与判断标准

本次直接分析以下内容：物品共通规则、金钱与货物、交易与市场、背包、仓库、银行、委托中的经济闭环、装备和遗物的持有与交易规则。情报系统仅分析行情信息接口，战斗系统仅分析物品进入战斗与离开战斗时的库存接口。情报解谜内容、装备战斗属性、遗物具体效果、数值曲线与代码实现分别由其归属阶段继续设计。

缺口等级按交接影响划分：

| 等级 | 含义 |
| --- | --- |
| B0 | 当前核心闭环无法完整推演，或者会改变物品所有权、资源结算、系统边界。关闭前相关系统不能作为架构设计基线 |
| B1 | 局部系统或内容无法定稿。不受影响的系统可以继续编写 |
| B2 | 远期扩展或低风险细节。当前版本可以在明确边界后延期 |

## 2. 已有材料已经确定的规则

以下结论已有正式来源，本次不重复提问：

1. 钱是物品，运营与战斗共享同一套资源。金钱用于满足前置条件、转化战力和探索事件，三种用途由玩家自由分配。
2. 货物的来源包括买入、事件掉落和委托报酬；去向包括卖出、交付和消耗。制造系统已经正式删除。
3. 行情由本局种子参与生成，并且需要具备局内动态变化。具体驱动与更新规则尚未确定。
4. 贸易与委托通过事件展开。探索区域不存在独立于事件的常驻商店节点和任务节点。
5. 同一时间只有一个事件处于进行中。玩家数据通常在事件内实时更新，场景局内数据通常在事件结束后更新，全局数据在局末更新。
6. 初期背包采用一格一物方向，远期扩展物品尺寸、重量和收纳玩法。物品已经预留体积与重量属性，当前阶段不启用相关限制。
7. 装备提供属性，部分装备提供储物空间。遗物提供特殊效果，通常只影响携带角色，同时也是高价值货物。
8. 战斗内使用库存物品需要通过技能调用。战斗内打开完整背包的方案已被识别为操作负担，但随身绑定方案仍是建议而非定案。
9. 线索树是唯一跨局保留的资源。钱、货、装备、遗物与仓库内容均属于单局资源并随本局结束重置。
10. B01 提出的现金单形态起步、银行自动收纳、委托模板化、事件间换装、确定性装备获取等内容均为顾问建议，尚未形成正式设计决策。

## 3. A. 覆盖检查表

| 系统或场景 | 已有规则 | 缺失项 | 适用性 |
| --- | --- | --- | --- |
| 物品共通模型 | 钱、货、装备、遗物和消耗品都可进入同一资源循环；遗物同时是货物；库存物品可以被战斗技能调用 | 分类是否互斥、同一物品可具备哪些用途、物品的持有状态与生命周期、唯一性与堆叠语义 | 适用，是所有运营系统的共同前提 |
| 正常获得物品 | 来源包括买入、事件掉落和委托报酬 | 获得时进入哪个容器、何时取得所有权、满背包时如何处理、奖励能否暂存 | 适用 |
| 正常消耗与转移 | 去向包括卖出、交付和消耗；战斗技能可以调用库存 | 丢弃、投掷、装备、交付、出售、存入和取出之间的状态迁移；操作取消后的状态 | 适用 |
| 金钱形态 | 创意稿要求现金、储值卡和支票均为占空间的物品 | 首版实际启用哪些形态；面额、找零、拆分、合并、支付顺序和兑现规则 | 适用，存在创意基线与后续建议尚未裁定的问题 |
| 购买 | 贸易通过事件展开，金钱与货物共享背包空间 | 商人库存、报价、购买数量、付款来源、背包空间不足、确认与取消、购买后的行情变化 | 适用 |
| 出售 | 货物、装备和遗物均可进入出售决策 | 商人的收购范围、需求量、资金或收购上限、已装备和受任务约束物品能否出售、出售撤销与回购 | 适用 |
| 条件不足 | 金钱与物资可以作为事件前置条件 | 金钱不足、物资不足、空间不足、商人不收购时的反馈与状态保持规则 | 适用 |
| 交易取消和重复操作 | 玩家可以拒绝进入一般事件；同一时间只有一个事件进行 | 进入贸易事件后能否取消单笔交易、退出事件的结算点、重复确认是否重复扣款、报价变化时如何处理 | 适用 |
| 同时事件 | 同一时间只有一个事件处于进行中 | 事件级并发已经排除；同一贸易界面中的连续交易与行情更新顺序仍需定义 | 事件并发不适用，连续结算适用 |
| 市场生成 | 种子影响本局行情；局生成系统负责行情生成流程 | 市场按全局、区域、商人还是事件划分；货品池、供需与初始价格的关系 | 适用 |
| 市场动态 | 行情需要局内动态，事件结束是场景数据的常规刷新节点 | 时间、事件结果和玩家交易分别是否驱动行情；变化范围、刷新时点与报价稳定期 | 适用 |
| 行情信息 | 玩家通过事件取得行情信息并据此规划交易和日程 | 当前价格、趋势与未来信息的揭示范围；情报有效期、可信度与过期表现 | 适用 |
| 背包基础规则 | 初期一格一物；存在整格、单个和一半三种取物粒度需求 | 一格一物与多数量操作的统一含义、堆叠条件、拆分合并、容量计算和自动整理 | 适用，现有表述尚未闭合 |
| 背包满载 | 空间是经营核心 | 拾取、购买、奖励、卸下装备和取款时的统一溢出规则；退出界面前未处理物品的归属 | 适用 |
| 仓库 | 仓库提供单局内的长期存放，仓库内容随局重置 | 仓库按地点独立还是共享、容量、开放条件、存取是否通过事件、存取的时间成本与满背包处理 | 适用 |
| 银行 | 创意稿提出存取与兑现环节 | 银行首版是否启用、账户余额是否占空间、现金与票据的转换规则、自动收纳建议是否采用 | 适用，取决于货币形态决策 |
| 装备持有与换装 | 装备提供属性并可能提供储物空间；角色装备格存在差异方向 | 装备槽体系、换装时点、装备状态是否计入携带空间、已装备物品的交易和交付限制 | 适用 |
| 储物装备 | 储物能力与战斗属性形成取舍；载具也读取装备提供的背包空格 | 卸下储物装备、队友离队、载具限制变化时的超载处理；容器嵌套边界 | 适用 |
| 遗物持有与交易 | 遗物通常作用于携带角色，并作为高价值货物参与买卖 | 遗物槽位、换装时点、重复效果、全局效果、负面效果、诅咒移除和商人收购条件 | 部分适用；具体战斗效果归战斗域 |
| 装备与遗物获取 | 可由经营过程收集，装备购买是金钱转化战力的一条路径 | 基础战力获取是否有确定性保障、随机掉落与市场购买的分工、唯一物品重复出现规则 | 适用 |
| 委托接取 | 委托是随机事件，奖励可以是钱、货或后续事件入口 | 接取后是持续任务还是事件链、并行委托数量、期限、进度来源和接取取消 | 适用 |
| 委托完成与失败 | 完成条件、评价与奖励可以不同 | 完成检查、交付来源、结算入口、失败和放弃、重复交付、奖励空间不足及后续事件入口生效时点 | 适用 |
| 退出与读档 | 玩家行为实时记录；局中存档范围尚未设计 | 贸易进行中、委托交付中、物品移动中退出时的恢复点；行情和随机结果是否保持一致 | 适用，需与存档系统共同裁定 |
| 本局结束 | 运营资源、战力和仓库内容随局重置 | 关底结算或死亡发生在交易、奖励领取、委托完成附近时的结算顺序 | 局部适用；跨局归属已经明确 |
| 经济失败恢复 | 现有设计允许钱承担多个竞争用途 | 失去资金或关键物资后是否允许本局进入无解状态；基础恢复路径、破产结果或保底事件 | 适用，影响核心循环可持续性 |
| 情报与解谜 | 情报可影响行情判断和交易计划 | 市场信息接口需由运营系统提供；机关与对话推理规则由情报解谜系统处理 | 行情接口适用，其余内容不在本次直接范围 |
| 远期体积、重量和收纳 | 已预留属性；远期包括打捆、包扎和装瓶 | 具体限制、尺寸占格和收纳配方 | 当前版本不适用，保留 B2 缺口 |

## 6. D. 暂缓问题及原因

### T-01 仓库与银行细节

仓库的地点共享范围、容量与存取事件可以在背包和交易基础规则完成后设计。银行规则依赖 OPS-Q-001 的货币范围，先行设计会产生大量失效内容。当前可以确认两者均为单局设施，内容随局结束重置。

### T-02 装备与遗物内容规则

装备品质分层、确定性获取、升级路径、遗物重复效果、全局效果比例与负面遗物规范会影响内容制作和战斗平衡。物品共通模型、市场模型和槽位规则确定后，再进入这一批问题能够减少反复修改。

### T-03 任务物品与局末边界

任务物品的出售限制、关键物资恢复和局末最后一次结算依赖委托状态模型与存档边界。当前先登记影响，不单独选择规则。

### T-04 物品风险

现金损失、货物损坏、腐坏、耐久与被夺取会显著增加玩家损失感和内容量。已有材料只提出风险关注，没有正式要求首版必须启用。建议在核心买卖和空间闭环可玩后，按体验测试决定首版采用哪些风险。

### T-05 远期收纳

体积、重量、打捆、包扎和装瓶已经有明确的远期定位与属性预留。首版采用格与堆叠规则即可继续，远期立项时再设计尺寸、容器和收纳规则。

### T-06 情报解谜正文

运营系统只需输出市场事实、价格和变化状态。情报的获取渠道、可信度表现和线索树记录由情报解谜系统继续设计。双方接口在 OPS-GAP-031 中登记。
