## 1. 采用的约定

组件类型必须声明在一个元对象内是否唯一。纹理组件、坐标组件均声明唯一；其他组件在实现时明确声明允许一个还是多个，不以当前字典结构替代该决定。

元对象提供同级的 AddComponent 与 ReplaceComponent：Add 只新增，Replace 明确指定被替换的旧组件。Add 遇到重复唯一组件时拒绝，不再隐式替换。替换动作由元对象统一编排，新组件自行声明哪些状态需要继承以及如何判断未赋值。

替换成功后，新组件必须具有正确 Owner；原对象已绑定场景时，新组件还必须完成场景绑定并立即应用状态。调用者不需要补一次 TryBind。

## 2. 唯一性声明和存储

拟新增 `MetaComponentPolicyAttribute`，用法：

```csharp
[MetaComponentPolicy(isUnique: true)]
public sealed class SceneCoordinateComponent : MetaObjectComponent { /* ... */ }

[MetaComponentPolicy(isUnique: true)]
public sealed class SceneTextureComponent : MetaObjectComponent { /* ... */ }
```

属性目标为 Class，`AllowMultiple=false`、`Inherited=false`，构造参数 `bool isUnique`，公开只读 `bool IsUnique`。每个具体运行时组件类型必须声明，缺失声明的新增或替换请求拒绝；唯一性以精确运行时类型 `GetType()` 为键。当前两个组件是 sealed，不涉及派生类型共享唯一槽。未来若增加组件继承族，需要单独声明族标识，不能暗中改变此规则。

`MetaObjectInstance` 的内部存储改为 `Dictionary<Type, List<MetaObjectComponent>>`；唯一组件列表长度只能为 0 或 1，可重复组件可保存多个不同组件实例。一个组件对象不能重复添加，也不能同时属于两个元对象。对已归属其他对象的组件直接拒绝，调用者先移除并完成释放后才可再次添加，避免验收 R2 的双重归属。

查询约定：

- `GetComponents<T>()` 返回该具体类型的只读快照，缺项为空，顺序为添加顺序；替换保留原槽位顺序。
- `GetComponent<T>()` 保留单项查询：0 项返回 null、1 项返回该项，超过 1 项抛 InvalidOperationException，避免悄悄选第一项。
- `TryGetComponent<T>(out T component)` 对 0 项或多项返回 false，component=null。
- `Components` 改为全体组件的只读快照列表，`ComponentCount` 为组件实例总数；遍历绑定、解绑、Dispose 的调用方同步改用列表，不能保留原 `.Values` 调用。
- 增加 `RemoveComponent(MetaObjectComponent component)` 精确移除；`RemoveComponent<T>()` 在多项时拒绝，防止误删其他实例。

上述返回值不能暴露内部可变 List，外部所有变更必须经过元对象入口。

## 3. 元对象公开调用契约

拟采用以下签名，均同步执行，仅允许 Unity 主线程调用：

```csharp
public bool AddComponent(MetaObjectComponent component);
public bool ReplaceComponent(MetaObjectComponent current, MetaObjectComponent replacement);
```

Add 的 bool 口径调整为“是否成功新增”，不再有“false 表示已替换”的语义。当前工程中 MetaObjectDefinition.CreateInstance 是该入口的主要调用方，实施时必须检查返回值并在配置错误时报告，不把拒绝当成功。

| 条件 | AddComponent | ReplaceComponent |
| --- | --- | --- |
| 参数为 null | 抛 ArgumentNullException，无变化 | 任一参数为空则抛 ArgumentNullException，无变化 |
| 类型未声明策略 | false，无变化 | false，无变化 |
| 新组件已有 Owner | false，包括重复添加同一实例 | false，新旧引用相同时也拒绝 |
| 唯一组件已存在 | false，不替换旧项 | 指定 current 后允许替换 |
| 可重复组件已存在 | 追加新实例 | 只替换 current，不影响其他实例 |
| current 不在本对象中 | 不适用 | false，无变化 |
| 新旧具体类型不同 | 不适用 | false；跨类型改变应显式移除和新增 |
| 生命周期函数内再次请求增删替换 | 拒绝并返回 false | 拒绝并返回 false |
| 状态交接或关键字段校验失败 | 不适用 | false，保留旧组件及原显示 |
| 成功 | 加入集合、Attach，若已绑定则 Bind | 原槽位换为新组件，旧组件退出，新组件已就绪 |

预期拒绝返回 false 并记录包含组件类型、对象标识和原因的诊断。未知异常不能伪装成普通重复添加；按第 5 节的回滚和故障语义处理。

场景绑定归属继续分层：`MetaObjectPreset` 解析 Grid、Renderer，并将承载引用交给 `MetaObjectInstance`；`MetaObjectInstance` 新增 `private MetaObjectPreset boundPreset` 保存当前绑定的承载，不自行搜索场景。新增内部 `BindAll(MetaObjectPreset preset)`，由 Preset.TryBind 调用；Instance.UnbindAll 清空该绑定记录。Add / Replace 在 boundPreset 非空时完成新组件 Bind。

这替代当前 Preset.TryBind 自行遍历组件、实例完全不知道绑定状态的做法。Dispose 也必须先清除绑定记录。

## 4. 组件自己负责交接字段

拟在基类增加受保护扩展点，由元对象内部包装方法调用：

```csharp
protected virtual bool TryInheritUnassignedState(
    MetaObjectComponent previous, out string reason);

protected virtual bool ValidateReplacementState(out string reason);
```

默认交接不复制任何业务字段、返回 true；默认校验返回 true。具体组件覆写这两个方法，声明自己需要交接和保证有效的字段。元对象只负责安排调用、检查结果，不识别 cell、texture 等具体字段，也不以通用反射盲目复制私有成员。

交接时新组件仍未 Attach / Bind，方法只读旧组件、只修改新组件内部状态，不读写场景、不修改旧组件、不触发订阅。校验也不产生场景副作用。若具体组件含资源请求，需要先完成解析与有效性验证才进入替换提交阶段；本方案不引入异步替换。

### 未赋值的准确含义

每个需要交接的字段或字段组另存显式赋值标志。字段值为默认值不表示未赋值：`(0,0)` 坐标、零偏移、false、0 都可以是调用者明确选择的值。

构造函数使用可选值/独立重载区分“不传”和“显式传零”；共有 setter 在参数验证成功后设置对应标志。定义资产需要增加相应的显式覆盖标志，旧资产迁移时把实际配置项标为已赋值，不能把所有序列化零值重新解释为未配置。

合并顺序固定为：新组件显式有效值 → 旧组件有效值 → 该字段允许的默认值。关键字段没有有效值且没有允许默认值时，拒绝替换。新组件显式提供了非法值应拒绝，不能悄悄退回旧值掩盖配置错误。

### 坐标组件的交接表

| 状态 | 新组件是否提供 | 替换结果 |
| --- | --- | --- |
| cell（关键值） | false | 继承旧组件的已初始化 cell |
| cell（关键值） | true，包括 `(0,0)` | 使用新值 |
| AnchorOffset | false | 继承旧偏移，旧项也未赋值时采用合法默认 Vector2.zero |
| AnchorOffset | true，包括零偏移 | 使用新值 |

增加 `hasCellAssignment`、`hasAnchorOffsetAssignment`，分别记录状态存在性。初始化由元对象绑定或显式 SetCell 完成，不能把新组件尚未赋值的 cell 默认零当作有效的交接输入。偏移还须拒绝 NaN / Infinity。替换成功通过 Bind 应用坐标，Preset 的预绑定暂存不能覆盖交接所得坐标。

### 纹理组件的交接表

纹理 Sprite 与来源路径组成一个选择组，以 `hasTextureSelection` 标记是否显式选择，避免逐字段继承造成“新 Sprite + 旧路径”。

| 新选择 | 交接行为 |
| --- | --- |
| 未提供 Sprite 和路径 | 成组继承旧 Sprite 与路径 |
| 显式提供有效 Sprite | 使用新 Sprite；路径清空，或仅保留经验证确实对应它的新路径 |
| 显式提供有效路径 | 替换提交前先解析得到 Sprite，成组使用新路径与 Sprite |
| 显式提供无效路径或 null Sprite | 拒绝，不从旧项偷偷补救 |
| 新旧两者均没有有效纹理 | 拒绝替换，不能生成“关键纹理为空”的新组件 |

初始占位定义允许空纹理的现有约定仍然有效；它不意味着替换动作能伪造有效纹理。替换空纹理占位组件时，调用者须为新组件提供有效 Sprite / 路径，否则旧占位组件继续保留。若未来需要“清空显示”，应另设明确命令，不能把未赋值和主动清空混在 null 中。

Owner、Preset、IsBound、渲染器缓存、订阅、资源句柄均不继承。这些状态由元对象和新组件的生命周期重新建立，避免把旧绑定和已释放资源转交给新对象。

## 5. 替换生命周期、可见性与失败处理

主线程进入操作时设置实例级变更锁。整个操作同步完成，不跨帧；生命周期回调中的再次结构变更直接拒绝。集合查询在准备阶段仍返回旧组件，成功提交后才返回新组件；不发布半完成的成功通知。

流程：校验所有权、目标、类型和策略 → 新组件继承未赋值状态 → 关键字段校验和资源解析 → 旧组件 Unbind → 新组件 Attach → 若原对象已绑定则 Bind → 原槽位切换到新组件 → 旧组件 Detach → 成功返回。未绑定对象只执行 Attach，稍后绑定由元对象统一完成。

旧组件在新绑定成功前保留 Owner、状态与资源，不提前执行不可逆的 OnDetached。框架只会让一个同槽组件处于已绑定状态。

准备阶段失败直接保留旧组件，丢弃准备中的新组件。新 Attach / Bind 抛异常时，尽力清理新组件并清空 Owner / Preset，然后重新 Bind 旧组件、重应用旧坐标/纹理，集合保持旧项。生命周期标志的清理必须放在 finally，不能沿用当前回调抛错便跳过清理的路径。

自定义回调必须满足“可解除、可重绑定、不得销毁借用资源”的契约。框架不能保证任意用户回调的不可逆外部副作用都能回滚；若旧组件恢复绑定也失败，应记录两次异常、将元对象标为未绑定故障状态并抛 InvalidOperationException，不能返回 false 后仍声称旧对象正常。若新项已提交但旧 OnDetached 清理抛错，保留成功的新项，报告清理异常，不能再把已释放旧项恢复进集合。

为避免成功与异常混淆，实际实施时应把可抛异常的旧资源释放约束为幂等且内部记录异常；在此前提下两项 bool API 只对正常成功和预期拒绝返回。未知回调异常始终对调用者可见。

## 6. 实施落点和兼容迁移

| 类型或资产 | 所需改动 |
| --- | --- |
| MetaComponentPolicyAttribute（新增） | 每类型唯一性策略，不承载实例状态 |
| MetaObjectComponent | 交接与校验扩展点、归属防错、回调异常时状态清理 |
| MetaObjectInstance | 多实例容器、显式替换、持有绑定承载、结构变更锁、精确移除与单项查询歧义处理 |
| MetaObjectPreset | 将整体绑定委托实例；初始格子只对确实未初始化的坐标赋值；不覆盖替换交接所得状态 |
| SceneCoordinateComponent / Definition | 唯一声明；坐标、偏移的赋值存在性与交接逻辑 |
| SceneTextureComponent / Definition | 唯一声明；纹理选择成组交接和有效性校验 |
| MetaObjectDefinition.CreateInstance | 检查 Add 结果；重复唯一配置要报错，不能隐式覆盖前项；失败时释放尚未交付的实例 |
| Player.asset | 迁移显式配置标志，保留现有零偏移和空纹理意图 |
| 调用与验证 | Preset 中 Components.Values 改为新列表；更新配置创建、单项查询与自检遍历 |

## 7. 实施时的决定性验收

| 场景 | 预期 |
| --- | --- |
| 给同一对象 Add 两个唯一坐标组件 | 第二次拒绝，旧坐标和显示保持 |
| 给允许多实例的类型 Add 两项 | 两项均可查询，精确 Replace 第一项不影响第二项 |
| 已绑定角色替换为未赋坐标的新组件 | 继承当前格子和偏移，调用返回时已绑定，SetCell 能继续移动 |
| 新坐标显式为 `(0,0)` | 使用 `(0,0)`，不沿用旧格子 |
| 旧坐标有跨格偏移，新项未赋偏移 | 继承偏移，格子不因世界坐标反推而改变 |
| 旧纹理有效，新纹理组未赋值 | 成组继承并保持可见 |
| 新纹理只有路径 | 成功解析后应用对应 Sprite，新旧路径不串用 |
| 新纹理路径无效，或新旧均空 | 拒绝替换，旧项及原显示保持 |
| 替换后再次 TryBind / Rebuild | 当前格子不回退，已交接状态不被预置旧缓存覆盖 |
| 把已有 Owner 的组件给另一对象 | 拒绝；另一对象 Dispose 不得影响原组件 |
| 新组件 Bind 抛错 | 新项清理；旧项恢复，或明确进入故障状态，不能假报成功 |
| OnBind 中递归 Add / Replace | 递归请求拒绝，容器及唯一性保持 |
| 替换与销毁 | 旧 Unbind / Detach 各一次，新组件随对象销毁释放，不出现双重响应 |
