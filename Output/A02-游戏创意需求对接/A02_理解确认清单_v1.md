## 二、总体理解综述

先给出我对游戏全貌的理解，请总监检验整体认知是否一致：

**一句话概括**：这是一款以"**时间日程抉择**"替代"空间岔路抉择"的 roguelite；玩家作为赏金猎人与商人的结合体，在一条条"if 世界线"中重历冒险、靠信息差经营发育、以"行动槽连携"进行半回合制战棋战斗，通过关底事件推进大关，并在局外线索树中拼合世界观真相。

**局内核心循环**：
`探索地图发现事件（不耗时间）→ 读取窗口期/持续时间与提示 → 决策日程（下一个时间段进哪个事件）→ 执行事件（战斗/剧情/贸易/委托，发育）→ 时间推进 → 重复 → 关底事件 → 本局结局（真/差/失败/死亡）`

**局外元循环**：
`结算时解锁线索树 → 局外查看线索树提示与节点关系 → 依据引导规划下一局（准备前置条件、触发未触发事件、解锁隐藏关底/下一大关）→ 开新世界线`

**贯穿性设计意图（我的理解）**：
- **时间即路线**：压力不在赶路，而在日程取舍——错过了什么机会。
- **信息即资源**：事件提示（内置数据的间接描述）贯穿经营（行情差）与战斗（敌方情报），是钱与战力之间的桥梁。
- **资源即战力**：无等级成长，战力由道具、工具、情报构成，战斗与运营共享同一决策空间。
- **线索树即叙事**：局外元进度、引导系统、剧情解谜三位一体，由"高位存在重历"设定提供叙事合法性。

## 三、逐节理解确认

### 3.1 定义性概念

#### 第 5-6 行（F01）

- 【原文】"本游戏属于roguelike游戏。不同于传统的roguelike游戏，本游戏在路线上的抉择体现在地图上的岔路选择。传统肉鸽游戏案例：以撒的结合、杀戮尖塔、元气骑士"
- 【理解】品类定位为 roguelike（对标以撒、杀戮尖塔、元气骑士等现代 roguelite）；传统 roguelike 的路线抉择 = 地图岔路选房间。总监对 F01 的修正明确了案例对标。
- 【存疑 T1】第 5 行"本游戏在路线上的抉择体现在地图上的岔路选择"与第 8 行"本游戏的路线选择在于时间上的抉择"**直接矛盾**。【多角度】(a) 编辑残留——本句"本游戏"应为"传统的roguelike游戏"（v1 原语义）；(b) 本游戏在地图岔路（区域/道路选择）与时间日程两个层面都存在路线抉择，地图层面是次要/基础层。请总监确认取哪种。

#### 第 8-9 行（F02）

- 【原文】"本游戏的路线选择在于时间上的抉择。地图允许在未锁定区域自由探索，玩家可以通过交互发现大量事件，这些事件都有预设的*入口开放窗口期*和*持续时间*，这要求玩家像在传统肉鸽当中抉择路线一样抉择事件日程表"
- 【理解】核心创新确认：传统肉鸽在空间岔路选房间，本作在时间日程上选事件。地图探索本身免费（不推进时间），抉择对象是"日程"：选哪些事件、按什么顺序、赶在窗口期关闭前进入。发现事件 ≠ 触发事件（触发才推进时间）。
- 【存疑 T5】时间模型仍需精确化："时间段"的刻度、"窗口期"与"持续时间"的计量单位未定义。【多角度】(a) 每个事件恰好占 1 个时间段，窗口期 = 允许进入的时段编号区间；(b) 事件持续时间 = 1~N 个时间段，窗口期 = 允许进入的起始时段区间；(c) 连续时间轴 + 区间判断。我的倾向是 (b)。请总监确认或授权我按 (b) 细化。
- 【存疑 T7】"**未锁定区域**"是新增概念：暗示地图存在锁定区域。锁定区域如何解锁（大关进度/事件/线索）？【推断】类似肉鸽按进度开放更多区域，锁定区域 = 后续大关/深层内容。请确认。

#### 第 11-13 行（F03）

- 【原文】"传统：完成一个房间的探索→抉择下一个房间选哪个……本游戏：在一个时间段内完成一个事件→抉择下一个事件触发哪个（通过不同的条件，如时间地点前置事件）→经历完下一个事件，存在一些固定的不容抉择的特殊事件，会在达到特定要求后强制触发boss事件和剧情事件"
- 【理解】映射关系确认：房间 = 事件；岔路抉择 = 日程抉择；固定特殊房间（boss/剧情）= 强制触发特殊事件（boss/剧情）。
- 【存疑 T6】"达到特定要求后强制触发"的力度未明确。【多角度】(a) 前置满足后立即强制插入日程、无法回避；(b) 强制出现在当前可选项、必须安排；(c) 到点强制开始、打断当前事件。我的推断是 (a)（类似肉鸽必经 boss 房）。请确认。

#### 第 14-15 行（F04）

- 【原文】"不同事件的前置条件各不相同，严格程度也不同。在设计时，事件的触发条件需要预留充分的可扩展空间，以根据剧情要求在游戏制作过程中来安自由组合触发条件。玩家一般通过在地图上的行为来触发事件，此处也应当预留可扩展空间，触发方式包括但不限于：进入区域，特定对话选项等。在进入那些会推进时间段的事件之前，玩家会收到直接的ui提示，来避免误触发"
- 【理解】设计原则确认：触发条件与触发方式都必须是**模块化、可扩展、可组合**的（时间/地点/前置事件/资源/情报等自由装配，严格程度可调）；触发方式可扩展（进入区域、对话选项等）；推进时间的事件进入前有 UI 确认提示防误触。→ 后续拆解时我会把"条件系统"与"触发方式"设计为可配置的数据驱动模块。
- 【存疑 T2】"来安自由组合"为语病（疑为"来自由组合"），请修正。

#### 第 18-20 行（F05）

- 【原文】"每一场游戏都是一条不同的'if世界线'……if世界线是游戏社区讨论的常用语，指的是与主线剧情不同，但是在特定条件变化时可能会发生的剧情走向。每场游戏的随机种子会影响玩家决策，玩家的决策直接影响一局游戏当中触发的剧情事件的内容。在玩家视角来看，每一场游戏都讲了一个走向有所差异的故事。'引导'所包含的内容极其多样，包括但不限于对话中的暗示，线索树当中的提示等。这里的引导更倾向于对玩家在文字和视觉层面的提示，而非需要解锁的游戏机制"
- 【理解】"if 世界线" = 社区用语机制化：指特定条件变化下可能发生的剧情走向，每局 = 一条 if 世界线；差异来源 = 随机种子（扰动环境→影响决策）+ 玩家决策（决定触发哪些剧情事件）。"引导" = 文字/视觉提示层（对话暗示、线索树提示），不是需要解锁的机制——即引导是"信息层"而非"机制层"。
- 【推断】随机种子影响的粒度：种子主要扰动事件池/窗口期/地点/货价等"环境参数"，剧情内容差异主要由玩家选择产生。请确认。

#### 第 22 行（F06）

- 【理解】最终事件 = 关底事件，同义。术语问题消解。

#### 第 24-25 行（F06）

- 【原文】"在完成一个大关的内容（无论失败还是成功，是真结局还是差结局）都算一局游戏结束。如果是首次通过本大关的真结局，那么下一大关将会解锁。单局通关时长预期不在本文档的考虑范围内。有关大关之间的关卡切换，详见线索树的部分。目前提及的内容当中，只有线索树和线索树中解锁的东西是局外资源"
- 【理解】单局结构确认：一局 = 一个大关；任一结局（成功/失败 × 真/差）达成即本局结束；首次真结局通关 → 解锁下一大关；局外资源仅线索树及其解锁物（钱/货/仓库/战力全部随局重置）。
- 【存疑 T4】"有关大关之间的关卡切换，详见线索树的部分"——**线索树章节未涉及关卡切换内容**，引用落空。我推断总监想表达的是"大关解锁状态记录于线索树（元进度）"，请确认引用意图。
- 【存疑 T8】解锁新大关后，旧大关可否重玩（补全线索/体验其他支线）？我的推断：可以，因为收集是鼓励目标且只有线索树是局外资源。请确认。
- 【存疑 T9】术语对应确认："默认关底事件 → 差结局，隐藏关底事件 → 真结局"？隐藏关底事件的触发条件是否即"本局线索/情报收集达标"（具体判定细节留后续）？请确认对应关系。

### 3.2 游戏内的机制

#### 第 31-33 行（F07）

- 【原文】"游戏以不断通过关底事件和在if当中收集各种线索和信息来补全世界观故事线为两大目标。这两个目标互不冲突，不断通过关底事件……能够帮助解锁更多的线索和信息，让线索树更加完整。而线索和信息收集的越多，也越能帮助玩家更轻松地通过关底事件，甚至是触发隐藏的，与默认关底事件不同的隐藏关底事件。'将线索和信息收集齐全'不是通关的强制要求，只是游戏当中鼓励玩家去探索的内容。"
- 【理解】两大目标互补且形成正反馈环：通关 → 解锁更多线索；线索多 → 降低通关难度、解锁隐藏关底；收集非强制、属鼓励项。"在 if 当中" = 在一局 if 世界线当中。隐藏关底事件使"真结局"成为收集驱动的内容目标，与线索树的"解锁条件标注"呼应——剧情解谜的奖励端点。

#### 第 36-38 行（F09）

- 【原文】"游戏中的主角在一个*不向玩家具体交代*的剧情位置遇到了困难，然后受到了某种高位存在的帮助。高位存在提出让主角无限制地重新体验经历自己的冒险生涯，发掘曾经在冒险过程当中被忽略的，或者因不可抗力错过的细节和真相。作为辅助，高位存在还提供了'线索树'这一工具来帮助主角在诸多可能性当中梳理信息。剧情性的世界观背景暂时不关注，本文档的目的主要是为游戏玩法开发服务"
- 【理解】叙事框架确认：主角无限重历冒险生涯（"重历"型框架），发掘被忽略/错过的细节真相；线索树 = 高位存在提供的梳理工具。该设定为世界线重开提供叙事合法性，也解释了线索树的"局外"属性（两次冒险之间梳理信息）。世界观细节不在本玩法文档范畴——我接受该边界。

### 3.3 运营

#### 第 42-43 行（F08）

- 【原文】"模拟经营与解谜。这里的解谜主要指的是通过剧情当中已有的视觉和文字引导，推断出做好那些前置条件准备可能会触发一个曾经没触发过的事件，也可以包含事件内的谜题（机关、对话推理）"
- 【理解】解谜的两种形态：(1) 条件推断式解谜——依据引导推断"做哪些前置准备可触发未触发事件"；(2) 事件内谜题——机关、对话推理。解谜闭环：局内观察引导 → 局外线索树提示 → 下一局准备前置条件 → 触发新事件 → 新引导。这已部分覆盖 F25 的引导闭环（F25 虽被排除，但我理解该闭环是解谜玩法的自然延伸，后续策划阶段会补全）。

#### 第 44-47 行（F10、F12）

- 【原文】"主角的身份类似赏金猎人与商人的结合，非战力相关的运营资源主要为：钱、货和委托。根据事件提示在货物买卖中盈利，在事件当中接取委托赢取报酬。获得的金钱用于达成一些前置条件或直接转变为战斗力（见战斗机制部分）探索新的事件。达成前置条件 / 转变战斗力 / 探索新事件互为并列关系"
- 【理解】金钱三种用途并列、无优先级：开前置（解锁事件）、提战力（买道具/工具）、探新事件（买情报/入场）。玩家自由分配。
- 【推断 T25】"金钱 → 战斗力"（Q29 已划归策划工作）：结合第 77-78 行，我推断其路径 = 购买道具、工具、情报；后续我在策划阶段细化"钱 → 战力转化路径清单"。

#### 第 49 行（F11）

- 【原文】"事件提示主要指的是玩家在事件当中获取到的信息，来源广泛，通常定义为对游戏内置数据的间接描述，比如某物的行情，有特殊事件会发生的事件地点等。"
- 【理解】事件提示 = 对游戏内置数据的**间接**描述（行情趋势、事件地点预告），不直接给数值——这正是信息差的原料。玩家把提示转化为经营决策（低买高卖）与日程决策（去哪触发什么）。

#### 第 51-54 行（F10）

- 【原文】"货物：来源（买入、事件掉落、委托报酬、制造）与去向（卖出、交付、消耗）。委托：随机的事件，完成条件，结算评价标准，奖励内容（钱、货还是下一个事件）都各不相同"
- 【理解】货品生命周期 = 4 来源 × 4 去向矩阵；"制造"是新转化接口（原料→货品，配方留策划）。委托奖励可以是"下一个事件"——**事件本身成为可流通资源**，与线索树/世界线衔接（委托奖励的事件 = 未解锁事件的入口）。委托有"结算评价标准"（推断类似评级，影响奖励，细节留策划）。

#### 第 56-60 行（F13）

- 【原文】"背包的机制上打算设计丰富的拓展。底层上，计划采取'类塔科夫'的背包管理系统，具象化物品的尺寸和携带难易度，同时引入诸如'打捆''包扎''装瓶'等物品收纳管理方式。但是在初步研发阶段，背包暂时采取原始的'一格一物'策略，并留好接口，后续再拓展开发。值得注意的是，金钱也将作为物品中的一种……就算是存入银行，也有储值卡、支票等物品需要管理（这部分有关背包机制的拓展需要和策划进一步研判，是否让游戏机制过于冗杂了）"
- 【理解】空间管理 = 运营核心：金钱物品化后，货币也纳入空间决策（带现金还是储值卡？占几格？），强化"商人管理空间"主题。初期一格一物 + 接口预留是稳妥路线。
- 【存疑 T17】仓库与银行未展开：仓库机制（容量/存取地点）在 v2 中仅"背包和仓库"一句提及；银行（储值卡/支票）是新增要素，存取时机、设施分布未说明。【推断】仓库 = 城镇/驻点存取；银行 = 大额资金转换（现金 ↔ 票据）的固定设施。请确认方向。
- 【策划研判】回应括号注记：类塔科夫背包与"空间管理核心"定位一致、沉浸感强，但复杂度高（UI 操作量、教学成本、与战棋节奏冲突的风险）。我的初步意见：**初版一格一物 + 2~3 种低门槛收纳动作（堆叠/捆扎）**，全部走物品属性接口（尺寸/堆叠/收纳标记），不做全量塔科夫化；以"决策深度 / 操作成本"比作为后续拓展的判据，在玩法原型阶段验证后再决定是否加装。同意总监"进一步研判"的谨慎态度。

### 3.4 战斗（含附加内容）

#### 第 66-68 行（F14、F09）

#### 附加内容第 102-151 行（F14、F15）——机制逐条梳理

**① 局外技能配置**（第 102-110 行）：携带 4 个基础技能（A/B/C/D 四类各恰好一个）+ 5 个连携技能（类别不限）。

- 【存疑 T14】"连携技能的效果会受到对应基础技能类别的影响（例如：连携里含 A，则基础技能 A 的部分效果会生效）"——【多角度】(a) 连携释放时，其 COST/PRODUCE 中出现的类别字母会附带对应基础技能的部分效果（连携 = 基础技能效果的组合放大器，即"连携强度 = 字母构成 × 所带基础技能"）；(b) 连携技能自身有类别归属，同类连携吃同类基础的加成。我的理解是 (a)。请确认。

**② 行动槽**（第 112-121 行）：上限 10；每次行动在槽尾添加字母——基础技能 → 类别字母（A/B/C/D），移动 → M。
- 【理解】战斗的"连招引擎"：玩家通过行动序列在槽中"编程"出连携指令。槽 = 滚动窗口，只需槽尾匹配；上限 10 限制了连招最大长度（最长 COST ≤ 10）。

**③ 连携释放**（第 123-135 行）：每个连携含 COST（一串字母，如 ABA）与 PRODUCE（如 C）；仅当槽尾序列与 COST 完全一致时可释放；释放 = 删槽尾 COST + 槽尾加 PRODUCE。
- 【理解】例：槽 = A → AB → ABA，释放 COST=ABA → 槽 = C，可继续接 C、CB、CBA……形成连续释放链。机制自洽。

**④ 移动打断**（第 137-144 行）：移动加 M；槽内已有 M 时，任何行动（含再次移动）清空 M 及其之前所有字母。
- 【理解】M = 连招终止符：**走位与连携爆发互斥**——这是战棋层（位置）与连携层（序列）的核心耦合：玩家在"保持连招"与"调整站位"间取舍。战术含义：移动的代价 = 连招进度清零。
- 【推断】COST 不应含 M（M 作为打断符不参与连携）；例：槽 = ABM 时，因尾字母为 M，任何 COST 均无法匹配（末尾序列被 M 阻断）。

**⑤ 半回合制时间轴**（第 146-149 行）：所有角色（敌我）行动顺序由时间轴决定；时间轴推进到某角色标记时该角色行动；行动结束后按行动内容 + 属性补正决定下次行动时机。
- 【理解】战斗节奏 = CTB 式时间轴（类似 FFX）：不同行动消耗不同"延迟"，速度属性影响行动频率；"半回合制" = 时序驱动、按标记行动（非双方轮流）。

**⑥ 战场**（第 151 行）：战斗在大世界原地展开；我方主控 2-4 单位；敌人数量视强度（数值策划负责）；可能存在非主控友方单位与场地道具。
