## XDM-GAP-017 结算组件的划分与写入契约未定：四类状态项目的表述已撤销并改为存档快照加结算组件，但后续组件的划分方式、各组件之间的写入边界与组件清单的登记位置没有规则

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-aa-bb-02 回答 XDM-GAP-008；07-线索树与元进度/40-局末结算与写入/40_局末结算与写入设计_v2.4.md 的 3.2、3.3、3.12；01-通用系统/50-存档与持久化/50_存档与持久化设计_v4.3.md 的第 4 节 |
| 影响范围 | 07-40 局末结算与写入、07-10 线索树核心、07-20 剪枝系统、01-50 存档与持久化、06-A0 战斗目标与结果 |
| 关闭条件 | 定义结算组件的划分原则、组件之间的写入边界与组件清单的登记处 |

**候选 A：按跨局数据类别划分组件，扩展配置表登记组件清单（推荐）**

方案：结算组件按跨局数据的类别划分，当前只启用节点解锁检查组件。新增一类跨局写入内容时新增一个组件，组件清单与各自的写入项范围登记在新建的结算组件表（`07-线索树与元进度/40-局末结算与写入/40_结算组件表_v1.csv`）中，表内保留待补充记录声明扩展契约；组件之间不得写入同一项跨局数据。

代价与影响：组件的写入边界互不重叠，新增内容有明确的登记入口，与库内其他扩展配置表的做法一致。代价是需要新建并长期维护一张配置表，组件数量增长时表内条目同步增长。

**候选 B：只区分状态类与记录类两份组件，不建表**

方案：结算组件简化为两份：状态类组件负责节点、传闻与事件的解锁状态写入，记录类组件负责达成记录、大关进度与统计信息一类的结果记录写入。组件划分写在正文中，不单独建表。

代价与影响：实现最简，不需要新增配置表，两类组件的职责足够稳定。代价是后续新增的写入内容必须在两类之间归类，跨类的内容容易产生归属争议。

**候选 C：Demo 只保留节点解锁检查组件，组件扩展留到后续版本再定**

方案：Demo 阶段只保留节点解锁检查组件，不在本阶段定义组件划分原则与清单；后续版本出现第二类跨局写入内容时再单独设计。

代价与影响：不为尚未出现的需求预付结构，Demo 实现的约束最少。代价是新增内容的落点暂时没有规则，开发过程中容易出现直接扩展写入项的临时做法。

## XDM-GAP-018 装备栏开放配置所依据的事件段未定义：裁定要求由事件段的属性配置声明装备栏开放，但库内没有事件段这一结构，事件属性配置与事件片段的层级关系需要明确

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-aa-bb-02 回答 XDM-GAP-007；06-战斗/60-装备系统/60_装备系统设计_v7.2.md 的第 4 节；02-时间与事件/30-事件系统/30_事件系统设计_v4.3.md 的 4.9、4.10 |
| 影响范围 | 06-60 装备系统、02-30 事件系统、06-70 遗物系统、01-20 信息传递系统 |
| 关闭条件 | 确定装备栏开放配置挂载在事件片段、事件内时间段还是事件整体，并统一术语 |

**候选 A：挂载在事件片段上，事件段即事件片段的同义表述（推荐）**

方案：装备栏开放作为事件片段的一项属性，随片段类型表与事件属性配置登记；片段是事件内部可单独配置的内容单元，同一事件的不同片段可以有不同的开放状态。术语统一使用事件片段，事件段作为历史表述不再单独出现。

代价与影响：复用已有的片段结构，不需要新增概念；片段本身已经承载进入条件、内容参数与离开条件，追加一项界面开放属性符合它的定位。代价是同一片段内跨越多个时间段时无法再细分开放状态。

**候选 B：挂载在事件内的时间段上**

方案：事件内的每个时间段可以声明本时段的界面开放状态，装备栏的可用性随世界时间推进切换。配置项登记在事件属性配置中，与时间检查点并列。

代价与影响：开放状态可以按时间粒度切换，与时间即容量的呈现一致。代价是需要为每个事件配置逐时段的开关，内容侧成本高，且玩家难以预期装备栏何时可用。

**候选 C：挂载在事件整体上，事件级开关**

方案：装备栏开放作为事件级属性，整个事件内统一生效，事件内的所有阶段共用同一个开放状态。

代价与影响：配置最简单，一个事件一个开关。代价是无法表达事件内不同阶段的不同需要，例如剧情阶段锁定而准备阶段开放的情形无法配置。

## XDM-GAP-019 全队失去行动能力的结局归属需要收口：回答同时把全体覆没列为未能抵达关底的成因，而既有规则规定全队失去行动能力即时触发死亡结局

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-aa-bb-02 回答 XDM-GAP-004；07-线索树与元进度/40-局末结算与写入/40_局末结算与写入设计_v2.4.md 的 3.13；06-战斗/A0-战斗目标与结果/A0_战斗目标与结果设计_v3.2.md 的 3.4 |
| 影响范围 | 07-40 局末结算与写入、06-A0 战斗目标与结果、06-10 战斗总览、01-50 存档与持久化 |
| 关闭条件 | 确定全队失去行动能力的结局归属与两类结局的优先级呈现 |

**候选 A：死亡结局优先，主线中断计入本局记录（推荐）**

方案：全队失去行动能力一律即时判定为死亡结局，本局按死亡结局收尾；主线因此中断这一事实作为同一事件的一部分计入本局记录，不改变结局类型。两类结局的结算差异仍只体现在达成记录与大关进度两项上。

代价与影响：与既有的即时判定规则一致，不需要为战斗内部再分两种收尾方式，玩家看到的结果稳定。代价是死亡结局与失败结局在结算内容上的差异进一步缩小，区别只落在文案与达成记录字段上。

**候选 B：按发生位置区分，主线战斗的覆没判失败结局**

方案：全队失去行动能力发生在主线战斗时判定为失败结局，发生在非主线战斗时判定为死亡结局。判定依据是该战斗是否属于通向关底的主线链路。

代价与影响：失败结局与主线中断的语义完全对齐，玩家能从结局类型直接读出本局为何结束。代价是需要为每场战斗标注是否属于主线链路，战斗结果需要读取主线链路数据，两个结局的判定源出现分叉。

**候选 C：合并为单一结局类型，不再区分死亡与失败**

方案：取消死亡结局与失败结局在判定源上的区分，统一为一种未通关结局，差异只在达成记录的描述字段上体现。

代价与影响：判定源唯一，实现与文案都最简。代价是推翻已有的四结局结构，与创意文档对多种结局的设计意图以及既有决策 27 冲突。

| 关闭条件 | 06 域内指向问题清单的引用统一指向最新版本或改写为不依赖版本的表述 |
