| OPS-RQ-002 | 上一轮已关闭，本轮复核确认正文按先当前接收角色、后队伍其他角色的顺序定义 | 完全关闭 |
| OPS-RQ-003 | 领取确认中的取消不产生任何状态变化；继续领取时部分装入与落地在同一次提交内完成 | 完全关闭 |

| OPS-RQ-005 | 识别范围由场合决定，战斗之外按全队识别、战斗中只调取自己身上的库存；装备栏容器常驻可识别；活动状态的条件检测沿用同一份已提交状态 | 完全关闭 |
| OPS-RQ-006 | 商人经营内容由主营词条对应的物品池随机选取，规模基准值等于商品基准价值总量或回收资金量，出售会消耗该值 | 系统模型关闭，项数与周期归内容与数值 |
| OPS-RQ-008 | 交易中按容器格识别，不要求玩家先卸下装备 | 部分关闭，界面开放时机作为遗留边界保留 |

| OPS-RQ-011 | 逾期与主动放弃同义，一次结算完成，不设分批与重复交付；完成率公式归数值模型 | 完全关闭 |
| OPS-RQ-012 | 任务目标物品永久丢失后本局无法继续完成 | 部分关闭，是否立即失败作为遗留边界保留 |
| OPS-RQ-013 | 保存时机为时间段推进与战斗轮次推进；不提供手动保存与多个存档位 | 完全关闭，写入中断与版本迁移归实现层容错 |
| OPS-RQ-014 | 局内进行中的交易、委托进度、押金、落地物与未领取奖励都不进入局末结算，结算顺序问题因此不存在 | 完全关闭 |
