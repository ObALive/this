## 1 系统定位

全部界面与操作的交互方式规范：鼠标/键盘操作模型、界面框架与各界面交互细节的统一落点。任务书明确要求从"交互体验、交互方式"粒度展开设计（如背包取物的多粒度操作）。

## 2 设计依据（已确定内容摘录）

- 创意文档 §11：14 条关键交互逻辑为各界面交互设计的总约束（见 `00-总览/01_设计原则与跨系统交互逻辑_v1.md` 第二节）；
- 创意文档 §11-2：进入会推进时间的事件前必须有界面确认提示，防止误触发；
- C01 任务书：背包界面移动物品的方式包括——将单格物品所有内容移动到鼠标、从一格物品里取出一个到鼠标、从一格物品中取出一半到鼠标等，需全量设计。

## 3 研讨增量要点（待拍板）

- B01 评价书 4.3①：行动槽表达建议改图标+颜色并"点亮即示"（关联 06-50 战斗 UI）；
- B01 评价书 4.3②：日程簿可视化（甘特图式时间轴 + 事件块）为本作卖点画面（关联 02-20）；
- B01 评价书 4.3③：剪枝预览面板（关联 07-20）；
- B01 评价书 4.3④：技能页面基于当前构筑实时渲染效果预览（关联 06-40）；
- B01 评价书 4.4②：时间轴 UI 需在出手前显示"这招之后我的下回合在哪"（关联 06-20）。

## 4 设计内容

### 4.1 待设计问题清单

- [ ] 全局交互规范：操作模型（鼠标为主？键盘快捷键？）、交互层级、手感基线（来源：C01 任务书）；
- [ ] 背包取物交互全粒度规范：整格取走 / 取一个 / 取一半 / 其他粒度的操作方式、按键与视觉反馈（来源：C01 任务书，与 05-30 联调）；
- [ ] 事件进入确认提示的界面形式与文案规范（来源：§11-2）；
- [ ] 各界面清单与框架划分：探索 HUD、日程界面、背包/仓库/银行界面、战斗界面、线索树界面、局末结算界面（来源：任务书全量交互设计目标）；
- [ ] 信息揭露机制的界面承载：位置提示与错过提示（来源：C-01-10-03 候选 3 裁定，移动系统交接）；
- [ ] UI 信息呈现原则：与"世界状态充分呈现给玩家"（§2.3）的对齐方案。
