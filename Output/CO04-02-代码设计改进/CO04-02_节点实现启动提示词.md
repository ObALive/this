# 项目网络图单节点实现启动提示词

用途：将一个网络图节点作为增量功能任务，交给智能体完成必要的局部设计、实际实现和验证。本文是供用户复制使用的任务提示词，不修改 Rules，也不代表已经执行某个节点。

适用于已有早期实现的工程：以当前已定设计为目标，设计一致时复用，局部差异时适配，结构冲突时重构或重做。单节点限定本轮功能目标，必要改造可以跨越多个类、模块和资产。

每次填写目标节点和 Unity 工程绝对路径即可。资料库与数据库已按当前工作区填写；切换网络图时，同时更换数据库路径。完整路线、序号与概要共同定位，不能只依赖可能在导入或重排后变化的 `n2` 等内部 ID。

## 启动提示词

```text
请实现以下项目网络图节点，完成实际可用的功能与验证，不停留在分析、方案或伪代码。

资料库：D:\myspace\Git\this
系统设计稿目录：D:\myspace\Git\this\系统设计文档
架构设计稿目录：D:\myspace\Git\this\架构设计文档
网络数据库：D:\myspace\Git\this\Tool\项目网络图\数据\N01_完整依赖清理新图_v2.sqlite
目标节点：【完整路线 / 节点序号 / 节点概要】
Unity 工程：【Unity 工程根目录的绝对路径】

本消息就是本次任务说明与授权。采用“单节点增量实现”方式：在当前节点内部完成必要技术决定并直接实现，不要求先编制完整代码设计案、独立类稿或伪代码，不因缺少另存的 Task 文件而停止。技术设计的准确性要求仍需满足。

授权修改上述 Unity 工程中完成本节点所需的脚本、场景、Prefab、配置和相关测试，包括重构、替换或删除与当前已定设计冲突的旧实现，以及同步迁移受影响的现有调用方、已有前置实现和资产接线。上述必要改造已获授权，不因跨类、跨文件、跨模块或涉及旧公共接口而逐项请示。保留无关的既有修改，理解改动意图后合并，不用还原或覆盖工作区代替重构。

任务范围以完成本节点及维持受影响的既有有效功能为界，不以修改文件数量为界；不借机实现其他节点的新能力或重写无关系统。任务记录可写入资料库的 Output、Report 本任务位置。资料库的 Rules、系统设计、架构设计、旧 Code_Design 与 Tool 本轮只读，不修改网络数据库；需要修订这些内容时在结果中提出具体建议。默认不提交或推送 git。

一、准确读取目标
先读资料库 Rules/README.md 及适用规则，工程内 AGENTS.md 和与本任务相关的技能按实际情况执行。再读 Tool/项目网络图/读库说明.md，使用 query.py 并显式指定上述数据库，只读查询。

按完整路线、序号及概要核对目标，读出完整正文、对象声明、实现路径、备注，以及全部直接前置。显式依赖和同路线自动链式依赖都要读取：v_edge 中 from_id 是前置、to_id 是依赖者，不能只看 node_refs 或节点高度。名称不唯一或指定内容已变化时，不要猜测另一个节点。

执行过程中，根据目标节点、涉及对象和实际遇到的问题，自行在上述系统设计稿与架构设计稿目录内检索、阅读所需信息；系统稿用于核对玩法规则与边界，架构稿用于核对职责、依赖、数据归属及生命周期约束。无需用户逐项指定文件或章节，也不要求预先通读全部设计稿。必要时沿文档引用追查来源，区分已定结论与待定内容，并在任务记录中注明实际采用的文件及章节。查阅设计稿不扩大本节点的功能范围。

不要启动绘图服务、初始化默认库，或把旧 JSON 和导出文件当作当前数据。仅阅读与当前节点、前置及实际实现有关的资料，不以通读全项目设计为开工条件。

二、核查前置与现有工程
检查 git 状态，保留已有修改。确认 Unity 版本、现有程序集、包、场景组织和当前可用的工程工具。

将每个直接前置映射到实际代码或资产，确认它提供的能力已存在且能被本节点使用；图中存在前置节点不等于它已经实现。按需追查上游，理解现有实现的意图、状态流转、调用关系与资产引用。对同名对象和公共类型先检索现有定义；能复用的能力优先复用，其旧结构是否保留按下一节判断。

关键前置未完成时，明确缺少的能力、证据及受影响部分；继续完成不依赖该缺口的工作，但不要用空方法、TODO、假返回值或绕过公共入口伪装前置可用，也不要自动扩大任务去实现整个前置节点。

三、评估旧实现，决定复用或重构
工程中已有部分实现来自项目构思尚不完整的阶段。先依据用户当前明确要求、目标节点、相关已定游戏规则与现行架构约束确定本轮目标，再判断旧实现的适用性。旧代码的存在、已能运行、类名相同或历史投入，都不构成必须保留其设计的理由。旧 Code_Design 和历史方案需要核对是否仍符合当前目标，不能以过时内容覆盖当前已定要求；缺少预先编写的完整设计稿时，自行完成本节点所需的局部技术决定。

按职责、状态所有权、依赖方向、生命周期及对外行为评估相关旧实现，作出以下选择：

1. 设计一致且满足完成条件：直接复用，保留有效代码和资产，不为统一写法或个人偏好重写。
2. 设计思路相近，差异可局部消除：保留有效部分，以达到目标所需的最小改动补齐接口、行为或接线。
3. 核心职责、状态归属、依赖关系或生命周期与当前设计冲突：大胆重构，必要时替换或重做相关部分；允许拆分、合并、更名、调整接口及模块归属，并同步修改所有受影响的工程内调用方和资产。可独立复用的算法、数据或资产仍应保留。

最小改动适用于设计已相容的情况。不要为了减少差异而保留错误结构、复制一套新旧状态、增加层层适配或旁路实现。只保留有实际使用需求的过渡兼容，并说明其使用方与退出条件；完成迁移后清理本次取代的旧入口、重复逻辑与失效引用。也不要因局部存在冲突就推翻无关系统。

简短列出关键部分的“复用／适配／重构”判断、依据与影响范围，然后直接实施；此判断是执行记录，不是等待批准的独立设计阶段。旧实现与当前已定设计冲突时，按当前设计改造工程。若冲突发生在当前有效的节点要求、游戏规则或全局架构约束之间，列明具体来源和差异，针对真正未决的规则或约束请求澄清，同时继续不受影响的工作。

四、确定本次增量并实现
从节点描述和相关已定规则提炼可观察的完成条件，简短说明本次会新增什么能力、复用什么前置、主要修改哪些对象，然后直接实施，不为普通技术选择逐项请示。

类拆分、成员、数据结构、引擎机制和局部算法由你在当前已定架构约束内决定；允许改变旧代码呈现的结构。涉及共享接口、状态所有权、初始化、广播订阅、异步取消或资源释放时，先确定准确协议，再同步调整受影响的实现与调用方，使它们共同遵循该协议。只为真正需要的扩展建立抽象，不为下游未来节点提前搭建整套框架。

重构前确认影响范围，改造时一并处理程序集依赖、场景与 Prefab 引用、组件绑定、序列化字段及已有数据的迁移；只处理本次实际受影响的项目。类型或文件迁移需要延续 Unity 资产身份时保留对应 .meta/GUID，字段或数据结构变化采用适用的迁移方式，不能用重新生成空资产或清空数据掩盖迁移缺口。

Unity 功能要完成实际接线：脚本、场景、Prefab、配置或资产需要绑定时一并完成；不要只交付无人调用的脚本。现有工具无法安全完成某项编辑器操作时，写明尚缺的具体接线、影响及可执行操作，保持任务为未完整验收，不伪称已经可用。

不要自行改变已定玩法或全局架构约束；旧实现的技术结构调整按第三节直接执行。需要超出本消息范围或无法定位工程等关键信息时，一次说明最少缺项，同时继续不受影响的工作。

五、验证功能结果
检查本节点的核心成功路径及适用的拒绝、失败或生命周期边界，并验证受影响且仍符合当前设计的前置与既有功能未回退。按当前设计明确替换的旧行为应记录变化依据，不把保留所有历史行为作为验收条件。使用工程现有的编译、测试及 Unity 工具完成与改动相适应的检查；涉及场景表现或交互时，尽可能在实际场景验证。

发生重构时，额外核查受影响的调用链、初始化与释放、场景及 Prefab 接线和数据迁移；检索被移除类型、旧入口和旧字段的残留引用，确认迁移已覆盖实际使用点。不能只证明新代码单独可用而忽略工程集成。

不要为凑数量编写与实现同构的测试。不能运行 Unity 或缺少必要环境时，仍完成能做的检查，准确区分已验证、静态确认和未验证内容。仅编译通过或文件生成，不等于节点行为已验收。

六、交付与记录
为本次执行使用唯一任务标识，按资料库适用规则归档必要记录。将影响后续节点的技术决定、接口使用方式和验证证据简要记入本任务记录；准确字段和签名以源码为准，不重复抄写一套平行设计稿。

最终说明：节点定位；完成的可观察能力；旧实现哪些复用、适配或重做及理由；主要变更文件、调用方与资产迁移；实际执行的验证与结果；未完成或未验证事项；后续节点可以直接使用的入口。状态如实区分“完成且已验证”“实现完成但待运行验证”“前置阻塞或部分完成”。本轮不修改图上的正文或任何状态，也不把代码存在当作验证完成。
```

## 定位填写示例

```text
目标节点：瓦片地图 / 2 / 禁行地块
Unity 工程：【替换为实际工程绝对路径】
```

这只说明填写方式，不表示该节点的前置当前已完成，也不代表本次已授权执行这个示例节点。节点不必是一个类；同一个类可以在后续节点中继续扩展。

## 同一任务中断后的续接提示词

```text
继续完成本任务的目标节点。先读已有任务记录与断点，核对当前节点、数据库和工程仍是同一组输入，再检查 git 变更及已完成验证。从未完成部分接着实施，复用已经符合当前设计的成果；发现旧实现或本任务已有实现与当前设计冲突时，继续按“复用／适配／重构”原则处理，并更新受影响的验证结论。不把未经运行的检查改记为通过。原授权、必要重构权限和单节点功能范围继续适用。
```

续接段用于原任务保留上下文的情况。全新任务或新智能体还应一并收到启动提示词及原任务记录位置。
