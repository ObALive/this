## 三、核心链路（系统关系总览）

```
局外（持久）：
  线索树查看 / 剪枝调配 / 概率池 → 规划下一局 → 开新局（局生成与种子：日程/地图/行情生成）
        ▲                                                          │
        │ 结算写入                                                  ▼
        │                                          局内（每局独立世界线）：
        │                                     世界地图探索（移动、对话，不耗时间）
        │                                                     │
        │                                                     ▼
        │                                      发现事件 → 日程抉择（进入 / 拒绝）
        │                                                     │
        │                                                     ▼ 确认进入（时间推进）
        │                                         事件执行：战斗 / 剧情 / 贸易 / 探索 / 委托
        │                                                     │
        │                                                     ▼
        │                                     收益：钱、货、情报、装备、遗物（资源即战力）
        │                                                     │
        │                                                     ▼
        └────────────────────── 关底事件 → 结局 → 局末结算 ←──┘
```

三条系统耦合主线：

1. **时间链**：时间机制（02-10）→ 日程抉择（02-20）→ 事件执行（02-30）→ 世界线走向（03-10）——"时间即路线"；
2. **资源链**：经营（05）与战斗（06）共享同一套资源与成长——"资源即战力"；情报（05-50）直接改变战斗战术与结果（06-A0）；
3. **知识链**：局内情报与解锁内容 → 结算写入线索树（07-40）→ 线索树/剪枝/概率池（07）→ 经局生成（09-20）塑造下一局环境（03-10）——"知识改变世界"。

## 四、跨域关注点

- 全部跨系统交互逻辑清单：`00-总览/01_设计原则与跨系统交互逻辑_v1.md`；
- 术语统一：`00-总览/02_术语表_v1.md`；
- 重大取舍决策（砍掉/不做/悬置）：`00-总览/03_设计决策记录_v1.md`；
- **局生成定主（C02）**："种子→本局日程/地图/行情生成流程"由 09-20 局生成与种子负总责；03-10 世界线只保留叙事框架，不再承担生成流程设计；
- **02 域合并（C-02-bb-01）**：时间、日程、事件、探索四个系统合并为 02-时间与事件域，理由是四者共用事件这一操作对象且相互耦合最密；原 04-探索与事件域的编号 04 停用不复用，指向旧域编号的引用一律改写为新域编号；
- **场景变化包装为事件（C-02-bb-01）**：世界场景的全部变化在程序上包装为事件执行，形式是没有流程、日程中不可见、没有投入产出、玩家不可感知的强制事件；该机制使 02-30 事件系统成为世界状态变化的统一执行入口；
- **时间语义与强制事件（C-02-bb-01-fix，C-02-bb-02 更新）**：时间以时间段为基本刻度、一个时间段的长度固定为 10 分钟；世界时间只在玩家进行有效行为时推进，是角色实力与玩家实力对齐的调整；强制事件本质是普通事件经属性组合包装而成，分三类：部分主线事件（日程提示窗口和位置）、场景转换包装事件（不需提示）、由玩家其他游戏行为触发的强制事件（起因经过结果需玩家调查），错过后果与失败进入属于第三类；
- **数据更新时机通则（C-02-bb-02）**：全局数据在局末更新结算，场景局内数据通常在事件结束后更新结算，玩家数据在事件内实时结算，特例在开发过程中确认；各系统涉及数据更新的部分按此规律标注更新时机；
- **甘特图悬置（C-02-bb-02）**：未来事件以甘特图方式展示、玩家在甘特图界面预编排后续事件参与计划；连同依赖未来事件展示的事件错过提示移入未来开发计划，demo 阶段只做已经历事件；
- **02 域问题汇总（问题汇总）**：02-时间与事件域全部未拍板与待设计问题统一汇总于 `02-时间与事件/02_时间与事件问题汇总_v1.md`，问题逐条详细说明见 `02_时间与事件/02_时间与事件问题说明_v1.md`，各系统文档正文只收录已敲定内容；
- **剧情内容接口（C02）**：03-30 剧情与叙事内容 ↔ 05-50 情报与解谜（剧情文本中的情报字段）、↔ 07-10 线索树核心（剧情文本与线索树情报同步、未触发支线记录）；
- 战斗域内部 10 个子系统间耦合最密（行动槽、时间轴、技能、库存联动互相引用），填充顺序建议先 10-战斗总览定"决策主角"与复杂度预算，再自上而下展开（依据 B01 结语议题 1）。
