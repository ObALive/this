## 一、创意文档既定术语（源自 §4）

| 术语 | 定义 |
| --- | --- |
| 事件 | 日程中占据一定持续时间、具有入口开放窗口期、经地图交互发现并确认进入、推进世界线或产出资源的内容单元。事件类型包括战斗、剧情、贸易、探索与委托 |
| 时间段 | 世界时间的基本刻度。一个事件占据一个或多个时间段，占据的数量即该事件的持续时间 |
| 入口开放窗口期 | 事件允许玩家进入的时间段区间。累计时间越过窗口期后，事件本局失效 |
| 日程 | 玩家对后续时间段执行哪些事件的安排，是本游戏路线抉择的载体；日程表同时记录每段时间经历了哪些事件 |
| 世界线 | 一局游戏对应的剧情走向。每局一条世界线，互不继承 |
| 大关 | 游戏世界的主线章节。一局游戏的范围就是一个大关 |
| 关底事件 | 每个大关的最终事件，通过关底事件即完成该大关内容 |
| 真结局 | 以额定条件通过默认关底事件达成的结局 |
| 隐藏关底事件 | 在收集了足够线索与信息的前提下才可能触发的隐藏版关底事件，难度显著高于默认关底 |
| 线索树 | 局外元进度系统，记录玩家已解锁的全部内容及其关系，详见创意文档 §5 |
| 剪枝 | 玩家在局外主动选择线索树节点进行暂时封锁并按需撤销的进度回溯机制，详见创意文档 §5.6 |
| 行动槽 | 战斗中记录行动序列的容器，详见创意文档 §10.5 |
| 连携技能 | 以行动序列为释放条件的技能，详见创意文档 §10.5 |

| 读招敌人 | 敌方 AI 针对玩家出招类型的应对行为（如架开重击、闪避连续轻击） | B01 战斗研讨 |

| 点亮即示 | 战斗 UI 逐位对照槽尾序列与连携成本串、差一步时高亮提示的引导设计 | B01 战斗研讨 |
| 决策主角 | 一局游戏核心决策时间应花在哪个系统上的裁定（B01 建议：日程与情报是主舞台，战斗与经营是决策的兑现场） | B01 评价书 |
| 首小时体验线 | 首局内让玩家完整经历一次"获得情报→情报改变战斗结果或解锁事件→结算写入线索树→看到新占位节点"闭环的体验设计 | B01 评价书 |

| 自由移动 | 探索阶段活动范围内的基本位移方式：键盘方向输入连续移动（a/d/w/s 速度合成）或 shift 长按点选位置自动寻路，承担发现职能，零成本 | C-01-10-01、C-01-10-03、C03 修订 |
| 快速移动 | 探索阶段跨范围位移方式的总称：离开活动范围的转移事件与远距离的载具租赁事件；活动范围内只有免费徒步移动 | C-01-10-01、C-01-10-03 修订 |
| 载具租赁事件 | 远距离快速移动的事件包装：以租赁载具形式在交通站点之间移动，投入金钱和更少的时间成本，获得更远的基点位置与活动范围变化；时间消耗属于日程；经济接口归事件系统快速移动章节 | C-01-10-02、C-01-10-03 修订 |
| 危险地形 | 对进入其中的单位产生数值影响的地形（毒池、火焰、泥泞）；探索阶段保持封锁，经安全通道通行；战斗阶段实际结算 | C-01-10-01、C-01-10-03 修订 |
| 隐藏事件 | 入口不揭露以强调稀缺性的事件；进度与其他支线事件一样由线索树保留；区别于隐藏关底事件 | C-01-10-01、C-01-10-03 修订 |
| 基点 | 自由探图阶段划定活动范围的基准位置，取玩家结束上一个事件的位置 | C-01-10-02 |
| 活动范围 | 以基点为中心划定的自由探图区域：范围内免费徒步移动与 shift 长按点选寻路；范围外为封锁区域；范围大小取决于主控角色行动力相关数值 | C-01-10-02、C-01-10-03、C03 修订 |
| 封锁区域 | 自由探图阶段活动范围之外的区域：交互上不可通行，统一携带封锁理由与允许的通行方式两个接口，活动范围机制纳入锁定区代码实现 | C-01-10-02、C-01-10-03、C-01-10-04 修订 |
| 转移事件 | 玩家离开活动范围的过程包装而成的事件，投入产出为支付时间、获得基点位置与活动范围变化；时间消耗属于日程 | C-01-10-02、C-01-10-03 修订 |
| 安全通道 | 危险地形上供玩家通行的位置，主要形式是地图上只有自由探索环节才能交互的位置；出入口包装为不可见、不可通过的场景道具，f 键交互到达对端；确保探索环节能够通过，营造环境氛围感，并在战斗环节造成实质影响 | C-01-10-02、C-01-10-03、C03 修订 |
| 行动力 | 决定活动范围大小的主控角色属性 | C-01-10-02 |
| 信息揭露 | 线索树更新后，后续局中已解锁事件信息的呈现机制：以文案包装的位置提示告知事件可能发生的位置，靠近后显示全量信息，窗口期错过后给出提示；效果上线后测试验证 | C-01-10-02、C-01-10-03 修订 |
| 交通站点 | 道路网络上的载具停靠点，载具租赁事件的出发与抵达位置 | C-01-10-03 |
| 道路网络 | 连接交通站点的路线系统，约束载具租赁的移动路径与目的地 | C-01-10-03 |
| 封锁理由 | 封锁区域的两个管理接口之一：管理封锁与解封过程 | C-01-10-03、C-01-10-04 修订 |
| 允许的通行方式 | 封锁区域的两个管理接口之一：记录该区域仍然开放的交通手段，例如路面维修区域仍可通过地铁抵达 | C-01-10-04 |
| 支线进度阶段化 | 线索树解锁进度达到一定程度后，玩家在一局内再次进入支线时从之后的阶段开始、简化部分流程的机制，隐藏事件同样适用 | C-01-10-04 |
| 速度合成移动 | 方向键移动的速度计算方式：未按移动键时速度向量为零，按下方向键为角色叠加对应方向的速度向量，角色以最终合成方向向量为准移动 | C03 |
| 奔跑 | shift 长按开启的移动加速状态，按住 shift 移动时生效，提升赶路效率 | C03 |
| 点选移动模式 | shift 长按解锁的自动寻路模式：长按 shift 期间点击地图可通行区域，目标点可达且距离未超限时角色自动奔跑前往 | C03 |
| 场景道具交互 | f 键的通用功能：与场景道具交互，交互对象规则由各系统定义；安全通道出入口即被包装为不可见、不可通过的场景道具 | C03 |
| 对话分支图 | 组织对话内容的结构化图：保存下一句话是什么、不同的回答各自走向哪里；以 json 配置文件承载，设计阶段约定配置文件格式与解析契约；玩家选项与游戏进度（携带物品、健康状态等数值）均参与分支走向判定 | C-01-20-01 |
| 文本库 | 单独保存剧情文本全局阅读状态的数据结构：判定标准为全局范围，过去所有游戏场次中都未出现过的文本为未阅读文本；不受线索树剪枝影响 | C-01-20-01 |
| 富文本 | 对话框文本的呈现效果：彩色、粗体、斜体、抖动、打字机式逐字出现等；动画播放完毕前单击立即结束动画显示全文；扩展开发以预留接口方式登记 | C-01-20-01 |
| 最小时间粒度 | 时间划分的最小单位 10 分钟，自 10 分钟往上的小时、天、月、年与现实一致；全部时间参数与时间消耗都落在 10 分钟的整数倍上 | C-02-bb-01 |
| 游戏内日历 | 游戏内虚构的一套日历，历法结构与现实一致，程序按现实历法计算闰年与闰月，例如游戏内现代设定为 1900 年时按现实的 1900 年判断闰年 | C-02-bb-01 |
| 事件状态 | 事件在生命周期中所处的状态，分为未出现、可进入、进行中、已完成、已错过五种；拒绝进入不改变状态，窗口期结束使可进入转为已错过 | C-02-bb-01 |
| 事件流程 | 玩家经历一个事件的五个步骤：到达事件地点、交互目标并确认进入、时间在参与事件的过程中逐步推进、达成结束条件、退出事件并结算玩家资源与时间 | C-02-bb-01 |
| 场景变化包装事件 | 世界场景变化在程序上的执行形式：没有流程、日程中不可见、没有投入产出、玩家不可感知的强制事件，例如楼房区域变为火场区域 | C-02-bb-01 |
| 区域形态 | 区域在某一时刻的状态，例如楼房、火场、废墟；形态决定该区域上事件池的刷新范围与窗口期长度 | C-02-bb-01 |
| 日程表 | 日程系统的界面，完全套用手机与电脑当中的时间与日期系统，参照 Ubuntu 26 桌面点击屏幕上方时间后显示的页面，Notification 显示区改造为日程表；呈现已经历、正在经历与规划中三类事件 | C-02-bb-01 |

## 三、术语命名待定事项

- "线索树"为暂时代称，正式命名待世界观确定后定夺（创意文档 §5.3）；
- 战斗类别字母 A/B/C/D 的包装词汇（B01 建议方向：轻击/重击/架势/射击）待总监拍板（创意文档 §10.4、B01 战斗研讨第五节）；
- 市场用语"搓招"与"决策式连招/排招"的取舍待总监拍板；
- 队友与伙伴：任务书 C-02-bb-01 描述激进排除隐患的后果时使用"伙伴牺牲"，库内既有称谓是队友，两者指同一类成员还是两类成员待总监确认，系统文档当前统一写为队友。
