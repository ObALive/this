## CBT2-GAP-001 战斗域允许追加子系统，但新系统的范围、名称与编号方式尚未确定

| 字段 | 内容 |
| --- | --- |
| 等级 | B0 |
| 责任方 | 游戏总监 |
| 来源 | C-06-bb-02 回答 CBT-GAP-001；06 战斗索引填充顺序建议；README 系统编号扩容规则 |
| 影响范围 | 06 战斗索引、00-总览/00 系统全景图、README、06 全域 |
| 关闭条件 | 确定战斗域新增子系统的清单、命名与编号 |

**候选 A：候选 A：本阶段暂不新增系统，先把新规则并入现有子系统**

方案：维持现有十个子系统。元效果并入遗物系统、容器搜刮与敌方遗体并入战场与战棋规则、四类动作词汇并入技能系统、配置表挂在对应系统目录下。战斗域系统数量不变，只增加各系统的具名子节与配置表。

代价与影响：系统清单与编号完全稳定，全部引用不需要更新。代价是遗物系统与战场规则的职责范围变宽，元效果与容器搜刮这类通用能力挂在具体系统下不易被其他域发现。

**候选 B：候选 B：新增元效果系统，其余规则并入现有子系统**

方案：在 06 域新增一个系统，编号取 75，位于遗物系统 70 与技能与库存联动 80 之间，命名为元效果系统，承担增益、状态、持续伤害、防护与穿透的统一模型与元效果表的维护。其余新规则并入现有子系统：容器搜刮与敌方遗体并入战场与战棋规则，四类动作词汇并入技能系统。

代价与影响：元效果获得独立归属，遗物、装备、道具、技能四类来源共用同一套效果模型，后续新增效果类型有明确落点。代价是系统清单增至十一个，需要同步更新索引、全景图与编号说明，且战斗域已超过九个系统锚点的问题需要一并处理。

**候选 C：候选 C：新增元效果系统与战斗行为系统**

方案：在 06 域新增两个系统，分别承担元效果统一模型与战斗行为规范化管理，编号取 75 与 85。战斗行为系统维护战斗行为表，定义玩家可控角色在战斗中可执行的全部行为及其契约字段。

代价与影响：两项通用能力各有独立归属，扩展方向最清晰，战斗行为的增改有统一入口。代价是系统清单增至十二个，编号与索引改动最大，且战斗行为与技能系统的职责边界需要在两者之间划清。

## CBT2-GAP-002 角色属性集合未定义：力量、行动力与专长契合等属性在多处被引用，属性归属与接口未闭合

| 字段 | 内容 |
| --- | --- |
| 等级 | B0 |
| 责任方 | 游戏总监 |
| 来源 | C-06-bb-02 回答 CBT-GAP-010、CBT-GAP-040、CBT-GAP-045；06-10 §4.2；01-40 §4.1；01-10 §3.2 |
| 影响范围 | 06-10 战斗总览、06-60 装备系统、01-40 角色与小队、01-10 移动系统、09-10 数值模型 |
| 关闭条件 | 确定参战单位属性集合的归属与最小接口 |

**候选 A：候选 A：由战斗总览维护单位属性总表**

方案：参战单位的属性集合与含义由战斗总览统一维护，包含生命、伤势、行动力、力量与行动速度五类。角色与小队负责角色的属性取值来源，移动系统读取行动力用于活动范围，战斗总览读取力量用于投掷折算，时间轴读取行动速度用于行动延迟补正。属性数量与取值范围由数值侧给出。

代价与影响：属性只有一份权威定义，四个系统的读取关系清晰，后续新增属性有唯一落点。代价是战斗总览的职责范围扩大到全游戏通用属性，需要与角色与小队划清取值来源与属性定义的边界。

**候选 B：候选 B：在战斗总览内以具名子节定义，不升级为独立系统**

方案：沿用战斗总览现有的健康与单位属性具名子节，把行动力、力量与行动速度并入该子节，不新增系统也不新增属性表。各系统按子节引用属性名称。

代价与影响：改动最小，不需要新增系统或配置表，与现有文档结构一致。代价是子节内容持续变厚，属性被多个域引用时缺少独立的权威文档，后续可能仍需拆分。

**候选 C：候选 C：属性只在各系统内部定义，跨系统只约定接口名称**

方案：各系统自行定义读取的属性项，跨系统只约定接口字段名，例如移动系统按行动力取值、战斗域按力量取值，属性之间的换算与依赖由数值模型台账登记。

代价与影响：各域自治，改动局部化。代价是同一属性可能在多处出现不同解释，跨系统一致性依赖数值台账的人工校验。

## CBT2-GAP-003 战斗内搜刮的时机与行动成本未定义：容器搜刮已登记为独立行为，但其时间、次数与战斗结束后的搜刮窗口没有规则

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 回答 CBT-GAP-006、CBT-GAP-026、CBT-GAP-034；战斗行为表 BHV-INTERACT-001 |
| 影响范围 | 06-30 战场与战棋规则、06-A0 战斗目标与结果、05-30 背包系统、战斗行为表 |
| 关闭条件 | 定义搜刮的入口、行动成本与战斗结束后的处理 |

**候选 A：候选 A：搜刮占用行动机会，战斗结束后的窗口自由搜刮**

方案：战斗过程中搜刮一个容器占用该单位一次行动机会，按移动规则追加 M 字母并参与时间轴计算，同一容器可多次搜刮直到取空。战斗结束后进入不限时的安全窗口，此时搜刮不消耗行动机会，玩家可以逐个容器整理物资，窗口中不推进世界时间。

代价与影响：战斗中的取舍明确，搜刮与连携构建形成互斥，战斗结束后的整理不打断节奏。代价是战斗内搜刮的机会成本较高，敌方遗体较多时会拉长战后整理时间。

**候选 B：候选 B：搜刮不占用行动机会，只受每轮次数限制**

方案：战斗过程中每个单位每轮次可以搜刮有限个容器，不消耗行动机会也不追加字母，超出次数上限后需要等待下一轮次。战斗结束后取消次数限制。

代价与影响：搜刮的门槛低，玩家不会因搜刮而牺牲输出机会。代价是搜刮与战斗决策解耦，搜刮最优解变成每轮都搜满，机会成本的设计意图减弱。

**候选 C：候选 C：战斗内不可搜刮，统一在战斗结束后搜刮**

方案：战斗中容器与敌方遗体不可交互，战斗结束时才开放搜刮，此时不消耗行动机会、不推进世界时间，玩家可以完整整理全部战场物资。

代价与影响：战斗流程最紧凑，玩家注意力集中在战斗本身，物资整理集中在一处。代价是战斗中的战术选择少了一层，例如抢夺敌方补给或破坏敌方物资的玩法无法表达。

## CBT2-GAP-004 重量与力量属性向投掷伤害的折算规则未定义，属性本身也尚未注册

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 数值策划 |
| 来源 | C-06-bb-02 回答 CBT-GAP-010；元效果表 EFF-THROW-001 |
| 影响范围 | 06-80 技能与库存联动、05-05 物品系统、09-10 数值模型 |
| 关闭条件 | 定义重量到投掷伤害与后摇的换算关系 |

**候选 A：候选 A：按重量与力量的比值折算伤害，比值决定后摇档位**

方案：投掷无伤害组件物品时，以物品重量与角色力量属性的比值决定伤害与后摇：比值越大伤害越高、后摇越重；比值低于下限时视为投掷无效。不引入随机因素。

代价与影响：规则可预期，玩家可以从物品重量与角色力量直接推断投掷效果，与拟真取向一致。代价是需要为每个可投掷物品登记重量，物品策划的配置量上升。

**候选 B：候选 B：按物品重量分档，力量属性提高上限档位**

方案：物品重量划分为若干档位，每档对应固定的伤害与后摇；角色力量属性决定可投掷的最高档位，超出档位的物品无法投掷。

代价与影响：档位便于配置与平衡，玩家只需要理解分档。代价是连续量被离散化，力量属性的收益呈阶梯状，边界物品的手感差异不明显。

**候选 C：候选 C：系统只输出重量与力量的比较结果，伤害与后摇全部由数值侧给出**

方案：系统层只定义投掷判定需要读取重量与力量两项属性，并输出比较结果；伤害、后摇与失败阈值全部由数值侧配置，系统不规定折算形式。

代价与影响：系统层保持纯粹，数值侧可以自由调整手感。代价是投掷表现完全依赖数值配置，系统文档无法回答投掷轻重与伤害的大致关系。

## CBT2-GAP-005 法术的组件结构与条目形态未定义：法术由元物品加组件构建，但其组件类型与配置位尚未确定

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 回答 CBT-GAP-011；06-80 §4.2；05-05 §2.2 |
| 影响范围 | 06-80 技能与库存联动、06-40 技能系统、05-05 物品系统、元效果表 |
| 关闭条件 | 定义法术的组件构成与在技能面板中的配置位 |

**候选 A：候选 A：法术沿用物品组件模型，由元物品加效果组件与伤害组件构建**

方案：法术与物品共用同一套组件模型：法术的元物品挂载效果组件与伤害组件，可携带元素标记，可拥有堆叠组件表达同类法术的数量。法术在技能面板中单独占用配置位，与四个基础技能位和五个连携技能位并列且互不占用。

代价与影响：组件模型全库统一，法术、道具、装备与遗物共用同一套效果表达与元效果结算，后续新增法术类型不需要新机制。代价是法术需要以物品实例的形式保存与管理，背包与技能面板两处都需要处理法术条目。

**候选 B：候选 B：法术使用专属的法术定义结构，只复用效果组件**

方案：法术使用独立的定义结构，保存法术标识、类别归属、目标类型与效果引用；效果本身复用元效果与效果组件。法术不进入物品实例体系，只存在于法术库中。

代价与影响：法术与物品解耦，法术库管理简单，不需要为法术维护物品实例。代价是法术无法参与物品层面的玩法，例如交易、掉落与容器收纳，知识资产的表达少了一条路径。

**候选 C：候选 C：法术并入技能系统作为第三种技能类型**

方案：不建立独立的法术条目结构，法术作为技能系统中的第三种技能类型存在，与基础技能、连携技能并列，只是获取方式为获得型。检索技能调用时从已获得的法术中选择。

代价与影响：技能体系内统一，配置位与界面呈现简单，法术与技能的继承与连携规则可以直接复用。代价是获得型与习得型两种来源混在一个系统内，与技能库由交易获取的定位需要重新划界。

## CBT2-GAP-006 法术与技能库的关系边界未定义：两者并行获取，但清单归属、界面归属与相互影响规则未写明

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 回答 CBT-GAP-011、CBT-GAP-030；06-40 §4.1；06-80 §4.2 |
| 影响范围 | 06-40 技能系统、06-80 技能与库存联动、07-10 线索树核心 |
| 关闭条件 | 定义法术与技能的清单归属、界面归属与相互影响 |

**候选 A：候选 A：两套内容契约分开，界面统一为一个技能面板**

方案：法术库与技能库各自维护清单与获取规则，法术为获得型、技能为习得型。技能面板把基础技能、连携技能与法术三类内容分区呈现，法术自带独立的配置位。连携成本串可以使用法术的类别字母，法术不参与基础技能的四类骨架约束。

代价与影响：两类内容的来源差异被保留，玩家在一处完成全部战斗配置，界面只有一套。代价是技能面板需要承载三类内容，信息密度上升，配置位数量增加。

**候选 B：候选 B：法术以技能形式呈现，只是获取方式不同**

方案：法术在技能面板中与连携技能同列表呈现，用图标区分获得型与习得型。法术的类别归属与连携成本串的匹配规则与连携技能完全一致，不设独立配置位。

代价与影响：玩家心智模型最简单，只有一套技能列表，配置位数量不变。代价是获得型与习得型的差异只能靠图标与文案表达，来源规则在界面上不显著。

**候选 C：候选 C：法术不进入战斗配置，由检索技能在战斗内临时选择**

方案：法术不占用任何配置位。检索技能在战斗内被释放时打开法术库，玩家从已获得的法术中选择一个立即释放，选择结果不保存为配置。

代价与影响：配置负担最低，法术的使用完全由战斗内的临场决策驱动。代价是玩家无法在战前规划法术组合，检索技能的构筑意义下降。

## CBT2-GAP-007 未被敌方察觉的判定规则未定义：Demo 以受到伤害作为察觉标准，其余察觉来源与解除条件没有规则

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 回答 CBT-GAP-015、CBT-GAP-017；06-30 §4.1 |
| 影响范围 | 06-30 战场与战棋规则、06-90 敌人与AI、02-40 探索系统 |
| 关闭条件 | 定义察觉状态的进入与解除规则 |

**候选 A：候选 A：只保留受到伤害触发察觉，其余来源全部等到侦查系统立项**

方案：战斗内察觉状态只由受到伤害触发，一旦触发即进入常规战斗，敌方按行为模板正常行动。潜行、侦查与被侦查相关内容不进入 Demo，系统层只保留察觉状态这一处接口。

代价与影响：判定标准单一且可预期，玩家只需要理解攻击即暴露，与回答完全一致，实现成本最低。代价是布置阶段的持续时间完全取决于玩家何时出手，缺少其他进入战斗的方式。

**候选 B：候选 B：补充我方行动触发察觉，形成一张最小判定表**

方案：除受到伤害外，我方在布置阶段执行攻击类、投掷类与场景交互类行为同样触发察觉，移动与道具使用不触发。判定表登记在战场与战棋规则中，后续新增行为时同步登记。

代价与影响：判定标准可扩展，行为与暴露的关系明确，后续补入侦查系统时只需往表里加行。代价是需要逐条判断每个行为是否暴露，配置与测试量上升。

**候选 C：候选 C：察觉改为由敌方感知范围决定**

方案：敌方拥有感知范围，我方单位进入该范围或在其内执行行为时触发察觉。布置阶段玩家可以看见敌方感知范围的预览。

代价与影响：空间判定最直观，站位与潜入的战术价值高，与战棋的空间规则一致。代价是需要新增感知范围属性与可视化，规则量明显上升，与 Demo 阶段以受到伤害为标准的回答不一致。

## CBT2-GAP-008 布置阶段的具体规则未定义：布置期间的行动、范围限制、时间与结束条件没有规则

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 回答 CBT-GAP-015；06-30 §4.1；02-10 §4.3 |
| 影响范围 | 06-30 战场与战棋规则、06-20 时间轴与行动顺序、02-10 时间机制 |
| 关闭条件 | 定义布置阶段的行动范围、时间处理与结束条件 |

**候选 A：候选 A：布置阶段在战场范围内自由调整，不消耗行动机会也不推进世界时间**

方案：布置阶段我方单位可以在战场配置的初始区域内自由调整位置与朝向，调整不消耗行动机会，时间轴不启动，世界时间不推进。玩家确认布置完成后时间轴开始运转。察觉触发时立即结束布置阶段并进入常规战斗。

代价与影响：布置与战斗的边界清晰，站位准备充分，与探索阶段时间静止的规则一致。代价是玩家可能用布置阶段反复试探战场信息，需要限制可查看的信息范围。

**候选 B：候选 B：布置阶段消耗真实的行动机会**

方案：布置阶段与战斗共用同一套行动机会，调整位置占用单位的行动机会并参与时间轴计算，玩家可以选择不调整直接开战。

代价与影响：站位的价值被计价，与排招的节奏设计一致，规则只有一套。代价是抢先开战与充分布置之间形成硬取舍，未察觉状态下仍要付出行动代价，与获得充足时间的设定存在张力。

**候选 C：候选 C：布置阶段做成独立的事件片段**

方案：布置阶段作为战斗片段之前的一个独立事件片段，拥有自己的操作与退出条件，退出后进入战斗片段。布置片段的可用操作由事件配置决定。

代价与影响：布置的内容可以按战斗单独配置，例如某些战斗允许布置、某些不允许，事件编排最灵活。代价是需要在事件片段类型表中再补一个片段类型，流程被切成两段。

## CBT2-GAP-009 倒地与伤势的恢复规则未定义：轻伤、重伤与致残三档的后果、救治次数与战斗结束后的恢复路径没有规则

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 游戏总监 |
| 来源 | C-06-bb-02 回答 CBT-GAP-003、CBT-GAP-037；06-10 §4.2；战斗行为表 BHV-COMBAT-001 |
| 影响范围 | 06-10 战斗总览、06-A0 战斗目标与结果、01-50 存档与持久化、战斗行为表 |
| 关闭条件 | 定义三档伤势的后果与恢复路径 |

**候选 A：候选 A：救治次数有限，伤势档位决定救治难度与战斗外恢复成本**

方案：同一单位在战斗内的救治次数按伤势档位限制：轻伤可多次救治，重伤在一次战斗中至多被救治一次，致残无法在战斗内救治。战斗结束后倒地单位按伤势档位进入恢复流程，轻伤可通过常规恢复道具处理，重伤需要专门恢复资源，致残保留到本局结束。

代价与影响：伤势形成跨战斗的资源压力，与健康状态占极大比重的设计意图一致，救治成为有次数的战术资源。代价是玩家需要跟踪每个单位的救治次数与伤势档位，界面信息量上升。

**候选 B：候选 B：救治次数不限，代价体现在行动机会与资源消耗**

方案：救治不设次数上限，每次救治消耗一次行动机会与一份恢复资源，恢复量随伤势档位递减。战斗外恢复按同样口径处理，不设专门的恢复流程。

代价与影响：规则只有一条，玩家只需要关注资源是否充足，界面信息最少。代价是反复救起会让倒地几乎没有代价，健康状态的紧张感下降。

**候选 C：候选 C：救治无限且免费，伤势只影响战斗外状态**

方案：战斗内救治不消耗资源也不限次数，倒地与救起只影响当次战斗的节奏。伤势档位在战斗结束后生效，决定战斗外需要处理的状态与成本。

代价与影响：战斗内的容错最高，战斗节奏不受资源约束。代价是战斗内缺少代价层，与资源即战力的整体设计脱节。

## CBT2-GAP-010 战斗行为表的字段契约与字段取值未定案：表已建立，但各字段的取值集合与新增流程需要固化

| 关闭条件 | 固化战斗行为表的字段含义与新增行为的登记流程 |

**候选 A：候选 A：字段契约写入战斗总览正文，新增行为必须同时登记表与正文**

方案：战斗行为表的字段含义与取值规则写入战斗总览正文，作为权威定义。新增战斗行为时必须同时修改表内记录与总览正文，并在受影响的子系统文档中登记该行为的时间与后摇口径。

代价与影响：表的权威性与扩展流程明确，后续新增行为有固定路径，配置与实现不会各写一套。代价是每次新增行为都要改三处文档，流程较重。

**候选 B：候选 B：字段契约由表自身承载，正文只保留指向**

方案：字段含义与取值规则写在表的扩展说明列中，正文只保留指向表的链接与一句职责说明。新增行为只改表，正文不随每次新增而修改。

代价与影响：文档改动最小，表是唯一事实来源，新增行为的成本最低。代价是正文读者需要跳到表才能理解战斗行为的完整契约。

**候选 C：候选 C：表只作清单，完整契约由各子系统分别定义**

方案：表只登记行为名称与归属系统，每个行为的完整规则由归属子系统在自己的正文中定义。

代价与影响：各子系统的规则完整度最高，读者不需要跨文档拼装。代价是缺少统一契约，同一个行为在两个系统交界处可能出现不同描述。

## CBT2-GAP-012 战斗界面的区块布局与以当前行动者为中心的呈现方式需要统一

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 回答 CBT-GAP-038、CBT-GAP-039；06-10 §4.1 |
| 影响范围 | 06-10 战斗总览、06-20、06-40、06-50 |
| 关闭条件 | 定义四区块布局与选中单位呈现的关系 |

**候选 A：候选 A：四区块固定布局，选中单位只切换详细面板内容**

方案：战场、行动槽、时间轴与技能面板四个区块的布局固定不变。详细状态面板与行动槽跟随当前选中单位切换：默认选中当前行动者，玩家点选其他单位时只切换显示内容，不改变可操作对象，当前行动者之外的单位不显示可操作按钮。

代价与影响：布局稳定，玩家不需要重新寻找信息，选中其他单位查看只影响内容不影响结构。代价是行动槽区块需要在展示非当前行动者时明确标注不可操作状态。

**候选 B：候选 B：以当前行动者为中心的单栏布局**

方案：界面以当前行动者为中心，用主栏集中呈现该单位的状态、技能、行动槽与时间轴摘要，其他单位只显示状态条。点选其他单位时主栏整体替换。

代价与影响：信息集中，切换单位时界面变化清晰，屏幕占用较少。代价是全局态势的可读性下降，玩家不易同时掌握多个单位的连携构建情况。

**候选 C：候选 C：区块固定，另设独立的单位检视面板**

方案：四区块固定布局之外新增一个可收起的单位检视面板，专门承担查看其他单位详情的职责。选中其他单位只影响该面板内容，不改变四个区块的显示。

代价与影响：查看与操作彻底分离，战斗区块的显示永远指向当前行动者，信息不混淆。代价是增加一个界面元素与相应的打开收起交互，屏幕空间占用增加。
