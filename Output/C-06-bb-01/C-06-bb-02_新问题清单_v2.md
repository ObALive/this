## CBT3-GAP-001 法术书与符文书页的物品侧规则未定义：容器约束的表达方式、容量与槽位、书页的装入与取出流程均未写明

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 第二轮回答 CBT2-GAP-005；05-05 物品系统；06-60 装备系统 |
| 影响范围 | 05-05 物品系统、05-30 背包系统、06-60 装备系统、06-80 技能与库存联动、物品操作总表 |
| 关闭条件 | 确定法术书的组件构成、容量约束与书页装入取出的流程 |

**候选 A：候选 A：法术书用容器组件加物品类型约束表达，书页按普通容器格操作装入**

方案：法术书挂载容器组件与武器装备组件，容器的允许内容由物品类型约束配置为只接受符文书页类型，容量与格位由容器组件给出。书页的装入与取出使用容器界面的常规操作，不新增操作类型。

代价与影响：复用既有容器与界面能力，实现与操作成本最低，玩家不需要学习新的装填流程。代价是容器约束需要新增物品类型过滤规则的表达能力，且书页与普通容器物品在界面上不易区分。

**候选 B：候选 B：法术书使用专用插槽组件，每个插槽容纳一页**

方案：法术书挂载法术书组件，组件提供若干固定插槽，每个插槽容纳一张符文书页。装入时界面按插槽排列，玩家把书页拖入插槽。

代价与影响：书页数量与插槽数量在界面上一目了然，法术数量有明确上限，便于数值控制。代价是需要新增一种组件类型与配套界面，与既有容器体系的表达方式不一致。

**候选 C：候选 C：法术书是普通容器，书页类型只作内容提示**

方案：法术书使用标准容器组件，容量与格位按普通容器配置，允许容纳的物品种类不作系统限制，只通过物品描述与界面提示引导玩家放入书页。

代价与影响：规则最少，完全复用现有容器体系，不需要任何新增能力。代价是玩家可以把任意物品塞进法术书，法术书的武器与容器双重身份被稀释，配置错误无法被系统发现。

## CBT3-GAP-002 符文书页的来源未定义：Demo 阶段法术页通过什么途径进入玩家手中没有规则

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 第二轮回答 CBT2-GAP-005、006；06-40 技能系统 §3.3 |
| 影响范围 | 06-40 技能系统、06-60 装备系统、05-10 金钱与货物、05-20 委托系统、02-30 事件系统 |
| 关闭条件 | 确定符文书页的获取途径与投放分工 |

**候选 A：候选 A：符文书页与技能同源，通过事件奖励、委托报酬与交易获取**

方案：符文书页作为普通物品进入既有的获取体系，来源与技能库、装备和遗物一致：事件奖励、委托报酬与交易。法术书本身按武器投放。

代价与影响：获取途径统一，玩家不需要学习新的获取渠道，经营决策可以直接转化为法术能力。代价是法术与技能两条构筑线的获取体验完全同质，法术缺少独立的成长感。

**候选 B：候选 B：符文书页由战斗搜刮与事件掉落为主，交易为辅**

方案：符文书页主要从战斗后的容器搜刮、敌方遗体与事件掉落中取得，少数商人出售。法术的获取与战斗探索绑定更强。

代价与影响：战斗的即时回报多一类产出，搜刮的价值提高，与战利品来自搜刮的整体设计一致。代价是法术获取受随机性影响较大，玩家的构筑计划较难稳定实现。

**候选 C：候选 C：符文书页由线索树解锁后进入物品池**

方案：符文书页在线索树解锁后进入本局的物品池，再由事件、交易或搜刮产出。法术的可用范围最终由局外进度决定。

代价与影响：知识即构筑的定位落到了法术上，元进度有明确的战斗侧产出。代价是元进度与单局随机叠加，玩家较难判断某一局为什么拿不到想要的法术。

## CBT3-GAP-003 投掷法术书的规则未定义：法术书同时是武器与容器，投掷它时按武器还是按容器处理没有规则

| 字段 | 内容 |
| --- | --- |
| 等级 | B2 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 第二轮回答 CBT2-GAP-005；06-80 §5 投掷表 |
| 影响范围 | 06-80 技能与库存联动、06-60 装备系统、05-05 物品系统、元效果表 |
| 关闭条件 | 确定同时具备容器与武器身份的物品在投掷时的处理规则 |

**候选 A：候选 A：法术书按容器类物品投掷，容器内容随物移动**

方案：法术书投掷时按其容器组件处理：以整体为单位投出，书页随容器一同移动并沿用容器随物移动规则，伤害与后摇按重量与力量比值折算。

代价与影响：与既有容器投掷规则完全一致，不需要为法术书单独开一条规则，书页不会在投掷中散落。代价是投掷一本装满书页的法术书在数值上可能与预期不符，需要数值侧单独标定重量。

**候选 B：候选 B：法术书按武器投掷，书页在投掷时散落**

方案：法术书投掷时按武器处理，命中后书页随容器破损散落到落点周围，成为可拾取的独立物品。

代价与影响：投掷的破坏感与拟真感更强，散落的书页形成临时的战场资源，与搜刮体系衔接。代价是需要定义容器破损与内容散落的状态规则，实现量与边界情况明显增加。

**候选 C：候选 C：禁止投掷法术书**

方案：法术书在配置中标记为不可投掷，界面在选中投掷技能时不列出法术书。

代价与影响：避免了双重身份带来的规则歧义，实现最简单。代价是玩家不能用一本旧法术书换取战术效果，与物品离开角色只依据组件判断的原则存在张力。

## CBT3-GAP-004 技能清单与战斗行为类别列举未完成：回答提到技能列表待填充，战斗行为的待补充项也需要一份统一清单

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 第二轮回答 CBT2-GAP-011；06-85 §3.1；06-40 §3.1 |
| 影响范围 | 06-40 技能系统、06-85 战斗行为系统、08-引导与教学 |
| 关闭条件 | 输出技能清单框架与战斗行为待补充项的统一清单 |

**候选 A：候选 A：本轮只定框架，清单由内容设计填充**

方案：技能系统只定义四类动作的作用与配置约束，具体技能清单由内容设计按大关与区域分层填充；战斗行为的待补充项登记在扩展说明中，需要时逐条立项。

代价与影响：系统层不被内容细节拖慢，框架先稳定，内容可以并行推进。代价是战斗与教学在内容清单完成前无法做完整的体验验证。

**候选 B：候选 B：先产出最小可用清单作为 Demo 基线**

方案：本轮先给出一份最小可用清单：四类基础技能各 3 至 5 个、连携技能 8 至 12 个、战斗行为待补充项 3 至 5 条，作为 Demo 的实现与教学基线，后续按需扩充。

代价与影响：Demo 范围可估算，教学与测试有明确对象，进度可控。代价是需要内容侧先投入一轮设计，且清单可能在原型验证后返工。

**候选 C：候选 C：清单与数值一并交由数值与内容侧独立立项**

方案：系统层不产出清单，技能与行为的清单连同数值一起由数值与内容侧独立立项，系统层只提供扩展契约与配置约束。

代价与影响：职责边界最清晰，系统设计保持纯粹。代价是跨系统的体验验证缺少统一基线，系统层难以判断自己的框架是否够用。

## CBT3-GAP-005 敌人类型与强度分层的清单与配置参数未定义，行为模板与波次配置也缺少具体内容

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 回答 17；06-90 §4；09-30 难度体系 |
| 影响范围 | 06-90 敌人与AI、09-30 难度体系、09-10 数值模型、06-A0 |
| 关闭条件 | 输出敌人类型的清单框架与配置参数口径 |

**候选 A：候选 A：敌人清单由内容设计填充，系统层只定义模板契约**

方案：敌人类型、强度分层与行为模板的内容由内容设计填充，系统层只定义模板的字段与敌我交互规则，并说明难度体系如何调制敌人配置。

代价与影响：系统层与内容层职责清晰，敌人内容可以按大关逐个填充。代价是在内容完成前无法验证战斗时长与日程的匹配关系。

**候选 B：候选 B：先定义强度分层的档位与每档的模板骨架**

方案：先定义三到四档强度分层，每档给出行为模板骨架与配置区间，具体敌人按档位归类填充。

代价与影响：强度分层先稳定，数值与内容都拿到可比对的参照，战斗节奏可以被估算。代价是分层可能在实际内容产出后需要调整。

**候选 C：候选 C：随首个大关的内容设计一并产出**

方案：敌人清单不单独立项，随首个大关的事件链与战斗编排一并产出，保证敌人与关卡内容同步设计。

代价与影响：敌人与关卡体验一致，避免先做通用敌人再改造关卡。代价是战斗域的完整验证推迟到关卡设计阶段。

## CBT3-GAP-006 战斗界面的表现形式与信息密度未定案：四区块的布局、各区块的信息优先级与操作方式待设计

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 第二轮回答 CBT2-GAP-012；06-10 §3.6；C03 界面归属裁定 |
| 影响范围 | 06-10 战斗总览、06-20、06-40、06-50、01-60 设置与辅助功能 |
| 关闭条件 | 输出战斗界面的布局方案与信息优先级 |

**候选 A：候选 A：界面设计阶段统一产出，系统层只保留区块职责**

方案：系统层只规定四个区块的职责与选中单位的呈现规则，布局、信息优先级、键位与操作方式整体留到界面设计阶段产出。

代价与影响：系统设计不被界面细节拖慢，界面阶段有完整的设计空间。代价是部分界面需求可能在界面阶段反向提出规则变更。

**候选 B：候选 B：本轮先出线框级布局方案**

方案：本轮给出四区块的线框级布局方案与信息优先级清单，明确每个区块在常态与选中他人时的内容，键位与视觉留到界面设计阶段。

代价与影响：规则与界面的接口提前对齐，后续界面设计有明确约束，返工风险最低。代价是需要一轮额外的布局设计工作。

**候选 C：候选 C：按低分辨率优先设计并向上适配**

方案：先按最低支持分辨率设计四区块布局，再向上适配更大屏幕，保证信息密度上限可控。

代价与影响：保证低配环境可玩，信息取舍的优先级被迫明确。代价是宽屏下的空间利用效率下降，需要额外的适配规则。
