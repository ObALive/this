## CBT4-GAP-001 允许内容约束的类型划分口径未定义：约束按物品类型匹配，但物品类型体系本身还没有清单

| 字段 | 内容 |
| --- | --- |
| 等级 | B0 |
| 责任方 | 主策划 |
| 来源 | C-06-bb-02 第三轮回答 CBT3-GAP-001；05-05 §2.3 |
| 影响范围 | 05-05 物品系统、05-30 背包系统、06-60 装备系统、06-80 技能与库存联动、全部配置表 |
| 关闭条件 | 定义物品类型体系与允许内容约束的匹配规则 |

**候选 A：候选 A：建立物品类型表作为类型体系的权威清单**

方案：新建物品类型表，登记类型标识、类别名、父类型与适用说明，类型之间支持父子层级。允许内容约束按类型标识匹配，匹配规则为包含子类型。物品策划为每个元物品登记所属类型。

代价与影响：类型体系有唯一权威清单，约束、条件判定与投掷组件都引用同一套标识，后续扩展有落点。代价是需要一轮类型梳理，且既有物品需要补录类型字段。

**候选 B：候选 B：类型由物品词条体系兼任**

方案：不单独建类型表，用物品词条表达类型，允许内容约束匹配词条。词条体系已经服务于商人经营范围，可以复用。

代价与影响：不新增体系，词条与类型统一，商人经营与容器约束共用一套标识。代价是词条面向经营与效果，语义较宽，用它表达严格的类型约束容易误配。

**候选 C：候选 C：约束逐容器直接列举允许的元物品**

方案：允许内容约束不做类型抽象，直接在容器配置中列举允许的元物品清单。

代价与影响：规则最直白，不需要类型体系，配置错误一眼可见。代价是每新增一种书页都要改所有法术书配置，物品池扩充时维护成本随容器数量增长。

## CBT4-GAP-002 物品三维数值仍未定义：重量参与投掷折算，但重量的取值口径与是否登记到属性表没有规则

| 字段 | 内容 |
| --- | --- |
| 等级 | B1 |
| 责任方 | 数值策划 |
| 来源 | C-06-bb-02 第二轮回答 CBT2-GAP-004；第三轮回答 CBT3-GAP-003；05-05 §9 |
| 影响范围 | 05-05 物品系统、06-80 技能与库存联动、09-10 数值模型、投掷组件表 |
| 关闭条件 | 确定物品重量的登记方式与取值口径 |

**候选 A：候选 A：重量作为元物品的标准属性登记，与体积分离**

方案：重量作为元物品的一个标准字段登记，单位为统一量纲，与体积属性分离；重量影响投掷折算、载具带货与后续的重量限制，体积留给远期收纳玩法。

代价与影响：重量有唯一来源，投掷与载具读取同一字段，远期收纳不会被重量口径绑住。代价是需要为全部物品补录重量，且重量与体积的配合关系要留给远期设计。

**候选 B：候选 B：重量由物品类型加尺寸档位推导**

方案：不逐件登记重量，按物品类型与尺寸档位推导重量，同类同档物品重量一致。

代价与影响：配置量最小，物品策划只需要选类型与档位，重量自动得出。代价是同类物品之间无法表达重量差异，投掷手感趋同。

**候选 C：候选 C：重量随体积一并留到远期收纳玩法立项**

方案：重量与体积都不在当前版本登记，投掷折算暂以固定档位代替，待远期收纳玩法立项时一并设计。

代价与影响：当前版本范围最小，避免为未定体系做两遍设计。代价是投掷的重物组件缺少实际输入，重物投掷在 Demo 内只能用档位近似。
