# 三、改写方式（硬性）

1. **禁止使用任何脚本或批量替换程序（python／sed／awk／perl 等）改写文档。** 必须直接使用文件编辑工具（`edit`／`write`）逐处改写目标文档。理由：代码设计案的改动带语义，每一处替换都要读上下文、判断术语归属与句首句尾衔接；脚本只能做字面匹配，会把同一术语在否定句、作废说明、跨文档引用中的不同处理方式一并抹平，也会在删除后留下悬空句。
2. 脚本只允许用于**只读的检索、统计与核对**（`grep`、`git diff`、行数统计等），不得写入任何文件。
3. **只允许修改分配给你的那一份文件。** 不得修改任何其他文件：其他代码设计案、`Code_Design/README.md`、上游文档、`Output/CO01-*`、`Output/S02-*` 一律只读。
4. 若你已经用脚本写入过内容，立即用 `git checkout -- <该文件路径>` 恢复该文件，再改用编辑工具重做。

# 四、写作约束

1. **禁止在代码设计案中写引擎类名、API 名、C# 语法、容器类型**（NR-06 §三.2 第 2 项）。用架构案术语表达引擎能力：常驻场景、启动物体、单元装配声明、可寻址资源机制、引擎的输入方案、引擎的资产载体与序列化原语、引擎的域重载、引擎的退出回调、引擎的对象池与集合池。
2. 保持 NR-06 的**十节结构**与**契约八项字段**完整，不得省略节或字段；功能要求 `F-` 与实现要求 `I-` 分别编号。
3. **每处删除都要同时改写上下文**，不允许留下悬空句、悬空引用或断掉的编号。
4. 新增 `I-` 条目编号**续接本文档已有的最大序号**，不跳号、不复用；作废的对象与接口 ID 按 NR-06 §九.4 记「作废、不再复用」，不重新分配。
5. 不得改写上游游戏规则；发现上游缺口按 CO01 的八项格式写 `REQ-` 条目（编号续接该单元已有最大序号，不跨单元借号）；约定第七节列出的撤销条目直接删除，连同「待上游补充」标注。
6. 元信息表「更新日期」改为 `2026-10-09`；「关联文档」栏若引用架构案旧章节号，按约定第五节复核改写。
