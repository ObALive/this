## MET-GAP-059 事件错过后能否在后续局再次出现未定义：事件解锁的保持期限与节点解锁的可重复性没有规则

| 字段 | 内容 |
| --- | --- |
| 等级 | B0 |
| 责任方 | 游戏总监 |
| 来源 | C-07-bb-02 第二轮回答 MET-GAP-053；07-10 §3.6；02-30 §4.2、§4.5 |
| 影响范围 | 07-10 线索树核心、02-30 事件系统、07-30 概率池联动、03-20 大关与结局体系 |
| 关闭条件 | 定义事件解锁的保持期限与节点解锁的可重复性 |

**候选 A：事件解锁跨局保持，事件错过后在后续局可再次出现，节点解锁以首次经历为准**

方案：开放阈值一旦满足，事件解锁状态跨局保持，不因事件被错过而回退。事件在本局被错过只影响本局：该事件在本局消失，在后续局中仍按事件池规则再次出现，直到玩家经历并完成它。节点解锁以玩家首次经历并完成该事件为准，达成后不再回退。已经解锁的节点对应的事件在后续局中仍可再次出现，用于重复体验与内容重历。

代价与影响：与重历叙事的框架最契合，错过一次不等于永久失去；玩家不必为了补齐节点而在单局内强行赶事件。代价是已解锁节点的事件会重复出现，需要内容侧控制重复出现的权重，避免挤压新内容的空间。

**候选 B：事件解锁跨局保持，节点解锁以本局经历为准，错过后需重新满足阈值**

方案：开放阈值满足后事件解锁并在本局生效；若事件在本局被错过，该事件在结算时回到未解锁状态，下一局需要重新满足开放阈值才能再次出现。节点解锁以本局经历为准。

代价与影响：错过的代价最直接，玩家在窗口期内的抉择压力最大，与机会成本的定位一致。代价是玩家可能反复错过后长期无法推进，且「上游节点已经全部解锁却仍无法出现」的体验与锁定节点的设计目的容易混淆。

**候选 C：事件解锁只在单局内有效，每局按阈值重新判定**

方案：开放阈值不产生跨局的事件解锁状态，每局结算时按当前上游解锁状态与封锁状态重新判定一次，判定通过的事件在本局出现。是否出现仍受事件池与窗口期约束。

代价与影响：状态最少，线索树上不需要保存事件解锁状态，判定每次都按同一份输入计算。代价是玩家无法预期某个事件是否已经解锁，链条较长时推进感不明显，引导强度最弱。

## MET-GAP-060 结算窗口的边界与延后项的关系未定义：结算窗口从延后项变为 Demo 组成部分之后需要收口

| 字段 | 内容 |
| --- | --- |
| 等级 | B0 |
| 责任方 | 主策划 |
| 来源 | C-07-bb-02 第二轮回答 MET-GAP-048；07-40 §3.1、§3.3、§3.7 |
| 影响范围 | 07-40 局末结算与写入、08-20 首小时体验线、03-20 大关与结局体系 |
| 关闭条件 | 定义 Demo 阶段结算窗口内呈现的项目与操作，并协调与延后项的关系 |

**候选 A：Demo 结算窗口只呈现变更清单与进入下一局的入口**

方案：Demo 阶段的结算窗口由三个部分组成：本局写入的节点与传闻变更清单、结局类型的文案提示、进入局外循环的入口。清算窗口内不显示达成记录与大关进度（二者不在 Demo 写入范围），不显示统计信息与叙事卡片。窗口的界面结构列入界面设计阶段，系统层只规定三部分内容与其呈现粒度。

代价与影响：范围清晰，与 Demo 阶段只写入四类状态项目完全对齐，后续版本追加两类写入项时只需在清单中增加分组。代价是窗口内容较少，玩家对一局成果的整体感知仍不完整。

**候选 B：Demo 结算窗口同时展示本局的关键行为摘要**

方案：除变更清单与入口之外，窗口内追加一段由存档数据直接提取的关键行为摘要，例如触发过的事件数量、战斗次数与主要收益来源。摘要只做数字呈现，不做结构化统计页面。

代价与影响：局末的信息反馈更完整，玩家对本局成果有直观感知，首小时闭环的收束感更强。代价是摘要需要一份从存档数据取数的口径，属于统计信息功能的轻量前置，与「统计信息列入后续版本」的边界需要一次说明。

**候选 C：结算窗口只做提示与入口，内容全部交给线索树查看**

方案：结算窗口只提示本局进度已写入并给出进入下一局的入口，变更清单改由玩家在线索树中自行查看，窗口本身不列清单。

代价与影响：窗口实现最轻，与「Demo 只实现线索树状态更新」最接近。代价是与第二轮裁定的变更清单方案冲突，需要回到 MET-GAP-048 重新裁定。

## MET-GAP-061 触发方法揭示与事件锁定的交叉未定义：触发方法已揭示但事件仍处于锁定时该如何呈现

| 字段 | 内容 |
| --- | --- |
| 等级 | B0 |
| 责任方 | 主策划 |
| 来源 | C-07-bb-02 第二轮回答 MET-GAP-050、MET-GAP-053；07-10 §3.6、§3.7 |
| 影响范围 | 07-10 线索树核心、02-30-10 触发条件、01-10 移动系统、02-40 探索系统 |
| 关闭条件 | 定义触发方法揭示与事件锁定两个状态的组合规则 |

**候选 A：两个条件独立成立，触发方法先于事件解锁显示**

方案：触发方法揭示的判定条件是关联节点全部解锁，事件解锁的判定条件是上游节点满足开放阈值，两者独立。关联节点全部解锁但开放阈值未满足时，触发方法照常显示，同时节点保持锁定可见并标注事件尚未解锁。玩家由此知道该内容的存在与进入方式，也知道它还未对自己开放。

代价与影响：引导信息最完整，玩家可以提前规划准备，条件推断式解谜的目标清晰。代价是玩家可能长期看到「知道怎么进但进不去」的状态，需要在节点上有一次明确的呈现说明。

**候选 B：事件未解锁时不显示触发方法，两个条件都满足后才揭示**

方案：触发方法揭示在事件解锁之后才生效，事件仍处于锁定时节点只显示锁定形态，不显示事件名称、区域与进入方式。

代价与影响：呈现最干净，不会出现可望不可及的状态，与锁定节点避免跳过流程的目的叠加。代价是玩家在锁定阶段完全没有方向，只能通过关系图上未连通的边推断，引导强度最弱。

**候选 C：触发方法先显示区域，事件解锁后再补事件名与进入方式**

方案：分两段揭示：关联节点全部解锁后先显示事件所在区域，事件解锁后再显示事件名称与进入方式，最终达到三类项目齐全。

代价与影响：兼顾引导与阶段感，玩家先知道去哪里、再知道怎么进。代价是揭示规则从一条变为两段条件，内容侧需要为区域与进入方式分别登记数据。

## MET-GAP-062 结算写入的五种情况与幂等规则未定义：节点与传闻的新增、更新与跳过需要同一套处理口径

| 字段 | 内容 |
| --- | --- |
| 等级 | B0 |
| 责任方 | 主策划 |
| 来源 | C-07-bb-02 第二轮回答 MET-GAP-047、MET-GAP-051、MET-GAP-058；07-40 §3.4、§3.6、§3.12 |
| 影响范围 | 07-40 局末结算与写入、07-10 线索树核心、07-20 剪枝系统、01-50 存档与持久化 |
| 关闭条件 | 定义结算写入的五种情况处理与幂等规则 |

**候选 A：五种情况统一处理，以内容标识为唯一幂等键**

方案：结算写入按五种情况处理并统一提交：新增项写入且标记为新增；已存在项跳过写入并计入已存在计数；封锁标记写入时按封锁集合重建；传闻条目按内容标识去重后追加；同一节点的多条写入项合并为一次节点更新。幂等键是内容标识，重复提交同一标识不产生第二次写入。

代价与影响：五种情况有统一口径，幂等判定不依赖本局标识一类的外部状态。代价是「已存在项」与「更新项」之间的差别被抹平，若后续需要记录本局是否首次达成，需要另加一项写入规则。

**候选 B：五种情况分别处理，幂等键加上本局标识**

方案：五种情况各自定义处理方式，幂等键由本局标识与内容标识共同组成，同一局内重复提交被拒绝，跨局提交按新记录处理。

代价与影响：可以区分本局首次达成与历史已达成，为后续版本的达成记录留出接口。代价是需要为本局标识建立保存与校验规则，且该规则在两轮裁定之间已被裁定挂起（MET-GAP-058），需要先解除挂起。

**候选 C：只定义新增与跳过两种情况，其余情况由存档层兜底**

方案：结算写入只区分新增与跳过两种情况，更新、去重、重建三类情形由存档层的全量保存与恢复兜底，线索树不单独处理。

代价与影响：写入逻辑最简，规则数量最少。代价是封锁标记与传闻去重的边界情形没有明确归属，出现异常时难以判断是写入问题还是存档问题。
