# 建库说明：如何创建一个新的缺口表

| 项目 | 内容 |
| --- | --- |
| 文档定位 | 指导如何把一个系统的信息缺口分析结果建造成可填写的决策库 |
| 适用对象 | 任意章节的系统设计任务，不限于战斗域 |
| 工具位置 | `Dsh/Tool/缺口决策系统/` |
| 前置条件 | 已完成该系统的信息缺口分析，得到一份 GAP 清单与每项的候选方案 |
| 更新日期 | 2026-09-25 |

## 1 这套系统做什么

缺口决策系统把信息缺口分析产出的一份待决清单，变成一个人可以逐项拍板、可以追溯、可以归档的结构化工具。它解决三件事：待决清单有唯一落点，裁定结果不会散落在对话与文档里；同一套网页填写器可以服务任意章节，新库不需要改界面；裁定进度与归档内容可查询，随时能回答还有多少项没拍板、已经拍板的结论是什么。

系统由三层组成。底层是 SQLite 决策库，承载缺口、候选与裁定结果。中层是工具集，负责建库、导出、填写、导入与归档。上层是文档，即本目录下的三份说明。

## 3 数据模型

决策库由五张表与一张视图构成，表名与列名固定，任何章节都沿用同一套结构。

| 对象 | 职责 |
| --- | --- |
| `meta` | 库的自述信息，键值对形式，填写器读取 title 作为库的显示名 |
| `gaps` | 缺口主表，只保留尚未澄清的问题；填写器只呈现这一层 |
| `solution_options` | 候选方案，每项缺口 2 至 3 条候选加一条自定义预留行 |
| `decisions` | 裁定结果，采用候选写 chosen_option_id，自定义方案写 answer_text |
| `gaps_archived` | 归档表，已澄清问题连同结论与设计落点移入此处 |
| `v_gap_decision` | 裁定进度视图，一屏看清哪些项已定、哪些项还开着 |

列的完整含义与取值规则见 `Dsh/Output/C-06-bb-01/决策库结构规范_v1.md`，该文档是表结构的权威定义。

## 4 建库流程

### 4.1 准备数据

把该系统的缺口与候选整理成一份 JSON 数据文件。文件里的每一项缺口都要有：编号、一句话陈述、阻塞等级、来源、影响范围、关闭条件、责任方，以及 2 至 3 条互斥候选；每条候选要有短标题、可直接落成规则的方案正文与代价说明。

方案正文的写法要求：说清规则是什么、适用范围、状态变化、与既有系统的衔接，必要时补充边界与例外。只写方向不写规则的候选不满足要求，因为它在填写时无法被判断。

```json
{
  "meta": {
    "title": "C-aa-bb-01 某系统缺口决策库",
    "chapter": "C-aa-bb-01",
    "domain": "某系统域",
    "analysis_doc": "Dsh/Output/C-aa-bb-01/C-aa-bb-01_某系统信息缺口分析_v1.md",
    "created_at": "2026-09-25"
  },
  "db_path": "Dsh/Output/C-aa-bb-01/C-aa-bb-01_某系统缺口决策库_v1.sqlite",
  "gaps": [
    {
      "gap_id": "XXX-GAP-001",
      "title": "缺口陈述",
      "level": "B0",
      "source_ref": "来源文档与章节",
      "impact_scope": "受影响系统编号清单",
      "close_condition": "关闭条件",
      "owner": "游戏总监",
      "priority_round": "第一轮 骨架，XXX-Q-001",
      "options": [
        {"label": "A", "title": "候选 A：短标题", "detail": "方案正文",
         "tradeoff": "代价与影响", "recommended": true},
        {"label": "B", "title": "候选 B：短标题", "detail": "方案正文", "tradeoff": "代价与影响"}
      ]
    }
  ]
}
```

`level` 取 `B0`、`B1`、`B2`；`recommended` 每项缺口至多一条，建议给出恰好一条，留空表示本轮不推荐任何候选；`db_path` 与数据文件放在同一任务目录下，便于回溯这一库是怎么来的。

分析阶段认定属于明显设计空缺、没有提供候选的依据时，该项缺口可以不给候选，把 `status` 写成 `开放填写`，`options` 留空数组。这类缺口不受“每项缺口 2 至 3 条候选”的校验约束，填写器只呈现一条自定义输入框，提示语改为直接填写需要设计的内容。该状态由 C-07-bb-01 引入，用于承载“明显有设计空缺、没有提供选项的依据时直接提出具体需要设计的内容”这一要求。

```json
{
  "gap_id": "XXX-GAP-005",
  "title": "缺口陈述",
  "level": "B1",
  "status": "开放填写",
  "source_ref": "来源文档与章节",
  "impact_scope": "受影响系统编号清单",
  "close_condition": "填写需要设计的内容并回填设计稿",
  "owner": "主策划",
  "options": []
}
```

### 4.2 建库

```powershell
python Dsh/Tool/缺口决策系统/建库工具/build_decision_db.py --data <数据文件.json>
```

建库脚本会自动完成四件事：建表并写入元信息；写入缺口与候选；为每项缺口追加一条自定义预留行，使填写器始终呈现"候选若干加一个自定义输入框"；运行结构校验并打印结果。

校验项包括必需表与视图齐备、引用完整性、每项缺口的候选数量、推荐数量、是否存在空正文、是否存在孤儿候选。任一项不通过时输出中的 `problems` 字段会列出具体问题，修正数据后重建即可。

目标库已存在时脚本会拒绝覆盖并要求另存新版本，确认覆盖时才加 `--force`。这与库内默认禁止覆盖已有文件的规则一致。

### 4.3 校验与导出文本

```powershell
# 单独校验一个库
python Dsh/Tool/缺口决策系统/建库工具/decision_db.py --check <库路径>

# 导出候选清单与作答模板（在库所在目录生成两份 Markdown）
python Dsh/Tool/缺口决策系统/建库工具/export_catalog.py --db <库路径>
```

候选清单用于横向比对，作答模板用于离线填写，两者都是只读派生文件，内容随时可从库中重新导出。

### 4.4 建库后的自检清单

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 必需表与视图 | `meta`、`gaps`、`solution_options`、`decisions`、`gaps_archived` 与 `v_gap_decision` 齐备 |
| 2 | 引用完整性 | 完整性检查为 ok，外键检查无错误，无孤儿候选 |
| 3 | 候选数量 | 每项缺口 2 至 3 条候选，另有且仅有一条自定义预留行；登记为 `开放填写` 的缺口不设候选，只有自定义预留行 |
| 4 | 推荐数量 | 每项缺口至多一条推荐候选；超过一条会被判为问题，未标满的缺口由校验结果中的 `gaps_without_one_recommendation` 计数报出；`开放填写` 的缺口不设推荐 |
| 5 | 内容完整 | 候选正文与代价说明均非空 |
| 6 | 裁定初始状态 | `decisions` 全部为 `待裁定`，两个答案字段为空 |
| 7 | 自述信息 | meta 含 title、chapter、analysis_doc |
| 8 | 填写器可读 | 启动填写器后能在下拉框中看到该库，缺口数与清单一致；`开放填写` 的缺口只呈现一条自定义输入框，提示语为直接填写需要设计的内容 |

第 1 至第 7 项由建库脚本与 `--check` 自动完成，第 8 项在启动填写器后确认。

## 5 为早期建立的库补齐结构

新库已经包含全部结构。早期的库可能缺少 meta 表或归档表，用以下命令补齐，不会改动其余数据。

```powershell
# 补建自述表
python Dsh/Tool/缺口决策系统/建库工具/decision_db.py --ensure-meta <库路径> `
  --title "库标题" --chapter "C-aa-bb-01" --domain "06-战斗"

# 补建归档表
python Dsh/Tool/缺口决策系统/建库工具/decision_db.py --ensure-archive <库路径>
```

## 6 从既有库回溯数据文件

需要把某个既有库的缺口与候选重新导出为数据文件时，可参照 `Dsh/Output/C-06-bb-01/.artifact_runtime/extract_decisions_data.py`：它读取库中的主表、候选表与归档表，写出同时包含未澄清问题与已归档问题的 JSON，作为该库的来源记录。
