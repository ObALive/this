## 一、为什么要建副本

缺口决策系统的路径解析模块 `建库工具/db_locator.py` 用两个条件认定工作区根目录：该目录下同时存在 `Dsh` 目录与 `.git` 目录。本工作区把仓库的 `Dsh` 目录内容直接挂载在根目录，两个标记都不存在，模块回退判定出的工作区是 `/home/ob-alive`，而扫描模式 `Dsh/Output/**/*决策库*.sqlite` 指向的 `/home/ob-alive/Dsh/Output/` 不存在，因此决策库自动发现返回空列表，填写器顶部显示未找到任何决策库。

按 `Rules.md` 第二章第二节的文件隔离规则，未获授权不得修改 `Report/`、`Output/` 之外的目录，需要使用其他目录的文件时应当创建副本。因此不改原件，改为在任务输出目录内建立副本并修正副本。

## 二、副本相对原件改动了什么

只改动一个文件：`建库工具/db_locator.py`。改动两处，其余文件与原件逐字节一致。

改动一，工作区识别增加第二种布局的判定。新增常量与判定分支：

```
ROOT_MARKERS = ("Design", "Output", "Task", "Tool")
```

向上逐级查找时，命中同时含 `Dsh` 与 `.git` 的目录仍按原规则认定为工作区根目录；未命中时再判断当前目录下是否同时存在 `ROOT_MARKERS` 中的四个目录，是则同样认定为工作区根目录。

改动二，扫描范围增加第二种布局的两条模式，原有两条保留：

```
SCAN_PATTERNS = [
    "Dsh/Output/**/*决策库*.sqlite",
    "Dsh/Tool/缺口决策系统/示例/*.sqlite",
    "Output/**/*决策库*.sqlite",
    "Tool/缺口决策系统/示例/*.sqlite",
]
```

改动后两种目录结构都能正常识别：仓库根目录布局走前两条模式，`Dsh` 内容挂载在根目录的布局走后两条模式。不存在的模式匹配为空，不产生副作用。

## 四、启动命令

```
python3 Output/R001/.artifact_runtime/缺口决策系统/填写器/decision_server.py \
  --db Output/R001/R001_系统设计精简缺口决策库_v1.sqlite --no-browser --port 8777
```

`--db` 的路径相对修正后的工作区根目录，可以省略；省略时填写器默认选中列表中的第一份库，需要在页面顶部的选择器切换。后续的导入裁定与归档命令同样从本副本目录调用：

```
python3 Output/R001/.artifact_runtime/缺口决策系统/审阅工具/import_answers.py --db Output/R001/R001_系统设计精简缺口决策库_v1.sqlite --answers <模板路径> --check
python3 Output/R001/.artifact_runtime/缺口决策系统/审阅工具/archive_decided.py --db Output/R001/R001_系统设计精简缺口决策库_v1.sqlite --check
```

## 五、后续处理建议

副本只解决本次任务的运行问题，`Tool/` 下的原件在同等目录结构下仍会检索失败。若希望后续任务不再重复建副本，可以把本文件第二节的两处改动合并回原件；该操作属于修改任务输出目录之外的文件，需要明确授权后再执行。
