## 一、返工处理方式

### 1.1 两条基本原则

1. 肯定式表述：正文只写我们是什么，用正面句式定义设计与规则，删除所有以否定句式承担定义职责的表述。
2. 降级靠删除：信息相关要素的降级通过大批删除表述实现，保留的内容仅限介绍玩家交互方式的短句，典型句式如玩家可以从线索树中了解、玩家可据此安排等。

### 1.2 执行的删除与改写

| 位置 | v2.1 处理 |
| --- | --- |
| 一句话定位 | 删除信息获取一词，发育动作只保留日程选择与资源经营 |
| 设计目标 | 原信息条目删除，替换为让世界状态充分呈现给玩家，使玩家的日程、经营与战斗决策都有据可依 |
| 核心创意 | 删除信息相关专节，核心创意收敛为时间即路线、世界线与重历叙事、资源即战力、线索树与剧情解谜四节 |
| 资源即战力 | 只写战斗成长完全来自道具与工具，信息相关内容整句删除 |
| 局内循环 | 获得钱、货与各类信息改为获得钱、货等收益 |
| 时间机制 | 删除为下一个时间段的事件抉择收集信息一句 |
| 触发条件 | 情报解锁改为线索解锁 |
| 运营系统 | 信息获取专节整节删除，替换为事件提示一节，共两句，只介绍玩家在事件中看到什么、可以据此做什么 |
| 金钱用途 | 保留间接性说明，删除情报一词，聚焦解锁事件等内容的支持方式 |
| 战力构成 | 只写成长来自道具与工具的积累，追加一句肯定式说明：玩家在战斗前掌握的情报会改变战术选择，并可能开启不同的战斗结果 |
| 战斗目标与结果 | 保留胆小头目案例，作为战术选择与战斗结果的交互描述 |
| 关键交互清单 | 删除信息相关的边界性条目 |
| 线索树章节 | 边界性定义段落删除，替换为肯定式说明：线索树承担剧情线索的记录、组织与推理功能，玩家可以从中回顾已解锁的故事内容，了解节点之间的关联、解锁条件与后续可探索的方向 |

### 1.3 保留的信息表述清单

正文中保留的信息相关表述集中于以下三类，全部为玩家交互方式描述：

1. 线索树章节的全部内容，包括玩家可以从中回顾什么、看到什么提示、如何剪枝；
2. 事件提示一节，玩家在事件中获得关于世界状态的说明并可据此安排买卖与日程；
3. 战斗中的胆小头目案例，事先掌握情报改变战术选择并开启不同战斗结果。

## 三、策划研判意见（供总监参考）

1. 背包复杂度：类塔科夫背包与空间管理核心定位一致、沉浸感强，但复杂度高。建议初版采用一格一物加少量低门槛收纳动作，例如堆叠与捆扎，全部走物品属性接口预留扩展；以决策深度与操作成本的比值作为后续拓展的判据，在玩法原型阶段验证后再决定是否全面塔科夫化。
2. 行动槽认知负担：字母序列、时间轴与战棋走位三层机制叠加，学习成本偏高。建议新手引导分三步展开，先教时间轴行动顺序，再教字母槽与连携释放，最后引入移动打断的取舍；初期连携技能的成本串宜短。
3. 健康状态定位：健康状态占战斗资源极大比重、无伤难度高，意味着恢复手段与恢复时机将成为战斗与运营衔接的关键决策点，建议在纲要阶段优先确定恢复道具与背包空间的互动关系。
