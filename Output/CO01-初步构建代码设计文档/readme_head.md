# 代码设计案库

本目录是**按游戏系统与架构单元编制、持续维护**的代码设计案库。代码设计案以 `系统设计文档/` 的系统设计稿与 `架构设计文档/` 的架构设计案为输入，以伪代码设计与实际编码为下游目标。

本库文档的编制规则见 `Rules/06_代码设计案编辑规范.md`；目录组织与命名规则见 `Rules/05_文档库组织规范.md` 第七章与 `Rules/06` 第十二章。本文件只登记本库的定位、索引与当前状态，不承载规则条款。

## 一、本库承载的内容

本库对每个单元明确其在程序中的：

职责边界、所需数据、对外接口、输入输出、状态变化、依赖关系、调用关系与实现约束。

目标是让开发者在不重新阅读上层游戏设计案的情况下，可以据此完成该单元的伪代码设计与代码实现。

单元取两类，取两者的并集：`系统设计文档/` 设计库中的 32 个系统（含 1 个远期占位），与 `架构设计文档/架构设计案.md` 2.5.2 的 11 个架构新增单元。服务容器是 M01 的模块成员，作为顶层对象载于 M01 文档，不另立文件，因此 43 个单元落在 42 份文档上。

## 二、与相邻文档的分界

| 文档 | 回答的问题 |
| --- | --- |
| `系统设计文档/` 系统设计稿 | 玩家具体会怎么玩，游戏规则是什么 |
| 架构设计案 | 整个程序应该如何组织 |
| **代码设计案（本库）** | 某个系统或模块在程序里必须具备什么，与其他部分如何协作 |
| 伪代码 | 这些程序功能具体按什么步骤执行 |

架构设计案是代码设计案的上级约束，规定整个程序允许怎样组织；本库的每份代码设计案规定某个具体单元在架构允许的范围内需要怎样实现。两者是两个并列维度，不是同一维度的上下层。

六层文档的完整分工见 `Rules/03_文档编辑规范.md` 第七章。

## 三、目录结构

```
Code_Design/
├── README.md                    本文件：库定位、索引与当前状态
├── 00-架构单元/                  架构设计案新增单元的代码设计案
│   └── {模块编号}_{单元名}代码设计案.md
├── {域编号}-{域名}/              域目录，编号与命名沿用系统设计文档库
│   └── {系统编号}_{系统名}代码设计案.md
└── ...
```

域目录的编号与命名沿用 `系统设计文档/` 设计库的定义，不另立一套。域内不设系统子目录：一个系统一份代码设计案，子系统（如 30-10 触发条件）同样是独立一份，直接落在域目录内。
