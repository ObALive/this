# 角色属性1 实施记录

任务标识：角色属性1-20261022-010135。

## 节点与可观察能力

用户确认的定位为角色行为 / 角色属性 / 1 / 固定属性，指定数据库节点 n18。正文为：以角色配置提供行动力、力量与行动速度，详情能读取当前值；分别为移动范围、重物投掷与行动延迟提供属性输入。

使用 query.py 显式指定数据库，只读读取全部节点字段及 v_edge。直接前置为空（显式和同路线链式均无）。node_objects.path 中是属性修正的说明文字，并非源码落点，按需求读取：静态值、按来源调整、调用时计算。

## 复用、适配与局部决定

- 复用 MetaObjectDefinition → CreateInstance → AttributeComponent 的既有组合入口；不增加第二套角色运行状态。现有 CharacterInstance/Character_SO 是未接入的早期实现，没有属性状态可迁移，不把它们接成平行权威。
- 复用 MetaObjectPreset 的创建、绑定、重建、释放流程，不修改内核。属性定义沿用与坐标、纹理定义同样的 SerializeReference 注册方式，挂入现有 Player.asset。
- 适配 DebugPanel，增加右上角只读详情和明确的玩家预置引用，恢复 GUI.matrix 避免影响其他绘制。原来的坐标与纹理调试入口保留。
- 新建 AttributeComponent/AttributeComponentDefinition，以及三个值的枚举 CharacterAttribute。无装备、Buff、百分比、属性消耗、移动距离换算、伤害曲线或行动延迟公式；本节点只暴露属性输入。

## 状态与协议

每实例复制配置基础值；修正来源为组件私有的 SortedDictionary，来源以 ordinal 区分大小写。当前值为基础值与各来源加减量之和；同一来源同一属性再次设置会替换，零清除该项，一次 RemoveModifiers 撤销整个来源。读取不消耗、不钳位、不取整，不修改配置。保留小数。

参数要求有限数值和非空白来源，非法枚举或 NaN/Infinity 抛参数异常且不写入。汇总用 double 中间值，超出 float 范围时查询显式抛 OverflowException，撤销来源后可恢复。组件不自带事件、定时器或异步资源。Unbind 保留运行状态，Detach/替换/Dispose 清空来源。主线程同步使用，调用方负责来源标识在自身实例范围唯一。

配置位于 Assets/GameData/MetaObjects/Player.asset 的 AttributeComponentDefinition：行动力 5、力量 10、行动速度 1。这是本节点演示配置，不是平衡数值定案；编辑该条目的序列化字段即可调整，不从设计 CSV 运行时加载。

## 后续节点调用

```csharp
var attributes = preset.Instance.GetComponent<AttributeComponent>();
float movementInput = attributes.ActionPoints;
float throwInput = attributes.Strength;
float delayInput = attributes.ActionSpeed;

attributes.SetModifier("source-instance-id", CharacterAttribute.Strength, 4f);
attributes.RemoveModifiers("source-instance-id");
```

使用 GetBaseValue 读取基础值，GetValue 读取指定当前属性；详情通过 GetCharacterDetailsText 查询相同组件。后续装备/效果节点经它们确定的服务写入本组件，不在 UI 直接修改属性，不把当前值复制到另一份角色台账。

## 接线与迁移

Player.asset 保留 GUID、坐标和纹理组件的 managed reference 标识，只追加属性定义。Player_Layered.prefab 已引用同一资产，无需改写 prefab。PersistanceScene 的 Debug.metaObjectPreset 显式引用现有 Player/MetaObjectPreset。无类型迁移、字段更名或存档结构变化。

当前元对象底座仍在 Assembly-CSharp 且基类引用场景承载；本节点沿用现有编译布局，数值计算自身没有场景或 UI 依赖。架构文档的 Unity 6 与四程序集基线尚未落实，属于已有工程差距，不以本节点通过宣称全局架构已经达标。后续集中实施该基线时应一并迁移元对象底座及本组件。

## 验证复现

Unity 菜单 Tools / Meta Object / Verify Character Attributes 执行配置与逻辑检查。菜单 Verify Character Attributes In Scene 执行真实场景检查，拒绝覆盖脏场景；自动进入 Play Mode、确认帧推进、验证详情与重建、捕获截图，结束后恢复原场景组合和编辑模式。

命令行批处理入口为 CharacterAttributesVerification.RunBatch；默认输出到工程 Temp/CharacterAttributesVerification。工程已有编辑器时使用菜单，不同时启动第二个实例。

本地自动化可在 Temp/CharacterAttributesVerification.request 写入输出绝对路径，由编辑器测试工具消费。先触发 Assets/Refresh 并等待脚本编译完成，再写请求，避免检验旧程序集。本次验证日志与结果存放同任务目录。
