# 一、任务启动

## 1. 启动四步

执行任何任务之前，依次完成：

1. **读规范**：读 `Rules/README.md`，按索引判断本次任务适用哪些规范，列出适用清单；
2. **读任务书**：确认任务书存在，读取并解析授权范围；
3. **认识现有内容**：按任务书声明的工作方法阅读相关文档。凡任务涉及既有文档的任务，必须先读现行文档与对应索引再动手，禁止凭印象改写；
4. **明确四项**：把任务目标、任务方法、任务流程、完成标准四项写清，缺项时向用户确认。

## 2. 未授权行为的处置

未明确授权的行为一律不得执行，按第五章异常处理规则上报并等待决策。判断依据是「任务书是否授权」，不是「该行为是否显然有益」。

## 3. 任务书缺失

任务书不存在时不得自行补写任务目标并开工，必须先向用户索取任务书或确认口头指令的授权范围。

# 二、目录与文件

## 1. 目录职责

| 目录 | 职责 | 可否写入 |
| --- | --- | --- |
| `Task/` | 任务书。一个任务一份，文件名与任务编号一致 | 仅在任务书本身需要落盘时 |
| `Report/` | 任务执行报告。每份任务书对应唯一报告，命名与任务书一致 | 可写本任务报告 |
| `Output/` | 任务执行过程中产生的非报告文件。按任务编号建独立子目录 | 可写本任务子目录 |
| `Design/` | 全局设计文档库，跨任务共享、长期维护 | 仅当任务书明确授权 |
| `Rules/` | 规范目录 | 仅当任务属于规范变更类 |
| `Input/` | 用户输入的原始材料，只读 | 禁止写入 |
| `Tool/` | 工具与说明 | 仅当任务书明确授权 |

一个任务的产物落点结构：

```
Task/05-任务规范整理.md

Report/05-任务规范整理_Report.md

Output/05-任务规范整理/
 ├── checkpoint_001.md
 ├── system_operation_log.md
 └── {其余过程文件}
```

## 2. 文件隔离

* 未获得任务书授权，禁止修改 `Report/`、`Output/` 之外的任何目录；
* 需要引用其他目录的文件内容时，在任务输出目录内建立副本使用，不得直接改动原件；
* 禁止修改、删除、覆盖其他任务在 `Report/` 与 `Output/` 中产生的内容；
* 默认禁止覆盖已有文件。确需覆盖时满足三项：创建新版本、保留旧版本、记录修改原因；
* 覆盖前的兜底动作是把原件复制到本任务输出目录留档，并核对复制前后的校验值一致。本工作区的 `Rules/` 目录未纳入 git，其中的文件被覆盖后无法靠版本管理复原，属于必须留档的对象。

## 3. 文件命名

任务产生的文件必须包含任务标识，格式为：

```
任务编号_文件类型_版本或时间戳.扩展名
```

示例：

```
05-任务规范整理_信息缺口分析_v1.md
05-任务规范整理_回答归档_v1.md
checkpoint_001.md
system_operation_log.md
```

`checkpoint` 与 `system_operation_log` 两类文件由规范固定命名，不加任务标识，原因是它们的位置已经在任务目录内，加前缀只增加噪声。

# 三、执行过程

## 1. 任务状态

每个任务维护一个状态，取值如下：

```
Pending    待执行
Running    执行中
Paused     等待决策
Blocked    外部阻塞
Completed  已完成
Failed     执行失败
Archived   已归档
```

状态变化记录于任务报告。

## 2. 断点记录

长任务按固定节奏生成断点文件，路径为 `Output/{任务编号}/checkpoint_xxx.md`，序号三位递增。触发时机为：完成一个可独立验收的阶段、上下文接近用尽、需要中断等待决策。

断点内容固定七项：

```
任务状态：
任务详细说明：
已完成：
未完成：
当前环境：
已修改文件：
执行记录：
下一步：
```

因对话长度限制、运行时间限制或进程限制无法继续时，必须生成完整断点记录，使新的执行环境可以无损恢复。恢复执行时先读最新断点，再从「未完成」与「下一步」两节接着做。

## 3. 完成标准

任务不得仅因命令执行成功、文件生成或无错误提示而判定完成。完成必须同时满足三项：

```
任务目标达成
+ 输出文件完整
+ 任务报告完成
```

# 四、权限与审计

## 1. 权限边界

智能体禁止自行提升权限、修改自身规则、修改权限限制、删除审计记录。四项行为都需要用户明确授权，授权前一律不做。

## 2. 必须登记的系统操作

以下操作必须登记：`sudo` 与 root 命令、系统配置修改、环境变量修改、软件安装与卸载、服务启动与停止、网络配置修改、用户权限修改。

登记格式：

```
时间：
执行命令：
执行目的：
影响范围：
执行结果：
恢复方案：
```

登记文件为 `Output/{任务编号}/system_operation_log.md`。

## 3. 高风险操作

高风险操作必须先获得授权。禁止默认执行上传内部数据、调用收费服务、发送外部消息、修改云端资源四类动作。

启动本地服务属于需要登记但不属于高风险操作，登记时写清监听地址与读写范围；只监听回环地址的服务不得对外网开放。

## 4. 数据安全

禁止泄露任务文件内容、将内部数据发送第三方、在日志中记录敏感信息。

# 五、异常处理

## 1. 触发条件

出现下列情况必须生成情况说明文件并等待用户决策：任务书未预料的情况、权限不足、需要超范围操作、存在数据风险、任务目标无法继续完成。

文件路径为 `Output/{任务编号}/exception_report_xx.md`。

## 2. 异常等级与处置

| 等级 | 名称 | 典型情形 | 处置 |
| --- | --- | --- | --- |
| Level 1 | 普通异常 | 文件缺失、临时网络失败 | 允许自动恢复，恢复过程写入任务报告 |
| Level 2 | 任务风险异常 | 修改系统配置、删除文件、改变运行环境 | 暂停并请求授权，批准前不执行 |
| Level 3 | 安全异常 | 数据泄露风险、恶意文件、权限异常 | 立即停止相关操作并报告 |

## 3. 如实登记

异常必须如实登记，禁止隐瞒。已经自动恢复的 Level 1 异常同样进入报告，写明原因、处置与结果，并登记由此产生的遗留问题。

# 六、任务报告

每个任务生成一份报告，路径为 `Report/{任务编号}_Report.md`，文件名与任务书一致。

报告至少包含十一节：

```
1. 任务目标
2. 任务书摘要
3. 执行环境
4. 使用工具
5. 执行过程
6. 文件变更列表
7. 权限操作记录
8. 异常情况
9. 输出文件列表
10. 完成状态
11. 后续建议
```

报告头部用元信息表登记任务编号、任务书路径、执行日期、任务状态与报告版本；报告在任务执行期间被多次修订时，在元信息表之后附变更记录表，逐版写明版本、日期、变更与原因。

第 10 节按第三章第 3 节的完成标准逐项核对后填写，第 11 节写明遗留问题、待人工确认项与下一轮建议。

---

# 七、多任务与多智能体隔离

不同任务或不同智能体之间：不共享临时文件、不修改其他任务文件、不覆盖其他任务报告、不读取未授权任务数据。

并行执行多个子任务时，先确认各子任务改写的文件集合互不重叠，再并行开工。文件集合存在重叠时必须串行，或先划定各自的改写范围。

---

# 八、探索许可

在授权范围内允许无限制探索、允许尝试不同方案、允许生成辅助文件。探索不得突破权限边界、不得修改未授权目录、不得影响其他任务。

探索产生的中间产物放在本任务输出目录内，进入报告的文件变更列表。

---

# 九、自检清单

任务收口前逐项核对：

| # | 检查项 |
| --- | --- |
| 1 | 已读规范索引并列出本次适用的规范清单 |
| 2 | 已读任务书并确认授权范围 |
| 3 | 涉及既有文档的任务已先读现行文档与索引 |
| 4 | 产物落点符合目录职责，未越界写入 |
| 5 | 覆盖文件前已在本任务输出目录留档并核对校验值 |
| 6 | 文件命名包含任务标识 |
| 7 | 长任务已生成断点记录 |
| 8 | 需要登记的系统操作已写入 `system_operation_log.md` |
| 9 | 异常情况已如实登记并评定等级 |
| 10 | 报告十一节齐备，完成状态按三项标准核对 |
| 11 | 遗留问题与下一轮建议已写入报告 |
