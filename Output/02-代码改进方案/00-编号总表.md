# 编号总表（取舍清单）

> 本文是任务书《02-代码改进方案》的**取舍索引**，是全部编号的权威登记表。
> 每一条改进行为一个编号，用户按编号取舍即可；编号一经采纳，其"操作""依赖"栏中的约束一并生效。

## 0. 编号规则

| 前缀 | 类别 | 说明 |
| --- | --- | --- |
| P | 目录布局（创建/改名目录） | 不改代码内容，只动目录与 .meta |
| F | 文件建档/迁移/删除 | 含类型与全部成员的搬移，是"拆 DataCollection/Enums"等的主体 |
| N | 命名与代码级小修 | 标识符改名、拼写修正、清理性改动，逐条列出全部引用点 |
| NS | 命名空间 | 为文件加 namespace 并补齐 using |
| E | 编码 | GBK→UTF-8 等 |
| X | 可选跨界项 | 不属于 §5 范围但与本次重组强相关（P0-7、P1-1、编辑器目录等） |
| K | 维持不改（决策记录） | 非改进行为，仅对照报告 §5 给出"无需处理"的结论 |

依赖标记：**必**=必须同批或先于本编号执行；**选**=与本编号相关的可选项；**互斥**=A/B 二选一，不能同时采纳。

## 2. 备注

- 风险注①（P-02 大小写改名）：`dataSO`→`Data` 不是仅大小写变化，Windows 下可直接改名；若日后遇到"仅大小写"改名（如 `Data`→`DATA`）需在 Unity 内分两步（加临时名过渡）以防 GUID 丢失。目录改名必须在 Unity Project 窗口或连同 `.meta` 一起移动，禁止在资源管理器里只移动目录本体。
- "引用点"统计基线为当前 24 个源文件与下述序列化资产：
  - `Assets/GameData/Inventory/ItemDataList_SO.asset`（字段级键名）
  - `Assets/GameData/Inventory/Bags/BagSturcture_SO.asset`（slotType 等键名）
  - `Assets/GameData/Inventory/Bags/PlayerBag.asset`、`Assets/GameData/Char_SO.asset`
  - `Assets/Scenes/PersistanceScene.unity`（InventoryManager 字段键：itemDataList_SO/bagSturcture_SO/playerBag，TriggerItemFader 的 test1/test2）
  - `Assets/Scenes/01.Field.unity`（prefab 覆盖 propertyPath：`itemInstance.itemID`）
  - `Assets/M Studio/Art/Prefabs/ItemBase.prefab`（旧布局残留键 `itemID: 1001`）
  - `Assets/Scenes/UI.unity`（SlotUI 无任何已序列化业务字段，改名安全）
- 场景/预制体对脚本的引用一律走 `.cs.meta` GUID，移动文件、类改名、加命名空间都不会破坏挂载；只有**序列化字段键名**（YAML 键、propertyPath）与**文件 GUID** 敏感，本表涉及处均已给出措施（`[FormerlySerializedAs]` / 编辑器内重设 / YAML 文本同步）。
