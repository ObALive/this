## 3. 中途形态（常见取舍组合）

| 取舍组合 | 结果形态 |
| --- | --- |
| 只采纳 E 系列 + N-01/N-02/N-08 | 目录与文件不动，仅编码统一与拼写修正，可单独提交 |
| 只采纳 N 系列（不改目录） | 所有改名在现有 24 个文件内完成；`SlotType`/`ESlotType` 冲突需 N-06B 先于 N-06A |
| 采纳 P+F 系列（不采纳 NS） | 得到第 2 节目录树，但所有文件仍在全局命名空间（可编译，引用关系不变） |
| 全采纳（推荐） | 第 2 节目录树 + 各文件按 NS 表加命名空间 |
| 不采纳 F-10/F-08 删除、保留遗留 | 遗留类型按 02 表 §4 的"保留路径"落位，其余不变 |

## 4. 目录/文件操作纪律（每步都适用）

1. **Unity 内操作优先**：新建/移动/改名目录与文件一律在 Unity Project 窗口执行（或外部移动时**同时移动同名 .meta**），保证 GUID 连续，场景/资产引用不断。
2. 改名后的 .cs 若类名与文件名不一致（Unity 只对 MonoBehaviour 校验类名=文件名），应保持"一个文件一个主导类型"的整洁规则：本方案新建文件均以最终类型命名。
3. 任何"删除文件"动作都应先确认无场景挂载（本方案已核实：ItemManager.cs、InventoryBag_SO.cs、Char_SO.cs 均未挂载到任何场景；InventoryManager.cs 等均只按 GUID 引用，移动安全）。
4. 每完成一批改动（见 06），在 Unity 中等待编译通过并抽查相关场景，再进入下一批。
