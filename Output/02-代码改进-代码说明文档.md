- 源文件数：`Script` 下 **23 → 32** 个 `.cs`（Editor 下 `ItemEditor.cs` 未动）。

## 1. 数据模型层（Inventory/Data）

> 这一层是"静态配置"与"运行时实例"的**纯 C# 数据模型**，不继承 MonoBehaviour。是物品=ID+组件字典模型的核心载体。

### 1.1 ItemType.cs

```csharp
public enum ItemType
{
    Seed, Commodity, Furniture,
    HoeTool, ChopTool, BreakTool, ReapTool, WaterTool, CollectTool,
    ReapableScenery, Weapon,
    Inventory,
    Artifact,
    Armors
}
```

- 物品**种类**枚举，取值顺序与资产中存储的 int 严格一致（本次未改动任何枚举值顺序）。
- 从原 `Enums.cs` 独立出来。

### 1.2 ItemDetails.cs（物品详情 / 配置表行）

```csharp
    public AssetReferenceSprite ItemIcon;          // 背包图标（Addressables）

    public string ItemDescription;

    public int ItemUseRadius;    // 原 itemUseRadius
    public bool CanPickedup;     // 原 canPickedup
    public bool CanDropped;      // 原 canDropped
    public bool CanCarried;      // 原 canCarried

    public int ItemPrice;        // 原 itemPrice
    public float SellPercentage; // 原 sellPercentage

    public List<ComponentRef> ComponentRefs; // 原 componentConfigs

```

- 描述"某**一类**物品"的静态定义，一条 = 一张 `ItemDataList_SO` 表的一行。
- 字段风格已统一为 PascalCase；camelCase 旧字段名全部用 `[FormerlySerializedAs("旧名")]` 做了**资产数据迁移**（见 §8）。
- `ItemIcon / ItemOnWorldSprite` 用 Addressables 的 `AssetReferenceSprite`（非直接贴图引用）。

#### 嵌套类型 → 顶层结构体 ComponentRef

```csharp
public struct ComponentRef
{
    public int ComponentID;           // 原 componentID
    public ScriptableObject ConfigAsset; // 原 componentConfigs
}
```

- 原为 `ItemDetails` 内嵌套的小写 `struct component`，现已提升为**顶层结构体** `ComponentRef`，表示"一份组件配置的间接引用"：`ConfigAsset` 指向某份组件配置库（`*ComponentData_SO`），`ComponentID` 是该库内配置行的 ID。
- 设计意图（报告 §4.2）：同一份配置可被多处引用、未来支持热更/瘦身。

## 2. 组件层（Components）

> 组件体系 = `ItemComponentData<T>` 配置行 + `ItemComponent` 运行时接口 + 各具体组件。是"编辑器配数据 / 运行时生成对象"的工厂模式。

### 2.1 ItemComponent.cs（组件基座）

```csharp
public abstract class ItemComponentData<T> where T : ItemComponent
{
    public string ComponentName;
    public int ComponentID;
    public abstract T CreateComponent();   // 配置行知道自己怎么实例化成运行时组件
}

public interface ItemComponent { }          // 运行时组件标记接口
```

- 两个类型均未改动，仅保持原位置。

### 2.2 MeterComponentData_SO.cs（数值组件，未改动逻辑）

一个文件含三类（小项目可接受）：
- `MeterComponent : ItemComponent` —— 运行时数值组件：`Value` 属性自动 Clamp、`Modify(amount)` 统一入口、`OnValueChanged / OnCheckpointReached` 事件、`CheckCheckpoints` 检查点判定。
- `MeterComponentData : ItemComponentData<MeterComponent>` —— 配置行（`maxValue/minValue/initvalue/checkpoints`），`CreateComponent()` 工厂。
- `MeterComponentData_SO : ScriptableObject` —— 数值组件配置库（`List<MeterComponentData> DetailsList`）。

### 2.3 InventoryComponentData_SO.cs（容器组件）

- `InventoryComponent : ItemComponent` —— 运行时容器：`List<BaseInventorySlot> Slots`、构造里 `CreateSlots(slots)`、`InventoryCanPlacein(item)`、`InventoryFastPlacein(item)`、`CreateSlots(configs)` 槽位工厂（switch 已改用 `SlotType.*`）。
- `InventoryComponentData : ItemComponentData<InventoryComponent>` —— 配置行（`List<SlotConfig> slots`）。
- `InventoryComponentData_SO : ScriptableObject` —— 容器组件配置库。

### 2.4 槽位模型（本次从 DataCollection 拆分，全部独立成文件）

| 文件                   | 类型                                                                | 职责                                                                                         |
| ---------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `SlotType.cs`          | `enum SlotType { Grid, Equipment, Secure }`                         | 数据层**槽位种类**（原 `ESlotType`；删除原 `StupidSlot` 占位值）                             |
| `SlotConfig.cs`        | `struct SlotConfig { SlotType slotType; List<int> settings; }`      | 单槽配置行；`settings` 为不同槽类型的魔法数字参数                                            |
| `BaseInventorySlot.cs` | `abstract class BaseInventorySlot`                                  | 槽位抽象：`SlotCanPlaceItem` / `SlotFastPlaceItem`                                           |
| `InventoryCell.cs`     | `class InventoryCell { int itemID; int itemAmount; bool IsEmpty; }` | 槽内实际容纳的单格                                                                           |
| `EquipmentSlot.cs`     | `class EquipmentSlot : BaseInventorySlot`                           | 装备槽实现（`SlotCanPlaceItem` 恒 false 的占位、`SlotFastPlaceItem` 抛异常——保持原实现未改） |

## 8. 序列化迁移说明（重要）

- 所有**改名且已序列化**的字段，都加了 `[FormerlySerializedAs("旧名")]`，Unity 会在**载入资产/场景时自动把旧键数据迁到新字段**，下次保存时重写为新键。无需手工改 `.asset`/`.unity` 数据文件。
- 唯一需要手工处理的挂载关系：`01.Field.unity` 中预制体实例覆盖的 `propertyPath: itemInstance.itemID` 已同步改为 `itemInstance.ItemID`（prefab override 的路径串不会随 FormerlySerializedAs 自动迁移）。
- 受影响的序列化资产/场景（供回归自查）：
  - `Assets/GameData/Inventory/ItemDataList_SO.asset`（ItemDetails 字段键 + ComponentRef 元素键）
  - `Assets/GameData/Inventory/Bags/BagSturcture_SO.asset`（无改名字段，不受影响）
  - `Assets/GameData/Char_SO.asset`（`charDatas`→`characterDatas`）
  - `Assets/Scenes/PersistanceScene.unity`（`bagSturcture_SO`→`bagStructure_SO`）
  - `Assets/Scenes/01.Field.unity`（`itemInstance.itemID`→`itemInstance.ItemID`）
