# 项目网络图绘制与编辑工具

| 项目 | 内容 |
| --- | --- |
| 工具定位 | 把「按开发路线增量构建」的任务书 Markdown 解析成项目网络图（Project Network Diagram），并支持在图上插入、编辑、删除条目 |
| 工具位置 | `Tool/项目网络图/` |
| 数据位置 | `Tool/项目网络图/数据/项目网络图.sqlite`（SQLite 库，自动存档；库内滚动保留最近 30 份整模型快照） |
| 数据读取 | 库结构与各字段边界见 `读库说明.md`；只读查询入口 `query.py` |
| 数据来源 | 首次建库时由任务书导入；之后以库为准。现行 `Task/CO系列任务/CO05.md` 只留任务背景，网络内容在库里 |
| 前置条件 | 本机可运行 Python 3.11+ 与浏览器（只需标准库，无需第三方库、无需联网） |
| 更新日期 | 2026-10-13 |

## 1 工具做什么

1. **解析**：读一份任务书 Markdown，按标题切成「开发路线」，按编号切成「实现目标条目」。
2. **成图**：同一路线下的编号条目自动形成「依次向上依赖」；条目括号里写明的跨路线依赖绘制成曲线边。
3. **编辑**：新增/插入/删除/上下移动条目与路线；插入后自动处理**后续编号顺位偏移**，并**改写正文里指向被移动条目的引用**。
4. **实时渲染**：每步编辑后立即重画；节点上只写「实现目标概要 + 章节索引」，点击节点打开详情编辑框。
5. **校验**：列出未解析依赖、依赖成环、空条目、未写实现路径的对象等，用于核对网络图的依赖空缺。
6. **存档**：全部数据存放在一份 SQLite 库里，整模型覆盖写入，并按时间限流追加整模型快照，供误操作恢复与只读查询。

本工具**不改写** `Task/` 下的原任务书；导出产物写入 `Tool/项目网络图/数据/导出/`。

## 2 启动与关闭

在工作区根目录运行：

```bash
python3 Tool/项目网络图/server.py
```

只监听 `127.0.0.1:8791`，默认自动打开浏览器。若不希望自动打开或端口被占用：

```bash
python3 Tool/项目网络图/server.py --no-browser --port 8792
```

浏览器打开终端打印的地址即可。编辑过程中每次操作都会自动写入 `数据/项目网络图.sqlite`；结束编辑后在终端按 `Ctrl+C` 停止。库路径可用环境变量 `PN_DB` 指向别的库文件（用于对副本库做端到端测试，不影响正在用的数据）。

数据读取与恢复：

```bash
python3 Tool/项目网络图/query.py --outline          # 一屏速览路线与条目
python3 Tool/项目网络图/db.py --check Tool/项目网络图/数据/项目网络图.sqlite       # 库自检
python3 Tool/项目网络图/db.py --snapshots Tool/项目网络图/数据/项目网络图.sqlite   # 快照清单
python3 Tool/项目网络图/db.py --restore Tool/项目网络图/数据/项目网络图.sqlite --snapshot-id 12
```

## 3 输入格式（任务书约定）

```markdown
## 瓦片地图
1. 平铺的地图绘制，每个瓦片无区别
2. 禁行地块，部分瓦片纹理笔刷设置禁止通过（依赖角色移动1）（元对象-地格占用组件，用于…）
```

| 位置 | 含义 | 工具如何处理 |
| --- | --- | --- |
| 标题（`#` / `##` / `###`） | 一条开发路线 | 成为网络图的一列；`##` 的父级 `#` 只在图上方作为分组带 |
| 标题之后的署名编号行 `N. 正文` | 一个实现目标 | 成为一个节点 |
| 正文（第一个句读之前） | 实现目标概要 | 节点上显示；可在详情框改写 |
| 正文（其余部分） | 实现目标说明 | 详情框里编辑；括号外的内容原样保留 |
| 括号内 `依赖X1` | 其他开发路线中的前置条目 | 画成跨路线依赖边；支持 `依赖角色移动1、地图2` |
| 括号内 `元对象-某某组件` | 为实现本目标需要一并构建实现的对象 | 记入该条目与「对象索引」，**实现路径可留空** |
| 括号内 `依赖元效果`（无编号） | 指向整条路线的前置 | 解析到该路线首条；路线不存在时列为「未解析依赖」 |
| 括号内其他长句（>24 字） | 设计方式说明 | 如果这段说明点名了某个程序对象（`TilemapManager` 这类含内部大写的标识符，或 `…管理器`），说明就**归到那个对象下**，成为该对象的「说明 / 备注」；只有完全没点名对象的说明才留在条目的「设计方式说明」里 |

任务书正文里**标题之前的编号列表**（例如「本阶段你需要做的是：1. … 2. …」）视为背景说明，不进入网络图。

## 4 成图规则

1. **依次向上依赖**：同一路线下，第 N 条依赖第 N−1 条，形成链式边。这条边是推导出来的，不占用手工依赖，也不会因插入而断。
2. **跨路线依赖**：只来自正文里显式写的 `依赖…`。
3. **编号基准**：每条路线的起点编号取原文第一条的编号（`角色移动` 从 0 开始就保持从 0 开始），其后顺排。
4. **引用改写**：插入/删除/移动导致编号变化时，所有已绑定目标的引用文本按新编号改写；仍能指到同一目标的别名写法（例如 `地图1` 指的是 `瓦片地图1`）保持原文不动。
5. **别名与后缀**：`地图1` 能解析到 `瓦片地图`，靠的是「引用名是路线名的后缀」这一规则；匹配到多条路线时判为未解析，需在详情框里手工指定。

## 5 界面操作

| 操作 | 位置 |
| --- | --- |
| 打开条目详情编辑框 | 点击图中的节点，或点击左侧条目行 / 校验项 |
| 新增条目 | 路线标题右侧 `＋`（加到末尾）；详情框底部「在此后插入新条目」 |
| 新增子路线 | 路线标题右侧 `＋子`：在该路线下再开一层（层级自动取父级 + 1，插到父级现有子树之后）。例如在「角色技能」下建子路线，章节路径变成 `角色行为/角色技能/子路线` |
| 删除条目 | 详情框底部「删除条目」 |
| 上下移动 | 详情框底部「上移 / 下移」 |
| 改概要 / 说明 / 依赖 / 对象 | 详情框内对应字段；保存时正文括号会重新解析，字段编辑优先。对象的「实现路径」与「说明 / 备注」都是**可拖动下沿调高度的文本框**，适合写长文；多行内容原样保存 |
| 指定未解析依赖 | 依赖行的下拉框选目标条目；只改文本则保存时重新按文本解析 |
| 新增 / 改名 / 删除路线 | 左侧「开发路线」标题右侧的按钮；新增的子路线会缩进显示在父级下面 |
| 平移 / 缩放 | 拖动空白处 / 滚轮；「适配视图」回到全局 |
| 微调节点位置 | 直接拖动节点（存为该条目的手工偏移）；「清除手工挪位」恢复自动排版 |
| 撤销 / 重做 | 顶栏按钮或 `Ctrl+Z` / `Ctrl+Shift+Z` |
| 导入任务书 | 顶栏「导入任务书」：填工作区内路径，或直接粘贴 Markdown |
| 导出 Markdown | 顶栏「预览 Markdown」/「导出 Markdown」（写入 `数据/导出/`） |

节点版面由 `graph.js` 的 `LAYOUT` 决定，改数值即可整体调整：节点宽度 176，高度随概要行数自适应（单行 52，每多一行加 17，最多显示 4 行，超出加省略号），同一列相邻节点的纵向间距 78，概要按节点宽度折行，过长的章节索引截断加省略号。

图上每条开发路线是一列，列顶有该路线的名字与色条；还没有条目的叶子路线也会标出列头并注明「还没有条目」，方便确认新子路线建在了哪里。层级只影响分组与导出时的 `#` 数量，画布上的父子关系一律由 `parent_id` 决定。

## 6 校验项

| 级别 | 类型 | 含义 |
| --- | --- | --- |
| 阻塞 | 未解析引用 | 依赖文本找不到对应路线，或该路线下没有这个编号（例如 `依赖元效果`） |
| 阻塞 | 依赖成环 | 依赖关系构成环，无法排出构建顺序 |
| 提醒 | 空条目 | 正文与概要都为空（原文里只写了「制作」这类未展开项不会触发） |
| 提醒 | 引用了自身 | 依赖目标就是自己 |
| 提示 | 对象未写实现路径 | 对象已声明但未填落点（实现路径是可选项） |
| 提示 | 路线下没有条目 | 该路线在图上没有节点 |

```

├── db.py               SQLite 库结构、整模型读写、快照、自检（无第三方依赖）
├── store.py            工作区定位、库存取路径、旧存档迁移、Markdown 导出
├── query.py            只读查询入口：速览、单条目、依赖、对象、问题、只读 SQL
├── server.py           本机 HTTP 服务与 JSON 接口
├── index.html          页面结构
├── app.css             样式
├── graph.js            布局计算（纯函数，可单独测试）

├── 使用说明.md          本文件
├── 读库说明.md          数据读取方式与各数据条目的边界功能说明
├── 数据/
│   ├── 项目网络图.sqlite  当前网络图（唯一事实来源，首次启动由 CO05.md 初始化）
│   ├── 项目网络图.json    旧版 JSON 存档，仅作一次性迁移来源，不再更新
│   ├── 备份/            旧版 JSON 备份，保留历史文件，不再新增
│   └── 导出/            导出的任务书 Markdown
└── 测试/
    ├── test_model.py    解析 / 重编号 / 引用改写 / 校验 / 往返（unittest）
    ├── test_db.py       库存取往返、视图一致性、只读约束、快照恢复（unittest）
    ├── test_layout.js   布局纯函数测试
    └── smoke_dom.js     前端冒烟测试（需先启动服务）

## 8 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 当前网络图 + 工作区配置 |
| GET | `/api/markdown` | 当前网络图的 Markdown 文本 |
| POST | `/api/op` | 统一操作入口：`insert_node`、`update_node`、`delete_node`、`move_node`、`insert_section`、`update_section`、`delete_section`、`move_section`、`replace`（撤销用） |
| POST | `/api/import` | 按 `path` 或 `text` 导入并替换网络图 |
| POST | `/api/reset` | 按文件重新建立网络图 |
| POST | `/api/export` | 导出 Markdown，返回写入路径与文本 |

所有写路径都被限制在工作区内；服务只监听本机回环地址。写库与导出不提供 HTTP 之外的写入口，只读查询用 `query.py` 或任意 SQLite 客户端打开 `数据/项目网络图.sqlite`。

```

## 10 已知边界

1. 只解析「标题 + 编号条目」这一种任务书结构，且标题层级最深到六级；更深层标题会按六级处理。界面上新建子路线的层级由父级推导，因此不会出现层级浅于父级的路线。
2. 少于 24 字的短括号（例如 `（放技能还是移动还是挂机）`）视为正文的一部分，不摘成说明；长括号才摘出。
3. 导出 Markdown 时，括号会被规范化重写（依赖合并成一个括号、对象之间用 `；`），语义等价但排版可能与原文不同；原任务书不会被覆盖。
4. 不自动补依赖：工具只把「已有声明」和「同路线相邻」画出来，缺失的前置需要人工在详情框里补，补完即可在图上看到。
5. 未解析引用不会被自动猜测目标，只标红等待人工指定。
6. 库是唯一事实来源。`数据/项目网络图.json` 与 `数据/备份/*.json` 只在首次建库时被读取一次用于迁移，之后不再更新；手工改这两个文件对工具没有影响。
7. 快照按 120 秒限流追加，整模型覆盖写入时才可能新增，因此快照可能落后于最新编辑（最多 120 秒，另受 30 份上限约束）。需要精确的当前数据时读表，不要读快照。
8. 条目编号、依赖边、对象索引、`index_label`、统计值都是派生数据，不落表；库中的派生列（`nodes.summary_is_auto`、`node_refs.section/number/reason`）由工具在每次写入时重算，不要手工改。
9. 条目与路线的 `id`（`n1`、`s1`）是工具内部标识：导入、重置或撤销整体替换后可能重新分配，不能当作长期身份引用。
10. 库损坏时工具把原文件改名成 `项目网络图.broken-<时间戳>.sqlite` 留档，再按「旧 JSON 存档 → 默认任务书」重建，不会静默删数据。
11. 只读查询与浏览器编辑可以同时进行；SQLite 的行级写锁偶尔会让读操作报 `database is locked`，稍后重试即可。
12. 写入过程中可能在 `数据/` 里短暂出现 `项目网络图.sqlite-journal`，正常结束后自动删除；`数据/.gitignore` 已排除这类临时文件与 `.broken-*.sqlite` 损坏留档，`项目网络图.sqlite` 本身仍纳入版本控制。
