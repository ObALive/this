# 一、数据落点与唯一事实来源

| 载体 | 状态 | 说明 |
| --- | --- | --- |
| `数据/项目网络图.sqlite` | **唯一事实来源** | 全部路线、条目、依赖、对象、说明、快照都在这里；工具每次编辑后整模型覆盖写入 |
| `数据/项目网络图.json` | 冻结 | 旧版 JSON 存档；只在库不存在时被读取一次用于迁移，之后不再更新 |
| `数据/备份/*.json` | 冻结 | 旧版滚动备份；保留历史，不再新增 |
| `数据/导出/*.md` | 产物 | 由工具导出的任务书 Markdown，可被覆盖，不是事实来源 |
| `Task/**` 原任务书 | 只读输入 | 工具不改写原任务书；导入后源文件与库不再自动同步 |

三条由此推出的读取原则：

1. **只读库**。要判断「现在图上有什么」，读库；不要读旧 JSON，也不要读导出产物。
2. **不反向回写**。需要修改时走工具界面或 `server.py` 接口，不要直接对库执行 INSERT/UPDATE/DELETE（详见第六章）。
3. **库是过程数据**。库路径、条目编号、路线编号都属于过程信息，只落在 `Tool/`、`Task/`、`Output/`、`Report/` 内；三个设计库的正文与台账不得引用它们。

# 二、三种读取方式

按「读多少」选择方式，避免为了一个问题把整图读进上下文。

| 想解决的问题 | 首选方式 | 输出规模 |
| --- | --- | --- |
| 一屏了解全图：有哪些路线、各条目概要、依赖与对象 | `query.py --outline` | 与条目数同阶（约每节点 1 至 2 行） |
| 看单个条目的全部字段（正文、依赖、对象、说明） | `query.py --node <id>` | 十几行 |
| 只看依赖空缺 / 只看对象缺实现路径 | `query.py --refs --unresolved`、`query.py --objects --missing-path` | 与命中数同阶 |
| 看阻塞问题（未解析、成环） | `query.py --issues --level error` | 与问题数同阶 |
| 精确筛选、聚合、自定列 | `query.py --sql "<SELECT …>"` 或任意 SQLite 客户端只读打开 | 自行控制 |
| 在 Python 里加工 | `import db, query`，见 §2.4 | 不经过文本 |
| 拿整图数据（等价 `/api/state`） | `query.py --view --json` | 最大，仅在确实需要整图时用 |

## 2.1 命令行速览

在工作区根目录运行（默认读工具自带库）：

```bash
python3 Tool/项目网络图/query.py --outline
python3 Tool/项目网络图/query.py --node n2
python3 Tool/项目网络图/query.py --node 瓦片地图2        # 也接受「路线名+编号」，匹配不唯一时报错
python3 Tool/项目网络图/query.py --section s1
python3 Tool/项目网络图/query.py --refs --unresolved
python3 Tool/项目网络图/query.py --objects --missing-path
python3 Tool/项目网络图/query.py --edges --limit 20
python3 Tool/项目网络图/query.py --issues --level error
python3 Tool/项目网络图/query.py --stats
python3 Tool/项目网络图/query.py --find 地格占用
python3 Tool/项目网络图/query.py --schema                  # 列出表与视图及其列
python3 Tool/项目网络图/query.py --verify                  # 结构、完整性、外键、统计
```

加 `--json` 输出结构化数据，便于脚本二次处理；`--limit` 控制列表与 SQL 的最大行数（默认 200）。库不在默认位置时用 `--db <路径>`；环境变量 `PN_DB` 会覆盖默认库路径（工具与查询入口同时生效，便于对副本库做测试）。

## 2.2 只读 SQL

```bash
python3 Tool/项目网络图/query.py --sql "SELECT index_label, summary FROM v_node WHERE number = 1"
```

只允许 `SELECT` / `WITH` / `PRAGMA` / `EXPLAIN`，并且连接以 `mode=ro` 打开，任何写入都会被数据库拒绝。也可以用任意 SQLite 客户端打开同一个文件；工具**不使用 WAL**，因此只读打开不需要额外的 `-shm` 文件。

## 2.3 直接用 Python

```python
import sys
sys.path.insert(0, "Tool/项目网络图")
import db, query

conn = db.connect("Tool/项目网络图/数据/项目网络图.sqlite", readonly=True)
outline = query.outline(conn)                 # 全图骨架（字典）
detail = query.node_detail(conn, "n2")        # 单条目（字典）
issues = query.issues("Tool/项目网络图/数据/项目网络图.sqlite")   # 现算校验问题
conn.close()

model = db.load_model("Tool/项目网络图/数据/项目网络图.sqlite")   # 需要成图规则时用
```

## 2.4 一次读取的推荐顺序

1. `--outline` 建立全图印象，记下需要的条目 `id`；
2. `--node <id>` 取该条目的完整正文与依赖解析结果；
3. `--refs --unresolved` 与 `--issues --level error` 取本轮要处理的问题；
4. 只有需要跨条目推理（传递依赖、构建顺序、成环）时才用 `--sql` 做递归查询（配方见第五章）。

# 三、库对象清单

## 3.1 表

| 对象 | 行含义 | 关键列 |
| --- | --- | --- |
| `meta` | 库级标量，键值对 | `key`、`value` |
| `model_meta` | 模型可扩展元信息，值为 JSON 文本 | `key`、`value` |
| `aliases` | 引用别名 → 标准路线标题 | `alias`、`target` |
| `sections` | 开发路线（原任务书里的一级至三级标题） | `id`、`seq`、`title`、`level`、`parent_id`、`start_number` |
| `nodes` | 实现目标条目（网络图节点） | `id`、`seq`、`section_id`、`number`、`summary`、`body` |
| `node_refs` | 条目声明的依赖引用 | `node_id`、`seq`、`raw`、`target_id` |
| `node_objects` | 条目声明需要一并实现的对象 | `node_id`、`seq`、`name`、`note`、`path` |
| `node_notes` | 从正文长括号摘出的说明性文本 | `node_id`、`seq`、`text` |
| `snapshots` | 整模型快照 | `id`、`created_at`、`reason`、`payload` |

## 3.2 视图（读取优先用视图）

视图是现算的派生结果，不存冗余数据，因此永远与表一致。

| 视图 | 一行代表 | 用途 |
| --- | --- | --- |
| `v_section` | 一条路线 | 路线 + 章节路径 `path` + 条目数 `node_count` |
| `v_node` | 一个条目 | 条目 + `section_path`、`index_label` + 各类计数 |
| `v_ref` | 一条依赖引用 | 引用原文、解析目标、`resolved` 标记与未解析原因 |
| `v_object` | 一条对象声明 | 对象 + 宿主条目 + `has_path` |
| `v_edge` | 一条依赖边 | 链式与显式依赖统一成 `from → to` |
| `v_stats` | 全库一行 | 全部计数汇总，用于速览与自检 |

# 四、各数据条目的边界与功能

先给一条总规则：**能据以判断的只有表中的内容列与 `seq`/`number`；视图列、缓存列、显示列都只是现算结果。**

## 4.1 字段可信度分级

| 级别 | 字段 | 读时怎么用 |
| --- | --- | --- |
| 权威 | `sections.title/level/parent_id/start_number/note`、`nodes.section_id/summary/body`、`node_refs.raw`、`node_objects.name/note/path`、`node_notes.text`、`aliases.*`、`meta` 的标题与来源 | 可作为判断依据；也是唯一可被编辑改动的部分 |
| 权威（结构） | `sections.seq`、`nodes.seq`、`nodes.number`、`node_refs.seq`、`node_objects.seq`、`node_notes.seq` | `seq` 是排序依据；`number` 是路线内引用键 |
| 派生 | `v_*` 全部视图列、`nodes.summary_is_auto`、`v_edge.kind/raw`、`v_stats.*` | 读来即用，但**不要**把它们写回库或当作独立事实 |
| 缓存 | `node_refs.section/number/target_id/reason` | 解析结果的快照，载入时会重算；`target_id` 为空才代表未解析 |
| 显示 | `nodes.manual` | 只影响节点在图上的位置，无设计含义 |
| 快照 | `snapshots.*` | 只用于恢复历史，可能落后于当前数据 |

## 4.2 `meta`：库的自述

| 键 | 含义 | 边界 |
| --- | --- | --- |
| `schema_version` | 库结构版本，当前 `1` | 读到不认识的版本时不要按本文件假定列含义，先看 `db.py` |
| `tool` | 固定为「项目网络图」 | 用于确认库的来源 |
| `title` | 图标题，取自源任务书名 | 与源文件后续改名无关 |
| `source` | 来源任务书的工作区相对路径 | 只是记录导入时的来源，不代表源文件仍与库一致 |
| `preamble` | 任务书里标题之前的背景说明 | 不参与成图；**不含**任何实时状态 |
| `updated_at` | 最近一次写入时间（本机时间） | 写入动作的时间，不是数据变更的时间 |
| `last_reason` | 最近一次写入来源（操作名或迁移标记） | 仅用于排查「最后一次改的是什么」，不是操作日志 |

## 4.3 `model_meta`：可扩展元信息

| 键 | 含义 | 边界 |
| --- | --- | --- |
| `warnings` | 最近一次导入/重置时解析器给出的提示（例如编号不连续已重排） | **编辑后不会刷新**；不要当作当前校验结果，当前问题用 `query.py --issues` |
| `aliases_note` | 别名机制的说明占位 | 预留字段，当前为空 |
| 其它键 | 值为 JSON 文本 | 未知键按 JSON 解析，解析失败时按原文读出 |

## 4.4 `sections`：开发路线

| 列 | 含义 | 来源 | 边界 |
| --- | --- | --- | --- |
| `id` | 路线标识 `s1`、`s2`… | 工具分配 | 只在当前库版本内有效；导入、重置、撤销整体替换后可能重新分配，不要长期引用 |
| `seq` | 路线的文档顺序，全库唯一 | 文件顺序 | 排序一律用它；不要用 `title` 或 `id` 排序 |
| `title` | 路线名 | 标题文本 | 也是引用解析的匹配键（全名、路径名、后缀、别名）；改名会让原本按旧名解析的引用变成未解析 |
| `level` | 标题层级 1 至 3 | 原 `#` 数量 | 大于三级的标题被压成 3；只影响图上的分组显示 |
| `parent_id` | 上级标题的 `id`，无上级为空 | 标题嵌套 | 章节路径沿它上溯；为空的路线在 `v_section.path` 中就是自身标题 |
| `start_number` | 该路线首条的编号基准 | 原路线第一条的编号 | 影响全路线编号与引用改写；改它等于整条路线重编号 |
| `note` | 标题与首条之间、或条目之后的散落文字 | 原任务书 | 用于保留原文，不成图，不属于任何实现目标 |

## 4.5 `nodes`：实现目标条目

| 列 | 含义 | 来源 | 边界 |
| --- | --- | --- | --- |
| `id` | 条目标识 `n1`、`n2`… | 工具分配 | 同 `sections.id`：当前库内有效，不保证跨导入稳定 |
| `seq` | 条目的全局文档顺序，全库唯一 | 文件顺序 | 跨路线排序用 `seq`；`number` 跨路线会重复 |
| `section_id` | 所属路线 | 解析结果 | 每个条目必属一条路线；路线删除时其条目一并删除 |
| `number` | 路线内编号 | 路线起点 + 顺位 | **引用解析的键**（路线 + 编号）；插入、删除、移动会让后续编号顺延，引用文本由工具同步改写；单独一个数字无法定位条目 |
| `summary` | 图上显示的概要 | 正文第一个句读前的短语，或人工指定 | 人工概要不会随正文变化；`summary_is_auto` 为 0 时说明该概要是人工指定的 |
| `body` | 实现目标说明 | 正文（括号内容已摘出、空白已规范化） | **不是原文逐字副本**：依赖、对象、长说明括号都已取出到别的表；导出时才拼回 |
| `manual` | 手工挪位，JSON 如 `{"dx": 12, "dy": -4}` | 拖拽节点 | 纯显示数据；`{}` 表示自动排版 |
| `summary_is_auto` | 概要是否等于由正文自动推导的结果 | 写入时重算 | 派生列；读它判断「概要是人工定的还是自动的」，不要手工改 |

条目正文可能**同时**有 `summary` 与 `body`：`summary` 是缩略，`body` 才是完整说明；不要只读 `summary` 就断言实现目标已被完整描述。

## 4.6 `node_refs`：依赖引用

| 列 | 含义 | 来源 | 边界 |
| --- | --- | --- | --- |
| `node_id` | 声明这条依赖的条目 | 解析结果 | 依赖方向是「`node_id` 依赖 `target_id`」 |
| `seq` | 同一排版条目内的引用顺序 | 原文顺序 | 同一 `node_id` 内唯一 |
| `raw` | 引用原文，如 `角色移动1`、`地图2` | 原文；编号变化后由工具改写 | 导出 Markdown 时用它；别名写法（仍在指向同一目标时）保持原文 |
| `section`、`number` | 解析到的路线名与编号 | 解析缓存 | 仅供参考；判断是否解析成功要看 `target_id` |
| `target_id` | 前置条目的 `id` | 解析结果 | **为空即未解析**，本条依赖不参与成图；不要用 `raw` 自己猜目标 |
| `reason` | 未解析原因 | 解析结果 | 只对未解析项有内容；载入时重算 |

三条必须知道的边界：

1. **一条引用只指向一个条目。** 同一目标写两次会在 `v_edge` 中合并成一条边，`raw` 取 `seq` 最小的那条。
2. **解析允许别名与后缀。** `地图1` 能指到「瓦片地图 1」，靠的是「引用名是路线名的后缀」；匹配到多条路线时按未解析处理。
3. **删除目标后，引用会在下一次载入时按原文重新解析。** 删除某个被依赖的条目时工具把依赖项置为未解析并写入原因；但下次启动载入时会用 `raw` 重新解析，而编号顺延后的新条目可能占用同一编号，导致这条引用**指向另一个条目**。因此删除条目后应立刻复核 `query.py --refs --unresolved`，必要时在工具里改依赖文本。

## 4.7 `node_objects`：需要一并实现的对象

| 列 | 含义 | 来源 | 边界 |
| --- | --- | --- | --- |
| `node_id` | 声明该对象的条目 | 解析结果 | 同一对象名可以出现在多个条目，这是正常的共享声明 |
| `seq` | 条目内的对象顺序 | 原文顺序 | 导出时按它排列 |
| `name` | 对象名，如 `元对象-地格占用组件` | 括号内声明 | 只是**声明**，不代表对象已实现、已存在或已命名一致 |
| `note` | 用途或实现方式说明 | 括号内逗号后的文字 | 常包含实现约定，回填设计时不能漏读 |
| `path` | 实现路径 | 人工填写 | 可空；为空是「提示」级校验项，不是错误；判断是否已落点用 `v_object.has_path` |

对象索引（同名对象的全部落点）是**派生**结果，用 `v_object` 按 `name` 聚合得到，库里没有单独的索引表。

## 4.8 `node_notes`：摘出的说明性文本

| 列 | 含义 | 来源 | 边界 |
| --- | --- | --- | --- |
| `node_id` | 宿主条目 | 解析结果 | 只是从正文里搬出来的位置，不是独立的实现目标 |
| `seq` | 条目内顺序 | 原文顺序 | 导出时按它还原成括号 |
| `text` | 被摘出的说明，通常是长括号里的设计方式 | 原任务书 | 不参与成图；短括号（不足 24 字）不会被摘出，仍留在 `nodes.body` 里 |

读条目时不要只看 `body`：正文里被摘出的说明在 `node_notes`，依赖在 `node_refs`，对象在 `node_objects`。三者合起来才是原文的完整信息。

## 4.9 `snapshots`：整模型快照

| 列 | 含义 | 边界 |
| --- | --- | --- |
| `id` | 快照编号，自增 | 恢复时用它定位 |
| `created_at`、`created_unix` | 写入时间（本机时间 / Unix 秒） | `created_unix` 用于 120 秒限流判断 |
| `reason` | 写入来源，如 `操作 update_node`、`导入任务书`、`恢复快照 #12` | 不是语义标签，只用于辨认这次改动做了什么 |
| `payload` | 整模型 JSON，与旧版存档同构 | 结构与旧 JSON 完全一致，可被 `model_from_dict` 直接读回 |

快照的三条边界：

1. **可能落后。** 只有距上一份快照超过 120 秒、或导入/重置/恢复等强制写入时才会新增；最多保留最近 30 份，更旧的会被删除。
2. **不是每次编辑都有。** 需要「当前」数据时读表，只有需要「历史」数据时才读快照。
3. **恢复是写操作。** 用 `db.py --restore` 执行；恢复前工具会把当前状态再存一份快照，因此恢复本身也可回退。

# 五、常用读取配方

## 5.1 全部未解析依赖

```sql
SELECT node_index_label, raw, reason FROM v_ref WHERE resolved = 0 ORDER BY node_id, seq;
```

```bash
python3 Tool/项目网络图/query.py --refs --unresolved
```

## 5.2 某个条目的全部前置（含传递依赖）

```sql
WITH RECURSIVE upstream(id) AS (
    SELECT 'n2'
    UNION
    SELECT e.from_id FROM v_edge e JOIN upstream u ON u.id = e.to_id
)
SELECT n.id, n.index_label, n.summary FROM upstream u JOIN v_node n ON n.id = u.id;
```

`v_edge` 的方向是 `from` 为前置、`to` 为依赖方，所以要往上游走时按 `to_id` 连接。

## 5.3 谁依赖某个条目

```sql
SELECT from_index_label, to_index_label, kind FROM v_edge WHERE from_id = 'n2';
```

## 5.4 没有前置的起点条目（可开工项）

```sql
SELECT id, index_label, summary FROM v_node
WHERE id NOT IN (SELECT to_id FROM v_edge) ORDER BY seq;
```

## 5.5 全部阻塞问题

```bash
python3 Tool/项目网络图/query.py --issues --level error
```

# 六、读取边界

读库只负责读出与核对，以下动作不属于读库范围：

| 动作 | 为什么不允许 | 正确做法 |
| --- | --- | --- |
| 直接对库执行 INSERT / UPDATE / DELETE | 表之间有外键与顺序约束，行级改动极易造出与模型不一致的库（编号不再顺排、引用缓存过期） | 用工具界面，或 `server.py` 的 `/api/op` 接口；批量替换用 `db.save_model` |
| 手工修改派生列（`summary_is_auto`、`node_refs.reason` 等） | 每次写入都会重算，改动会被覆盖，且可能让读取方误判 | 改权威列，再让工具重算 |
| 把 `id`（`n1`、`s1`）写入设计文档或长期台账 | 导入、重置、撤销后可能重新分配 | 引用条目时写「路线名 + 编号」或直接写概要 |
| 把库路径、快照编号写进设计文档 | 库是过程数据，`Rules/05_文档库组织规范` 禁止设计库引用过程目录 | 设计文档只写设计内容，落点在 `Output/`、`Report/` 里登记 |
| 用未解析的 `raw` 自行猜测依赖目标 | 别名与后缀匹配由工具统一裁决，自行猜测会与图不一致 | 用 `query.py --refs --unresolved` 列出后交人工在工具里指定 |
| 用 `--issues` 之外的渠道判断「图是否可用」 | 成环、空条目等问题不在库里 | 先跑 `--issues`，`error` 为 0 才算可继续 |

并发边界：浏览器编辑与只读查询可以同时进行；SQLite 的写锁偶尔会让读操作报 `database is locked`，稍后重试即可。库本身不使用 WAL，只读打开不需要额外文件。

# 七、恢复与迁移

| 场景 | 命令 |
| --- | --- |
| 库自检 | `python3 Tool/项目网络图/db.py --check Tool/项目网络图/数据/项目网络图.sqlite --json` |
| 看快照清单 | `python3 Tool/项目网络图/db.py --snapshots Tool/项目网络图/数据/项目网络图.sqlite` |
| 恢复到某个快照 | `python3 Tool/项目网络图/db.py --restore Tool/项目网络图/数据/项目网络图.sqlite --snapshot-id 12` |
| 看表与视图结构 | `python3 Tool/项目网络图/db.py --schema Tool/项目网络图/数据/项目网络图.sqlite` |

迁移是自动的：库不存在而旧 JSON 存在时，工具读入旧 JSON 建成库，并追加一份 `迁移自旧 JSON 存档` 快照。库损坏（无法打开、结构不完整）时，工具把原文件改名为 `项目网络图.broken-<时间戳>.sqlite` 留档，再按「旧 JSON → 默认任务书」重建。
