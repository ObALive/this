# 软件设计案库（架构）

本目录是**全篇一份、持续维护**的架构设计案库。架构设计案规定游戏程序作为一个整体如何成立：由哪些部分组成、各部分负责什么、如何连接、依赖方向是什么，以及系统必须遵守哪些全局技术规则。

本库文档的编制规则见 `Rules/07_架构设计案编辑规范.md`；目录组织与命名规则见 `Rules/05_文档库组织规范.md` 第八章。本文件只登记本库的定位、清单与当前状态，不承载规则条款。

## 一、本库承载的内容

架构设计案回答六个问题：

1. 程序由什么组成？
2. 每一部分负责什么？
3. 部分之间允许怎样依赖？
4. 它们通过什么方式通信？
5. 数据在程序中如何流动和持久化？
6. 整个项目必须遵守哪些统一规则？

## 二、与相邻文档的分界

| 文档 | 解决的问题 |
| --- | --- |
| `Design/` 系统设计稿 | 玩家应该经历什么 |
| **架构设计案（本库）** | 整个程序应该怎样组织 |
| `Code_Design/` 代码设计案 | 这个具体系统为了实现要求，需要哪些程序实体和接口 |
| 伪代码 | 这个接口内部具体按照什么步骤执行 |

架构设计案是代码设计案的上级约束：架构定下的全局规则在具体系统进入代码设计之前确定，代码设计案必须服从。

两者的关系是两个并列维度而非同一维度的上下层，结构图与分工细则见 `Rules/03_文档编辑规范.md` 第七章与 `Rules/07_架构设计案编辑规范.md` 第六章。
