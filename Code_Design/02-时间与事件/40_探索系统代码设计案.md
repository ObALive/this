## 1. 系统定义

### 1.1 系统目的

`SYS-EXPLORE-001` 探索系统承载地图层（术语表 T-182）的呈现与过滤语义：把固定的地图模板读成一组区域与事件点位，把区域形态（术语表 T-067）推算出来，并按形态决定该区域上事件在地图上的呈现条目、可出现的刷新范围与窗口期（术语表 T-003）长度，供玩家点选、事件刷新与条件判定使用。它回答的问题是"这张图上此刻玩家能看到哪些事件、这些事件什么时候过期、区域长什么样"。

### 1.2 系统职责

- 从地图模板读取固定的区域划分、区域连接、事件点位布局与点位的战斗瓦片地图标识，构成地图层的空间基础；地图模板完全固定，不参与随机生成（02-40 §2、§4.2、01-10 §3.6）。
- 承载区域的两种状态——可以进入与封锁，其本局初始状态由局生成的区域解锁状态建立，活动范围内的可进入性由基点与活动范围推导（02-40 §4.2、01-10 §3.2、§3.3、09-20 §2.1）。
- 区域形态（术语表 T-067）的推算与查询：按形态转变事件（场景变化包装事件，术语表 T-065）的状态推算当前形态，不保存形态本身（02-40 §4.1）。
- 区域形态对当前事件池的作用：给出该形态命中的事件刷新范围限制与窗口期长度取数，供事件调度在过滤与实例创建时读取；形态变化后与新形态对应的事件在下一轮刷新中进入当前事件池（02-40 §4.1、02-30 §4.5）。
- 事件在地图上的呈现列表：承载呈现条目（事件实例标识、点位、窗口期、类别、强制标记、呈现状态与锁定标记），按节点解锁状态、封锁状态与隐藏事件标记决定条目的可见性；呈现列表的写入由事件系统经 `API-M03-005` 提交（02-40 §4.4、01-10 §3.8、架构案 3.3 第 5.3 项）。
- 区域封锁规则（术语表 T-068、T-069）的通行限制取数：封锁理由（术语表 T-028）、不允许的载具列表与解锁方式的多规则合并，以及允许的通行方式（术语表 T-029）的对外取数（02-40 §4.3、01-10 §3.7）。
- 地图界面所需数据的提供与地图侧事件的发布；地图界面的绘制、排版与事件信息面板的形态归 M08（架构案 2.4 第 4 项、ARC-M03-001）。

### 1.3 系统边界

本系统负责：区域配置与区域状态的地图侧取数、区域形态的推算与取数、形态对刷新范围限制与窗口期长度的取数、呈现列表与呈现条目的持有与取数、区域封锁规则的通行限制取数、区域解锁状态的受理；这些数据与能力的对外契约。

本系统不负责：

- 事件的生成、事件池的过滤执行、抽取、变体查重与事件状态迁移（归 02-30 事件系统与 M02）；
- 事件在地图上的刷新结果写入（由 02-30 经 `API-M03-005` 提交，本系统不自行生成呈现条目）；
- 事件进入的事件信息面板与点选入口（面板形态归 M08，点选方式与地点条件的判定归 02-30-10 触发条件）；
- 区域与点位的布局设计、基点与活动范围的推导、区域封锁规则的解锁判定与通行求值（归 01-10 区域与位移与 M03 的模块能力）；
- 地图界面的绘制、区块排版、图标表现与载具目的地选取界面的形态（归 M08）；
- 世界时间的推进与窗口期的时间口径（推进的唯一受理入口归 `API-M01-005`，时间口径归 02-10 时间机制）；
- 战斗内的空间判定、地形与射程（归 M05）；
- 剪枝封锁集合与封锁标记的维护、线索树节点解锁状态的写入（归 M06）；
- 随机生成：本系统不申请随机序列，不对区域划分、区域连接与事件点位布局做任何扰动（01-10 §3.6、架构案 7.10）；
- 条件判定的实现（归 `API-M09-004`）、效果叠加（归 M09）、物品写入（归 `API-M09-005`）、存档文件读写（归 M01 与 01-50）。

### 1.4 上游需求

上游设计稿出处：02-40 §1、§2、§4.1 至 §4.4、§5、§6；01-10 §2、§3.1 至 §3.9、§4、§5；02-30 §4.1、§4.2、§4.5、§4.8、§4.9；09-20 §2.1、§4.3、§5、§6；07-30 §3.2、§3.4（经 02-40 §4.1 转引）。

架构出处：架构案 2.3（02-40 主模块 M03、地图界面归 M08）、2.4（界面清单第 4 项「地图界面：M03 提供数据，M08 呈现」，所属阶段为地图阶段）、3.1 ARC-M03-001、3.2（M03 拥有区域、区域形态、事件点位绑定、呈现列表、基点与活动范围）、3.3 第 5 与 5.1 与 5.3 项、5.2.1（世界状态域与区域形态派生项）、5.2.5（两个事件池与形态转变不重算全局集合）、6.6（阶段状态机与结算阶段封闭）、7.10（随机服务的绕过禁令）、9.3 第 6 步、9.5.1、9.5.3 第 9 步、9.5.4。

功能要求：

- `F-EXPLORE-01` 地图是平面地图，由区域区块与事件点构成；玩家在地图上点选事件点，点选之后事件点原地展开事件信息面板（02-40 §1、§5）。
- `F-EXPLORE-02` 地图模板完全固定，区域划分、区域连接与事件点位布局由内容侧一次性配置，不参与随机生成；进入本局事件池的事件按事件属性配置刷新到点位上（02-40 §4.2、01-10 §3.6、09-20 §2.1）。
- `F-EXPLORE-03` 区域有两种状态：可以进入与封锁；区域的初始解锁状态由局生成产出并交付（02-40 §4.2、09-20 §2.1）。
- `F-EXPLORE-04` 游戏不直接保存区域形态，而通过检测转变形态的事件的状态推算当前形态，供相关条件检测使用（02-40 §4.1）。
- `F-EXPLORE-05` 区域形态决定该区域上当前事件池（术语表 T-170）的刷新范围与窗口期长度；形态变化后，与新形态对应的事件进入当前事件池并刷新，新形态相关事件的窗口期受该形态存在时长的约束（02-40 §4.1）。
- `F-EXPLORE-06` 区域形态的变化由事件系统以场景变化包装事件的形式执行；同一时间只有一个事件发生，形态变化本质也是一种事件，不与进行中事件冲突；区域形态属场景局内数据，在事件结束后更新结算（02-40 §4.1、§5、02-30 §4.4）。
- `F-EXPLORE-07` 玩家进入事件并达成不引发形态转变的结束结果时，区域形态保持不变（02-40 §4.1）。
- `F-EXPLORE-08` 已解锁节点对应的事件在开新局时直接在地图上完整呈现窗口期与位置；剪枝封锁节点后该事件随封锁状态从地图上隐去（02-40 §4.4、01-10 §3.8）。
- `F-EXPLORE-09` 隐藏事件（术语表 T-034）不进入地图上的呈现列表，其进度由线索树保留（02-40 §4.4）。
- `F-EXPLORE-10` 区域封锁规则单独管理一条封锁理由、一个不允许的载具列表与一个解锁方式；多规则并存时封锁理由与不允许的载具列表取并集；满足解锁方式后规则自行消失（02-40 §4.3）。
- `F-EXPLORE-11` 通行方式的封锁分边界封锁与全域封锁；步行被全域封锁时载具租赁方式亦不可进入；交通站点位于封锁区域时不可作为载具目的地（02-40 §4.3、01-10 §3.7）。
- `F-EXPLORE-12` 区域上不设立独立于事件的内容点：贸易展开与委托接取全部依赖事件进行（02-40 §4.2）。
- `F-EXPLORE-13` 在地图上的操作不消耗时间，进入事件才推进时间（02-40 §5）。

- 派生：`CLS-EXPLORE-003` 区域形态推算结果由形态转变事件的状态与 `CLS-EXPLORE-002` 推得；刷新范围限制与窗口期长度取数由 `CLS-EXPLORE-003` 推得；通行限制求值结果由 `CLS-EXPLORE-001` 与已提交状态推得。派生项按来源重建，不得作为来源状态使用（架构案 8.2 第 3 条）。
- 写入与生成：`CLS-EXPLORE-004` 与 `CLS-EXPLORE-005` 由 02-30 经 `API-M03-005` 写入，本系统是持有方与取数方；`CLS-EXPLORE-006` 在开新局时由 09-20 经 `API-EXPLORE-006` 交付；`CLS-AREA-xxx` 区域状态由本系统的初始化解锁状态与 01-10 侧的活动范围推导合成。
- 与两个事件池的关系：区域形态只作用于当前事件池的刷新范围与窗口期长度，不影响全局事件池内容集合（架构案 5.2.5；全局集合由 07-30 计算、开新局快照入档，局内不变）。

### 2.4 数据生命周期

按架构案 6.5 分类：常驻对象为本系统的系统对象，由服务容器创建与销毁；数据域对象为 `CLS-EXPLORE-001` 至 `CLS-EXPLORE-006`，随单局创建与销毁，容器常驻、内容按局重置；场景对象无（地图界面实例归 M08）；临时运行对象为形态推算中间量与通行限制求值中间量，单次操作内有效，不跨帧保留、不入档；存档对象为世界状态域切面中本系统的条目，只在采集与恢复期间存在；静态配置对象为 `CLS-EXPLORE-002` 与地图模板、封锁区属性配置、载具属性配置，启动阶段加载，运行期只读。

跨局边界：本系统数据不跨局保留，区域形态、呈现列表与解锁状态每局按生成结果与事件结果重建；跨局的解锁内容经 M06 的局末写入进入跨局存档，下一局才参与全局事件池与呈现取数（架构案 5.5）。

### 2.5 持久化要求

| 数据 | 切面归属 | 粒度与恢复 |
| --- | --- | --- |
| `CLS-EXPLORE-001` 区域封锁规则状态 | 单局存档·世界状态域切面 | 逐条；恢复后未满足解锁方式的规则继续生效 |
| `CLS-EXPLORE-004`、`CLS-EXPLORE-005` 呈现列表与条目 | 单局存档·世界状态域切面 | 逐条；按快照恢复，读档不重新过滤、不重新抽取、不重新分配点位占用 |
| `CLS-EXPLORE-006` 区域解锁状态 | 单局存档·世界状态域切面 | 逐区域；与该局生成结果一致，恢复后不重新生成 |
| `CLS-EXPLORE-003` 区域形态推算结果 | 不入档 | 按来源重建（架构案 5.2.1 派生项、9.3 第 6 步）；恢复后由形态转变事件的状态重算 |
| 刷新范围限制、窗口期长度与通行限制求值结果 | 不入档 | 按来源重建；读取方不得缓存（架构案 8.2 第 3 条） |

采集与装载经 `API-SAVE-001` 声明切面、经 `API-SAVE-009` 提交世界状态域条目执行，本系统不自行序列化状态、不读写存档文件（架构案 7.1）。恢复顺序按架构案 7.1：恢复世界状态域（区域状态、封锁规则、呈现列表、解锁状态）→ 重建派生项（区域形态、刷新范围与窗口期取数、通行限制）；读档不重新生成布局、不重新分配点位占用；界面位置恢复到地图阶段（架构案 9.3 第 9 步）。待上游补充：呈现列表与区域解锁状态的数据域归属与切面登记未在架构案 5.2 逐项写明（见 `REQ-EXPLORE-01`）。

## 3. 状态定义

### 3.1 状态

| 状态主体 | 状态取值 | 定义方 |
| --- | --- | --- |
| `CLS-EXPLORE-001` 区域封锁规则 | 生效、已解除 | 本系统（规则内容由 02-40 §4.3 与 01-10 §3.7 定义） |
| `CLS-EXPLORE-003` 区域形态推算 | 待重算、已推算 | 本系统 |
| `CLS-EXPLORE-005` 呈现条目 | 呈现中、已移除（可见性不构成条目状态，每次取数现场判定） | 本系统 |
| `CLS-EXPLORE-006` 区域解锁状态 | 未建立、已建立 | 本系统（取值由 09-20 交付） |
| 本系统装配 | 未装配、已装配、已就绪、已销毁 | 本系统 |

区域形态的取值本身构成一组枚举（形态取值由内容侧登记，取值清单待上游补充，见 `REQ-EXPLORE-03`），但它不作为独立状态机迁移，只由 `CLS-EXPLORE-003` 的推算结果承载。区域的可进入与封锁取值由 `CLS-AREA-002` 区域状态（AREA），本系统只读取与合成，不拥有。

### 3.2 状态转换

```
区域封锁规则：生效 →（解锁方式条件满足）→ 已解除
区域形态推算：已推算 →（事件结算完成）→ 待重算 →（推算执行）→ 已推算
呈现条目：呈现中 →（事件完成、过期或移除项写入）→ 已移除
         可见性（呈现中／已隐去）为每次取数的现场判定结果，不写回条目状态、不产生状态迁移
区域解锁状态：未建立 →（开新局生成路径受理）→ 已建立
本系统装配：未装配 → 已装配 → 已就绪 → 已销毁
```

### 3.3 状态转换触发条件

| 转换 | 触发 | 承接接口 |
| --- | --- | --- |
| 规则生效 → 已解除 | 解锁方式引用的复合条件全部满足，规则自行消失；求值与解除只发生在事件结束结算后的更新时点 | `API-EXPLORE-202`（经 `API-M01-012` 订阅事件结算完成触发，见 8.5） |
| 形态已推算 → 待重算 | 订阅到 事件结算完成，且该事件的结果标识命中 `CLS-EXPLORE-002` | `API-EXPLORE-201`（经 `API-M01-012` 订阅触发） |
| 形态待重算 → 已推算 | 按命中声明的区域重算并写入推算依据 | `API-EXPLORE-201` |
| 条目可见性变化（不构成状态迁移） | 封锁状态或节点解锁状态变化，随下一次 `API-EXPLORE-005` 取数由 `API-EXPLORE-206` 现场判定 | `API-EXPLORE-005`（经 `API-EXPLORE-206` 判定） |
| 条目呈现中 → 已移除 | 事件完成、窗口期越过或位移结果，由 02-30 的刷新与退出结算提交移除项 | `API-M03-005` 呈现列表写入 |
| 解锁状态未建立 → 已建立 | 开新局生成路径交付区域解锁状态 | `API-EXPLORE-006` |
| 装配状态迁移 | 服务容器按依赖拓扑创建、注入与逆序销毁 | `API-M01-001`、`API-M01-002` |

### 4.2 接口详细定义

### API-EXPLORE-001 QueryRegionMap() 区域与点位配置查询

职责：返回地图模板读取后的区域划分、区域连接与事件点位布局的只读快照，供地图呈现、事件刷新的点位绑定与生成输入取数使用。

输入：
- 参数输入：区域标识、点位标识或由两者构成的筛选条件。
- 状态输入：本系统装配状态。
- 数据输入：地图模板（区域划分、区域连接、事件点位布局、点位的战斗瓦片地图标识）。
- 外部事件输入：无。

读取：
- 地图模板（`CLS-AREA-001`）、区域状态（`CLS-AREA-002`）、事件点位绑定（`CLS-AREA-003`）。

输出：
- 返回值：区域与点位只读快照（区块呈现数据、区域连接、点位归属与占位、战斗瓦片地图标识）。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：`API-M01-003` 配置服务.Query。

产生的状态变化：无。

前置条件：本系统装配状态为已就绪；配置服务已加载地图模板。

后置条件：返回内容为只读形态、不携带写入口；结果与查询时刻的已提交状态一致；不含任何随机扰动结果。

副作用：无。

异常情况：标识不存在时返回未找到；地图模板未加载时返回不可用；区域连接或点位归属缺失时该项按缺失返回并经 `API-M01-010` 记内容日志，不阻塞其余查询。

### API-EXPLORE-002 QueryRegionState() 区域状态与通行限制查询

职责：返回区域的当前状态与通行限制取数，含解锁状态、活动范围内外标记、封锁理由并集与允许的通行方式。

输入：
- 参数输入：区域标识或区域集合。
- 状态输入：区域状态、区域解锁状态、基点与活动范围、区域封锁规则状态。
- 数据输入：封锁区属性配置、载具属性配置、解锁方式引用的条件定义。
- 外部事件输入：无。

读取：
- 区域状态（`CLS-AREA-002`）、`CLS-EXPLORE-006` 区域解锁状态、`CLS-EXPLORE-001` 区域封锁规则、基点与活动范围（`CLS-AREA-004`）。

输出：
- 返回值：区域状态取值、解锁状态、活动范围内外标记、封锁理由并集、不允许的载具列表并集、允许的通行方式。
- 状态输出：无（本接口只读取；规则解除由 `API-EXPLORE-202` 在事件结束结算后的更新时点提交）。
- 事件输出：无（区域状态变化的发布由 M03 的模块能力决定）。
- 外部系统调用：`API-M01-003` 配置服务.Query、`API-M01-010` 日志服务.Write。

产生的状态变化：无（通行限制求值结果按来源重建、不写入来源状态；规则解除不在本接口内发生）。

前置条件：本系统装配状态为已就绪；区域标识可解析。

后置条件：多规则并存时封锁理由与不允许的载具列表按并集返回（02-40 §4.3）；活动范围内的区域标记为可进入；本接口不触发条件判定、不改变任何规则状态，界面取数因此不会造成局内数据变更（架构案 8.4 第 5 条）。

副作用：无。

异常情况：载具属性配置缺失时该项通行方式按不可用处理；解锁求值尚未发生时按现有规则状态返回（求值时点见 8.5）；解锁状态为未建立时区域状态按封锁返回并标记成因。

### API-EXPLORE-003 QueryRegionForm() 区域形态查询

职责：返回指定区域的形态取值及其推算依据，供事件刷新的范围过滤、窗口期取数与条件求值使用。

输入：
- 参数输入：区域标识或区域集合。
- 状态输入：`CLS-EXPLORE-003` 区域形态推算结果、形态转变事件的状态。
- 数据输入：`CLS-EXPLORE-002` 区域形态声明、事件结果配置、事件属性配置。
- 外部事件输入：无（重算由订阅 事件结算完成 驱动）。

读取：
- `CLS-EXPLORE-003` 区域形态推算结果、`CLS-EXPLORE-002` 区域形态声明、事件实例（`CLS-EVENT-006`）。

输出：
- 返回值：区域形态取值、推算时间点、推算依据的事件实例与结果标识清单。
- 状态输出：推算状态由待重算转为已推算。
- 事件输出：无（区域形态转变的发布由 `API-EXPLORE-201` 在其判定成立时执行）。
- 外部系统调用：`API-M02-001` 事件状态查询、`API-M01-003` 配置服务.Query、`API-M10-001` 阶段查询。

产生的状态变化：推算状态由待重算转为已推算；查询本身不改变形态取值。

前置条件：本系统装配状态为已就绪；区域标识可解析。

后置条件：返回结果与最近一次推算一致；推算依据可回溯到具体事件实例与结果标识；派生结果不携带写入口、读取方不得缓存（架构案 8.2 第 3 条）。

副作用：无。

异常情况：形态声明缺失或形态取值未登记时返回无法判定并经 `API-M01-010` 记内容日志，不得以默认形态代替（见 `REQ-EXPLORE-03`）；区域标识不存在时返回未找到；推算状态为待重算时先执行一次重算再返回。

### API-EXPLORE-004 QueryWindowLength() 窗口期长度查询

职责：按区域形态给出该区域上事件的窗口期长度取值，作为事件实例创建时窗口期初始化的输入。

输入：
- 参数输入：区域标识、事件模板标识或事件类别、形态取值（省略时按该区域当前推算形态取数）。
- 状态输入：`CLS-EXPLORE-003` 区域形态推算结果、区域状态。
- 数据输入：事件属性配置的时间配置字段类（窗口期基础参数）、形态取值对应的窗口期参数表。
- 外部事件输入：无。

读取：
- `CLS-EXPLORE-003` 区域形态推算结果、事件属性配置（`CLS-EVENT-003`）、区域状态（`CLS-AREA-002`）。

输出：
- 返回值：窗口期长度取值、生效形态取值、取数依据标识、是否受形态存在时长约束。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：`API-M01-003` 配置服务.Query、`API-M01-010` 日志服务.Write。

产生的状态变化：无。

前置条件：本系统装配状态为已就绪；区域标识与事件模板标识可解析；形态取值已登记。

后置条件：同一区域同一形态下重复取数得到同一致；取值只作为事件实例创建时的窗口期初始化输入，窗口期的实际持有归 02-30 的事件实例。

副作用：无。

异常情况：形态取值为无法判定或未登记时拒绝取数并返回不可用，由调用方按事件配置处理（见 `REQ-EXPLORE-04`）；事件模板未登记形态相关窗口期参数时按事件配置的基础窗口期取数并标记为不受形态约束；区域状态为封锁时仍可返回取值，是否创建实例由 02-30 判定。

### API-EXPLORE-005 QueryMapPresentation() 呈现列表查询

职责：返回地图呈现所需的条目快照，按节点解锁状态与封锁状态给出可见性判定结果，供地图界面绘制与事件进入流程判定使用。

- 参数输入：区域标识、事件类别或由状态与类别构成的筛选条件。
- 状态输入：`CLS-EXPLORE-004` 区域呈现列表、`CLS-EXPLORE-005` 呈现条目、锁定标记、区域状态、活动范围内外标记。
- 数据输入：无。
- 外部事件输入：无。

读取：
- `CLS-EXPLORE-004` 区域呈现列表、`CLS-EXPLORE-005` 呈现条目、节点解锁状态与传闻（`CLS-CLUETREE-006`、`CLS-CLUETREE-007`）、封锁集合与封锁标记（`CLS-PRUNE-001`、`CLS-CLUETREE-009`）、事件实例（`CLS-EVENT-006`）。

输出：
- 返回值：呈现条目只读快照（事件实例标识、点位、窗口期、类别、强制标记、可见性、锁定标记、可进入标记）。
- 状态输出：无（可见性为现场判定结果，不写回条目状态；条目状态只有呈现中与已移除两个取值）。
- 事件输出：无。

产生的状态变化：无。

前置条件：本系统装配状态为已就绪。

后置条件：现场判定为已隐去的条目与已移除条目不出现在快照中；隐藏事件不出现在快照中（02-40 §4.4）；结果与最近一次 `API-M03-005` 写入一致；快照不携带写入口。

副作用：无。

异常情况：筛选条件为空时返回空快照；节点或封锁状态不可读时该条目的可见性结论按已隐去返回并经 `API-M01-010` 记内容日志，不返回未判定的条目；本系统未就绪时返回不可用。

### API-EXPLORE-006 ApplyRegionUnlock() 区域解锁状态受理

- 外部事件输入：无。

读取：
- 地图模板（`CLS-AREA-001`）、区域状态（`CLS-AREA-002`）、`CLS-EXPLORE-006` 区域解锁状态。

输出：
- 返回值：受理结果（建立项数、未匹配项清单）。
- 状态输出：区域解锁状态由未建立转为已建立；区域状态按生成结果初始化；呈现列表清空；形态推算状态置为待重算。

副作用：无（地图界面在开新局完成后一次性取数）。

异常情况：区域标识未在地图模板中登记时跳过该项并入未匹配项清单；同一生成批次重复受理时拒绝并返回已受理；结算阶段内拒绝受理并返回阶段封闭（架构案 6.6 硬规则 2）；区域状态的本局初始化与读档路径互斥，读档路径不走本接口。

### API-EXPLORE-201 DeriveRegionForm() 区域形态推算与转变判定

职责：按形态转变事件的状态与形态声明推算受影响区域的形态，判定形态取值是否变化并驱动转变发布。

输入：
- 参数输入：触发重算的事件实例标识（可省）。
- 状态输入：`CLS-EXPLORE-003` 区域形态推算结果、区域状态、`CLS-EXPLORE-005` 呈现条目。
- 数据输入：`CLS-EXPLORE-002` 区域形态声明、事件结果配置与事件属性配置。
- 外部事件输入：事件结算完成（经 `API-M01-012` 订阅）。

读取：
- `CLS-EXPLORE-003` 区域形态推算结果、`CLS-EXPLORE-002` 区域形态声明、事件实例（`CLS-EVENT-006`）。

输出：
- 返回值：受影响区域的形态取值与变化清单。
- 状态输出：推算状态由待重算转为已推算；推算时间点与推算依据清单更新。
- 事件输出：区域形态转变（仅当形态取值发生变化时）。
- 外部系统调用：`API-M02-001` 事件状态查询、`API-M01-011` 事件分发器.Publish、`API-M01-010` 日志服务.Write、`API-SAVE-009` 数据域变更提交（推算结果为派生项，不入档，此处不提交）。

产生的状态变化：`CLS-EXPLORE-003` 按命中声明的区域更新为最新推算值；未命中的区域保持原值。

前置条件：本系统装配状态为已就绪；触发事件实例可解析；形态声明已登记。

后置条件：受影响区域的形态为最新推算值；推算依据的事件实例与结果标识清单可回溯；取值未变化的区域不产生变化清单、不发布事件。

副作用：发布 区域形态转变；订阅方处理失败不回滚推算结果（架构案 8.4 第 4 条）。

异常情况：形态声明缺失或形态取值未登记时该区域保持上一有效推算值并经 `API-M01-010` 记内容日志，不以默认形态代替（见 `REQ-EXPLORE-03`）；触发事件实例不存在时跳过本次重算；同一区域存在多条命中声明时按内容侧登记的推算顺序取用，顺序未登记时拒绝重算并记内容日志（见 `REQ-EXPLORE-06`）；结算阶段内不执行重算。

### API-EXPLORE-202 EvaluateRegionBlockage() 封锁规则求值与解锁判定

职责：按区域封锁规则与已提交状态求值解锁方式，合成封锁理由并集、不允许的载具列表并集与允许的通行方式。

输入：
- 参数输入：区域标识或区域集合。
- 状态输入：`CLS-EXPLORE-001` 区域封锁规则状态、区域状态、基点与活动范围。
- 数据输入：封锁区属性配置、载具属性配置、解锁方式引用的条件定义。
- 外部事件输入：无。

读取：
- `CLS-EXPLORE-001` 区域封锁规则、区域状态（`CLS-AREA-002`）、基点与活动范围（`CLS-AREA-004`）。

输出：
- 返回值：区域可进入性、封锁理由并集、不允许的载具列表并集、允许的通行方式、边界封锁与全域封锁标注。
- 状态输出：满足解锁方式的规则由生效转为已解除。
- 事件输出：无（发布由调用方或 M03 的模块能力决定）。
- 外部系统调用：`API-M09-004` 条件判定、`API-M01-003` 配置服务.Query、`API-M01-010` 日志服务.Write、`API-SAVE-009` 数据域变更提交（规则解除状态入档）。

产生的状态变化：`CLS-EXPLORE-001` 规则状态迁移；求值结果为派生项、不写入来源状态。

前置条件：本系统装配状态为已就绪；区域与规则标识可解析；条件求值服务可用。

后置条件：同一区域全部规则完成一次求值；并集口径与 02-40 §4.3 一致；受影响的区域在剩余规则中的不允许载具列表里取并集来更新通行方式。

副作用：无。

异常情况：条件求值不可用时该规则保持生效并记内容日志；解锁方式引用的条件未登记时该规则保持生效并记内容日志；载具属性配置缺失时该项通行方式按不可用处理；区域同时存在多条规则且部分条件未登记时，取并集的范围只含已登记规则并标记不完整。

### API-EXPLORE-203 QueryFormWindowLength() 形态窗口期取数

职责：按区域形态给出该区域上事件的窗口期长度取值，并标注该取值是否受形态存在时长的约束。

输入：
- 参数输入：区域标识、事件模板标识或事件类别、形态取值（可省）。
- 状态输入：`CLS-EXPLORE-003` 区域形态推算结果、推算时间点。
- 数据输入：形态取值对应的窗口期参数、事件属性配置的时间配置字段类。
- 外部事件输入：无。

读取：
- `CLS-EXPLORE-003` 区域形态推算结果、事件属性配置（`CLS-EVENT-003`）。

输出：
- 返回值：窗口期长度取值、生效形态取值、取数依据标识、是否受形态存在时长约束。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：`API-M01-003` 配置服务.Query、`API-M01-010` 日志服务.Write。

产生的状态变化：无。

前置条件：形态推算状态为已推算；形态取值已登记。

后置条件：同一区域同一形态下取数结果一致；取值只作窗口期初始化的输入，窗口期的持有与过期判定归 02-30。

副作用：无。

异常情况：形态推算状态为待重算时先触发一次 `API-EXPLORE-201` 再取数；形态取值未登记时返回不可用并记内容日志；事件模板未登记形态相关窗口期参数时按基础窗口期取数并标注为不受形态约束。

### API-EXPLORE-204 MaintainPresentation() 呈现列表维护

职责：按 `API-M03-005` 提交的写入项、移除项与锁定范围维护呈现条目、点位占用与锁定标记；条目的可见性不在本功能内写回，由 `API-EXPLORE-206` 在取数时现场判定。

输入：
- 参数输入：刷新批次标识、写入项（事件实例标识、点位、窗口期、类别、强制标记）、移除项、周边事件锁定范围与解除项。
- 状态输入：`CLS-EXPLORE-004` 区域呈现列表、`CLS-EXPLORE-005` 呈现条目、区域状态。
- 数据输入：`CLS-EXPLORE-002` 区域形态声明（用于判定条目所属区域的形态变化）。
- 外部事件输入：无。

读取：
- `CLS-EXPLORE-004` 区域呈现列表、`CLS-EXPLORE-005` 呈现条目、事件点位绑定（`CLS-AREA-003`）。

输出：
- 返回值：维护结果（写入项数、移除项数、按首次现场判定可隐去的项清单、冲突项清单）。
- 状态输出：呈现条目在呈现中与已移除之间迁移；点位占用与释放；锁定标记建立与解除。
- 事件输出：无（由 `API-M03-005` 统一发布 呈现列表更新，含锁定范围时发布 周边事件锁定）。
- 外部系统调用：`API-SAVE-009` 数据域变更提交（可见性由 `API-EXPLORE-206` 在取数时判定，本功能不读取节点与封锁状态）。

产生的状态变化：呈现条目与点位占用更新；移除项与过期条目退出取数范围并释放点位；被封锁条目不发生状态迁移，仅在下一次取数时判定为已隐去。

前置条件：写入项与移除项的事件实例标识、点位标识可解析；点位未被其他事件占用。

后置条件：呈现列表与本次写入项一致；点位占用与写入项一一对应；锁定标记与锁定范围一致；隐藏事件不进入列表；条目状态只有呈现中与已移除两个取值。

副作用：无。

异常情况：点位冲突时该项进入冲突项清单且不改动该点位原有绑定，其余项照常写入；事件实例标识不可解析时跳过该项并记内容日志；隐藏事件被写入时拒绝该项并记内容日志；移除项不存在时忽略该项；锁定范围引用的实例不存在时按单项解除处理。

### API-EXPLORE-205 InitializeRegionUnlock() 区域解锁初始化

- 数据输入：地图模板的区域划分。
- 外部事件输入：无。

读取：
- 地图模板（`CLS-AREA-001`）、区域状态（`CLS-AREA-002`）、`CLS-EXPLORE-006` 区域解锁状态。

输出：
- 返回值：建立项数与未匹配项清单。
- 状态输出：区域解锁状态转已建立；区域状态按生成结果初始化；呈现列表清空；`CLS-EXPLORE-003` 置为待重算。
- 事件输出：无。
- 外部系统调用：`API-SAVE-009` 数据域变更提交、`API-M01-010` 日志服务.Write。

产生的状态变化：区域状态重置；上一局残留的呈现条目与点位占用清空。

副作用：无。

异常情况：区域标识未登记时跳过并入未匹配项清单；同一批次重复受理时拒绝并返回已受理；结算阶段内拒绝受理。

### API-EXPLORE-206 ResolveEntryVisibility() 条目可见性判定

职责：按节点解锁状态、封锁状态与隐藏事件标记判定单个呈现条目的可见性，并给出可进入性标记。

输入：
- 参数输入：呈现条目标识或条目快照。
- 状态输入：区域状态、活动范围内外标记、节点解锁状态、封锁状态、条目锁定标记。
- 数据输入：无。
- 外部事件输入：无。

读取：
- `CLS-EXPLORE-005` 呈现条目、节点解锁状态与传闻（`CLS-CLUETREE-006`、`CLS-CLUETREE-007`）、封锁集合与封锁标记（`CLS-PRUNE-001`、`CLS-CLUETREE-009`）、区域状态（`CLS-AREA-002`）。

输出：
- 返回值：可见性结论（呈现中、已隐去）与可进入标记。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：`API-M06-001`、`API-M06-002`。

产生的状态变化：无（判定结果不写回条目状态）。

前置条件：条目引用的事件实例可解析。

后置条件：隐藏事件与未解锁事件判定为已隐去；被剪枝封锁的事件判定为已隐去；锁定范围内的条目带锁定标记但可见性不变（锁定只作用于进入，不改变事件状态）。

副作用：无。

异常情况：节点或封锁状态不可读时按已隐去返回并记内容日志；条目引用的实例已销毁时判定为已移除。

### 5.2 功能之间的关系

- 形态与窗口期路径：订阅 事件结算完成 → `API-EXPLORE-201` 重算形态；`API-EXPLORE-003` 提供形态取数；02-30 在过滤与实例创建时经 `API-EXPLORE-003` 取形态、经 `API-EXPLORE-004`（内部 `API-EXPLORE-203`）取窗口期长度。
- 呈现路径：02-30 经 `API-M03-005` 提交刷新结果 → `API-EXPLORE-204` 维护条目与点位占用 → `API-EXPLORE-206` 判定可见性 → `API-EXPLORE-005` 供地图界面取数。
- 封锁路径：事件结束结算后的更新时点 → `API-EXPLORE-202` 求值规则、解除满足条件的规则并合成并集；`API-EXPLORE-002`、`API-EXPLORE-007` 只读取数，不触发求值（架构案 5.2.1 的更新时机与 8.4 第 5 条）。
- 开新局路径：09-20 的生成结果 → `API-EXPLORE-006`（内部 `API-EXPLORE-205`）建立区域初始状态 → 02-30 首次刷新经 `API-M03-005` 写入首批条目。
- 查询路径：`API-EXPLORE-001` 只读取，不触发内部功能、不产生事件；`API-EXPLORE-003` 在推算状态为待重算时触发一次 `API-EXPLORE-201`。
- 内部功能只在本系统内被调用，不经服务容器对外暴露；跨模块入口一律使用 M03 的模块能力 `API-M03-001` 至 `API-M03-006`，本系统的 `API-EXPLORE-xxx` 是这些能力与 `REQ-EXPLORE-07` 所列待登记能力的落点。模块级能力 `API-M03-005` 的落点在本系统的内部功能 `API-EXPLORE-204`，模块级能力 `API-M03-006` 的落点在本系统的 `API-EXPLORE-006`，模块级能力 `API-M03-002` 的落点为 `API-EXPLORE-003` 与 `API-EXPLORE-004`。

## 8. 核心流程

### 8.1 开新局的地图侧建立

触发：玩家在局外选择开新局，启动阶段的本局装配走生成路径（架构案 9.5.1）。
参与者：09-20 局生成、M02（生成流程调用与转发）、本系统（`API-EXPLORE-006`）、M01（配置服务、数据域、存档服务）、M08（地图界面）。
调用顺序：1 09-20 按种子与解锁状态计算四项产物，其中区域解锁状态经 `API-M02-005` 交付；2 M02 经 `API-M03-006` 转发写入，落点为 `API-EXPLORE-006`；3 `API-EXPLORE-205` 按地图模板建立各区域初始状态，清空呈现列表并把形态推算置为待重算；4 02-30 执行首次刷新，按 `API-EXPLORE-003` 的形态过滤与 `API-EXPLORE-004` 的窗口期长度创建首批事件实例，并经 `API-M03-005` 写入呈现条目；5 `API-EXPLORE-204` 维护条目与点位占用，`API-EXPLORE-206` 判定可见性；6 M08 打开地图界面并取数。
状态变化：区域解锁状态由未建立转为已建立；区域状态按生成结果初始化；呈现列表由空转为首批条目；形态推算状态置为待重算。
产生的事件：本局生成完成、事件进入当前事件池、事件刷新到点位、当前事件池刷新完成（均由 M02 发布）；区域形态转变仅在该次结算命中形态声明时由本系统发布。
结束条件：地图界面可交互且存在可进入的呈现条目（架构案 9.5.1）。
待上游补充：区域解锁状态的写入由 09-20 直接交付还是由 M02 经 `API-M03-006` 转发，两种写法在 M02 的代码设计案与本文之间尚未统一（承接方：架构设计案 3.3 与本模块的模块级契约，见 `REQ-EXPLORE-05`）。

### 8.2 事件退出后的形态重算与呈现刷新

触发：事件达成结束条件并退出结算，时间推进与自动保存完成后进入当前事件池刷新（架构案 9.5.3 第 3 至 9 步）。
参与者：M10（事件执行器）、M02（退出结算与刷新）、本系统、M01（时间服务、存档服务、事件分发器、日志服务）、M06（节点与封锁状态）、M08（地图界面）。
调用顺序：1 M02 经 `API-M02-004` 完成退出结算并发布 事件结算完成；2 本系统经 `API-M01-012` 收到事件后调用 `API-EXPLORE-201`，按结果标识命中 `CLS-EXPLORE-002` 推算受影响区域的形态，变化时发布 区域形态转变；3 M02 经 `API-EXPLORE-003` 取新形态用于范围过滤、经 `API-EXPLORE-004` 取窗口期长度用于新建实例；4 抽取生成后 M02 经 `API-M03-005` 提交写入项、移除项与锁定范围；5 `API-EXPLORE-204` 维护条目、点位占用与锁定标记，`API-EXPLORE-206` 重判可见性；6 发布 呈现列表更新（含锁定范围时先发布 周边事件锁定）；7 M08 经 `API-EXPLORE-005` 取数并刷新地图界面，M10 回到地图阶段。
状态变化：区域形态推算结果更新；呈现条目迁移与点位占用更新；锁定标记建立或解除。
产生的事件：区域形态转变、周边事件锁定、呈现列表更新；事件结算完成、时间刻度变化、自动保存完成、当前事件池刷新完成、阶段切换由对应模块发布。
结束条件：受影响区域的形态为最新推算值，且呈现列表与 02-30 的刷新结果一致。
顺序约束：本系统的形态重算与 02-30 的下一轮刷新共用同一次退出流程；02-30 在刷新前经模块能力 `API-M03-002`（落点 `API-EXPLORE-003`）取形态，该接口在推算状态为待重算时会先完成一次重算，故抽取过滤不使用旧形态（见 `30_事件系统代码设计案.md` 的 8.1）。

### 8.3 区域形态转变后的刷新范围与窗口期取数

触发：区域形态发生转变，事件系统进入下一轮刷新的范围过滤与实例创建。
参与者：本系统、M02、02-30-10 触发条件、M09（条件求值）、M01（配置服务）。
调用顺序：1 本系统在 `API-EXPLORE-201` 中按形态声明登记刷新范围限制与窗口期参数；2 M02 在刷新时经 `API-EXPLORE-003` 取该区域形态，过滤当前事件池的可用范围；3 M02 在创建实例时经 `API-EXPLORE-004` 取该形态下的窗口期长度并写入实例的窗口期；4 形态相关事件的窗口期受该形态存在时长的约束，约束标记随取数返回；5 由 02-30 完成入池、抽取与刷新写入。
状态变化：无（本系统只提供取数；当前事件池与事件实例由 02-30 持有与变更）。
产生的事件：无（本系统不发布；事件进入当前事件池、事件刷新到点位由 02-30 发布）。
结束条件：本轮刷新的范围过滤与窗口期初始化均以最新形态为依据。
边界：形态变化不需要重算全局事件池内容集合；刷新范围限制与窗口期长度取值按来源重建、不入档（架构案 5.2.5、8.2 第 3 条）。

### 8.4 玩家在地图上点选事件点

触发：玩家在地图上点选一个呈现中的事件点（02-40 §1、§5、02-30 §4.1 第 1 步）。
参与者：M08（地图界面与事件信息面板）、本系统（`API-EXPLORE-005`、`API-EXPLORE-002`）、02-30-10 触发条件（进入资格判定）、M02（事件状态查询）、M10（阶段状态机）。
调用顺序：1 M08 经 `API-EXPLORE-005` 取呈现条目并绘制区块与事件点；2 点选经 `API-M01-007` 的意图通道转为一次操作，由 M08 转交 02-30-10 判定进入资格；3 判定需要地图侧输入时，02-30-10 经 `API-EXPLORE-005` 取该条目的可进入标记、经 `API-EXPLORE-002` 取区域状态；4 M08 在原地展开事件信息面板，面板展示窗口期、参考持续时间与强制标记；5 玩家确认进入后由 M10 的事件执行器驱动 `API-M02-007`，阶段切换到事件执行阶段。
状态变化：本系统无状态变化（地图上的操作不推进世界时间，点选不改变事件状态）。
产生的事件：无（本系统不发布；界面打开与阶段切换由 M08 与 M10 发布）。
结束条件：事件信息面板可交互，或玩家关闭面板放弃进入（事件保持可进入直至窗口期结束）。
边界：面板的形态与交互归 M08；点选方式与地点条件的判定归 02-30-10；事件状态归 02-30。

### 8.5 区域封锁解除后的通行限制更新

触发：事件结束结算后的更新时点（本系统经 `API-M01-012` 订阅事件结算完成）；或开新局初始化完成、读档恢复完成后的首个更新时点（02-40 §4.3、架构案 5.2.1 的更新时机）。
参与者：本系统（`API-EXPLORE-202`；取数侧 `API-EXPLORE-002`、`API-EXPLORE-007`）、M09（条件判定）、M01（配置服务、数据域、事件分发器）、M08（地图界面）。
调用顺序：1 订阅收到事件结算完成 → `API-EXPLORE-202` 求值各规则的解锁方式；2 满足的规则由生效转为已解除；3 在剩余规则的不允许载具列表里取并集，更新该区域允许的通行方式；4 经 `API-SAVE-009` 提交规则状态变更；5 M08 在后续取数（`API-EXPLORE-002`、`API-EXPLORE-007`）时按新状态刷新区块的封锁状态与解锁提示。
状态变化：区域封锁规则状态迁移；区域状态与允许的通行方式更新；求值结果按来源重建。
产生的事件：无（本系统不发布；界面刷新由 M08 在取数后执行）。
结束条件：该区域的全部规则完成一次求值，且通行方式与并集口径一致。
边界：界面取数只读，不触发解锁求值、不造成场景局内数据变更（架构案 8.4 第 5 条与 5.2.1 的更新时机）。

## 9. 异常与边界情况

| 判定条件 | 期望结果 |
| --- | --- |
| 区域形态声明缺失或形态取值未登记 | 该区域保持上一有效推算值并经 `API-M01-010` 记内容日志，不以默认形态代替；`API-EXPLORE-003`、`API-EXPLORE-004` 返回无法判定（见 `REQ-EXPLORE-03`） |
| 同一区域存在多条命中的形态声明 | 按内容侧登记的推算顺序取用；顺序未登记时拒绝重算并记内容日志（见 `REQ-EXPLORE-06`） |
| 形态转变事件的事件实例不可解析 | 跳过本次重算，保持上一有效推算值，不阻塞同一批次的其他区域 |
| 玩家进入事件并达成不引发形态转变的结束结果 | 区域形态保持不变，不发布 区域形态转变（02-40 §4.1） |
| 索引不到形态取数所需的窗口期参数 | `API-EXPLORE-004` 按事件配置的基础窗口期取数并标注不受形态约束 |
| 剪枝封锁状态或节点解锁状态变化但未触发刷新 | 随下一次 `API-EXPLORE-005` 取数现场判定可见性（判定为已隐去或恢复为可见），条目的持久状态不发生迁移，取数结果不与封锁状态矛盾 |
| 隐藏事件被写入呈现列表 | 拒绝该项并记内容日志；隐藏事件不进入呈现列表（02-40 §4.4） |
| 写入项的点位已被其他事件占用 | 该项进入冲突项清单且不改动该点位原有绑定，其余项照常写入 |
| 呈现列表为空或筛选无命中 | 返回空快照，不返回错误；地图界面按空列表呈现 |
| 玩家点选事件点后关闭面板放弃进入 | 事件状态不变，条目保持呈现中直至窗口期结束（02-30 §4.2） |
| 区域解锁状态未建立时取区域状态 | 区域状态按封锁返回并标记成因为未建立；`API-EXPLORE-006` 的写入方向未登记前该路径不得实施（见 `REQ-EXPLORE-05`） |
| 同一生成批次重复受理区域解锁状态 | 拒绝并返回已受理；不重置已建立的本局初始状态 |
| 结算阶段内收到形态变更或区域解锁受理 | 按 `API-M10-001` 判定拒绝并返回阶段封闭（架构案 6.6 硬规则 2） |
| 界面取数期间的封锁规则 | `API-EXPLORE-002`、`API-EXPLORE-007` 只读取数，不触发解锁求值；规则解除只在事件结束结算后的更新时点由 `API-EXPLORE-202` 执行（架构案 8.4 第 5 条） |
| 交通站点位于封锁区域，或通行方式被全域封锁 | `API-EXPLORE-007` 返回封锁理由并集与封锁类型标注，目的不可用由调用方按标注判定；步行被全域封锁时载具租赁一并在标注中体现（02-40 §4.3） |
| 区域既未解锁又在活动范围之外 | 判定为封锁，取数返回封锁理由与允许的通行方式的并集 |
| 地图模板缺失区域连接或未登记交通站点 | 该项按缺失返回并记内容日志，不阻塞其余查询 |
| 读档恢复 | 区域状态、封锁规则状态、呈现列表与解锁状态按切面恢复；区域形态、刷新范围与窗口期取数、通行限制按来源重建；不重新生成布局、不重新分配点位占用、不重新抽取（架构案 9.3） |
| 上一局的呈现条目在开新局时残留 | `API-EXPLORE-006` 清空呈现列表并释放点位占用，避免跨局残留 |
| 上游形态取值清单为空或未定义 | 本系统的形态相关能力返回不可用并申报缺口，不自行拟定形态取值（见 `REQ-EXPLORE-03`） |

## 10. 实现约束

实现要求：

- `I-EXPLORE-01` 地图模板完全固定：本系统不得对区域划分、区域连接与事件点位布局做任何随机生成或扰动，也不得申请随机序列用于地图侧取数（01-10 §3.6、架构案 7.10）。
- `I-EXPLORE-02` 区域形态不作为来源状态保存，只由 `CLS-EXPLORE-003` 承载推算结果，按来源重建、不入档；读取方不得把形态推算结果当作来源状态缓存或反推（架构案 5.2.1、8.2 第 3 条）。
- `I-EXPLORE-03` 呈现条目只能由 `API-M03-005` 的写入项建立；本系统不得自行生成条目、不得直接修改事件实例或事件池；呈现列表的唯一写入方是 02-30（架构案 3.3 第 5.3 项）。
- `I-EXPLORE-04` 区域解锁状态由局生成产出，本系统只经 `API-EXPLORE-006` 受理与持有，不得自行计算解锁结果，也不得在局内改写初始解锁状态。
- `I-EXPLORE-05` 区域状态、区域与点位、基点与活动范围的权威数据归 01-10 与 M03；本系统只做取数与合成，不持有权威副本（架构案 3.4 第 5 项、8.2 第 1 条）。
- `I-EXPLORE-06` 区域形态只作用于当前事件池的刷新范围与窗口期长度，不影响全局事件池内容集合；形态转变后由 02-30 在下一轮刷新中按新形态过滤（架构案 5.2.5）。
- `I-EXPLORE-07` 窗口期长度只作为事件实例创建时的初始化输入，窗口期的持有、延长与过期判定归 02-30；本系统不判定过期、不推进世界时间（架构案 7.5）。
- `I-EXPLORE-08` 封锁解除与可进入性合成一律基于已提交状态；条件判定一律经 `API-M09-004`，本系统不得自行实现条件判定（架构案 7.11）。
- `I-EXPLORE-09` 形态与地图侧状态只在事件结算完成后更新；结算阶段开始后不得变更形态、不得受理解锁写入（架构案 6.6、8.3 第 5 条）。
- `I-EXPLORE-10` 存档读写一律经 `API-SAVE-001` 与 `API-SAVE-009`；本系统不得自行读写存档文件、不得自行序列化状态（架构案 7.1）。
- `I-EXPLORE-11` 跨模块状态广播一律经 `API-M01-011`；事件载荷只承载已发生的事实，本系统不发布 `CO01_编制约定_v1` §五词表之外的事件（架构案 8.4 第 1、2、3 条）。
- `I-EXPLORE-12` 配置只经 `API-M01-003` 读取且运行期只读；本系统不得读取文本、音频与表现资源，封锁理由等文案只返回标识、由 M08 经 `API-M08-004` 取用（架构案 7.8、7.9）。
- `I-EXPLORE-13` 本系统的数据与对象 ID 按 `CLS-EXPLORE-xxx`、`API-EXPLORE-xxx` 分配；模块级能力 `API-M03-001` 至 `API-M03-006` 与成员系统 01-10 已登记的对象不重复定义，只引用其 ID。
- `I-EXPLORE-14` 常驻对象由服务容器创建与销毁；`CLS-EXPLORE-001` 至 `CLS-EXPLORE-006` 随单局创建与销毁，容器常驻、内容按局重置（架构案 8.3）。
- `I-EXPLORE-15` 写入失败、标识不可解析、形态声明缺失、封锁求值异常与未匹配的区域标识必须经 `API-M01-010` 写入日志，供内容侧定位配置问题。

待上游补充：区域解锁状态的数据域归属与切面登记（承接方：架构设计案 5.2.1、5.3 与 5.4，见 `REQ-EXPLORE-01`）；区域形态的取值清单与形态转变事件的声明方式（承接方：系统设计文档 02-40 §4.1，见 `REQ-EXPLORE-03`）；形态取值对应的窗口期参数表与刷新范围限制的字段清单（承接方：系统设计文档 02-40 §4.1 与 02-30 §4.9，见 `REQ-EXPLORE-04`）；区域解锁状态写入方向的架构登记（承接方：架构设计案 3.3、3.1 ARC-M03-001 与 09-20 §4.1，见 `REQ-EXPLORE-05`）；同一区域多条形态声明的推算顺序（承接方：系统设计文档 02-40 §4.1，见 `REQ-EXPLORE-06`）；三项能力的模块能力登记与 ID（承接方：架构设计案 3.1 ARC-M03-001 与 M03 模块文档，见 `REQ-EXPLORE-07`）。呈现列表写入能力的 ID 已按 `API-M03-005` 回填（见 `REQ-EXPLORE-02`）。
