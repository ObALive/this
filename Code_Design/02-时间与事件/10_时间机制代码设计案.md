# 时间机制系统

## 1. 系统定义

### 1.1 系统目的

时间机制是「时间即路线」的程序底座：把世界时间（术语表 T-015）定义为一个可比对、可累计、可存档的整数刻度，并规定一切时间消耗在什么时机、以什么口径写进这条刻度。**世界时间是唯一持久化刻度**：事件内只做时间记账（术语表 T-186），事件退出时把累计值一次性写进这条刻度；每推进一步广播一次刻度变化，自动保存节点与界面时间显示由该广播派生（架构案 7.5；设计决策记录决策 91）。

### 1.2 系统职责

本系统（单元码 `TIME`，`SYS-TIME-001`）负责：

- 定义时间段（术语表 T-002）刻度：基本刻度的长度、刻度的唯一表示、由刻度向上换算小时与日等更大单位的规则；
- 定义游戏内日历（术语表 T-006）：历法结构与现实历法一致，闰年与闰月按现实历法计算；
- 定义窗口期（术语表 T-003）与持续时间的**时间口径**：两者的单位、比较方式、窗口期截止位置与失效判定语义；
- 维护事件内时间记账（术语表 T-186）：非战斗事件在进入时按事件配置录入一次性耗时，并把事件内各项操作或行为各自配置的耗时累加到本事件的记账上；战斗事件由战斗模块（M05）以秒为单位累计战斗净时长并持有；**事件内不动世界时间**（架构案 7.5）；
- 维护战斗净时长记账侧的受理口径与退出时的取整规则：对 M05 提交的秒值增量记账，退出时把不足一个时间段的余量向上取整对齐到时间段边界；
- 执行事件退出时的记账结算，并核算本次应**一次性推进**的时间段数量，交 M01 的时间服务受理；
- 写入事件持续时长记录，供日程系统按时间段粒度回顾每段时间经历了哪些事件；
- 提供世界时间的只读查询与日历显示数据；
- 判定某个时间段位置是否落在给定时间区间内，供窗口期与时限类判定使用；
- 声明自动保存的时间段推进节点的判定口径（另一类战斗轮次推进节点由战斗模块侧声明，架构案 5.3）。

### 1.3 系统边界

本系统不负责：

- **世界时间的持有与写入**：世界时间段位置属世界状态域，由 M01 的数据域持有；推进的唯一受理入口是 M01 时间服务的 `API-M01-005`，且只在事件退出时被写入，本系统不持有世界时间的写入口（架构案 5.2.1、7.5）；
- **时间推进的执行与广播**：推进的执行、刻度变化广播、读档时的时间恢复由 M01 时间服务负责；每次推进一步广播一次刻度变化，自动保存节点与界面时间显示由该广播派生；本系统只提供结算后的推进量与取整结果（架构案 7.5）；
- **时间服务自身的生命周期**：时间服务由常驻场景承载，由启动物体按单元装配声明顺序显式初始化并完成相互引用、按逆序销毁（架构案 2.4.1、6.1、6.3、8.3 第 1 条）；本系统不创建、不解析、不就地取用任何常驻单元；
- **时间参数的取数**：窗口期与持续时间登记在事件配置中，读取经 M01 配置服务的 `API-M01-003`；本系统只解释这两个参数的时间语义，不持有事件配置；
- **窗口期长度与事件池内容集合的计算**：窗口期长度由区域形态决定（探索系统 02-40），当前事件池的内容集合由事件调度（事件系统 02-30）与概率池联动（07-30）计算；
- **事件的过期剔除与状态迁移**：越过窗口期的事件由事件系统转为已错过，本系统只提供判定所需的区间判定能力；
- **战斗内时间轴与行动顺序的推进**：战斗时间轴、行动机会与轮次由战斗模块（06-20）负责；本系统只受理战斗模块以秒为单位累计并持有的净时长提交；
- **日程记录与日程界面**：日程表（术语表 T-005）的记录本体与呈现归日程系统（02-20）与 M08，本系统只写入事件持续时长记录；
- **自动保存的执行**：存档提交归 M01 存档服务，本系统只声明时间段推进节点的判定口径；
- **界面时钟、甘特图与提示文案的呈现**：呈现归 M08 与信息传递系统（01-20）；
- **帧时间与引擎的时间机制**：帧时间只用于表现、动画与界面计时，**任何影响游戏状态的判定都不得使用帧时间**；引擎的时间机制只提供帧钟、真实钟与固定步，不提供逻辑钟与刻度调度，世界时间受理、刻度调度、事件内记账与刻度广播按项目实现（架构案 7.5、7.12、8.6 第 6 条）；
- **结算阶段的输入通道**：结算阶段的进入条件是事件结算环节的事件结果提交，不是「结局成立」（架构案 6.6 第 3 条、9.5.5；设计决策记录决策 90）；进入结算阶段后世界时间不再推进（架构案 6.6 硬规则 2），该阶段的可推进性判定由 M10 阶段状态机承担，本系统按 `API-M10-001` 查询阶段后在结算接口上拒绝推进。

#### 世界时间段位置（M01 持有：`CLS-M01-006` 世界时间取值）

世界时间的唯一权威表示（本局自创建以来已经过的时间段总数）是 M01 数据域持有的数据对象，ID 为 `CLS-M01-006 世界时间取值`（世界状态域，架构案 5.2.1、5.4；M01 侧登记见 `Code_Design/00-架构单元/M01_核心与基础设施代码设计案.md`）。该对象不属本系统，本系统不为其分配 ID、不持有写入口，仅在本文档登记其时间语义与读取口径：

| 项 | 内容 |
| --- | --- |
| 本系统登记的语义 | 取值域为不小于零的整时间段序号；本系统的时间换算、窗口期比较与结算一律以该序号为唯一输入 |
| 用途 | 窗口期与持续时间的比较基准；世界时间对玩家的呈现由本系统的 `API-TIME-002` 换算 |
| 本系统访问级别 | 只读；写入一律经 `API-M01-005`，且只在事件退出时被写入，推进量由本系统经 `API-TIME-004` 提交 |
| 生命周期 | 数据域对象，随单局创建，结算提交完成时随世界状态域释放，开新局时重建；读档按世界状态域切面恢复（架构案 5.2.1、8.3 第 3 条） |
| 与其他对象的关系 | 被 `CLS-TIME-004`、`CLS-TIME-006`、`CLS-TIME-007` 读取；派生 `CLS-TIME-009` |
| 是否持久化 | 入档，归单局存档的世界状态域切面；**世界时间是唯一持久化刻度，只在事件退出时被写入**（架构案 7.5）；字段形态与恢复顺序由 M01 与 01-50 的切面清单给出，本系统不自行为其序列化 |

#### CLS-TIME-004 事件内时间记账

| 项 | 内容 |

| 名称 | 事件内时间记账（术语表 T-186） |

### 2.3 数据关系

- `CLS-TIME-001` 与 `CLS-TIME-002` 是全部时间换算的输入常量与静态定义，其中 `CLS-TIME-001` 的常量取值不落表、`CLS-TIME-002` 的显示命名取配置资产；
- `CLS-TIME-001` 只声明规则不承载状态，全部时间值都落在 `CLS-M01-006` 的整序号上；
- `CLS-M01-006` 是世界时间的唯一来源值，**也是唯一持久化刻度，只在事件退出时被写入**；`CLS-TIME-009` 是它在显示侧的派生投影，不得由显示侧反推来源状态（架构案 7.5、8.2 第 3 条）；
- `CLS-TIME-004` 与 `CLS-TIME-005` 是同一事件实例上互斥的两条记账路径：非战斗事件走前者、战斗事件走后者，同一实例不得同时累加两条账；
- 两条记账路径都只在事件内累计、**不动世界时间**；事件退出时由 `API-TIME-004` 把累计值一次性推进世界时间：非战斗事件按整个时间段累加（最小推进单位为一整个时间段），战斗净时长向上取整对齐到时间段边界（架构案 7.5；设计决策记录决策 91）；
- `CLS-TIME-008` 是记账到世界时间之间的唯一中间产物：由 `CLS-TIME-004` 或 `CLS-TIME-005` 经 `API-TIME-004` 产出，交给 `API-M01-005` 受理；
- `CLS-TIME-007` 是结算结果的留痕，由 `CLS-TIME-008` 写入，供日程系统只读查询；
- `CLS-TIME-010` 只作用于 `CLS-TIME-008` 的推进结果与 M01 时间服务的刻度变化广播，不产生独立数据。

### 2.4 数据生命周期

| 分类（架构案 6.5） | 对象 | 创建 | 销毁 |
| --- | --- | --- | --- |
| 静态配置对象 | `CLS-TIME-001`、`CLS-TIME-002`、`CLS-TIME-006`、`CLS-TIME-010` | 启动第 2 阶段（配置装载） | 进程退出 |
| 数据域对象（世界状态域，M01 持有） | `CLS-M01-006` | 启动第 5 阶段（本局装配） | 结算提交完成时随世界状态域释放，开新局时重建（架构案 6.6、8.3 第 3 条） |
| 数据域对象（单局状态域） | `CLS-TIME-004`、`CLS-TIME-005`、`CLS-TIME-007` | 本局装配或事件实例进入进行中 | 事件实例销毁，或结算提交完成时随单局状态域释放（架构案 8.3 第 3 条） |
| 常驻对象 | `SYS-TIME-001` 的对外能力本体 | 启动第 3 阶段由启动物体按单元装配声明顺序显式初始化并完成相互引用（架构案 6.1 阶段 3、8.3 第 1 条） | 程序结束时的逆序销毁；进程终止不执行销毁序列、不做任何收尾承诺（架构案 6.4、9.4） |
| 临时运行对象 | `CLS-TIME-008`、`CLS-TIME-009` 与各接口的调用中间量 | 单次调用 | 调用返回 |

- 唯一持久化刻度：**世界时间是唯一持久化刻度**，只在事件退出时被写入；事件内的两条记账路径是它的输入——非战斗事件按「进入时的一次性耗时 ＋ 事件内各项操作或行为各自配置的耗时」累加，战斗事件按 M05 持有的净时长累加；两个累计量随事件实例与战斗状态入档（架构案 7.5）。
- 状态复位：本单元全部常驻对象在初始化时显式复位自身状态，不假定引擎已提供初始状态（架构案 6.1、8.3 第 7 条、8.6 第 5 条）。

跨局数据：本系统不产生跨局数据。世界时间属单局范畴，开新局时三个数据域全部重建，不继承上一局的世界时间（架构案 8.3 第 3 条）。

### 2.5 持久化要求

| 数据对象 | 是否持久化 | 切面归属 | 恢复方式 |
| --- | --- | --- | --- |
| `CLS-M01-006`（M01 持有） | 是 | 单局存档·世界状态域切面 | 按整序号整体恢复，不重算；恢复后不重新推进。世界时间是唯一持久化刻度，只在事件退出时被写入（架构案 7.5） |
| `CLS-TIME-004` | 是 | 单局存档·单局状态域切面（随事件实例的暂存结果） | 按快照恢复；已结算账不再累加 |
| `CLS-TIME-005` | 是 | 单局存档·单局状态域切面（战斗未结状态与段内累计时长） | 按秒值恢复，取整在事件退出结算时执行；累计与写入由 M05 持有，恢复随 M05 的战斗状态切面驱动（架构案 3.3 第 14 项、5.2.2、7.5） |
| `CLS-TIME-007` | 是 | 单局存档·单局状态域切面 | 按条目恢复，日程记录按快照呈现，读档不重新计算 |
| `CLS-TIME-001`、`002`、`006`、`010` | 否 | 不适用 | 静态配置，由配置版本标识统一覆盖 |
| `CLS-TIME-008`、`009` | 否 | 不适用 | 派生项按来源重建，不入档 |
| 存档结构的序列化形态（本系统涉及的单局状态域切面） | 是 | 单局存档·单局状态域切面 | 采用**判别字段式多态序列化**：序列化结果中只出现自定义的字符串判别值，**不写入运行时类型名**，多态类型按判别值映射；不得使用已被运行时移除实现的二进制序列化机制（架构案 7.1、8.6 第 8 条） |
| 单局存档的写入原子性（由 M01 存档服务执行，本系统不自行写档） | 是 | 单局存档 | 写临时文件后原子替换；提交过程中断时整次作废并保留上一份有效存档（架构案 5.3 第 4 条） |

**退出不提交存档：** 退出游戏即进程终止，退出时不提交存档、不构成任何提交点、不执行销毁序列、不依赖任何退出回调完成存档或收尾。单局存档的唯一可靠写路径是时间段推进与战斗轮次推进两类自动保存节点；任意时刻终止进程后重新启动，必须能正常启动并继续游玩，自上一个自动保存节点以来的进度不恢复（架构案 3.4 第 17 项、5.3 第 4 项、6.4、7.1、9.4；设计决策记录决策 89）。

**待上游补充：** 事件内时间记账与战斗净时长在单局状态域切面内的具体字段归属与恢复位置，由 01-50 的切面清单给出（架构案 5.2 已把战斗净时长（秒）登记为单局状态域内容，且逐条目的写入方与切面粒度不设严格限制）；本系统只声明「两者都入单局存档、不重算、不重新取整」，字段级落点见 `REQ-TIME-03`。

## 3. 状态定义

### 3.1 状态

本系统自身不持有跨帧可变状态机，全部状态集中在记账项与派生判定上：

| 状态载体 | 取值 |
| --- | --- |
| 本单元装配（`SYS-TIME-001` 的对外能力本体） | 未初始化 → 初始化中 → 已初始化 → 已销毁 |
| 事件内时间记账 `CLS-TIME-004` | 未结算账、已结算账 |
| 战斗净时长 `CLS-TIME-005` | 未结算、已结算 |
| 世界时间段位置 `CLS-M01-006`（M01 持有，本系统只读） | 整时间段序号（随推进单调前进） |
| 窗口期判定（每次现算，不保存） | 未越过、已越过 |
| 推进受理（每次现算，不保存） | 已受理、零推进、被拒绝 |

本单元由常驻场景承载，只能由启动物体按单元装配声明顺序显式初始化（架构案 6.1 阶段 3、8.3 第 1 条）。

单局的生命周期状态取值（未装配／局内／已结算）归 M10 阶段状态机，本系统只按 `API-M10-001` 只读查询。

### 3.2 状态转换

```
本单元装配：未初始化 → 初始化中 → 已初始化 → 已销毁
（由启动物体按单元装配声明顺序显式初始化；程序结束时按逆序销毁，进程终止不执行销毁序列、不做任何收尾承诺）

事件实例进入进行中
→ 记账创建：未结算账
→ 事件内每次消耗受理：未结算账（累计值增长，状态不变；世界时间不变）
→ 事件达成结束条件并退出：已结算账
→ 事件实例销毁：记账清除

战斗事件进入战斗
→ 战斗净时长创建：未结算
→ 战斗轮次推进：未结算（秒值增长；世界时间不变）
→ 战斗结束且事件退出：已结算
→ 事件实例销毁：记账清除
```

世界时间段位置的取值只经 `API-M01-005` 前进，不存在回退转换：读档按切面整体恢复到一个确定位置，该恢复不视为一次推进、不广播刻度变化；事件进行中的任何记账都不改变该位置，世界时间只在事件退出时被写入（架构案 7.5）。

### 3.3 状态转换触发条件

| 转换 | 触发 | 对应接口 |
| --- | --- | --- |
| 未初始化 → 初始化中 → 已初始化 | 启动物体读取并校验单元装配声明后，按声明顺序显式调用本单元的初始化方法并完成相互引用 | 无（不经本表接口；架构案 6.1 阶段 3、8.3 第 1 条） |
| 已初始化 → 已销毁 | 程序结束时的逆序销毁；进程终止不执行销毁序列、不做任何收尾承诺 | 无（架构案 6.4、9.4） |
| 记账创建（未结算账） | 事件实例置为进行中，事件执行器录入一次性耗时 | `API-TIME-003`（首次调用即创建） |
| 累计值增长 | 事件内一项操作或行为提交，或战斗模块 M05 以秒为单位累计并提交净时长增量（事件内不动世界时间） | `API-TIME-003` |
| 转为已结算账 | 事件达成结束条件并退出，且推进被受理 | `API-TIME-004` |
| 记账清除 | 事件实例销毁（已完成或已错过） | `API-TIME-005` |
| 世界时间段位置前进 | M01 时间服务受理 `API-TIME-004` 提交的推进量 | `API-M01-005`（执行方为 M01） |
| 持续时长记录写入 | 事件退出结算完成后 | `API-TIME-006` |
| 窗口期判定为已越过 | 当前 `CLS-M01-006` 越过窗口期上界；由事件系统按判定结果把事件转为已错过 | `API-TIME-008`（本系统判定，事件系统迁移状态） |

### 4.2 接口详细定义

### API-TIME-001 GetTimeSegment

职责：返回本局当前的世界时间段序号与刻度换算常量，供需要比较时间的系统使用。

输入：
- 参数输入：无
- 状态输入：世界时间段位置 `CLS-M01-006`
- 数据输入：时间段刻度与历法换算规则 `CLS-TIME-001`
- 外部事件输入：无

读取：
- `CLS-M01-006`（只读）、`CLS-TIME-001`

输出：
- 返回值：当前时间段序号、一个时间段对应的时间长度常量、本局已推进的时间段总数
- 状态输出：无
- 事件输出：无
- 外部系统调用：无（世界时间取值按 `CLS-M01-006` 只读引用取得；推进受理经 `API-M01-005`，读取入口见 6.2）

产生的状态变化：
- 无

前置条件：
- 本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；本局已装配，世界状态域存在

后置条件：
- 返回值与最近一次受理的推进结果一致，不返回缓存值

副作用：
- 无

异常情况：
- 本局未装配（局外阶段）时，世界状态域不存在，判定为不可查询
- 数据域被判定为不可用时，返回失败标识而不返回默认值

### API-TIME-002 GetClock

职责：把世界时间段位置换算为对玩家呈现的日历时间。

输入：
- 参数输入：显示制式（24 小时制或 12 小时制）
- 状态输入：世界时间段位置 `CLS-M01-006`
- 数据输入：游戏内日历定义 `CLS-TIME-002`、时间刻度与历法换算规则 `CLS-TIME-001`
- 外部事件输入：时间刻度变化（每次推进一步广播一次，界面按该广播重新取数，见 7.2）

读取：
- `CLS-M01-006`、`CLS-TIME-002`、`CLS-TIME-001`

输出：
- 返回值：日历显示快照 `CLS-TIME-009`（几月几日几时几分、所在星期、当前时间段在日内的位置）
- 状态输出：无
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 无

前置条件：
- 本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；本局已装配；日历配置已加载且校验通过

后置条件：
- 返回值可由 `CLS-M01-006` 与静态定义完全重建，不引入额外状态

副作用：
- 无

异常情况：
- 日历定义缺失或未通过校验时，判定为不可呈现，返回失败标识
- 显示制式取值未登记时，判定为非法入参，按默认制式返回并写内容日志

### API-TIME-003 RecordTimeCost

职责：受理事件内的一次时间消耗，把消耗记在事件自己的账上，不改变世界时间。

输入：
- 参数输入：事件实例标识、事件类型标识、本次消耗量（非战斗事件为时间段数，战斗事件为秒数）、消费点标识、消耗原因（一次性耗时、操作、行为、战斗净时长）
- 状态输入：事件内时间记账 `CLS-TIME-004`、战斗净时长 `CLS-TIME-005`、当前阶段（`API-M10-001`）
- 数据输入：事件时间参数 `CLS-TIME-006`（含按操作或行为分别声明的耗时字段）
- 外部事件输入：无

读取：
- `CLS-TIME-004`、`CLS-TIME-005`、`CLS-TIME-006`、`CLS-M01-006`

输出：
- 返回值：受理结果与记账累计值
- 状态输出：`CLS-TIME-004` 的累计时间段数增长，或 `CLS-TIME-005` 的累计秒数增长
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 非战斗事件：`CLS-TIME-004` 累计值按本次消耗量增长
- 战斗事件：`CLS-TIME-005` 累计秒数按本次消耗量增长

前置条件：
- 本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）
- 该事件实例处于进行中，且存在对应记账或可创建记账
- 消耗量非负
- 该事件类型的时间记账方式已在事件类型契约中登记（`系统设计文档/02-时间与事件/30-事件系统/30_事件类型表.csv` 的时间推进列；按即用即定登记，设计决策记录决策 95）
- 同一事件实例只使用一条记录路径

后置条件：
- 记账累计值等于原值加受理量
- 世界时间段位置 `CLS-M01-006` 未变化

副作用：
- 累计值超过配置的单事件时间预算时写入运行日志
- 参数不合法时写入内容日志

异常情况：
- 事件实例不存在或不在进行中（含已结算、已销毁）时，判定为不可受理
- 消耗量为负时，判定为非法入参
- 事件类型未登记时间记账方式时，判定为不可受理（按即用即定补登记后重试，设计决策记录决策 95）
- 非战斗事件消耗量不是整数时间段数时，判定为非法入参
- 战斗事件消耗量不是秒粒度、或调用方不是战斗模块时，判定为非法入参
- 同一事件实例混用非战斗记账与战斗净时长两条路径时，判定为记账冲突
- 当前阶段为结算阶段时，判定为封闭阶段拒绝受理
- 调用方以帧计数或帧时间增量作为消耗量时，判定为非法入参：影响游戏状态的判定不得使用帧时间（架构案 3.4 第 16 项、7.5）
- M01 时间服务不可用时，记账仍可受理，结算时再判定

### API-TIME-004 SettleOnEventExit

职责：事件退出时取出本事件记账上的累计值，按事件类型确定推进口径与取整规则，形成**一次性推进量**并交 M01 的时间服务写入世界时间；事件进行中不动世界时间（架构案 7.5；设计决策记录决策 91）。

输入：
- 参数输入：事件实例标识、事件类型标识、结算时点、推进请求标识
- 状态输入：事件内时间记账 `CLS-TIME-004`、战斗净时长 `CLS-TIME-005`、世界时间段位置 `CLS-M01-006`、当前阶段（`API-M10-001`）
- 数据输入：事件时间参数 `CLS-TIME-006`、时间刻度与历法换算规则 `CLS-TIME-001`
- 外部事件输入：无

读取：
- `CLS-TIME-004`、`CLS-TIME-005`、`CLS-M01-006`、`CLS-TIME-006`、`CLS-TIME-001`

输出：
- 返回值：时间推进结算单 `CLS-TIME-008`（推进受理结果、一次推进的时间段数量、取整前后差值、推进后的时间段位置）
- 状态输出：记账转为已结算账；`CLS-M01-006` 按受理结果前进
- 事件输出：时间刻度变化（由 M01 时间服务在推进受理后广播：每次推进一步广播一次，自动保存节点与界面时间显示由该广播派生）
- 外部系统调用：`API-M01-005`（提交一次性推进量）、阶段查询 `API-M10-001`；时间段与日历的换算由 `CLS-TIME-001` 与本系统完成，不外部委托

产生的状态变化：
- `CLS-TIME-004` 或 `CLS-TIME-005`：状态由未结算转为已结算
- `CLS-M01-006`：按推进量前进
- 局面推进结算完成标记：与推进受理结果同步写入

前置条件：
- 本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）
- 事件已达成结束条件并处于退出流程中（事件内不得调用本接口）
- 推进受理入口 `API-M01-005` 可用
- 世界时间段位置已从单局存档或本局装配中恢复
- 同一事件实例的记账尚未结算

后置条件：
- 推进量等于结算后的记账值：非战斗事件为累计时间段数（零头按一整个时间段向上对齐，最小推进单位为一个时间段），战斗事件为秒数按 `CLS-TIME-001` 换算后向上取整到时间段边界
- 推进量与结算单中的时间段数量一致，两者不得出现差一次推进的偏差
- 推进量确定后，世界时间段位置由 M01 的受理结果整体更新，不由本系统分段累加
- 同一事件实例不得重复结算

副作用：
- 推进受理成功后产生时间刻度变化广播，界面与日程按该广播刷新
- 结算单中的推进量大于零时构成自动保存的时间段推进节点，由 M01 存档服务执行提交

异常情况：
- 当前阶段为结算阶段时，判定为封闭阶段，拒绝推进且不改变记账
- 同一事件实例重复调用时，判定为重复结算，返回既有结算结果而不二次推进
- 记账缺失时，判定为数据缺失，按零推进处理并写入内容日志
- 推进量超过单次结算允许的上限时，判定为非法推进量
- 一次结算跨越多个日界时，判定为合法，按 `CLS-TIME-001` 换算推进后的日历位置，不拆分推进
- 事件进行中调用本接口时，判定为顺序错误：事件内只做时间记账，本接口只在事件退出时受理（架构案 7.5、3.4 第 10 项）
- `API-M01-005` 不可用或受理失败时，判定为推进未落库；记账保持未结算，本系统记录失败标识与推进量，是否重试由事件执行器决定

### API-TIME-006 RecordEventDuration

- 状态输出：事件持续时长记录 `CLS-TIME-007` 增加一条

### API-TIME-010 QueryTimeLedger

职责：按事件实例标识返回该实例当前的记账累计值与折算后的时间段数，供日程系统与界面求值正在经历事件的已历时间段数；本接口不改变任何记账。

输入：
- 参数输入：事件实例标识
- 状态输入：事件内时间记账 `CLS-TIME-004`、战斗净时长 `CLS-TIME-005`
- 数据输入：时间段刻度与历法换算规则 `CLS-TIME-001`
- 外部事件输入：无

读取：
- `CLS-TIME-004`、`CLS-TIME-005`、`CLS-TIME-001`

输出：
- 返回值：该实例的在途累计耗时（非战斗事件为时间段数，战斗事件为秒数）、所采用的记账路径、折算后的时间段数与结算状态
- 状态输出：无
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 无

前置条件：
- 本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）
- 该事件实例存在且处于进行中或已结算状态

后置条件：
- 返回值与最近一次受理的记账一致，不返回缓存值、不返回未受理的预测值
- 战斗事件的秒数按 `CLS-TIME-001` 换算为时间段数，取整口径与 `API-TIME-004` 的退出结算一致；本接口不改动记账，也不提前结算

- 无

异常情况：
- 事件实例标识不可解析或该实例无记账时，返回不可得，不返回零值与过期值
- 当前阶段为结算阶段时，查询照常受理（只读不改变局内状态）
- 记账路径冲突（同一实例同时存在两条记账）时，返回失败标识并写内容日志

**待上游补充：** 战斗净时长以秒累计到「不足一个时间段」时，向上对齐采用「对齐到下一个时间段边界」的单一规则（架构案 7.5 与 `06-战斗/20` §3.3），对齐后的时间段数量是否需要一个统一的最小值（例如不足一个时间段仍记为一个时间段）未在上游写明；本接口按「零头向上对齐、零消耗不推进」实现，非零但不足一个时间段的战斗至少推进一个时间段，承接方见 `REQ-TIME-01`。

| API-TIME-106 | 推进结算单的组装 | 否（经 `API-TIME-004`） | 组装推进量与取整差值，交给 `API-M01-005` |

| API-TIME-108 | 时间参数在事件刷新与进入两个时点的解释 | 否 | 刷新时确定窗口期区间的比较基准，进入时确定持续时间段数 |
| API-TIME-109 | 结算阶段的时间封闭校验 | 否 | 在 `API-TIME-003`、`API-TIME-004`、`API-TIME-006` 上统一校验 |

### 5.2 功能之间的关系

- API-TIME-108 是 API-TIME-102 与 API-TIME-107 的前置：先解释参数，再录入耗时或判定区间；
- API-TIME-102 与 API-TIME-105 在一次 `API-TIME-003` 调用内共同完成：先校验消费点，再累加；
- API-TIME-103 与 API-TIME-104 互斥，由事件类型选择，两者都由 `API-TIME-004` 触发，产出 `CLS-TIME-008`；
- API-TIME-106 在 API-TIME-103 或 API-TIME-104 之后执行，产出交给 `API-M01-005`，并在受理成功后交给 `API-TIME-009` 判定自动保存节点；
- API-TIME-101 只被 `API-TIME-002` 与 API-TIME-107 使用，不参与推进；
- API-TIME-109 是全部写入类功能的共同前置校验，任何模块不得绕过；
- 全部写入类功能都只改变记账、不改变世界时间：世界时间只由 API-TIME-106 组装的推进量在事件退出时经 `API-TIME-004` 一次性写入（架构案 7.5）。

### 6.5 依赖方向限制

分层与模块是架构案的**描述性分类**，不承担数据隔离、交互隔离与依赖方向约束职责（架构案 1.6）。本节只用于阅读导航：列出本单元实际依赖的模块与方向，以及仍然成立的少量硬规则。调用是否合法的判据是架构案 3.3 的允许清单、3.4 的禁止清单与 8.1 的依赖方向规则；**同层只读查询按 3.3 第 5 项的通则成立，不需要逐条登记、不需要逐条例外申报**（架构案 8.1、8.2）。

依赖方向（阅读导航）：

- 向基础设施：本单元使用 M01 提供的时间服务、配置服务、日志服务、事件分发器、数据域读取与存档切面（架构案 3.3 第 9、10 项）；世界时间的写入只能由 M01 受理本系统提交的推进量，M01 不回调本系统的规则（架构案 3.4 第 11 项）。
- 向编排：本单元按 `API-M10-001` 只读查询当前阶段，用于结算阶段的封闭校验（架构案 3.3 第 12 项）。
- 同层只读查询：本单元对事件系统（02-30）、日程系统（02-20）、委托系统（05-20）与时间轴与行动顺序（06-20）只做只读查询或作为其调用对象，读取其状态标识而不持有其可变对象。
- 同层写入（已登记的依赖）：战斗模块（M05）以秒为单位累计并持有战斗净时长、写入单局状态域，秒值增量经本系统的 `API-TIME-003` 记入记账；该依赖已由架构案 3.3 第 14 项登记为**写入型依赖**，本系统的立场是「口径与受理方」，双方不互相持有对方的可变对象（架构案 5.2.2、7.5）。
- 表现侧：本单元不引用 M08 的任何界面对象，呈现由 M08 主动查询。

硬规则：

1. 不写入他方数据、不持有对方的可变引用；跨域变更经持有方入口（架构案 3.4 第 5 项、8.2）。
2. 不绕过统一入口：存档、物品写入、效果叠加、随机源、世界时间、资源、场景、输入、日志（架构案 3.4 第 6 至 10 项、第 7 章）；本系统不自行实现时间源、不自行读写存档、不自行创建日志与事件通道。
3. 基础设施不依赖任何具体玩法系统（架构案 3.4 第 11 项）：本单元不得被 M01 反向依赖，世界时间的写入只能由 M01 受理本系统提交的推进量。
4. 不形成循环依赖；跨模块状态广播走事件通道（架构案 3.4 第 12 项、8.4 第 1 条）；本单元不发布新的跨模块事件，只订阅时间刻度变化。
5. 不使用系统基础库的随机源、不在游戏状态判定中使用帧时间、不依赖引擎的退出回调完成存档或收尾（架构案 3.4 第 15 至 17 项）。
6. 不重复实现引擎已提供的能力（架构案 8.6 第 1 条、7.12）：引擎的时间机制只提供帧钟、真实钟与固定步，不提供逻辑钟与刻度调度；世界时间受理、刻度调度、事件内记账与刻度广播按架构案 7.12「项目实现」栏由项目实现（架构案 7.5）。

## 8. 核心流程

### 8.1 非战斗事件的事件内记录与一次性推进

```
触发：玩家在地图界面确认进入一个非战斗事件
参与者：M10 事件执行器、本系统、事件系统、M01（时间服务、配置服务、存档服务）
调用顺序：
  1 M10 事件执行器把事件实例置为进行中（事件内不动世界时间）
  2 事件执行器调用 API-TIME-003，消费点为「进入时一次性耗时」，消耗量取事件配置的持续时间段数；本系统创建 CLS-TIME-004 并录入
  3 事件进行中，每项操作或行为提交后由事件执行器或事件类型实现调用 API-TIME-003，消耗量取该消费点登记的时间段数；事件配置未登记该操作或行为的耗时时不另计，等效于只计一次性耗时
  4 事件达成结束条件，事件执行器调用 API-TIME-004
  5 本系统读取 CLS-TIME-004 累计值，按整个时间段累加（最小推进单位为一整个时间段），组装 CLS-TIME-008，提交 API-M01-005
  6 M01 时间服务受理推进、写入 CLS-M01-006、广播时间刻度变化（每次推进一步广播一次；自动保存节点与界面时间显示由该广播派生）
  7 本系统调用 API-TIME-009 判定自动保存节点，M01 存档服务按判定提交单局存档
  8 事件执行器调用 API-TIME-006 写入 CLS-TIME-007，随后调用 API-TIME-005 清理记账
状态变化：CLS-TIME-004 由未结算账转为已结算账后清除；世界时间段位置一次性前进（事件内始终不变）；持续时长记录增加
产生的事件：时间刻度变化、自动保存完成（由 M01 发布）
结束条件：推进被受理且持续时长记录已写入
约束：事件内只做时间记账，任何步骤都不得改动世界时间（架构案 7.5；设计决策记录决策 91）；持续时长记录（第 8 步）先于「事件结算完成」的订阅方取数完成；该事件的发布时点与载荷由 02-30 的 7.2 登记，本系统不订阅该事件
```

### 8.2 战斗事件的净时长累计与退出取整

```
触发：战斗事件进入战斗阶段
参与者：战斗模块（06-20）、本系统、M10 事件执行器、M01（时间服务、存档服务）
调用顺序：
  1 战斗模块（M05）按轮次推进战斗内时间轴，并以秒为单位累计战斗净时长、写入单局状态域，逐次调用 API-TIME-003（消费点为「战斗净时长」）把秒值增量记入 CLS-TIME-005；世界时间在战斗内不动
  2 战斗结束时，战斗模块提交本次战斗的净秒数；战斗结果标识与达成目标清单仍由战斗模块输出，不进入本系统
  3 事件执行器在事件退出时调用 API-TIME-004；本系统读取 CLS-TIME-005，按 CLS-TIME-001 换算并向上取整对齐到时间段边界，组装 CLS-TIME-008
  4 提交 API-M01-005；M01 受理并广播（每次推进一步广播一次）
  5 写入 CLS-TIME-007，日程按该结果回填本次事件的记录长度
状态变化：CLS-TIME-005 由未结算转为已结算后清除；世界时间段位置一次性前进；持续时长记录增加
产生的事件：时间刻度变化、自动保存完成
结束条件：取整后的推进量被受理
边界：同一战斗事件在不同局、不同战斗进程下的记录长度不同；收尾窗口内不推进世界时间（06-30 §4）；战斗净时长由 M05 持有并写入单局状态域（架构案 3.3 第 14 项、5.2.2、7.5）
```

### 8.3 记账清理与事件生命周期对齐

```
触发：事件实例转为已完成或已错过
参与者：M10 事件执行器、本系统、事件系统
调用顺序：
  1 事件执行器确认该实例的推进已完成结算
  2 调用 API-TIME-005 清除 CLS-TIME-004 与 CLS-TIME-005
  3 事件系统把事件实例置为已完成或已错过，并从地图呈现中移除已错过事件
状态变化：记账条目移除；事件状态迁移
产生的事件：事件结算完成（由 M02 / M10 发布）
结束条件：事件实例销毁且不再持有记账
异常路径：未结算即清理时本系统拒绝，事件执行器先补结算
```

### 8.4 读档后的世界时间与记账恢复

```
触发：启动阶段的读档路径或玩家在局外选择继续
参与者：M01（存档服务、数据域、时间服务）、本系统、事件系统、M10 事件执行器
调用顺序：
  1 M01 存档服务按恢复顺序装载世界状态域切面，整体恢复 CLS-M01-006
  2 装载单局状态域切面，恢复 CLS-TIME-004、CLS-TIME-005 与 CLS-TIME-007
  3 本系统不重算任何时间，也不重新推进；按快照提供 API-TIME-001、API-TIME-002 与 API-TIME-007 的查询结果
  4 若存在未结战斗，战斗模块按记录重建战场与时间轴，恢复到最近一次行动机会开始的时刻，该次行动机会内尚未确认的选择不恢复；已提交的行为结果对应的净时长按快照恢复
状态变化：世界时间段位置与全部记账由空转为快照内容
产生的事件：存档恢复完成（由 M01 发布）
结束条件：阶段状态机进入地图阶段或战斗阶段
约束：恢复过程不重新推进、不重新取整、不重新写入持续时长记录
```

## 9. 异常与边界情况

| 情形 | 判定条件 | 期望结果 |
| --- | --- | --- |
| 非法消耗量 | `API-TIME-003` 收到负数、非整数时间段数或非秒粒度的消耗量 | 拒绝受理，记账不变，写内容日志 |
| 事件内推进世界时间 | 事件进行中调用 `API-TIME-004` 或提交推进量 | 判定为顺序错误：事件内只做时间记账，世界时间不变；推进只在事件退出时受理（架构案 7.5、3.4 第 10 项；设计决策记录决策 91） |
| 帧时间口径的时间输入 | 调用方以帧计数或帧时间增量作为消耗量 | 判定为非法入参；影响游戏状态的判定不得使用帧时间，时间消耗只以时间段数与秒计的净时长表示（架构案 3.4 第 16 项、7.5、8.6 第 6 条） |
| 未登记的时间记账方式 | 事件类型的时间推进列未登记或为空 | 拒绝受理与结算，交由事件系统按即用即定补登记（设计决策记录决策 95）后重试；缺口见 `REQ-TIME-04` |
| 记账路径冲突 | 同一事件实例同时累加 `CLS-TIME-004` 与 `CLS-TIME-005` | 拒绝后到的写入，写内容日志 |
| 结算阶段的时间请求 | 当前阶段为结算阶段 | 拒绝受理、推进与持续时长记录写入（含补写），世界时间不变（架构案 6.6 硬规则 2） |
| 重复结算 | 同一事件实例二次调用 `API-TIME-004` | 返回既有结算结果，不二次推进 |
| 记账缺失 | 结算时找不到该实例的记账 | 按零推进处理，写内容日志，不写入持续时长记录 |
| 未结算即清理 | `API-TIME-005` 在结算前被调用 | 拒绝清理，要求先结算 |
| 推进受理失败 | `API-M01-005` 不可用或返回失败 | 记账保持未结算，记录失败标识与推进量；重试与上报由事件执行器处置 |
| 零消耗事件 | 事件配置的持续时间为零且事件内无耗时 | 推进量为零，不广播刻度变化、不构成自动保存节点，仍写入持续时长记录 |
| 不足一个时间段的战斗 | 战斗净秒数大于零但不足一个时间段 | 向上对齐为一个时间段，构成自动保存节点 |
| 跨日界结算 | 推进后世界时间段位置跨过一个或多个日界 | 合法；按 `CLS-TIME-001` 换算日历位置，不拆分推进、不特殊处理 |
| 消耗超过单事件预算 | 单事件累计时间段数超过配置上限 | 允许受理并写运行日志，由内容侧核对；不静默截断 |
| 时间参数缺失 | 事件配置未给出窗口期或持续时间 | 判定为内容问题，写内容日志；窗口期缺失时该事件不进入可进入状态（由事件系统按参数缺失处置） |
| 窗口期上界来源缺失 | 撤退后的窗口期延长或区域形态对应的窗口期长度未给出 | 本系统不猜值，判定为无法判定，交由事件系统按 `REQ-TIME-05` 补齐 |
| 读档后记账与事件状态不一致 | 快照中存在已结算账但事件实例仍为进行中 | 判定为数据不一致，按未结算处理并要求重新结算，写内容日志 |
| 持续时长记录重复 | 同一事件实例二次写入 | 保留既有记录，写内容日志 |
| 区间非法 | `API-TIME-008` 的下界大于上界或目标位置为负 | 返回非法入参，不做包含判定 |
| 查询时记录损坏 | `CLS-TIME-007` 条目引用的时间段位置越界 | 跳过该条目并写内容日志，其余条目正常返回 |
| 无存档可恢复 | 读档路径下世界状态域切面缺失 | 由 M01 按存档失败语义处置（提示并停在主界面），本系统不提供默认时间 |

## 10. 实现约束

### 10.1 功能要求

- **F-TIME-01** 世界时间必须只在玩家进行有效行为（术语表 T-014）时推进；地图界面上的点选、区域之间的移动操作、对话与放弃进入事件都不推进时间。
- **F-TIME-02** 时间以时间段（术语表 T-002）为基本刻度，一个时间段的长度固定为 10 分钟，也是游戏内时间的最小粒度；小时、天、月、年按现实规则逐级向上换算。
- **F-TIME-03** 游戏内使用一套虚构日历，历法结构与现实一致，闰年与闰月按现实历法由程序计算；对玩家的全部时间呈现都使用游戏内日历。
- **F-TIME-04** 每个事件携带入口开放窗口期与持续时间两组时间参数；越过窗口期的事件在本局失效，由事件系统按判定结果把事件转为已错过。
- **F-TIME-05** 需要消耗时间的过程一律包装为事件承载，因此**时间记账永远发生在事件内部、世界时间的推进只发生在事件退出时**；手动挂机同样包装为事件。
- **F-TIME-06** 非战斗事件在进入时按事件配置的持续时间录入一次性耗时，事件内各项操作或行为按事件配置声明的耗时累加到本事件的记账上；战斗事件的持续长度取决于玩家的战斗进程，在战斗内按秒累计净时长，是区间结果。
- **F-TIME-07** 战斗事件退出时把不足一个时间段的余量向上取整对齐到时间段边界，本次战斗占用的时间段数量即净时长向上取整的结果，并在退出时一次性推进世界时间。
- **F-TIME-08** **事件内只做时间记账（术语表 T-186）、不动世界时间**；事件退出时把累计值一次性推进世界时间，非战斗按整个时间段累加（最小推进单位为一整个时间段），战斗净时长向上取整对齐到时间段边界；事件进行中界面向玩家呈现本次事件已占用时长，使玩家能判断剩余时间与后续事件的窗口期（设计决策记录决策 91）。
- **F-TIME-09** 时间段推进是自动保存的两类节点之一（另一类为战斗轮次推进）；每次推进一步广播一次刻度变化，自动保存节点与界面时间显示由该广播派生；日程表在事件退出后按实际推进量回填。

### 10.2 实现要求

- **I-TIME-01** 世界时间的权威表示必须是一个整时间段序号，不使用浮点或本地时间表示；全部时间参数与时间消耗都以时间段为单位，落在时间段的整数倍上。
- **I-TIME-02** 世界时间段位置随单局创建，结算提交完成时随世界状态域释放、开新局时全部重建；必须入单局存档的世界状态域切面，读档按整序号整体恢复（架构案 6.6、8.3 第 3 条）。
- **I-TIME-03** 事件内的时间消耗必须记在事件自己的记账上（术语表 T-186 事件内时间记账），世界时间在事件退出前不得改变；`API-TIME-003` 不得调用任何推进能力（架构案 7.5；设计决策记录决策 91）。
- **I-TIME-04** 世界时间的推进只有一个受理入口 `API-M01-005`，且只允许由 `API-TIME-004` 在事件退出结算时**一次性**提交：非战斗事件按整个时间段累加（最小推进单位为一整个时间段），战斗净时长向上取整对齐到时间段边界；其他任何模块与接口都不得推进世界时间（架构案 7.5；设计决策记录决策 91）。
- **I-TIME-05** 本系统不持有世界时间的写入口，只读取其值；推进量一律经 `API-M01-005` 提交并整体更新，不由本系统分段累加。
- **I-TIME-06** 一个事件实例只使用一条记账路径：非战斗事件用 `CLS-TIME-004`，战斗事件用 `CLS-TIME-005`，两者互斥且同一实例不得混用。
- **I-TIME-07** 战斗净时长只能由战斗模块（M05）以秒为单位累计并持有、写入单局状态域，其他系统不得使用该记账路径；本系统只受理其秒值增量、持有记账侧并在事件退出时取整对齐（架构案 3.3 第 14 项、5.2.2、7.5）。
- **I-TIME-08** 时间刻度换算常量与取整规则必须在全库唯一，不得在各调用方另行定义；返回给调用方的时间值必须与已经受理的推进结果一致，不得返回未提交的记账值。
- **I-TIME-09** 记账在结算前保持未结算状态，结算后不得再次累加；事件实例销毁时必须清理记账，不得跨事件实例累加。
- **I-TIME-10** 显示侧的日历时间是按来源重建的派生值，不得作为数据来源被反推或缓存为权威值。
- **I-TIME-11** 本系统持有的全部数据对象必须可序列化，其持久化形态不承载显示字符串与本地化文案；存档序列化采用**判别字段式多态序列化**，序列化结果中只出现自定义的字符串判别值、**不写入运行时类型名**，多态类型按判别值映射，不得使用已被运行时移除实现的二进制序列化机制；单局存档的写入必须原子（架构案 7.1、5.3 第 4 条、8.6 第 8 条）。
- **I-TIME-12** 时间参数与推进口径必须可查询：调用方通过 `API-TIME-001`、`API-TIME-008` 与 `API-TIME-009` 取得口径，不得自行实现刻度换算或窗口期比较。
- **I-TIME-13** 结算阶段必须封闭：`API-TIME-003`、`API-TIME-004`、`API-TIME-006` 在结算阶段一律拒绝写入，不设补写例外——三者的写入对象都在数据域内，任何写入都构成改变局内状态（架构案 6.6 硬规则 2）；只读查询（`API-TIME-001`、`API-TIME-002`、`API-TIME-007`、`API-TIME-010`）照常受理。
- **I-TIME-14** 事件持续时长记录必须按时间段粒度登记，并以事件实例标识唯一定位；场景变化包装事件按日程不可见标记登记。
- **I-TIME-15** 存档、日志、事件通道、配置与阶段查询一律经 M01 与 M10 的既有入口，本系统不得自行实现上述能力；跨模块事件的契约以**类型契约**的形式确定、按**即用即定**登记，由**一条对账测试**强制，受理侧不做运行期登记校验（架构案 4.3、7.6、8.4 第 2 条）。
- **I-TIME-16** 不得重复实现引擎已提供的能力：对象池与集合池、异步任务、设备到动作的输入映射、音频与本地化与特效动画的播放原语、资产载体与序列化原语、资源加载、场景装卸与日志通道一律使用引擎提供的能力；**引擎的时间机制只提供帧钟、真实钟与固定步，不提供逻辑钟与刻度调度**，世界时间受理、刻度调度、事件内记账与刻度广播按架构案 7.12「项目实现」栏由项目实现（架构案 7.5、7.12、8.6 第 1 条）。
- **I-TIME-17** 运行期配置的权威载体是引擎编辑器内的配置资产；`系统设计文档/` 的扩展配置表是各自系统的初始素材与迁移来源，程序侧不直接读表，内容侧不直接改运行期资产；配置版本标识写入单局存档并参与读档一致性判定（架构案 5.1、7.9、8.6 第 10 条；设计决策记录决策 93）。
- **I-TIME-18** 权威游戏状态由普通 C# 对象持有，引擎对象只承担承载、呈现与编辑器配置职责；不得把权威状态放在随场景销毁的对象上（架构案 8.6 第 2 条）。
- **I-TIME-19** 不依赖引擎的启动回调顺序、脚本执行顺序或帧回调顺序满足初始化与推进的顺序要求；顺序由单元装配声明与显式调用序列决定（架构案 6.1、6.3、8.6 第 4 条）。
- **I-TIME-20** 本单元在初始化时显式复位自身状态，不依赖引擎的域重载提供初始状态（架构案 6.1、8.3 第 7 条、8.6 第 5 条）。
- **I-TIME-21** 影响游戏状态的判定不得使用帧时间：帧时间只用于表现、动画与界面计时；本作为半回合制，玩家不操作时游戏状态不推进，**不设暂停概念**，任何模块不得以暂停为由冻结数据或引入暂停语义（架构案 3.4 第 16 项、7.4、7.5、8.6 第 6 条；设计决策记录决策 87、88）。
- **I-TIME-22** 世界时间是唯一持久化刻度，只在事件退出时被写入；每次推进一步广播一次刻度变化，自动保存节点与界面时间显示由该广播派生；退出游戏即进程终止，不提交存档、不构成任何提交点、不依赖任何退出回调完成存档或收尾（架构案 3.4 第 17 项、5.3、6.4、7.1、7.5、9.4；设计决策记录决策 89、91）。
