## 1. 系统定义

### 1.1 系统目的

本单元为 `SYS-CONDITION-001 触发条件`，是事件系统（02-30）下的子系统。它回答两件事：事件在什么条件下被允许出现，以及玩家通过什么操作进入事件。条件侧把散落在各系统数据上的判定要求组织成可组合、可扩展、可复用的条件模块；进入方式侧登记事件采用哪种进入方式，当前版本取地图点选一项。

### 1.2 系统职责

- 持有条件的组合结构：与、或、非三种组合节点与作为叶子的条件引用项（设计稿 4.2）；
- 登记条件的引用侧：哪个内容在哪个位点引用哪个条件模块、以什么时机求值、结果用于什么；
- 发起求值请求：按引用项类别装配求值上下文，经 `API-M09-004` 委托条件求值服务，并把判定结果标注其状态版本；
- 定义缓存失效规则：求值结果以状态版本为键，状态提交与存档恢复完成为统一失效时点（架构案 7.11）；
- 持有条件类别登记与触发方式类型登记（架构案 5.1 的先登记后使用）与触发方式声明，并在启动阶段校验条件模块、引用声明与触发方式声明的可解析性与结构合法性。

### 1.3 系统边界

本系统负责：条件模块、组合节点、引用项与条件类别登记的内存形态与只读查询；内容标识到条件模块的引用关系登记与查询；求值请求的组织、上下文齐备性判定与结果的状态版本标注；触发方式声明与类型登记的持有与查询；无法判定与请求拒绝情形的记录。

本系统不负责：

- 条件判定、比较与阈值计算：归 M09 的条件求值服务（`API-M09-004`），本系统不实现任何判定（架构案 7.11、第 10 章第 6 项）；
- 已提交状态、世界时间、区域形态、物品与行情、解锁与封锁状态的持有：归 M01 数据域侧与各来源系统，本系统只登记引用目标，不读取其内容；
- 地图点选的空间侧与面板呈现：事件点位布局、点选受理与面板落点归 M03（`API-M03-001`）与 M08，事件信息面板（术语表 T-183）的展开与进入按钮归 M08（设计稿 4.3、5）；
- 事件状态迁移、当前事件池与进入确认：归 02-30（`API-EVENT-003`、`API-EVENT-005`）；事件解锁与开放阈值的判定与写入归 M06（07-10 的 3.6 与 07-40 的结算写入）；
- 条件的玩家可见性呈现与文案暗示：归 M08 与 01-20（设计稿 4.5）；存档读写、切面结构与恢复顺序归 M01 的存档服务与 01-50，本系统不声明持久化切面。

### 1.5 功能要求

- F-CONDITION-01 条件必须模块化、可扩展、可组合，允许按与、或、非自由组合（设计稿 4.2）。
- F-CONDITION-02 条件判定作用于事件的生成，不作用于事件的进入；刷新到地图上的事件都可以进入，进入时不进行条件判定（设计稿 4.1、4.3）。
- F-CONDITION-03 时间条件、地点条件、前置事件条件、资源门槛与线索解锁都是对已提交存档状态中对应数据表达的条件（设计稿 4.2）。
- F-CONDITION-04 线索解锁是首次触发事件的硬门槛：开放阈值未满足时，即使事件自身条件满足，该事件也不得在局内出现（设计稿 4.4）。
- F-CONDITION-05 当前版本的触发方式取地图点选一项，由本系统的触发方式声明唯一持有、随内容需求保持可扩展，事件属性配置只按标识引用该声明：玩家在地图上点选事件点，事件点原地展开事件信息面板，在面板上点击进入按钮完成进入；进入会推进时间段的事件在进入前由面板给出直接提示（设计稿 4.3、5）。
- F-CONDITION-06 物品条件读取当前已提交存档中的物品实例、组件与归属，不改变物品状态；条件配置必须声明物品需求与可见范围；涉及物品资格的部分按物品词条判断，条件引用词条标识（设计稿 4.6、6）。
- F-CONDITION-07 条件信息不做直接提示，揭露经线索树触发方法揭示与文案暗示两条渠道；玩家拒绝进入已发现事件不改变事件状态，条件判定不因拒绝而失效（设计稿 4.5、5）。

### 2.3 数据关系

条件模块以组合节点构成结构，组合节点逐层指向子节点、叶子为条件引用项，一个模块被若干条条件引用声明指向；条件引用项引用一个条件类别登记项并携带来源系统数据的引用目标标识，引用目标的内容归来源系统、本系统不复制；求值请求由条件模块、求值上下文与状态版本构成，上下文所需项由引用项类别决定；触发方式声明引用一个触发方式类型登记项并被事件属性配置按标识引用；条件求值结果与求值结果缓存是按来源重建的派生项。

### 2.4 数据生命周期

静态配置对象（条件模块、组合节点、引用项、类别登记项、引用声明、触发方式声明与类型登记项）在启动阶段随配置加载，运行期只读，进程退出销毁；求值上下文与求值请求为临时运行对象，在单次判定内有效、不跨帧保留、不入档；条件求值结果与求值结果缓存为派生项、按来源重建，本系统持有其键与失效时点声明，缓存本体归条件求值服务；本单元不持有随单局创建与销毁的数据对象，也不向任何数据域写入。

### 2.5 持久化要求

本系统不声明持久化切面，不写入任何数据域（架构案 8.2、7.1）。静态配置对象随配置版本标识绑定、不单独入档；求值上下文与求值请求不入档；条件求值结果与求值结果缓存按来源重建、不入档（架构案 8.2 第 3 条与 `50_存档与持久化设计.md` 第 7 节的派生项口径）。读档不改变条件配置，恢复完成后按恢复后的已提交状态版本重建求值结果的键。

## 3. 状态定义

### 3.1 状态

| 对象 | 状态取值 |
| --- | --- |
| 条件类别登记项（`CLS-CONDITION-004`）、触发方式类型登记项（`CLS-CONDITION-009`） | 未登记、已登记 |
| 求值请求（`CLS-CONDITION-007`） | 已装配、已委托、已返回、已拒绝 |
| 触发方式声明（`CLS-CONDITION-008`） | 未声明、已声明 |
| 条件模块、组合节点、条件引用项、条件引用声明 | 无状态：静态配置，加载后只读 |
| 求值上下文（`CLS-CONDITION-006`） | 无状态：随请求产生与释放 |
| 求值结果缓存（外部持有，M09 条件求值服务） | 有效、已失效 |

### 3.2 状态转换

```
条件类别登记项、触发方式类型登记项：未登记 →（启动校验通过）→ 已登记
触发方式声明：未声明 →（内容侧声明并通过启动校验）→ 已声明
求值请求：已装配 →（受理并委托）→ 已委托 →（返回）→ 已返回；已装配 →（拒绝）→ 已拒绝
求值结果缓存（外部）：有效 →（状态提交或存档恢复完成）→ 已失效
```

### 3.3 状态转换触发条件

| 状态转换 | 触发条件 | 承接接口 | 产生的事件 |
| --- | --- | --- | --- |
| 未登记 → 已登记 | 迁移方为启动校验流程（M01 配置服务的配置装载）：条件类别与触发方式类型可解析、引用完整，登记态落定 | `API-CONDITION-005`、`API-CONDITION-004`（登记态的暴露入口） | 无（配置加载完成由 M01 发布） |
| 未声明 → 已声明 | 迁移方为启动校验流程（M01 配置服务的配置装载）：本系统按事件属性配置的引用登记该事件的触发方式声明，校验通过后登记态落定 | `API-CONDITION-004`、`API-CONDITION-005`（登记态的暴露入口） | 无（配置加载完成由 M01 发布） |
| 已装配 → 已委托 | 求值请求受理，上下文齐备且状态版本与已提交状态一致 | `API-CONDITION-002` | 无 |
| 已委托 → 已返回 | 条件求值服务返回判定结果 | `API-CONDITION-002` | 无 |
| 已装配 → 已拒绝 | 模块不可解析、上下文缺项、状态版本过期或当前阶段不允许受理 | `API-CONDITION-002` | 无 |
| 有效 → 已失效 | 状态提交使状态版本变化（`API-SAVE-009` 数据域变更提交被受理），或收到存档恢复完成 | 无（缓存本体归条件求值服务） | 无 |

条件判定、条件查询与求值请求按架构案 4.5 判定为只读查询与直接调用，均不产生事件；本系统不发布任何跨模块事件。

## 4. 对外接口

### 4.1 接口列表

本系统的对外能力是 M02 模块能力「触发条件的模块组合与求值调用」（架构案 3.1 ARC-M02-001 的负责栏）在子系统内的落点；模块级装配与模块能力契约由 `M02_事件与生成代码设计案.md` 定义，接口 ID 由本单元分配。

| 接口 ID | 接口 | 调用者 | 输入 | 输出 | 状态变化 | 副作用 |
| --- | --- | --- | --- | --- | --- | --- |
| `API-CONDITION-001` | QueryConditionModule 条件模块查询 | 02-30 事件系统、06-75 元效果系统、M06 元进度与结算、M09 条件求值服务 | 条件模块标识 | 组合结构只读视图：组合算子、子节点、引用项与类别标识 | 无 | 无 |
| `API-CONDITION-002` | RequestConditionEvaluation 条件求值请求 | 02-30 事件系统、06-75 元效果系统 | 条件模块标识、求值上下文、状态版本标识 | 判定结果（满足／不满足／无法判定）与所用状态版本 | 求值请求 已装配→已委托→已返回，或 已装配→已拒绝 | 经 `API-M09-004` 委托判定；无法判定、版本过期与拒绝经日志服务记录 |
| `API-CONDITION-003` | QueryConditionBinding 条件引用查询 | 02-30 事件系统、M06 元进度与结算、M09 条件求值服务 | 内容标识、引用位置筛选（可空） | 引用清单：引用位置类别、条件模块标识、求值时机、结果用途 | 无 | 无 |
| `API-CONDITION-004` | QueryTriggerMethod 触发方式查询 | M08 界面与信息、02-30 事件系统 | 事件模板标识 | 触发方式声明：方式类型、进入受理侧、进入前确认要求、是否允许放弃 | 无 | 无 |
| `API-CONDITION-005` | QueryConditionCategory 条件类别清单查询 | M09 条件求值服务、M01 配置服务、02-30 事件系统 | 类别标识（可空） | 已登记类别清单：类别标识、引用目标类型、所需上下文项 | 无 | 无 |

### 4.2 接口详细定义

### API-CONDITION-001 QueryConditionModule 条件模块查询
职责：按条件模块标识返回该模块的组合结构只读视图，供求值请求发起方与配置校验使用。
输入：参数输入：条件模块标识；状态输入：条件类别登记项的登记态；数据输入：条件模块、条件组合节点、条件引用项、条件类别登记项；外部事件输入：无。
读取：`CLS-CONDITION-001`、`CLS-CONDITION-002`、`CLS-CONDITION-003`、`CLS-CONDITION-004`。
输出：返回值：组合结构只读视图，含组合算子、子节点与引用项清单；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：配置服务已就绪；条件模块标识可解析；结构在启动校验中已通过。
后置条件：返回视图只读，不携带写入口。
副作用：无。
异常情况：标识不可解析时返回查询失败；结构成环、组合节点无子节点或引用项类别未登记时返回校验失败并写内容日志（该情形在启动校验阶段已中止启动，运行期不出现）。

### API-CONDITION-002 RequestConditionEvaluation 条件求值请求
职责：把条件模块、求值上下文与状态版本组织为一次判定请求，经条件求值服务取得判定结果并返回。
输入：参数输入：条件模块标识、求值上下文（判定对象标识、事件实例或效果实例标识、区域与点位标识、当前阶段）、状态版本标识；状态输入：当前已提交状态版本与当前局内阶段；数据输入：条件模块结构、条件类别登记项；外部事件输入：无。
读取：`CLS-CONDITION-001`、`CLS-CONDITION-003`、`CLS-CONDITION-004`、`CLS-CONDITION-006`、`CLS-CONDITION-007`；已提交状态由条件求值服务读取，本系统不读取数据域内容。
输出：返回值：判定结果（满足／不满足／无法判定）与该次判定所用的状态版本；状态输出：求值请求由已装配转已委托，再由已委托转已返回或由已装配转已拒绝；事件输出：无；外部系统调用：`API-M09-004` 条件判定（唯一判定路径）、`API-M01-010` 日志服务.Write（无法判定、版本过期与拒绝）。
产生的状态变化：无游戏状态变化，仅求值请求自身的状态迁移。
前置条件：条件模块标识可解析；引用项所需的上下文项齐备；请求携带的状态版本与当前已提交状态版本一致；当前阶段允许受理。
后置条件：判定结果标注其状态版本；同一状态版本与同一求值上下文标识的重复请求可按缓存命中返回结果。
副作用：按状态版本登记判定结果的键（缓存本体的持有、键控与重建归条件求值服务）；无法判定、版本过期与被拒绝的情形写内容日志。
异常情况：条件求值服务不可用时返回调用失败，由调用方按其规则处置（02-30 的口径为该事件保持未出现）；上下文缺项时返回无法判定，不得降级为满足；状态版本与当前已提交状态不一致时返回版本过期并拒绝；模块不可解析时返回失败；结算阶段允许只读求值，但不接受登记类请求。

### API-CONDITION-003 QueryConditionBinding 条件引用查询
职责：按内容标识返回该内容引用的条件模块清单与求值时机，作为入池判定、解锁检查与配置校验的取数入口。
输入：参数输入：内容标识（事件模板标识、效果定义标识等）、引用位置筛选（可空）；状态输入：条件引用声明的登记态；数据输入：条件引用声明与条件模块；外部事件输入：无。
读取：`CLS-CONDITION-005`、`CLS-CONDITION-001`。
输出：返回值：引用清单，逐条给出引用位置类别、条件模块标识、求值时机与结果用途；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：内容标识在该内容的引用位置类别中可解析。
后置条件：返回清单与该内容声明的引用一致。
副作用：无。
异常情况：内容标识不可解析时返回空清单并写内容日志；引用位置类别未登记时返回校验失败（启动校验阶段中止启动）；清单不返回判定阈值明细与引用目标的取值，避免条件信息经本接口外泄（设计稿 4.5）。

### API-CONDITION-004 QueryTriggerMethod 触发方式查询
职责：按事件模板标识返回该事件的触发方式声明与进入前的确认要求，供地图呈现与事件信息面板取数。
输入：参数输入：事件模板标识；状态输入：触发方式类型登记项的登记态；数据输入：触发方式声明、触发方式类型登记项；外部事件输入：无。
读取：`CLS-CONDITION-008`、`CLS-CONDITION-009`（触发方式声明的唯一来源；事件属性配置按标识引用本声明，见 2.1）。
输出：返回值：触发方式声明，含方式类型标识、进入受理侧标识、进入前确认要求与是否允许放弃；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：事件模板标识可解析；该模板的触发方式声明已登记（未声明时启动校验中止启动，运行期不出现该情形）；声明引用的方式类型已登记。
后置条件：返回视图只读，不携带写入口。
副作用：无。
异常情况：模板未声明触发方式时判定为配置校验失败（该情形在启动校验阶段已中止启动，运行期不出现），不按事件属性配置回退、不提供默认值；方式类型未登记时返回失败；本接口不返回事件点位数据。

### API-CONDITION-005 QueryConditionCategory 条件类别清单查询
职责：返回已登记的条件类别清单及每类别的引用目标类型与所需上下文项，供配置校验与求值服务装配判定输入使用。
输入：参数输入：类别标识（可空，为空时返回全部已登记类别）；状态输入：条件类别登记项的登记态；数据输入：条件类别登记项；外部事件输入：无。
读取：`CLS-CONDITION-004`。
输出：返回值：类别清单，逐条给出类别标识、引用目标类型与所需上下文项；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：配置服务已就绪。
后置条件：返回清单与启动校验结论一致。
副作用：无。
异常情况：类别标识未登记时返回失败并写内容日志；清单内容的完整字段契约待上游补充（缺口 REQ-CONDITION-01）。

### 5.2 功能之间的关系

`API-CONDITION-002` 依次触发求值上下文装配与齐备性判定、缓存命中与失效判定、求值委托与结果标注，被拒绝的路径只产生求值与拒绝记录；`API-CONDITION-001`、`API-CONDITION-003`、`API-CONDITION-005` 由条件结构装配与校验和引用关系登记与定位供数，都不改变状态；`API-CONDITION-004` 由触发方式解析与校验供数，其结论同时供启动阶段校验使用；条件结构装配与校验在启动阶段一次运行，运行期不改变结构。

### 6.4 使用方式

直接调用的依赖：`API-M01-003` 在启动阶段加载条件配置、运行期按标识补充取数；`API-M01-010` 在无法判定、版本过期、校验失败与拒绝时写入；已提交状态版本的读取在每次受理 `API-CONDITION-002` 前发生；`API-M09-004` 在每次受理后调用；`API-M10-001` 在受理前查询阶段；运行期配置与事件侧视图都只读、不携带写入口。经事件间接获得的依赖：存档恢复完成由 M01 发布，本系统在回调内清空按状态版本登记的键；判定源数据由条件求值服务在判定内读取，本系统不缓存其结果。

### 6.5 依赖方向限制

- 本单元属 L3 领域层、主模块 M02。真实依赖只有三类：向 M01 申请基础设施能力（架构案 3.3 第 9 项）、经 M01 事件分发器订阅已登记事件（第 10 项）、调用 M09 的条件求值服务（第 8 项），加查询 M10 的当前阶段（第 12 项）；同模块的 02-30 按模块内协作处理；对 M03、M04、M06、M07 与 02-10 只做引用目标登记，本系统不调用其接口、不读取其内容，读取由 M09 的条件求值服务执行，故不占用 3.3 第 5 项，也不产生「3.3 第 5 行未含 M06」的登记事项（该事项见 02-30 的 `REQ-EVENT-08`）。
- 本单元不得反向依赖 M08 的任何界面对象：事件信息面板与地图呈现由 M08 主动调用 `API-CONDITION-004` 取数（架构案 3.4 第 1、4 项）；不得被 M01 依赖（架构案 3.4 第 11 项）。
- 本单元不得自行实现条件判定、效果叠加、物品写入、随机源、时间推进与存档读写（架构案 3.4 第 6、7、8、9、10 项与第 10 章第 6 项）；条件判定一律经 `API-M09-004`。
- 本单元不持有任何跨域对象的可变引用，不缓存跨域取值作为数据来源（架构案 3.4 第 5 项、8.2 第 3 条）；本单元调用 M09 而 M09 不回调，与 02-30 之间是同模块内的调用方与取数关系，不构成架构案 3.4 第 12 项的循环依赖。

本系统调用：`API-M09-004`（每次求值请求受理后）、`API-M01-003`（启动加载与运行期取数）、`API-M01-010`（无法判定、版本过期、校验失败与拒绝时）、`API-M01-012`（启动阶段建立订阅）、已提交状态版本读取（每次受理求值请求前，ID 待补）、`API-M10-001`（每次受理求值请求前）。本系统不调用 M03、M04、M05、M06、M07、M08 的任何接口：这些单元的数据只作为引用目标登记，读取由条件求值服务在判定内完成。

### 7.2 事件关系

本系统不发布任何跨模块事件：条件判定与条件查询按架构案 4.5 判定为只读查询与直接调用，不产生事件；判定结果由调用方按其自身规则转化为状态迁移并发布其登记事件。

| 事件 | 发布方 | 响应职责 |
| --- | --- | --- |
| 存档恢复完成 | M01 存档服务 | 清空按状态版本登记的求值结果键与会话内记录，按恢复后的已提交状态版本重建键 |

失败语义：订阅方处理失败不得回滚发布方的状态提交（架构案 8.4 第 4 条）；本系统的回调只做只读处理与派生项重建。

```

        ▼
```

## 8. 核心流程

### 8.1 入池判定的条件求值请求

- 触发：02-30 的当前事件池刷新进入入池判定环节（`API-EVENT-003`）。
- 参与者：02-30 事件系统、本系统、M09 条件求值服务、M01（配置服务、日志服务、数据域侧）。
- 调用顺序：02-30 经 `API-CONDITION-003` 取该事件模板引用的条件模块与求值时机 → 经 `API-CONDITION-001` 取模块结构 → 组装求值上下文后经 `API-CONDITION-002` 发起请求 → 本系统读取已提交状态版本并比对 → 经 `API-M09-004` 委托判定 → 返回判定结果与所用状态版本 → 02-30 按结果执行入池与配额核算。
- 状态变化：求值请求由已装配转已委托再转已返回；不满足时事件保持未出现；本系统不改变任何游戏状态。
- 产生的事件：无（入池结果引起的事件由 02-30 发布）。
- 结束条件：判定结果返回并标注状态版本，请求方已按结果完成入池判定。
- 约束：线索解锁类别的求值点只在开新局的全局事件池内容集合计算与事件解锁检查两个位置；局内入池判定不得以线索解锁为过滤条件（该类别只作用于全局集合，架构案 5.2.5），本条在局内的求值时点申报为缺口 `REQ-CONDITION-05`。

### 8.2 条件引用登记与启动校验

- 触发：启动阶段的配置装载与校验（架构案 6.1 第 2 阶段）。
- 参与者：M01 配置服务、本系统、各引用方内容（事件属性配置、事件解锁门槛、效果定义）。
- 调用顺序：M01 经 `API-M01-003` 提供配置 → 本系统执行条件结构装配与校验 → 经 `API-CONDITION-005` 提供类别清单供表间引用校验 → 登记引用关系 → 校验触发方式声明的类型登记 → 校验结论回报 M01。
- 状态变化：条件类别登记项与触发方式类型登记项由未登记转已登记；触发方式声明由未声明转已声明。
- 产生的事件：无（配置加载完成由 M01 发布）。
- 结束条件：全部条件模块、引用声明与触发方式声明的引用可解析、结构不成环、类别与类型已登记；否则中止启动并报出具体项。

### 8.3 地图点选进入方式的声明与取数

- 触发：M08 展开事件信息面板或地图呈现需要该事件的进入方式；玩家在地图上点选事件点。
- 参与者：M08 界面与信息、M03 探索与推进、02-30 事件系统、本系统、M01 输入服务。
- 调用顺序：M03 提供事件点位与点选受理 → M08 经 `API-EVENT-002` 取事件实例视图 → M08 经 `API-CONDITION-004` 取触发方式声明与进入前确认要求 → 面板原地展开并呈现窗口期、参考持续时间与强制标记 → 玩家点击进入按钮 → 02-30 经 `API-EVENT-005` 确认进入。
- 状态变化：事件实例由可进入转进行中（由 02-30 提交）；本系统无状态变化。
- 产生的事件：事件进入进行中（02-30 发布）。
- 结束条件：进入结果返回，界面按事件类别切换；点位布局、点选受理与面板落点归 M03 与 M08，进入路径上不进行条件判定。

### 8.4 状态提交后的求值结果失效与重建

- 触发：状态提交被受理使状态版本变化（自动保存的两类节点）；或收到存档恢复完成。
- 参与者：M01（存档服务、数据域侧、事件分发器）、M09 条件求值服务、本系统。
- 调用顺序：状态提交受理 → 已提交状态版本变化 → 后续求值请求携带新版本，旧版本键失效 → 收到存档恢复完成 → 本系统清空按状态版本登记的键与会话内记录 → 后续请求按恢复后的状态求值。
- 状态变化：求值结果缓存由有效转已失效（外部持有）；本系统无游戏状态变化。
- 产生的事件：无（时间刻度变化、自动保存完成与存档恢复完成分别由 M01 发布）。
- 结束条件：后续求值请求返回与已提交状态一致的判定结果；状态版本不一致的判定结果不得被请求方采用。

## 9. 异常与边界情况

- 条件模块或引用项标识不可解析：`API-CONDITION-001`、`API-CONDITION-003` 返回失败或空清单并写内容日志，不改变任何状态。
- 组合结构成环、组合节点无子节点或引用项类别未登记：启动校验阶段判定为配置校验失败并中止启动，运行期不出现该结构。
- 求值上下文缺项：`API-CONDITION-002` 返回无法判定，不返回满足；由调用方按其规则处置，不得以默认值补足上下文。
- 状态版本过期：请求携带的版本与当前已提交状态版本不一致时拒绝并返回版本过期，调用方需以当前版本重新发起。
- 条件求值服务不可用：`API-CONDITION-002` 返回调用失败；02-30 的口径是该事件保持未出现并由流程编排决定是否再次调用刷新，本系统不代替其决定入池结果。
- 结算阶段收到请求：允许只读求值与查询；登记类请求与任何状态写入一律拒绝（架构案 6.6 结算阶段封闭）。
- 重复请求：同一状态版本与同一求值上下文标识的重复请求按缓存命中返回同一结果，不改变任何状态。
- 未登记的条件类别或触发方式类型：`API-CONDITION-005`、`API-CONDITION-004` 返回失败；新增类别或类型必须先登记再使用（架构案 5.1 与 8.5）。
- 触发方式声明缺失：判定为配置校验失败并在启动校验阶段中止启动，运行期不出现该情形；本系统不按事件属性配置回退、不提供默认值（唯一来源见 2.1 `CLS-CONDITION-008`）。
- 读档恢复过程中收到求值请求：按恢复未完成拒绝，恢复完成后再受理；恢复不重放条件判定，缓存键按恢复后的状态版本重建。
- 线索解锁条件与事件自身条件同时存在：两者分别判定，解锁未成立时即使事件自身条件满足也不得在局内出现（设计稿 4.4）；线索解锁类别的求值点只在开新局的全局事件池内容集合计算与事件解锁检查，局内入池判定以该类别的请求按不可求值拒绝（架构案 5.2.5，其局内求值时点见缺口 `REQ-CONDITION-05`）；窗口期已越过而尚未完成过期剔除的进入请求由 02-30 按其规则拒绝，本系统不参与该判定。

## 10. 实现约束

### 10.1 实现约束

- 条件模块、组合节点、引用项、类别登记项、引用声明与触发方式声明必须随配置版本标识加载并校验，运行期只读；配置问题在启动阶段中止启动，不得在运行期以默认值代替。
- 求值上下文与求值请求是临时运行对象，不得跨帧保留、不得入档；本系统不声明持久化切面，不写入任何数据域。
- 求值请求与判定结果必须携带状态版本，供调用方与缓存键控判定一致性。
- 条件引用查询不返回判定阈值明细与引用目标取值，条件的玩家可见性按设计稿 4.5 由线索树揭示与文案暗示承担。
- 启动阶段必须完成类别登记与触发方式类型登记；新增类别或类型按架构案 8.5 的接入步骤登记后再使用。

### 10.2 实现要求

- I-CONDITION-01 条件的组合结构只能由与、或、非三种组合节点与条件引用项构成；引用项只能引用已登记类别、按标识引用来源系统的数据，不得复制其内容或在结构内嵌判定实现。
- I-CONDITION-02 条件判定只能经 `API-M09-004` 执行；本系统不得实现任何比较、阈值计算或结果叠加（架构案 7.11、第 10 章第 6 项）。
- I-CONDITION-03 判定输入必须是已提交状态与当前上下文；不得读取未提交的编辑态、界面态或临时选择（`50_存档与持久化设计.md` 第 5 节）。
- I-CONDITION-04 每个求值请求必须携带状态版本，返回值必须标注所用状态版本；版本不一致的结果不得被调用方采用。
- I-CONDITION-05 求值结果以状态版本与求值上下文标识为键，状态提交与存档恢复完成为统一失效时点；缓存本体的持有与重建归条件求值服务，本系统不缓存跨域判定结果作为数据来源（架构案 7.11、8.2 第 3 条）。
- I-CONDITION-06 无法判定不得降级为满足：上下文或状态缺项时返回无法判定，由调用方按其规则处理。
- I-CONDITION-07 线索解锁条件与事件自身条件是两次独立判定；本系统不得折叠二者，也不得因解锁成立而跳过事件条件。
- I-CONDITION-08 条件判定只作用于事件生成；进入事件的路径上不得插入条件判定（设计稿 4.1）。
- I-CONDITION-09 地图点选的空间侧归 M03 与 M08；本系统只登记触发方式声明与类型登记，不持有点位数据、不实现点选受理。
- I-CONDITION-10 条件的引用关系可被查询，条件详情不得经本系统接口暴露给界面做直接提示（设计稿 4.5、F-CONDITION-07）。
- I-CONDITION-11 本系统不发布跨模块事件、不自建观察者、不自行读写存档、不推进世界时间（架构案 3.4 第 6、9、10 项与 8.4 第 1 条）。
