## 1. 系统定义

### 1.1 系统目的

信息传递系统是本作表现层中「话与提示怎么显示出来」的承接单元：把界面文案与提示按投放规则送到界面，并在界面内以对话框演绎角色台词。本单元的系统标识为 `SYS-INFO-001 信息传递系统`。

### 1.2 系统职责

- 持有台词分组索引、提示索引、结算说明索引与文案载体形态表，并维护触发场景登记；
- 受理对话投放请求：按触发场景与角色标识从候选台词中选取一条，装配可供界面直接呈现的首段内容；
- 受理界面副框区域的对话投放：以同一契约演绎事件内角色的对话，副框对话不阻塞主界面操作；
- 受理对话推进输入：按推进契约返回下一段、结束动画或会话结束结论；
- 受理三条提示通道中事件提示与引导提示的投放请求，并受理结算说明文案请求；
- 提供本局引导提示批次的有序清单查询，引导提示不受触发条件与线索树锁定门槛约束；
- 按载体标识给出文案载体的呈现规格声明，供界面以同一框架呈现对话与各文案载体；
- 经 M08 的文案取用通道按标识取用文本内容，经 M01 的随机服务按表现类序列选取候选台词；
- 不改变任何游戏数据、不推进世界时间、不产生分支选择，也不发布跨模块事件。

### 1.3 系统边界

本系统不负责：

- 界面栈、界面清单、界面的层级与返回关系、界面的打开与关闭，归 M08 的界面栈；本系统不为对话与提示创建、销毁或切换任何界面；
- 界面内部的布局、投放位置的具体排版、视觉样式与操作细节，归各系统设计文档与 M08；本系统只给出投放位置标识与呈现规格标识；
- 文案内容的生产、多语言文本与内容侧文案管线，归内容侧；本系统只按文案标识取用，不撰写、不改写文案；
- 文案与台词的按标识取用通道本体，归 M08 的 `API-M08-004 文案取用`（通道实现落 M01 的 7.8 表现通道）；
- 音频播放、音量分轨与特效触发，归 M01 的表现通道；文本呈现设置（字幕与语言）的清单与界面，归 01-60；
- 事件提示的触发时点与投放位置在事件侧的声明，归 02-30 的事件属性配置（`CLS-EVENT-003`）的呈现配置字段类；
- 引导提示与教学文案的编排内容，归关卡与内容策划；本系统只提供投放位置与触发时点；
- 结局判定、触发起因的写入、结算组件与跨局写入，归 07-40 与 M10；本系统只按传入的结局类型与成索取说明文案；
- 剧情演出、剧情回放与分支选择，归 07-10 的内容记录机制；
- 情报的记录、组织与呈现：情报回归为各系统文案对隐藏机制的提示，本系统不为其建立独立机制（交互逻辑 48）；
- 界面开放状态的声明与判定：一个事件一个开放状态，配置登记在事件属性配置中（交互逻辑 69、75），本系统不判定界面是否开放；
- 任何游戏状态的改变：界面上的状态变化（如交易确认、装备调整）由对应持有系统经意图与命令提交完成，本系统不提供任何写入游戏数据的入口。

### 1.5 功能要求

- F-INFO-01 玩家在界面上的操作必须能带出角色台词；台词按角色与触发场景分组配置，呈现时从候选台词中取一条。
- F-INFO-02 台词的呈现必须不阻塞玩家的界面操作，对话框出现期间玩家可以继续执行界面操作。
- F-INFO-03 对话必须不推进世界时间、不产生分支选择、不改变任何游戏状态。
- F-INFO-04 文本框必须支持单击播放下一段；富文本动画播放完毕之前再次单击必须立即结束动画并显示该段全部文本，不进入下一段。
- F-INFO-05 说话主体的称呼与头像必须与文本同框呈现；旁白内容必须预留头像位置留空，称呼栏显示空或统一文案。
- F-INFO-06 界面副框对话必须在副框区域内演绎事件内角色的对话，不影响主界面操作，也不改变任何游戏状态。
- F-INFO-07 事件提示、引导提示与结算说明文案必须统一由本系统的三条投放通道投放。
- F-INFO-08 引导提示必须不受触发条件与线索树锁定门槛的约束，在本局开始时按内容配置投放一组。
- F-INFO-09 结算说明文案必须按结局与未通关结局的触发起因取用，三种收尾情形分别可取。
- F-INFO-10 海报、短信、刊物、公告与书籍等文案载体必须与对话共用同一套呈现框架，并保留各自的包装规格登记位。

### 2.3 外部数据引用

本系统只引用下列数据的标识，不定义其结构与业务含义：

- 文案标识与文本内容：经 `API-M08-004 文案取用`（M08）按标识取得；
- 事件属性配置的呈现配置（02-30，`CLS-EVENT-003`）：事件提示的触发时点与投放位置声明；
- 事件状态与窗口期（02-30，`API-M02-001 事件状态查询`，系统侧落点为 `API-EVENT-001`）：由界面侧读取，用于判定事件提示的时点是否到达；
- 结局类型与未通关触发起因（07-40，`CLS-SETTLE-004 结局判定结果`，经 `API-SETTLE-004 结算窗口数据查询` 取得）：由结算窗口随请求传入；
- 角色标识：由请求方传入（其取值来源归 M07 与 M04）；说话主体标识由台词条目引用给出，本系统不解析角色身份；
- 文本呈现设置（01-60，`API-OPTION-001 设置项查询`）：字幕与语言的取值来源；
- 投放位置与承载界面：由登记方经本系统 `API-INFO-006` 声明，界面本体归 M08 的界面清单。

### 2.4 数据关系

- 包含：台词分组索引包含台词条目引用；引导提示批次由引导提示条目组成；呈现内容包由索引项与取用到的文本合成。
- 引用：触发场景登记项被台词分组索引与提示索引共同引用；台词条目引用、提示索引与结算说明索引分别引用文案标识；文案载体形态被呈现内容包引用。
- 派生：呈现内容包与投放请求记录由索引项与请求参数派生，随单次投放释放；对话推进快照由请求方持有，本系统不保存。
- 互斥：一次投放只作用于一个触发场景或一个提示标识；同一投放位置同时只允许一个在途对话会话。

### 2.6 持久化要求

- 本系统不持有需要入档的数据：全部索引与登记项属静态配置与启动期登记，随配置版本标识绑定（`CLS-M01-004`），不单独入档；
- 对话呈现进度、副框呈现与提示投放均为界面表现状态，不入档，读档后不恢复（恢复界面位置归 M08 的界面栈）；
- 候选台词的选取使用随机服务的表现类序列，不写入存档、不影响游戏状态（架构案 7.10、`CLS-M01-005`）；
- 派生项与临时运行对象按来源重建、不入档：呈现内容包按投放请求即时装配；对话推进快照由请求方按投放返回与推进输入维护；投放请求记录随投放结束释放。

## 3. 状态定义

### 3.1 状态

| 状态集 | 取值 | 说明 |
| --- | --- | --- |
| 触发场景登记状态 | 未登记／已登记／冲突 | 冲突表示同一标识以不一致的投放位置重复登记，该触发场景的投放被拒绝 |
| 索引完整性状态 | 完整／缺项 | 缺项按类别判定，只影响对应类别的投放 |
| 载体形态登记状态 | 已登记包装规格／取对话统一形态 | 未登记包装规格的载体按对话统一形态呈现 |
| 对话推进状态 | 未开始／动画播放中／等待推进／已结束 | 取值由请求方持有的对话推进快照承载 |
| 会话占用状态 | 空闲／占用 | 按投放位置分别维护，占用表示该位置存在在途对话会话 |

### 3.2 状态转换

```
未登记 → 已登记
未登记 → 冲突 → 已登记
完整 ↔ 缺项
取对话统一形态 → 已登记包装规格
空闲 → 占用（首次投放）
未开始 → 动画播放中
动画播放中 → 等待推进（动画播完，或单击立即结束动画并显示全文）
等待推进 → 动画播放中（单击进入下一段）
等待推进 → 已结束（末段之后单击）
占用 → 空闲（会话结束或承载界面关闭）
```

### 3.3 状态转换触发条件

| 转换 | 触发条件 |
| --- | --- |
| 未登记 → 已登记 | API-INFO-006 RegisterTriggerScene 受理并校验通过 |
| 未登记 → 冲突 | API-INFO-006 收到同一标识且投放位置不一致的登记 |
| 冲突 → 已登记 | 登记方以与既有登记一致的投放位置重新登记 |
| 完整 ↔ 缺项 | 配置加载与校验给出的索引完整性结论（API-M01-003、CLS-M01-003） |
| 取对话统一形态 → 已登记包装规格 | 文案载体形态表新增该载体的包装规格登记项 |
| 空闲 → 占用 | API-INFO-001 RequestDialogue 在某投放位置建立对话会话 |
| 未开始 → 动画播放中 | API-INFO-001 返回首段，界面按返回值更新对话推进快照 |
| 动画播放中 → 等待推进 | API-INFO-002 AdvanceDialogue 受理单击且动画已播完，或受理单击时立即结束动画并返回全文 |
| 等待推进 → 动画播放中 | API-INFO-002 受理单击且存在下一段 |
| 等待推进 → 已结束 | API-INFO-002 受理单击且当前段为末段 |
| 占用 → 空闲 | 会话结束，或承载界面关闭导致对话推进快照失效 |

### 4.2 接口详细定义

### API-INFO-001 RequestDialogue 对话投放请求

职责：受理一次对话投放请求，按触发场景与角色标识选取一条候选台词并装配首段呈现内容，或返回不可投放结论。
输入：参数输入：触发场景标识、角色标识、投放位置标识；状态输入：触发场景登记状态、会话占用状态、索引完整性状态；数据输入：台词分组索引、台词条目引用、文案载体形态；外部事件输入：无（由界面在登记的触发时点调用）。
读取：CLS-INFO-002 台词分组索引、CLS-INFO-003 台词条目引用、CLS-INFO-004 触发场景登记项、CLS-INFO-008 文案载体形态。
输出：返回值：对话推进快照与首段呈现内容包（CLS-INFO-011），或不可投放结论与原因；状态输出：该投放位置的会话占用由空闲转为占用，对话推进快照由未开始转为动画播放中；事件输出：无；外部系统调用：API-M08-004 文案取用（M08）、API-M01-004 随机服务.Next（M01，表现类序列）、API-M01-010 日志服务.Write（M01）。
产生的状态变化：该投放位置的会话占用置位；对话推进快照按返回值更新（快照由请求方持有，本系统不保存）。
前置条件：触发场景标识已登记且投放位置与登记项一致；触发分类为界面操作、界面事件或副框演绎；角色标识在关联分组范围内存在候选台词；该投放位置当前为空闲；所属界面处于可交互状态。
后置条件：返回值中的首段文本与文案标识一致；对话不阻塞界面操作、不改变任何游戏状态、不推进世界时间。
副作用：消耗随机服务的表现类序列位置（不入档、不影响游戏状态）；选取结果与投放位置经日志服务记录。
异常情况：触发场景未登记或投放位置与登记不一致；候选分组为空或候选参数缺项；所选文案标识在取用通道中缺项；该投放位置已有在途会话；承载界面不在可交互状态。
### API-INFO-002 AdvanceDialogue 对话推进

职责：受理一次对话推进输入，按推进契约返回下一段内容、结束动画结论或会话结束结论。
输入：参数输入：对话推进快照、推进输入（单击）；状态输入：快照中的对话推进状态与段位置；数据输入：台词条目引用（段序列与富文本规格标识）、文案载体形态；外部事件输入：无（单击由输入服务映射为意图后由界面转交）。
读取：CLS-INFO-010 对话推进快照、CLS-INFO-003 台词条目引用、CLS-INFO-008 文案载体形态。
输出：返回值：更新后的对话推进快照与当前段呈现内容，或会话结束结论；状态输出：对话推进状态按 3.2 转换，会话结束时会话占用由占用转为空闲；事件输出：无；外部系统调用：API-M08-004 文案取用（M08）。
产生的状态变化：段位置前进一段，或动画状态由播放中转为已完成，或会话结束标记置位。
前置条件：快照中的会话标识与本次投放一致；段位置在段序列范围内；该投放位置的会话占用为占用。
后置条件：动画播放中收到单击时，段位置不变并返回该段全文；动画已完成且存在下一段时，段位置加一；末段已完成时返回会话结束；推进不消耗表现类序列位置。
副作用：无。
异常情况：会话标识不匹配；段位置越界；会话已结束仍收到推进输入；承载界面已关闭导致的迟到输入。
### API-INFO-003 RequestPrompt 提示投放请求

职责：受理事件提示与引导提示的投放请求，按提示标识解析文案并装配呈现内容。
输入：参数输入：提示类别（事件提示／引导提示）、提示标识、投放位置标识；状态输入：索引完整性状态；数据输入：提示索引、引导提示条目、文案载体形态；外部事件输入：无（由界面在事件系统声明的提示时点调用）。
读取：CLS-INFO-005 提示索引、CLS-INFO-006 引导提示条目、CLS-INFO-008 文案载体形态。
输出：返回值：提示文案的呈现内容包（CLS-INFO-011），或不可投放结论与原因；状态输出：无；事件输出：无；外部系统调用：API-M08-004 文案取用（M08）、API-M01-010 日志服务.Write（M01）。
产生的状态变化：无（本系统不保存投放历史）。
前置条件：事件提示的提示标识取进入可进入、窗口期临近结束、已错过三者之一，其触发时点与投放位置由事件系统按事件属性配置的呈现配置声明；引导提示的提示标识取引导提示条目标识；提示标识在提示索引中登记。
后置条件：返回的文案内容与提示索引登记的文案标识一致；投放不改变任何游戏状态，且引导提示的解析不查询触发条件求值结果与线索树封锁状态。
副作用：投放记录经日志服务写入，用于问题定位。
异常情况：提示类别未登记；提示标识缺项（索引完整性为缺项）；文案标识在取用通道中缺项；事件提示的触发时点未被事件系统声明而调用方仍发起请求。
### API-INFO-004 QueryGuidePrompts 引导提示批次查询

职责：返回本局引导提示批次的有序条目清单，供界面在本局开始时按投放位置投放。
输入：参数输入：批次标识、投放位置标识；状态输入：索引完整性状态；数据输入：引导提示条目、文案载体形态；外部事件输入：无。
读取：CLS-INFO-006 引导提示条目、CLS-INFO-008 文案载体形态。
输出：返回值：引导提示条目清单（顺序号、文案标识、投放位置标识）与对应文案内容；状态输出：无；事件输出：无；外部系统调用：API-M08-004 文案取用（M08）。
产生的状态变化：无。
前置条件：引导提示批次已按内容配置登记；投放位置标识在批次条目内登记。
后置条件：清单顺序与内容配置一致；引导提示不受触发条件与线索树锁定的门槛约束，解析过程不查询条件求值服务与封锁状态。
副作用：无。
异常情况：批次未登记；批次为空（本局无引导提示）；投放位置标识不在批次条目内；索引完整性为缺项。
### API-INFO-005 RequestEndingNote 结算说明文案请求

职责：按结局类型与未通关结局的触发起因取用结算说明文案并装配呈现内容。
输入：参数输入：结局类型（真结局／隐藏关底事件／未通关结局）、未通关触发起因（未通关结局时必填）、投放位置标识；状态输入：索引完整性状态；数据输入：结算说明索引、文案载体形态；外部事件输入：无（由结算窗口在呈现结局提示时调用）。
读取：CLS-INFO-007 结算说明索引、CLS-INFO-008 文案载体形态。
输出：返回值：说明文案的呈现内容包（CLS-INFO-011），或不可投放结论与原因；状态输出：无；事件输出：无；外部系统调用：API-M08-004 文案取用（M08）、API-M01-010 日志服务.Write（M01）。
产生的状态变化：无。
前置条件：结局类型已由判定方写入并随结算数据传入；结局类型为未通关结局时，触发起因取关底未达标、主线中断、全队失去行动能力三者之一且只有一个取值。
后置条件：返回的说明文案与结算说明索引登记项一致；呈现位置与格式按本系统与 07-40 的联合约定（待上游补充，REQ-INFO-02）。
副作用：无。
异常情况：结局类型未登记；未通关结局未给出触发起因；成因取值不在登记范围；索引缺项；文案标识在取用通道中缺项。
### API-INFO-006 RegisterTriggerScene 触发场景登记

职责：受理一个触发场景的声明登记，登记触发分类、投放位置与关联分组范围，供台词与提示投放按标识解析。
输入：参数输入：触发场景标识、触发分类（界面操作／界面事件／副框演绎／提示时点）、投放位置标识、关联分组范围、登记方单元；状态输入：触发场景登记状态；数据输入：台词分组索引、提示索引；外部事件输入：无。
读取：CLS-INFO-004 触发场景登记项、CLS-INFO-002 台词分组索引、CLS-INFO-005 提示索引。
输出：返回值：登记结果与冲突项；状态输出：触发场景登记状态由未登记转为已登记，或由未登记转为冲突；事件输出：无；外部系统调用：API-M01-010 日志服务.Write（M01）。
产生的状态变化：登记项新增或更新一条；冲突时保留既有登记并回报冲突项。
前置条件：该触发场景标识尚无在途投放请求；同一标识未曾以不一致的投放位置登记；触发场景标识在台词分组索引或提示索引中有对应项。
后置条件：该触发场景可按登记的投放位置受理投放请求。
副作用：冲突与校验结论经日志服务记录。
异常情况：同一触发场景标识以不一致的投放位置重复登记；触发分类缺失；标识在两张索引中均无对应项；登记方单元不属于该投放位置的归属单元。
### API-INFO-007 QueryCarrierProfile 文案载体形态查询

职责：按载体标识返回呈现规格声明，供界面以同一框架呈现对话与各文案载体。
输入：参数输入：载体标识（对话／海报／短信／刊物／公告／书籍）；状态输入：载体形态登记状态；数据输入：文案载体形态表；外部事件输入：无。
读取：CLS-INFO-008 文案载体形态。
输出：返回值：呈现规格声明（承载文案类别、呈现规格标识、包装规格标识），或未登记结论；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：载体标识已登记。
后置条件：未登记包装规格的载体取对话统一形态的呈现规格；具体排版与尺寸取值归界面内部布局。
副作用：无。
异常情况：载体标识未登记；承载文案类别与请求投放的文案类别不匹配（如提示文案请求到仅承载台词的载体）。

| API-INFO-105 | ValidateTriggerScene 触发场景校验 | 校验标识、触发分类与投放位置的合法性并处置登记冲突 | 触发场景标识、触发分类、投放位置标识、登记方单元；CLS-INFO-002、CLS-INFO-004、CLS-INFO-005 | 校验结论与冲突项 | 否 |

### 5.2 内部功能契约

### API-INFO-101 ResolveAndSelectLine 候选解析与选取

职责：由触发场景与角色标识解析候选台词集合并经表现类序列选取一条候选台词。
输入：参数输入：触发场景标识、角色标识；状态输入：触发场景登记状态、索引完整性状态；数据输入：台词分组索引、台词条目引用；外部事件输入：无。
读取：`CLS-INFO-002` 台词分组索引、`CLS-INFO-003` 台词条目引用、`CLS-INFO-004` 触发场景登记项。
输出：返回值：台词标识，或不可用结论与原因；状态输出：无；事件输出：无；外部系统调用：`API-M01-004` 随机服务.Next（表现类序列）、`API-M01-010` 日志服务.Write。
产生的状态变化：无。
前置条件：触发场景标识已登记且投放位置与登记项一致；角色标识在关联分组范围内存在候选台词。
后置条件：返回的台词标识取自该分组的候选集合，不回落其他触发场景的台词。
副作用：经 `API-M01-004` 消耗表现类序列位置（不入档、不影响游戏状态）。
异常情况：候选分组为空或候选参数缺项；触发场景未登记；索引完整性为缺项。

### API-INFO-102 ResolveContentIndex 文案索引项解析

职责：由提示类别与提示标识、或结局类型与未通关触发起因解析文案标识与投放位置标识。
输入：参数输入：提示类别、提示标识、结局类型、未通关触发起因；状态输入：索引完整性状态；数据输入：提示索引、引导提示条目、结算说明索引；外部事件输入：无。
读取：`CLS-INFO-005` 提示索引、`CLS-INFO-006` 引导提示条目、`CLS-INFO-007` 结算说明索引。
输出：返回值：文案标识与投放位置标识，或缺项结论；状态输出：无；事件输出：无；外部系统调用：`API-M01-010` 日志服务.Write。
产生的状态变化：无。
前置条件：提示标识或结局类型在对应索引中登记；结局类型为未通关结局时触发起因只有一个取值。
后置条件：解析结果只使用登记的索引项，三种收尾情形不共用同一条索引项。
副作用：缺项经日志服务记录。
异常情况：提示类别未登记；成因取值不在登记范围；索引完整性为缺项。

### API-INFO-103 AdvanceCursor 段推进判定

职责：按推进契约读入对话推进快照并给出下一段、结束动画或会话结束结论。
输入：参数输入：对话推进快照、推进输入（单击）；状态输入：快照中的对话推进状态与段位置；数据输入：台词条目引用的段序列与富文本规格标识；外部事件输入：无（单击由输入服务映射为意图后由界面转交）。
读取：`CLS-INFO-003` 台词条目引用、`CLS-INFO-010` 对话推进快照。
输出：返回值：更新后的快照与推进结论；状态输出：对话推进状态按 3.2 转换；事件输出：无；外部系统调用：无。
产生的状态变化：段位置前进一段，或动画状态转为已完成，或会话结束标记置位。
前置条件：快照中的会话标识与本次投放一致；段位置在段序列范围内。
后置条件：动画播放中收到单击时段位置不变并返回该段全文；末段已完成时返回会话结束；判定不消耗表现类序列位置。
副作用：无。
异常情况：会话标识不匹配；段位置越界；会话已结束仍收到推进输入；承载界面已关闭导致的迟到输入。

### API-INFO-104 AssemblePayload 呈现内容装配

职责：按文案标识经文案取用通道取用文本并装配为可直接呈现的内容包。
输入：参数输入：文案标识、载体标识、投放位置标识、说话主体标识与旁白标记；状态输入：载体形态登记状态；数据输入：文案载体形态表；外部事件输入：无。
读取：`CLS-INFO-008` 文案载体形态、文案内容与文本（经 `API-M08-004` 取用）。
输出：返回值：呈现内容包（`CLS-INFO-011`），或取用失败结论；状态输出：无；事件输出：无；外部系统调用：`API-M08-004` 文案取用（M08）。
产生的状态变化：无（装配结果单次投放内有效）。
前置条件：文案标识已在取用通道中登记；载体标识已登记。
后置条件：内容包中的文本与取用通道按标识返回的文本一致；本系统不缓存文本内容。
副作用：无。
异常情况：文案标识在取用通道中缺项；承载文案类别与请求投放的文案类别不匹配；取用通道不可用。

### API-INFO-105 ValidateTriggerScene 触发场景校验

职责：校验触发场景标识、触发分类与投放位置的合法性并处置登记冲突。
输入：参数输入：触发场景标识、触发分类、投放位置标识、登记方单元；状态输入：触发场景登记状态；数据输入：台词分组索引、提示索引；外部事件输入：无。
读取：`CLS-INFO-002` 台词分组索引、`CLS-INFO-004` 触发场景登记项、`CLS-INFO-005` 提示索引。
输出：返回值：校验结论与冲突项；状态输出：触发场景登记状态由未登记转为已登记或冲突；事件输出：无；外部系统调用：`API-M01-010` 日志服务.Write。
产生的状态变化：登记项新增或更新一条；冲突时保留既有登记并回报冲突项。
前置条件：该触发场景标识尚无在途投放请求；触发场景标识在台词分组索引或提示索引中有对应项。
后置条件：校验通过时该触发场景可按登记的投放位置受理投放请求。
副作用：冲突与校验结论经日志服务记录。
异常情况：同一标识以不一致的投放位置重复登记；触发分类缺失；标识在两张索引中均无对应项；登记方单元不属于该投放位置的归属单元。

### 5.3 功能之间的关系

- 四个投放接口（API-INFO-001、API-INFO-003、API-INFO-004、API-INFO-005）共用 API-INFO-104 完成文本取用与装配，区别只在文案标识的解析来源（分别经 API-INFO-101 与 API-INFO-102）；
- API-INFO-001 依次调用 API-INFO-105 校验登记、API-INFO-101 解析并选取候选、API-INFO-104 装配首段，并置会话占用；
- API-INFO-002 调用 API-INFO-103 给出推进结论，需要新文本时再调用 API-INFO-104；API-INFO-006 调用 API-INFO-105 完成校验与冲突处置；
- 任一环节返回缺项或不可投放结论时，由对应接口原样返回结论并经日志服务记录，不回落其他文案与其他触发场景。

### 6.4 使用方式

- 启动阶段：经 `API-M01-001` 登记本服务能力与依赖声明，经 `API-M01-002` 取得配置、随机与日志能力；各登记方调用 `API-INFO-006` 完成触发场景登记；
- 运行期：本系统不被领域模块直接调用，全部投放请求来自 M08 的界面实例（界面栈打开并承载），本系统只做只读解析与内容装配；
- 事件提示的时点不由本系统判定：触发时点与投放位置由 02-30 按事件属性配置的呈现配置声明，界面在对应时点调用 `API-INFO-003`；
- 文案取用与随机选取：全部文本经 `API-M08-004` 按标识取得（架构案 7.8），候选台词经表现类序列选取（架构案 7.10），两者都不写入存档、不影响游戏状态；
- 设置读取与结果告知：文本呈现设置经 `API-OPTION-001` 读取，标识缺项时按默认呈现；登记冲突、投放缺项与投放记录经 `API-M01-010` 记录日志；本系统不发布跨模块事件。

### 6.5 依赖方向限制

- 本系统位于 L5 表现层，只使用 M01 的基础设施与 M08 模块内的呈现能力，不引用任何 L4／L3 模块的业务对象，只读取其状态或接收其随请求传入的数据（架构案 2.1、3.3 第 1、9 项）；
- 与 M08 的界面栈、编辑态与文案取用通道为同一模块内的依赖，不新增架构案 3.3 的允许清单条目；本系统不定义界面栈、不创建或销毁界面实例（架构案 8.3 第 2 项）；
- 本系统不持有世界状态域、单局状态域与玩家状态域的任何权威副本，也不持有跨局数据；全部接口均不产生游戏状态变化（架构案 3.4 第 3、14 项、8.4 第 5 条）；
- 反向依赖禁止：任何模块不得绕过本系统另行实现台词投放、提示索引与文案载体形态，也不得要求本系统反向调用其业务入口（架构案 3.4 第 12 项）；
- 本系统不发布跨模块事件，也不订阅跨模块事件：投放不构成跨模块状态广播（架构案 8.4 第 1 条只强制跨模块状态广播走事件分发器）；
- 本系统不自行实现文案取用、随机源、日志与配置读取，也不自行实现条件判定与效果叠加，全部经 M01、M08 与 M09 的既有入口（架构案 3.4 第 6 至 9 项、第 7 章）。

## 8. 核心流程

### 8.1 对话的投放与单击推进

| 项 | 内容 |
| --- | --- |
| 触发 | 玩家在界面上执行一次登记过的操作或界面事件（点击角色立绘、执行一次交易、资源不足的提示出现、副框演绎的时点到达），随后在文本框区域内单击推进 |
| 参与者 | 界面实例（M08）、本系统、输入服务与随机服务（M01）、文案取用通道（M08） |
| 调用顺序 | 1 界面调用 API-INFO-001，传入触发场景标识、角色标识与投放位置标识；2 本系统内部调用 API-INFO-105 校验登记、API-INFO-101 解析候选并经 API-M01-004 取表现类序列选取一条、API-INFO-104 经 API-M08-004 取文本并装配首段呈现内容包；3 界面按返回值建立对话框或副框对话框并持有对话推进快照；4 玩家单击后由输入服务映射为意图，界面调用 API-INFO-002，本系统内部调用 API-INFO-103 判定推进结论，需要新文本时再调用 API-INFO-104 取文本；5 界面按返回的快照更新呈现 |
| 状态变化 | 会话占用 空闲→占用；对话推进状态 未开始→动画播放中→等待推进（或直接结束动画）→动画播放中或已结束；会话结束或界面关闭时会话占用 占用→空闲；无游戏状态变化 |
| 产生的事件 | 无 |
| 结束条件 | 界面呈现首段内容并回到可交互状态且玩家的界面操作不被阻塞；末段之后返回会话结束，对话框由界面按自身规则关闭 |

### 8.2 提示与结算说明文案的投放

| 项 | 内容 |
| --- | --- |
| 触发 | 事件提示的时点到达（事件进入可进入、窗口期临近结束、事件错过），本局开始时的引导呈现，或结算窗口呈现结局提示 |

| 结束条件 | 提示与说明文案呈现完成；引导提示批次按顺序投放完毕；缺项时返回不可投放结论并由调用方按缺项提示 |

## 9. 异常与边界情况

| # | 情形 | 判定条件 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 触发场景未登记 | API-INFO-001 的触发场景标识无登记项，或投放位置与登记不一致 | 返回不可投放结论，不消耗表现类序列、不建立会话，经日志服务记录 |
| 2 | 候选缺项 | 候选分组为空或候选参数缺项 | 按缺项返回不可投放结论，界面不呈现对话框；不回落其他触发场景的台词 |
| 3 | 文案标识缺项 | 索引项指向的文案标识在 API-M08-004 中不存在 | 返回不可投放结论并记录缺项；不回落其他文案、不自行读取文本资源 |
| 4 | 登记冲突 | 同一触发场景标识以不一致的投放位置重复登记 | 保留既有登记，返回冲突项，登记状态置冲突，冲突项经日志服务记录 |
| 5 | 重复投放 | 同一投放位置已有在途会话时再次收到投放请求 | 返回既有会话的对话推进快照，不建立第二个会话，会话占用不重复置位 |
| 6 | 越界推进 | 对话推进快照的会话标识不匹配或段位置越界 | 拒绝推进，返回快照不变，经日志服务记录 |
| 7 | 会话已结束后的推进 | 快照已置已结束仍收到单击 | 拒绝推进，不产生状态变化 |
| 8 | 界面关闭后的迟到输入 | 承载界面已关闭后到达的推进输入 | 拒绝处理；会话随界面销毁，本系统不保存该快照 |
| 9 | 事件提示时点未声明 | 事件系统未在呈现配置中声明该提示的触发时点与投放位置 | 该提示不发生投放；本系统不自行判定时点，也不按窗口期推算 |
| 10 | 引导提示批次为空 | 本局引导提示条目为空 | 返回空清单，界面不呈现引导区，不计为异常 |
| 11 | 未通关结局缺成因 | 结局类型为未通关结局但未给出触发起因，或成因不在三种收尾情形内 | 拒绝取用，返回缺参结论，由结算窗口按缺项提示；三种成因不得共用同一条索引项 |
| 12 | 文本呈现设置缺项 | 字幕与语言相关设置项未登记或取值缺失 | 按默认呈现，不阻断投放，经日志服务记录一次缺项 |
| 13 | 载体未登记包装规格 | 载体标识在文案载体形态表中无包装规格登记项 | 取对话统一形态的呈现规格，投放照常完成 |
| 14 | 结算阶段的投放请求 | 结算窗口在结算阶段请求结算说明文案 | 属只读取用，受理；本系统不因阶段拒绝（结算阶段禁止的是改变局内状态的输入） |
| 15 | 并发投放 | 同一投放位置在同一帧内收到两个投放请求 | 按到达顺序只受理一个，后到请求按第 5 行处理 |

## 10. 实现约束

### 10.1 实现约束条目

- 本系统不得改变任何游戏数据、不得推进世界时间、不得产生分支选择；全部接口只做只读解析与内容装配（架构案 3.4 第 3 项、8.4 第 5 条）；
- 界面上的状态变化由对应持有系统经意图与命令提交完成，本系统不提供任何写入游戏数据的入口，也不代界面提交任何数据；
- 全部文本内容必须经 `API-M08-004` 按标识取用，本系统不得自行读取文本资源，也不得缓存文案内容作为数据来源（架构案 7.8、8.2 第 3 条）；
- 候选台词的选取必须经 `API-M01-004` 的表现类序列，不得自行创建随机源（架构案 3.4 第 9 项）；
- 本系统不持有跨帧的界面呈现状态：对话推进快照由请求方（界面实例）持有，本系统只按契约读入并返回；
- 本系统不持有世界状态域、单局状态域、玩家状态域与跨局数据的任何权威副本（架构案 3.4 第 14 项）；
- 索引与登记项只保存标识与投放参数，不保存显示字符串与文案正文，文本一律按标识取用；
- 触发场景标识、提示类别与提示标识、结局类型与成因、载体标识必须先登记后使用（架构案 5.1 约束 2）；
- 引导提示与教学文案的解析不得查询触发条件求值结果与线索树封锁状态（交互逻辑 64）；
- 全部投放、登记冲突与缺项必须经 `API-M01-010` 记录日志，不得自行写日志文件（架构案 7.7）；
- 对话与提示的投放不产生跨模块事件；确需广播时先按约定 §五.3 登记事件名；
- 投放位置的具体排版、尺寸与视觉样式不在本系统内定义，本系统只给出投放位置标识与呈现规格标识（架构案 1.2、2.4）。

### 10.2 实现要求

- I-INFO-01 本系统不得持有任何游戏数据的权威副本，且不得提供任何写入游戏数据的接口。
- I-INFO-02 台词索引、提示索引、结算说明索引与文案载体形态必须按标识检索，文本内容必须经 `API-M08-004` 取用。
- I-INFO-03 候选台词的选取必须经随机服务的表现类序列，且不写入存档、不影响游戏状态。
- I-INFO-04 对话推进快照必须由请求方持有；本系统不得跨帧保存界面呈现状态。
- I-INFO-05 触发场景标识、提示标识、结局类型与成因、载体标识必须先登记后使用，未登记的标识不得参与投放。
- I-INFO-06 引导提示的解析不得读取条件求值结果与线索树封锁状态，也不得按解锁门槛过滤批次。
- I-INFO-07 同一投放位置同时只允许一个在途对话会话。
- I-INFO-08 未通关结局的说明文案必须按触发起因分别取用，三种收尾情形不得共用同一条索引项。
- I-INFO-09 未登记包装规格的文案载体必须取对话统一形态的呈现规格。
- I-INFO-10 本系统不得发布或订阅未登记的跨模块事件，也不得自行实现界面栈、条件判定与效果叠加。
