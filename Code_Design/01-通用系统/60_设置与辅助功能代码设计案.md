## 1. 系统定义

### 1.1 系统目的

设置与辅助功能系统承载玩家对本游戏运行方式的全部可配置项，并把这些配置项转换为程序可读的设置数据，供输入服务、表现通道与各界面在运行时读取。

本系统的对象标识：`SYS-OPTION-001 设置与辅助功能`。

### 1.2 系统职责

* 登记设置项的清单、取值类型、默认值与取值范围；
* 持有运行期的设置数据，并向读取方提供查询能力；
* 受理设置变更，校验后提交给存档侧落盘；
* 维护键位映射，并在改键后使输入服务即时生效；
* 声明暂停行为，并维护暂停状态供表现与输入两侧读取；
* 为辅助功能提供取值落点。

### 1.3 系统边界

本系统不负责：

* 设置界面的布局、字段呈现与操作流程（归 M08 界面与信息）；
* 设置数据的持久化结构与读写实现（归 01-50 存档与持久化）；
* 物理输入的采集与意图映射（归 M01 的输入服务）；
* 音频播放、文案取用与特效触发的实现（归 M01 的表现通道与 M08 的文案组织）；
* 界面文案的多语言内容生产（内容侧文案管线承担）。

### 1.5 功能要求

- F-OPTION-01 玩家必须能对四类设置项取值：键位、音量分轨、字幕与语言、暂停相关设置；设置项的完整清单、取值类型与默认值待上游补充（REQ-OPTION-01；设计稿 §3.1 第 1 至 4 条）。
- F-OPTION-02 键位映射必须可由玩家调整；改键后映射即时生效，不要求重启（架构案 7.4）。
- F-OPTION-03 音量必须按表现通道声明的轨道分别设置（架构案 7.8）。
- F-OPTION-04 字幕与语言必须作为设置项登记并可读取；多语言在长期范围内暂不考虑，只预留接口（架构案 7.8）。
- F-OPTION-05 暂停只冻结表现与输入，不改变任何数据；暂停在各阶段的适用范围待上游补充（REQ-OPTION-02；架构案 7.4）。
- F-OPTION-06 设置数据必须独立于游戏进度持久化，提交时机为设置变更时（架构案 5.3）。
- F-OPTION-07 无障碍功能（字体缩放、输入辅助等）的范围界定待上游补充；在范围界定前，无障碍类设置项并入本系统的设置项定义与设置数据登记范围（REQ-OPTION-01；设计稿 §3.1 第 5 条）。

设置项定义由本系统持有；设置项完整清单待上游补充（REQ-OPTION-01）。已确定需要落点的设置项类别为四类：键位、音量分轨、字幕与语言、暂停相关设置（`60_设置与辅助功能设计.md` §3.1 第 1 至 4 条）。无障碍功能（字体缩放、输入辅助等）的范围界定同样待上游补充（设计稿 §3.1 第 5 条）：在其范围界定前，无障碍类设置项并入 `CLS-OPTION-001` 与 `CLS-OPTION-002` 的登记范围，本系统按同一套登记、校验与提交路径承载。

设置数据这一个对象在三份文档之间的分工按内容权威与载体分层：本文件定义设置项定义与设置数据的**内容**（`CLS-OPTION-001`、`CLS-OPTION-002`）；01-50 的 `CLS-SAVE-006` 是设置数据的**持久化结构**，按 `CLS-OPTION-002` 的内容提交与读取；M01 的 `CLS-M01-019` 是设置数据的**运行期内存形态**，按 `CLS-OPTION-002` 的取值更新。后两处的引用关系由各自文档写明（01-50 侧见 `50_存档与持久化代码设计案.md` 2.1；M01 侧的引用说明待其同步，见 REQ-OPTION-03）。

### 2.2 外部数据引用

| 数据 | 所有者 | 本系统访问级别 | 用途 |
| --- | --- | --- | --- |
| 单局存档结构与提交入口 | 01-50 存档与持久化（API-SAVE 系列） | 经接口修改 | 提交设置数据 |
| 音频轨道划分声明 | M01 表现通道 | 只读 | 生成音量分轨设置项的取值域 |

### 2.3 数据关系

设置数据按设置项标识引用设置项定义；键位映射是设置数据的子集，意图标识由输入服务定义、本系统只保存对应关系，不定义意图清单。暂停状态是独立于设置数据的一次性运行期状态，不持久化。

### 2.4 数据生命周期

设置项定义在启动阶段随静态配置加载并常驻；设置数据在启动阶段读取持久化结果，缺失或损坏时回落默认值，随后随进程常驻；键位映射在设置数据变更后即时更新；暂停状态由暂停相关设置与玩家操作产生，进程退出后失效。

### 2.5 持久化要求

设置数据整体作为一个持久化结构提交，与游戏进度相互独立，切面归属设置数据（架构案 5.3）。提交时机为设置变更时；未发生变更时不提交。存档结构的读写实现归 01-50，本系统只声明切面内容与提交请求。

## 3. 状态定义

### 3.1 状态

本系统自身只有一项运行期状态：

| 状态 | 取值 |
| --- | --- |
| 暂停状态 | 暂停中、未暂停 |

设置项的取值域属于取值定义，不属于状态。设置项定义与设置数据均无自身状态机。

### 3.2 状态转换

```
未暂停 → 暂停中 → 未暂停
```

### 3.3 状态转换触发条件

| 转换 | 触发条件 |
| --- | --- |
| 未暂停 → 暂停中 | 玩家触发暂停操作，且暂停相关设置声明该操作生效 |
| 暂停中 → 未暂停 | 玩家解除暂停 |

暂停行为的适用范围（半回合制战斗中的暂停规则、事件中的暂停规则）待上游补充（REQ-OPTION-02）。暂停只冻结表现与输入，不改变任何数据（架构案 7.4）。

### 4.2 接口详细定义

### API-OPTION-001 设置项查询

职责：
按设置项标识返回当前取值与取值范围，供界面呈现与各系统读取。

输入：
- 参数输入：设置项标识
- 状态输入：设置数据
- 数据输入：设置项定义
- 外部事件输入：无

读取：
- CLS-OPTION-001 设置项定义
- CLS-OPTION-002 设置数据

输出：
- 返回值：设置项取值与取值范围
- 状态输出：无
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 无

前置条件：
- 设置项标识已在设置项定义中登记

后置条件：
- 返回的取值与设置数据的当前内容一致

副作用：
- 无

异常情况：
- 设置项标识未登记时判定为非法输入，返回失败结果，调用方不得按下发取值使用。

### API-OPTION-002 设置变更提交

职责：
受理一项或一组设置变更，校验后写入设置数据并请求落盘。

输入：
- 参数输入：设置项标识与目标取值
- 状态输入：设置数据
- 数据输入：设置项定义
- 外部事件输入：无

读取：
- CLS-OPTION-001 设置项定义
- CLS-OPTION-002 设置数据

输出：
- 返回值：提交结果
- 状态输出：设置数据变更；键位映射随键位类设置项变更而更新
- 事件输出：无（设置变更不是跨系统状态广播；架构案 3.1 的 M01 事件表未登记设置变更事件）
- 外部系统调用：请求 01-50 提交设置数据切面

产生的状态变化：
- 设置数据中对应设置项的取值改变
- 键位映射在键位类设置项变更后改变

前置条件：
- 提交内容全部通过设置项定义声明的取值校验
- 当前不处于暂停状态，或该项设置在暂停中允许修改

后置条件：
- 设置数据与落盘结果一致；键位变更已对输入服务生效

副作用：
- 触发一次设置数据提交

异常情况：
- 取值越界或类型不符时判定为校验失败，整笔提交不产生状态变化。
- 落盘失败时判定为提交失败，设置数据回退到提交前内容。

### API-OPTION-003 键位映射查询

职责：

输入：

- 数据输入：设置项定义中的默认键位
- 外部事件输入：无

读取：

输出：
- 返回值：意图与物理输入的对应关系
- 状态输出：无
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 无

前置条件：
- 无

后置条件：
- 返回内容与键位映射当前内容一致

副作用：
- 无

异常情况：
- 键位映射存在冲突或缺失时判定为数据异常，输入服务对缺失项使用默认值。

### API-OPTION-005 暂停状态切换

职责：
按玩家操作切换暂停状态。

输入：
- 参数输入：目标暂停状态
- 状态输入：暂停状态
- 数据输入：暂停相关设置
- 外部事件输入：无

读取：
- CLS-OPTION-004 暂停状态

输出：
- 返回值：切换结果
- 状态输出：暂停状态变更
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 暂停状态在暂停中与未暂停之间切换

前置条件：
- 目标状态与当前状态不同
- 当前阶段允许暂停（各阶段的暂停适用规则待上游补充，见 REQ-OPTION-02）

后置条件：
- 表现与输入按新状态冻结或恢复；任何游戏数据不因暂停改变

副作用：
- 无

异常情况：
- 当前阶段不允许暂停时判定为状态不允许，返回失败结果且状态不变。

## 5. 内部功能

### 5.1 功能列表

| 功能 ID | 功能 | 职责 | 是否对外暴露 |
| --- | --- | --- | --- |
| API-OPTION-101 | 设置项登记与校验 | 加载设置项定义并校验标识唯一性与取值域合法 | 否 |
| API-OPTION-102 | 默认值回落 | 设置数据缺失或损坏时生成默认设置数据 | 否 |
| API-OPTION-103 | 键位冲突检测 | 检查键位映射中同一物理输入是否被多个意图占用 | 否，结果供 API-OPTION-002 使用 |

### 5.2 功能之间的关系

`API-OPTION-101` 设置项登记与校验在启动阶段先于 `API-OPTION-102` 默认值回落执行；`API-OPTION-102` 为 `API-OPTION-001` 与 `API-OPTION-003` 提供可用数据；`API-OPTION-103` 键位冲突检测由 `API-OPTION-002` 在键位类变更时触发。三个内部功能只在本系统内被调用，不经服务容器对外暴露。

### 6.4 使用方式

设置数据提交在设置变更时直接调用；输入映射更新在键位类设置项变更后调用；配置查询在启动阶段与设置项校验时调用；日志写入只在设置数据损坏的异常路径调用。

### 6.5 依赖方向限制

本系统属 M01 模块，层级 L1、L5。允许依赖：M01 的基础设施能力、同模块的存档能力（架构案 3.3 第 9 条）。不得被玩法模块反向依赖其内部状态；界面侧对设置的呈现一律经 M08 的界面栈与 `API-OPTION-001` 查询，不得直接读写设置数据（架构案 3.4 第 3 项）。

## 7. 系统交互

### 7.1 调用关系

| 调用方 | 被调用方 | 接口 | 时机 |
| --- | --- | --- | --- |
| M08 设置界面 | 本系统 | API-OPTION-001、API-OPTION-002、API-OPTION-005 | 界面打开呈现、编辑态提交 |
| M01 输入服务 | 本系统 | API-OPTION-003 | 启动阶段与键位变更后 |
| M01 表现通道 | 本系统 | API-OPTION-004 | 播放与输入分发前 |
| 各系统的界面侧 | 本系统 | API-OPTION-001 | 呈现需要读取设置时 |

### 7.2 事件关系

本系统不发布跨系统事件，也不订阅跨系统事件。设置变更与暂停状态切换都不是架构案 3.1 已登记的跨模块事件；需要广播时按约定 §五.3 标注【待架构登记】并走需求申报，不在本文档自行发布。

### 7.3 数据流

设置项定义由静态配置流向本系统；玩家的设置操作形成设置数据，经存档侧写入设置数据结构；键位映射由本系统流向输入服务；暂停状态由本系统流向表现通道与输入服务。

## 8. 核心流程

### 8.1 启动阶段读取设置

| 项 | 内容 |
| --- | --- |
| 触发 | 启动阶段的设置与存档索引读取 |
| 参与者 | 本系统、配置服务、存档服务 |
| 调用顺序 | 调用 API-M01-003 读取设置项定义 → `API-OPTION-101` 校验设置项定义 → 读取设置数据 → 设置数据缺失或损坏时执行 `API-OPTION-102` 默认值回落 → 调用 API-OPTION-003 向输入服务提供键位映射 |
| 状态变化 | 暂停状态置为未暂停；设置数据就绪 |
| 产生的事件 | 无 |
| 结束条件 | 主界面可呈现，键位映射可供输入服务使用 |

### 8.2 设置变更提交

| 项 | 内容 |
| --- | --- |
| 触发 | 玩家在设置界面确认一次设置变更（编辑态提交） |
| 参与者 | M08 设置界面、本系统、存档服务、输入服务 |
| 调用顺序 | 界面把编辑态经 `API-M08-003` 提交 → 调用 API-OPTION-002 → 校验取值（键位类变更时经 `API-OPTION-103` 检测冲突）→ 写入设置数据 → 键位类变更时更新键位映射并通知输入服务 → 经 `API-SAVE-006` 请求存档侧提交设置数据切面 |
| 状态变化 | 设置数据变更；键位映射可能变更 |
| 产生的事件 | 无 |
| 结束条件 | 提示提交成功，界面按新取值刷新 |

### 8.3 暂停与恢复

| 项 | 内容 |
| --- | --- |
| 触发 | 玩家触发暂停操作，或解除暂停 |
| 参与者 | M08 界面、本系统、M01 表现通道与输入服务 |
| 调用顺序 | 界面把操作经编辑态提交 → 调用 API-OPTION-005 → 校验当前阶段允许暂停 → 切换暂停状态 → 表现通道与输入服务按 API-OPTION-004 的结果冻结或恢复 |
| 状态变化 | 暂停状态变更 |
| 产生的事件 | 无 |
| 结束条件 | 界面反馈暂停或恢复完成 |

## 9. 异常与边界情况

| 情形 | 判定条件 | 期望结果 |
| --- | --- | --- |
| 设置数据损坏 | 设置数据结构无法解析或校验不通过 | 回落默认值，记录内容日志，不阻断启动 |
| 设置项标识未登记 | 查询或提交使用了设置项定义中没有的标识 | 判定为非法输入，返回失败结果，设置数据不变 |
| 取值越界 | 提交取值超出设置项定义声明的取值范围或类型不符 | 判定为校验失败，整笔提交不产生状态变化 |
| 键位冲突 | 同一物理输入被两个意图占用 | 判定为校验失败并返回冲突项；冲突的解除方式待上游补充（REQ-OPTION-03） |
| 落盘失败 | 设置数据提交返回失败 | 设置数据回退到提交前内容并提示玩家 |
| 阶段不允许暂停 | 当前阶段按上游规则不允许暂停 | 判定为状态不允许，暂停状态不变 |
| 暂停期间发起变更 | 暂停中提交游戏数据类变更 | 暂停只冻结表现与输入，界面不得发起改变游戏数据的提交（架构案 7.4） |

## 10. 实现约束

### 10.1 实现约束条目

- 设置数据与游戏进度相互独立持久化，不得写入单局存档或跨局存档（架构案 5.3）。
- 任何模块不得自行读写设置数据；读取经 `API-OPTION-001`，写入经 `API-OPTION-002`（架构案 3.4 第 6 项与 7.1）。
- 设置项定义在运行期只读，任何模块不得在运行期修改定义（架构案 7.9）。
- 键位映射的默认值由设置侧维护，改键后即时生效，不得要求重启（架构案 7.4）。
- 暂停只冻结表现与输入，不改变任何数据；暂停期间产生的界面编辑态在解除暂停后按各界面规则提交或丢弃（架构案 7.4、6.2）。
- 设置界面的呈现归 M08，本系统只提供取值与提交入口（架构案 2.3 跨列说明）。
- 多语言只预留接口，当前版本不实现具体语言内容（架构案 7.8）。

### 10.2 实现要求

- I-OPTION-01 设置数据必须与游戏进度相互独立持久化，不得写入单局存档或跨局存档；提交时机为设置变更时（架构案 5.3）。
- I-OPTION-02 设置数据的读取与写入必须经 `API-OPTION-001` 与 `API-OPTION-002`，任何模块不得自行读写设置数据（架构案 3.4 第 6 项与 7.1）。
- I-OPTION-03 设置项定义在运行期必须只读，任何模块不得在运行期修改定义（架构案 7.9）。
- I-OPTION-04 键位映射的默认值必须由设置侧维护，改键后必须即时生效，不得要求重启（架构案 7.4）。
- I-OPTION-05 暂停必须只冻结表现与输入、不改变任何数据；暂停期间产生的界面编辑态在解除暂停后按各界面规则提交或丢弃（架构案 7.4、6.2）。
- I-OPTION-06 设置界面的呈现归 M08，本系统只提供取值与提交入口，不持有界面对象（架构案 2.3 跨列说明）。
- I-OPTION-07 多语言在长期范围内只预留接口，当前版本不得实现具体语言内容（架构案 7.8）。
- I-OPTION-08 设置项标识、意图标识与暂停相关设置必须先登记后使用，未登记的标识不得参与查询与提交。
- I-OPTION-09 本系统不得发布或订阅跨模块事件；确需广播时先按约定 §五.3 登记事件名并走需求申报，不自行发布未登记事件（架构案 3.1 的 M01 事件表未登记设置变更事件）。
