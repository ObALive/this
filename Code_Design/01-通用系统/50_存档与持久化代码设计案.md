## 1. 系统定义

### 1.1 系统目的

存档与持久化是本作的统一持久化入口：在自动保存的两类节点把三个数据域的可持久化切面提交为单局存档，在局末结算提交跨局存档，在设置变更时提交设置数据，并在读档时按恢复顺序把存档还原为可运行的运行时状态。本单元的系统标识为 SYS-SAVE-001 存档与持久化。

### 1.2 系统职责

- 持有单局存档、跨局存档与设置数据三份持久化结构，维护结构标识与结构版本；
- 受理各数据域的可持久化切面登记：切面归属、覆盖的状态项、采集入口、装载入口、重建步骤声明与切面版本；
- 在自动保存的两类节点采集切面、装配并提交单局存档；
- 在正常退出时执行一次收尾提交；
- 受理局末结算的一次跨局提交，按元进度与结算给出的写入内容落库；
- 受理设置数据的提交并独立落库，与游戏进度互不牵连；
- 维护存档索引，提供「是否存在有效单局存档」的只读查询；
- 读档时驱动装载与恢复顺序，并在数据域就绪后触发恢复完成通知；
- 提交前执行引用完整性校验；按结构维护版本绑定，版本不一致时派发迁移；
- 提交失败时作废整次提交并保留上一份有效存档；发布 自动保存完成、存档提交完成、存档恢复完成 三个事件。

### 1.3 系统边界

本系统不负责：

- 任何数据域业务含义与字段结构的定义，数据内容与其变更规则归各数据域所有者与变更入口模块；
- 结算时的跨局写入内容与结算组件清单，归 `07-线索树与元进度/40-局末结算与写入`，结算流程编排归 M10；
- 设置项清单、默认值、取值类型与设置界面，归 `01-通用系统/60-设置与辅助功能` 与 M08；本系统只负责设置数据的落点、结构与提交；
- 派生项的计算与重建执行，归各来源方，本系统只决定重建的触发时点与顺序位；
- 界面呈现、资源加载、日志落点、随机数生成与时间推进，分别归 M08 与 M01 的对应基础设施；
- 手动保存、多存档位与存档位管理，游戏只提供自动保存（术语表 T-016）。

### 1.5 功能要求

- F-SAVE-01 存档执行全量保存，读档执行全量恢复；恢复后的系统状态与保存提交完成时一致，不得以默认初始值代替已保存状态。
- F-SAVE-02 自动保存只发生在时间段推进与战斗轮次推进两类节点，不提供手动保存与多个存档位。
- F-SAVE-03 所有影响事件分支、事件生成、资源归属、时间判断与任务结算的状态必须入档。
- F-SAVE-04 保存快照必须保持引用完整：容器与内部物品、装备与容器内容、委托与交付事件、当前事件与其暂存结果、行情与已刷新交易事件以稳定标识关联。
- F-SAVE-05 跨局数据与单局数据分开保存；局内进行中的交易、委托进度、押金（术语表 T-096）、落地物（术语表 T-106）与未领取奖励不进入跨局数据，落地物在本局内完整保存与恢复。
- F-SAVE-06 恢复先装载基础定义版本，再创建实例与关系，最后重建派生效果与可查询缓存。
- F-SAVE-07 设置数据独立持久化，不随游戏进度变化。
- F-SAVE-08 读档失败时保留上一份有效存档并给出提示，停在主界面；版本无法迁移时提示存档不兼容。
- F-SAVE-09 恢复过程不重新抽取随机结果，未确认的操作不恢复。

### 2.4 数据关系

- 包含：单局存档包含世界状态域、单局状态域、玩家状态域三个切面与版本绑定；跨局存档与设置数据各自独立成结构，不与单局存档互相包含。
- 引用：切面声明登记项引用数据域侧的采集、装载入口与声明方的重建步骤；版本绑定引用配置版本标识与各切面的切面版本。
- 派生：存档索引由提交结果派生；恢复顺序单由切面声明与固定恢复顺序派生；区域形态推算、背包空间、同名遗物效果、条件求值结果等派生项由来源方按其来源状态重建，本系统不保存其取值。
- 互斥：三份结构各自独立提交，单次提交只作用于一个目标结构，失败语义互不牵连。

### 2.6 持久化要求

| 结构 | 入档内容 | 切面归属 | 提交时机 | 恢复位置 |
| --- | --- | --- | --- | --- |

## 3. 状态定义

### 3.1 状态

| 状态集 | 取值 | 说明 |
| --- | --- | --- |
| 存档服务运行状态 | 空闲／装载中／恢复中／采集中／提交中／失败回退 | 同一时刻只有一个取值；提交与装载、恢复互斥 |
| 单局存档有效性状态 | 无有效存档／有效／待迁移／不可读 | 由存档索引与版本校验共同判定 |
| 提交点状态 | 待提交／已提交／已作废 | 一次提交一个取值；已作废表示本批内容不落库 |
| 设置数据状态 | 有效／损坏 | 损坏时回落默认值，下一次成功提交后转为有效 |
| 版本绑定状态 | 一致／不一致／不可迁移 | 由版本校验给出，按结构分别维护 |

### 3.2 状态转换

```
空闲 → 装载中 → 空闲
空闲 → 恢复中 → 空闲
空闲 → 采集中 → 提交中 → 空闲
空闲 → 失败回退 → 空闲
待提交 → 已提交
待提交 → 已作废
无有效存档 → 有效
有效 → 待迁移 → 有效
待迁移 → 不可读
损坏 → 有效
一致 ↔ 不一致
```

### 3.3 状态转换触发条件

| 转换 | 触发条件 |
| --- | --- |
| 空闲 → 装载中 | API-SAVE-003 SaveService.Load 受理并读取目标结构 |
| 装载中 → 空闲 | 结构内容与结构版本读取完成 |
| 空闲 → 恢复中 | API-SAVE-004 SaveService.Restore 受理且版本校验结论为一致或迁移成功 |
| 恢复中 → 空闲 | 三个数据域按顺序装载完成，恢复完成通知已发布 |
| 空闲 → 采集中 | API-SAVE-002、API-SAVE-007 或 API-SAVE-006 取得提交点并开始采集 |
| 采集中 → 提交中 | 切面采集完成且引用完整性校验通过 |
| 提交中 → 空闲 | 目标结构落库完成、存档索引维护完成、提交点释放 |
| 任一在途状态 → 失败回退 | 采集、校验、落库或恢复任一环节失败 |
| 失败回退 → 空闲 | 本批内容丢弃，上一份有效存档保持可读 |
| 待提交 → 已提交 | 目标结构落库成功并返回提交结果 |
| 待提交 → 已作废 | 引用完整性校验不通过、落库失败或被并发拒绝 |
| 无有效存档 → 有效 | 单局存档首次提交成功或首次装载通过校验 |
| 有效 → 待迁移 | API-SAVE-005 判定配置版本或结构版本不一致且可迁移 |
| 待迁移 → 有效 | 迁移责任方执行成功 |
| 待迁移 → 不可读 | 迁移责任方未登记或执行失败 |
| 损坏 → 有效 | 设置数据下一次提交成功 |

### 4.2 接口详细定义

### API-SAVE-001 SaveService.RegisterSlice 切面登记

职责：受理一个数据域的可持久化切面声明，登记切面归属、覆盖状态项、采集与装载入口、重建步骤与切面版本。
输入：参数输入：切面声明；状态输入：启动阶段的服务容器登记状态；数据输入：无；外部事件输入：无。
读取：切面声明登记项、本服务的运行状态。
输出：返回值：登记结果与冲突项；状态输出：切面声明由未登记转为已登记；事件输出：无；外部系统调用：日志服务.Write（API-M01-010）。
产生的状态变化：切面声明登记新增或更新一条登记项。
前置条件：处于启动阶段且服务容器已完成能力登记；同一域标识与同一结构归属未登记过不同入口。
后置条件：该切面进入后续批次的采集范围与恢复顺序。
副作用：登记冲突时经日志服务记录冲突项。
异常情况：同一域标识重复登记且入口不一致；切面版本缺失；覆盖状态项为空；登记发生在启动阶段之后。

### API-SAVE-002 SaveService.Submit 存档提交

职责：在一个提交点上采集切面、装配单局存档、校验引用完整性并落库，失败时整次作废。
输入：参数输入：提交点类别、目标结构标识；状态输入：切面声明登记表、运行状态、存档索引；数据输入：配置版本标识；外部事件输入：时间刻度变化、轮次推进（配置加载完成 由 `API-SAVE-005` 版本校验受理，不在本接口的输入内）。
读取：切面声明登记表、数据域侧的采集入口、单局存档结构、版本绑定。
输出：返回值：提交结果与失败项；状态输出：单局存档内容与存档索引更新；事件输出：自动保存完成、存档提交完成；外部系统调用：日志服务.Write（API-M01-010）、事件分发器.Publish（API-M01-011）。
产生的状态变化：运行状态 空闲→采集中→提交中→空闲或失败回退；提交点 待提交→已提交或已作废。
前置条件：运行状态为空闲；目标结构已被切面声明覆盖；不存在在途的装载、恢复或另一笔提交。
后置条件：成功时单局存档内容等于本次采集结果；失败时上一份有效存档保持可读且内容不变。
副作用：发布 自动保存完成 与 存档提交完成；写入提交点与校验结论的分类日志。
异常情况：采集入口缺失或返回内容不完整；引用完整性校验不通过；落库中断；提交期间收到新的提交请求；运行状态非空闲。

### API-SAVE-003 SaveService.Load 存档装载

职责：从指定结构读取内容与结构版本供恢复或呈现使用，不做业务解释。
输入：参数输入：结构选择（单局存档、跨局存档、设置数据、存档索引）；状态输入：存档索引；数据输入：无；外部事件输入：无。
读取：目标结构、存档索引、版本绑定。
输出：返回值：结构内容与结构版本，或不可读结论与缺失结论；状态输出：不可读结构在存档索引中标记；事件输出：无；外部系统调用：日志服务.Write（API-M01-010）。
产生的状态变化：运行状态 空闲→装载中→空闲或失败回退。
前置条件：运行状态为空闲；存档索引可读；目标结构在索引中存在。
后置条件：成功时结构内容完整可用于恢复或呈现；失败时结构内容不被部分采用。
副作用：不可读时经日志服务记录结构标识与失败类别。
异常情况：结构缺失；结构不可读；结构版本高于可识别范围；索引与结构不一致。

### API-SAVE-004 SaveService.Restore 恢复驱动

职责：按固定恢复顺序驱动数据域装载，并在三个域就绪后触发恢复完成通知与重建时点。
输入：参数输入：装载结果、恢复范围；状态输入：切面声明登记表、阶段状态机当前阶段（API-M10-001）；数据输入：配置版本标识；外部事件输入：无。
读取：切面声明登记表、数据域侧的装载入口、三个数据域的空结构。
输出：返回值：恢复结果；状态输出：三个数据域由空结构转为存档内容；事件输出：存档恢复完成；外部系统调用：数据域侧装载入口（API-SAVE-008 侧）、事件分发器.Publish（API-M01-011）、日志服务.Write（API-M01-010）。
产生的状态变化：运行状态 空闲→恢复中→空闲或失败回退；数据域内容按世界状态域、单局状态域、玩家状态域的顺序逐域就绪。
前置条件：版本校验结论为一致或迁移成功；三个数据域已创建为空结构；运行状态为空闲。
后置条件：三个数据域内容与单局存档一致；派生项重建时点已触发；恢复过程未重新抽取任何随机结果。
副作用：发布 存档恢复完成；每域完成时经日志服务记录。
异常情况：某域装载入口返回失败；切面登记缺失导致某域无法恢复；恢复期间收到提交或装载请求；阶段状态机取值不允许恢复落点。

### API-SAVE-005 SaveService.VerifyVersion 版本校验

职责：比对配置版本标识与各结构的版本绑定，给出结论并派发迁移。
输入：参数输入：版本绑定、结构选择；状态输入：存档索引；数据输入：配置版本标识（API-M01-003 配置服务.Query）；外部事件输入：配置加载完成。
读取：版本绑定、切面声明登记项中的迁移责任方、存档索引。
输出：返回值：校验结论（一致／可迁移／不兼容）与依据项；状态输出：单局存档有效性状态与版本绑定状态更新；事件输出：无；外部系统调用：迁移责任方的迁移入口（声明该切面的单元，ID 待补）、日志服务.Write（API-M01-010）。
产生的状态变化：版本绑定由不一致转为一致，或结构标记为不可读。
前置条件：目标结构已完成装载；配置服务已给出当前配置版本标识。
后置条件：结论为一致时可直接进入恢复；结论为可迁移时迁移由声明该切面的域执行并回报结果。
副作用：校验结论与迁移派发经日志服务记录。
异常情况：配置版本标识缺失；结构版本无法识别；迁移责任方未登记；迁移执行失败。

### API-SAVE-006 SaveService.SubmitSettings 设置数据提交

职责：受理设置数据的变更提交，独立落库，不改变游戏进度。
输入：参数输入：设置数据变更项；状态输入：设置数据当前内容与设置数据状态；数据输入：设置项定义（OPTION，`CLS-OPTION-001`）；外部事件输入：无。
读取：设置数据、设置项定义、切面声明登记表中的设置切面。
输出：返回值：提交结果；状态输出：设置数据内容更新，设置数据状态 损坏→有效；事件输出：无；外部系统调用：日志服务.Write（API-M01-010）。
产生的状态变化：设置数据内容等于本次提交内容；提交点记录新增一条设置提交。
前置条件：变更项落在设置项定义登记范围内；运行状态不处于采集中、提交中、装载中、恢复中。
后置条件：设置数据与游戏进度结构互不影响，各自独立可读。
副作用：提交结果经日志服务记录。
异常情况：变更项不在设置项定义范围内；设置数据不可写；提交期间进程终止。

### API-SAVE-007 SaveService.CommitCrossRun 跨局存档提交

职责：受理局末结算的一次跨局提交，按调用方随参数传入的写入内容落库；写入内容与组件清单不由本接口定义，本系统不调用组件清单查询。
输入：参数输入：跨局写入内容、整局存档快照标识；状态输入：存档索引、跨局存档结构；数据输入：无（跨局写入内容由调用方随参数传入）；外部事件输入：结局成立（M10）。
读取：跨局存档结构、整局存档快照的装载结果。
输出：返回值：提交结果与失败项；状态输出：跨局存档内容按写入项更新，提交点记录新增；事件输出：存档提交完成；外部系统调用：日志服务.Write（API-M01-010）、事件分发器.Publish（API-M01-011）。
产生的状态变化：运行状态 空闲→采集中→提交中→空闲或失败回退；跨局存档内容变更。
前置条件：阶段状态机处于结算阶段（API-M10-001）；整局存档快照可用；同一局尚无成功的跨局提交。
后置条件：成功时跨局存档内容等于调用方传入的写入内容；失败时跨局存档保持提交前内容并保留重试能力，重试不产生重复写入。
副作用：发布 存档提交完成。
异常情况：快照缺失或不可读；写入项与调用方传入的写入内容声明不一致；同一局重复提交；跨局存档不可写。

### API-SAVE-008 DataDomain.Read 数据域只读查询

职责：按域标识返回只读快照，供允许读取该域的模块取数，不提供写入口。
输入：参数输入：域标识、读取范围；状态输入：该域当前内容与提交版本；数据输入：无；外部事件输入：无。
读取：目标数据域内容、切面声明登记表。
输出：返回值：只读快照；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：该域已创建，或该域为跨局数据且已装载。
后置条件：快照不携带写入口；读取方不得把快照缓存为自身数据。
副作用：无。
异常情况：域标识未登记；恢复期间读取尚未就绪的域；读取范围越出该域。

### API-SAVE-009 DataDomain.Submit 数据域变更提交

职责：按域标识接收变更入口模块的提交项并落库，不解释提交项的业务含义。
输入：参数输入：域标识、变更提交项、提交来源模块；状态输入：该域当前内容、阶段状态机当前阶段、运行状态；数据输入：无；外部事件输入：无。
读取：目标数据域内容、切面声明登记表。
输出：返回值：提交结果；状态输出：该域内容按提交项更新；事件输出：无；外部系统调用：日志服务.Write（API-M01-010）。
产生的状态变化：该域内容整笔变更；提交项不产生部分生效。
前置条件：提交来源模块为该域登记的变更入口；运行状态不处于采集中、提交中、装载中、恢复中；阶段状态机允许该提交。
后置条件：提交项整笔生效或整笔不生效。
副作用：被拒绝的提交经日志服务记录。
异常情况：提交来源模块不是该域登记的变更入口；提交项引用不存在的对象；提交发生在恢复期间；结算阶段提交改变局内状态的内容。

### API-SAVE-101 CollectSlices 切面采集

职责：按切面声明组织本批次的采集范围并回收切面内容，产出切面快照集合。
输入：参数输入：目标结构与提交点类别；状态输入：切面声明登记表；数据输入：无；外部事件输入：无。
读取：切面声明登记表、数据域侧的采集入口。
输出：返回值：切面快照集合；状态输出：运行状态 空闲→采集中；事件输出：无；外部系统调用：数据域侧采集入口。
产生的状态变化：本批次切面快照生成。
前置条件：已取得提交点，运行状态为空闲且无在途装载或恢复。
后置条件：快照覆盖切面声明登记的全部可持久化切面。
副作用：无。
异常情况：采集入口缺失或不可用；切面返回内容不完整；采集期间目标结构被并发提交。

### API-SAVE-102 AssembleAndValidate 装配与引用完整性校验

职责：把切面快照装配为目标结构，并校验结构内部引用完整。
输入：参数输入：切面快照集合、目标结构标识；状态输入：切面声明登记表；数据输入：配置版本标识；外部事件输入：无。
读取：切面快照集合、版本绑定、目标结构标识。
输出：返回值：装配结果与引用完整性校验结论；状态输出：运行状态 采集中→提交中或失败回退；事件输出：无；外部系统调用：无。
产生的状态变化：目标结构内容成型；校验结果生成。
前置条件：切面快照集合完整且非空。
后置条件：校验通过时结构可落库；不通过时整次提交作废。
副作用：不通过项经日志服务记录。
异常情况：切面之间引用无法解析；结构版本缺失；装配期间快照被释放。

### API-SAVE-103 ManageCommitPoint 提交点管理

职责：为一次提交或恢复分配提交点并串行化，拒绝并发与重入请求。
输入：参数输入：提交点类别、目标结构标识；状态输入：运行状态、在途提交点；数据输入：无；外部事件输入：无。
读取：运行状态、提交点记录。
输出：返回值：提交点取得结果；状态输出：提交点 待提交→已提交或已作废；事件输出：无；外部系统调用：无。
产生的状态变化：在途提交点占用或释放；运行状态按 3.2 转换。
前置条件：运行状态为空闲或该请求属于当前在途批次。
后置条件：提交点释放后运行状态可再次受理请求。
副作用：被拒绝的请求经日志服务记录。
异常情况：已有在途提交点；恢复期间收到提交请求；提交期间收到装载请求。

### API-SAVE-104 PersistAndIndex 落库与索引维护

职责：把目标结构写入存档落点，维护存档索引，失败时丢弃本批内容并保留上一份有效存档。
输入：参数输入：目标结构内容、提交点类别；状态输入：存档索引、运行状态；数据输入：无；外部事件输入：无。
读取：目标结构内容、存档索引。
输出：返回值：落库结果；状态输出：目标结构与存档索引更新，或本批内容作废；事件输出：无；外部系统调用：日志服务.Write（API-M01-010）。
产生的状态变化：目标结构内容更新；存档索引最近一次成功提交点更新；失败时运行状态转失败回退。
前置条件：引用完整性校验通过；提交点处于待提交。
后置条件：成功时存档索引指向本次提交；失败时上一份有效存档保持可读。
副作用：落库结果与失败类别经日志服务记录。
异常情况：存档落点不可写；写入中断；索引维护失败；写容量达到上限。

### API-SAVE-105 DriveRestore 恢复顺序驱动

职责：按世界状态域、单局状态域、玩家状态域的顺序驱动装载，并在三个域就绪后触发恢复完成通知与重建时点。
输入：参数输入：装载结果、恢复范围；状态输入：切面声明登记表、阶段状态机当前阶段；数据输入：无；外部事件输入：无。
读取：切面声明登记表、数据域侧装载入口、恢复顺序单。
输出：返回值：恢复结果；状态输出：三个数据域由空结构转为存档内容；事件输出：恢复完成通知交由 API-SAVE-004 发布；外部系统调用：数据域侧装载入口。
产生的状态变化：运行状态 空闲→恢复中→空闲或失败回退；逐域就绪状态推进。
前置条件：装载已成功且版本校验通过；数据域已创建为空结构。
后置条件：三个域就绪，重建时点已触发，恢复过程未重新抽取随机结果。
副作用：每域完成情况经日志服务记录。
异常情况：某域装载入口失败；切面缺失导致顺序不完整；恢复期间收到提交请求。

### API-SAVE-106 DispatchMigration 版本比对与迁移派发

职责：比对配置版本与结构版本，并把可迁移的差异交给声明该切面的域执行。
输入：参数输入：版本绑定、结构选择；状态输入：存档索引；数据输入：配置版本标识；外部事件输入：配置加载完成。
读取：版本绑定、切面声明登记项中的迁移责任方。
输出：返回值：校验结论；状态输出：版本绑定状态更新；事件输出：无；外部系统调用：迁移责任方的迁移入口（声明该切面的单元，ID 待补）。
产生的状态变化：版本绑定由不一致转为一致，或结构标记为不可读。
前置条件：目标结构已完成装载。
后置条件：结论与依据项可供 API-SAVE-005 返回。
副作用：结论经日志服务记录。
异常情况：版本标识缺失；结构版本无法识别；迁移责任方未登记；迁移执行失败。

### 5.3 功能之间的关系

- API-SAVE-002 与 API-SAVE-007 依次调用 API-SAVE-103、API-SAVE-101、API-SAVE-102、API-SAVE-104，两者共用同一条链路，只是采集范围与目标结构不同；API-SAVE-006 走提交链路但目标结构为设置数据、不采集三个数据域切面。
- API-SAVE-003 调用 API-SAVE-103 与数据域侧装载入口，只完成读取；API-SAVE-004 调用 API-SAVE-105 完成顺序驱动与恢复完成通知。
- API-SAVE-005 调用 API-SAVE-106 完成比对与派发；结论为可迁移时由声明该切面的域执行迁移。
- 任一环节返回失败时由 API-SAVE-104 执行失败回退，API-SAVE-103 释放提交点，运行状态回到空闲。
- 派生项重建不由本系统的功能触发执行：API-SAVE-105 在三个域就绪后决定重建时点，由 API-SAVE-004 发布 存档恢复完成，来源方订阅后按来源状态重建。

### 6.4 使用方式

- 启动阶段：经 API-M01-001 登记本服务能力与依赖声明，经 API-M01-002 取得日志、配置与事件分发能力；各域声明方调用 API-SAVE-001 登记切面。
- 运行期：节点提交为事件间接获得，本系统按事件名订阅 时间刻度变化 与 轮次推进，不解析其业务含义；配置加载完成 由 `API-SAVE-005` 版本校验受理，不作为提交节点的触发；`API-SAVE-005`、`API-SAVE-002` 与 `API-SAVE-007` 的调用方直接调用本系统。
- 切面读写：采集与装载只在提交与恢复期间经切面声明与数据域侧入口进行；结算阶段不接受改变局内状态的提交。
- 结果告知：每次提交与恢复经 API-M01-011 发布事件，失败与拒绝经 API-M01-010 记录日志。

### 6.5 依赖方向限制

- 本系统位于 L1、L2，只使用基础设施与数据层自身的能力，不引用任何 L3 及以上模块的对象与接口（架构案 3.4 第 1、2 项）；唯一例外是对 M10 的 `API-M10-001` 阶段只读查询，属架构案 3.3 第 12 项「任何模块查询 M10 的当前阶段」，已在 4.2 的 `API-SAVE-004`、`API-SAVE-007` 与 6.3 按登记例外写明，不构成越层调用。
- 本系统与玩法模块只有两种接触：启动阶段接收其切面声明，恢复完成时发布事件由其订阅；两者都不构成对玩法模块的调用，切面读写入口位于数据域持有侧。
- 反向依赖禁止：任何模块不得绕过本系统读写存档或自行序列化状态（架构案 3.4 第 6 项与 7.1）；本系统也不得被要求反向调用玩法模块的业务入口。
- 与 M10 之间不构成循环依赖：M10 调用本系统的提交与装载接口，本系统只发布事件并对阶段做只读查询（架构案 3.3 第 12 项）、不调用其业务入口；与 M06 之间不发生直接依赖（架构案 3.4 第 12 项）。
- 本系统的依赖落在架构案 3.3 第 9 项与第 10 项内；本系统内部的调用属同一模块内依赖，不新增允许清单条目。

## 8. 核心流程

### 8.1 自动保存的两类节点提交

| 项 | 内容 |

## 9. 异常与边界情况

| # | 情形 | 判定条件 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 提交失败 | 采集、校验或落库任一环节失败 | 本批内容作废，单局存档与存档索引保持上一份有效内容，提交点记已作废，失败项经日志服务记录 |
| 2 | 引用完整性校验不通过 | 容器与内部物品、装备与容器内容、委托与交付事件、当前事件与其暂存结果、行情与已刷新交易事件之间存在无法解析的引用 | 整次提交作废，不落库部分内容 |
| 3 | 版本不一致 | API-SAVE-005 判定配置版本或结构版本不一致 | 可迁移时派发迁移并在成功后进入恢复；不可迁移或迁移失败时判定为不可读，提示不兼容并停在主界面 |
| 4 | 读档失败 | 结构缺失、不可读或存档索引与结构不一致 | 保留上一份有效存档，向表现通道给出提示并停在主界面 |
| 5 | 恢复期并发 | 恢复中收到提交或装载请求 | 后到请求被拒绝，恢复继续，拒绝项经日志服务记录 |
| 6 | 提交期并发 | 采集中或提交中收到新的提交请求 | 后到请求被拒绝，不排队、不合并 |
| 7 | 重复结算提交 | 同一局已有成功的跨局提交记录 | API-SAVE-007 拒绝提交，不产生重复写入 |
| 8 | 提交期间进程终止 | 提交未返回结果时进程结束 | 以最近一次成功提交为准，未完成的提交不生效 |
| 9 | 设置数据损坏 | 设置数据不可读或校验失败 | 回落默认值，设置数据状态转为损坏，下一次成功提交后转为有效 |
| 10 | 切面登记缺失 | 某域未登记切面或声明的入口不可用 | 该域不进入本批次采集与恢复顺序，提交照常完成并记日志 |
| 11 | 未登记内容尝试入档 | 存在未声明切面的状态数据 | 不进入任何结构，由该域按新增数据域的接入步骤补登记 |
| 12 | 派生项缺失或不一致 | 恢复后发现派生项未重建或其取值与来源状态不符 | 由来源方按来源状态重建，不按派生结果反推来源状态 |
| 13 | 结算阶段提交局内状态 | 阶段状态机处于结算阶段且提交项改变局内状态 | API-SAVE-009 拒绝提交 |
| 14 | 存档索引损坏 | 索引不可读或与结构不一致 | 判定为无有效存档，只提供开新局 |

## 10. 实现约束

### 10.1 实现约束条目

- 全部可持久化状态必须可序列化；不可序列化的临时运行对象不得进入任何结构。
- 采集与装载只能经切面声明登记进行；任何模块不得自行序列化状态或绕过本系统读写存档。
- 未登记切面的数据不入档；数据所有者新增可持久化状态时先登记切面再纳入采集范围。
- 提交与装载、恢复互斥，任一时刻只允许一个在途操作。
- 三份结构分别提交、分别维护结构版本，失败语义互不牵连。
- 引用完整性的关联必须使用稳定标识，运行期标识不得写入结构。
- 派生项不入档，只由来源方按来源状态重建，不得按派生结果反推来源状态。
- 恢复过程不得重新抽取随机结果，未确认的操作不得恢复。
- 存档对象与临时运行对象不得跨帧保留，采集完成后释放。
- 本系统不得持有任何玩法模块的对象引用，只持有切面声明、入口标识与事件订阅。
- 结算阶段不接受改变局内状态的提交。
- 提交失败必须保留上一份有效存档可读。
- 条件判定、事件生成与结果判定必须读取同一份已提交状态，不得读取未提交的编辑态（上游 `50_存档与持久化设计.md` §5；架构案 5.4、8.2 第 2 条）。

### 10.2 实现要求

- I-SAVE-01 三份持久化结构必须分别具有独立的提交点与结构版本标识。
- I-SAVE-02 可持久化内容必须经切面声明登记，未登记内容不得进入任何结构。
- I-SAVE-03 提交前必须完成引用完整性校验，校验不通过不得落库。
- I-SAVE-04 提交与装载、恢复必须互斥，任一时刻只允许一个在途操作。
- I-SAVE-05 失败提交必须整体作废，并保留上一份有效存档可读。
- I-SAVE-06 恢复顺序必须为世界状态域、单局状态域、玩家状态域，派生项在三个域就绪后由来源方重建。
- I-SAVE-07 派生项不得作为数据来源，不得入档，只能按来源状态重建。
- I-SAVE-08 恢复过程不得重新抽取随机结果。
- I-SAVE-09 存档对象与临时运行对象不得跨帧保留、不得入档。
- I-SAVE-10 本系统不得引用任何玩法模块的对象，跨模块接触只经事件订阅与切面声明。
