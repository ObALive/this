## 1. 系统定义

### 1.1 系统目的

本系统的对象标识：`SYS-ITEM-001 物品系统`。

物品系统为全部物品提供统一的元物品加组件模型与通用状态变化规则，使物品的功能由组件组合表达而不由用途名称决定；它是物品侧规则的唯一定义方与需要物品侧判定的操作的受理校验方，状态变化一律经 M09 的写入服务提交。

### 1.2 系统职责

- 元物品定义与物品实例的分离持有：元物品承载识别信息与可配置属性，实例承载组件状态、归属与堆叠数量（`05_物品系统设计.md` 2.1）
- 元对象与组件内核的物品侧部分：物品侧元对象、组件挂载声明与挂载登记的物品侧校验与查询；组件定义（`CLS-M04-002`）与对象与组件注册表（`CLS-M04-001`）由 M04 模块单元文档定义，本文档只引用；新增组件必须先经该注册表登记，元对象定义与组件定义都是配置资产（架构案 3.1 ARC-M04-001、5.1、7.11、8.5.4）
- 物品词条体系与物品池的静态登记：词条标识、类别与匹配用途，按用途词条组织物品池成分（2.3）
- 容器组件的物品侧规则：有序储物格、存取限制、自动装载许可、允许内容约束与即时取用、嵌套调用许可两个开关（2.4、2.5）
- 物品归属与移动：归属载体引用、容器内容随物移动、嵌套结构保持与容器携带代价的规则承载（第 3 节）
- 通用物品操作的物品侧受理与校验：物品操作总表登记的界面交互操作（第 5 节）
- 物品获得与溢出的物品侧部分：可获得物品清单的受理与物品侧校验、向自动装载发起请求；未装入部分的落地物生成由 05-30 的自动装载与溢出受理完成（第 6 节）
- 交易动作的物品侧部分：物品交付、付款与交换目标的扣除与获得组装，按整笔原子性一次提交（5.2）
- 落地物载体的持有与其单局生命周期（5.1）
- 物品投掷的组件归属：投掷组件的挂载登记与资格取数，供 06-80 判定（第 4 节）
- 物品侧派生项的重建与物品变更类别的语义定义，变更集一律经 `API-M09-005` 提交；写入服务按「变更一项一落库」执行、任一项无法完成时整笔回滚，本系统不落库、不自行序列化状态（架构案 3.4 第 7 项、7.11、9.5.7）

### 1.3 系统边界

本系统不负责：

- 物品状态变化的落库、按「变更一项一落库」的逐项执行与整笔回滚（归 M09 的物品与经济写入服务 `API-M09-005`）
- 背包空间的构成、自动装载顺序与溢出流程的执行（归 05-30 背包系统）
- 货币媒介、基准价值的展示口径、估价与交易事件流程（归 05-10 金钱与货物）；行情的字段与取数口径归 05-10，行情数据的所有权归世界状态域、变更入口为 M02 的生成流程（架构案 5.2.1、5.4），本系统不读取也不写入行情
- 装备槽的持有、槽位适配定义与储物装备的空间提供（归 06-60 装备系统）
- 遗物词条的同名判定与生效规则（归 06-70 遗物系统）
- 战斗内的行为结算、投掷折算、库存调取的行动成本与消耗确认（归 M05，尤其 06-80）
- 效果叠加与效果生命周期（归 M09 的元效果服务）、条件判定（归 M09 的条件求值服务）
- 容器界面、装备栏界面与物品选择界面的绘制、界面编辑态与鼠标悬挂位的持有（归 M08）
- 事件的生成、刷新、退出与结算，以及事件侧交付需求与效果声明（归 M02 与 M10）
- 持续任务的接取、推进与结算，以及任务要求的持有（归 05-20 委托系统）
- 存档结构、切面顺序、版本迁移与恢复驱动（归 01-50 存档与持久化）
- 结算阶段之后的跨局写入、结局判定与大关进度（归 M06 与 M10）

### 1.5 功能要求

- F-ITEM-01 所有物品共用元物品加组件的模型，功能由组件组合表达；不得按货物、货币、任务物品或装备等用途名称建立互斥判断。
- F-ITEM-02 物品词条是统一分类标识，一件物品可同时挂载多个词条且互不排斥；按类别筛选的规则统一引用词条。
- F-ITEM-03 物品始终归属于一个明确载体，容器内的物品随容器整体移动；改变归属时不得在无显式规则的情况下拆离或转存容器内容。
- F-ITEM-04 物品操作必须先验证来源、目标、组件能力、容量与状态限制；无效操作不改变任何物品状态。
- F-ITEM-05 需要玩家确认的操作在确认前不提交状态变化；交易确认后立即成立，不提供撤回、退款或返还路径。
- F-ITEM-06 一笔交易的全部资源变化构成不可分割的整体，任何一部分无法完成时整笔不产生状态变化。
- F-ITEM-07 直接获得物品统一走自动装载；空间不足时未装入部分作为落地物生成在事件点位，装入与落地在同一笔领取内一次提交，取消领取不产生任何状态变化。
- F-ITEM-08 落地物属于单局状态，随单局存档完整保存与恢复，结算提交完成、进入局外阶段时随单局状态域释放、不进入跨局数据与局末结算；事件结束与事件结束后的场景状态刷新都不回收落地物。
- F-ITEM-09 容器按允许内容约束限定可容纳的物品，未挂载所要求词条的物品无法放入，界面提示具体原因且操作不提交。
- F-ITEM-10 物品将因出售、投掷、交付或其他操作离开角色且满足持续任务要求时，系统必须在提交操作前提示玩家。
- F-ITEM-11 消耗品在玩家确认行动时扣减堆叠数量，取消行动不扣减；堆叠数量减至零时该实例销毁、所在容器格清空。
- F-ITEM-12 物品能否投掷以及投掷后产生什么，全部由已挂载的投掷组件决定，不按用途名称判断；配置为禁止投掷的物品不出现在投掷选择界面中。
- F-ITEM-13 元物品的重量为标准字段，参与投掷折算、载具带货与后续重量限制规则；体积字段保留，当前版本不启用限制。

### 2.4 数据关系

- 元物品定义与物品实例是一对多的定义与个体关系：实例以标识引用元物品，元物品随静态配置装载而不随局重置。
- 组件运行状态从属于实例；容器状态是容器组件在某一实例上的状态，容器内物品随容器整体移动（`05_物品系统设计.md` 3）。
- 归属引用指向载体：容器格载体由容器实例的格位结构给出，装备槽载体由 06-60 给出，事件交付区载体由 M02 给出，世界掉落点载体由 CLS-ITEM-009 给出，界面悬挂位载体由 M08 持有。
- 落地物载体与物品实例是容器与内容的关系，其内容格序沿用容器随物移动的规则，不参与背包空间。
- 物品操作请求与物品变更集是一对一关系：一次受理产出一个变更集，变更集内的变更项构成原子整体。
- 词条与物品池是一对多关系：一个用途词条对应一个物品池，池成分按物品去重；同一物品挂载多个用途词条时可出现在多个池中。

### 2.5 数据生命周期

| 分类 | 本系统的对象 | 约束 |
| --- | --- | --- |
| 常驻对象 | 组件注册表（`CLS-M04-001`，定义方为 M04 模块单元文档） | 由常驻场景承载，由启动物体按单元装配声明顺序初始化、按逆序销毁（架构案 2.4.1、6.1、6.4、8.3 第 1 条）；本系统只读引用、不创建 |
| 数据域对象 | 物品实例、组件运行状态、容器状态、归属引用、落地物载体 | 随单局创建，跨局写入提交完成、进入局外阶段时随三个数据域一并释放，开新局时全部重建；容器定义常驻、内容按局重置（架构案 5.2、6.6、8.3 第 3 条；变更 J） |
| 场景对象 | 无 | — |
| 临时运行对象 | 物品操作请求、物品变更集、预检结果、交付检测结果 | 单次操作内有效，不跨帧保留、不入档 |
| 存档对象 | 本系统的单局状态域切面 | 只在采集与恢复期间存在，采集完成后释放 |
| 静态配置对象 | 元物品定义、组件定义、词条定义与物品池 | 启动阶段装载，运行期只读，不销毁直到进程退出 |

结算阶段开始后，本系统不得创建或销毁单局状态域内的实例（架构案 8.3 第 5 条）：结算阶段收到的获得、销毁与投掷丢弃请求一律拒绝。单局状态域在跨局写入提交完成、进入局外阶段时释放，开新局时三个数据域全部重建（架构案 5.2、6.6、8.3 第 3 条；变更 J）。

### 2.6 持久化要求

| 入档内容 | 切面归属 | 提交时机 | 恢复位置 |
| --- | --- | --- | --- |
| 物品实例与组件运行状态 | 单局状态域切面，由本系统经 API-SAVE-001 登记 | 自动保存的两类节点（时间段推进、战斗轮次推进）；**退出不提交存档、不构成提交点**（架构案 5.3 第 4 项、7.1；设计决策记录决策 89） | 单局状态域恢复阶段，按实例标识与归属引用重建 |
| 容器状态与嵌套关系 | 同上 | 同上 | 同上，格位与嵌套结构按存档恢复 |
| 归属引用与落地物载体 | 同上 | 同上 | 同上，落地物按点位标识与格序恢复，不回收、不重算 |
| 元物品、组件、词条与物品池定义 | 不入档 | — | 随静态配置装载重建；配置版本标识不一致时按 01-50 的迁移规则处理 |
| 存档序列化形态 | 单局状态域切面 | — | 采用**判别字段式多态序列化**：序列化结果中只出现**自定义的字符串判别值**，**不写入运行时类型名**；多态类型按判别值映射，不接受任意类型名；不得使用已被运行时移除实现的二进制序列化机制（架构案 7.1、8.6 第 8 条） |
| 单局存档的写入原子性 | 单局存档 | — | 写临时文件后原子替换；提交过程中断时整次作废并保留上一份有效存档；读档时未确认的操作不恢复（架构案 5.3 第 4 项） |

退出游戏即**进程终止**，与强制关闭、平台关闭、异常终止同义：退出时**不提交存档、不构成任何提交点、不执行销毁序列、不依赖任何退出回调**完成存档或收尾。单局存档的唯一可靠写路径是**时间段推进与战斗轮次推进两类自动保存节点**；任意时刻终止进程后重新启动，必须能正常启动并继续游玩，自上一个自动保存节点以来的进度不恢复（架构案 3.4 第 17 项、5.3 第 4 项、6.4、7.1、9.4；设计决策记录决策 89）。

## 3. 状态定义

### 3.1 状态

| 状态集 | 取值 | 说明 |
| --- | --- | --- |
| 本单元初始化状态 | 未初始化 → 初始化中 → 已初始化 → 已销毁 | 常驻对象由常驻场景承载，由启动物体按单元装配声明顺序显式初始化并注入相互引用；未进入已初始化前，本系统的对外接口一律拒绝受理（架构案 2.4.1、6.1 阶段 3、8.3 第 1、6 条） |
| 物品实例存续状态 | 待获得／存续／已销毁 | 待获得表示已受理、尚未装入且载体未定；堆叠数量减至零或投掷丢弃完成后销毁 |
| 归属载体类别 | 角色装备槽／容器格／事件交付区／世界掉落点／界面悬挂位／待获得（载体未定） | 实例在同一时刻只属于一个载体；待获得表示已受理尚未装入、载体未定，装入后转入具体载体 |
| 容器存取状态 | 可自动识别／需界面打开 | 由容器存取限制、即时取用与嵌套调用许可及当前场合共同决定 |
| 操作受理状态 | 待校验／已校验待提交／已提交／已拒绝 | 单次操作内有效；已拒绝表示不产生任何状态变化 |
| 交付检测状态 | 满足／不满足 | 需求匹配结论，不改变物品状态 |
| 变更集提交状态 | 组装中／已提交／已回滚 | 由写入服务的整笔结论决定 |
| 落地物载体状态 | 挂载中／已清空 | 已清空后该载体不再被拾取引用 |

### 3.2 状态转换

```
本单元初始化：未初始化 → 初始化中 → 已初始化 → 已销毁
物品实例存续：待获得 → 存续 → 已销毁
归属载体：世界掉落点 → 容器格 → 事件交付区
          容器格 → 世界掉落点
          容器格 ↔ 角色装备槽
          容器格 ↔ 界面悬挂位
容器存取：需界面打开 ↔ 可自动识别
操作受理：待校验 → 已校验待提交 → 已提交
          待校验 → 已拒绝
          已校验待提交 → 已拒绝
变更集提交：组装中 → 已提交
            组装中 → 已回滚
落地物载体：挂载中 → 已清空
```

| --- | --- | --- |

### 3.4 状态转换与接口的一致性

3.3 的「相关接口」列与 4.1 接口表的状态变化列一一对应：只读接口（`API-ITEM-001`、`API-ITEM-002`、`API-ITEM-007`）的状态变化列为「无」，因此不承担状态转换；由事件驱动的重算行（容器存取状态）以事件为触发来源、以 `API-ITEM-004` 的状态变化列为对应项；本单元初始化状态的两行由启动物体的显式初始化序列与逆序销毁驱动，不构成对外接口（架构案 6.1、8.3 第 1、6 条）。域级事件不在本系统的接口内直接产生，一律在收到 物品变更提交 之后按变更类别发布，见 7.2。

## 4. 对外接口

### 4.1 接口列表

### 4.2 接口详细定义

输入与输出按参数输入／状态输入／数据输入／外部事件输入与返回值／状态输出／事件输出／外部系统调用四类分别记录（NR-06 §七）。本系统的接口自身不直接发布域级事件：域级事件经订阅 物品变更提交 后按变更类别发布，见 7.2。

### API-ITEM-001 物品定义查询

职责：按标识返回元物品定义、组件定义、词条与物品池成分。
输入：参数输入：元物品标识或词条标识、查询范围；状态输入：组件注册表状态；数据输入：CLS-ITEM-001、CLS-ITEM-002、CLS-ITEM-004；外部事件输入：无。
读取：CLS-ITEM-001 元物品定义、CLS-ITEM-002 组件定义、CLS-ITEM-004 词条定义与物品池。
输出：返回值：只读定义视图或查询失败结果；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条，由启动物体按单元装配声明顺序显式初始化）；配置服务已从引擎编辑器内的配置资产完成装载并通过校验；组件注册表处于可用状态。
后置条件：返回内容为只读形态，不携带写入面（架构案 7.9）。
副作用：无。
异常情况：标识不可解析；组件注册表处于登记中或冲突状态；请求写入（拒绝，运行期配置只读）；元物品、组件或词条为待补充记录（返回待补充标记，见 REQ-ITEM-01、REQ-ITEM-05）。

### API-ITEM-002 物品实例与组件能力查询

职责：按实例、载体或查询面返回实例与组件状态、容器内容与可识别判定、归属的只读视图。
输入：参数输入：实例标识或载体标识、查询面（组件能力／容器内容／归属）、场合标识（战斗之外／战斗过程中）、嵌套深度许可；状态输入：实例存续状态、容器存取状态、装备槽归属；数据输入：CLS-ITEM-001、CLS-ITEM-002、CLS-ITEM-004、CLS-ITEM-007；外部事件输入：无。
读取：CLS-ITEM-005 物品实例、CLS-ITEM-006 组件运行状态、CLS-ITEM-007 容器状态、CLS-ITEM-008 归属引用、CLS-ITEM-009 落地物载体。
输出：返回值：组件能力与状态（堆叠数量与上限、容器开关、装备槽适配声明、投掷组件标识、元物品重量）、格序内容与可识别判定、归属视图；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；实例处于存续状态且挂载对应组件；查询为只读且调用方不缓存跨域结果（架构案 3.3 第 5 项、8.2 第 3 条）。
后置条件：返回内容不携带写入口；调用方不得缓存结果作为来源状态（架构案 4.2、8.2 第 3 条）。
副作用：无。
异常情况：实例已销毁或标识不可解析；容器组件未挂载；场合标识与当前阶段不一致；嵌套深度超过许可时报出不可识别（见 REQ-ITEM-02）；请求写入（拒绝）。

### API-ITEM-003 容器操作提交

职责：受理容器界面交互操作的物品侧部分，完成物品侧校验、变更集组装并提交落库。
输入：参数输入：操作标识（ITEM-UI-001 至 ITEM-UI-009、ITEM-CTN-001、ITEM-CTN-002）、来源与目标载体及格位、数量、确认标记；状态输入：实例存续状态、容器存取状态、归属引用；数据输入：CLS-ITEM-001、CLS-ITEM-004、CLS-ITEM-007；外部事件输入：无。
读取：CLS-ITEM-005 至 CLS-ITEM-009。
输出：返回值：操作结果与失败原因；状态输出：操作受理状态转换，归属、格位与堆叠数量按变更集变化；事件输出：无（域级事件经订阅 物品变更提交 后发布）；外部系统调用：API-M09-005 物品变更提交。
产生的状态变化：来源格数量清零或按数量扣减、目标格数量增加或交换、悬挂数量变化；整笔回滚时不产生任何状态变化。
前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；操作标识在物品操作总表登记范围内；来源与目标载体可解析；预检通过，或需要确认的确认项已确认；阶段不在结算阶段。
后置条件：变更集整笔提交，提交成功或整笔回滚，不产生部分提交。
副作用：提交成功后按 7.2 发布 物品归属变化、容器内容变化；被拒绝与回滚项经日志服务记录。
异常情况：来源格为空或数量不足；目标容器允许内容约束不接受该词条；容量不足；悬挂物品无法完整放入目标格；操作标识未登记（对应 ITEM-TBD-001 的待补充范围）；写入服务不可用；结算阶段提交（拒绝）。

### API-ITEM-004 装备与卸下提交

职责：受理装备与卸下的物品侧部分，校验槽位适配声明与目标载体可接收性，组装归属与效果变更并提交落库。
输入：参数输入：操作标识（ITEM-EQP-001、ITEM-EQP-002）、实例标识、目标槽位声明或目标载体、确认标记；状态输入：实例存续状态、容器状态、装备槽归属；数据输入：CLS-ITEM-001、CLS-ITEM-002、CLS-EQUIP-001 装备槽定义；外部事件输入：无。
读取：CLS-ITEM-005、CLS-ITEM-006、CLS-ITEM-007、CLS-ITEM-008。
输出：返回值：操作结果与失败原因；状态输出：归属在容器格与装备槽之间变化，容器存取状态随之变化、容器调取范围由 05-30 按来源重建（本系统只经 `API-INVENTORY-001` 取数）；事件输出：无（域级事件经订阅 物品变更提交 后发布）；外部系统调用：API-M09-005 提交变更集，并按组件声明的效果标识调用 API-M09-001 效果施加与 API-M09-002 效果移除。
产生的状态变化：装备时实例进入槽位并启用组件效果；卸下时实例与其内容整体回到目标载体、效果移除。
前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；槽位适配声明接受该装备组件；目标载体可接收整件装备；确认项已确认；阶段不在结算阶段。
后置条件：容器内容保持原有格位并随容器一同移动，不被拆离或转存（`05_物品系统设计.md` 3、`30_背包系统设计.md` 5）。
副作用：效果经 M09 施加与移除；提交成功后按 7.2 发布 物品归属变化、容器内容变化；失败项经日志服务记录。
异常情况：槽位不适配；目标载体无法接收整件装备；装备栏在事件内未开放（事件属性配置未声明开放）；写入服务或效果服务不可用；结算阶段提交（拒绝）。

### API-ITEM-005 物品扣除提交

职责：受理物品离开角色的扣除需求（交付、付款、出售与委托交付），返回扣除结果与缺口项。
输入：参数输入：扣除需求（词条标识或元物品标识与数量）、来源范围标识（场合）、关联任务要求、确认标记；状态输入：容器调取范围（经 `API-INVENTORY-001` 取数）、实例与归属；数据输入：CLS-ITEM-001、CLS-ITEM-004；外部事件输入：无。
读取：CLS-ITEM-005 至 CLS-ITEM-008、CLS-ITEM-013 交付检测结果。
输出：返回值：扣除结果（涉及实例清单与实际扣除量）与缺口项；状态输出：数量或归属变化，归零时实例销毁、格位清空；事件输出：无（域级事件经订阅 物品变更提交 后发布）；外部系统调用：API-M09-005 提交变更集。
产生的状态变化：扣除项的归属或数量变化；投掷与丢弃目标为世界掉落点时生成落地物载体。
前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；来源范围按场合规则可识别；扣除需求可满足，或调用方接受部分扣除；满足持续任务要求时离开前提示已确认（F-ITEM-10）；阶段不在结算阶段。
后置条件：整笔扣除一次提交；需求未满足时不产生任何状态变化。
副作用：提交成功后按 7.2 发布 物品归属变化、对象实例创建与销毁；投掷与丢弃生成的落地物属单局状态并随单局存档保存。
异常情况：来源范围内无满足物品；需求不足且不接受部分扣除；落地物载体无法生成时不得提交（ITEM-GEN-002）；关联任务要求未随请求传入（不产生提示项，记内容日志）。

### API-ITEM-006 物品获得受理

职责：受理物品获得的物品侧部分，完成来源合法性与物品侧校验后向 05-30 的自动装载与溢出受理发起请求；未装入部分生成落地物，装入与落地由该受理组装为同一笔领取并一次提交。
输入：参数输入：待获得物品清单、接收角色、来源载体、点位标识、溢出确认结论；状态输入：背包空间与装载顺序（经 05-30 查询）、实例与归属；数据输入：CLS-ITEM-001、CLS-ITEM-007；外部事件输入：无。
读取：CLS-ITEM-005 至 CLS-ITEM-009、自动装载与溢出受理的试算与提交结果（经 `API-INVENTORY-003`）。
输出：返回值：装入量与未装入量、生成落地物的标识；状态输出：待获得→存续并落入背包空间，未装入部分归属改为世界掉落点；事件输出：无（域级事件经订阅 物品变更提交 后发布）；外部系统调用：API-INVENTORY-003 自动装载与溢出受理（由其组装装入项与落地项并经 API-M09-005 一次提交，本系统不重复提交同一笔领取；交易路径下只取试算与写入目标，提交归交易侧）。
产生的状态变化：物品侧受理状态迁移；装入与落地在同一笔领取内由 05-30 一次提交；拾取落地物后载体转为已清空。
前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；来源合法（事件结果产出、物品交换目标、委托结算报酬、购买、世界拾取）；接收角色可解析；需要溢出确认时确认结论已给出；阶段不在结算阶段。
后置条件：未装入部分在事件点位生成落地物；装入与落地在同一笔领取内由 05-30 一次提交，交易路径下并入交易侧同一变更集；取消领取时不产生任何状态变化；本系统不自行组装或提交该笔领取的变更集。
副作用：提交成功后按 7.2 发布 物品归属变化、对象实例创建与销毁、容器内容变化。
异常情况：自动装载能力不可用（拒绝并记日志，不产生部分装入；提交方为 05-30，本系统不代其提交）；点位标识不可解析（拒绝）；溢出未确认（不提交，等待确认结论）；结算阶段获得（拒绝）。

### API-ITEM-007 物品操作预检

职责：在不改变任何状态的前提下给出一项操作的可执行性、失败原因与需要确认项，供界面提示与提交前判定。
输入：参数输入：操作标识、来源与目标载体及格位、数量、关联任务要求；状态输入：实例与归属、容器存取状态；数据输入：CLS-ITEM-001、CLS-ITEM-004、CLS-ITEM-007；外部事件输入：无。
读取：CLS-ITEM-005 至 CLS-ITEM-008。
输出：返回值：预检结果（可执行／不可执行／需确认）与原因、需确认项清单；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；操作标识在物品操作总表登记范围内。
后置条件：不产生状态变化；预检结论不构成提交承诺，提交时按同一判定复核。
副作用：无。
异常情况：操作标识未登记（对应 ITEM-TBD-001 的待补充范围）；标识不可解析；关联任务要求未传入（提示项为空并记内容日志）。

## 5. 内部功能

### 5.1 功能列表

| 功能 | 对外暴露 | 说明 |
| --- | --- | --- |
| 元物品、组件与词条登记 | 部分是（查询经 API-ITEM-001） | 在引擎编辑器内的配置资产与 M04 的对象与组件注册表内登记识别信息、挂载声明与词条，校验标识唯一与表间引用完整；新增组件先登记后使用 |
| 物品池成分维护 | 部分是（查询经 API-ITEM-001） | 按用途词条组织池成分，抽取与选取归消费方 |
| 组件能力与容器内容判定 | 部分是（经 API-ITEM-002） | 按组件类别给出能力与状态，按扩展开关给出可识别结论 |
| 操作前置条件判定 | 部分是（经 API-ITEM-007） | 来源、目标、组件能力、容量与状态限制的逐项判定 |
| 变更集组装与提交 | 否（提交经 API-M09-005） | 按变更类别产出原子变更项，只提交不落库；落库由写入服务按「变更一项一落库」执行，任一项无法完成时整笔回滚 |
| 容器格位与嵌套维护 | 否（经 API-ITEM-003） | 格序、堆叠合并、异类交换与装入受限容器 |
| 归属变更与容器随物移动 | 否（经 API-ITEM-004、API-ITEM-005） | 内容保持格位随容器移动，不拆离、不转存 |
| 装载请求与溢出落地 | 否（经 API-ITEM-006） | 调用 05-30 的自动装载，并按结果生成落地物 |
| 交付与付款检测 | 否（经 API-ITEM-005） | 需求匹配、来源范围检测与缺口项输出 |
| 任务关联离开提示 | 部分是（经 API-ITEM-007 的需确认项） | 按 05-20 的任务要求产生确认项 |
| 效果联动与派生项重建 | 否 | 按组件声明经 M09 的效果服务施加与移除；容器调取范围与容器识别结果由 05-30 装配，本系统只经 `API-INVENTORY-001` 取数、不重建 |
| 域级事件发布与落地物载体维护 | 否（经订阅 物品变更提交） | 按变更类别发布 M04 的域级事件；落地物生成、维护与清空 |

### 5.2 功能之间的关系

- 初始化序：本单元在初始化序列内按单元装配声明顺序被显式初始化 → 元物品、组件与词条登记 → 组件注册表进入可用 → 物品池成分就绪；登记失败时按架构案 6.1 中止启动过程。
- 受理序：操作前置条件判定 → 变更集组装与提交；预检（API-ITEM-007）只执行第一步，是受理的判定子集。
- 归属序：归属变更与容器随物移动 → 容器格位与嵌套维护 → 通知 05-30 重建容器调取范围与容器识别结果；本系统不自建该派生项，只经 `API-INVENTORY-001` 取数。
- 获得序：装载请求与溢出落地 → 生成落地物载体 → 由 05-30 的自动装载与溢出受理组装并提交；装入与落地在同一变更集内，本系统只做物品侧受理与校验。
- 交易序：交付与付款检测 → 扣除与获得项组装为同一变更集 → 变更集组装与提交；整笔失败时全部变更项作废。
- 事件序：提交返回成功 → 写入服务发布 物品变更提交 → 域级事件发布 → 订阅方按新状态刷新；读档时由 存档恢复完成 驱动派生项重建。
- 效果序：归属变更 → 效果联动 → 效果经 API-M09-001 或 API-M09-002 施加或移除；本系统不实现效果叠加（架构案 3.4 第 8 项）。
- 间接关系：任务关联离开提示由 API-ITEM-007 的需确认项与 API-ITEM-005 的提交前判定间接产生；投掷资格取数经 API-ITEM-002 间接提供，判定归 M05。

### 6.4 使用方式

- 初始化阶段：常驻对象由常驻场景承载，由启动物体按单元装配声明顺序显式初始化本单元并注入相互引用；本单元在初始化时经 API-M01-003 从引擎编辑器内的配置资产读取静态定义并建立组件注册表，经 API-M01-010、API-M01-011、API-M01-012 获得日志与事件分发能力，并显式复位自身状态；经 API-SAVE-001 登记单局状态域切面（架构案 2.4.1、6.1 阶段 3、8.3 第 1 条、8.6 第 4、5 条）。
- 运行期只读取数：跨系统取数一律经 API-ITEM-001 与 API-ITEM-002 直接调用，返回只读视图，调用方不得缓存结果（架构案 4.2）。
- 运行期写入：需要物品侧判定的操作经 API-ITEM-003 至 API-ITEM-006 受理，校验与变更集组装在本系统内完成，落库一律经 API-M09-005 直接调用，写入服务按「变更一项一落库」执行、任一项无法完成时整笔回滚；写入服务不反向调用本系统（架构案 3.4 第 12 项、9.5.7）。
- 效果联动：装备、卸下与容器归属变化时，按组件声明的效果标识直接调用 API-M09-001 与 API-M09-002；效果语义由 06-60 与 06-70 给出，本系统不解释、不叠加。
- 事件间接获得：物品变更提交、存档恢复完成与配置加载完成经 API-M01-012 订阅获得；域级事件经 API-M01-011 发布；本系统不轮询他方状态。
- 同模块与定义引用：05-10、05-20、05-30、06-60 与 06-70 属 M04，其对象在同模块内取用；06-80 与 06-90 属 M05（架构案 2.3），按只读依赖取用本系统的对象与组件能力；事件侧需求、点位标识与投掷组件契约只作为定义引用与调用方参数进入。

### 6.5 依赖方向限制

分层与模块是架构案的**描述性分类**，不承担数据隔离、交互隔离与依赖方向约束职责（架构案 1.6）。本节只用于阅读导航：列出本单元实际依赖的模块与方向，以及仍然成立的少量硬规则。调用是否合法的判据是架构案 3.3 的允许清单、3.4 的禁止清单与 8.1 的依赖方向规则；**同层只读查询按 3.3 第 5 项的通则成立，不需要逐条登记、不需要逐条例外申报**（架构案 8.1、8.2）。

- 被依赖方向：M05 读取本系统的组件能力与容器内容（架构案 3.3 第 6 项）；M06 读取本系统的物品归属（第 7 项）；M08 只读查询定义与实例，并只经意图与命令提交操作（第 1 项、8.4 第 5 条）；全体模块只读查询物品定义与实例（第 5 项通则、第 8 项）。
- 依赖方向：本单元向 M01 取静态配置、日志与事件分发（架构案 3.3 第 9、10 项）；向 M09 提交物品变更与效果并经其统一入口落库（第 8 项）；向同一主模块 M04 内的 05-10、05-20、05-30 与 06-60、06-70、06-80 取数或发起受理（第 5 项通则）。
- 硬规则：
  1. 不写入他方数据、不持有对方的可变引用；跨域变更经持有方入口（架构案 3.4 第 5 项、8.2）。
  2. 不绕过统一入口：物品状态变化一律经 M09 的物品写入服务，效果与条件判定一律经 M09 的服务；存档、随机源、世界时间、资源、场景、输入与日志一律经各自统一入口（架构案 3.4 第 6 至 10 项、第 7 章）。
  3. 基础设施不依赖任何具体玩法系统（架构案 3.4 第 11 项）；本系统不引用 M08 的任何界面对象，界面不得持有物品状态的权威副本（第 1、2、14 项）。
  4. 不形成循环依赖；跨模块状态广播走事件通道（架构案 3.4 第 12 项、8.4 第 1 条）。
  5. 不使用系统基础库的随机源、不在游戏状态判定中使用帧时间、不依赖引擎的退出回调完成存档或收尾（架构案 3.4 第 15 至 17 项）。
  6. 不重复实现引擎已提供的能力（架构案 7.12、8.6 第 1 条）。
- 不发起清单外的查询：本系统不查询 M02 的事件状态、M03 的区域与点位、M06 的跨局数据与 M07 的队伍状态；事件交付区载体标识与点位标识随调用方参数进入，其有效性由调用方与写入服务的引用完整性校验给出（架构案 8.1）。
- 提交链的分工：物品侧规则的校验方是本系统，按「变更一项一落库」执行与整笔回滚的执行方是 M09 的物品写入服务，两者之间不存在反向调用，因此校验必须发生在提交之前（见 REQ-ITEM-03）。

域级事件一律在收到 物品变更提交 之后按变更类别发布，同一提交标识只发布一次对应类别的事件；由其他模块（如 M05 战斗内扣减）按变更类别直接提交的变更同样经此路径产生域级事件。

跨模块事件的契约以**类型契约**的形式确定：登记事件名、唯一发布方、载荷字段类别与失败语义；登记表以可检视的资产承载、按**即用即定**登记（需要新事件时直接在登记表补一行，不设审批、编号申领或版本流程）。契约的强制方式是**一条对账测试**：测试遍历代码中的全部事件发布点并与登记表逐项比对，出现未登记事件即测试失败（架构案 4.3、7.6、8.4 第 2 条、8.6 第 10 条）。本表「订阅」方向的行是本系统消费的他方事件，「发布」方向的行是本系统登记并发布的域级事件；**事件名不在契约登记表内属于契约缺口，由对账测试在测试期发现，不在运行期拦截**；载荷字段落在该事件的契约字段类别内方予发布（架构案 7.6、8.4 第 2 条）。

## 10. 实现约束

### 10.1 实现约束条目

- 物品状态变化只能经 API-M09-005 提交：**任何模块不得绕过 M09 的物品写入服务改物品状态**，写入服务按「变更一项一落库」执行、任一项无法完成时整笔回滚；本系统不落库、不自行序列化状态、不直接改数据域内容（架构案 3.4 第 7 项、7.11、9.5.7、7.1）。
- 变更类别的语义与必需字段类别由本系统登记；载荷封装与落库执行由写入服务定义；其他模块直接提交时只能使用本系统登记过的变更类别。
- 变更集必须整笔提交；提交前必须完成物品侧判定，提交后不接受部分生效。
- 元物品定义与物品实例必须分离，实例只以标识引用元物品；运行期不得修改配置资产。运行期配置的权威载体是**引擎编辑器内的配置资产**；设计库的 `05_物品词条表.csv`、`05_商人原型配置表.csv`、`05_物品操作总表.csv` 是**初始素材与迁移来源**，用于设计评审与对照，**程序侧不直接读表**，内容侧不直接改运行期资产（架构案 5.1、7.9、8.6 第 10 条；设计决策记录决策 93）。
- 未在 M04 的对象与组件注册表登记的组件不得挂载、不得生效；**新增组件必须先经该注册表登记**，元对象定义与组件定义都是配置资产；物品词条、商人原型、投掷组件等跨系统引用项新增时仍须在引用方登记（架构案 5.1、7.11、8.5.4）。
- 物品实例、组件运行状态、容器状态、归属引用与落地物载体必须可序列化，并纳入单局状态域切面；存档序列化采用**判别字段式多态序列化**：序列化结果中只出现**自定义的字符串判别值**，**不写入运行时类型名**，且不得使用已被运行时移除实现的二进制序列化机制（架构案 7.1、8.6 第 8 条）。
- 派生项不入档，只由来源方按来源状态重建；容器调取范围与容器识别结果的来源方是 05-30，本系统只读取数；不得按派生结果反推来源状态（架构案 8.2 第 3 条）。
- 查询接口一律返回只读视图，不携带写入口；调用方不得缓存查询结果。
- 效果一律经 M09 的效果服务施加与移除，条件判定一律经 M09 的条件求值服务，本系统不得自行实现（架构案 3.4 第 8 项、7.11）。
- 结算阶段不接受创建或销毁单局状态域实例的请求（架构案 8.3 第 5 条）；单局状态域在跨局写入提交完成、进入局外阶段时释放，开新局时三个数据域全部重建（架构案 5.2、6.6、8.3 第 3 条；变更 J）。
- 常驻对象由常驻场景承载，由启动物体按单元装配声明顺序显式初始化并注入相互引用；任何模块不得自行创建常驻单元实例，也不得静态单例就地取用其他单元（架构案 2.4.1、6.1、8.3 第 1 条、7.11）。
- 跨模块事件的契约以类型契约的形式确定，并由**一条对账测试**在测试期强制；本系统发布的域级事件必须先登记事件名、唯一发布方与载荷字段类别，**受理侧不做运行期登记校验**（架构案 4.3、7.6、8.4 第 2 条）。
- 临时运行对象不得跨帧保留、不得入档；操作被拒绝时不得留下任何中间状态；拒绝、回滚与内容问题一律经日志服务记录（架构案 7.7）。

### 10.2 实现要求

- I-ITEM-01 物品状态变化必须经 API-M09-005 提交：写入服务按「变更一项一落库」执行，任一项无法完成时整笔回滚；任何模块不得绕过 M09 的物品写入服务改物品状态；本系统不得自行落库或序列化状态（架构案 3.4 第 7 项、7.11、9.5.7）。
- I-ITEM-02 元物品定义与物品实例必须分离，实例以标识引用元物品；运行期不得修改配置资产（架构案 5.1、7.9）。
- I-ITEM-03 组件必须先经 M04 的对象与组件注册表登记、词条必须先经词条定义与物品池登记，方可挂载与生效；元对象定义与组件定义都是配置资产（架构案 5.1、7.11、8.5.4）。
- I-ITEM-04 物品实例、组件运行状态、容器状态、归属引用与落地物载体必须可序列化并登记单局状态域切面；存档序列化采用**判别字段式多态序列化**，序列化结果中只出现自定义的字符串判别值、不写入运行时类型名，多态类型按判别值映射，且不得使用已被运行时移除实现的二进制序列化机制（架构案 7.1、8.6 第 8 条）。
- I-ITEM-05 派生项（容器调取范围与容器识别结果、价值评估、同名遗物效果、投掷折算）不入档；其中容器调取范围与容器识别结果由 05-30 装配，本系统经 `API-INVENTORY-001` 只读取数，其余按来源重建。
- I-ITEM-06 变更集必须整笔提交，部分失败时整笔回滚，不产生部分提交。
- I-ITEM-07 效果必须经 API-M09-001、API-M09-002 施加与移除，条件判定必须经 API-M09-004，本系统不得自行实现。
- I-ITEM-08 容器内容必须随容器整体移动，任何操作不得在无显式规则时拆离或转存内容。
- I-ITEM-09 结算阶段不得受理创建、销毁与投掷丢弃请求；单局状态域在跨局写入提交完成、进入局外阶段时释放，开新局时三个数据域全部重建（架构案 5.2、6.6、8.3 第 3、5 条）。
- I-ITEM-10 查询接口必须返回只读视图，且不得被调用方缓存为来源状态。
- I-ITEM-11 本系统不得创建随机源；候选集只按物品去重后提供，抽取由消费方经 API-M01-004 申请。
- I-ITEM-12 临时运行对象不得跨帧保留、不得入档。
- I-ITEM-13 常驻对象由常驻场景承载：常驻场景是专门承载常驻对象的场景，启动阶段最先加载并全程保留，不参与阶段切换、不作为界面承载、不被卸载；常驻对象只能由启动物体按单元装配声明顺序显式初始化并注入相互引用，任何模块不得自行创建常驻单元实例，也不得静态单例就地取用其他单元（架构案 2.4.1、6.1、6.2.1、7.3、7.11、8.3 第 1 条）。
