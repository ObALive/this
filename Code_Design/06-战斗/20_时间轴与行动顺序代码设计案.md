本单元 ID：`SYS-TIMELINE-001` 时间轴与行动顺序。本单元是 M05 战斗的成员系统（架构案 2.3、3.1 ARC-M05-001），层级 L3；战斗的启动、轮次循环与收束由 M10 的战斗执行器编排（`API-M10-004`），本系统提供被其编排调用的时间轴与轮次能力。

---

## 1. 系统定义

### 1.1 系统目的

战斗节奏的驱动源：以单条时间轴（术语表 T-117）决定敌我全部参战单位的行动顺序，以行动轻重决定下一次行动时机，并把战斗轮次（术语表 T-120）确立为操作提交边界与自动保存节点之一。本系统同时定义战斗内时间推进的口径，使战斗耗时成为可存档、可回填日程的结果。

### 1.2 系统职责

- 持有并推进单条战斗时间轴：敌我全部参战单位在同一时间轴上按标记排布，推进到某单位的标记时该单位获得一次行动机会（术语表 T-118）（06-20 §3.1）。
- 定义并判定战斗轮次：起点是该单位获得行动机会的时刻，终点是该单位行动结束并完成下一次行动时机计算的时刻（06-20 §3.2）。
- 产出轮次边界判定结果，作为 M05 的 轮次推进 事件与自动保存节点（战斗轮次推进）的判定依据（架构案 5.3、01-50 §6）。
- 求值并写回下一次行动时机：按行为后摇（术语表 T-119）、技能后摇与行动速度补正三类输入的来源口径给出结果（06-20 §3.1）。
- 维护行动机会的时机侧状态：归属单位、轮次序号、开放次序与确认结果；该次机会的可用行为集合归 06-85 战斗行为系统。
- 定义战斗内时间推进口径并给出战斗内时长增量：每累计十分钟推进一个时间段（术语表 T-002）；结束时不足一个时间段的余量向上对齐到下一时间段边界；时长增量按登记的消费点写入战斗净时长账（06-20 §3.3、02-10）。
- 提供时间轴预览：未来若干次行动机会的归属单位序列与本单位的预计时机，以及某个待执行行为执行后本单位的下一次行动时机（06-20 §3.5）。
- 登记预测结果与实际执行结果之间可能产生偏差的来源，控制预览的可接受范围（06-20 §4）。
- 维护单位标记的增补与移除，支持后续波次在既有战斗内刷新而不重置时间轴（06-90 §3）。
- 声明时间轴的可持久化切面并支持读档重建，恢复到最近一次行动机会开始的时刻（架构案 5.2.2、9.3）。
- 维护本系统拥有的数据对象、对外接口与登记装配。

### 1.3 系统边界

本系统不负责：

- 战斗的启动、轮次循环与收束的执行编排：归 M10 的战斗执行器（`API-M10-004`、`API-M10-010`）；本系统只提供被其编排调用的能力（架构案 2.4、3.1 ARC-M05-001）。
- 战斗实例的建立与释放、参战编成、战场装配与初始站位、布置阶段（术语表 T-121）的阶段推进：归 M05 的模块级装配路径与 06-30 战场与战棋规则。
- 可用行为集合的给出、行为的字母追加与资源消耗：归 06-85 战斗行为系统与 06-50 行动槽与连携（术语表 T-139）；本系统只给出时机侧结果。
- 行为的可用性判定与前置条件（射程、地形、成本串（术语表 T-142）、库存与法术书内容）：归发起系统与 06-30、06-50、06-80；行动条件不满足时不提交、不消耗行动机会，本系统不推进时间轴（06-20 §4）。
- 技能效果、伤害与单位状态（术语表 T-113）判定：归 06-40、06-80、06-10 与 M09；本系统不实现效果叠加，也不实现条件判定。
- 战斗结果标识与达成目标清单的产出、全队失去行动能力的判定：归 06-A0 与 06-10（`API-BATTLE-005`）；本系统只受理收束后的时间轴处置。
- 世界时间（术语表 T-015）的持有与推进：唯一受理入口是 `API-M01-005`，且只在事件退出时由 M10 提交；本系统只提供战斗内时长增量与推进口径（架构案 7.5、3.4 第 10 项）。
- 战斗净时长账的结算与取整对齐执行：归 02-10 时间机制（`API-TIME-004`）与 M05 的净时长累计与对齐（`API-M05-105`）；本系统提供口径与增量。
- 自动保存的提交：提交点由存档侧按 01-50 §4.1 的登记在 轮次推进 后经 `API-SAVE-002` 执行；触发请求由 M10 的战斗执行器在收到该事件后下发（M05 侧记作「自动保存由 M10 触发」，两处口径统一为「M10 下发触发请求、存档服务执行提交」），本系统既不下发触发请求也不执行提交、不自行序列化状态、不读写存档（架构案 7.1、3.4 第 6 项）。
- 时间轴界面的绘制、布局、悬浮预览的交互规格与显示次数上限的取值：归 M08 与界面设计阶段（06-20 §3.5）。
- 敌方行为模板与破招时点、敌方撤退判定：归 06-90 敌人与AI；连携释放条件与移动打断规则：归 06-50。
- 队伍编制的来源与重置：归 M07（01-40）；技能与行为的内容清单与后摇数值：归内容与数值设计。

## 3. 状态定义

### 3.1 状态

| 状态集 | 取值 | 说明 |
| --- | --- | --- |
| 时间轴（`CLS-TIMELINE-001`） | 未排布／已排布／推进中／已冻结 | 未排布表示战斗已启动但标记尚未建立；已冻结表示行动机会关闭且推进停止 |
| 时间轴标记（`CLS-TIMELINE-002`） | 在场待行动／机会开放／机会已确认／已跳过／已移除 | 已跳过表示该标记被推进到但不产生可执行行为（口径待上游补充，REQ-TIMELINE-02） |
| 行动机会（`CLS-TIMELINE-003`） | 等待／机会开放／已确认 | 与 M05 §3.1 登记的单位行动机会状态同名同义；一次行动机会内只执行一项行为；机会序号为该次机会的对外键，与 06-85、M05 使用的「行动机会序号」为同一字段 |
| 时机输入登记（`CLS-TIMELINE-004`） | 未装配／已装配／校验不通过 | 三类输入来源必须齐全，任一来源未登记即校验不通过 |
| 时间推进口径登记（`CLS-TIMELINE-006`） | 未装配／已装配／校验不通过 | 校验项为刻度引用、取整语义与消费点标识齐备 |
| 偏差来源登记（`CLS-TIMELINE-008`） | 未装配／已装配／待补充 | 待补充表示来源清单尚未由上游给出（REQ-TIMELINE-04） |
| 轮次边界判定结果（`CLS-TIMELINE-007`） | 构成轮次起点／不构成轮次起点 | 只有构成轮次起点才对应一次自动保存节点 |

### 3.2 状态转换

```
时间轴：未排布 → 已排布 → 推进中 → 已冻结 → 未排布（随战斗实例释放）
时间轴：未排布 →（排布失败）不转换，保持未排布，不建立标记集合
标记：  在场待行动 → 机会开放 → 机会已确认 → 在场待行动
标记：  在场待行动 → 已跳过 → 在场待行动
标记：  在场待行动 → 已移除
行动机会：等待 → 机会开放 → 已确认 → 等待
行动机会：等待 → 等待（未确认或取消，不产生状态变化）
时机输入登记／时间推进口径登记：未装配 → 已装配 ／ 未装配 → 校验不通过
偏差来源登记：未装配 → 已装配 ／ 未装配 → 待补充
轮次边界判定结果：构成轮次起点 ／ 不构成轮次起点
```

### 3.3 状态转换触发条件

| 转换 | 触发条件 | 经接口或事件 | 与 4.1 的状态变化一致 |
| --- | --- | --- | --- |
| 时间轴 未排布 → 已排布 | M05 的装配路径受理战斗启动请求后调用 | `API-TIMELINE-001`（内部经 `API-TIMELINE-101`） | 标记集合建立；时间轴进入已排布 |
| 时间轴 排布失败（保持未排布，不产生转换） | 参战单位清单为空、单位标识重复或初始排布输入缺失 | `API-TIMELINE-001` | 不建立标记集合；时间轴保持未排布；登记原因；战斗启动被拒绝 |
| 时间轴 已排布 → 推进中 | 首次调用推进接口并成功开启首个行动机会 | `API-TIMELINE-003`（内部经 `API-TIMELINE-102`） | 推进位置落到归属单位标记 |
| 时间轴 推进中 → 已冻结 | M05 的收束编排受理战斗结果后调用 | `API-TIMELINE-009`（结束方式为常规或全队失去行动能力）；撤退方式下保持已排布且保留标记（架构案 9.5.4） | 行动机会关闭；推进停止 |
| 时间轴 已冻结 → 未排布 | 收尾窗口结束并完成事件退出，或读档丢弃未结状态 | `API-M10-002`（起因＝窗口结束）或恢复流程 | 时间轴随战斗实例释放 |
| 标记 在场待行动 → 机会开放 | 推进到该标记 | `API-TIMELINE-003` | 该标记成为当前行动机会的归属 |
| 标记 机会开放 → 机会已确认 | 该单位的行为确认提交并完成时机写回 | `API-TIMELINE-004`（内部经 `API-TIMELINE-104`） | 标记写回新位置；行动机会用尽 |
| 标记 机会开放 → 在场待行动（未确认） | 玩家取消或未确认选择 | 无接口调用 | 不产生任何状态变化；时间轴不推进（06-85 §3.4） |
| 标记 在场待行动 → 已跳过 | 推进到该标记而单位处于不可行动状态 | `API-TIMELINE-003`（依据 `API-BATTLE-003`） | 不开启行动机会；是否计入轮次与保存节点待上游补充（REQ-TIMELINE-02） |
| 标记 在场待行动 → 已移除 | 单位退出参战（含离场），经 M05 的波次与入场路径请求 | `API-TIMELINE-002`（移除口径待上游补充，REQ-TIMELINE-02） | 标记集合减项；其余标记顺序不变 |
| 行动机会 等待 → 机会开放 | 推进成功并选出归属单位 | `API-TIMELINE-003` | 机会归属与轮次序号落定 |
| 行动机会 机会开放 → 已确认 | 行为确认并写回下一次行动时机 | `API-TIMELINE-004` | 机会用尽，等待下一次推进 |
| 行动机会 已确认 → 等待 | 推进到下一个标记 | `API-TIMELINE-003` | 上一条机会记录释放 |
| 登记 未装配 → 已装配 | 订阅 配置加载完成 后装配并校验通过 | `API-TIMELINE-108` | 三项登记可用 |
| 登记 未装配 → 校验不通过／待补充 | 来源字段缺失或偏差来源清单缺失 | `API-TIMELINE-108` | 相应接口按 9 的判定拒绝或降级 |
| 轮次边界判定结果 各取值 | 每次推进由 `API-TIMELINE-105` 判定 | `API-TIMELINE-003` | 构成轮次起点时对应一次自动保存节点（`API-SAVE-002`） |

| API-TIMELINE-009 | CloseAxis 时间轴收束处置 | M05 的收束编排（`API-M05-104`） | 战斗实例标识、结束方式（常规／撤退／全队失去行动能力） | 处置结果 | 行动机会关闭；时间轴：推进中 → 已冻结，撤退方式下保持已排布并保留标记 | 无 |

### 4.2 接口详细定义

#### API-TIMELINE-001 ArrangeAxis 时间轴排布

职责：受理一场战斗的时间轴排布，建立全部参战单位的标记并给出首个行动机会的归属。

输入：
- 参数输入：战斗实例标识、参战单位清单与阵营、初始排布输入（06-20 §3.1 的三类输入中可用于初始排布的部分）。
- 状态输入：阶段取值、参战单位的属性取值与生效值、布置阶段口径。
- 数据输入：属性台账（行动速度）、`CLS-TIMELINE-004` 的三类输入来源登记。
- 外部事件输入：无（由 M05 的装配路径直接调用）。

读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-002`、`CLS-TIMELINE-004`、`CLS-TIMELINE-006`；属性取值（`API-M07-004`）；属性生效值（`API-M09-003`）；阶段取值（`API-M10-001`）。

输出：
- 返回值：排布结果、首个行动机会的归属单位与轮次序号。
- 状态输出：时间轴 未排布 → 已排布；`CLS-TIMELINE-002` 的标记集合建立；`CLS-TIMELINE-003` 建立等待态记录。
- 事件输出：无（战斗开始 由 M05 按其登记发布）。
- 外部系统调用：`API-SAVE-009` 数据域变更提交、`API-M01-010` 日志服务.Write。

产生的状态变化：时间轴与标记集合建立并落库；行动机会处于等待态；世界时间未推进。

前置条件：当前阶段为事件执行阶段，或由 M10 在地图阶段以战斗事件进入的编排点发起；参战单位清单非空且单位标识唯一；三类时机输入来源已装配。

后置条件：全部参战单位在时间轴上有且仅有一个标记；首个行动机会可经 `API-TIMELINE-003` 开启。

副作用：排布结果落库；不通过项经日志服务记录；不发起界面、场景与资源调用。

异常情况：参战单位清单为空或含重复标识；阶段取值不允许；时机输入登记未装配或校验不通过；初始排布口径缺失（REQ-TIMELINE-01）；落库提交被拒绝。

#### API-TIMELINE-002 MaintainUnitMarker 单位标记维护

职责：在既有战斗内增补或移除单位标记，支持后续波次在同一时间轴上刷新。

输入：
- 参数输入：战斗实例标识、单位标识与阵营、操作（增补／移除）。
- 状态输入：时间轴状态、现有标记集合、阶段取值。
- 数据输入：`CLS-TIMELINE-004` 的输入来源登记；敌方波次与行为模板（ENEMY，`CLS-ENEMY-002` 波次配置、`CLS-ENEMY-001` 行为模板）。
- 外部事件输入：无（由 M05 的波次与入场路径直接调用）。

读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-002`、`CLS-TIMELINE-004`；阶段取值（`API-M10-001`）；波次与模板（ENEMY，`API-ENEMY-001` TemplateRegistry.Query 敌方行为模板查询、`API-ENEMY-002` WaveRegistry.Query 波次配置查询）。

输出：
- 返回值：维护结果（增补成功／移除成功／拒绝及原因）。
- 状态输出：标记集合增项或减项；其余标记的相对顺序与进度不变。
- 事件输出：无。
- 外部系统调用：`API-SAVE-009`、`API-M01-010`。

产生的状态变化：时间轴保持推进中；标记集合按操作变化；波次之间不结算、不重置时间轴（06-90 §3）。

前置条件：战斗实例处于进行中；单位标识未在标记集合内（增补）或已存在（移除）；当前阶段允许改变局内状态。

后置条件：增补的单位从该次操作之后的推进开始参与排队；已完成的历史推进不重算。

副作用：落库；拒绝原因经日志服务记录。

异常情况：时间轴未排布或已冻结；单位标识重复增补（幂等拒绝）；对不存在的标记请求移除；阶段为结算阶段；移除口径待上游补充（REQ-TIMELINE-02）。

#### API-TIMELINE-003 OpenNextOpportunity 推进并开放行动机会

职责：把时间轴推进到下一个标记，开启一次行动机会并给出轮次边界判定结果。

输入：
- 参数输入：战斗实例标识。
- 状态输入：时间轴状态、标记集合、单位状态、行动机会状态。
- 数据输入：`CLS-TIMELINE-004` 的输入来源登记、属性台账。
- 外部事件输入：无（由 M05 的轮次推进路径驱动，编排方为 M10 的战斗执行器）。

读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-002`、`CLS-TIMELINE-003`、`CLS-TIMELINE-004`；单位状态（`API-BATTLE-003`）；阶段取值（`API-M10-001`）。

输出：
- 返回值：机会序号、机会归属单位、轮次序号、开放次序、轮次边界判定结果（`CLS-TIMELINE-007`）、预计下一次行动时机。
- 状态输出：时间轴推进到归属单位标记；行动机会 等待 → 机会开放；对应标记置为机会开放。
- 事件输出：无（轮次推进 由 M05 按其登记发布，载荷中的轮次序号与归属单位取自本接口的返回值）。
- 外部系统调用：`API-SAVE-009`、`API-M01-010`。

产生的状态变化：推进位置落到归属单位标记；该单位获得一次行动机会；上一条机会记录释放；世界时间未推进。

前置条件：战斗实例处于进行中；时间轴为已排布或推进中；上一次行动机会已确认或不存在未确认的选择；存在至少一个可行动的标记。

后置条件：归属单位可经 `API-M05-003` 提交唯一一项行为；轮次序号与轮次起点可经 `API-TIMELINE-007` 查询。

副作用：轮次边界判定结果供 M05 发布 轮次推进 使用；该事件的自动保存由 M10 的战斗执行器下发触发请求、由存档侧在收到该事件后经 `API-SAVE-002` 执行提交（01-50 §4.1）；本系统既不触发提交也不下发触发请求。

异常情况：时间轴未排布；战斗实例不存在或已冻结；存在未确认的选择；标记集合为空；阶段为结算阶段；推进到不可行动单位时的处置口径待上游补充（REQ-TIMELINE-02）。

#### API-TIMELINE-004 WriteBackNextTiming 下一次行动时机写回

职责：在行为确认后求值该单位的下一次行动时机并写回其标记，收尾该次行动机会与轮次。

输入：
- 参数输入：战斗实例标识、行动者标识、行为或技能标识、该次行动的时机输入（行为后摇来源、技能后摇来源、行动速度补正来源标识）。
- 状态输入：行动机会归属与状态、标记集合、单位状态、阶段取值。
- 数据输入：`CLS-TIMELINE-004`、`CLS-TIMELINE-006`；行为契约的时间与后摇字段（BATTLEACT，`CLS-BATTLEACT-002` 战斗行为表）；技能后摇参数（SKILL，`CLS-SKILL-001` 技能定义）。
- 外部事件输入：无（由 M05 的行为提交路径直接调用）。

读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-002`、`CLS-TIMELINE-003`、`CLS-TIMELINE-004`、`CLS-TIMELINE-006`；属性取值（`API-M07-004`）；属性生效值（`API-M09-003`）；阶段取值（`API-M10-001`）。

输出：
- 返回值：写回结果与下一次行动时机。
- 状态输出：该单位标记更新为新位置；行动机会 机会开放 → 已确认 → 等待；轮次结束。
- 事件输出：无（行为提交完成 由 M05 按其登记发布）。
- 外部系统调用：`API-TIME-003` 记录战斗内时长增量（消费点「战斗净时长」）、`API-SAVE-009`、`API-M01-010`。

产生的状态变化：标记写回；行动机会用尽；战斗净时长账按登记的消费点增长；世界时间未推进。

前置条件：行动者是当前行动机会的归属单位；该次行为已确认提交；行为或技能的时机输入来源已登记；战斗实例处于进行中。

后置条件：时间轴上该单位的下一次行动时机已确定；轮次已收尾，可经 `API-TIMELINE-003` 推进到下一个标记。

副作用：时长增量经 `API-TIME-003` 写入战斗净时长账；写回后立即落库并在下一次自动保存节点写入存档。

异常情况：非当前行动者写回；该次机会已确认（重复写回幂等拒绝）；行为或技能未登记时机输入（REQ-TIMELINE-03）；属性取值或生效值不可读；阶段为结算阶段；落库被拒绝。

#### API-TIMELINE-005 QueryAxis 时间轴查询

职责：返回时间轴的只读预览：未来若干次行动机会的归属单位序列、本单位的预计时机与当前机会归属。

输入：
- 参数输入：战斗实例标识、查询范围（未来次数上限）。
- 状态输入：时间轴状态、标记集合、当前行动机会。
- 数据输入：`CLS-TIMELINE-004`、`CLS-TIMELINE-008`。
- 外部事件输入：无。

读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-002`、`CLS-TIMELINE-003`、`CLS-TIMELINE-004`、`CLS-TIMELINE-008`。

输出：
- 返回值：未来若干次行动机会的归属单位序列、本单位的预计时机、当前机会归属与状态、偏差来源标记。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：无。

产生的状态变化：无（`CLS-TIMELINE-005` 为临时运行对象，不改变来源状态）。

前置条件：战斗实例存在且时间轴已排布；查询范围不超过配置限定的未来次数上限。

后置条件：返回值为只读快照，不携带写入口；读取方不得把预览缓存为自身数据来源（架构案 4.4、8.2 第 3 条）。

副作用：无。

异常情况：时间轴未排布或战斗实例不存在；查询范围超过上限（按上限截断并登记，REQ-TIMELINE-05）；读取方为 L5 表现层（应经 `API-M05-005` 取数）。

#### API-TIMELINE-006 PreviewAfterAction 行动后时机预览

职责：对某个待执行的行为或技能给出执行后本单位的下一次行动时机，使后摇代价在出手前可见。

输入：
- 参数输入：战斗实例标识、行动者标识、待评估的行为或技能标识。
- 状态输入：标记集合、当前行动机会、行动者属性取值与生效值。
- 数据输入：`CLS-TIMELINE-004`、`CLS-TIMELINE-008`；行为契约的时间与后摇字段（BATTLEACT，`CLS-BATTLEACT-002` 战斗行为表）；技能后摇参数（SKILL，`CLS-SKILL-001` 技能定义）。
- 外部事件输入：无。

读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-002`、`CLS-TIMELINE-004`、`CLS-TIMELINE-008`；属性取值（`API-M07-004`）；属性生效值（`API-M09-003`）。

输出：
- 返回值：该行动执行后本单位的下一次行动时机在时间轴上的位置、时机增量、偏差来源标记。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：无。

产生的状态变化：无；不占用行动机会、不写回标记、不追加行动槽字母。

前置条件：行动者存在且拥有当前或可预期的一次行动机会；行为或技能的时机输入来源已登记。

后置条件：预览结果与 `API-TIMELINE-004` 的求值使用同一份来源登记；预览不构成提交，不产生任何状态变化（06-85 §3.4）。

副作用：无。

异常情况：行为或技能未登记时机输入（REQ-TIMELINE-03）；偏差来源登记待补充（REQ-TIMELINE-04）；行动者不可行动；非当前行动者的预览请求（按只读预览受理，不改变可操作性）。

#### API-TIMELINE-007 QueryRoundState 轮次状态查询

职责：返回当前轮次序号、轮次起点、当前行动机会的归属与状态，供编排与存档侧核对轮次节点。

输入：
- 参数输入：战斗实例标识。
- 状态输入：时间轴状态、`CLS-TIMELINE-003` 的当前记录。
- 数据输入：无。
- 外部事件输入：无。

读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-003`、`CLS-TIMELINE-007`。

输出：
- 返回值：轮次序号、轮次起点、当前机会序号与归属、当前机会状态、是否处于轮次起点。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：无。

产生的状态变化：无。

前置条件：战斗实例存在且时间轴已排布。

后置条件：返回值与该时刻已提交的推进结果一致；不返回未确认的选择。

副作用：无。

异常情况：战斗实例不存在；时间轴未排布；读档恢复期间查询（返回恢复后的记录或未就绪结论）。

#### API-TIMELINE-008 QueryBattleTimeAdvance 战斗内时间推进查询

职责：返回战斗内时间推进口径与该场战斗已占用的时长，供净时长累计与对齐以及时长呈现取数。

输入：
- 参数输入：战斗实例标识。
- 状态输入：`CLS-TIMELINE-006` 的装配状态、时长增量累计。
- 数据输入：`CLS-TIMELINE-006`；时间段刻度（TIME，`API-TIME-001`）。
- 外部事件输入：无。

读取：`CLS-TIMELINE-006`；时间段刻度（`API-TIME-001`）。

输出：
- 返回值：推进口径（每累计十分钟推进一个时间段、结束余量向上对齐到下一时间段边界）、战斗已占用时长、已写入的时长增量合计。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：无。

产生的状态变化：无。

前置条件：`CLS-TIMELINE-006` 已装配；战斗实例存在。

后置条件：返回值只提供口径与已占用时长；时间段数量的换算与退出时的推进分别由 M05 的净时长对齐（`API-M05-105`）与 02-10 的退出结算（`API-TIME-004`）执行。

副作用：无。

异常情况：口径登记未装配或校验不通过；时长增量计量口径待上游补充（REQ-TIMELINE-06）；战斗实例不存在。

#### API-TIMELINE-009 CloseAxis 时间轴收束处置

职责：在战斗收束后关闭行动机会并对时间轴做冻结或保留处置。

输入：
- 参数输入：战斗实例标识、结束方式（常规／撤退／全队失去行动能力）。
- 状态输入：时间轴状态、当前行动机会状态。
- 数据输入：无。
- 外部事件输入：无（由 M05 的收束编排直接调用）。

读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-003`；战斗结果标识与结束方式（BATTLEGOAL，`CLS-BATTLEGOAL-004` 战斗结果）。

输出：
- 返回值：处置结果。
- 状态输出：行动机会关闭；时间轴 推进中 → 已冻结；撤退方式下时间轴保持已排布并连同敌方状态与位置保留（架构案 9.5.4）。
- 事件输出：无（战斗结束、撤退发生 由 M05 按其登记发布）。
- 外部系统调用：`API-SAVE-009`、`API-M01-010`。

产生的状态变化：停止开启行动机会；时间轴推进停止；标记集合按结束方式保留或随战斗实例释放。

前置条件：战斗已产出结果标识或已受理撤退；战斗实例处于收束中。

后置条件：`API-TIMELINE-003` 与 `API-TIMELINE-004` 在本场战斗内拒绝受理；收尾窗口内不消耗行动机会、不推进世界时间。

副作用：处置结果落库；拒绝原因经日志服务记录。

异常情况：重复收束处置（幂等拒绝）；结束方式缺失；收尾窗口结束后仍收到推进请求（拒绝）。

### 5.2 内部功能契约

#### API-TIMELINE-101 ArrangeMarkers 标记排布与增补

职责：建立、增补与移除参战单位的时间轴标记。输入：参数输入：单位标识集合、阵营、操作；状态输入：时间轴状态；数据输入：`CLS-TIMELINE-004`；外部事件输入：无。读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-002`、`CLS-TIMELINE-004`；属性取值（`API-M07-004`）。输出：返回值：排布或维护结果；状态输出：标记集合变化；事件输出：无；外部系统调用：`API-SAVE-009`。产生的状态变化：标记建立、增补或移除，其余标记相对顺序不变。前置条件：战斗实例处于装配中或进行中；单位标识合法且不重复。后置条件：每个参战单位在时间轴上有且仅有一个标记。副作用：结果落库。异常情况：初始排布口径缺失（REQ-TIMELINE-01）；空集合；重复标识；移除口径未定（REQ-TIMELINE-02）。

#### API-TIMELINE-102 AdvanceToMarker 推进到下一标记

职责：按标记集合把推进位置移到下一个待行动标记并给出归属单位。输入：参数输入：战斗实例标识；状态输入：时间轴状态、标记状态、单位状态；数据输入：无；外部事件输入：无。读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-002`；单位状态（`API-BATTLE-003`）。输出：返回值：归属单位或无可行动单位的结论；状态输出：推进位置更新；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：推进位置落到归属单位标记；不可行动标记按登记的处置跳过或开启机会。前置条件：时间轴为已排布或推进中；不存在未确认的选择。后置条件：归属单位确定，可进入机会开启。副作用：跳过与拒绝经日志服务记录。异常情况：时间轴未排布或已冻结；标记集合为空；不可行动标记的处置口径缺失（REQ-TIMELINE-02）。

#### API-TIMELINE-103 EvaluateNextTiming 下一次行动时机求值

职责：按行为后摇、技能后摇与行动速度补正三类输入的来源登记求值下一次行动时机与时长增量。输入：参数输入：行动者标识、行为或技能标识、时机输入；状态输入：标记集合、属性取值与生效值；数据输入：`CLS-TIMELINE-004`、行为契约的时间与后摇字段（BATTLEACT，`CLS-BATTLEACT-002` 战斗行为表）、技能后摇参数（SKILL，`CLS-SKILL-001` 技能定义）；外部事件输入：无。读取：`CLS-TIMELINE-002`、`CLS-TIMELINE-004`；属性取值（`API-M07-004`）；属性生效值（`API-M09-003`）。输出：返回值：下一次行动时机与时长增量；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无（只求值，不写回）。前置条件：三类输入来源均已登记；行动者属性取值可读。后置条件：求值只使用已登记的来源，预览与写回共用同一结果口径。副作用：无。异常情况：来源未登记（REQ-TIMELINE-03）；合成口径与参数载体缺失（REQ-TIMELINE-03）；属性取值或生效值不可读；连携技能的后摇参数缺失。

#### API-TIMELINE-104 WriteBackMarker 标记写回与轮次收尾

职责：把下一次行动时机写回行动者标记并收尾该次行动机会与轮次。输入：参数输入：行动者标识、求值结果；状态输入：行动机会状态、标记集合；数据输入：无；外部事件输入：无。读取：`CLS-TIMELINE-002`、`CLS-TIMELINE-003`。输出：返回值：写回结果；状态输出：标记位置更新；行动机会 机会开放 → 已确认 → 等待；事件输出：无；外部系统调用：`API-SAVE-009`、`API-TIMELINE-107`。产生的状态变化：行动者标记写回新位置；该次机会用尽。前置条件：行动者是当前机会归属单位且行为已确认。后置条件：时间轴可推进到下一个标记；写回结果立即落库。副作用：写回结果参与下一次自动保存节点的落库内容。异常情况：非当前行动者；重复写回（幂等拒绝）；标记缺失；阶段为结算阶段。

#### API-TIMELINE-105 JudgeRoundBoundary 轮次边界判定

职责：判定一次推进是否构成轮次起点并给出轮次序号与归属单位。输入：参数输入：战斗实例标识；状态输入：归属单位、机会状态、轮次序号；数据输入：`CLS-TIMELINE-006`；外部事件输入：无。读取：`CLS-TIMELINE-002`、`CLS-TIMELINE-003`。输出：返回值：`CLS-TIMELINE-007`（构成／不构成轮次起点、轮次序号、轮次起点）；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：推进已完成且归属单位已确定。后置条件：构成轮次起点时，M05 据此发布 轮次推进，存档侧据此提交战斗轮次推进节点的单局存档（架构案 5.3、01-50 §4.1）。副作用：无。异常情况：推进未完成即判定；轮次序号缺失；不可行动标记被跳过时的计数口径缺失（REQ-TIMELINE-02）。

#### API-TIMELINE-106 BuildPreview 预览生成

职责：按查询范围生成未来的归属单位序列与本单位的预计时机，并标注偏差来源。输入：参数输入：战斗实例标识、行动者标识、查询范围或待评估行为标识；状态输入：标记集合、当前机会；数据输入：`CLS-TIMELINE-004`、`CLS-TIMELINE-008`；外部事件输入：无。读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-002`、`CLS-TIMELINE-004`、`CLS-TIMELINE-008`。输出：返回值：`CLS-TIMELINE-005`；状态输出：无；事件输出：无；外部系统调用：`API-TIMELINE-103`（待评估行为的情形）。产生的状态变化：无。前置条件：时间轴已排布。后置条件：预览为只读结果，不占用行动机会、不写回标记。副作用：无。异常情况：查询范围超过配置上限（按上限截断，REQ-TIMELINE-05）；偏差来源登记待补充（REQ-TIMELINE-04）；行为或技能未登记时机输入。

#### API-TIMELINE-107 AccumulateBattleTime 战斗内时长增量写账

职责：按登记的消费点把该次行动的时长增量写入战斗净时长账。输入：参数输入：战斗实例标识、时长增量；状态输入：`CLS-TIMELINE-006` 的装配状态；数据输入：`CLS-TIMELINE-006`；外部事件输入：无。读取：`CLS-TIMELINE-006`；战斗净时长账（TIME，`CLS-TIME-005`）。输出：返回值：受理结果与累计值；状态输出：战斗净时长账增长；事件输出：无；外部系统调用：`API-TIME-003`。产生的状态变化：战斗净时长账按增量增长（记账本体归 02-10，本系统只提交增量）。前置条件：口径登记已装配且消费点已登记；增量取值合法；阶段允许改变局内状态。后置条件：增量与写回结果同源，保证时间轴推进与战斗耗时口径一致。副作用：记账由 02-10 维护，退出时的取整对齐与推进由 `API-TIME-004`、`API-M01-005` 执行。异常情况：消费点未登记；增量为负；口径未装配；计量口径待上游补充（REQ-TIMELINE-06）；记账受理被拒绝。

#### API-TIMELINE-108 BuildRegistrations 登记装配与校验

职责：在配置加载完成后装配三类登记并校验齐备。输入：参数输入：无；状态输入：无；数据输入：`CLS-TIMELINE-004`、`CLS-TIMELINE-006`、`CLS-TIMELINE-008` 的来源字段；外部事件输入：配置加载完成。读取：战斗行为表的时间与后摇字段（BATTLEACT，`CLS-BATTLEACT-002` 战斗行为表）、技能后摇参数（SKILL，`CLS-SKILL-001` 技能定义）、属性台账、时间段刻度（`API-TIME-001`）。输出：返回值：装配结果与不通过项；状态输出：三项登记 未装配 → 已装配 或 校验不通过／待补充；事件输出：无；外部系统调用：`API-M01-003`、`API-M01-010`。产生的状态变化：登记内容就绪。前置条件：配置加载完成 已发布且配置服务可用。后置条件：三类输入来源逐项有登记；偏差来源清单缺失时该项标为待补充。副作用：不通过项经日志服务记录。异常情况：来源字段缺失；口径校验不通过；偏差来源清单未给出（REQ-TIMELINE-04）。

#### API-TIMELINE-109 CollectAndRebuildSlice 切面采集与重建

职责：声明时间轴的可持久化切面内容，并在读档后重建到最近一次行动机会开始的时刻。输入：参数输入：采集范围或恢复范围；状态输入：时间轴状态；数据输入：无；外部事件输入：无（由 M05 的切面重建路径驱动）。读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-002`、`CLS-TIMELINE-003`；存档切面（经 `API-SAVE-008`）。输出：返回值：切面内容或重建结果；状态输出：时间轴与标记集合按记录恢复；事件输出：无；外部系统调用：`API-SAVE-001`（切面声明，经 M05 汇总）、`API-SAVE-008`、`API-M01-010`。产生的状态变化：时间轴与行动机会回到存档记录的时刻；该次行动机会内尚未确认的选择不恢复。前置条件：切面已登记；恢复流程已装载单局状态域切面。后置条件：可经 `API-TIMELINE-003` 继续推进，或时间轴保持已冻结。副作用：本系统不自行序列化状态、不自行读写存档。异常情况：切面缺失或引用完整性校验不通过（按架构案 7.1 的失败语义处理）；时间轴与机会记录不一致（按最近一次行动机会起点重建）。

#### API-TIMELINE-110 FreezeAndRelease 冻结与释放

职责：按结束方式冻结时间轴或释放标记集合。输入：参数输入：结束方式；状态输入：时间轴状态、机会状态；数据输入：无；外部事件输入：无。读取：`CLS-TIMELINE-001`、`CLS-TIMELINE-003`。输出：返回值：处置结果；状态输出：时间轴 推进中 → 已冻结 或保持已排布；事件输出：无；外部系统调用：`API-SAVE-009`。产生的状态变化：行动机会关闭；推进停止。前置条件：战斗已收束并给出结束方式。后置条件：推进与写回接口在本场战斗内拒绝受理。副作用：处置结果落库；撤退情形下标记与敌方状态一并保留。异常情况：重复处置（幂等拒绝）；结束方式缺失；收尾窗口内收到推进请求。

### 5.3 功能之间的关系

- `API-TIMELINE-001` 依次调用 `API-TIMELINE-101` 与 `API-TIMELINE-105`，给出首个行动机会的归属与轮次边界；排布失败时不建立标记集合。
- `API-TIMELINE-003` 依次调用 `API-TIMELINE-102` 与 `API-TIMELINE-105`，每次推进产出一份 `CLS-TIMELINE-007` 供 M05 发布 轮次推进。
- `API-TIMELINE-004` 依次调用 `API-TIMELINE-103`、`API-TIMELINE-104`、`API-TIMELINE-107`：先求值时机，再写回标记，最后提交时长增量；任一环节被拒绝时不改变标记与记账。
- `API-TIMELINE-006` 复用 `API-TIMELINE-103` 的求值结果但不写回；`API-TIMELINE-005` 调用 `API-TIMELINE-106` 生成只读预览。
- `API-TIMELINE-108` 是三项登记的唯一装配入口，`API-TIMELINE-109` 只服务启动与恢复路径，`API-TIMELINE-110` 只服务收束路径；三者互不调用。
- `API-TIMELINE-002` 在战斗进行中只调用 `API-TIMELINE-101` 的增补与移除分支，不重算已完成的历史推进。

### 6.4 使用方式

- 启动阶段：经 `API-M01-001` 登记本系统能力与依赖声明，经 `API-M01-002` 取得配置、日志与事件分发能力；经 `API-M01-012` 订阅 配置加载完成 后由 `API-TIMELINE-108` 装配三项登记；切面声明经 M05 汇总后调用 `API-SAVE-001`。
- 战斗装配与推进：由 M05 的装配路径与轮次推进路径经 `API-TIMELINE-001`、`API-TIMELINE-003` 直接调用，编排入口为 M10 的战斗执行器（`API-M10-004`、`API-M10-010`）；本系统不主动发起战斗流程。
- 行为路径：行为确认后由 M05 的行为提交路径经 `API-TIMELINE-004` 写回时机；时长增量经 `API-TIME-003` 提交，不在本系统内累计。
- 取数路径：界面与编排侧的只读取数经 `API-M05-005` 与 `API-TIMELINE-005`、`API-TIMELINE-006`、`API-TIMELINE-007`、`API-TIMELINE-008`；本系统不直接向 L5 表现层提供入口。
- 事件侧：本系统只订阅 配置加载完成；轮次推进 的发布与存档提交均不由本系统执行，恢复重建由 M05 的切面重建路径驱动。
- 落库与告知：时间轴与标记的变更一律经 `API-SAVE-009`；拒绝与校验不通过经 `API-M01-010` 记录；配置对象运行期只读（架构案 7.9）。

### 6.5 依赖方向限制

- 本系统主模块为 M05（L3），依赖落在架构案 3.3 第 3 项（读写单局状态域与使用基础设施）、第 6 项（读取 M09 的效果能力）、第 9 项（申请 M01 的基础设施）、第 10 项（经事件分发器订阅）、第 12 项（查询 M10 的阶段）内。

- 与 01-40 之间只有一次只读取值（`API-M07-004` 行动速度）。该读取属同层只读查询，但 M05 与 M07 的组合未逐条列于架构案 3.3 第 5 项，已按 REQ-TIMELINE-07 提请架构案登记（与 06-10 的 REQ-BATTLE-06 为同一登记项），不自行按例外处理。
- 不得依赖 M08 与任何 L5 表现层对象（架构案 3.4 第 1、2 项）：时间轴界面与悬浮预览由 M08 经 `API-M05-005` 取数，本系统不发起界面、场景与资源调用。
- 不得被越权依赖：其他模块不得持有时间轴、标记与行动机会的可变引用（架构案 3.4 第 5 项、8.2 第 1、2 条）；M10 只经 M05 的入口驱动轮次；界面不得经本系统修改任何游戏数据（3.4 第 3 项）。
- 不得绕过的基础设施：世界时间的推进（`API-M01-005`）、存档读写（`API-SAVE-001`、`API-SAVE-008`、`API-SAVE-009`）、效果求值（`API-M09-003`）、日志（`API-M01-010`）与事件分发（`API-M01-012`）一律经登记入口，本系统不自行实现其中任何一项（架构案 3.4 第 6、8、9、10 项、第 7 章）。

## 8. 核心流程

### 8.1 战斗装配的时间轴排布与首个行动机会

触发与参与：M10 的战斗执行器经 `API-M10-004` 调用 `API-M05-001`，M05 的装配路径调用 `API-TIMELINE-001`；参与方为 M05、本系统、01-40、M09、M01、06-30（布置阶段）。
调用顺序：① `API-TIMELINE-108` 已在 配置加载完成 后装配三项登记；② `API-TIMELINE-101` 按参战单位清单与初始排布输入建立标记集合；③ 时机求值取行动速度的取值与生效值（`API-M07-004`、`API-M09-003`）；④ `API-TIMELINE-105` 判定首个行动机会的轮次边界；⑤ `API-TIMELINE-001` 返回首个行动机会的归属单位与轮次序号；⑥ 变更经 `API-SAVE-009` 落库。
状态变化：时间轴 未排布 → 已排布；标记集合建立；行动机会处于等待态；世界时间未推进。
产生的事件：无（战斗开始 由 M05 发布；阶段切换 由 M10 发布）。
结束条件：`API-TIMELINE-003` 可开启首个行动机会，战斗界面可交互。

### 8.2 轮次推进与自动保存节点

触发与参与：M10 的战斗执行器（`API-M10-004`、`API-M10-010`）驱动轮次循环，经 M05 的 `API-M05-002` 调用 `API-TIMELINE-003`；参与方为 M10、M05、本系统、01-50 存档侧、06-10、M08。
调用顺序：① `API-TIMELINE-003` 校验前置（进行中、无未确认选择）并调用 `API-TIMELINE-102` 推进到下一个标记；② `API-TIMELINE-105` 产出轮次边界判定结果；③ 返回归属单位、轮次序号与预计下一次行动时机；④ M05 据此发布 轮次推进；⑤ 存档侧按 01-50 §4.1 的登记在收到该事件后经 `API-SAVE-002` 提交战斗轮次推进节点的单局存档；⑥ 界面经 `API-M05-005` 与 `API-TIMELINE-005` 刷新时间轴区块。
状态变化：时间轴推进到归属单位标记；行动机会 等待 → 机会开放；标记 在场待行动 → 机会开放；世界时间未推进。
产生的事件：轮次推进（M05）；自动保存完成（M01，由存档侧提交后发布）。
结束条件：该单位获得一次行动机会并可提交唯一一项行为；该节点对应的单局存档提交完成或按失败语义处理。

### 8.3 行为确认后的时机写回与轮次收尾

触发与参与：玩家在战斗界面确认行为或敌方模板选定行为后，M05 的行为提交路径（`API-M05-003`）调用 `API-TIMELINE-004`；参与方为 M08（意图与命令）、M05、本系统、06-40、06-85、02-10、M01。
调用顺序：① `API-TIMELINE-103` 按三类输入的来源登记求值下一次行动时机与时长增量；② `API-TIMELINE-104` 写回行动者标记并收尾该次机会；③ `API-TIMELINE-107` 经 `API-TIME-003` 按消费点「战斗净时长」提交时长增量；④ 变更经 `API-SAVE-009` 落库，行为结果由 M05 发布 行为提交完成；⑤ 取消或未确认的选择不调用本系统，不产生任何状态变化。
状态变化：标记写回新位置；行动机会 机会开放 → 已确认 → 等待；轮次结束；战斗净时长账增长。
产生的事件：行为提交完成、单位状态变化（M05 按其结算结果发布）。
结束条件：下一次行动时机已确定并落库，时间轴可推进到下一个标记。

### 8.4 行动后时机预览与时间轴呈现

触发与参与：玩家悬浮当前可用技能或查看战斗行为时可预览，界面经 M05 的状态切面路径取数；参与方为 M08、M05、本系统、06-40、06-85。
调用顺序：① 界面经 `API-M05-005` 请求时间轴区块与预览；② `API-TIMELINE-005` 调用 `API-TIMELINE-106` 生成未来若干次行动机会的归属序列与本单位的预计时机；③ 悬浮某个技能或行为时 `API-TIMELINE-006` 复用 `API-TIMELINE-103` 求值该行动后的下一次行动时机；④ 预览结果标注偏差来源（`CLS-TIMELINE-008`）；⑤ 预览不占用行动机会、不写回标记、不追加行动槽字母。
状态变化：无（只读；预览结果为临时运行对象）。
产生的事件：无。
结束条件：界面按预览结果完成呈现；显示次数不超过配置限定的上限。

### 8.5 战斗收束、净时长对齐与读档重建

触发与参与：战斗产出结果标识（常规／撤退／全队失去行动能力）后由 M05 的收束编排（`API-M05-104`）调用 `API-TIMELINE-009`；参与方为 M05、本系统、06-A0、06-10、M10、02-10、01-50。
调用顺序：① `API-TIMELINE-110` 关闭行动机会并按结束方式冻结或保留时间轴；② M05 的净时长对齐（`API-M05-105`）按 `API-TIMELINE-008` 的口径取整；③ 事件退出时由 M10 经 `API-TIME-004` 与 `API-M01-005` 一次性推进世界时间；④ 撤退方式下时间轴连同敌方状态与位置保留（架构案 9.5.4）；⑤ 读档时由 M01 装载单局状态域切面，M05 的切面重建路径驱动 `API-TIMELINE-109` 重建时间轴与行动机会，恢复到最近一次行动机会开始的时刻，该次机会内尚未确认的选择不恢复。
状态变化：时间轴 推进中 → 已冻结（撤退方式保持已排布并保留标记）；世界时间按取整结果推进；读档后回到存档记录的时刻。
产生的事件：战斗结束、撤退发生（M05）；阶段切换（M10）；时间刻度变化、自动保存完成（M01）。
结束条件：收尾窗口结束并完成事件退出，或读档后 `API-TIMELINE-003` 可继续推进。

## 9. 异常与边界情况

| 情形 | 判定条件 | 期望结果 |
| --- | --- | --- |
| 未排布即推进 | `API-TIMELINE-003` 收到请求而时间轴为未排布 | 拒绝，不开启行动机会，登记原因 |
| 实例不存在或已冻结 | 战斗实例已释放，或时间轴为已冻结 | 拒绝推进与写回，不改变任何状态 |
| 上一轮次未确认 | 存在未确认的选择而请求推进 | 拒绝；未确认的选择不产生状态变化（06-85 §3.4） |
| 行为前置条件不满足 | 射程、地形、成本串、库存或法术书不满足 | 操作不提交、不消耗行动机会与行动槽字母，时间轴不推进（06-20 §4） |
| 越权或重复写回 | 非当前行动者写回；同一行动机会重复写回 | 拒绝；重复写回幂等，不产生第二次标记变化 |
| 结算阶段请求 | 阶段取值为结算阶段 | 拒绝推进、写回与标记维护（架构案 6.6 硬规则 2） |
| 无任何可行动标记 | 标记集合内全部单位处于失去行动能力状态 | 不由本系统开启机会，转由 M05 按全队失去行动能力收束（架构案 9.5.5、`API-BATTLE-005`） |
| 不可行动标记的处置 | 推进到已失去行动能力的单位标记 | 按上游补齐后的口径跳过或开启空机会；口径缺失时登记（REQ-TIMELINE-02） |
| 标记缺失 | 写回或移除时找不到对应标记 | 拒绝，标记集合不变，登记原因 |
| 重复增补 | 同一单位被二次增补标记 | 幂等拒绝，不产生第二个标记 |
| 时机输入未登记 | 行为或技能未登记后摇来源，或输入来源登记校验不通过 | 拒绝写回与预览，登记原因（REQ-TIMELINE-03） |
| 属性取数不可用 | 行动速度取值或生效值不可读 | 拒绝写回，保持机会开放并可重试；不按默认值代替 |
| 预览超出配置上限 | 查询范围大于时间轴显示的未来次数上限 | 按上限截断返回并登记（REQ-TIMELINE-05） |
| 偏差超出可接受范围 | 预览位置与实际写回位置不一致且超出登记范围 | 按偏差来源登记标记结果并登记日志；偏差来源清单待上游补充（REQ-TIMELINE-04） |
| 时长增量口径未登记 | 消费点未登记或计量口径缺失 | 拒绝写账并登记；时间轴写回仍成立，缺口按 REQ-TIMELINE-06 处置 |
| 时间推进记账冲突 | 同一战斗事件实例同时走非战斗记账与战斗净时长两条路径 | 由 02-10 拒绝后到的写入，本系统不重试（02-10 §9） |
| 波次刷新 | 后续波次在既有战斗内入场 | 只增补标记，不结算、不重置时间轴与已完成的推进（06-90 §3） |
| 收尾窗口内推进 | 阶段为收尾窗口阶段而请求推进或写回 | 拒绝；收尾窗口内不消耗行动机会、不推进世界时间 |
| 读档后时间轴与机会记录不一致 | 快照中的机会记录与标记集合不匹配 | 按最近一次行动机会开始的时刻重建，未确认的选择不恢复（架构案 5.2.2） |
| 切面装载失败 | 引用完整性校验不通过或切面缺失 | 按架构案 7.1 的失败语义处理，本系统不提供默认时间轴 |

## 10. 实现约束

### 10.1 功能要求

- `F-TIMELINE-01` 敌我双方全部参战单位在一条时间轴上按标记排布；时间轴推进到某单位的标记时，该单位获得一次行动机会（06-20 §3.1）。
- `F-TIMELINE-02` 单位行动结束后，按该次行动的内容与单位属性补正计算下一次行动时机并写回时间轴；行动内容越重、延迟越长（06-20 §3.1）。
- `F-TIMELINE-03` 决定下一次行动时机的输入有三类：行为后摇由行为配置提供、技能后摇由技能配置提供、属性补正由行动速度属性提供（06-20 §3.1）。
- `F-TIMELINE-04` 战斗轮次的起点是单位获得行动机会的时刻，终点是该单位行动结束并完成下一次行动时机计算的时刻（06-20 §3.2）。
- `F-TIMELINE-05` 战斗轮次推进是自动保存的两类节点之一，保存在单位获得行动机会的时刻触发（06-20 §3.2、01-50 §6）。
- `F-TIMELINE-06` 玩家的行动只有确认时才提交状态变化；取消或未确认的选择不产生状态变化，也不消耗行动机会、行动槽字母与道具；读档恢复到最近一次行动机会开始的时刻（06-20 §3.2、06-85 §3.4）。
- `F-TIMELINE-07` 战斗内每累计十分钟推进一个时间段；结束时不足十分钟的余量向上对齐到下一个时间段边界，占用时间段数量即战斗净时长向上取整的结果；日程按该结果回填（06-20 §3.3）。
- `F-TIMELINE-08` 时间轴固定显示未来若干次行动机会的归属单位与本单位的预计时机，显示的未来次数由配置限定，超出范围的部分不显示（06-20 §3.5）。
- `F-TIMELINE-09` 玩家在执行当前行动前即可看到该次行动之后自己的下一次行动在时间轴上的位置；悬浮当前可用技能时显示该技能释放后的下次行动时机位置，战斗行为表登记的各类行为同样提供预览（06-20 §3.5）。
- `F-TIMELINE-10` 连携释放后同样推进时间轴；连携完成不设节奏奖励，不改变该单位的下一次行动时机（06-20 §3.4、§4）。
- `F-TIMELINE-11` 行动条件不满足时操作不提交、不消耗行动机会，时间轴不推进（06-20 §4）。
- `F-TIMELINE-12` 一次行动机会内只执行一项行为，技能与移动不能合并（06-20 §4、06-85 §3.3）。
- `F-TIMELINE-13` 时间轴的预测结果与实际执行结果的偏差控制在可接受范围内，偏差来源在时间轴规则中登记（06-20 §4）。
- `F-TIMELINE-14` 后续波次在既有战斗内刷新，波次之间不结算、不重置行动槽与时间轴（06-90 §3）。
- `F-TIMELINE-15` 战斗内时间推进的可见性：玩家在事件进行中每次推进都能看到时长的更新，战斗实际耗时对玩家是可见的区间结果（06-20 §3.3）。

### 10.2 实现要求

- `I-TIMELINE-01` 时间轴、标记与行动机会是本系统拥有的数据对象，其他系统只读；变更一律经 4.1 登记的接口提交，不得直接改对象字段或内部集合（架构案 8.2 第 1、2 条、3.4 第 5 项）。
- `I-TIMELINE-02` 时间轴属单局状态域的战斗未结状态，必须可序列化并入单局存档的单局状态域切面；读档后按记录重建并恢复到最近一次行动机会开始的时刻（架构案 5.2.2、9.3）。
- `I-TIMELINE-03` 轮次边界只能由本系统的判定结果给出；M10 的战斗执行器是唯一编排方，其他模块不得驱动轮次推进，成员系统不得反向调用 M10 的执行入口（架构案 3.3 第 11 项、3.4 第 12 项、M05 `I-M05-02`）。
- `I-TIMELINE-04` 自动保存的提交点由存档侧按 01-50 §4.1 的登记在 轮次推进 后经 `API-SAVE-002` 执行，触发请求由 M10 的战斗执行器下发、提交由存档服务执行；本系统不触发提交、不下发触发请求、不自行序列化状态、不读写存档（架构案 7.1、3.4 第 6 项）。
- `I-TIMELINE-05` 世界时间只能经 `API-M01-005` 受理且只在事件退出时推进；本系统只提供战斗内时长增量与推进口径（架构案 7.5、3.4 第 10 项）。
- `I-TIMELINE-06` 行动速度的取值一律经 `API-M07-004` 取得、生效值一律经 `API-M09-003` 求值；本系统不自行实现效果叠加或条件判定（架构案 3.4 第 7、8 项、7.11）。
- `I-TIMELINE-07` 三类时机输入必须登记后使用；未登记来源的行为或技能不得写回时机，也不得生成预览（架构案 8.5.4）。
- `I-TIMELINE-08` 时间轴、标记与机会记录只写入单局状态域，提交经 `API-SAVE-009`；本系统不持有他方可变对象，不把跨域读取结果缓存为自身数据来源（架构案 8.2 第 2、3 条）。
- `I-TIMELINE-09` 预览结果为临时运行对象，不跨帧保留、不入档；读取方不得把预览当作来源状态使用（架构案 6.5、8.2 第 3 条）。
- `I-TIMELINE-10` 本系统不依赖 M08 与任何 L5 表现层对象；时间轴区块与悬浮预览经 `API-M05-005` 取数，界面不得经本系统修改任何游戏数据（架构案 3.4 第 1、2、3 项）。
- `I-TIMELINE-11` 本系统不发布跨模块事件：轮次推进 由 M05 按其登记发布，载荷中的轮次序号与归属单位取自 `CLS-TIMELINE-007`；不得把「要求谁做什么」写进事件（架构案 8.4 第 2、3 条）。
- `I-TIMELINE-12` 常驻对象由服务容器按依赖拓扑创建与逆序销毁；时间轴、标记与机会记录属数据域对象，随战斗实例创建与释放，本系统不自行创建常驻对象（架构案 6.3、6.4、8.3）。
- `I-TIMELINE-13` 结算阶段拒绝推进、写回、标记维护与时长写账（架构案 6.6 硬规则 2）。
- `I-TIMELINE-14` 时间轴与战斗净时长账的口径必须一致：两者都取自 `API-TIMELINE-103` 的求值结果，不得各算一套后摇与补正。

### 10.3 其他实现约束

- 三项登记的装配只在 配置加载完成 之后执行一次；运行期配置只读，不得就地修改配置对象（架构案 7.9）。
- 待上游补充项按 9 的判定拒绝或降级，不猜值、不用默认值代替：初始排布口径（REQ-TIMELINE-01）、不可行动与离场标记的处置（REQ-TIMELINE-02）、时机合成口径与参数载体（REQ-TIMELINE-03）、偏差来源清单（REQ-TIMELINE-04）、显示次数上限（REQ-TIMELINE-05）、时长增量计量口径（REQ-TIMELINE-06）、M05 对 M07 的只读读取登记（REQ-TIMELINE-07）。
- 成员系统之间不互相持有对方的可变数据对象；本系统需要的行为契约、技能后摇与波次数据一律按其单元提供的查询入口读取。
- 收尾窗口内本系统只提供只读取数（`API-TIMELINE-005`、`API-TIMELINE-007`、`API-TIMELINE-008`），不受理推进、写回与标记维护。
- 时间轴的显示次数上限、界面布局与悬浮预览的交互规格归界面设计阶段，本系统只提供可配置的范围输入与只读预览结果。
