## 1. 系统定义

### 1.1 系统目的

行动槽与连携在程序上持有每个参战我方单位的行动槽（术语表 T-139）序列，并给出连携（术语表 T-140）的槽尾匹配判定、成本串（术语表 T-142）删尾与产出串（术语表 T-143）追加、移动打断三项契约，使「构建序列—条件达成—释放连携—被打断」这条决策链在战斗内有唯一的数据持有者与判定入口，而不由界面或各行为发起方各自维护一份序列。本单元的系统标识为 SYS-ACTIONSLOT-001 行动槽与连携。

### 1.2 系统职责

- 持有各参战我方单位的行动槽序列：按单位建立独立条目，容量上限 10，按进入顺序记录字母并给出占用长度；
- 受理已提交行为的字母追加：按 06-85 的行动槽字母登记把本次行为的字母落到槽尾；追加后只保留最近的容量上限个字母；
- 执行移动打断：槽内存在字母 M 时，之后执行的任何行动先清空 M 及其之前的全部字母，再落下本次行动的字母；移动本身不打断已有序列；
- 判定连携释放条件：逐连携对照槽尾序列与成本串，返回完全一致匹配的结论、匹配长度与可释放清单；
- 执行连携释放结算：成本串从槽尾删除，产出串追加到槽尾，并把本次涉及的两串构成作为释放结果返回；
- 执行破招（术语表 T-126）打断：受理敌方破招命中后的序列清空请求；
- 提供行动槽边界登记：容量上限、成本串长度上限、连携数量上限与字母来源引用，其运行期权威载体是引擎编辑器内的配置资产；
- 提供界面取数与提示：序列只读快照、连携条件达成情况、可继续构建的下一步提示与打断待决状态；
- 维护序列条目的建立、装载与释放，并提供行动槽切面的采集与装载入口；
- 提供序列的只读查询与变更入口，并把序列变更经单局状态域提交、随自动保存的战斗轮次推进节点入档；读档时由 M05 重建战场与时间轴，把序列恢复到最近一次行动机会开始的时刻（架构案 5.2.2、9.3）。

### 1.3 系统边界

本系统不负责：

- 行为的权威清单、逐行为的行动槽字母与行动机会消耗登记：归 06-85 战斗行为系统（BATTLEACT，`CLS-BATTLEACT-002` 战斗行为表、`CLS-BATTLEACT-003` 行为契约字段登记）；本系统按其登记追加字母，不定义字母含义、不判定行为是否占用行动机会、不判定行为能否合并；
- 成本串与产出串的定义、连携清单与技能类别归属：归 06-40 技能系统（SKILL，`CLS-SKILL-001` 技能定义、`CLS-SKILL-002` 动作类别登记）；本系统只按连携标识读取其串并完成匹配与删尾，不把这些串复制为自身数据来源；
- 后摇（术语表 T-119）计算、时间轴（术语表 T-117）推进与下一次行动时机写回：归 06-20 时间轴与行动顺序（TIMELINE，`API-TIMELINE-004` WriteBackNextTiming 下一次行动时机写回）与 M05 的行为提交路径；连携与基础技能（术语表 T-144）的后摇一视同仁，本系统不设节奏奖励；
- 行动机会（术语表 T-118）的开放、归属与用尽判定：归 06-20 与 M05 的轮次推进（`API-M05-002`）；
- 继承效果（术语表 T-145）的求值与效果施加：归 06-40 与 M09 的元效果服务（`API-M09-001`～`API-M09-003`）；本系统只返回本次释放涉及的两串构成，不实现效果叠加、不实现条件判定；
- 破招的触发条件、命中判定与视觉预告：归 06-90 敌人与AI（ENEMY，`CLS-ENEMY-007` 破招判定结果、`API-ENEMY-006` Interrupt.Evaluate 破招命中判定）与后续界面设计阶段；本系统只在命中后执行清空；
- 法术（术语表 T-149）与符文书页：归 06-40 与 06-80；法术不进入行动槽序列，也不作为成本串或产出串内容；
- 战场空间、站位与布置阶段（术语表 T-121）的站位调整判定：归 06-30 战场与战棋规则（FIELD，`CLS-FIELD-008` 布置阶段状态、`API-FIELD-006` SubmitPositionAdjustment 站位调整提交）；站位调整按移动规则追加 M，追加动作由本系统执行；
- 收尾窗口内的搜刮：收尾窗口（术语表 T-123）内不消耗行动机会、不参与时间轴，其中的搜刮不产生字母追加（06-30 §3.7）；本系统只在战斗阶段受理字母追加；
- 行动槽区块的绘制、布局、提示数量与视觉标注：归 M08 与后续界面设计阶段；本系统只提供只读取数内容。全量界面清单的权威来源是 `架构设计文档/界面索引.md`，其中第 8 项战斗界面承接战场、时间轴与行动槽的呈现；本系统只在该区块的取数范围内提供只读内容，不搬运界面清单（架构案 2.4、设计决策记录决策 94）；
- 序列的存档文件读写、切面装配与恢复顺序：归 M01 的存档服务与 M05 的切面声明；本系统只提供切面采集与装载入口；
- 战斗的启动、轮次推进与收束编排：归 M05 与 M10 的战斗执行器（`API-M10-004`）；
- 世界时间的持有与推进：唯一受理入口是 M01 时间服务（`API-M01-005`），本系统不推进也不改写世界时间。

### 1.5 功能要求

- F-ACTIONSLOT-01 每个我方单位持有独立的行动槽序列，容量上限 10，槽满时最早进入的字母被挤出。
- F-ACTIONSLOT-02 任何行为完成后都向槽尾追加字母，单位不能选择不追加；追加内容按 06-85 的行动槽字母登记取值。
- F-ACTIONSLOT-03 基础技能追加其所属类别字母；连携技能先按成本串删除槽尾对应字母，再追加一个或多个产出串字母；移动、布置阶段的站位调整、容器搜刮与场景交互追加字母 M。
- F-ACTIONSLOT-04 连携的释放条件是槽尾序列与成本串完全一致；多个连携同时满足时由玩家手动选择，任何时候都不自动释放。
- F-ACTIONSLOT-05 释放连携时成本串从槽尾删除，产出串追加到槽尾并立即参与后续行动的匹配判定。
- F-ACTIONSLOT-06 行动槽内一旦存在 M，之后执行的任何行动把 M 以及排在 M 之前的全部字母一并清空，序列从 M 之后重新开始；移动本身不打断已有序列，本次移动后未再执行其他行动时 M 保留在槽内等待判定。
- F-ACTIONSLOT-07 M 与其他字母一样占用容量，槽满时按最早字母被挤出的规则处理。
- F-ACTIONSLOT-08 一次行动机会内只执行一项行为，技能与移动不能合并；取消行动不产生任何状态变化，也不消耗行动槽字母。
- F-ACTIONSLOT-09 法术不进入行动槽序列，也不作为成本串或产出串的内容。
- F-ACTIONSLOT-10 敌方破招命中正在构建连携的我方单位时，打断其行动槽序列。
- F-ACTIONSLOT-11 行动槽序列属单局状态域的战斗未结状态，在事件内实时结算并随自动保存的战斗轮次推进节点入档；读档后由 M05 重建战场与时间轴，恢复到最近一次行动机会开始的时刻，该次行动机会内尚未确认的选择不恢复（架构案 5.2.2、9.3）。
- F-ACTIONSLOT-12 界面呈现当前行动者的字母序列、连携条件达成情况与移动打断的当前状态；点选其他单位查看时切换为该单位的序列并明确标注为不可操作状态。

## 3. 状态定义

### 3.1 状态

| 状态集 | 取值 | 说明 |
| --- | --- | --- |
| 序列条目（`CLS-ACTIONSLOT-001`） | 未建立／已建立／已释放 | 装配阶段为参战我方单位逐个建立；收束时释放；撤退收场时保留 |
| 序列占用（`CLS-ACTIONSLOT-001`） | 未满／已满 | 达到容量上限时为已满；追加后只保留最近的容量上限个字母 |
| 打断待决（`CLS-ACTIONSLOT-001`） | 无待清空字母／待打断 | 槽内存在 M 时为待打断；该状态下执行的任何行动先清空 M 及其之前的全部字母 |
| 边界登记（`CLS-ACTIONSLOT-002`） | 已登记／待补充 | 成本串长度上限待上游补充（REQ-ACTIONSLOT-01） |
| 匹配判定（`CLS-ACTIONSLOT-003`） | 可释放／不可释放／口径待定 | 完全一致为可释放；口径待定对应槽内存在 M 的连携释放（REQ-ACTIONSLOT-02） |
| 下一步提示（`CLS-ACTIONSLOT-004`） | 可继续／已可释放／无可继续项 | 槽尾序列构成某成本串前缀时给出下一步字母类型 |
| 变更结果（`CLS-ACTIONSLOT-005`） | 已追加／触发打断清空／被拒绝 | 被拒绝时不产生任何状态变化 |
| 切面记录（`CLS-ACTIONSLOT-006`） | 已采集／已装载 | 记录在采集完成或恢复完成后释放 |
| 本单元装配状态 | 未初始化 → 初始化中 → 已初始化 → 已销毁 | 由启动物体按单元装配声明顺序在初始化序列第 3 步显式初始化（架构案 6.1 阶段 3、8.3 第 1 条）；本系统的全部对外接口以「本单元已完成初始化」为前置条件；本文档不对该状态设对外接口 |

### 3.2 状态转换

```
序列条目：未建立 → 已建立 → 已释放
序列条目：已建立 →（撤退收场）不转换，条目与序列内容保留
序列占用：未满 → 已满
序列占用：已满 → 未满（成本串删尾或打断清空后）
打断待决：无待清空字母 → 待打断（追加字母 M）
打断待决：待打断 → 无待清空字母（之后执行的任何行动触发清空）
匹配判定：可释放 ／ 不可释放 ／ 口径待定
下一步提示：可继续 → 已可释放
下一步提示：可继续 → 无可继续项
变更结果：已追加 ／ 触发打断清空 ／ 被拒绝
边界登记：已登记 ／ 待补充
切面记录：已采集 → 已装载
本单元装配：未初始化 → 初始化中 → 已初始化 → 已销毁（程序结束时的逆序销毁）
```

### 3.3 状态转换触发条件

| 转换 | 触发条件 |
| --- | --- |
| 序列条目 未建立 → 已建立 | `API-ACTIONSLOT-007` 在战斗装配的「行动槽序列初始化」步骤按参战我方单位集合建立；或 `API-ACTIONSLOT-009` 按切面记录重建 |
| 序列条目 已建立 → 已释放 | `API-ACTIONSLOT-010` 由 M05 的战斗收束编排调用；撤退收场时不触发该转换 |
| 序列占用 未满 → 已满 | `API-ACTIONSLOT-004` 或 `API-ACTIONSLOT-005` 追加后占用达到容量上限 |
| 序列占用 已满 → 未满 | `API-ACTIONSLOT-005` 删除成本串后占用低于上限；或 `API-ACTIONSLOT-006` 清空后占用归零 |
| 打断待决 无待清空字母 → 待打断 | `API-ACTIONSLOT-004` 本次落下的字母为 M（移动、布置阶段站位调整、容器搜刮与场景交互按 06-85 登记追加 M） |
| 打断待决 待打断 → 无待清空字母 | `API-ACTIONSLOT-004` 在追加本次字母前清空 M 及其之前的全部字母；或 `API-ACTIONSLOT-006` 执行打断清空 |
| 匹配判定 可释放 | `API-ACTIONSLOT-002` 判定某连携的成本串与槽尾序列完全一致（成本串是否允许为空与长度上限按 REQ-ACTIONSLOT-01 补齐） |
| 匹配判定 不可释放 | `API-ACTIONSLOT-002` 判定全部候选连携的成本串均不与槽尾序列完全一致 |
| 匹配判定 口径待定 | 槽内存在 M 且成本串匹配成立时，先后次序待上游补充（REQ-ACTIONSLOT-02），该情形不落定 |
| 下一步提示 各取值 | `API-ACTIONSLOT-003` 按槽尾序列构成其前缀的连携给出下一步字母类型与剩余位数 |
| 变更结果 各取值 | `API-ACTIONSLOT-004`、`API-ACTIONSLOT-005`、`API-ACTIONSLOT-006` 的单次受理给出；被拒绝时序列与落库内容保持受理前内容 |
| 边界登记 各取值 | 启动阶段加载后由 `API-ACTIONSLOT-109` 校验；成本串长度上限缺失时标记待补充 |
| 切面记录 已采集 → 已装载 | `API-ACTIONSLOT-009` 按记录重建条目并置为已装载 |
| 本单元装配 未初始化 → 初始化中 → 已初始化 | 启动物体在初始化序列第 3 步按单元装配声明顺序显式调用本系统的初始化；本系统在初始化时显式复位自身状态（架构案 6.1 阶段 3、8.3 第 1、7 条、8.6 第 4、5 条） |
| 本单元装配 已初始化 → 已销毁 | 程序结束时的逆序销毁；进程终止不执行销毁序列、不做任何收尾承诺（架构案 6.4、8.3 第 6 条、9.4） |

| API-ACTIONSLOT-006 | ActionSlot.ApplyInterrupt 序列打断执行 | M05 行为提交的结算路径（敌方破招命中，06-90） | 战斗实例标识、单位标识、打断来源行为标识 | 打断结果（被清空的字母范围、清空后的序列、是否落定） | 按移动打断规则清空 M 及其之前的全部字母；槽内无 M 的情形不落定（REQ-ACTIONSLOT-03） | 经 `API-SAVE-009` 提交；命中判定与预告不由本接口处理 |
| API-ACTIONSLOT-007 | ActionSlot.InitializeForBattle 序列装配初始化 | M05 战斗启动的装配顺序（`API-M05-001` 经 `API-M05-101`） | 战斗实例标识、参战我方单位标识集合 | 初始化结果（建立条目的单位清单与未建立项） | 序列条目 未建立 → 已建立；序列内容为空 | 未建立项经日志服务记录 |
| API-ACTIONSLOT-008 | ActionSlot.CollectSlice 序列切面采集 | M05 的切面采集路径（`API-M05-106`） | 战斗实例标识 | 行动槽切面记录 `CLS-ACTIONSLOT-006` | 无 | 无 |
| API-ACTIONSLOT-009 | ActionSlot.RestoreFromSlice 序列装载重建 | M05 的恢复路径（`API-M05-106`） | 战斗实例标识、行动槽切面记录 | 装载结果（重建条目的单位清单与不一致项） | 序列条目 未建立 → 已建立；序列内容取记录值 | 不一致项经日志服务记录 |
| API-ACTIONSLOT-010 | ActionSlot.ReleaseForBattle 序列条目释放 | M05 的战斗收束编排（`API-M05-104`） | 战斗实例标识、收束结果标识 | 释放结果 | 序列条目 已建立 → 已释放；序列内容销毁 | 无 |

### 4.2 接口详细定义

#### API-ACTIONSLOT-001 ActionSlot.QuerySequence 序列查询

职责：返回指定范围内单位行动槽序列的只读快照，不提供写入口。输入：参数输入：战斗实例标识、单位标识集合；状态输入：序列条目与序列内容 `CLS-ACTIONSLOT-001`、当前阶段（`API-M10-001`）；数据输入：行动槽边界登记 `CLS-ACTIONSLOT-002`（容量上限用于给出占用与满槽标记）；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`、当前阶段（`API-M10-001`）。输出：返回值：各单位序列快照（字母序列、占用长度、容量上限、打断待决状态、条目建立标记）；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条；由启动物体按单元装配声明顺序显式初始化）；战斗实例存在；查询范围内单位已建立序列条目。后置条件：快照为只读且不携带写入口；读取方不得把快照缓存为自身数据来源；「不可操作」的判定不由本接口给出，界面按 M05 的行动机会归属口径标注。副作用：无。异常情况：战斗实例不存在或查询发生在装配完成前；单位标识未建立条目（敌方单位不建立条目）；切面装载期间查询；结算阶段查询只返回只读内容。

#### API-ACTIONSLOT-002 ActionSlot.EvaluateCombo 连携条件判定

职责：按当前槽尾序列逐连携判定成本串是否完全一致，返回可释放清单与匹配长度。输入：参数输入：战斗实例标识、单位标识、候选连携标识集合（可缺省为全部连携）；状态输入：`CLS-ACTIONSLOT-001`、当前阶段（`API-M10-001`）；数据输入：连携清单与成本串（SKILL，`CLS-SKILL-001` 技能定义）、`CLS-ACTIONSLOT-002`；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`、连携定义（SKILL，`CLS-SKILL-001` 技能定义）、当前阶段（`API-M10-001`）。输出：返回值：连携匹配判定结果 `CLS-ACTIONSLOT-003`（逐连携结论、匹配长度、可释放清单）；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；单位已建立序列条目；候选连携标识在 06-40 的连携清单内。后置条件：判定只依据当前序列与成本串，不缓存判定结果；产出串追加后立即参与后续判定（06-50 §3.2）；判定不改变序列，释放动作另经 `API-ACTIONSLOT-005`。副作用：无。异常情况：连携标识未登记；成本串长度上限待上游补充（REQ-ACTIONSLOT-01）；槽内存在 M 且匹配成立（REQ-ACTIONSLOT-02）；单位无序列条目。

#### API-ACTIONSLOT-003 ActionSlot.QueryNextStep 下一步提示查询

职责：返回槽尾序列构成其前缀的各连携的下一步可执行字母类型与剩余位数。输入：参数输入：战斗实例标识、单位标识；状态输入：`CLS-ACTIONSLOT-001`；数据输入：连携清单与成本串（SKILL，`CLS-SKILL-001` 技能定义）、`CLS-ACTIONSLOT-002`；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`、连携定义（SKILL，`CLS-SKILL-001` 技能定义）。输出：返回值：下一步提示 `CLS-ACTIONSLOT-004`（逐连携的下一步字母类型、剩余位数、可释放标记）；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；单位已建立序列条目。后置条件：提示只给出字母类型与剩余位数，不给出可执行行为清单与操作入口（行为可用性归 06-85 与 M05）；不给出自动释放建议。副作用：无。异常情况：无可继续项时返回空提示而非伪造候选项；连携清单为空；提示数量上限与呈现规格待上游补充（REQ-ACTIONSLOT-05）；单位无序列条目。

#### API-ACTIONSLOT-004 ActionSlot.AppendBehaviorLetter 行为字母追加

职责：受理一次已提交行为的字母追加，按 06-85 的行动槽字母登记把字母落到槽尾，并处理移动打断与满槽挤出。输入：参数输入：战斗实例标识、单位标识、行为标识、行为结果标识；状态输入：`CLS-ACTIONSLOT-001`、当前阶段（`API-M10-001`）；数据输入：行动槽字母与行动机会消耗登记（BATTLEACT，`CLS-BATTLEACT-002` 战斗行为表）、技能类别（SKILL，`CLS-SKILL-002` 动作类别登记）、`CLS-ACTIONSLOT-002`；外部事件输入：无（由 M05 的行为提交结算路径直接调用）。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`、行为契约（BATTLEACT，`CLS-BATTLEACT-002` 战斗行为表）、技能类别（SKILL，`CLS-SKILL-002` 动作类别登记）、当前阶段（`API-M10-001`）。输出：返回值：追加结果 `CLS-ACTIONSLOT-005`（实际落下的字母、是否触发打断清空、被清空的字母范围、被挤出的字母）；状态输出：`CLS-ACTIONSLOT-001` 的字母序列、占用与打断待决状态；事件输出：无（序列变化随 M05 的 行为提交完成 对外告知）；外部系统调用：`API-SAVE-009`、`API-M01-010`。产生的状态变化：槽内存在 M 时先清空 M 及其之前的全部字母，再追加本次行为的字母；追加后只保留最近的容量上限个字母。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；行为已经 M05 确认提交（`API-M05-003`）；行为标识在 06-85 的行为表内登记且其行动槽字母字段非空；单位已建立序列条目；当前阶段为战斗阶段。后置条件：序列内容等于追加后的结果且已提交到单局状态域；被拒绝时序列与落库内容保持受理前内容。副作用：经单局状态域提交入口落库，随下一次自动保存写入存档；不消耗行动机会（行动机会的用尽由 M05 落定）。异常情况：行为未登记或行动槽字母字段为空（含撤退与防御待机的类别归属待上游补充，REQ-ACTIONSLOT-04）；行为未经确认提交或非当前行动者；单位无序列条目（敌方单位、非参战单位）；当前阶段不是战斗阶段（收尾窗口与结算阶段）；同一行动机会内重复追加；落库被拒绝。

#### API-ACTIONSLOT-005 ActionSlot.ReleaseCombo 连携释放结算

职责：受理一次已提交的连携技能释放，把成本串从槽尾删除并把产出串追加到槽尾，返回本次涉及的两串构成。输入：参数输入：战斗实例标识、单位标识、连携技能标识；状态输入：`CLS-ACTIONSLOT-001`、当前阶段（`API-M10-001`）；数据输入：连携的成本串与产出串（SKILL，`CLS-SKILL-001` 技能定义）、`CLS-ACTIONSLOT-002`；外部事件输入：无（由 M05 的行为提交结算路径直接调用）。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`、连携定义（SKILL，`CLS-SKILL-001` 技能定义）、当前阶段（`API-M10-001`）。输出：返回值：释放结果（删尾与追加后的序列、本次消耗的成本串、本次追加的产出串）；状态输出：`CLS-ACTIONSLOT-001` 的字母序列与占用、打断待决状态；事件输出：无（随 行为提交完成）；外部系统调用：`API-SAVE-009`、`API-M01-010`。产生的状态变化：槽尾与成本串完全一致的部分被删除；产出串按顺序追加到槽尾；追加后只保留最近的容量上限个字母。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；该连携经玩家确认提交；`API-ACTIONSLOT-002` 的判定为可释放；连携的技能类别、成本串与产出串已登记；当前阶段为战斗阶段。后置条件：序列内容等于删尾并追加后的结果且已提交；返回的两串构成作为 06-40 继承效果判定与技能呈现的输入；产出串不触发任何自动释放。副作用：经单局状态域落库；后摇与下一次行动时机不由本接口处理；不实现效果叠加。异常情况：成本串与槽尾不完全一致；连携未登记或产出串为空；槽内存在 M 时的清空与删尾次序待上游补充（REQ-ACTIONSLOT-02），该情形不落定并拒绝；单位无序列条目；阶段不可受理；落库被拒绝。

#### API-ACTIONSLOT-006 ActionSlot.ApplyInterrupt 序列打断执行

职责：受理敌方破招命中后的序列清空请求，执行打断并返回被清空的字母范围。输入：参数输入：战斗实例标识、单位标识、打断来源行为标识；状态输入：`CLS-ACTIONSLOT-001`、当前阶段（`API-M10-001`）；数据输入：破招行动登记（ENEMY，`CLS-ENEMY-001` 行为模板、`CLS-ENEMY-007` 破招判定结果）、`CLS-ACTIONSLOT-002`；外部事件输入：无（由 M05 的行为提交结算路径直接调用）。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`、破招行动登记（ENEMY，`CLS-ENEMY-001` 行为模板）、当前阶段（`API-M10-001`）。输出：返回值：打断结果（被清空的字母范围、清空后的序列、是否落定）；状态输出：`CLS-ACTIONSLOT-001` 的字母序列与占用、打断待决状态；事件输出：无（随 行为提交完成）；外部系统调用：`API-SAVE-009`、`API-M01-010`。产生的状态变化：按移动打断规则清空槽内 M 及其之前的全部字母；槽内不存在 M 时的清空范围待上游补充（REQ-ACTIONSLOT-03），该情形不落定该迁移并返回未清空。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；打断来源行为已登记为破招行动且判定为命中；单位已建立序列条目；当前阶段为战斗阶段。后置条件：落定时序列内容等于清空后的结果且已提交；未落定时序列与落库内容保持受理前内容。副作用：经单局状态域落库；触发条件、命中判定与预告不由本接口处理。异常情况：打断来源行为未登记为破招；槽内无 M（REQ-ACTIONSLOT-03）；单位无序列条目；阶段不可受理；落库被拒绝。

#### API-ACTIONSLOT-007 ActionSlot.InitializeForBattle 序列装配初始化

职责：在一次战斗的装配阶段为参战我方单位逐个建立空序列条目。输入：参数输入：战斗实例标识、参战我方单位标识集合；状态输入：当前阶段（`API-M10-001`）；数据输入：`CLS-ACTIONSLOT-002`；外部事件输入：无（由 M05 的装配顺序直接调用）。读取：`CLS-ACTIONSLOT-002`、当前阶段（`API-M10-001`）、参战编成结果（经调用参数）。输出：返回值：初始化结果（建立条目的单位清单与未建立项）；状态输出：序列条目 未建立 → 已建立，序列内容为空；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：逐单位建立条目并把序列置空；对已建立条目的单位不重置其内容。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；战斗实例处于装配中且参战编成已完成；单位集合非空且全部为参战我方单位。后置条件：集合内每个单位恰有一个条目；敌方单位与非参战单位不建立条目。副作用：未建立项经日志服务记录。异常情况：集合为空或含敌方单位；战斗实例已进入进行中（重复装配）；结算阶段受理；参战编成结果缺失。

#### API-ACTIONSLOT-008 ActionSlot.CollectSlice 序列切面采集

职责：按当前战斗采集各单位序列内容，产出行动槽切面记录，供单局状态域切面装配。输入：参数输入：战斗实例标识；状态输入：`CLS-ACTIONSLOT-001`；数据输入：无；外部事件输入：无（由 M05 的切面采集路径调用）。读取：`CLS-ACTIONSLOT-001`。输出：返回值：行动槽切面记录 `CLS-ACTIONSLOT-006`；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；序列条目已建立；采集发生在自动保存的战斗轮次推进节点或其后的提交批次内。后置条件：切面记录覆盖全部已建立条目且不含派生结果；记录在采集完成后释放，本系统不自行序列化、不读写存档文件。副作用：无。异常情况：战斗实例不存在；条目缺失；采集发生在装配未完成时；采集内容混入派生结果或非法字母。

#### API-ACTIONSLOT-009 ActionSlot.RestoreFromSlice 序列装载重建

职责：按行动槽切面记录重建各单位序列条目，恢复到记录时刻的内容。输入：参数输入：战斗实例标识、行动槽切面记录；状态输入：单局状态域的装载结果；数据输入：`CLS-ACTIONSLOT-002`；外部事件输入：无（由 M05 的重建路径调用）。读取：切面记录内容、`CLS-ACTIONSLOT-002`、当前阶段（`API-M10-001`）。输出：返回值：装载结果（重建条目的单位清单与不一致项）；状态输出：序列条目 未建立 → 已建立，序列内容取记录值；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：条目与序列内容按记录重建；派生结果不重建，按查询即时判定。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；单局状态域的恢复顺序已到单局状态域；记录来自同一次有效提交；记录内单位与本次参战编成一致。后置条件：序列内容等于最近一次行动机会开始时刻的记录内容；该次行动机会内尚未确认的选择不恢复。副作用：不一致项经日志服务记录。异常情况：记录缺失或结构版本不匹配；记录内单位不在本次参战编成内；装载期间收到变更请求；同一战斗重复装载。

#### API-ACTIONSLOT-010 ActionSlot.ReleaseForBattle 序列条目释放

职责：在战斗收束时释放本次战斗的序列条目。输入：参数输入：战斗实例标识、收束结果标识；状态输入：`CLS-ACTIONSLOT-001`；数据输入：无；外部事件输入：无（由 M05 的战斗收束编排调用）。读取：`CLS-ACTIONSLOT-001`、当前阶段（`API-M10-001`）。输出：返回值：释放结果；状态输出：序列条目 已建立 → 已释放，序列内容销毁；事件输出：无；外部系统调用：无。产生的状态变化：条目与序列内容被销毁；收束结果为撤退时按 M05 的收束口径保留条目与内容，不执行该转换。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；战斗已收束且收束结果已产出。后置条件：已释放条目不参与后续查询与采集；重复调用幂等。副作用：无。异常情况：战斗未收束；收束结果为撤退而调用方请求释放；结算阶段受理（架构案 6.6 硬规则 2）；重复释放。

### 5.2 内部功能契约

#### API-ACTIONSLOT-101 ResolveSlotLetter 字母解析

职责：按行为标识解析本次应追加的字母，连携另取其成本串与产出串。输入：参数输入：行为标识、单位标识、连携技能标识（技能释放时）；状态输入：`CLS-ACTIONSLOT-001`；数据输入：行动槽字母登记（BATTLEACT，`CLS-BATTLEACT-003` 行为契约字段登记）、技能类别与连携定义（SKILL，`CLS-SKILL-001`、`CLS-SKILL-002`）、`CLS-ACTIONSLOT-002`；外部事件输入：无。读取：行为契约（BATTLEACT，`CLS-BATTLEACT-003` 行为契约字段登记）、技能与连携定义（SKILL，`CLS-SKILL-001`、`CLS-SKILL-002`）、`CLS-ACTIONSLOT-002`。输出：返回值：本次应落下的字母序列，或解析失败原因；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：行为标识已登记且行动槽字母字段非空；技能释放行为已给出技能或连携标识。后置条件：字母取值只来自 06-85 与 06-40 的登记，本系统不推断、不补充字母。副作用：无。异常情况：行为未登记；行动槽字母字段为空或为待定义（含撤退与防御待机的类别归属，REQ-ACTIONSLOT-04）；连携的成本串或产出串为空；字母编码清单待上游补充（REQ-ACTIONSLOT-04）。

#### API-ACTIONSLOT-102 ApplyInterruptClear 打断清空

职责：按移动打断规则清空槽内 M 及其之前的全部字母。输入：参数输入：单位标识、打断类别（行动打断／破招打断）；状态输入：`CLS-ACTIONSLOT-001` 的字母序列；数据输入：`CLS-ACTIONSLOT-002`；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`。输出：返回值：被清空的字母范围与清空后的序列，或未发生清空的原因；状态输出：无（迁移由调用接口落定）；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：序列中存在字母 M（行动打断）；破招打断时序列内容与清空范围按 REQ-ACTIONSLOT-03 判定。后置条件：清空范围为 M 及其之前的全部字母，M 之后的字母保留；槽内无 M 时不落定该迁移。副作用：无。异常情况：槽内无 M；字母 M 的登记来源缺失；清空后序列与容量上限不一致。

#### API-ACTIONSLOT-103 AppendLetters 字母追加与容量维持

职责：把本次行为的字母落到槽尾，并维持容量上限内的最近字母。输入：参数输入：单位标识、字母序列；状态输入：`CLS-ACTIONSLOT-001` 的字母序列与占用；数据输入：`CLS-ACTIONSLOT-002` 的容量上限；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`。输出：返回值：追加后的字母序列、占用长度与被挤出的字母；状态输出：无（迁移由调用接口落定）；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：追加字母已在 06-85 或 06-40 的登记内；单位已建立序列条目。后置条件：序列按进入顺序记录且只保留最近的容量上限个字母；被挤出的字母按最早进入的顺序移除。副作用：无。异常情况：字母未登记；容量上限待补充（REQ-ACTIONSLOT-01）；追加请求为空；序列处于待打断状态时未先执行清空。

#### API-ACTIONSLOT-104 DeleteCostString 成本串删尾

职责：删除与成本串完全一致的槽尾部分。输入：参数输入：单位标识、成本串；状态输入：`CLS-ACTIONSLOT-001` 的字母序列；数据输入：连携定义（SKILL，`CLS-SKILL-001` 技能定义）；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、连携定义（SKILL，`CLS-SKILL-001` 技能定义）。输出：返回值：删尾后的序列与被删除的字母范围，或不匹配结论；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：`API-ACTIONSLOT-105` 的判定为可释放。后置条件：只删除完全一致的槽尾部分，不删除槽内其他位置的同名字母；不匹配时不产生任何变化。副作用：无。异常情况：成本串不匹配；成本串为空（REQ-ACTIONSLOT-01）；槽内存在 M 导致的次序待定（REQ-ACTIONSLOT-02）。

#### API-ACTIONSLOT-105 MatchCostStrings 槽尾匹配判定

职责：逐连携对照槽尾序列与成本串，输出匹配结论、匹配长度与可释放清单。输入：参数输入：单位标识、候选连携标识集合；状态输入：`CLS-ACTIONSLOT-001` 的字母序列；数据输入：连携清单与成本串（SKILL，`CLS-SKILL-001` 技能定义）、`CLS-ACTIONSLOT-002`；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`、连携定义（SKILL，`CLS-SKILL-001` 技能定义）。输出：返回值：连携匹配判定结果 `CLS-ACTIONSLOT-003`；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：候选连携标识在 06-40 的连携清单内；成本串长度不超过登记上限。后置条件：判定以「完全一致」为唯一通过口径，不做部分匹配通过、不做自动释放；判定结果不缓存。副作用：无。异常情况：连携未登记；成本串长度超上限或上限待补充（REQ-ACTIONSLOT-01）；槽内存在 M 且匹配成立（REQ-ACTIONSLOT-02）；候选集合为空。

#### API-ACTIONSLOT-106 BuildNextStepHints 下一步提示构建

职责：为槽尾序列构成其前缀的连携构建下一步可执行字母类型与剩余位数。输入：参数输入：单位标识；状态输入：`CLS-ACTIONSLOT-001` 的字母序列；数据输入：连携清单与成本串（SKILL，`CLS-SKILL-001` 技能定义）；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、连携定义（SKILL，`CLS-SKILL-001` 技能定义）。输出：返回值：下一步提示 `CLS-ACTIONSLOT-004`；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：单位已建立序列条目。后置条件：提示只包含字母类型与剩余位数，不含行为清单与操作入口；多条连携给出同一字母类型时可合并呈现依据由界面侧决定。副作用：无。异常情况：无可继续项；连携清单为空；提示数量与呈现规格待上游补充（REQ-ACTIONSLOT-05）。

#### API-ACTIONSLOT-107 SubmitSlotChange 序列变更提交

职责：把一次已受理的序列变更提交到单局状态域，失败时回退受理前内容。输入：参数输入：单位标识、变更类别（追加／删尾与追加／清空）、变更后的序列内容；状态输入：`CLS-ACTIONSLOT-001`；数据输入：无；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、当前阶段（`API-M10-001`）。输出：返回值：提交结果；状态输出：`CLS-ACTIONSLOT-001` 的内容等于提交项或回退到受理前内容；事件输出：无；外部系统调用：`API-SAVE-009`、`API-M01-010`。产生的状态变化：单局状态域内的行动槽序列按提交项变更；提交被拒绝时回退。前置条件：变更已经 `API-ACTIONSLOT-109` 校验；单局状态域处于可写状态。后置条件：单局状态域内容与内存内容一致；本系统不自行序列化、不写存档文件。副作用：被拒绝的提交经日志服务记录。异常情况：落库被拒绝或失败；切面采集与恢复期间提交；单局状态域未就绪。

#### API-ACTIONSLOT-108 MaintainSlotEntries 序列条目维护

职责：按装配、装载与收束三类入口建立、重建与销毁序列条目。输入：参数输入：条目操作（建立／装载／释放）、战斗实例标识、单位标识集合或切面记录；状态输入：`CLS-ACTIONSLOT-001`、当前阶段（`API-M10-001`）；数据输入：`CLS-ACTIONSLOT-002`；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`、当前阶段（`API-M10-001`）。输出：返回值：条目操作结果与未建立项；状态输出：序列条目 未建立 → 已建立、已建立 → 已释放；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：条目集合按操作变化；已建立条目的内容不因重复建立请求重置；撤退收场时不释放。前置条件：当前阶段允许建立或销毁单局状态域对象。后置条件：条目集合与最近一次参战编成或切面记录一致。副作用：未建立项与不一致项经日志服务记录。异常情况：结算阶段收到建立或释放请求；单位不属于参战我方；重复建立或重复释放；装载记录与参战编成不一致。

#### API-ACTIONSLOT-109 ValidateSlotOperation 操作校验与边界核对

职责：核对一次追加、释放或打断请求的可受理性与边界字段完整性。输入：参数输入：操作类别、单位标识、行为或连携标识、字母；状态输入：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`、当前阶段（`API-M10-001`）；数据输入：行为契约（BATTLEACT，`CLS-BATTLEACT-002` 战斗行为表）、技能与连携定义（SKILL，`CLS-SKILL-001`、`CLS-SKILL-002`）；外部事件输入：无。读取：`CLS-ACTIONSLOT-001`、`CLS-ACTIONSLOT-002`、行为契约（BATTLEACT，`CLS-BATTLEACT-002` 战斗行为表）、连携定义（SKILL，`CLS-SKILL-001`）、当前阶段（`API-M10-001`）。输出：返回值：校验结论与不通过项清单；状态输出：无；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：无。前置条件：请求字段齐备。后置条件：校验结论只依据两处权威登记与边界登记，不依据界面或调用方自带的默认值。副作用：不通过项经日志服务记录。异常情况：行为或连携未登记；字母未在两处登记内；容量上限或成本串长度上限待补充（REQ-ACTIONSLOT-01）；阶段不可受理；槽内存在 M 的次序待定（REQ-ACTIONSLOT-02）。

### 5.3 功能之间的关系

- `API-ACTIONSLOT-004` 依次调用 `API-ACTIONSLOT-109`、`API-ACTIONSLOT-101`、`API-ACTIONSLOT-102`（仅在待打断状态下）、`API-ACTIONSLOT-103`，再由 `API-ACTIONSLOT-107` 落库并返回 `CLS-ACTIONSLOT-005`；任一环节不通过时不落库。
- `API-ACTIONSLOT-005` 依次调用 `API-ACTIONSLOT-109`、`API-ACTIONSLOT-105`、`API-ACTIONSLOT-104`、`API-ACTIONSLOT-103`，再由 `API-ACTIONSLOT-107` 落库；不匹配时不做删尾与追加。
- `API-ACTIONSLOT-006` 调用 `API-ACTIONSLOT-109` 与 `API-ACTIONSLOT-102`，落定与否按 REQ-ACTIONSLOT-03 判定后再经 `API-ACTIONSLOT-107` 提交。
- `API-ACTIONSLOT-002` 只读序列与连携定义并调用 `API-ACTIONSLOT-105`；`API-ACTIONSLOT-003` 只读并调用 `API-ACTIONSLOT-106`；两者都不改变状态、不发事件。
- `API-ACTIONSLOT-007`、`API-ACTIONSLOT-009`、`API-ACTIONSLOT-010` 统一经 `API-ACTIONSLOT-108` 维护条目，分别服务装配、恢复与收束三条路径，互不调用。
- `API-ACTIONSLOT-008` 只读序列产出切面记录，不触发条目变化，也不调用变更提交。

### 6.4 使用方式

- 初始化序列：本系统的规则侧随 M05 的成员系统由常驻场景承载，由启动物体按单元装配声明顺序在初始化序列第 3 步显式初始化并完成相互引用（战斗总览 → 技能系统 → 行动槽与连携 → 战场与战棋规则 → …），按初始化逆序销毁；本模块成员系统之间的装配顺序登记在 M05 的模块装配登记内，**不设统一的持有容器，不设解析入口，不设静态单例就地取用**（架构案 2.4.1、2.4.2、6.1 阶段 3、6.3、6.4、7.11、8.3 第 1 条）。
- 一次战斗内：由 M05 的一次战斗装配顺序在「行动槽序列初始化」步骤直接调用 `API-ACTIONSLOT-007`；行为确认提交后由 M05 的行为提交结算路径直接调用 `API-ACTIONSLOT-002`、`API-ACTIONSLOT-004`、`API-ACTIONSLOT-005`、`API-ACTIONSLOT-006`；界面侧经 `API-ACTIONSLOT-001`、`API-ACTIONSLOT-002`、`API-ACTIONSLOT-003` 只读取数；收束后由 M05 调用 `API-ACTIONSLOT-010`。
- 字母与串的取用：追加字母与匹配所依据的字母、成本串、产出串一律经 06-85 与 06-40 的登记查询取得，本系统不内置字母表、不缓存串内容。
- 落库与告知：一切序列变更经 `API-SAVE-009` 提交；拒绝与不通过项经 `API-M01-010` 记录；本系统不发布、不订阅跨模块事件（见 7.2）。运行期配置的权威载体是引擎编辑器内的配置资产，设计库的表是初始素材与迁移来源，程序侧不直接读表，内容侧不直接改运行期资产；配置对象运行期只读，不得就地修改（架构案 5.1、7.9、8.6 第 10 条；设计决策记录决策 93）。
- 阶段受理：追加、释放、打断与条目维护前一律经 `API-M10-001` 判定阶段，收尾窗口与结算阶段不受理（架构案 6.6）。

### 6.5 依赖方向限制

分层与模块是架构案的**描述性分类**，不承担数据隔离、交互隔离与依赖方向约束职责（架构案 1.6）。本节只用于阅读导航：列出本系统实际依赖的模块与方向，以及仍然成立的少量硬规则。调用是否合法的判据是架构案 3.3 的允许清单、3.4 的禁止清单与 8.1 的依赖方向规则；**同层只读查询按 3.3 第 5 项的通则成立，不需要逐条登记、不需要逐条例外申报**（架构案 8.1、8.2）。

- 本系统的模块归属为 M05（L3）。运行期依赖只有三类：向 M01 申请基础设施能力（配置读取、日志记录、单局状态域的只读查询与变更提交）；向 M10 查询当前阶段；与 M05 模块内的 06-85、06-40、06-90、06-20、06-30 及 M05 的编排侧相互调用。本系统不调用 M05 之外的玩法模块。
- 被依赖方向：M08 的行动槽区块与技能面板经 `API-ACTIONSLOT-001` 至 `API-ACTIONSLOT-003` 取只读内容，属 L5 向下只读；06-85 的行为可用性判定取连携匹配结论，属同一模块内的只读查询（架构案 4.2、8.2）。
- 硬规则：
  1. 不写入他方数据、不持有对方的可变引用；跨域变更经持有方入口（架构案 3.4 第 5 项、8.2）。
  2. 不绕过统一入口：序列变更与落库经单局状态域提交入口，读取经只读查询；存档、物品写入、效果叠加、随机源、世界时间、资源、场景、输入与日志一律不得自行实现（架构案 3.4 第 6 至 10 项、第 7 章）。
  3. 基础设施不依赖任何具体玩法系统（架构案 3.4 第 11 项）。
  4. 不形成循环依赖；跨模块状态广播走事件通道（架构案 3.4 第 12 项、8.4 第 1 条）。
  5. 不使用系统基础库的随机源、不在游戏状态判定中使用帧时间、不依赖引擎的退出回调（架构案 3.4 第 15 至 17 项）。
  6. 不重复实现引擎已提供的能力（架构案 7.12、8.6 第 1 条）。
- 唯一事实来源：行动槽序列只由本系统提供变更入口；任何模块不得绕过本系统改写序列，也不得直接改写单局状态域内的序列内容，界面不得经本系统或绕过本系统修改任何游戏数据（架构案 3.4 第 3、5 项、8.2）；本系统不实现效果叠加与条件判定（第 8 项）。
- 循环依赖：本系统只查询 M10 的阶段（`API-M10-001`），战斗轮次的推进由 M10 的战斗执行器经 M05 编排，两者不互相直接调用，不构成循环依赖（架构案 3.4 第 12 项）。

## 8. 核心流程

### 8.1 行为字母追加与移动打断

- 触发：玩家在战斗界面确认一次行为，M05 的行为提交（`API-M05-003`）受理并进入结算。参与者：本系统、M05、06-85、06-40、单局状态域、日志服务。
- 调用顺序：1 M05 调用 `API-ACTIONSLOT-004`；2 `API-ACTIONSLOT-109` 校验行为登记、字母登记与可受理阶段；3 `API-ACTIONSLOT-101` 经行为契约查询取得本次字母（基础技能取技能类别字母，移动与布置阶段站位调整、容器搜刮、场景交互取 M，撤退与防御待机取其类别字母）；4 槽内存在 M 时 `API-ACTIONSLOT-102` 清空 M 及其之前的全部字母；5 `API-ACTIONSLOT-103` 追加字母并维持容量上限；6 `API-ACTIONSLOT-107` 经 `API-SAVE-009` 提交；7 返回追加结果 `CLS-ACTIONSLOT-005`。
- 状态变化：序列内容、占用与打断待决状态按 3.2 迁移；被拒绝时序列与落库内容保持受理前内容。产生的事件：无（随 M05 的 行为提交完成）。结束条件：追加结果返回且序列已提交到单局状态域。

### 8.2 连携条件判定与释放

- 触发：玩家在技能面板选择连携技能并确认提交。参与者：本系统、M05、06-40、06-85、单局状态域。
- 调用顺序：1 M05 的前置校验侧调用 `API-ACTIONSLOT-002`，`API-ACTIONSLOT-105` 逐连携对照槽尾序列与成本串，返回可释放清单与匹配长度；2 未列为可释放的连携由 M05 拒绝提交，不产生状态变化；3 可释放时 M05 调用 `API-ACTIONSLOT-005`；4 `API-ACTIONSLOT-104` 删除与成本串完全一致的槽尾；5 `API-ACTIONSLOT-103` 追加产出串并维持容量上限；6 `API-ACTIONSLOT-107` 经 `API-SAVE-009` 提交；7 返回本次消耗的成本串与追加的产出串，供 06-40 的继承效果判定与技能呈现取用。
- 状态变化：序列内容与占用按 3.2 迁移；产出串追加后立即参与后续行动的匹配判定，不触发任何自动释放。产生的事件：无（随 行为提交完成）。结束条件：释放结果返回且序列已提交；成本串不匹配或槽内存在 M 的次序待定时拒绝且不落定。

### 8.3 破招打断

- 触发：敌方破招行动命中正在构建连携的我方单位，经 M05 的行为提交结算进入本系统。参与者：本系统、06-90、M05、单局状态域。
- 调用顺序：1 06-90 按行为模板与命中判定给出破招结果；2 M05 在行为提交结算路径调用 `API-ACTIONSLOT-006`；3 `API-ACTIONSLOT-109` 校验打断来源属于破招行动；4 `API-ACTIONSLOT-102` 按移动打断规则清空 M 及其之前的全部字母；5 槽内不存在 M 时按 REQ-ACTIONSLOT-03 判定为不落定，返回未清空并登记原因；6 落定时经 `API-ACTIONSLOT-107` 提交。
- 状态变化：序列内容与占用按 3.2 迁移；打断待决状态回到无待清空字母。产生的事件：无（随 行为提交完成）。结束条件：打断结果返回；未落定时序列保持受理前内容并登记缺口。

### 8.4 序列装配初始化与收束释放

- 触发：M10 的战斗执行器经 `API-M05-001` 启动一次战斗；或战斗收束并退出收尾窗口。参与者：本系统、M05、M10、单局状态域。
- 调用顺序：1 一次战斗的装配顺序在「行动槽序列初始化」步骤调用 `API-ACTIONSLOT-007`；2 `API-ACTIONSLOT-108` 为参战我方单位逐个建立空条目，敌方单位不建立；3 收束后 M05 的收束编排调用 `API-ACTIONSLOT-010`；4 `API-ACTIONSLOT-108` 释放条目与序列内容；5 收束结果为撤退时不释放，条目与内容按 M05 的收束口径保留以便再次进入。
- 状态变化：序列条目 未建立 → 已建立、已建立 → 已释放；所属单局状态域在结算提交完成时释放、开新局时全部重建，释放后本系统不保留序列内容（架构案 6.6、8.3 第 3 条）。产生的事件：无。结束条件：条目集合与最近一次参战编成或收束结果一致。

### 8.5 切面采集与读档重建

- 触发：自动保存的战斗轮次推进节点采集切面；或读档后单局状态域恢复。参与者：本系统、M05、M01 存档服务、M10 阶段状态机。
- 调用顺序：1 M05 的切面采集路径调用 `API-ACTIONSLOT-008`，本系统产出行动槽切面记录 `CLS-ACTIONSLOT-006`（只含序列内容，不含派生结果）；2 记录随单局状态域切面装配并经判别字段式多态序列化入档，单局存档的写入必须原子；3 读档时 M05 的重建路径调用 `API-ACTIONSLOT-009`，`API-ACTIONSLOT-108` 按记录重建条目与序列内容；4 派生结果不重建，匹配判定与提示在查询时即时给出；5 M05 重建战场与时间轴并把战斗恢复到最近一次行动机会开始的时刻，该次行动机会内尚未确认的选择不恢复（架构案 5.2.2、7.1、9.3）。
- 状态变化：切面记录 已采集 → 已装载；序列条目 未建立 → 已建立。产生的事件：无（存档服务发布 自动保存完成、存档恢复完成，归 M01）。结束条件：序列内容等于记录内容，恢复后查询与判定可正常工作。

### 8.6 界面取数与提示刷新

- 触发：界面栈打开战斗界面（`API-M08-001`），或收到 行为提交完成、轮次推进 后刷新，或玩家点选其他单位查看。参与者：M08、本系统、M05、06-40、06-85。
- 调用顺序：1 M08 按战斗界面取数契约（`API-BATTLE-008`）取得行动槽区块的取数归属；2 调用 `API-ACTIONSLOT-001` 取当前行动者或选中单位的序列快照（含打断待决状态）；3 调用 `API-ACTIONSLOT-002` 取连携条件达成情况；4 调用 `API-ACTIONSLOT-003` 取下一步提示；5 技能面板的可执行行为可用性由 M05 与 06-85 的口径给出，本系统不提供行为清单。
- 状态变化：界面呈现随数据刷新；界面不改变任何游戏状态，其他单位标注为不可操作状态。产生的事件：无。结束条件：行动槽区块显示字母序列、M 的位置与打断范围依据、连携达成情况与提示，且不携带写入口。

## 9. 异常与边界情况

| # | 情形 | 判定条件 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 阶段不可受理 | 当前阶段为收尾窗口阶段或结算阶段 | `API-ACTIONSLOT-004`、`API-ACTIONSLOT-005`、`API-ACTIONSLOT-006` 拒绝受理，序列与落库内容不变，记日志（架构案 6.6） |
| 2 | 行为未登记或字母字段为空 | 行为标识不在 06-85 行为表内，或其行动槽字母字段为空、为待定义 | 拒绝追加，不消耗行动机会与字母；撤退与防御待机的类别归属按 REQ-ACTIONSLOT-04 补齐前不落定 |
| 3 | 单位无序列条目 | 单位标识未建立条目（敌方单位、非参战单位、装配未完成） | 查询返回未建立；追加、释放与打断拒绝受理，由 `API-ACTIONSLOT-007` 或 `API-ACTIONSLOT-009` 按装配或记录建立 |
| 4 | 成本串不匹配 | `API-ACTIONSLOT-105` 判定槽尾序列与成本串不完全一致 | 拒绝释放，序列不变，行动机会与道具不消耗（06-85 §3.5） |
| 5 | 槽内存在 M 时的连携释放 | 待打断状态下收到的释放请求判定为可释放 | 先后次序按 REQ-ACTIONSLOT-02 补齐前不落定，拒绝受理并记日志 |
| 6 | 破招命中而槽内无 M | `API-ACTIONSLOT-006` 收到的序列不含字母 M | 清空范围按 REQ-ACTIONSLOT-03 补齐前不落定，返回未清空并记日志 |
| 7 | 满槽追加 | 追加后占用超过容量上限 | 只保留最近的容量上限个字母，被挤出的字母在追加结果中列出（F-ACTIONSLOT-07） |
| 8 | 同一行动机会重复追加 | 同一单位的同一行动机会内收到第二次追加请求 | 幂等拒绝，序列不变并记日志；行动机会的用尽由 M05 判定 |
| 9 | 未确认或已取消的行为 | 提交来源不是已确认提交的行为结果 | 拒绝受理，序列、行动机会与道具均不变化（06-85 §3.4） |
| 10 | 字母不在登记内 | 待追加字母不在 06-85 与 06-40 的登记内 | 拒绝追加并记日志；不得以默认字母或占位字母代替 |
| 11 | 边界字段待补充 | 成本串长度上限缺失或成本串超上限 | 匹配与释放返回口径缺失，不自行约定上限，按 REQ-ACTIONSLOT-01 补齐；相关接口不得以默认值代替登记值 |
| 12 | 落库提交被拒 | `API-SAVE-009` 拒绝或失败 | 本次变更不落库，返回值标记失败，序列回退到受理前内容并可重试 |
| 13 | 切面装载期间的状态写入 | 单局状态域处于装载或恢复期间 | 拒绝受理；恢复完成后按记录重建条目与序列内容 |
| 14 | 装载记录与参战编成不一致 | 记录内出现本次编成之外的单位，或缺少编成内单位 | 缺失单位按空序列建立并记日志；多余单位不建立条目，避免跨战斗串档 |
| 15 | 撤退收场 | 收束结果为撤退 | 不释放条目与序列内容，按 M05 的收束口径保留未结状态，供再次进入；再次进入时的续战恢复口径见 REQ-M05-03 |
| 16 | 重复装配或重复释放 | 同一战斗重复调用 `API-ACTIONSLOT-007` 或 `API-ACTIONSLOT-010` | 已建立条目不重置内容；已释放条目重复释放幂等返回 |
| 17 | 提示无可继续项 | 槽尾序列不是任何连携成本串的前缀 | 返回空提示，不伪造候选项，不给出自动释放建议 |
| 18 | 派生结果被当作数据来源 | 有模块以匹配判定结果或提示作为自身数据来源，或采集内容混入派生结果 | 拒绝该用法；派生项按来源重建、不入档（架构案 8.2 第 3 条） |
| 19 | 单局状态域已释放 | 结算提交完成进入局外阶段后收到序列读取或变更请求 | 返回失败结果，不隐式创建序列条目与域内容；单局状态域在开新局时全部重建（架构案 6.6、8.3 第 3 条） |
| 20 | 进程终止 | 玩家主动退出、强制关闭、平台关闭或异常终止（同一口径处理） | 不执行销毁序列、不提交存档、不触发任何退出回调驱动的流程；序列以最近一次自动保存的战斗轮次推进节点提交结果为准（架构案 6.4、9.4；设计决策记录决策 89） |

## 10. 实现约束

### 10.1 实现约束条目

- 行动槽序列只能有一个所有者：本系统。任何模块不得持有序列的可变引用，也不得直接改写单局状态域内的序列内容（架构案 3.4 第 5 项、8.2）。
- 字母与行动机会消耗的权威登记在 06-85，成本串与产出串的权威定义在 06-40；本系统不得登记字母含义、不得内置字母表、不得复制串内容作为自身数据来源（架构案 5.2.4）。
- 序列必须可序列化并随单局状态域切面入档；存档序列化采用**判别字段式多态序列化**：序列化结果中只出现自定义的字符串判别值、**不写入运行时类型名**，多态类型按判别值映射，不接受任意类型名；不得使用已被运行时移除实现的二进制序列化机制；单局存档的写入必须原子（写临时文件后原子替换，提交过程中断时整次作废并保留上一份有效存档）；匹配判定结果、下一步提示、追加结果与打断待决状态属派生项，只按来源重建，不入档、不作为数据来源（架构案 5.3 第 4 项、7.1、8.6 第 8 条）。
- 序列的一切变更必须经本系统的接口，落库必须经单局状态域的提交入口；本系统不得自行序列化状态或读写存档文件（架构案 3.4 第 6 项、7.1）。
- 容量上限、成本串长度上限与连携数量上限必须取自行动槽边界登记（其运行期权威载体是引擎编辑器内的配置资产，设计库的表是初始素材与迁移来源，程序侧不直接读表），不得在接口内写死，也不得另立一套口径（架构案 5.1、7.9、8.6 第 10 条）。
- 追加与打断必须共用同一套清空规则：待打断状态下执行的任何行动都先清空 M 及其之前的字母；破招打断与移动打断必须同源（06-50 §3.4、06-90 §3.2）。
- 连携释放的判定只以「槽尾序列与成本串完全一致」为通过口径，不得提供部分匹配通过或自动释放的路径（F-ACTIONSLOT-04、F-ACTIONSLOT-05）。
- 单位不能选择不追加字母：凡在战斗阶段完成并提交的行为，其字母追加一律执行，不设跳过开关（06-50 §3.1）。
- 本系统不得实现效果叠加，也不得实现条件判定；连携与继承效果由 06-40 与 M09 求值（架构案 3.4 第 8 项、7.11）。
- 本系统不得推进世界时间、不得创建随机源（架构案 3.4 第 9、10 项）。
- 序列变更不单独发布跨模块事件；对外告知随 M05 的 行为提交完成。跨模块事件的契约以**类型契约**的形式确定并以**一条对账测试**强制：需要新事件时按即用即定在事件契约登记表内直接补一行；事件名不在登记表内属契约缺口，由对账测试在测试期发现，不在运行期拦截（架构案 4.3、7.6、8.4 第 2 条）。
- 界面取数只提供只读快照与提示内容，不含写入口与数据本体副本；界面不得经本系统修改任何游戏数据（架构案 3.4 第 3 项）。
- 本系统的规则侧随 M05 的成员系统由常驻场景承载，由启动物体按单元装配声明顺序在初始化序列第 3 步显式初始化并按逆序销毁；不得自行创建单元实例，也不得静态单例就地取用其他单元（架构案 2.4.1、6.1 阶段 3、7.11、8.3 第 1 条）。
- 序列条目随战斗收束释放，撤退收场时按 M05 的收束口径保留；所属单局状态域在结算提交完成时释放、开新局时全部重建，释放后不得隐式重建域内容（架构案 5.2.2、6.6、8.3 第 3 条）。
- 待上游补充的字段（成本串长度上限、字母编码与撤退防御待机的类别归属、破招清空范围、槽内存在 M 时的释放次序）为空或未定时，相关接口必须返回拒绝或口径待定，不得取默认值（REQ-ACTIONSLOT-01 至 REQ-ACTIONSLOT-05）。

### 10.2 实现要求

- I-ACTIONSLOT-01 序列必须按参战我方单位逐个建立独立条目，敌方单位不建立条目。
- I-ACTIONSLOT-02 序列必须可序列化并随单局状态域切面入档；存档序列化采用**判别字段式多态序列化**，序列化结果中只出现自定义的字符串判别值、不写入运行时类型名，多态类型按判别值映射；不得使用已被运行时移除实现的二进制序列化机制；单局存档的写入必须原子；匹配判定结果、下一步提示、追加结果不得入档（架构案 5.3 第 4 项、7.1、8.6 第 8 条）。
- I-ACTIONSLOT-03 序列变更必须经 `API-ACTIONSLOT-004`、`API-ACTIONSLOT-005`、`API-ACTIONSLOT-006`，条目维护必须经 `API-ACTIONSLOT-007`、`API-ACTIONSLOT-009`、`API-ACTIONSLOT-010`；其他模块只读。
- I-ACTIONSLOT-04 落库必须经单局状态域的提交入口，本系统不得自行序列化或读写存档文件。
- I-ACTIONSLOT-05 字母取值必须经 06-85 的行动槽字母登记与 06-40 的技能类别取得，本系统不得内置或推断字母。
- I-ACTIONSLOT-06 成本串与产出串必须经 06-40 的定义查询取得，不得复制为自身数据源。
- I-ACTIONSLOT-07 连携释放必须要求成本串与槽尾序列完全一致，不得提供部分匹配或自动释放。
- I-ACTIONSLOT-08 容量上限、成本串长度上限与连携数量必须取自 `CLS-ACTIONSLOT-002`（其运行期权威载体是引擎编辑器内的配置资产，程序侧不直接读表），缺失时相关接口返回口径缺失而非默认值。
- I-ACTIONSLOT-09 待打断状态下的追加必须先清空 M 及其之前的全部字母；破招打断与移动打断共用同一清空规则。
- I-ACTIONSLOT-10 收尾窗口阶段与结算阶段不得追加、释放、打断或维护序列条目。
- I-ACTIONSLOT-11 本系统不得实现效果叠加与条件判定，不得推进世界时间、不得创建随机源。
- I-ACTIONSLOT-12 序列变化不得单独发布跨模块事件，对外告知随 M05 的 行为提交完成。
- I-ACTIONSLOT-13 界面取数接口不得携带写入口与数据本体副本，其他单位序列一律按只读返回。
- I-ACTIONSLOT-14 待上游补充的字段未定时的相关请求必须拒绝或返回口径待定，不得按默认值落定。
- I-ACTIONSLOT-15 不得重复实现引擎已提供的能力：对象池与集合池、异步任务、设备到动作的输入映射、音频与本地化与特效动画的播放原语、资产载体与序列化原语、资源加载、场景装卸与日志通道一律使用引擎提供的能力，项目只做架构案 7.12「项目实现」栏登记的部分（架构案 7.12、8.6 第 1 条）。
- I-ACTIONSLOT-16 行动槽序列等权威游戏状态由普通 C# 对象持有，引擎对象只承担承载、呈现与编辑器配置职责；不得把权威状态放在随场景销毁的对象上，界面与表现对象不得持有序列的权威副本（架构案 3.4 第 14 项、8.6 第 2 条）。
- I-ACTIONSLOT-17 不依赖引擎的启动回调顺序、脚本执行顺序或帧回调顺序满足初始化与推进的顺序要求；顺序由单元装配声明与显式调用序列决定（架构案 6.1、6.3、8.6 第 4 条）。
- I-ACTIONSLOT-18 本系统在初始化时显式复位自身状态，不依赖引擎的域重载提供初始状态（架构案 6.1、8.3 第 7 条、8.6 第 5 条）。
- I-ACTIONSLOT-19 影响游戏状态的判定不得使用帧时间；本作为半回合制，玩家不操作时游戏状态不推进，**不设暂停概念**，任何模块不得以暂停为由冻结序列或引入暂停语义（架构案 3.4 第 16 项、7.4、8.6 第 6 条；设计决策记录决策 87、88）。
- I-ACTIONSLOT-20 空间判定归玩法侧的网格与坐标逻辑，物理与动画只用于表现；行动槽序列是权威数据，表现对象与数据对象分离，界面与表现不得回写序列（架构案 8.6 第 7 条）。
