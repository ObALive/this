## 1. 系统定义

本单元系统 ID：`SYS-EFFECT-001`。主模块 M09 全局能力，层级 L3；战斗内的效果结算时机归 M05。

### 1.1 系统目的

为全游戏提供唯一的增益、减益与状态表达：道具、装备、遗物、技能等来源产生的效果以同一模型登记、施加、移除与求值，使同名判定、叠加与生命周期在全部系统之间可复现。

### 1.2 系统职责

- 维护元效果定义（`75_元效果表.csv` 记录）的内存形态与登记校验结果；
- 持有并维护承载对象名下的元效果实例与效果来源绑定；
- 受理效果的施加、移除与来源状态同步，作为 M09 的全局效果服务对全部领域与逻辑模块开放；
- 执行同名判定、强度方向解释与叠加生效项求值，给出按结算层组织的求值结果；
- 维护效果实例的生命周期状态（已施加、生效、保留、已移除）；
- 声明效果相关数据在单局存档中的切面内容与读档后的重建步骤；
- 发布效果附加与效果移除事件。

### 1.3 系统边界

本系统不负责：

- 效果的业务语义与数值取值：来源系统定义某件物品或某个技能提供什么效果，数值由数值侧给出，本系统只登记与求值；
- 战斗内的结算时机与层内结算执行：归 M05 战斗（战斗内结算时机，`API-M05-103`，M05 内部功能、不对外暴露；本系统只按其给出的时点取用）；
- 条件判定：归 M09 的条件求值服务（`API-M09-004 条件判定`），引用侧由触发条件系统定义；
- 物品状态写入：归 M09 的物品与经济写入服务（`API-M09-005 物品变更提交`）；
- 效果来源对象的持有、启停状态维护与效果清单内容产出：归各来源系统与内容设计；
- 界面呈现与文案投放：归 M08 界面与信息；
- 存档文件的读写、序列化与恢复顺序驱动：归 M01 的存档服务；
- 世界时间推进与随机抽取：归 M01 的时间服务与随机服务。

## 2. 数据定义

### 2.1 本系统拥有的数据

### 2.3 数据关系

- 元效果定义与元效果实例：一对多，实例以效果标识引用定义；
- 效果来源绑定与元效果实例：一对多，一个来源的一次同步产生的实例归入同一绑定；
- 承载对象与元效果实例：一对多，一个承载对象名下可同时存在多个不同名效果与多份同名效果；
- 效果生效判定结果：派生自承载对象名下的实例与来源绑定状态，不反向成为来源数据（架构 8.2 第 3 条）。

### 2.4 数据生命周期

- 元效果定义：启动阶段加载，运行期只读，进程退出时销毁；
- 元效果实例与效果来源绑定：随施加创建，在单局内跨事件、跨战斗存续，随移除销毁，本局结束时随单局状态域废弃；
- 效果生效判定结果：求值时建立，来源状态或实例发生变化时失效，读取时按来源重建；
- 待上游补充：战斗外可生效标记为「否」的效果在战斗结束时的处理，见缺口 REQ-EFFECT-04。

### 2.5 持久化要求

| 数据 | 是否入档 | 切面归属 | 恢复方式 |
| --- | --- | --- | --- |
| `CLS-EFFECT-001` | 否 | 静态配置 | 启动阶段加载；配置版本标识随单局存档校验 |
| `CLS-EFFECT-002` | 是 | 单局存档（单局状态域切面） | 随单局状态域装载；派生结果按来源重建 |
| `CLS-EFFECT-003` | 是 | 单局存档（单局状态域切面） | 随单局状态域装载 |
| `CLS-EFFECT-004` | 否 | 无 | 按来源重建，不入档 |

1. 效果实例与来源绑定只经 M01 的存档服务采集与装载，本系统不读写存档文件、不自行序列化状态；
2. 本系统在恢复顺序中的位置是「重建派生缓存」一步（架构 9.3），由 `API-EFFECT-002` 触发；重建不重新施加效果、不发布事件、不重新抽取随机结果；
3. 战斗的未结状态中包含元效果与其来源（`50_存档与持久化设计.md` §3），读档恢复到最近一次行动机会开始的时刻，该次行动机会内尚未确认的效果变化不恢复。

## 3. 状态定义

### 3.1 状态

| 对象 | 状态 | 取值 |
| --- | --- | --- |
| `CLS-EFFECT-002` 元效果实例 | 生命周期状态 | 已施加、生效、保留、已移除 |
| `CLS-EFFECT-003` 效果来源绑定 | 来源登记状态 | 已登记、停用、已注销 |
| `CLS-EFFECT-004` 效果生效判定结果 | 派生有效性 | 有效、失效 |

生效指同名效果中强度最高、参与结算的一条；保留指同名比较中未被选中、保留在承载对象上但不参与结算的条目。

### 3.2 状态转换

```
元效果实例：已施加 → 生效
            已施加 → 保留
            生效  ↔ 保留
            生效  → 已移除
            保留  → 已移除
来源绑定：  已登记 → 停用 → 已登记
            已登记｜停用 → 已注销
派生结果：  失效 → 有效
            有效 → 失效
```

### 3.3 状态转换触发条件

| 转换 | 触发条件 | 对应接口 | 产生的事件 |
| --- | --- | --- | --- |
| 已施加 → 生效 | 施加或同步后，该实例在同名条目中强度最高 | `API-M09-001`、`API-EFFECT-001` | 效果附加 |
| 已施加 → 保留 | 施加或同步后，同名条目中存在更高强度项 | `API-M09-001`、`API-EFFECT-001` | 效果附加 |
| 生效 ↔ 保留 | 同名声明的施加、移除或来源变更引发重新比较 | `API-M09-001`、`API-M09-002`、`API-EFFECT-001` | 无（随引发它的施加或移除一并发布） |
| 生效／保留 → 已移除 | 来源停用、持续结束、被消耗、动作结算结束、来源注销 | `API-M09-002`、`API-EFFECT-001` | 效果移除 |
| 已登记 → 停用 | 来源系统同步来源停用状态 | `API-EFFECT-001` | 效果移除（逐项） |
| 停用 → 已登记 | 来源系统同步来源启用状态 | `API-EFFECT-001` | 效果附加（逐项） |
| 已登记｜停用 → 已注销 | 来源名下实例全部移除或来源对象销毁 | `API-M09-002`、`API-EFFECT-001` | 效果移除（若仍有剩余实例） |
| 失效 → 有效 | 求值或派生结果重建 | `API-M09-003`、`API-EFFECT-002` | 无（只读求值不产生事件） |
| 有效 → 失效 | 元效果实例或来源绑定发生变化 | `API-M09-001`、`API-M09-002`、`API-EFFECT-001` | 无 |

| API-M09-002 | 效果移除（定义方 M09，契约见 M09 模块单元文档 §4.2） | 战斗系统、技能与库存联动、装备系统、遗物系统、技能系统 | 承载对象标识、移除定位、移除原因 | 移除结果 | 实例 → 已移除；生效项重算；来源绑定按需注销 | 发布效果移除事件 |
| API-M09-003 | 效果求值（定义方 M09，契约见 M09 模块单元文档 §4.2） | M05 战斗、M07 角色与小队、M08 界面与信息、M10 流程编排、来源系统 | 承载对象标识、求值上下文（战斗内外、结算层、用途） | 按结算层组织的求值结果 | 派生结果：失效 → 有效 | 无 |
| API-EFFECT-001 | 来源状态同步 | 装备系统、遗物系统、技能系统、技能与库存联动 | 来源标识与来源类别、来源启停状态、来源当前的效果登记 | 同步结果 | 来源绑定：已登记 ↔ 停用；实例按差额施加与移除 | 按差额发布效果附加与效果移除事件 |
| API-EFFECT-002 | 派生结果重建 | M01 存档服务 | 重建范围 | 重建结果 | 派生结果：失效 → 有效 | 无 |

`API-M09-001` 至 `API-M09-003` 的契约落点唯一（约定 §三.5、附录 A；`Code_Design/00-架构单元/M09_全局能力代码设计案.md` §4.2）：本文档按 ID 引用，只登记本系统在这三项能力上承载的效果语义与数据落点，不复述其契约，同一对象不在两处定义。

### 4.2 接口详细定义

本系统自有的对外接口为 `API-EFFECT-001`、`API-EFFECT-002`，其八项契约见本节后两段。`API-M09-001` 至 `API-M09-003` 的契约落点在 M09 模块单元文档（见 4.1 末注），本节只按引用登记本系统侧的效果语义要点。

#### 引用的公共能力：`API-M09-001` 效果施加（定义方 M09，契约见 `M09_全局能力代码设计案.md` §4.2）

本系统侧语义要点：
- 登记粒度：同一来源与同一效果在同一承载对象上只有一份实例；重复施加按更新既有实例处理，不新增第二份、不重复发布事件；
- 登记前置：效果标识必须已在 `75_元效果表.csv` 的登记清单内且 Demo 状态不是「待补充」，否则按未登记拒绝并写内容日志；
- 同名与强度：施加后按效果标识归并同名条目，按强度方向把数值解释为强度，缺少方向配置时按数值越高效果越强；最高强度项为生效项，其余为保留项且不参与结算；
- 生命周期：新实例初始为已施加，随同名比较转为生效或保留；来源绑定记录该来源当前产生的实例；
- 派生影响：施加使 `CLS-EFFECT-004` 效果生效判定结果失效，下一次求值按新状态重建；
- 阶段封闭：结算阶段不得创建单局状态域内的对象，施加一律拒绝（架构案 8.3 第 5 项）。

#### 引用的公共能力：`API-M09-002` 效果移除（定义方 M09，契约见 `M09_全局能力代码设计案.md` §4.2）

本系统侧语义要点：
- 移除定位：按实例标识，或按来源标识与效果标识，或按到期与消耗的时点结论；到期与消耗的时点在战斗内归 M05；
- 生效项重算：被移除项为生效项时，剩余同名条目中强度最高的项转为生效项，本系统不代为施加其他来源的效果；
- 来源绑定：来源名下无剩余实例时注销该来源绑定；按来源移除时逐项按同一判定处理；
- 派生影响：移除使 `CLS-EFFECT-004` 失效，并按差额逐项发布效果移除；
- 阶段封闭：结算阶段一律拒绝（架构案 8.3 第 5 项）。

#### 引用的公共能力：`API-M09-003` 效果求值（定义方 M09，契约见 `M09_全局能力代码设计案.md` §4.2）

本系统侧语义要点：
- 只读性：求值不改变任何效果状态、不发布事件，返回按结算层组织的生效项与聚合结果；
- 输入面：承载对象标识与求值上下文（战斗内外、结算层筛选、用途）；调用方声明其所处场合；
- 结算分层：结算层取自 06-10 战斗总览的伤害与结算分层登记；前一层结果确定后才进入下一层，被上层判定为无效或已消耗的效果不进入下层；
- 派生影响：求值使 `CLS-EFFECT-004` 由失效转为有效；派生结果的维护属内部功能，不对外产生可观察状态变化；
- 异常口径：结算层未登记、生效项引用的效果定义缺失、场合与战斗外可生效标记冲突、同名强度比较在非单一数值效果上不可判定时，返回失败原因（见缺口 REQ-EFFECT-01、REQ-EFFECT-05）。

待上游补充：作用对象范围中「全队」的成员范围界定与解析责任方，承接方为系统设计文档（`06-战斗/75-元效果系统` §4 与 `06-战斗/10-战斗总览` §3.2），见缺口 REQ-EFFECT-07；叠加层数的配置字段落点，承接方为系统设计文档（`06-战斗/75-元效果系统` §3.3 与 `75_元效果表.csv` 的叠加规则列），见缺口 REQ-EFFECT-06。

#### API-EFFECT-001 来源状态同步

职责：来源系统提交其当前提供的效果登记与启停状态，由本系统按差额完成施加、更新与移除。

输入：
- 参数输入：来源标识与来源类别、来源启停状态、来源当前提供的效果登记（效果标识、作用对象范围、效果数值、持续信息）；
- 状态输入：该来源在各承载对象上的效果实例与来源绑定；
- 数据输入：`CLS-EFFECT-001`、结算分层登记；
- 外部事件输入：无。

读取：`CLS-EFFECT-001`、`CLS-EFFECT-002`、`CLS-EFFECT-003`、`CLS-EFFECT-004`。

输出：
- 返回值：同步结果，含新增、更新与移除的实例标识、生效项变化与失败原因；
- 状态输出：来源绑定按提交的登记对齐；元效果实例按差额施加、更新与移除；同名生效项重算；派生结果失效；
- 事件输出：效果附加、效果移除（逐项）；
- 外部系统调用：无。

产生的状态变化：来源绑定在已登记与停用之间转换或转为已注销；实例按差额转为已施加、生效、保留或已移除；派生结果由有效转为失效。

前置条件：
- 来源标识与来源类别已给出；
- 提交的是该来源当前的完整效果登记；
- 当前阶段不是结算阶段。

后置条件：
- 该来源在承载对象上的实例与提交的登记一致；
- 提交中不含的项已转为已移除；
- 同名生效项已按剩余条目重算；
- 派生结果失效。

副作用：按差额发布效果附加与效果移除事件。

异常情况：
- 来源标识缺失，或来源类别未登记；
- 来源启停状态为停用而效果登记非空；
- 提交中出现未登记的效果标识或 Demo 状态为「待补充」的条目；
- 同一来源的两次同步重叠（判定条件：上一次同步的结果尚未返回时收到同一来源的同步请求）；
- 当前处于结算阶段。

#### API-EFFECT-002 派生结果重建

职责：在读档恢复或指定范围重建时，按已装载的效果实例与来源绑定重建同名生效判定与求值结果。

输入：
- 参数输入：重建范围（全部承载对象或指定承载对象）；
- 状态输入：已从单局存档装载的元效果实例与来源绑定、当前处于读档恢复流程的标记；
- 数据输入：`CLS-EFFECT-001`、结算分层登记；
- 外部事件输入：无（由存档服务在恢复顺序的「重建派生缓存」一步直接调用）。

读取：`CLS-EFFECT-001`、`CLS-EFFECT-002`、`CLS-EFFECT-003`。

输出：
- 返回值：重建结果，含承载对象数量、生效项数量、无法重建的条目与原因；
- 状态输出：派生结果由失效转为有效；
- 事件输出：无；
- 外部系统调用：无。

产生的状态变化：派生结果由失效转为有效。

前置条件：
- 元效果实例与来源绑定已装载完成；
- 调用来自读档恢复流程或显式的状态重建入口。

后置条件：
- 派生结果与已装载的来源状态一致；
- 不重新施加效果，不发布效果附加与效果移除事件；
- 不产生随机消费。

副作用：无。

异常情况：
- 实例引用的效果定义不存在（配置版本不一致或条目撤销）；
- 实例没有对应的来源绑定（孤立实例）；
- 来源绑定引用的来源类别未登记；
- 重建范围包含不存在的承载对象。

## 5. 内部功能

### 5.1 功能列表

| 功能 | 说明 | 是否对外暴露 |
| --- | --- | --- |
| 效果登记读取 | 经配置服务读取元效果定义与结算分层登记，供施加与求值使用 | 否，经 `API-M09-001`、`API-M09-003` 间接使用 |
| 同名判定与强度解释 | 按效果标识归并同名条目，按强度方向把数值解释为强度 | 否 |
| 生效项重算 | 在同名范围内重新划分生效项与保留项 | 否，由 `API-M09-001`、`API-M09-002`、`API-EFFECT-001` 触发 |
| 叠加聚合 | 对生效项按叠加规则与结算层聚合出求值结果 | 否，经 `API-M09-003` 输出 |
| 生命周期到期判定 | 依据持续信息与调用方给出的时点判定实例是否到期 | 否，结果进入 `API-M09-002` 的移除定位 |
| 来源差额比对 | 以来源提交的登记与现存实例比对，得出应施加、更新与移除的条目 | 否，经 `API-EFFECT-001` 触发 |
| 派生结果维护 | 派生结果的失效标记与按来源重建 | 否，由 `API-M09-003`、`API-EFFECT-002` 触发 |
| 切面内容声明 | 向存档服务声明效果实例与来源绑定的切面内容与重建步骤 | 否，由存档服务按域采集时读取 |

### 5.2 功能之间的关系

- 效果登记读取是同名判定、强度解释与求值的前置；
- 同名判定与强度解释在每次施加、移除与来源同步后执行，其结果驱动生效项重算；
- 生效项重算是叠加聚合的输入，叠加聚合只由 `API-M09-003` 触发，不改变实例与绑定；
- 生命周期到期判定由调用方时点驱动，战斗内的时点归 M05，判定结果进入 `API-M09-002` 的移除定位；
- 来源差额比对是 `API-EFFECT-001` 的内部步骤，产出的施加与移除两个方向复用 `API-M09-001` 与 `API-M09-002` 的同一套判定；
- 派生结果维护由施加、移除、来源同步与重建共同驱动；`API-EFFECT-002` 只重建，不施加。

- `API-M01-001 服务容器.Register`：启动阶段登记本单元的能力与依赖声明；
- `API-M01-002 服务容器.Resolve`：解析配置服务、事件分发器、日志服务、时间服务、存档服务与阶段查询；

### 6.4 使用方式

- 启动阶段：经服务容器登记并解析依赖，经配置服务读取元效果定义与结算分层登记；登记校验由配置服务在启动阶段统一执行；
- 运行期：施加、移除、来源同步与求值均为直接调用并同步返回，不采用异步；
- 事件侧：效果附加与效果移除经事件分发器发布，发布方不感知订阅方；时间刻度变化经订阅获得，作为战斗外限时效果的到期输入；
- 恢复期：由存档服务在恢复顺序的「重建派生缓存」一步调用 `API-EFFECT-002`；
- 只读取用：属性标识与结算分层登记按同层只读查询取用，不在本系统留存为来源数据（架构 8.2 第 3 条）。

### 6.5 依赖方向限制

- 允许：本系统属 L3，依赖 M01（架构 3.3 第 9 行）、查询 M10 的当前阶段（架构 3.3 第 12 行）、同层只读查询 06-10 的属性标识与结算分层登记（架构 8.1 第二句的同层只读查询）；
- 被依赖：M09 的三处统一入口对全部游戏逻辑与领域模块开放（架构 3.3 第 8 行）；本系统的施加与移除是效果状态变化的唯一入口（架构 3.4 第 8 项）；界面经 M08 只读取用求值结果；
- 禁止：不反向依赖调用方（架构 3.4 第 12 项）；不持有来源系统的可变引用（架构 3.4 第 5 项）；不自行实现条件判定、物品写入、随机、世界时间推进、日志、事件分发与存档读写（架构 3.4 第 6、7、8、9、10 项与第 7 章）；
- 环：本系统与任何模块之间不存在双向调用；来源系统与战斗系统单向调用本系统；
- 战斗内结算时机由 `API-M05-103`（M05 战斗，内部功能）定义并由 M05 驱动，本系统不自持结算时机。

| --- | --- | --- | --- | --- |
| 效果附加 | 本系统发布 | 实例登记为生效或保留后 | 承载对象标识、效果标识、来源标识、实例标识、生效项变化 | 订阅方处理失败不回滚施加结果 |
| 效果移除 | 本系统发布 | 实例转为已移除且同名生效项重算完成后 | 承载对象标识、效果标识、来源标识、实例标识、移除原因、生效项变化 | 订阅方处理失败不回滚移除结果 |
| 时间刻度变化 | 本系统订阅（M01 发布） | 世界时间推进一步 | 刻度位置 | 本系统不因订阅处理失败回滚发布方状态 |

不发未登记事件；跨模块状态广播一律经 M01 的事件分发器（架构 8.4 第 1、2 条）。

### 7.3 数据流

```
来源系统（装备／遗物／道具／技能／场景）
        │ 来源效果登记与启停（API-EFFECT-001）或直接施加（API-M09-001）
        ▼
单局状态域：元效果实例与效果来源绑定 ──派生──▶ 效果生效判定结果
        │                                              │
        │ 移除（API-M09-002）                          │ 求值（API-M09-003）
        ▼                                              ▼
事件：效果附加／效果移除                    M05 结算取用、M07 属性取值、M08 界面呈现
        │
        ▼
单局存档（经 M01 存档服务采集）──读档──▶ API-EFFECT-002 重建派生结果（不入档）
```

元效果定义与结算分层登记取自静态配置，只读进入施加与求值。

## 8. 核心流程

### 8.1 装备穿卸驱动的效果同步

- 触发：玩家装备或卸下一件提供元效果的物品，或遗物进入与离开遗物槽；
- 参与者：装备系统（06-60）、遗物系统（06-70）、本系统、事件分发器；
- 调用顺序：来源系统在换装生效后调用 `API-EFFECT-001`，提交该来源当前的效果登记与启停状态 → 本系统完成来源差额比对 → 新增与更新项按施加判定登记，未再出现的项按移除定位处理 → 同名生效项重算；
- 状态变化：来源绑定登记或转为停用；元效果实例新增、更新或转为已移除；派生结果失效；
- 产生的事件：效果附加、效果移除，逐项经事件分发器发布；
- 结束条件：该来源在承载对象上的实例与其提交的登记一致，且生效项判定完成。

### 8.2 技能释放施加效果与同名重算

- 触发：技能释放或投掷落点结算需要以元效果表达效果；
- 参与者：技能系统（06-40）、技能与库存联动（06-80）、战斗系统、本系统；
- 调用顺序：调用方确定作用对象范围与效果数值后调用 `API-M09-001` → 本系统读取元效果定义与结算分层登记 → 登记元效果实例 → 按效果标识归并同名条目、按强度方向解释强度、选出最高强度项为生效项、其余为保留项 → 发布事件并返回施加结果；
- 状态变化：实例由已施加转为生效或保留；已生效的项可能转为保留；派生结果失效；
- 产生的事件：效果附加；
- 结束条件：施加结果返回，且生效项与保留项划分完成。

### 8.3 战斗内按结算层取用效果

- 触发：战斗内伤害结算、属性取值或状态判定需要读取当前生效效果；
- 参与者：M05 战斗（06-85、06-90、06-A0）、M07 角色与小队、本系统；
- 调用顺序：调用方在自身的结算时机调用 `API-M09-003`，给出承载对象、战斗内场合与结算层 → 本系统按层组织生效项与聚合结果返回 → 调用方在层内完成伤害、状态与属性结算；被上层判定为无效或已被消耗的效果不进入下层，其移除由调用方按结算结果调用 `API-M09-002`；
- 状态变化：仅派生结果由失效转为有效，元效果实例与来源绑定不变；
- 产生的事件：无；
- 结束条件：调用方取得该层求值结果并完成自身结算。

### 8.4 投掷效果的一次性移除

- 触发：投掷行为结算结束；
- 参与者：技能与库存联动（06-80）、战斗行为系统（06-85）、本系统、事件分发器；
- 调用顺序：投掷结算完成 → 调用方以动作结算结束为移除原因调用 `API-M09-002` → 本系统把对应实例转为已移除、按需注销来源绑定、在同名范围内重算生效项 → 发布事件；
- 状态变化：实例转为已移除；同名剩余条目中强度最高项转为生效；派生结果失效；
- 产生的事件：效果移除；
- 结束条件：投掷效果不再出现在承载对象名下。

### 8.5 读档恢复后的派生结果重建

- 触发：读档流程进入恢复顺序的「重建派生缓存」一步；
- 参与者：M01 存档服务、本系统、单局状态域；
- 调用顺序：存档服务按域恢复世界状态域、单局状态域与玩家状态域 → 元效果实例与来源绑定随单局状态域装载 → 存档服务调用 `API-EFFECT-002` → 本系统按已装载的来源状态重建同名生效判定与求值结果；
- 状态变化：派生结果由失效转为有效；
- 产生的事件：无（重建不构成新的状态变化）；
- 结束条件：重建范围内的承载对象全部完成，无法重建的条目按异常上报。

## 9. 异常与边界情况

| # | 情形 | 判定条件 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 效果标识未登记 | 施加或来源同步提交的效果标识不在元效果表中 | 施加或同步失败，返回失败原因，不改变任何状态，不发布事件 |
| 2 | 登记条目为待补充 | 效果定义的 Demo 状态为「待补充」 | 按未登记处理，写内容日志 |
| 3 | 承载对象无效 | 作用对象范围为空，或承载对象标识不存在 | 施加失败，返回失败原因，不产生部分提交 |
| 4 | 重复施加 | 同一来源与同一效果在同一承载对象上已有实例 | 更新既有实例的数值，不新增实例，不重复发布效果附加事件 |
| 5 | 重复移除 | 实例不存在或已处于已移除 | 移除失败，返回失败原因，不发布事件 |
| 6 | 归属不匹配 | 移除定位给出的实例不属于该承载对象 | 判定为非法输入，移除失败 |
| 7 | 结算阶段请求 | 阶段查询返回结算阶段 | 施加与移除均拒绝，返回失败原因（架构 8.3 第 5 条） |
| 8 | 场合与标记冲突 | 战斗外求值，而该效果定义的战斗外可生效为「否」 | 该项不进入求值结果，写运行日志 |
| 9 | 结算层未登记 | 求值上下文给出的结算层不在结算分层登记中 | 求值失败，返回失败原因，见缺口 REQ-EFFECT-01 |
| 10 | 计时口径缺失 | 限时效果的持续信息缺少可判定的计时口径 | 到期判定不上报，移除请求拒绝，写内容日志，见缺口 REQ-EFFECT-03 |
| 11 | 来源停用却提交登记 | 同步请求的启停状态为停用且效果登记非空 | 同步失败，返回失败原因，保留既有实例 |
| 12 | 恢复期孤立实例 | 装载后的实例没有对应的来源绑定 | 该实例不参与生效判定，按异常上报，由存档服务与内容侧定位来源缺失 |
| 13 | 配置版本不一致 | 实例引用的效果定义在本次配置中不存在 | 同上，按孤立实例处理并写内容日志 |
| 14 | 依赖不可用 | 配置服务或阶段查询不可用 | 请求失败并返回失败原因，不产生状态变化；本系统不停机 |
| 15 | 重叠同步 | 上一次来源同步的结果尚未返回时收到同一来源的同步请求 | 判定为并发修改，后一次请求失败并返回失败原因 |

## 10. 实现约束

1. 元效果定义与元效果实例必须分离：定义属静态配置、运行期只读，实例属单局状态域、按局重置；
2. 效果的施加、移除与来源同步必须经 `API-M09-001`、`API-M09-002`、`API-EFFECT-001`，其他系统不得直接改效果记录；效果是唯一的效果表达方式，不得另立效果表达机制；
3. 效果实例与来源绑定必须可序列化并入单局存档，切面归属单局状态域；本系统不读写存档文件、不自行序列化；
4. 派生结果按来源重建，不入档，不作为数据来源；任何读取方不得把求值结果缓存为自己的数据（架构 8.2 第 3 条）；
5. 求值必须是无副作用的只读能力；实例或来源状态变化后派生结果必须失效，下一次求值按新状态重建；
6. 效果标识必须取自元效果表的登记清单；表中的「待补充」条目不得进入施加与求值；
7. 效果数值由调用方按来源配置给出，本系统不自行推导数值、不重新解释游戏规则；
8. 战斗内效果的结算时机由 M05 决定，本系统只提供施加、移除与求值，不自行推进战斗内结算时点；
9. 本系统不得自行实现条件判定、物品写入、随机、世界时间推进、日志与事件分发，一律经 M09 的相应服务与 M01 的基础设施；
10. 跨模块状态广播只经事件分发器发布效果附加与效果移除，不自行实现观察者；
11. 本系统不得持有来源系统、承载对象所属系统的可变引用，只保存标识；
12. 同名判定必须在效果记录或来源状态每次变化后保持可复现：同一已提交状态下的求值结果必须一致。

## 附录：功能要求与实现要求

### 功能要求

- `F-EFFECT-01` 道具、装备、遗物与技能提供的效果必须以同一模型表达，效果的表达与结算方式一致；
- `F-EFFECT-02` 同名效果只生效强度最高的一条，其余条目保留但不重复结算；
- `F-EFFECT-03` 同名比较先按各效果自身的强度方向把数值解释为强度；缺少方向配置时按数值越高效果越强处理；
- `F-EFFECT-04` 不同名效果正常叠加，叠加层数由配置控制，系统层不设叠加上限；
- `F-EFFECT-05` 有效项被移除后立即重新计算，并从剩余条目中启用强度最高的一条；
- `F-EFFECT-06` 效果生命周期随来源配置：随装备启停的效果在卸下时移除，限时效果在持续时间结束时移除，投掷类效果在动作结算结束时一次性移除，技能继承效果与技能配置同生命周期并在基础技能被替换时重算；
- `F-EFFECT-07` 需要在战斗外生效的效果在角色状态中保留并随角色写入存档；
- `F-EFFECT-08` 结算按层处理，前一层结果确定后才进入下一层，被上层判定为无效或已被消耗的效果不进入下层；
- `F-EFFECT-09` 诅咒与普通负面词条共用同一判定通道，不做区分处理；
- `F-EFFECT-10` 全队范围的效果随来源启停对全队同步生效与移除。

### 实现要求

- `I-EFFECT-01` 每个效果必须能够通过效果标识唯一定位其定义，未登记的效果标识不得施加；
- `I-EFFECT-02` 元效果定义与元效果实例必须分离，实例以效果标识引用定义；
- `I-EFFECT-03` 其他系统不得直接修改效果实例与来源绑定，必须经本系统提供的接口修改；
- `I-EFFECT-04` 效果实例与来源绑定落在单局状态域，本系统是该数据的唯一变更入口；
- `I-EFFECT-05` 生效判定结果按来源重建，不入档，不作为数据来源；
- `I-EFFECT-06` 效果相关数据必须经统一存档入口保存与恢复，恢复后按来源重建派生结果，不重新施加效果；
- `I-EFFECT-07` 跨系统交互只经 `API-M09-001` 至 `API-M09-003` 与本系统自有接口，跨模块状态广播只经事件分发器；
- `I-EFFECT-08` 战斗内效果的结算时机由 M05 决定，本系统不自行结算；
- `I-EFFECT-09` 求值必须无副作用，且在同一已提交状态下可复现；
- `I-EFFECT-10` 本系统不得自行实现条件判定、物品写入与随机，条件与物品变更分别经 `API-M09-004` 与 `API-M09-005`。
