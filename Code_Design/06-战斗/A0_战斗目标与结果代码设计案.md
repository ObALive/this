本单元的系统标识为 `SYS-BATTLEGOAL-001` 战斗目标与结果。主模块为 M05 战斗，层级 L3、L4；架构案 2.3 的跨列说明为「结局判定归 M06」。战斗的启动、推进与收束由 M05 模块单元编排（`Code_Design/00-架构单元/M05_战斗代码设计案.md`），本系统提供被其调用的目标装配、进度推进、收束判定与即时判定入口；战斗结果对模块外与事件侧的取数出口是模块能力 `API-M05-004` 战斗结果查询，本系统不另立结果查询接口（约定 §三）。战斗对事件输出的契约只有**结果标识**（术语表 T-131）与**达成目标清单**（术语表 T-130）两项；全队失去行动能力等收尾情形在战斗内**只产生判定并写入战斗结果**，**不在战斗内成立结局**，结局成立的**唯一入口是事件结算环节的事件结果提交**（架构案 3.1 ARC-M05-001 与 ARC-M10-001、6.6 第 3 条、9.5.5；设计决策记录决策 90）。

## 1. 系统定义

### 1.1 系统目的

把一场战斗的目标清单装配成可运行、可入档、可重建的目标条目，在战斗过程中按已提交事实即时更新目标进度与失效判定，并在收束时刻把结束方式、达成目标清单与结果标识一次落定，使战斗以「结果标识 + 达成目标清单」两项输出接入事件流程（设计稿 §1、§3.6；架构案 3.1 ARC-M05-001）。结果标识由结束方式、达成目标的数量与达成的具体目标共同决定；本阶段只固定**结果标识**这一层接口，事件结果配置的字段级结构、存档落点与消费接口留待后续环节（设计决策记录决策 76）。

### 1.2 系统职责

- 装配战斗目标：按战斗配置与事件配置声明的目标清单建立目标条目，登记可见性（术语表 T-129 的显式目标与隐藏目标）、目标对象引用、达成条件与失败条件，并建立判定范围登记；
- 实时维护目标进度：按已提交的行为与状态事实推进目标进度项，对目标对象被提前消灭、指定道具被提前破坏或因其他原因无法达成的情形即时判定该目标失败（设计稿 §3.2）；
- 给出目标预警：按目标定义登记的预警阈值给出预警标记，供界面侧取数与呈现（设计稿 §3.2）；
- 判定收束与产出结果：结束方式取常规、撤退、全队失去行动能力三类；结束方式、达成目标的数量与达成的具体目标共同决定战斗结果标识（术语表 T-131），达成项归集为达成目标清单（术语表 T-130）；撤退成功时把**撤退结果写入战斗结果标识**；结果经 `API-M05-004` 交回事件侧；本系统只写入战斗结果，**不在战斗内成立结局**（设计稿 §3.6；架构案 3.1 ARC-M05-001、6.6 第 3 条；设计决策记录决策 90、92）；
- 即时判定全队失去行动能力：全部我方单位同时处于失去行动能力状态时即时成立并写入战斗结果，供 M10 的事件执行器轮询检出；该情形**只产生判定并写入战斗结果，不在战斗内成立结局**；结局成立的**唯一入口是事件结算环节的事件结果提交**，三种未通关收尾情形统一在该环节成立（设计稿 §3.4；架构案 3.1 ARC-M05-001 与 ARC-M10-001、6.6 第 3 条、9.5.5；设计决策记录决策 90）；
- 判定撤退条件：按配置声明的撤退条件给出行为前置结论，供行为可用性判定与行为提交前置判定取用，不占用行动机会、不消耗资源（设计稿 §3.3；`85_战斗行为表.csv` 的 BHV-RETREAT-001）；
- 声明并重建自身切面：目标条目、达成目标清单与战斗结果入单局存档的单局状态域切面，读档后按记录重建，不重新判定（架构案 5.2.2、5.3）。

### 1.3 系统边界

战斗目标与结果不负责：

- 结局类型与触发起因的判定与写入：归 07-40 局末结算与写入（`API-SETTLE-002`、`CLS-SETTLE-004`）；本系统只输出结束方式与结果标识，不承担结局判定，也不在战斗内成立结局；结局成立的唯一入口是事件结算环节的事件结果提交（架构案 2.3 跨列说明、3.1 ARC-M10-001、6.6 第 3 条、9.5.5；设计决策记录决策 90）；
- 事件流程的编排：事件退出、结算与阶段切换归 M10 的事件执行器与阶段状态机（`API-M10-002`、`API-M10-003`）；结果标识到后续事件与解锁内容的对应关系归 02-30 的事件结果配置（设计稿 §3.6）；该配置的字段级结构与消费接口属悬置项，本系统只按结果标识这一层接口取数（设计决策记录决策 76）；
- 时间推进与净时长换算：世界时间的唯一受理入口是 `API-M01-005`，且只在事件退出时由 M10 提交；战斗净时长以秒累计与按时间段对齐归 M05 的 `API-M05-105`（架构案 7.5、3.4 第 10 项）；
- 战利品与产出：战斗不发放战利品，战利品由玩家在战斗过程中或收尾窗口（术语表 T-123）内搜刮取得，归 06-30 与 05-30；本系统不登记物品与货币变化（设计稿 §3.5）；
- 单位状态的判定与持有：生命状态、伤势档与击倒标记归 06-10 战斗总览（`API-BATTLE-003`、`API-BATTLE-004`）；本系统只取快照并按队伍范围请求聚合结论（`API-BATTLE-005`）；
- 收尾窗口的规则与操作集合：归 06-30 战场与战棋规则（`API-FIELD-010`、`API-FIELD-013`）与 M10 的阶段状态机；本系统不判定是否进入收尾窗口；
- 撤退成功后的地图侧结果：撤退后事件在技术上**仍为可进入**，保留敌人撤退那一刻的状态与位置，玩家可以重新进入，事件状态取值保持未出现、可进入、进行中、已完成、已错过五种，**撤退不新增状态取值**；窗口期延长与周边事件锁定归 M10 的事件执行器按事件配置执行（架构案 9.5.4）；本系统只输出撤退成立的结束依据并把撤退结果写入战斗结果标识（设计决策记录决策 92）；
- 目标的呈现与文案：界面的目标清单呈现、预警提示与结局文案归 M08 与 01-20（架构案 3.4 第 1、3 项）；
- 敌方行为与敌方撤退的判定：归 06-90 敌人与AI（`API-ENEMY-008`）；本系统只受理其结果作为目标判定与结束依据（REQ-BATTLEGOAL-06）；
- 战斗失败后本局的走向与再次挑战：设计稿 §4 写明「战斗失败不结束本局，事件按失败分支继续或直接结束」「同一场战斗在本局内不提供重复挑战」「失败后果由内容配置的失败进入类强制事件兑现」；三条均属事件侧与流程侧规则，承接方为 02-30 事件系统与 M10 流程编排，本系统不落成契约，见缺口 REQ-BATTLEGOAL-09。撤退后的事件状态不属本条：撤退后事件在技术上仍为可进入、玩家可以重新进入，已由设计决策记录决策 92 直接裁定（架构案 9.5.4）。

### 1.5 功能要求

- `F-BATTLEGOAL-01` 战斗目标分显式目标与隐藏目标两类，显式目标在战斗开始时即可知悉，隐藏目标需要玩家在战斗中自行发现或通过事前准备达成（设计稿 §3.1）。
- `F-BATTLEGOAL-02` 任意一个战斗目标达成即结束战斗并触发收束判定与结果落定；目标评价时点统一为战斗结束的时刻（设计稿 §3.2；架构案 6.6）。
- `F-BATTLEGOAL-03` 全部目标均判定失败、我方全队无法继续行动、玩家主动发起撤退并成功三种情况使战斗以失败收场，三种未通关收尾情形统一在事件结算环节成立结局（设计稿 §3.2；架构案 3.1 ARC-M10-001、9.5.5；设计决策记录决策 90）。
- `F-BATTLEGOAL-04` 战斗内不设战斗轮次上限；未达成目标且敌方未全灭时战斗继续（设计稿 §3.2）。
- `F-BATTLEGOAL-05` 目标对象被提前消灭、指定道具被提前破坏或因其他原因无法达成时，系统即时判定该目标失败（设计稿 §3.2）。
- `F-BATTLEGOAL-06` 系统在目标濒临失效时给出预警提示，预警范围覆盖关键目标的进度项（设计稿 §3.2）。
- `F-BATTLEGOAL-07` 撤退需要满足配置条件并消耗一次行动机会；成功后玩家回到地图界面，撤退结果写入战斗结果标识；撤退后事件在技术上仍为可进入，保留敌人撤退那一刻的状态与位置，玩家可以重新进入，事件状态取值保持未出现、可进入、进行中、已完成、已错过五种，撤退不新增状态取值；已获得的战利品保留；该事件的窗口期按配置延长并以它为中心锁定周边事件，锁定持续到该事件完成或过期；世界时间在事件退出时按实际战斗时长一次性推进（设计稿 §3.3；架构案 9.5.4、7.5；`85_战斗行为表.csv` 的 BHV-RETREAT-001；设计决策记录决策 91、92）。
- `F-BATTLEGOAL-08` 全部我方单位同时处于失去行动能力状态时战斗立即结束，判定对象是整支队伍；该情形与战斗失败严格区分，收场时两种条件同时成立以全队失去行动能力为准；本系统**只产生判定并写入战斗结果，不在战斗内成立结局**，结局成立的唯一入口是事件结算环节的事件结果提交，战斗阶段不直接退出到结算阶段（设计稿 §3.4；架构案 3.1 ARC-M05-001 与 ARC-M10-001、6.6 第 3 条、9.5.5；设计决策记录决策 90）。
- `F-BATTLEGOAL-09` 战斗只输出战斗结果标识与达成目标清单两项，不发放战利品；这两项即战斗对事件输出的契约（术语表 T-130、T-131）；解锁内容由事件在退出结算时按结果标识查询事件配置发放（设计稿 §3.5、§3.6；设计决策记录决策 76）。
- `F-BATTLEGOAL-10` 战斗的结束方式、达成目标的数量与达成的具体目标共同决定结果标识；结果标识与后续事件的对应关系由事件配置定义，本阶段只固定结果标识这一层接口（设计稿 §3.6；设计决策记录决策 76）。

## 3. 状态定义

### 3.1 状态

| 实体 | 状态取值 | 说明 |
| --- | --- | --- |
| 战斗目标条目 `CLS-BATTLEGOAL-002` | 未建立／进行中／已达成／已失败 | 已失败覆盖全部失败原因（目标对象被提前消灭、指定道具被提前破坏、其他原因无法达成），原因类别单独登记 |
| 目标条目预警标记 | 无预警／预警中 | 由进度项与目标定义登记的预警阈值派生的出数，不属条目自身状态、不入档、不改变条目状态与判定结论 |
| 撤退条件判定结论 `CLS-BATTLEGOAL-005` | 满足／不满足／未定义 | 单次判定给出；未定义表示撤退条件口径未由上游给出（REQ-BATTLEGOAL-03） |
| 达成目标清单 `CLS-BATTLEGOAL-003` | 未归集／已归集 | 收束判定时一次归集 |
| 战斗结果 `CLS-BATTLEGOAL-004` | 未产生／已产生／已交回 | 已产生表示结果已落定并可经 `API-M05-004` 检出；已交回表示结果已被事件侧取用；结果只承载判定，结局不由本系统成立 |
| 战斗结果的结束方式 | 常规／撤退／全队失去行动能力 | 与 M05 模块单元、`API-TIMELINE-009` 与 06-30 的分派口径同名同值；常规覆盖目标达成与全部目标失败两类依据 |
| 判定范围登记 `CLS-BATTLEGOAL-007` | 未建立／已建立 | 建立后其内容以存档记录为准 |
| 结果标识判定登记 `CLS-BATTLEGOAL-006` | 已登记／取值待补充 | 取值待补充表示判定项或结果标识取值清单未由上游给出（REQ-BATTLEGOAL-04） |
| 本单元装配 | 未初始化 → 初始化中 → 已初始化 → 已销毁 | 由启动物体按单元装配声明顺序显式初始化、按逆序销毁（架构案 6.1 阶段 3、8.3 第 1、6 条）；本文档不对该状态设对外接口 |

### 3.2 状态转换

```
战斗目标条目：未建立 → 进行中 → 已达成
                          └→ 已失败
撤退条件判定结论：满足／不满足／未定义（单次判定取值）
达成目标清单：未归集 → 已归集
战斗结果：未产生 → 已产生 → 已交回
判定范围登记：未建立 → 已建立
结果标识判定登记：已登记 ⇄ 取值待补充
本单元装配：未初始化 → 初始化中 → 已初始化 → 已销毁（程序结束时的逆序销毁）
```

预警标记不是状态转换的结果，按进度项与阈值在查询时出数，不入档、不作为数据来源。

### 3.3 状态转换触发条件

| 转换 | 触发条件 | 经接口／事件 | 状态变化（与 4.1 一致） |
| --- | --- | --- | --- |
| 目标条目 未建立 → 进行中 | M05 的装配路径受理战斗启动并调用目标装配 | `API-BATTLEGOAL-001` | 目标条目与判定范围建立；战斗结果置未产生 |
| 目标条目 进行中 → 已达成 | 已提交事实使该目标的达成条件成立 | `API-BATTLEGOAL-003` | 条目置已达成并进入达成项归集；触发收束判定 |
| 目标条目 进行中 → 已失败 | 目标对象被提前消灭、指定道具被提前破坏或因其他原因无法达成；或全部目标判定失败 | `API-BATTLEGOAL-003` | 条目置已失败并登记原因类别；全部失败时触发收束判定 |
| 达成目标清单 未归集 → 已归集 | 收束判定归集达成项 | `API-BATTLEGOAL-004` | 清单归集完成并被战斗结果引用 |
| 战斗结果 未产生 → 已产生 | 结束依据成立并完成结果标识判定；全队失去行动能力成立时即时落定；落定只写入战斗结果，**不在战斗内成立结局**（架构案 6.6 第 3 条、9.5.5；设计决策记录决策 90） | `API-BATTLEGOAL-004`、`API-BATTLEGOAL-005` | 结束方式与结果标识落定；经 `API-SAVE-009` 提交 |
| 战斗结果 已产生 → 已交回 | M10 的事件执行器经 `API-M05-004` 取用结果 | `API-M05-004`（模块能力） | 结果标记为已交回；重复取用返回同一份结果 |
| 判定范围登记 未建立 → 已建立 | 目标装配受理参战编成结果 | `API-BATTLEGOAL-001` | 我方参战单位标识集合登记完成 |
| 结果标识判定登记 已登记 ⇄ 取值待补充 | 配置加载完成后重新解析与一致性校验的结论 | `API-BATTLEGOAL-101`、`API-BATTLEGOAL-103` | 登记状态落定；差异项经 `API-M01-010` 记录 |
| 目标条目与结果 → 释放 | 战斗收束并退出收尾窗口，或读档丢弃未结状态；本局结束时随单局状态域在结算提交完成时一并释放（架构案 8.3 第 3 条） | `API-M05-104`、`API-M10-002` | 条目、清单与结果随之释放；撤退情形保留，供事件重新进入时取用（设计决策记录决策 92） |
| 本单元装配 未初始化 → 初始化中 → 已初始化 | 启动物体读取并校验单元装配声明后，按装配声明顺序显式调用本单元的初始化方法并完成相互引用；本单元在初始化时显式复位自身状态 | 无（不经本表接口；架构案 2.4.1、2.4.2、6.1 阶段 3、8.3 第 1、7 条、8.6 第 4、5 条） | 解析与校验能力随成员系统常驻对象就绪 |
| 本单元装配 已初始化 → 已销毁 | 程序结束时的逆序销毁；进程终止不执行销毁序列、不做任何收尾承诺 | 无（不经本表接口；架构案 6.4、8.3 第 6 条、9.4） | 常驻对象按初始化逆序销毁；不提交存档、不依赖退出回调 |

### 4.2 接口详细定义

#### API-BATTLEGOAL-001 BattleGoal.Assemble 战斗目标装配

职责：按战斗配置与事件配置声明的目标清单建立一次战斗的目标条目与判定范围，并完成与结果标识判定登记的一致性校验。

输入：
- 参数输入：战斗实例标识、事件实例标识、战斗配置标识、我方参战单位标识集合、敌方单位标识集合。
- 状态输入：无（装配期，战斗结果与目标条目尚未建立）。
- 数据输入：战斗配置与事件配置的目标清单声明与结果配置声明（`API-M01-003`）、`CLS-BATTLEGOAL-001`、`CLS-BATTLEGOAL-006`、事件结果配置 `CLS-EVENT-004`。
- 外部事件输入：无（由 M05 的装配路径直接调用）。

读取：战斗配置与事件配置（`API-M01-003`）、`CLS-BATTLEGOAL-001`、`CLS-BATTLEGOAL-006`、事件结果配置登记的结果标识集合（`CLS-EVENT-004`）。

输出：
- 返回值：装配结果与目标条目清单（目标标识、目标名称、可见性、目标对象标识）。
- 状态输出：`CLS-BATTLEGOAL-002` 条目由未建立转进行中；`CLS-BATTLEGOAL-007` 判定范围登记建立；`CLS-BATTLEGOAL-004` 置未产生、`CLS-BATTLEGOAL-003` 置未归集。
- 事件输出：无。
- 外部系统调用：`API-M01-010` 日志服务.Write（装配不通过项的记录）。

产生的状态变化：目标条目建立并携带目标对象标识与可见性；判定范围登记建立；战斗结果置未产生；世界时间未推进。

前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条；由启动物体按单元装配声明顺序显式初始化）；战斗配置与事件配置可解析；目标清单非空；每个目标的对象引用、达成条件与失败条件登记齐备；事件结果配置的结果标识集合可读。

后置条件：每个目标条目携带唯一的目标标识与可见性；`CLS-BATTLEGOAL-006` 的取值集合与事件结果配置登记的结果标识一致；判定范围登记与传入的我方参战单位标识集合一致。

副作用：不通过项经 `API-M01-010` 记录，不建立目标条目；装配事实由 M05 统一发布为 战斗开始，本系统不发布事件。

异常情况：目标清单为空；目标定义缺达成条件或失败条件；目标对象标识不在本次战斗的参战方清单内；目标对象的归属阵营与目标类型不匹配；结果标识判定登记的取值不在事件结果配置登记的结果标识集合内；同一战斗重复装配（幂等拒绝）；目标清单的字段级结构未由上游给出（REQ-BATTLEGOAL-01）。

#### API-BATTLEGOAL-002 BattleGoal.QueryTargets 战斗目标清单查询

职责：返回一次战斗的目标条目只读视图，供界面呈现、事件侧取数与目标对象识别取数。

输入：
- 参数输入：战斗实例标识、查询面（全部目标／按目标对象／按可见性）。
- 状态输入：目标条目状态与标记、战斗结果状态。
- 数据输入：`CLS-BATTLEGOAL-001`。
- 外部事件输入：无。

读取：`CLS-BATTLEGOAL-001`、`CLS-BATTLEGOAL-002`、`CLS-BATTLEGOAL-004`；目标对象相关的单位状态快照（`API-BATTLE-003`，用于进度项与预警标记的当前值取数）。

输出：
- 返回值：目标条目只读视图（目标标识、目标名称、可见性、目标对象标识、进度项当前值、达成与失败标记、失败原因类别、预警标记）。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：`API-BATTLE-003` 单位状态查询；`API-M01-010` 日志服务.Write（查询面不可用时的记录）。

产生的状态变化：无（只读查询不改变条目状态；预警标记按阈值判定只作出数）。

前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；目标条目已装配；或战斗已收束且结果已产生（此时按结果快照返回）。

后置条件：视图为只读快照，不携带写入口；读取方不得把视图缓存为自身数据来源（架构案 4.4、8.2 第 3 条）。

副作用：无。

异常情况：战斗实例不存在或目标条目未装配 → 返回空清单并标注未装配；查询面未登记 → 拒绝该查询面；请求的单位状态不可读 → 该项进度按不可用返回并标注原因类别；结算阶段内只返回只读内容（架构案 6.6 硬规则 2）；隐藏目标的呈现时点未定（REQ-BATTLEGOAL-02）。

#### API-BATTLEGOAL-003 TargetProgress.Advance 目标进度推进

职责：按已提交的行为与状态事实推进目标进度项，并对无法达成的目标即时判定失败。

输入：
- 参数输入：战斗实例标识、推进来源类别（目标对象被消灭／目标对象离场／指定道具被破坏或被取走／容器被搜刮／场景交互完成／其他登记来源）、来源标识（行为标识、单位标识或对象标识）、受影响对象标识集合。
- 状态输入：目标条目状态与标记、战场容器与场地道具条目的当前状态、战斗结果状态。
- 数据输入：`CLS-BATTLEGOAL-001`；战斗行为表登记的推进来源类别（`API-BATTLEACT-001`）。
- 外部事件输入：无（由行为提交结算侧与收束编排直接调用）。

读取：`CLS-BATTLEGOAL-001`、`CLS-BATTLEGOAL-002`、`CLS-BATTLEGOAL-004`；单位状态快照（`API-BATTLE-003`）；战场容器与场地道具条目（`API-FIELD-008`）；物品实例与组件能力（`API-M04-001`、`API-M04-002`）。

输出：
- 返回值：推进结论（受影响目标条目、逐条判别结论、是否即时判定失败、是否触发收束）。
- 状态输出：目标条目进度项与标记变更，达成项就绪待归集；全部目标判定失败时向 `API-BATTLEGOAL-004` 提交结束依据类别「全部目标失败」。
- 事件输出：无（单位状态变化与战斗结束由 06-10 与 M05 按其登记发布）。
- 外部系统调用：`API-BATTLEGOAL-004` 收束判定；`API-SAVE-009` 数据域变更提交；`API-M01-010` 日志服务.Write。

产生的状态变化：目标条目由进行中转为已达成或已失败；达成目标数量与具体目标集合随之变化；战斗结果在收束成立时由 `API-BATTLEGOAL-004` 落定。

前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；战斗处于进行中且未收束；推进来源类别已登记；受影响对象属于本次战斗的参战方或战场对象。

后置条件：进度项与标记已落库；任一目标达成或全部目标失败时收束判定已被触发；被拒绝的推进不改变任何目标条目与标记。

副作用：确认后立即落库并在下一次自动保存节点写入存档；同一事实重复推进幂等，不产生第二次状态变化；已失败条目按失败标记保持，不回退。

异常情况：战斗已收束或阶段取值为结算阶段 → 拒绝；推进来源类别未登记 → 拒绝并经 `API-M01-010` 记内容日志；受影响对象不属于任何目标条目 → 返回无受影响条目；目标对象的离场事实来源缺失（敌方撤退结果未交回）→ 该项按待判定返回（REQ-BATTLEGOAL-06）；进度项口径未由上游给出 → 该项标注待补充（REQ-BATTLEGOAL-08）。

#### API-BATTLEGOAL-004 BattleGoal.EvaluateOutcome 战斗收束判定与结果落定

职责：按结束依据归集达成目标清单、判定结束方式并取结果标识，把战斗结果一次落定。

输入：
- 参数输入：战斗实例标识、结束依据类别（目标达成／全部目标失败／撤退成功／全队失去行动能力／敌方全部离场）、来源标识与判定时刻。
- 状态输入：目标条目状态与标记、判定范围登记、战斗结果状态、达成目标清单状态。
- 数据输入：`CLS-BATTLEGOAL-001`、`CLS-BATTLEGOAL-006`、战斗配置与事件配置的目标清单声明与结果配置声明（`API-M01-003`、`CLS-EVENT-004`）。
- 外部事件输入：无（由 M05 的收束编排与本系统的即时判定路径调用）。

读取：`CLS-BATTLEGOAL-001`、`CLS-BATTLEGOAL-002`、`CLS-BATTLEGOAL-003`、`CLS-BATTLEGOAL-006`、`CLS-BATTLEGOAL-007`、战斗配置与事件配置（`API-M01-003`）。

输出：
- 返回值：战斗结果（结果标识、结束方式、达成目标清单、判定时刻与判定依据项）。
- 状态输出：`CLS-BATTLEGOAL-003` 由未归集转已归集；`CLS-BATTLEGOAL-004` 由未产生转已产生。
- 事件输出：无（战斗结束与撤退发生由 M05 按其登记发布；结局成立由 M10 的结算执行器在事件结算环节统一发布，唯一发布方）。
- 外部系统调用：`API-SAVE-009` 数据域变更提交；`API-M01-010` 日志服务.Write。

产生的状态变化：结束方式落定为常规、撤退或全队失去行动能力；结果标识按 `CLS-BATTLEGOAL-006` 的判定项取值；达成目标清单归集完成。

前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；战斗未收束；结束依据成立且来源可追溯；达成目标清单可归集；结果标识判定登记已装配。

后置条件：结果标识取值为事件结果配置登记的取值之一；同一战斗的结果只产生一次，重复判定幂等返回已有结果；结果可经 `API-M05-004` 检出并交回事件侧。

副作用：结果落定后 M10 的事件执行器轮询 `API-M05-004` 即可检出全队失去行动能力并按其流程收场（架构案 9.5.5）；本系统只写入战斗结果，**不在战斗内成立结局**，结局成立的唯一入口是事件结算环节的事件结果提交；本系统不推进世界时间、不发放战利品（架构案 3.1 ARC-M10-001、6.6 第 3 条；设计决策记录决策 90）。

异常情况：结束依据不成立或来源缺失 → 不落定并登记原因；结束方式为常规而判定登记无匹配项 → 返回未定义结论并经 `API-M01-010` 记内容日志（REQ-BATTLEGOAL-04）；多种结束依据同时成立 → 按即时成立的那一刻取一种，全队失去行动能力与战斗失败同时成立时取全队失去行动能力（设计稿 §3.4）；同一战斗重复判定 → 幂等返回已有结果；结果落库被拒绝 → 保持未产生并登记原因，可重试。

#### API-BATTLEGOAL-005 BattleGoal.JudgePartyIncapacitated 全队失去行动能力即时判定

职责：在单位状态结算使某个我方单位进入失去行动能力时即时判定全队是否同时失去行动能力，成立即写入战斗结果。

输入：
- 参数输入：战斗实例标识、触发来源类别（单位状态变化／轮次推进边界复核）。
- 状态输入：判定范围登记、目标条目状态与标记、战斗结果状态。
- 数据输入：`CLS-BATTLEGOAL-007`。
- 外部事件输入：单位状态变化（由 06-10 发布；本系统订阅后触发本项）。

读取：`CLS-BATTLEGOAL-007`、`CLS-BATTLEGOAL-002`、`CLS-BATTLEGOAL-004`；我方参战单位的单位状态快照（`API-BATTLE-003`）。

输出：
- 返回值：判定结论（成立／不成立）与依据项（处于失去行动能力的单位清单）。
- 状态输出：成立时经 `API-BATTLEGOAL-004` 落定战斗结果，结束方式取全队失去行动能力，达成目标清单按当前目标条目归集。
- 事件输出：无。
- 外部系统调用：`API-BATTLE-003` 单位状态查询、`API-BATTLE-005` 队伍行动能力判定、`API-BATTLEGOAL-004` 收束判定、`API-M01-010` 日志服务.Write。

产生的状态变化：成立时 `CLS-BATTLEGOAL-004` 由未产生转已产生，结束方式落定为全队失去行动能力。

前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；战斗处于进行中且未收束；判定范围登记已建立；我方参战单位标识集合非空。

后置条件：成立时战斗结果已写入并可由 M10 的事件执行器轮询检出；不成立时不产生任何状态变化；同一战斗的结果只落定一次。

副作用：无（判定为只读判定，落定只发生一次；本系统不发布事件、不推进世界时间）。

异常情况：判定范围登记为空或含非我方单位 → 拒绝并返回缺失项，不按部分集合给出结论；战斗已收束 → 幂等返回已有结果；单位状态快照不可读 → 判定不成立并记运行日志，下一次触发时重试；`API-BATTLE-005` 判定方不可用 → 同上；全队失去行动能力与全部目标失败同时成立 → 以全队失去行动能力为准（设计稿 §3.4）；判定成立后的收尾窗口、事件退出与结局成立不由本项处理，本项只写入战斗结果，结局成立的唯一入口是事件结算环节的事件结果提交（架构案 6.6 第 3 条、9.5.5 第 3 至 5 步；设计决策记录决策 90）。

#### API-BATTLEGOAL-006 RetreatCondition.Evaluate 撤退条件判定

职责：按配置声明的撤退条件给出撤退行为的前置结论与逐条件结论，供行为可用性判定与行为提交前置判定取用。

输入：

- 数据输入：战斗配置与事件配置的撤退条件声明（`API-M01-003`）、撤退行为契约（`API-BATTLEACT-001`、BHV-RETREAT-001）。
- 外部事件输入：无。

读取：撤退条件声明（`API-M01-003`）；空间判定结果（`API-FIELD-004`）；布置阶段状态（`API-FIELD-003`）；轮次状态（`API-TIMELINE-007`）；物品实例与组件能力（`API-M04-001`、`API-M04-002`、`API-M04-003`）；角色属性取值（`API-M07-004`）；阶段取值（`API-M10-001`）。

输出：
- 返回值：`CLS-BATTLEGOAL-005` 撤退条件判定结论（是否满足、逐条件结论、未满足原因类别）。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：`API-FIELD-004`、`API-FIELD-003`、`API-TIMELINE-007`、`API-M04-003`、`API-M07-004`、`API-M01-010`。

产生的状态变化：无（不占用行动机会、不追加行动槽字母、不消耗资源）。

前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；战斗处于进行中或布置阶段；行动者属于我方参战单位；撤退条件声明可读。

后置条件：结论为只读，逐条件给出结论与原因类别；结论不携带写入口，调用方不得据此直接改变战斗状态。

副作用：无。

异常情况：撤退条件声明缺失或配置口径未定 → 返回未定义结论并经 `API-M01-010` 记内容日志（REQ-BATTLEGOAL-03）；行动者不属于我方参战单位 → 拒绝；条件类别未登记 → 拒绝该类别；某条件判定方不可用或被拒绝 → 该条件按不可用返回并标注原因类别；撤退条件已满足而重复发起 → 结论幂等。

### 5.2 内部功能契约

#### API-BATTLEGOAL-101 ResolveGoalConfig 目标定义解析与校验

职责：解析目标清单声明并产出目标定义。输入：参数输入：战斗配置标识、事件实例标识；状态输入：无；数据输入：战斗配置与事件配置（`API-M01-003`）；外部事件输入：配置加载完成。读取：战斗配置与事件配置（`API-M01-003`）、`CLS-BATTLEGOAL-001`。输出：返回值：`CLS-BATTLEGOAL-001` 与不通过项；状态输出：`CLS-BATTLEGOAL-001` 置已登记或取值待补充；事件输出：无；外部系统调用：`API-BATTLEGOAL-103`、`API-M01-010`。产生的状态变化：`CLS-BATTLEGOAL-001` 生成或标注取值待补充。前置条件：配置服务可用；目标清单声明可解析。后置条件：解析结果覆盖目标标识、名称、可见性、目标类型、目标对象引用、达成条件、失败条件、预警阈值声明与进度项声明。副作用：不通过项经 `API-M01-010` 记录。异常情况：目标清单声明缺失；字段级结构未由上游给出（REQ-BATTLEGOAL-01）；同一战斗声明了重复的目标标识；隐藏目标的发现条件未给出（REQ-BATTLEGOAL-02）。

#### API-BATTLEGOAL-102 BuildGoalEntries 目标条目建立

职责：按目标定义与参战方清单建立目标条目与判定范围。输入：参数输入：战斗实例标识、我方参战单位标识集合、敌方单位标识集合；状态输入：无；数据输入：`CLS-BATTLEGOAL-001`；外部事件输入：无。读取：`CLS-BATTLEGOAL-001`、战斗配置（`API-M01-003`）。输出：返回值：目标条目清单与判定范围建立结果；状态输出：`CLS-BATTLEGOAL-002` 条目置进行中，`CLS-BATTLEGOAL-007` 置已建立；事件输出：无；外部系统调用：`API-SAVE-009`、`API-M01-010`。产生的状态变化：条目建立并落库。前置条件：目标定义已登记；我方参战单位标识集合非空。后置条件：每个条目携带目标对象标识、可见性与进度项初值。副作用：无。异常情况：目标对象标识不在参战方清单内；参战单位标识集合为空；条目已建立（幂等拒绝）。

#### API-BATTLEGOAL-103 CheckResultRegistry 结果标识判定登记一致性校验

职责：校验判定登记与事件结果配置的结果标识集合一致。输入：参数输入：战斗配置标识与事件实例标识；状态输入：无；数据输入：`CLS-BATTLEGOAL-006`、事件结果配置 `CLS-EVENT-004`；外部事件输入：无。读取：`CLS-BATTLEGOAL-006`、`CLS-EVENT-004`（经 `API-M01-003` 取得内存形态）。输出：返回值：校验结论与差异项清单；状态输出：`CLS-BATTLEGOAL-006` 置已登记或取值待补充；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：登记状态落定。前置条件：判定登记与事件结果配置均可读。后置条件：差异项逐条给出。副作用：差异项经 `API-M01-010` 记录。异常情况：结果标识取值清单未由上游给出（REQ-BATTLEGOAL-04、REQ-EVENT-01）；判定项引用的事件结果配置条目不存在；结束方式取值与判定登记的键不一致。

#### API-BATTLEGOAL-104 EvaluateGoalProgress 目标单条判别

职责：按推进来源与受影响对象给出单个目标条目的判别结论。输入：参数输入：推进来源类别、来源标识、受影响对象标识集合、目标条目；状态输入：条目进度项与标记、对象当前状态；数据输入：`CLS-BATTLEGOAL-001`；外部事件输入：无。读取：`CLS-BATTLEGOAL-001`、`CLS-BATTLEGOAL-002`、单位状态快照（`API-BATTLE-003`）、战场容器与场地道具条目（`API-FIELD-008`）、物品实例与组件能力（`API-M04-001`、`API-M04-002`）。输出：返回值：判别结论（推进量、是否达成、是否失败、原因类别）；状态输出：条目进度项与标记按结论变更；事件输出：无；外部系统调用：`API-BATTLEGOAL-105`、`API-M01-010`。产生的状态变化：条目进度项与标记更新，达成项就绪待归集。前置条件：条目处于进行中；推进来源类别已登记。后置条件：达成与失败标记不同时成立；进度项只按已提交事实变更。副作用：无。异常情况：推进来源类别未登记；受影响对象不属于该条目；进度项口径未给出（REQ-BATTLEGOAL-08）；达成条件与失败条件的登记形式未给出（REQ-BATTLEGOAL-01）；条目已达成或已失败（幂等保持）。

#### API-BATTLEGOAL-105 EvaluateGoalInvalidation 目标失效即时判定

职责：对目标无法达成的事实即时判定该目标失败并登记原因类别。输入：参数输入：目标条目、失效事实类别（目标对象被消灭／指定道具被破坏或被取走／其他登记原因）、来源标识；状态输入：条目状态与对象当前状态；数据输入：`CLS-BATTLEGOAL-001` 的失败条件登记；外部事件输入：无。读取：`CLS-BATTLEGOAL-001`、`CLS-BATTLEGOAL-002`、单位状态快照（`API-BATTLE-003`）、物品实例与组件能力（`API-M04-001`、`API-M04-002`）。输出：返回值：失效判定结论与原因类别；状态输出：条目置已失败并登记原因类别；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：条目由进行中转已失败。前置条件：条目处于进行中；失效事实类别已登记。后置条件：失败原因类别唯一；已失败条目幂等保持。副作用：无。异常情况：失效条件口径未定（REQ-BATTLEGOAL-05）；失效事实来源不可读；失效事实晚于收束判定（按结果快照保持，不回退）。

#### API-BATTLEGOAL-106 CollectAchievedGoals 达成目标清单归集

职责：按目标条目归集达成项形成达成目标清单。输入：参数输入：战斗实例标识；状态输入：全部目标条目状态与标记；数据输入：`CLS-BATTLEGOAL-001`；外部事件输入：无。读取：`CLS-BATTLEGOAL-002`。输出：返回值：`CLS-BATTLEGOAL-003`；状态输出：清单置已归集；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：清单归集完成。前置条件：收束判定已受理。后置条件：清单只含达成项，且与条目标记一致。副作用：无。异常情况：条目尚未全部判别完毕；清单重复归集（幂等返回同一份）。

#### API-BATTLEGOAL-107 EvaluateOutcomeKind 结束方式判定

职责：按结束依据与目标判定结论给出唯一结束方式。输入：参数输入：结束依据类别、来源标识、判定时刻；状态输入：条目标记与战斗结果状态；数据输入：`CLS-BATTLEGOAL-001`；外部事件输入：无。读取：`CLS-BATTLEGOAL-002`、`CLS-BATTLEGOAL-004`。输出：返回值：结束方式与判定依据项；状态输出：无；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：无（结论交由 `API-BATTLEGOAL-004` 落定）。前置条件：结束依据成立。后置条件：结束方式取值唯一，取值为常规、撤退或全队失去行动能力。副作用：无。异常情况：多种依据同时成立（按即时成立的那一刻取一种，全队失去行动能力优先）；依据类别未登记；来源缺失。

#### API-BATTLEGOAL-108 EvaluateResultIdentifier 结果标识判定

职责：按结束方式、达成目标数量与达成的具体目标在判定登记内取结果标识。输入：参数输入：战斗实例标识、结束方式、达成目标清单；状态输入：无；数据输入：`CLS-BATTLEGOAL-006`、事件结果配置 `CLS-EVENT-004`；外部事件输入：无。读取：`CLS-BATTLEGOAL-006`、`CLS-BATTLEGOAL-003`。输出：返回值：结果标识与命中项依据；状态输出：无；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：无（结论交由 `API-BATTLEGOAL-004` 落定）。前置条件：判定登记已装配；达成目标清单已归集。后置条件：结果标识取值为登记取值之一。副作用：无。异常情况：无匹配判定项（返回未定义结论并记内容日志）；判定登记取值待补充（REQ-BATTLEGOAL-04）；达成目标清单未归集。

#### API-BATTLEGOAL-109 EvaluateGoalWarning 目标预警判定

职责：按进度项与预警阈值给出预警标记。输入：参数输入：目标条目与进度项当前值；状态输入：条目状态；数据输入：`CLS-BATTLEGOAL-001` 的预警阈值声明；外部事件输入：无。读取：`CLS-BATTLEGOAL-001`、`CLS-BATTLEGOAL-002`。输出：返回值：预警标记与依据项；状态输出：无（派生出数，不写回条目）；事件输出：无；外部系统调用：`API-M01-010`。产生的状态变化：无。前置条件：条目处于进行中且阈值声明可读。后置条件：预警标记为派生结果，只作呈现供数，不入档、不改变条目状态与判定结论，读取方不得缓存为自身数据来源（架构案 8.2 第 3 条）。副作用：无。异常情况：预警阈值未由上游给出（REQ-BATTLEGOAL-05，按无预警出数并标注待补充）；条目已达成或已失败（不给出预警）；进度项当前值不可读（该项按不可用返回并标注原因类别）。

#### API-BATTLEGOAL-110 CollectAndRestoreSlice 目标与结果切面采集与重建

职责：声明可持久化切面并在恢复路径按记录重建目标条目、判定范围与战斗结果。输入：参数输入：战斗实例标识或恢复范围；状态输入：无（采集期）或切面记录（恢复期）；数据输入：`CLS-BATTLEGOAL-001`；外部事件输入：存档恢复完成。读取：`CLS-BATTLEGOAL-002`、`CLS-BATTLEGOAL-003`、`CLS-BATTLEGOAL-004`、`CLS-BATTLEGOAL-007`。输出：返回值：切面内容或重建结果与不一致项；状态输出：条目与结果按记录置值；事件输出：无；外部系统调用：`API-SAVE-001`、`API-SAVE-008`、`API-SAVE-009`、`API-M01-010`。产生的状态变化：条目、清单、结果与判定范围按记录重建，不重新判定。前置条件：切面声明已登记（`API-SAVE-001`）；恢复流程已受理 存档恢复完成。后置条件：重建结果与存档记录一致；派生项按来源重建。副作用：不一致项经 `API-M01-010` 记录。异常情况：切面记录缺失或引用完整性校验不通过（按架构案 7.1 的失败语义处理）；记录的战斗结果与目标条目标记不一致（以结果为收束依据并记运行日志）；恢复期重复重建（幂等）。

### 5.3 功能之间的关系

- `API-BATTLEGOAL-001` 依次调用 `API-BATTLEGOAL-101`、`API-BATTLEGOAL-102`、`API-BATTLEGOAL-103`；校验不通过时不建立目标条目。
- `API-BATTLEGOAL-003` 受理推进后调用 `API-BATTLEGOAL-104`，命中失效事实时调用 `API-BATTLEGOAL-105`；全部目标失败或任一目标达成时调用 `API-BATTLEGOAL-004`，达成项由 `API-BATTLEGOAL-004` 经 `API-BATTLEGOAL-106` 归集。
- `API-BATTLEGOAL-004` 依次调用 `API-BATTLEGOAL-107`、`API-BATTLEGOAL-106`、`API-BATTLEGOAL-108`，把结束方式、达成目标清单与结果标识一次落定；只写入战斗结果，**不成立结局**，结局成立由 M10 的结算执行器在事件结算环节承接事件结果提交时统一发布（架构案 3.1 ARC-M10-001、6.6 第 3 条；设计决策记录决策 90）。
- `API-BATTLEGOAL-005` 经 `API-BATTLE-005` 取得队伍行动能力结论，成立时调用 `API-BATTLEGOAL-004`，结束方式取全队失去行动能力。
- `API-BATTLEGOAL-002` 读取时调用 `API-BATTLEGOAL-109` 给出预警标记；`API-BATTLEGOAL-006` 只汇总各条件判定方的既有结论，不调用目标判定。
- `API-BATTLEGOAL-110` 只服务切面声明与恢复路径；`API-BATTLEGOAL-101` 与 `API-BATTLEGOAL-103` 在配置加载完成后重新解析。

### 6.5 依赖方向限制

分层与模块是架构案的**描述性分类**，不承担数据隔离、交互隔离与依赖方向约束职责（架构案 1.6）。本节只用于阅读导航：列出本单元实际依赖的模块与方向，以及仍然成立的少量硬规则。

- 实际依赖与方向：M01（基础设施：静态配置查询、日志写入、事件分发；存档服务与数据域的切面与写入入口）、M05（本模块单元：装配路径、行为提交路径与收束编排调用本系统，结果经模块能力 `API-M05-004` 交回）、M10（编排方：只查询阶段取值，收束后的分派与阶段切换由 M05 与 M10 执行，本系统不反向调用其执行入口）、M04（对象与组件能力的只读取数）、PARTY（01-40，角色属性取值的同层只读查询，不写入、不持有取值副本）、SAVE（01-50，切面声明、读取与提交）。同模块内的成员系统（06-10、06-20、06-30、06-85、06-90）之间为模块内取数，按 M05 模块单元登记的取数口径执行。
- 不依赖 M08 与任何 L5 表现层对象（架构案 3.4 第 1、2 项）：目标清单呈现、预警提示与结局文案由 M08 与 01-20 取数后呈现；本系统不发起界面、场景与资源调用，也不存在界面直接改数据的路径（架构案 3.4 第 3 项、8.4 第 5 条）。
- 不得被越权依赖：界面侧只允许经 `API-M05-005` 读取切面、经 `API-BATTLEGOAL-002` 读取目标清单；编排侧只允许经 `API-M05-004` 取结果；任何模块不得持有本系统的目标条目与战斗结果的可变引用。
- 横切能力不重复实现：本系统不自行实现效果叠加、条件判定、物品写入与空间判定，物品与效果状态的变化一律经 M09 的三处能力提交，条件判定一律经条件求值服务（架构案 3.3 第 6 项、3.4 第 7、8 项、8.2 第 1、2 条）。本系统当前的对外契约不含物品写入与效果施加，条件求值出口随目标定义的字段级结构确定后按架构案 8.5 的接入步骤登记（REQ-BATTLEGOAL-01）。
- 世界时间不经本系统推进（架构案 3.4 第 10 项、7.5）：事件内只做时间记账，世界时间只在事件退出时一次性推进；本系统只输出结束方式与结果标识，净时长由 M05 的 `API-M05-105` 提供（设计决策记录决策 91）。
- 结局不在战斗内成立：本系统在全队失去行动能力等情形下只产生判定并写入战斗结果；结局成立的**唯一入口是事件结算环节的事件结果提交**，三种未通关收尾情形统一在该环节成立，战斗阶段不直接退出到结算阶段（架构案 3.1 ARC-M05-001 与 ARC-M10-001、6.6 第 3 条、9.5.5；设计决策记录决策 90）。

## 8. 核心流程

### 8.1 战斗目标装配

- 触发：M10 的战斗执行器受理战斗事件并经 `API-M05-001` 启动战斗，M05 的装配序列在参战编成之后调用目标装配。参与者：本系统、M05 的装配路径、M01 的配置服务、单局状态域。
- 调用顺序：1 `API-BATTLEGOAL-101` 经 `API-M01-003` 解析目标清单声明；2 `API-BATTLEGOAL-103` 校验结果标识判定登记与事件结果配置一致；3 `API-BATTLEGOAL-102` 按目标定义与传入的我方参战单位标识集合建立目标条目与判定范围登记；4 经 `API-SAVE-009` 提交落库；5 装配事实由 M05 统一发布为 战斗开始，本系统不发布事件。
- 状态变化：目标条目由未建立转进行中；判定范围登记置已建立；战斗结果置未产生；达成目标清单置未归集；世界时间未推进。
- 产生的事件：无（本系统）；战斗开始（M05）。
- 结束条件：目标条目与判定范围登记就绪，且结果标识判定登记的一致性校验通过。

### 8.2 目标进度推进与即时失败判定

- 触发：M05 的行为提交结算侧、06-30 的搜刮与场景交互结算侧提交已确认的事实。参与者：本系统、M05 的行为提交路径、06-30、06-10、M04、单局状态域。
- 调用顺序：1 `API-BATTLEGOAL-003` 受理推进来源与受影响对象；2 `API-BATTLEGOAL-104` 逐条给出判别结论；3 命中失效事实时由 `API-BATTLEGOAL-105` 即时判定该目标失败并登记原因类别；4 经 `API-SAVE-009` 提交落库；5 达成项与标记就绪，任一目标达成或全部目标失败时调用 `API-BATTLEGOAL-004`，由 `API-BATTLEGOAL-106` 归集达成目标清单。
- 状态变化：目标条目由进行中转为已达成或已失败；达成目标数量与具体目标集合更新。
- 产生的事件：无（本系统）；单位状态变化与战斗结束由 06-10 与 M05 按其登记发布。
- 结束条件：推进结论返回且条目标记已落库；被拒绝的推进不产生任何状态变化。

### 8.3 全队失去行动能力的即时判定与写入

- 触发：06-10 发布 单位状态变化 且某个我方单位进入失去行动能力，或 M10 的战斗执行入口在轮次推进边界复核。参与者：本系统、06-10、M10 的事件执行器与阶段状态机、M05 的收束编排、单局状态域。
- 调用顺序：1 本系统按判定范围登记取我方参战单位标识集合；2 `API-BATTLE-003` 取单位状态快照；3 `API-BATTLE-005` 请求队伍行动能力判定；4 结论成立时 `API-BATTLEGOAL-004` 归集达成目标清单、判定结束方式为全队失去行动能力并取结果标识；5 结果经 `API-SAVE-009` 落库；6 M10 的事件执行器轮询 `API-M05-004` 检出该终止条件，随后按常规收尾窗口与事件退出规则收场。本系统在全队失去行动能力时**只产生判定并写入战斗结果，不在战斗内成立结局**；结局成立的**唯一入口是事件结算环节的事件结果提交**，三种未通关收尾情形统一在该环节成立；结算阶段的进入条件是**事件结果提交**，不是「结局成立」，战斗阶段不直接退出到结算阶段（架构案 3.1 ARC-M05-001 与 ARC-M10-001、6.6 第 3 条、9.5.5 第 2 至 5 步；设计决策记录决策 90）。
- 状态变化：战斗结果由未产生转已产生；结束方式落定为全队失去行动能力；本局的收场、结局成立与跨局写入不由本系统执行，只在事件结算环节由 M10 的结算执行器承接。
- 产生的事件：结局成立由 M10 的结算执行器在事件结算环节承接事件结果提交时统一发布（唯一发布方）；本系统不发布事件（架构案 3.1 ARC-M10-001、9.5.5；设计决策记录决策 90）。
- 结束条件：判定结论与依据项返回；成立时结果已写入并可由 M10 的轮询检出。

### 8.4 撤退条件判定与撤退收场

- 触发：06-85 的行为可用性判定、M05 的行为提交前置判定或 06-30 的撤退站位取数请求撤退条件结论。参与者：本系统、06-85、M05、06-30、06-20、M04、01-40。
- 调用顺序：1 `API-BATTLEGOAL-006` 按条件类别逐条判定：站位经 `API-FIELD-004` 取空间判定结果，轮次经 `API-TIMELINE-007` 取轮次状态，资源经 `API-M04-003` 与 `API-M07-004` 取数；2 结论以 `CLS-BATTLEGOAL-005` 返回；3 玩家确认撤退后由 M05 的行为提交路径受理并发布 撤退发生；4 撤退成功经 M05 的收束编排调用 `API-BATTLEGOAL-004`，结束方式取撤退、**撤退结果写入战斗结果标识**，达成目标清单按当时条目归集；5 结果经 `API-M05-004` 交回事件侧；窗口期延长与周边事件锁定由 M10 的事件执行器按事件配置执行（架构案 9.5.4）。
- 状态变化：撤退条件判定不改变任何状态；撤退成立时战斗结果落定，结束方式取撤退、撤退结果写入战斗结果标识；撤退后事件在技术上**仍为可进入**，保留敌人撤退那一刻的状态与位置，玩家可以重新进入，事件状态取值保持未出现、可进入、进行中、已完成、已错过五种，**撤退不新增状态取值**；该事件的窗口期按配置延长并以它为中心锁定周边事件，锁定持续到该事件完成或过期（架构案 9.5.4；设计决策记录决策 92）。
- 产生的事件：撤退发生（M05）；本系统不发布事件。
- 结束条件：条件结论返回；撤退成立时结果可经 `API-M05-004` 取用，事件保持可进入；结局成立不在本流程内，归事件结算环节的事件结果提交（设计决策记录决策 90）。

### 8.5 收束判定、结果落定与事件对接

- 触发：任一目标达成、全部目标判定失败、撤退成功、敌方全部离场或全队失去行动能力。参与者：本系统、M05 的收束编排、M10 的事件执行器与结算执行器、02-30 的事件结算、07-40 的结局判定。
- 调用顺序：1 `API-BATTLEGOAL-107` 按结束依据给出结束方式；2 `API-BATTLEGOAL-106` 归集达成目标清单；3 `API-BATTLEGOAL-108` 在判定登记内取结果标识；4 经 `API-SAVE-009` 落定战斗结果（只写入战斗结果，**不在战斗内成立结局**）；5 结果与达成目标清单经 `API-M05-004` 交回 M10 的事件执行器，随事件退出提交传入 02-30 按结果标识查询事件配置并发放解锁内容；6 事件结算环节受理事件结果提交后，结局类型与触发起因由 07-40 判定（`API-SETTLE-002`）、结局在本环节成立并写入跨局存档，三种未通关收尾情形统一在此成立；结算阶段的进入条件是事件结果提交，战斗阶段不直接退出到结算阶段（架构案 3.1 ARC-M10-001、6.6 第 3 条、9.5.5；设计决策记录决策 90）。
- 状态变化：达成目标清单由未归集转已归集；战斗结果由未产生转已产生，取用后转已交回；结局成立不在本流程内发生。
- 产生的事件：战斗结束（M05）；事件结算完成由 02-30 按其登记发布；结局成立由 M10 的结算执行器在事件结算环节统一发布（唯一发布方，M06 只提供判定取值）。
- 结束条件：结果标识与达成目标清单可经 `API-M05-004` 取用；重复取用返回同一份结果。

### 8.6 读档后目标与结果的恢复

- 触发：M01 发布 存档恢复完成 后由恢复流程驱动。参与者：本系统、M05 的切面重建路径、M01 的存档服务、单局状态域。
- 调用顺序：1 `API-BATTLEGOAL-110` 经 `API-SAVE-008` 读取本系统的切面记录；2 按记录重建目标条目、判定范围登记、达成目标清单与战斗结果；3 按来源重建派生项，不重新判定；4 条目与结果恢复到最近一次行动机会开始的时刻，该次行动机会内尚未确认的选择不恢复，不一致项经 `API-M01-010` 记录。
- 状态变化：条目与结果按存档记录置值；派生项按来源重建。
- 产生的事件：无（恢复流程只做重建）。
- 结束条件：目标条目可用于后续推进与收束判定，或已收束战斗的结果可经 `API-M05-004` 取用。

## 9. 异常与边界情况

| 情形 | 判定条件 | 期望结果 |
| --- | --- | --- |
| 目标清单缺失或字段不全 | `API-BATTLEGOAL-001` 解析不到目标清单声明，或目标定义缺达成条件、失败条件与目标对象引用 | 拒绝装配并不建立目标条目，登记不通过项（REQ-BATTLEGOAL-01） |
| 目标对象不在参战方内 | 目标对象标识不在本次战斗的参战方清单内，或阵营与目标类型不匹配 | 拒绝该目标条目并登记原因，其余条目按可装配处理；全部条目被拒时拒绝装配 |
| 结果标识不在登记集合内 | `API-BATTLEGOAL-103` 判定登记的取值与事件结果配置登记的结果标识不一致 | 按不通过处理，登记差异项并在取值待补充状态下降级（REQ-BATTLEGOAL-04） |
| 无匹配的结果标识判定项 | 结束方式、达成目标数量与具体目标在判定登记内无匹配项 | 返回未定义结论、不落定结果并记内容日志，由 M05 与 M10 处理未收束状态 |
| 战斗已收束或处于结算阶段 | 对已收束实例请求目标推进或重复收束判定；阶段取值为结算阶段 | 目标推进拒绝且不改变状态；收束判定幂等返回已有结果（架构案 6.6 硬规则 2） |
| 同一事实重复推进 | 同一来源标识与对象标识的推进重复提交 | 幂等，条目标记与进度项不产生第二次变化 |
| 失效事实晚于收束 | 收束判定完成后才产生目标失效或达成事实 | 按结果快照保持，不回退、不产生第二个结果 |
| 判定范围为空或含非我方单位 | `API-BATTLEGOAL-005` 收到空集合，或集合内出现敌方单位、非参战单位 | 前置条件不满足，拒绝受理并返回缺失项，不按部分集合给出结论 |
| 单位状态快照不可读 | `API-BATTLE-003` 不可用或被拒绝 | 判定不成立并记运行日志，下一次触发或轮次推进边界复核时重试 |
| 多种结束依据同时成立 | 全队失去行动能力与全部目标失败在同一时刻成立 | 按即时成立的那一刻取一种结束方式，全队失去行动能力优先（设计稿 §3.4） |
| 战斗内要求成立结局 | 任何模块在战斗内要求以全队失去行动能力等未通关收尾情形成立结局，或要求战斗阶段直接进入结算阶段 | 拒绝；本系统只产生判定并写入战斗结果，结局成立的唯一入口是事件结算环节的事件结果提交，三种未通关收尾情形统一在该环节成立（架构案 3.1 ARC-M05-001 与 ARC-M10-001、6.6 第 3 条、9.5.5；设计决策记录决策 90） |
| 撤退后重复进入同一事件 | 撤退结果已写入战斗结果标识后玩家重新进入该事件 | 事件在技术上仍为可进入，保留敌人撤退那一刻的状态与位置，不新增事件状态取值；窗口期延长与周边事件锁定按事件配置执行，本系统按保留的状态供数、不重复判定（架构案 9.5.4；设计决策记录决策 92） |
| 撤退条件口径未定 | 撤退条件声明缺失，或条件类别未登记 | 返回未定义结论并记内容日志，行为按不可用处理（REQ-BATTLEGOAL-03） |
| 撤退条件判定方不可用 | 站位、轮次或资源某一条件判定方不可用或被拒绝 | 该条件按不可用返回并标注原因类别，不消耗行动机会与资源 |
| 敌方撤退结果缺失 | 目标对象离场而 06-90 的撤退判定结果未交回 | 该项目标按待判定返回，收束判定不据此落定（REQ-BATTLEGOAL-06） |
| 切面记录缺失或损坏 | `API-BATTLEGOAL-110` 读取失败或引用完整性校验不通过 | 按架构案 7.1 的失败语义处理，保留上一份有效存档并停在主界面 |
| 切面记录与条目标记不一致 | 战斗结果已产生而目标条目存在进行中项 | 以结果作为收束依据，经 `API-M01-010` 记运行日志，不重新判定 |
| 查询面未登记 | `API-BATTLEGOAL-002` 收到未登记的查询面 | 拒绝该查询面，其余查询面照常返回 |
| 隐藏目标的可见性越界取数 | 查询方要求隐藏目标的完整信息而呈现时点未定 | 按可见性字段供数，呈现时点口径未定（REQ-BATTLEGOAL-02） |

## 10. 实现约束

### 10.1 实现要求

- `I-BATTLEGOAL-01` 目标条目、达成目标清单、战斗结果与判定范围登记必须可序列化并入单局存档的单局状态域切面，声明与提交经 `API-SAVE-001`、`API-SAVE-009`；读档后按记录重建，不重新判定（架构案 5.2.2、5.3、9.3）。序列化采用**判别字段式多态序列化**：序列化结果中只出现**自定义的字符串判别值**，**不写入运行时类型名**；多态类型按判别值映射，不接受任意类型名；不得使用已被运行时移除实现的二进制序列化机制；单局存档的写入必须原子，提交过程中断时整次作废并保留上一份有效存档（架构案 7.1、5.3 第 4 项、8.6 第 8 条）。
- `I-BATTLEGOAL-02` 战斗结果的落定只能经 `API-BATTLEGOAL-004` 与 `API-BATTLEGOAL-005` 受理，对外取数只能经模块能力 `API-M05-004`；其他模块不得驱动收束判定，也不得持有目标条目与战斗结果的可变引用（架构案 8.2 第 1、2 条）。
- `I-BATTLEGOAL-03` 全队失去行动能力的判定必须在事实成立的当次结算内即时完成并写入战斗结果，供 M10 的事件执行器轮询检出；该情形**只产生判定并写入战斗结果，不在战斗内成立结局**，本系统不为该终止条件新增事件；结局成立的唯一入口是事件结算环节的事件结果提交，三种未通关收尾情形统一在该环节成立，战斗阶段不直接退出到结算阶段（架构案 3.1 ARC-M05-001 与 ARC-M10-001、6.6 第 3 条、9.5.5；设计决策记录决策 90）。
- `I-BATTLEGOAL-04` 同一场战斗的战斗结果只产生一次；重复判定、重复推进与重复取用一律幂等，不产生第二个结果或第二次状态变化。
- `I-BATTLEGOAL-05` 目标判定只汇总各判定方的既有结论与登记字段，不得自行实现空间判定、条件判定、物品写入与效果叠加（架构案 3.4 第 7、8 项、8.2 第 1 条）。
- `I-BATTLEGOAL-06` 结果标识只能取事件结果配置登记的取值之一；本阶段只固定结果标识这一层接口（事件退出时按事件配置给出结果标识与达成目标清单，后续内容按结果标识查询事件配置），事件结果配置的字段级结构、存档落点与消费接口留待后续环节；判定登记与事件结果配置的一致性在装配时校验，不通过时不落定结果（设计稿 §3.6；架构案 8.5.4；设计决策记录决策 76）。
- `I-BATTLEGOAL-07` 本系统不发布跨模块事件；跨模块状态广播一律经事件通道，由 M05 与 06-10 按其登记发布。事件契约以**类型契约**的形式确定（事件名、唯一发布方、载荷字段类别与失败语义），以可检视的资产承载、按**即用即定**登记；契约的强制方式是**一条对账测试**：遍历代码中的全部事件发布点并与登记表逐项比对，出现未登记事件即测试失败；事件名不在登记表内属于契约缺口，由对账测试在测试期发现，**受理侧不做运行期校验**（架构案 4.3、7.6、8.4 第 1、2 条、8.6 第 10 条）。
- `I-BATTLEGOAL-08` 判定范围登记只登记我方参战单位标识集合；单位状态一律经 `API-BATTLE-003` 取快照，本系统不保存单位状态副本，派生结论不作数据来源（架构案 8.2 第 3 条）。
- `I-BATTLEGOAL-09` 世界时间的推进不经本系统；本系统只输出结束方式与结果标识，事件内只做时间记账、世界时间只在事件退出时一次性推进，战斗净时长与时间段对齐归 M05 的 `API-M05-105`（架构案 7.5、3.4 第 10 项；设计决策记录决策 91）。
- `I-BATTLEGOAL-10` 结局类型与触发起因的判定与写入归 07-40（`API-SETTLE-002`、`CLS-SETTLE-004`）；本系统只输出结束方式与结果标识，并按架构案 2.3 的跨列说明不承担结局判定，**不在战斗内成立结局**；结局成立的唯一入口是事件结算环节的事件结果提交，三种未通关收尾情形统一在该环节成立（架构案 3.1 ARC-M05-001 与 ARC-M10-001、6.6 第 3 条、9.5.5；设计决策记录决策 90）。
- `I-BATTLEGOAL-11` 本系统不得依赖 M08 与任何 L5 表现层对象；目标清单呈现、预警提示与结局文案由 M08 与 01-20 取数后呈现（架构案 3.4 第 1、2 项）。
- `I-BATTLEGOAL-12` 目标条目与战斗结果属单局状态域，随单局创建，**结算提交完成时释放、开新局时全部重建**；跨域变更经持有方入口，本系统不直接改对象字段、不持有他方的内部集合（架构案 8.2 第 1、2 条、8.3 第 3 条、3.4 第 5 项）。
- `I-BATTLEGOAL-13` 不得重复实现引擎已提供的能力：对象池与集合池、异步任务、设备到动作的输入映射、音频与本地化与特效动画的播放原语、资产载体与序列化原语、资源加载、场景装卸与日志通道一律使用引擎提供的能力，项目只做架构案 7.12「项目实现」栏登记的部分（架构案 7.12、8.6 第 1 条）。
- `I-BATTLEGOAL-14` 权威游戏状态由普通 C# 对象持有，引擎对象只承担承载、呈现与编辑器配置职责；目标条目、达成目标清单、战斗结果与判定范围登记不得放在随场景销毁的对象上（架构案 8.6 第 2 条）。
- `I-BATTLEGOAL-15` 不依赖引擎的启动回调顺序、脚本执行顺序或帧回调顺序满足目标装配、即时判定与切面重建的顺序要求；顺序由单元装配声明与显式调用序列决定（架构案 6.1、8.3 第 1 条、8.6 第 4 条）。
- `I-BATTLEGOAL-16` 本单元在初始化时显式复位自身状态（条目、清单、结果与判定范围登记的登记态），不依赖引擎的域重载提供初始状态（架构案 6.1、8.3 第 7 条、8.6 第 5 条）。
- `I-BATTLEGOAL-17` 影响游戏状态的判定不得使用帧时间；本系统不引入暂停语义，任何模块不得以暂停为由冻结目标条目、战斗结果与判定范围登记（架构案 3.4 第 16 项、7.4、8.6 第 6 条；设计决策记录决策 87、88）。
- `I-BATTLEGOAL-18` 空间判定归玩法侧的网格与坐标逻辑，物理与动画只用于表现；表现对象与数据对象分离。撤退条件的站位口径与目标对象位置一律取 06-30 给出的判定结论，不得以物理结果或动画结果作为判定依据（架构案 8.6 第 7 条）。

### 10.2 其他实现约束

- 运行期配置的权威载体是**引擎编辑器内的配置资产**；`系统设计文档/` 的扩展配置表是各自系统的**初始素材与迁移来源**，用于设计评审与对照，**程序侧不直接读表**，内容侧不直接改运行期资产（架构案 5.1、7.9、8.6 第 10 条；设计决策记录决策 93）。过渡口径：在引擎侧资产建立起来之前，设计库的配置表仍是唯一的配置内容载体，表内容不提前废弃（设计决策记录决策 93）。目标定义、结果标识判定登记与撤退条件声明的定义归属不变，本系统只做解析、校验与取数，不修改配置对象。
- 退出游戏即**进程终止**，与强制关闭、平台关闭、异常终止同义；退出时**不提交存档、不构成任何提交点、不执行销毁序列、不依赖任何退出回调**完成存档或收尾。本系统的切面内容以最近一次自动保存节点（战斗轮次推进与时间段推进两类）的提交结果为准（架构案 3.4 第 17 项、5.3 第 4 项、6.4、7.1、9.4；设计决策记录决策 89）。
- 结算阶段封闭：进入结算阶段后世界时间不再推进，本系统不接受任何改变局内状态的输入（目标推进与收束判定一律拒绝），也不创建或销毁单局状态域内的对象（架构案 6.6、8.3 第 5 条）。
- 收尾窗口的进入声明、窗口内操作集合与结束受理归 06-30（`API-FIELD-010`、`API-FIELD-013`）与 M10 的阶段状态机；本系统不判定是否进入收尾窗口，也不受理窗口内操作。
- 战利品与产出、非全歼式结果的收益差异表归内容与数值设计，不进本系统的程序契约（设计稿 §3.5、§5）。
- 新增目标类型、推进来源类别与结束依据类别时，先在配置资产内登记字段与取值，再按架构案 8.5.4 的接入步骤并入本系统的装配与判定登记。
