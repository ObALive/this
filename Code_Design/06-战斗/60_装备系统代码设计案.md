单元说明：本文档按《CO01 编制约定 v1》§一承载设计库系统「60 装备系统」（`SYS-EQUIP-001`），主模块 M04 对象与经济，层级 L3，跨列说明为「战斗内换装归 M05」。装备槽与遗物槽（术语表 T-111）属玩家状态域，随单局创建并重置、结算提交完成时释放（架构案 5.2.3、6.6）；储物装备（术语表 T-108）的容器组件（术语表 T-078）构成背包空间（术语表 T-086）来源，**背包空间是派生结果**，按来源状态重建、不入档（架构案 5.2.2、8.2 第 3 条）；效果表达归 M09 的元效果服务；物品状态变化一律经 M09 的物品与经济写入服务（`API-M09-005`），本系统不得绕过（架构案 3.4 第 7 项）；战斗内换装与行动机会（术语表 T-118）的耦合归 M05。模块级公共能力 `API-M04-001` 至 `API-M04-006` 的契约由 M04 模块单元文档给出，本文档只引用（约定 §三）。全量界面清单的权威来源是 `架构设计文档/界面索引.md`（架构案 2.4；设计决策记录决策 94），本系统只承接装备栏的内部布局、字段与操作细节，不搬运界面清单。

## 1. 系统定义
### 1.1 系统目的
装备系统在程序上持有「角色身上有哪些槽、每个槽里放着什么」这一份唯一记录，并把「一件物品能不能进这个槽」的判定、「装备栏现在能不能打开」的判定，以及已装备物品所提供的容器空间与法术构成的取数，统一提供给它方使用。
### 1.2 系统职责
- 持有装备槽定义（术语表 T-107 的槽位侧）与角色槽位配置：槽位标识、槽位类别（普通装备槽／遗物槽）、适配判据与逐角色槽位集合；槽位定义与角色配置解耦，适配按槽位标识判断而不按固定部位判断，装备本身不产生新的装备槽；
- 装配槽位登记并校验：槽位标识唯一、角色配置引用的槽位已登记、遗物槽类别齐备；
- 持有装备槽状态（玩家状态域）：逐角色逐槽位的占用与遗物槽当前数量，随单局创建并重置、结算提交完成时释放（架构案 5.2.3、6.6、8.3 第 3 条）；
- 受理槽位适配判定与换装受理的槽位侧部分；物品侧的归属迁移、容器内容随行与效果启停转由 05-05 执行，物品状态变化一律经 M09 的物品与经济写入服务（`API-M09-005`）落库（架构案 3.4 第 7 项）；
- 判定装备栏（术语表 T-109）开放状态：事件内按该事件属性配置（术语表 T-056）的界面配置字段类声明；事件之外按调用方声明的界面自身属性受理（该属性归 M08 持有，本系统不读取表现层数据）；装备栏界面的内部布局、字段与操作细节归 M08 与界面设计，全量界面清单不搬运（架构案 2.4；设计决策记录决策 94）；
- 装配已装备容器来源视图：给出已装备物品中挂载容器组件的清单及其是否计入背包空间，作为 05-30 重建背包空间与容器识别范围（术语表 T-104）的来源；背包空间是派生结果，由 05-30 按来源状态重建、不入档（架构案 5.2.2、8.2 第 3 条）；
- 装配法术书（术语表 T-152）构成视图：给出已装备法术书的容器内容与「符文书页（术语表 T-151）不进入行动槽（术语表 T-139）序列」的构成口径；
- 受理遗物槽数量的扩充与回收，并维护槽位状态条目（随队伍事件建立、保留与销毁）；
- 提供上述查询与受理接口，并声明本系统数据的可持久化切面与重建步骤。
### 1.3 系统边界
本系统不负责：
- 战斗内一次换装的触发条件、与行动机会的耦合、时间与行动后摇（术语表 T-119）口径、调整状态的退出与该次行动的结束：归 M05 战斗（06-40 技能系统、06-85 战斗行为系统、06-10 战斗总览）；本系统只提供换装受理入口与槽位侧判定，战斗外的换装也不设次数限制、不消耗资源；
- 物品侧的归属迁移、容器内容随行与可调取容器范围重建：归 05-05 物品系统（`API-ITEM-004`）；物品状态变化一律经 M09 的物品与经济写入服务（`API-M09-005`）落库，本系统不得绕过该入口直接改物品状态（架构案 3.4 第 7 项）；
- 元效果的构成、同名判定、强度方向、叠加顺序与生命周期：归 M09 的效果服务（`API-M09-001`～`API-M09-003`）与 06-75 元效果系统；本系统不实现效果叠加，也不自行实现条件判定（`API-M09-004`）；
- 背包空间的计算与容器识别范围的判定：归 05-30 背包系统；容器容量、允许内容约束（术语表 T-083）与嵌套许可的登记与判定归 05-05；
- 法术（术语表 T-149）的释放与可用技能清单的组装：归 06-80 与 06-40；「符文书页不进入行动槽序列」的执行归 06-50 行动槽与连携，本系统只登记构成口径；
- 遗物词条、同名效果判定与遗物交易：归 06-70 遗物系统；本系统只承载遗物槽的槽位与占用；
- 装备的获取、购买、掉落、升级、各装备池投放与品质、契合、容量数值：归内容与数值设计；装备槽适配是取得之后的穿戴判断；
- 装备栏界面、容器界面与技能页面的绘制、布局与操作方式，以及事件之外「界面自身的属性」的持有与判定：归 M08 与后续界面设计阶段；全量界面清单的权威来源是 `架构设计文档/界面索引.md`，本系统不搬运界面清单，只承接装备栏的内部布局、字段与操作细节；本系统只按调用方声明受理，不读取表现层数据（架构案 3.4 第 1、2 项），界面也不得直接修改槽位状态（第 3 项）；
- 世界时间的持有与推进：唯一受理入口是 M01 时间服务（`API-M01-005`）；事件内装备栏打开与调整的耗时只经事件侧记账入口登记（`API-TIME-003`），事件内只做时间记账、事件退出时把累计值一次性推进世界时间（架构案 7.5；术语表 T-186；设计决策记录决策 91），本系统不推进世界时间；
- 存档结构的读写、版本校验与迁移：归 M01 的存档服务与 01-50；本系统只声明可持久化切面与重建步骤。

### 1.5 功能要求
- F-EQUIP-01 普通装备槽的种类和数量固定，由角色配置决定，角色之间的差异不体现在槽位数量上，装备本身不产生新的装备槽。
- F-EQUIP-02 槽位定义与角色配置解耦：角色配置声明自身拥有的槽位集合，装备的物品类型适配按槽位标识而非固定部位判断。
- F-EQUIP-03 遗物槽属于装备槽体系，可以通过已配置的游戏效果增加；扩展遗物槽不改变普通装备槽的种类和数量。
- F-EQUIP-04 装备物品必须同时满足装备组件的槽位适配规则与角色当前槽位状态，才能进入对应装备槽。
- F-EQUIP-05 装备栏在事件内是否开放由该事件属性配置按事件级声明：放开的事件可以装备、卸下与调整，锁定的事件不可打开；事件之外按界面自身的属性决定。
- F-EQUIP-06 战斗内的一次换装由技能触发，一次调整至多包含一次穿戴与一次卸下；玩家确认后换装立即生效并即时影响属性、容器空间与遗物效果，随后退出装备栏调整状态并结束该次行动。
- F-EQUIP-07 战斗外的换装不设次数限制、不消耗任何资源；其时间与后摇口径按触发它的技能配置处理，不单独构成一种战斗行为（术语表 T-135）。
- F-EQUIP-08 拥有容器组件的已装备物品提供背包空间；储物装备被卸下或移动时内部物品保持在原格位随装备一同移动；离开装备槽后其容器格不再计入背包空间，内部物品仍然存在。
- F-EQUIP-09 装备栏槽位内的容器始终属于可被识别的容器格，交易过程中可直接访问与交付，不需要先卸下装备；交付已装备的物品时连同其容器内容一起改变归属。
- F-EQUIP-10 装备成功后启用其装备组件和属性效果，卸下后立即移除；容器内容与效果启停相互独立，卸下装备不会清空其内部物品。
- F-EQUIP-11 装备提供的属性修正与特殊效果统一以元效果的形式附加到角色身上，装备不引入独立于元效果的效果表达机制。
- F-EQUIP-12 法术书同时属于武器并带有容器组件，槽位适配按武器处理；容器容量与允许内容约束由容器组件给出；角色装备法术书后书中全部法术处于可用状态；符文书页不进入行动槽序列。
- F-EQUIP-13 装备的获取与其他物品没有本质区别，装备槽适配是取得之后的穿戴判断。

### 2.3 数据关系
- 包含：装备槽状态按角色分条，角色条目内按槽位分条；槽位登记收录槽位定义与角色槽位配置的索引项。
- 引用：槽位登记引用装备槽定义与角色槽位配置；装备槽状态引用槽位标识与 ITEM 的实例标识；换装请求与受理结果引用装备槽状态与 ITEM 的实例；两个派生视图引用装备槽状态与 ITEM 的容器状态。
- 派生：开放状态判定由事件属性配置的界面配置字段类与调用方声明的界面属性派生；槽位适配判定结果由槽位登记、装备槽状态与装备组件的适配声明派生；两个视图由装备槽状态与容器状态派生。派生项一律按来源重建、不入档，读取方不得当作来源状态使用（架构案 8.2 第 3 条）。背包空间与容器识别范围同为派生结果，由 05-30 按本系统 `CLS-EQUIP-008` 的来源视图重建、不入档（架构案 5.2.2、8.2 第 3 条）。
- 互斥：同一槽位同一时刻只能有一个占用实例，同一实例同一时刻只能占用一个装备槽；遗物槽与普通装备槽的类别互不通用，遗物槽数量的变化不得改变普通装备槽的槽位集合。

## 3. 状态定义
### 3.1 状态
| 状态集 | 取值 | 说明 |
| --- | --- | --- |
| 槽位占用状态（`CLS-EQUIP-004`） | 空闲／已占用 | 已占用表示该槽位承载一个实例，占用实例标识随槽位条目保存 |
| 槽位集合形态（`CLS-EQUIP-004`） | 与角色配置一致／已按扩展增量调整／校验不通过 | 已按扩展增量调整表示遗物槽数量多于基准；校验不通过表示占用引用的槽位不在当前槽位集合内 |
| 槽位登记装配状态（`CLS-EQUIP-003`） | 未初始化 → 初始化中 → 已初始化 → 已销毁；初始化中 → 校验不通过 | 由启动物体按单元装配声明顺序显式初始化（架构案 6.1 阶段 3、8.3 第 1 条）；`API-EQUIP-101` 在 配置加载完成 后装配，校验不通过时中止启动 |
| 装备栏开放状态（`CLS-EQUIP-005`） | 放开／锁定／不可判定 | 放开与锁定取事件级声明（事件内）或调用方声明的界面自身属性（事件之外）；不可判定表示事件内字段类不可读或调用方未给出声明（REQ-EQUIP-03） |
| 槽位适配结论（`CLS-EQUIP-007`） | 可适配／不适配 | 不适配时给出失败原因与目标槽位候选 |
| 换装受理状态（`CLS-EQUIP-006`、`CLS-EQUIP-010`） | 待校验／已提交／被拒绝 | 被拒绝表示槽位占用与物品归属均不变化 |
| 派生视图状态（`CLS-EQUIP-008`、`CLS-EQUIP-009`） | 未重建／已重建 | 未重建时查询返回未重建，不返回空清单冒充已重建结果 |
### 3.2 状态转换
```
槽位占用状态：空闲 → 已占用 → 空闲
槽位集合形态：与角色配置一致 → 已按扩展增量调整 → 与角色配置一致
槽位集合形态：与角色配置一致 ／ 已按扩展增量调整 → 校验不通过
槽位登记：未初始化 → 初始化中 → 已初始化 → 已销毁 ／ 初始化中 → 校验不通过（中止启动）
装备栏开放状态：放开 ／ 锁定 ／ 不可判定（按场合判定，互不转换）
槽位适配结论：可适配 ／ 不适配（单次判定取值）
换装受理：待校验 → 已提交 ／ 待校验 → 被拒绝
派生视图：未重建 → 已重建
```
### 3.3 状态转换触发条件
| 转换 | 触发条件 |
| --- | --- |
| 槽位占用 空闲 → 已占用 | `API-EQUIP-003` 受理穿戴，`API-EQUIP-102` 判定可适配，`API-ITEM-004` 物品侧受理成功，`API-EQUIP-103` 落库占用 |
| 槽位占用 已占用 → 空闲 | `API-EQUIP-003` 受理卸下并落库；储物装备的容器格随之不再计入背包空间（F-EQUIP-08） |
| 槽位集合形态 一致 → 已按扩展增量调整 | `API-EQUIP-007` 受理遗物槽扩充并落库（来源与上限待上游补充，REQ-EQUIP-02） |
| 槽位集合形态 已按扩展增量调整 → 一致 | `API-EQUIP-007` 受理遗物槽回收，且回收后数量不低于基准数量 |
| 槽位集合形态 → 校验不通过 | 装载或查询时发现占用引用的槽位不在角色当前槽位集合内，或遗物槽数量低于占用数 |
| 槽位登记 未初始化 → 初始化中 → 已初始化／校验不通过 | 启动物体按单元装配声明顺序显式调用本单元的初始化方法（架构案 6.1 阶段 3、8.3 第 1 条）；`API-EQUIP-101` 在 配置加载完成 后装配且 `API-EQUIP-107` 校验通过时进入已初始化；槽位标识重复、角色配置引用未登记槽位或遗物槽类别缺失时为校验不通过并中止启动 |
| 槽位登记 已初始化 → 已销毁 | 程序结束时的逆序销毁；进程终止不执行销毁序列、不做任何收尾承诺（架构案 6.4、9.4） |
| 装备栏开放状态 各取值 | `API-EQUIP-004` 按受理场合判定：事件内取界面配置字段类，事件之外取调用方声明的界面自身属性；事件内来源不可读或调用方未声明时为不可判定 |
| 槽位适配结论 各取值 | `API-EQUIP-002` 的单次判定给出；不适配时不产生任何状态变化 |
| 换装受理 待校验 → 已提交 | 槽位侧与物品侧均受理成功且槽位占用已落库 |
| 换装受理 待校验 → 被拒绝 | 前置条件不满足、物品侧受理失败或槽位侧落库被拒（一致性口径见 REQ-EQUIP-04） |
| 派生视图 未重建 → 已重建 | `API-EQUIP-105`、`API-EQUIP-106` 在 物品归属变化、存档恢复完成 后重建 |

### 4.2 接口详细定义
### API-EQUIP-001 QuerySlotState 装备槽状态查询
职责：返回指定角色的槽位定义、槽位集合形态与逐槽位占用快照，作为槽位取数与识别范围的唯一来源。输入：参数输入：角色标识或集合、槽位标识或类别、查询时刻；状态输入：槽位登记装配状态 `CLS-EQUIP-003`、装备槽状态 `CLS-EQUIP-004`；数据输入：`CLS-EQUIP-001`、`CLS-EQUIP-002`；外部事件输入：无。读取：`CLS-EQUIP-001`、`CLS-EQUIP-002`、`CLS-EQUIP-003`、`CLS-EQUIP-004`。输出：返回值：槽位定义与槽位顺序、槽位集合形态与逐槽位占用快照（只读，不携带写入口）；状态输出：无；事件输出：无；外部系统调用：无。产生的状态变化：无。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条），槽位登记处于已初始化（由启动物体按装配声明顺序显式初始化）；查询范围内的角色已建立装备槽状态条目。后置条件：快照与最近一次已落库的占用一致；读取方不得把快照缓存为自身数据（架构案 8.2 第 3 条）。副作用：无。异常情况：本单元未完成初始化或槽位登记处于校验不通过；角色条目缺失；槽位集合形态为校验不通过；查询发生在读档恢复期间。
### API-EQUIP-002 EvaluateSlotFit 槽位适配判定
职责：按装备组件的槽位适配声明与角色当前槽位状态判定实例能否进入目标槽位，并给出目标槽位或失败原因。输入：参数输入：角色标识、实例标识、目标槽位标识或候选范围；状态输入：`CLS-EQUIP-004` 的占用与槽位集合形态、实例存续状态；数据输入：`CLS-EQUIP-001`、`CLS-EQUIP-002`、装备组件的适配声明（`API-M04-002`、`API-ITEM-002`）、遗物词条与类别（`API-RELIC-001`，仅遗物槽）；外部事件输入：无。读取：`CLS-EQUIP-001`、`CLS-EQUIP-003`、`CLS-EQUIP-004`、ITEM 的组件能力与实例状态、RELIC 的遗物词条。输出：返回值：`CLS-EQUIP-007`（结论、目标槽位、失败原因）；状态输出：无；事件输出：无；外部系统调用：`API-M04-002`、`API-ITEM-002`、`API-RELIC-001`。产生的状态变化：无。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；实例存续且挂载装备组件；角色已建立装备槽状态条目。后置条件：判定只按槽位标识匹配，不按固定部位或物品用途名称判定；不适配时不产生任何状态变化。副作用：无。异常情况：实例未挂载装备组件；目标槽位不在角色当前槽位集合内；槽位已被占用；遗物槽数量不足或实例不携带遗物词条；适配声明或遗物词条取数不可用；角色侧可装备物品类型的差异口径待上游补充（REQ-EQUIP-05）。
### API-EQUIP-003 SubmitEquipmentChange 换装受理
职责：受理一次穿戴或卸下的槽位侧部分：判定开放状态与适配、转调物品侧受理、落库槽位占用并返回结果。输入：参数输入：`CLS-EQUIP-006` 换装请求；状态输入：`CLS-EQUIP-004`、当前阶段（`API-M10-001`）；数据输入：`CLS-EQUIP-001`、`CLS-EQUIP-002`、`CLS-EQUIP-003`；外部事件输入：无。读取：`CLS-EQUIP-001`、`CLS-EQUIP-003`、`CLS-EQUIP-004`、事件属性配置的界面配置字段类与界面自身属性、当前阶段、ITEM 的实例与组件状态。输出：返回值：`CLS-EQUIP-010`（受理结论、失败原因、槽位变化、时间消费点标识）；状态输出：槽位占用按 3.2 迁移并落库；事件输出：无（归属变化与效果启停由物品侧与效果服务按其自身契约发布）；外部系统调用：`API-EQUIP-004`、`API-EQUIP-002`、`API-ITEM-004`、`API-EQUIP-105`、`API-EQUIP-106`、`API-SAVE-009`、`API-M01-010`；目标或来源槽位为遗物槽时追加 `API-RELIC-003` 遗物启停同步（在槽位占用落库之后调用，避免同一次启停被两次受理）。产生的状态变化：穿戴时目标槽位由空闲转已占用；卸下时来源槽位由已占用转空闲；被拒绝时不产生任何状态变化。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；受理场合与开放状态允许换装；确认标记为已确认；实例存续且适配判定为可适配；当前阶段允许改变局内状态（非结算阶段）；一次调整至多包含一次穿戴与一次卸下（F-EQUIP-06）。后置条件：返回成功时槽位占用已落库且与物品归属一致；返回失败时槽位占用保持受理前内容。副作用：转调 `API-ITEM-004` 执行物品侧归属迁移、容器内容随行与效果启停（该受理经 M09 的物品与经济写入服务 `API-M09-005` 落库，本系统不直接改物品状态，架构案 3.4 第 7 项）；重建两个派生视图；拒绝与落库失败经日志服务记录。异常情况：装备栏在事件内未开放；结算阶段受理；槽位不适配；槽位已占用；实例已销毁或未挂载装备组件；物品侧受理失败或 M09 的物品与经济写入服务（`API-M09-005`）不可用；槽位侧落库被拒（跨域一致性口径见 REQ-EQUIP-04）；重复提交；同一角色同一槽位并发调整；读档恢复期间受理。
### API-EQUIP-004 EvaluateEquipmentBarOpen 装备栏开放状态判定
职责：按受理场合判定装备栏当前能否打开，并给出依据来源。输入：参数输入：受理场合（事件内／事件之外／战斗内）、事件实例标识、界面标识、事件之外场合的界面开放声明；状态输入：当前事件实例存续状态（`API-M02-001`）；数据输入：事件属性配置的界面配置字段类（读取入口见 REQ-EQUIP-03）；外部事件输入：无。读取：事件属性配置 `CLS-EVENT-003`。输出：返回值：`CLS-EQUIP-005`（放开／锁定／不可判定与依据）；状态输出：无；事件输出：无；外部系统调用：`API-M02-001`。产生的状态变化：无。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；受理场合可判定；事件内场合下事件实例标识可解析且处于进行中，事件之外场合下调用方已给出界面开放声明。后置条件：判定不改变任何状态、不写入事件或界面配置；战斗内场合只返回依据标识，触发资格由 M05 的技能规则裁定。副作用：无。异常情况：界面配置字段类无对外读取入口（REQ-EQUIP-03）；事件之外调用方未给出界面开放声明；事件实例不在进行中；受理场合缺失。
### API-EQUIP-005 QueryEquippedContainerSources 已装备容器来源查询
职责：返回已装备物品中挂载容器组件的清单及其是否计入背包空间与识别范围，供消费方重建背包空间。输入：参数输入：队伍标识或角色标识、场合标识；状态输入：`CLS-EQUIP-004`、派生视图状态 `CLS-EQUIP-008`；数据输入：ITEM 的组件能力与容器状态（`API-M04-002`、`API-ITEM-002`）；外部事件输入：无。读取：`CLS-EQUIP-004`、`CLS-EQUIP-008`、ITEM 的容器状态与容器开关。输出：返回值：`CLS-EQUIP-008`（容器清单、按装备栏既定槽位顺序排列的次序、容器引用、是否计入背包空间、是否属于可识别容器格）；状态输出：无；事件输出：无；外部系统调用：`API-M04-002`、`API-ITEM-002`。产生的状态变化：无。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；派生视图已重建。后置条件：只返回来源标识与只读引用，不返回容器状态的可变引用；背包空间本体不由本系统计算。副作用：无。异常情况：派生视图未重建（返回未重建）；场合标识缺失；容器状态取数不可用；嵌套容器的容量与格位不计入的结果按 ITEM 的容器状态给出。
### API-EQUIP-006 QuerySpellbookComposition 法术书构成查询
职责：返回已装备法术书的容器内容与构成口径，供法术可用清单与行动槽序列取数。输入：参数输入：角色标识；状态输入：`CLS-EQUIP-004`、派生视图状态 `CLS-EQUIP-009`；数据输入：ITEM 的容器状态与词条（`API-ITEM-002`）；外部事件输入：无。读取：`CLS-EQUIP-004`、`CLS-EQUIP-009`、ITEM 的容器状态与词条。输出：返回值：`CLS-EQUIP-009`（已装备法术书清单、容器内容即符文书页清单、书页不进入行动槽序列的构成口径）；状态输出：无；事件输出：无；外部系统调用：`API-ITEM-002`。产生的状态变化：无。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；派生视图已重建；角色已建立装备槽状态条目。后置条件：只给出构成与口径，不给出法术可用性结论与释放结果（归 06-80）。副作用：无。异常情况：派生视图未重建；已装备法术书的容器内容取数不可用；角色未装备法术书时返回空构成并标明未装备。
### API-EQUIP-007 SubmitSlotSetChange 槽位集合变更受理
职责：受理遗物槽数量的扩充与回收，并落库槽位集合形态。输入：参数输入：角色标识、变更类别（扩充／回收）、变更量、来源标识；状态输入：`CLS-EQUIP-004` 的槽位集合形态与占用；数据输入：`CLS-EQUIP-002` 的遗物槽基准数量与上限；外部事件输入：无。读取：`CLS-EQUIP-002`、`CLS-EQUIP-003`、`CLS-EQUIP-004`。输出：返回值：受理结果与变更后的槽位集合形态；状态输出：槽位集合形态按 3.2 迁移并落库；事件输出：无（来源效果的 效果附加／效果移除 由 M09 发布）；外部系统调用：`API-SAVE-009`、`API-M01-010`。产生的状态变化：遗物槽当前数量增减；回收至低于占用数或低于基准数量时拒绝。前置条件：本单元已完成初始化（架构案 6.1 阶段 3、8.3 第 1 条）；来源标识已登记；变更量为正整数且落在配置上限内；当前阶段允许改变局内状态（非结算阶段）。后置条件：普通装备槽的槽位集合不受影响（F-EQUIP-03）。副作用：被拒绝项经日志服务记录。异常情况：扩展来源、作用对象与上限待上游补充（REQ-EQUIP-02）；回收后数量低于占用数；变更量非法；结算阶段受理。

### 5.2 功能之间的关系
- `API-EQUIP-003` 依次调用 `API-EQUIP-104` 判定开放状态、`API-EQUIP-102` 判定适配、`API-ITEM-004` 完成物品侧受理，再由 `API-EQUIP-103` 落库并调用 `API-EQUIP-105`、`API-EQUIP-106` 重建派生视图；任一环节被拒绝时不做落库、不重建视图。
- `API-EQUIP-101` 先调用 `API-EQUIP-107` 完成登记校验，再产出 `CLS-EQUIP-003`；`API-EQUIP-007` 复用 `API-EQUIP-107` 的扩充校验与 `API-EQUIP-103` 的落库。
- `API-EQUIP-103` 是槽位状态条目的唯一维护与落库入口，也是 队伍成员加入、队伍成员离队、主角变化、队伍重置 与 存档恢复完成 的唯一响应点。
- `API-EQUIP-104` 是装备栏开放状态的唯一判定点，被 `API-EQUIP-003` 与外部查询共用；判定结果不缓存、不写入任何配置或状态。
- `API-EQUIP-001`、`API-EQUIP-002`、`API-EQUIP-005`、`API-EQUIP-006` 为只读查询，不触发落库、不产生事件；`API-EQUIP-002` 复用 `API-EQUIP-102`。

### 6.4 使用方式
- 初始化序列：常驻对象由常驻场景承载，本单元在单元装配声明中登记依赖关系，由启动物体按声明顺序显式初始化并注入相互引用（架构案 2.4.1、6.1 阶段 3、8.3 第 1 条）；初始化时经 `API-SAVE-001` 登记玩家状态域切面，并显式复位自身状态、不依赖引擎的域重载（架构案 8.3 第 7 条、8.6 第 5 条）；订阅 配置加载完成 后由 `API-EQUIP-101` 装配槽位登记。
- 配置取数：装备槽定义与角色槽位配置的运行期权威载体是引擎编辑器内的配置资产（启动阶段一次性加载、运行期只读、不带热重载）；`系统设计文档/` 的扩展配置表是初始素材与迁移来源，程序侧不直接读表（架构案 5.1、7.9、8.6 第 10 条；设计决策记录决策 93）。过渡口径：在引擎侧资产建立起来之前，设计库的配置表仍是唯一的配置内容载体，表内容不提前废弃（设计决策记录决策 93）。
- 运行期取数：槽位、适配、容器来源与法术书构成一律经 `API-EQUIP-001`、`API-EQUIP-002`、`API-EQUIP-005`、`API-EQUIP-006` 直接调用，返回只读视图，调用方不得缓存（架构案 4.2）。
- 运行期写入：换装经 `API-EQUIP-003` 受理，槽位侧落库经 `API-SAVE-009`，物品侧转调 `API-ITEM-004`（该受理经 M09 的物品与经济写入服务 `API-M09-005` 落库）；本系统不直接改物品字段、不绕过物品写入服务、不自行序列化状态（架构案 3.4 第 5、7 项、7.11、8.2）。
- 效果联动：装备来源的启停经 `API-EFFECT-001` 同步，效果实例的施加与移除由物品侧按其契约执行；本系统不实现效果叠加或条件判定（架构案 3.4 第 8 项、7.11）。
- 事件侧：开放状态由 `API-EQUIP-004` 按需判定、不缓存；事件内调整的耗时经 `API-TIME-003` 记入事件时间记账，调用方按 02-30 登记的记账路径确定；事件内只做记账、事件退出时把累计值一次性推进世界时间，本系统不推进世界时间（架构案 3.4 第 10 项、7.5；设计决策记录决策 91）。
- 事件间接获得：配置加载完成、存档恢复完成、物品归属变化 与队伍事件经 `API-M01-012` 订阅获得，不轮询他方状态；订阅依据是事件契约登记表内的类型契约（事件名、唯一发布方、载荷字段类别与失败语义），本系统不发布跨模块事件，受理侧不做运行期登记校验（架构案 4.3、7.6、8.4 第 2 条）。
### 6.5 依赖方向限制
分层与模块是架构案的**描述性分类**，不承担数据隔离、交互隔离与依赖方向约束职责（架构案 1.6）。本节只用于阅读导航：列出本单元实际依赖的模块与方向，以及仍然成立的少量硬规则。调用是否合法的判据是架构案 3.3 的允许清单、3.4 的禁止清单与 8.1 的依赖方向规则；**同层只读查询按 3.3 第 5 项的通则成立，不需要逐条登记、不需要逐条例外申报**（架构案 8.1、8.2）。

- 依赖方向（阅读导航）：M01 的基础设施能力——配置服务、日志服务、事件分发器、三个数据域与存档入口（架构案 3.3 第 9、10 项）；M02 的事件实例状态与事件属性配置为同层只读查询（架构案 3.3 第 5 项通则）；M10 的阶段只读查询（架构案 3.3 第 12 项）；M09 的效果服务与物品与经济写入服务（架构案 3.3 第 8 项、3.4 第 8 项、7.11），其中物品写入经 05-05 的 `API-ITEM-004` 物品侧受理转交，本系统不直接调用写入服务；05-05、05-30 与 01-40 是主模块内成员系统与相邻单元，按 ID 引用其已定义对象与接口。
- 被依赖方向（阅读导航）：M05 经 `API-EQUIP-001`、`API-EQUIP-002`、`API-EQUIP-003`、`API-EQUIP-006` 读取槽位与法术书取数、适配结论并提交战斗内的一次调整；05-05 经 `API-EQUIP-001`、`API-EQUIP-002` 做适配比对与容器识别取数；05-30 经 `API-EQUIP-005`、`API-EQUIP-001` 重建背包空间与识别范围；05-10 经 `API-EQUIP-005`、`API-EQUIP-001` 取付款来源范围；M07 与 01-40 经 `API-EQUIP-001` 取槽位定义；M08 经 `API-EQUIP-004`、`API-EQUIP-002`、`API-EQUIP-003`、`API-EQUIP-001` 取数并只经意图与命令提交（架构案 8.4 第 5 条、9.5.8）。
- 硬规则：
  1. 不写入他方数据、不持有对方的可变引用；跨域变更经持有方入口（架构案 3.4 第 5 项、8.2）。装备槽状态的一切变更经 `API-EQUIP-003`（遗物槽为 `API-EQUIP-007`）与玩家状态域提交入口；物品状态的一切变更经 M09 的物品与经济写入服务（`API-M09-005`），本系统只提交物品侧受理请求。
  2. 不绕过统一入口：存档与数据域提交、物品写入、效果叠加、随机源、世界时间、资源、场景、输入、日志一律经对应服务（架构案 3.4 第 6 至 10 项、第 7 章）。
  3. 基础设施不依赖任何具体玩法系统（架构案 3.4 第 11 项）。
  4. 不形成循环依赖；跨模块状态广播走事件通道（架构案 3.4 第 12 项、8.4 第 1 条）。本系统不发布跨模块事件，归属变化与效果启停由物品侧与效果服务按其契约发布。
  5. 不使用系统基础库的随机源、不在游戏状态判定中使用帧时间、不依赖引擎的退出回调完成存档或收尾（架构案 3.4 第 15 至 17 项）。
  6. 不重复实现引擎已提供的能力（架构案 7.12、8.6 第 1 条）。
- 禁止方向：任何模块不得直接修改装备槽状态、不得绕过 `API-EQUIP-003` 改写槽位占用，也不得持有槽位状态的可变引用（架构案 3.4 第 5 项、8.2）；界面不得直接修改槽位状态，未确认的编辑态不得提交（架构案 3.4 第 3 项、8.4 第 5 条、9.5.8）；本系统不得绕过 M09 自行实现效果叠加或条件判定（架构案 3.4 第 8 项、7.11），也不得自行读写存档、自行创建随机源、直接推进世界时间、自行加载资源或自行实现事件观察者（架构案 3.4 第 6、9、10 项与第 7 章）。
- 与 05-05 之间的双向调用：本系统调用 `API-ITEM-004` 完成物品侧受理，05-05 经 `API-EQUIP-001`、`API-EQUIP-002` 取得槽位定义与适配结论；两端同属主模块 M04，属对象侧与槽位侧的分工。物品状态的落库统一在 M09 的物品与经济写入服务，不存在第二条写入路径（架构案 3.4 第 7 项）。
- 唯一事实来源：本文档只定义 §2 的数据对象与 §4 的七项对外能力；05-05、05-30、M04、M09、M02、M07、M10 已定义的对象与接口一律引用其 ID。

| 队伍成员加入、队伍成员离队、主角变化、队伍重置 | 订阅 | 队伍与角色（M07） | 成员标识与主角标识、重置后的成员集合 | 处理失败不回滚队伍变化；条目在角色首次取数或战斗开始时补建，重置时按局重建占用 |
| 效果附加、效果移除 | 关联（不发布、不订阅） | M09 元效果服务与 06-75 | 来源标识、效果标识、生效与保留划分 | 由 M09 发布；本系统按其结果刷新派生视图，不重复施加或移除效果 |
本系统不发布跨模块事件：装备造成的归属变化、容器内容变化与效果启停由物品侧与效果服务按其自身契约发布；遗物槽数量的变化随其来源效果的 效果附加／效果移除 被订阅方感知；槽位占用的读取方一律按需查询，不得缓存（架构案 8.2 第 3 条）。跨模块事件的契约以**类型契约**的形式确定：登记事件名、唯一发布方、载荷字段类别与失败语义；契约的强制方式是一条**对账测试**——测试遍历代码中的全部事件发布点并与登记表逐项比对，出现未登记事件即测试失败。本系统没有发布点，只按登记表订阅；订阅的事件名不在登记表内属于契约缺口，由对账测试在测试期发现，不在运行期拦截（架构案 4.3、7.6、8.4 第 2 条）。

## 8. 核心流程
### 8.1 事件内换装与装备效果的启停
- 触发：玩家在装备栏界面提交一次穿戴或卸下，或由事件侧发起同一次调整。参与者：M08 装备栏界面、本系统、05-05 物品系统、M09 效果服务与 06-75、02-30 与 M10 事件执行器、M01 数据域与日志服务。
- 调用顺序：1 输入服务分发意图，界面组装换装请求并到达提交点；2 调用 `API-EQUIP-004` 判定开放状态，锁定或不可判定时拒绝；3 调用 `API-EQUIP-002` 判定适配并确定目标槽位；4 调用 `API-EQUIP-003`，由 `API-EQUIP-103` 落库槽位占用；5 转调 `API-ITEM-004` 完成物品侧归属迁移、容器内容随行与效果启停（物品状态的落库由物品侧转交 M09 的物品与经济写入服务 `API-M09-005`，本系统不绕过该入口）；6 目标或来源槽位为遗物槽时按 `API-RELIC-003` 同步遗物启停；7 按 `API-EFFECT-001` 同步装备来源的启停状态，效果实例由物品侧经 `API-M09-001`、`API-M09-002` 施加或移除；8 重建 `CLS-EQUIP-008`、`CLS-EQUIP-009`；9 由事件侧按消费点经 `API-TIME-003` 记入事件时间记账；10 界面按新状态刷新。
- 状态变化与事件：槽位占用按 3.2 迁移；物品归属与容器内容由物品侧按其契约变化并经 M09 的物品与经济写入服务落库；背包空间与识别范围由 05-30 重建，本系统不持有其副本；效果实例与来源绑定由效果服务按差额变化。产生的事件：物品归属变化、容器内容变化（物品侧发布）、效果附加或效果移除（M09 发布）。
- 结束条件：界面按新状态刷新并可交互；被拒绝时不产生任何状态变化并给出原因。
### 8.2 战斗内由技能触发的一次换装
- 触发：玩家在战斗中释放允许换装的技能，进入该次装备栏调整（F-EQUIP-06）。参与者：M05 战斗（06-40、06-85、06-10）、本系统、05-05 物品系统、M09 效果服务。
- 调用顺序：1 M05 按技能配置开放一次调整，约束为至多一次穿戴与一次卸下；2 调用 `API-EQUIP-002` 给出候选槽位与适配结论；3 玩家确认时调用 `API-EQUIP-003` 受理，槽位侧判定、物品侧受理与遗物启停同 8.1 的第 4 至 6 步；4 重建两个派生视图；5 换装立即生效，属性与遗物效果的取数由 M05 在本次行动结算中经 `API-M09-003`、`API-M07-004` 取得，容器空间经 `API-EQUIP-005`、`API-EQUIP-006` 取得；6 由 M05 退出装备栏调整状态并结束该次行动。
- 状态变化与事件：槽位占用迁移；物品归属与效果启停按物品侧与效果服务语义变化；行动相关状态由 M05 按其契约变化。产生的事件：物品归属变化、容器内容变化、效果附加或效果移除（行动相关事件由 M05 发布）。
- 结束条件：M05 结束该次行动；本系统在受理返回后即结束参与，不占用行动机会、不计后摇、不推进世界时间。
### 8.3 储物装备卸下后的容器空间与识别范围重建
- 触发：一次卸下受理成功，或队伍成员发生变化。参与者：本系统、05-30 背包系统、05-05 物品系统、05-10 金钱与货物（交易侧只读取数）。
- 调用顺序：1 本系统在受理成功后重建 `CLS-EQUIP-008`；2 订阅到 物品归属变化 后由 `API-EQUIP-105` 刷新；3 05-30 经 `API-EQUIP-005` 取得容器清单并重建背包空间与识别范围；4 卸下的储物装备其容器格不再计入背包空间，内部物品保持在原格位随装备移动；5 装备栏槽位内的容器仍属于可被识别的容器格，交易侧可直接访问与交付。
- 状态变化与事件：槽位占用迁移；派生视图刷新；背包空间由 05-30 重建，本系统不持有背包空间副本；产生的事件：无（本系统不发布事件，物品侧发布 物品归属变化、容器内容变化）。
- 结束条件：`API-EQUIP-005` 返回的来源与最近一次已落库的槽位占用一致。
### 8.4 读档恢复后的槽位与派生视图重建
- 触发：存档恢复完成。参与者：M01 存档服务、本系统、05-05、05-30、01-50 存档与持久化。
- 调用顺序：1 按恢复顺序在玩家状态域阶段装载装备槽状态；2 `API-EQUIP-103` 按装载内容重建角色与槽位条目；3 校验占用引用的槽位在当前槽位集合内、占用实例在单局状态域内可解析；4 `API-EQUIP-105`、`API-EQUIP-106` 重建两个派生视图；5 由 05-30 按 `API-EQUIP-005` 重建背包空间与识别范围；6 恢复过程不重新施加效果、不重新抽取任何随机结果；7 自上一个自动保存节点以来的进度不恢复，未确认的操作不恢复（架构案 5.3 第 5 项、9.3）。
- 状态变化与事件：装备槽状态按存档恢复；派生视图重建；校验不通过时槽位集合形态置为校验不通过。产生的事件：无（由 存档恢复完成 驱动，本系统不另发事件）。
- 结束条件：查询返回与最近一次提交一致的槽位占用；派生视图与来源状态一致。

| # | 情形 | 判定条件 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 结算阶段受理换装或槽位集合变更 | 当前阶段为结算阶段（`API-M10-001`）且请求改变局内状态 | 拒绝受理，槽位占用与物品归属均不变化，记日志（架构案 6.6、8.3 第 5 条） |

| 6 | 实例不可装备 | 实例已销毁、未挂载装备组件，或法术书的容器内容不满足允许内容约束 | 拒绝受理，记内容日志 |
| 7 | 未确认的编辑态被提交 | 换装请求的确认标记为未确认 | 拒绝受理，不产生任何状态变化（架构案 9.5.8） |

| 9 | 槽位侧落库被拒 | 数据域提交入口拒绝或失败 | 受理结果标记失败并记日志；槽位占用与物品归属的跨域一致性口径待上游补充（REQ-EQUIP-04），在此之前不得以槽位侧单独成功的形式返回成功 |
| 10 | 同一实例重复提交 | 实例已在目标槽位，或卸下时实例不在该槽位 | 拒绝重复受理，不产生重复变更 |
| 11 | 同一角色同一槽位并发调整 | 同一批次内对该槽位多次提交 | 按提交顺序串行受理，后到者在前一结果上判定，不合并 |
| 12 | 读档恢复期间的槽位写入 | 玩家状态域处于装载或恢复期间 | 拒绝受理，恢复完成后按切面内容重建条目与占用 |
| 13 | 派生视图未重建 | `API-EQUIP-005`、`API-EQUIP-006` 在重建前被调用 | 返回未重建，不返回空清单冒充已重建结果 |
| 14 | 遗物槽扩展来源未登记 | `API-EQUIP-007` 的来源标识未登记，或扩展来源待上游补充 | 按未登记拒绝，槽位集合形态保持与角色配置一致（REQ-EQUIP-02） |
| 15 | 调用方缓存查询结果或越界取数 | 读取方把槽位快照当作来源状态，或战斗内请求识别队友装备的容器 | 前者判定为违反架构案 8.2 第 3 条；后者按 05-05 §3.1 的场合规则拒绝 |
| 16 | 进程在两次自动保存之间被终止 | 退出、强制关闭、平台关闭或异常终止 | 退出即进程终止，不构成提交点、不执行销毁序列、不依赖任何退出回调完成存档或收尾（架构案 3.4 第 17 项、5.3 第 4 项、6.4、9.4；设计决策记录决策 89）；自上一个自动保存节点以来的进度不恢复，重启后必须能正常启动并继续游玩 |

## 10. 实现约束
### 10.1 实现约束条目
- 槽位定义与角色槽位配置必须分离登记，角色槽位配置只解析角色配置声明的槽位集合（声明本体归 01-40）；槽位标识在全库唯一，物品适配一律按槽位标识匹配，不得按固定部位或物品用途名称建立互斥判断（05-05 §2.1、§2.3）。
- 装备槽状态（玩家状态域）必须可序列化并登记切面；槽位占用的一切变更必须经 `API-EQUIP-003`（遗物槽为 `API-EQUIP-007`）与玩家状态域提交入口，不得自行序列化状态、不得直接读写存档；存档序列化采用**判别字段式多态序列化**，序列化结果中只出现自定义的字符串判别值、不写入运行时类型名，单局存档的写入必须原子（架构案 3.4 第 6 项、5.3 第 4 项、7.1、8.2、8.6 第 8 条）。
- 物品归属迁移、容器内容随行与组件效果启停必须经 `API-ITEM-004`，物品状态变化一律经 M09 的物品与经济写入服务（`API-M09-005`）落库；本系统不得绕过该唯一入口直接改物品状态，也不得持有物品实例与容器状态的可变引用或重定义其结构（架构案 3.4 第 5、7 项、7.11）。
- 效果必须以元效果为唯一表达；本系统不得实现效果叠加、同名判定、强度方向比较与条件判定（架构案 3.4 第 8 项、7.11）。
- 背包空间与容器识别范围由 05-30 按本系统提供的来源视图重建，**背包空间是派生结果**、按来源状态重建、不入档，本系统不得持有其结果副本，也不得按派生结果反推来源状态；槽位登记、开放状态判定与两个派生视图一律按来源重建、不入档、不得跨帧缓存（架构案 5.2.2、8.2 第 3 条）。
- 本系统不发布跨模块事件（归属变化与效果启停由物品侧与效果服务按事件契约登记表内的类型契约发布，不得另立事件名），不推进世界时间，不创建随机源；事件内装备栏打开与调整的耗时只经 `API-TIME-003` 登记，战斗内换装的时间与后摇口径归 M05（架构案 4.3、7.6、8.4 第 1、2 条、3.4 第 9、10 项、7.5）。
- 结算阶段不得建立、销毁或变更装备槽状态条目与槽位集合形态（架构案 6.6、8.3 第 5 条）。
- 界面不得直接修改槽位状态；一切来自界面的换装必须经意图与命令提交到 `API-EQUIP-003`，未确认的编辑态不提交（架构案 3.4 第 3 项、8.4 第 5 条、9.5.8）。
- 待上游补充的字段为空时（遗物槽扩展来源与上限、界面配置字段类读取入口、角色侧可装备限制）或调用方未给出界面开放声明时，相关判定必须返回拒绝或不可判定，不得以默认值代替。
- 临时运行对象不得跨帧保留、不得入档；被拒绝的受理不得留下任何中间状态，拒绝与不通过项一律经日志服务记录（架构案 7.7）。
- 常驻对象由常驻场景承载，只能由启动物体按单元装配声明顺序显式初始化并注入相互引用；本单元在初始化时显式复位自身状态，不依赖引擎的域重载提供初始状态（架构案 2.4.1、6.1 阶段 3、8.3 第 1、7 条、8.6 第 5 条）。
- 运行期配置的权威载体是引擎编辑器内的配置资产；`系统设计文档/` 的扩展配置表是初始素材与迁移来源，程序侧不直接读表，内容侧不直接改运行期资产（架构案 5.1、7.9、8.6 第 10 条；设计决策记录决策 93）。
- 装备栏的开放状态由事件属性配置按事件级声明；全量界面清单的权威来源是 `架构设计文档/界面索引.md`，本系统只承接装备栏的内部布局、字段与操作细节，不搬运界面清单，也不读取表现层数据（架构案 2.4；设计决策记录决策 94）。
- 装备槽与遗物槽属玩家状态域，随单局创建并重置、结算提交完成时释放；背包空间是派生结果，由 05-30 按来源状态重建、不入档（架构案 5.2.3、5.2.2、6.6、8.3 第 3 条、8.2 第 3 条）。
- 退出不构成提交点：退出游戏即进程终止，不提交存档、不执行销毁序列、不依赖任何退出回调完成存档或收尾（架构案 3.4 第 17 项、5.3 第 4 项、6.4、7.1、9.4；设计决策记录决策 89）。
- 引擎侧：不重复实现引擎已提供的能力（对象池与集合池、异步任务、资产载体与序列化原语、资源加载、场景装卸与日志通道等）；权威游戏状态由普通对象持有，引擎对象只承担承载、呈现与编辑器配置职责；不依赖引擎的启动回调顺序、脚本执行顺序或帧回调顺序满足顺序要求；影响游戏状态的判定不得使用帧时间、不得引入暂停语义（架构案 7.12、8.6 第 1、2、4、6 条）。
### 10.2 实现要求
- I-EQUIP-01 槽位定义与角色槽位配置必须分离登记，物品适配必须按槽位标识匹配。
- I-EQUIP-02 槽位标识必须全库唯一；角色槽位配置引用的槽位必须已登记，未登记不得进入槽位登记。
- I-EQUIP-03 装备槽状态必须可序列化并登记玩家状态域切面；一切变更经 `API-EQUIP-003`、`API-EQUIP-007` 与玩家状态域提交入口；存档序列化采用**判别字段式多态序列化**，序列化结果中只出现自定义的字符串判别值、不写入运行时类型名，单局存档的写入必须原子（架构案 7.1、5.3 第 4 项、8.6 第 8 条）。
- I-EQUIP-04 物品侧归属迁移、容器随行与效果启停必须经 `API-ITEM-004`，物品状态变化一律经 M09 的物品与经济写入服务（`API-M09-005`）落库；本系统不得自行实现、不得绕过该唯一入口直接改物品状态（架构案 3.4 第 5、7 项、7.11）。
- I-EQUIP-05 效果必须经 M09 的效果服务表达，本系统不得实现效果叠加、同名判定与条件判定。
- I-EQUIP-06 背包空间与识别范围必须由 05-30 按 `API-EQUIP-005` 的来源视图重建，本系统不得持有其副本。
- I-EQUIP-07 槽位登记、开放状态判定与两个派生视图不入档，按来源重建，且不得缓存；查询接口必须返回只读视图且不携带写入口。
- I-EQUIP-08 本系统不发布跨模块事件，也不得把「要求谁做什么」写进事件；归属变化与效果启停由物品侧与效果服务按事件契约登记表内的类型契约发布；事件名不在契约登记表内属于契约缺口，由对账测试在测试期发现，不在运行期拦截（架构案 4.3、7.6、8.4 第 2、3 条）。不得推进世界时间、不得创建随机源，事件内耗时只经 `API-TIME-003` 登记（事件内只做时间记账、事件退出时把累计值一次性推进世界时间，架构案 7.5、设计决策记录决策 91）。
- I-EQUIP-09 结算阶段不得变更装备槽状态与槽位集合形态。
- I-EQUIP-10 界面必须经意图与命令提交换装，未确认的编辑态不得提交。
- I-EQUIP-11 待上游补充字段为空时相关判定必须返回拒绝或不可判定，不得取默认值。
- I-EQUIP-12 常驻对象由常驻场景承载，只能由启动物体按单元装配声明顺序显式初始化并注入相互引用；本单元在初始化时显式复位自身状态，不依赖引擎的域重载提供初始状态（架构案 2.4.1、6.1 阶段 3、8.3 第 1、7 条、8.6 第 5 条）。
- I-EQUIP-13 运行期配置的权威载体是引擎编辑器内的配置资产；`系统设计文档/` 的扩展配置表是初始素材与迁移来源，程序侧不直接读表（架构案 5.1、7.9、8.6 第 10 条；设计决策记录决策 93）。过渡口径：在引擎侧资产建立起来之前，设计库的配置表仍是唯一的配置内容载体，表内容不提前废弃（设计决策记录决策 93）。
- I-EQUIP-14 装备栏的开放状态由事件属性配置按事件级声明；全量界面清单的权威来源是 `架构设计文档/界面索引.md`，本系统只承接装备栏的内部布局、字段与操作细节，不搬运界面清单，也不读取表现层数据（架构案 2.4；设计决策记录决策 94）。
- I-EQUIP-15 装备槽与遗物槽属玩家状态域，随单局创建并重置、结算提交完成时释放；背包空间是派生结果，按来源状态重建、不入档（架构案 5.2.3、5.2.2、6.6、8.3 第 3 条、8.2 第 3 条）。
- I-EQUIP-16 退出不构成提交点：退出游戏即进程终止，不提交存档、不执行销毁序列、不依赖任何退出回调完成存档或收尾（架构案 3.4 第 17 项、5.3 第 4 项、6.4、7.1、9.4；设计决策记录决策 89）。
- I-EQUIP-17 不得重复实现引擎已提供的能力：对象池与集合池、异步任务、设备到动作的输入映射、音频与本地化与特效动画的播放原语、资产载体与序列化原语、资源加载、场景装卸与日志通道一律使用引擎提供的能力，项目只做架构案 7.12「项目实现」栏登记的部分（架构案 7.12、8.6 第 1 条）。
- I-EQUIP-18 权威游戏状态由普通 C# 对象持有，引擎对象只承担承载、呈现与编辑器配置职责；不得把权威状态放在随场景销毁的对象上（架构案 8.6 第 2 条）。
- I-EQUIP-19 不依赖引擎的启动回调顺序、脚本执行顺序或帧回调顺序满足初始化与推进的顺序要求；顺序由单元装配声明与显式调用序列决定（架构案 6.1、6.3、8.6 第 4 条）。
- I-EQUIP-20 影响游戏状态的判定不得使用帧时间；不得引入暂停语义（架构案 3.4 第 16 项、8.6 第 6 条）。
