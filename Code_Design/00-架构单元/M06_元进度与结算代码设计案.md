## 1. 系统定义

### 1.1 系统目的

`SYS-M06-001` 元进度与结算是架构案 ARC-M06-001 的模块级单元，承载「跨局的东西」：持有并维护线索树、传闻、封锁集合与池内容集合，在每局结束时以整份存档快照为唯一输入判定结局并把本局成果一次写入跨局数据，是玩家进度中唯一跨局保留的资源在程序上的管理者。

### 1.2 系统职责

- 跨局数据的模块级持有与写入垄断：线索树节点与关系、传闻、封锁集合与封锁标记、达成记录与大关进度归本模块持有；除封锁数据的既定例外外，写入只发生在局末结算的一次提交内（架构案 3.2、5.4、ARC-M06-001）
- 节点、传闻与事件解锁状态的对外只读取数：向地图呈现取数、条件判定引用项、事件刷新过滤、界面呈现与局末结算提供一致快照（架构案 3.3 第 5.1 项、07-10 §3.6 至 §3.9、§3.11）
- 封锁集合与封锁标记的维护：受理局外剪枝提交，维护封锁集合这一权威来源与派生的节点封锁标记，保证撤销后判定恢复（07-20 §3.1 至 §3.4）
- 池内容集合的计算与快照：按开新局时点的解锁与封锁状态一次性确定内容集合，写入世界状态域并在本局内保持不变（架构案 3.2、5.2.5、07-30 §3.3、§3.7）
- 结算组件的内容定义与执行：定义组件清单契约，按组件分工从存档快照取数产出写入项，发起节点、传闻与事件解锁状态以及达成记录与大关进度的写入（07-40 §3.2、§3.3、§3.5、§3.6）
- 结局判定与触发起因：按快照中的关底事件结果与终止情形判定结局类型，产出结局成立的事实（07-40 §3.7、§3.13、架构案 9.5.5、9.5.6）
- 大关进度与达成记录：维护已解锁大关与首次达成时间，重复达成只更新次数与最近时间，不重复推进（07-40 §3.4、§3.8）
- 模块级装配与模块级事件：向服务容器登记能力与依赖声明，按依赖拓扑参与初始化与逆序销毁，发布与订阅本模块事件（架构案 6.3、6.4、8.5.1 第 4 步）

### 1.3 系统边界

本模块负责：跨局数据的持有与取数；节点、传闻与事件解锁状态的既定读出口径；封锁集合与封锁标记的维护与撤销；池内容集合的一次性计算与写入；结算组件的定义清单与执行；结局类型与触发起因的判定；达成记录与大关进度的写入；跨局数据只读快照的装配与刷新。

本模块不负责：

- 结算流程的执行编排：阶段切换、整局存档快照的收集、组件调度顺序、提交动作与局外流转，归 M10 的结算执行器（引用 `API-M10-005 结算执行入口`、`API-M10-002 阶段切换执行`）
- 存档文件与三份持久化结构的读写、提交点管理、版本校验与失败处置，归 01-50 的存档服务（引用 `CLS-SAVE-001`、`API-SAVE-002`；提交由 M10 的结算执行器发起，本模块不直接调用提交入口；架构案 7.1）
- 向其他模块索取结算输入：结算的输入只有整份存档快照，本模块不回读 M02、M04、M05 等模块的运行时状态，也不要求它们在结算时另行上报（架构案 3.1 ARC-M06-001、3.3 第 7 项）
- 局内数据的产生：事件结果、物品归属、战斗结果、队伍编制的产生归各玩法模块，本模块只从快照取数（架构案 3.1 ARC-M06-001、5.3）
- 抽取执行：事件池刷新抽取归 M02，物品池抽取归 05-05，商人经营池抽取归商人原型配置；本模块只定义池与内容集合输入契约（07-30 §1、§3.1、§4）
- 区域形态与当前事件池的刷新范围：形态归 M03，当前事件池归 M02（架构案 5.2.5、07-30 §3.4）
- 触发条件与线索解锁条件的判定实现：条件的组合与引用侧归 M02 的 02-30-10，求值归 M09 的条件求值服务（架构案 7.11、3.4 第 8 项）
- 线索树界面、剪枝界面与结算窗口的绘制、文案投放与界面内编辑态：归 M08；界面只读取本模块的只读快照，不得经界面改变跨局状态（架构案 3.4 第 3 项、2.4 界面清单、07-10 §3.10）
- 空行占位条数的独立记录：占位数量按传闻表登记的条数推导，不作为独立写入项（07-40 §3.3、§3.6）
- 效果叠加、条件判定、物品写入、随机源、时间推进、日志与配置的自行实现（架构案第 7 章、3.4 第 7 至 10 项）

功能要求（编号前缀 `F-`，来源为上游设计）：

- F-M06-01 线索树是唯一跨局保留的记录，记录主线与支线一类具有连贯故事属性的内容及其延伸内容；其余运营资源、战力与仓库内容随局重置（07-10 §1、§2）。
- F-M06-02 本局新解锁的内容只在结算时写入，结算后才能在局外看到；局内查看得到的是历史已解锁状态的只读快照（07-10 §2、§3.10、§3.11）。
- F-M06-03 节点状态取已解锁、锁定可见与隐藏三者之一；剪枝封锁给已解锁节点追加封锁标注，标注不改变节点状态取值，百科页内容保持可读（07-10 §3.5、07-20 §3.5）。
- F-M06-04 开放阈值决定节点对应的事件能否在局内出现，判定在每局结算时执行，只统计处于解锁状态且未被封锁的上游节点，配置取数量或比例（07-10 §3.6、07-20 §3.1、07-40 §3.6）。
- F-M06-05 事件解锁状态跨局保持且不回退，事件在本局被错过只影响本局；节点解锁以玩家首次经历并完成对应事件为准（07-10 §3.7）。
- F-M06-06 事件信息在开新局时按已解锁且未被剪枝的节点集合生成呈现列表，本局内保持静态，本局新解锁内容下一局才进入（07-10 §3.9、07-30 §3.3）。
- F-M06-07 剪枝对已解锁内容做可撤销的暂时封锁，级联取完整级联，被封锁内容按未解锁处理，解锁记录从不被剪枝删除（07-20 §3.1、§3.2）。
- F-M06-08 封锁集合是权威来源，节点上的封锁标记是派生结果，两者不一致时以封锁集合为准并允许重建（07-20 §3.4）。
- F-M06-09 概率池取事件池、物品池与商人经营池三类；解锁把内容加入对应池、剪枝把内容移除，两类修改在开新局计算池成分时一次性应用，局内不再变化（07-30 §3.1、§3.3、§3.7）。
- F-M06-10 全局事件池与当前事件池两层分离：线索树进度只作用于全局事件池，区域形态只作用于当前事件池，两个过滤条件正交（07-30 §3.2、§3.4、§3.6、架构案 5.2.5）。
- F-M06-11 一局的范围是一个大关，终点是关底事件；结局取真结局、隐藏关底事件与未通关结局三种，三种结局的写入差异只体现在达成记录与大关进度两项（07-40 §3.7、§3.13）。
- F-M06-12 结算的输入是整局存档快照，组件从快照取数并把写入项写入跨局数据；写入一次完成，失败整笔回滚，重试不产生重复写入（07-40 §3.2、§3.4、§3.5）。
- F-M06-13 任何结局都写入本局已解锁的节点与传闻；未通关局不推进大关进度，不设保底机制与失败安慰机制（07-40 §3.7、§3.9）。
- F-M06-14 封锁集合与节点封锁标记不经过结算组件；空行占位数量不作为独立写入项；场景变化包装事件默认不产生节点解锁项（07-40 §3.3、§3.6、§3.10）。

### 2.3 数据关系

- 从属关系：传闻从属于节点，事件解锁状态从属于节点；空行占位数量由传闻表登记的条数推导，不独立持有。
- 派生关系：节点封锁标记由封锁集合派生并在提交点重建，但按 07-20 §3.4 随跨局存档入档、装载后校验不一致时重建；`CLS-M06-004` 由跨局数据已提交状态派生，按来源重建、不入档。
- 权威与副本关系：封锁集合是权威来源，节点标记是呈现副本，不一致时以集合为准（07-20 §3.4）；本模块不产生第二个权威副本。
- 计算关系：池内容集合由节点与事件解锁状态、封锁集合与池定义计算得出，写入世界状态域；计算输入不含局内状态，也不含随机量（07-30 §3.3、§3.5）。
- 判定关系：开放阈值判定只统计处于解锁状态且未被封锁的上游节点；判定在节点解锁写入完成后统一执行一次（07-10 §3.6、07-40 §3.6）。
- 写入关系：除封锁数据按架构案 9.5.6 的约束不经结算组件外，本模块的跨局数据写入全部发生在一个局末结算的一次提交内，写入粒度是状态项目（07-40 §3.4、§3.11）。
- 跨单元引用：上表全部对象的结构归各成员系统定义，本模块只登记模块级归属、访问级别与写入边界。

### 2.4 数据生命周期

按架构案 6.5 分类：

- 常驻对象：`CLS-M06-001` 与四个成员系统的常驻系统对象，由服务容器按依赖拓扑创建与逆序销毁（架构案 6.3 第 3 项：领域层中本模块位于 M05 之后）。
- 数据域对象：池内容集合落世界状态域，随单局创建、内容按局重置（架构案 5.2.1、8.3 第 3 条）。
- 跨局数据：线索树节点与关系、传闻、事件解锁状态、封锁集合与封锁标记、达成记录与大关进度跨局保留，随跨局存档存续；局内以只读快照参与判定与呈现，写入只在局末结算的一次提交内（架构案 5.4、ARC-M06-001 生命周期）。
- 场景对象：无（线索树界面、剪枝界面与结算窗口的界面实例归 M08）。
- 临时运行对象：`CLS-M06-002`、`CLS-M06-003` 与写入项、锁定的下游清单等中间量，单次结算或单次计算内有效，不跨帧保留、不入档（架构案 8.3 第 4 条）。
- 存档对象：跨局存档切面与单局存档中的池内容集合条目，只在采集与恢复期间存在，采集完成后即释放。
- 静态配置对象：节点类型表、节点关系表、传闻表、概率池表、结算组件表，启动阶段加载，运行期只读。
- 跨局边界：本局进行中的交易、委托进度、押金、落地物与未领取奖励不进入跨局数据，随本局结束废弃（架构案 5.3 第 1 条）。

### 3.2 状态转换

```
模块能力登记项：未登记 → 已登记 → 装配就绪 → 已销毁
跨局写入批次：收集中 → 执行中 → 已提交 ／ 执行中 → 已回滚 → 收集中（重试）
池内容集合快照：未计算 → 计算中 → 已快照（本局内不再转出）
结算状态：未结算 → 结算中 → 已结算 ／ 结算中 → 未结算（提交失败，整笔回滚）
节点状态与可见性：隐藏 → 锁定可见 → 已解锁（不回退）；已解锁 ⇄ 叠加封锁标注（状态取值不变）
事件解锁状态：已锁定 → 已解锁（不回退）
传闻解锁状态：未解锁 → 已解锁；节点完全揭示时条目追加真／假标记
封锁状态：未封锁 ⇄ 已封锁（以单次操作为粒度撤销）
大关推进状态：未解锁任何大关 → 已解锁至某大关（首次达成真结局时；隐藏关底事件与未通关结局不推进）
```

### 4.2 接口详细定义

本节按 NR-06 §六的契约模板逐项展开；输入与输出按参数输入／状态输入／数据输入／外部事件输入与返回值／状态输出／事件输出／外部系统调用四类分别记录（NR-06 §七）。

#### API-M06-001 节点与传闻查询

职责：按节点标识或过滤条件返回线索树节点、事件解锁状态、传闻与封锁标注的只读快照，作为地图呈现取数、条件引用取数、事件刷新过滤、界面呈现与局末结算判定的共同口径。

输入：参数输入：节点标识集合或节点类型过滤、查询口径（含关系、含传闻、含封锁标注、含触发方法揭示）；状态输入：跨局数据已提交状态（`CLS-M06-004`）；数据输入：节点类型表、节点关系表、传闻表（经 `API-M01-003`）；外部事件输入：无。

读取：线索树节点与关系（`CLS-CLUETREE-002`、`CLS-CLUETREE-004`、`CLS-CLUETREE-006`）、传闻与空行占位（`CLS-CLUETREE-005`、`CLS-CLUETREE-007`）、事件解锁状态（`CLS-CLUETREE-008`）、封锁集合与节点封锁标记（`CLS-PRUNE-001`、`CLS-CLUETREE-009`）、`CLS-M06-004`、节点类型表、节点关系表与传闻表（`API-M01-003`）。

输出：返回值：节点只读视图集合与传闻只读视图集合，含节点状态、事件解锁状态、封锁标注、触发方法揭示结果、空行占位数；状态输出：无；事件输出：无（只读查询不产生事件，架构案 4.5）；外部系统调用：`API-M01-003`、`API-M01-010`（内容问题记录）。

产生的状态变化：无。

前置条件：模块装配状态为已就绪；跨局数据已装载或已完成初始化；查询口径已声明。

后置条件：结果取自跨局数据的已提交状态，不含本局尚未提交结算的成果（07-10 §3.10）；返回快照不携带写入口，读取方不得缓存跨域结果作为数据来源（架构案 8.2 第 3 条、4.2）。

副作用：无。

异常情况：节点标识不存在时返回未找到并记内容日志；隐藏状态的节点不进入返回值；查询条件为空时返回全部可见节点；局外阶段或本局未建立时照常返回跨局内容，不隐式创建任何数据域结构；封锁数据读取不可用时按封锁标注缺失返回并标注，不以默认未封锁代替（见 9 节）。

#### API-M06-002 封锁状态查询

职责：返回封锁集合与节点封锁标记的只读快照，供呈现取数、事件刷新过滤、开放阈值判定与剪枝界面呈现使用。

输入：参数输入：查询口径（按节点标识、按封锁操作批次、全量）、节点标识集合；状态输入：跨局数据已提交状态（`CLS-M06-004`）；数据输入：节点关系表（级联范围摘要取数，经 `API-M01-003`）；外部事件输入：无。

读取：封锁集合（`CLS-PRUNE-001`）、节点封锁标记（`CLS-CLUETREE-009`）、线索树节点与关系（`CLS-CLUETREE-002`、`CLS-CLUETREE-004`、`CLS-CLUETREE-006`）、`CLS-M06-004`、节点关系表（`API-M01-003`）。

输出：返回值：封锁状态只读视图（已封锁节点标识集合、封锁操作归属、级联范围摘要、标记与集合一致性标注）；状态输出：无；事件输出：无；外部系统调用：`API-M01-003`、`API-M01-010`。

产生的状态变化：无。

前置条件：模块装配状态为已就绪；跨局数据已装载或已完成初始化。

后置条件：结果以封锁集合为准；节点标记与集合不一致时按集合返回并标注可重建（07-20 §3.4）；返回快照不携带写入口。

副作用：无。

异常情况：局内调用时照常返回只读快照，不产生任何写入（剪枝只在局外提交，07-20 §3.3）；节点标识不存在时返回未找到；封锁操作批次标识未登记时返回未找到；封锁数据缺失时返回空集合并标注，不按未封锁静默处理。

#### API-M06-003 池内容集合查询

职责：返回指定池的内容集合快照，作为生成流程与当前事件池刷新的内容上界；本局尚未快照时完成一次计算并写入世界状态域。

输入：参数输入：池标识（事件池、物品池、商人经营池）；状态输入：池内容集合快照状态、节点与事件解锁状态、封锁集合；数据输入：概率池表、节点关系表（经 `API-M01-003`）；外部事件输入：无。

读取：池内容集合（`CLS-POOL-002`、`CLS-POOL-003`，世界状态域）、线索树节点与事件解锁状态（`CLS-CLUETREE-006`、`CLS-CLUETREE-008`）、封锁集合（`CLS-PRUNE-001`）、`CLS-M06-003`、`CLS-M06-004`、概率池表与节点关系表（`API-M01-003`）。

输出：返回值：内容集合快照（内容标识集合、内容类别、来源标记、快照批次标识）；状态输出：池内容集合快照 未计算 → 计算中 → 已快照，内容按解锁与封锁结果确定；事件输出：无；外部系统调用：`API-M01-003`、`API-SAVE-009`（首次计算的世界状态域变更提交）、`API-M01-010`。

产生的状态变化：本局首次受理时把计算所得的内容集合写入世界状态域并固定，本局内不再变化；已快照时无状态变化。

前置条件：模块装配状态为已就绪；池标识在概率池表内已登记；本局装配已建立（新开局路径）或单局存档已恢复（读档路径）。

后置条件：同一局内重复查询返回同一快照，不重新计算、不重新过滤（架构案 5.2.5 第 3 条）；读档路径按快照恢复；快照不携带写入口；快照内容不含随机量。

副作用：首次计算产生一次世界状态域变更提交（经 `API-SAVE-009`）；提交被拒绝时快照不建立并记日志。

异常情况：池标识未登记时拒绝并记内容日志；本局装配未建立时拒绝并返回原因，不隐式创建世界状态域结构；计算输入缺失（解锁状态或封锁集合不可读）时返回失败并标注缺失项，不以空集合代替；结算阶段内查询照常返回快照且不改变局内状态（架构案 6.6）；物品池与商人经营池的内容集合落点待上游补充（REQ-M06-11）。

#### API-M06-004 结算组件清单查询

职责：返回本次版本启用的结算组件清单、执行顺序与每个组件的取数来源与写入对象，作为 M10 的结算执行器调度与提交边界的唯一依据。

输入：参数输入：查询口径（本次版本启用／全量登记）；状态输入：本局结算状态（`CLS-SETTLE-003`）；数据输入：结算组件表（`CLS-SETTLE-001`，经 `API-M01-003`）；外部事件输入：无。

读取：结算组件定义（`CLS-SETTLE-001`）、本局结算状态（`CLS-SETTLE-003`）、`CLS-M06-002`、结算组件表（`API-M01-003`）。

输出：返回值：组件清单（组件标识、负责的跨局数据类别、取数来源、写入对象、生效时点、执行顺序）；状态输出：无；事件输出：无；外部系统调用：`API-M01-003`、`API-M01-010`。

产生的状态变化：无。

前置条件：模块装配状态为已就绪；静态配置已加载（配置加载完成）。

后置条件：清单只列生效状态为已确认的组件；一个组件只负责一类跨局数据，组件之间不写入同一项数据；执行顺序确定且可复核（07-40 §3.3、架构案 8.5.5）。

副作用：无。

异常情况：结算组件表缺失必要登记项时返回失败并记内容日志，不以默认组件代替；本局已结算时清单照常返回，可执行性由组件执行的受理判定（07-40 §3.4）；查询口径非法时拒绝。

#### API-M06-005 大关进度查询

职责：返回已解锁大关与首次达成时间、各结局类型的达成记录与未通关结局的触发起因，供开新局确定世界线起点、达成记录写入与局外界面呈现取用。

输入：参数输入：查询口径（全部已解锁大关／指定大关标识）；状态输入：跨局数据已提交状态（`CLS-M06-004`）、达成记录与大关进度；数据输入：大关清单与标识（载体见 REQ-M06-09，经 `API-M01-003`）；外部事件输入：无。

读取：达成记录与大关进度（`CLS-SETTLE-005`、`CLS-SETTLE-006`）、`CLS-M06-004`、大关清单（`API-M01-003`）。

输出：返回值：大关进度只读视图（已解锁大关标识、首次达成时间、各结局类型的达成次数与最近达成时间、未通关结局的触发起因）；状态输出：无；事件输出：无；外部系统调用：`API-M01-003`、`API-M01-010`。

产生的状态变化：无。

前置条件：模块装配状态为已就绪；跨局数据已装载或已完成初始化。

后置条件：进度取值与跨局数据的已提交状态一致；剪枝不回退大关进度、不改变达成记录（07-20 §3.2、07-40 §3.8）；返回快照不携带写入口。

副作用：无。

异常情况：无跨局存档（首次启动）时返回初始进度（未解锁任何大关、无达成记录），不隐式写入；大关标识不在清单内时返回未找到并记内容日志；大关清单缺失时返回失败并标注（REQ-M06-09）。

### 5.2 功能之间的关系

- 装配路径：模块装配登记与依赖声明 → 服务容器按依赖拓扑创建 → 订阅建立 → 跨局只读快照装配与刷新 → 装配就绪（架构案 6.3 第 3 项、6.4）。
- 开新局路径：`API-M06-003` 首次受理 → 池内容集合计算与一次性快照 → `API-SAVE-009` 提交世界状态域 → 生成流程与事件刷新按快照读取；本局内后续查询不再触发计算。
- 结算路径：M10 收集整局存档快照并请求结局判定 → 本模块经 `API-SETTLE-002` 判定并返回结局类型与触发起因 → M10 发布 结局成立 并经 `API-M10-005` 受理、落定结算阶段 → M10 经 `API-M06-004` 取组件清单 → `API-SETTLE-001` 逐项执行 → 跨局写入项收集与写入边界校验 → M10 一次提交并经 `API-SETTLE-003` 登记回执 → 跨局只读快照刷新。
- 剪枝路径：剪枝提交受理入口（`API-PRUNE-001`、`API-PRUNE-002`）→ 封锁范围计算与封锁标记重建 → 发布 封锁状态变化 → 下一局开新局时经 `API-M06-003` 生效。
- 只读路径：`API-M06-001`、`API-M06-002`、`API-M06-005` 只读，不触发写入类内部功能，不产生事件（架构案 4.5）。
- 对外能力以 `API-M06-001` 至 `API-M06-005` 为跨模块入口；其余内部功能只在本模块内被调用，其中快照刷新与池内容集合计算由事件、查询与提交回执间接驱动。

### 6.4 使用方式

- 直接调用：配置读取、日志写入、数据域提交与存档切面声明、阶段查询、条件判定，均为同步调用，调用点集中在 `API-M06-003`、`API-M06-004`、`API-M06-005` 与内部功能。
- 经事件间接获得：订阅 配置加载完成（绑定静态定义并自检）、存档恢复完成（重建跨局只读快照）；不轮询、不解析订阅事件的业务分支（M01 文档 7.2 的订阅职责）。
- 受理式调用：M10 的结算执行器收集整局存档快照后，向本模块请求结局判定与组件执行；快照收集、组件调度、提交与阶段流转全部由 M10 执行，本模块只受理判定请求与组件执行请求、不自持流程，也不反向调用 M10 的三个执行入口（架构案 9.5.6、3.3 第 11 项、REQ-M06-05）。
- 跨模块状态广播：本模块只经 `API-M01-011` 发布，不自行实现观察者（架构案 8.4 第 1 条）。
- 数据共享：只读取他方数据；跨局数据由本模块独占写入；不缓存跨域结果作为数据来源，不持有他方可变对象（架构案 8.2）。

### 6.5 依赖方向限制

- 允许的依赖：本模块位于 L3、L4，向 M01 申请基础设施能力属架构案 3.3 第 9 项，经事件分发器发布与订阅属第 10 项；对 M10 的阶段读取属第 12 项；读 M02 的事件结果与 M04 的物品归属属第 7 项，且只以整份存档快照为读取面；M03、M02 对本模块节点解锁状态与封锁状态的只读查询属第 5 项与第 5.1 项；M10 编排本模块执行入口属第 11 项；调用 M09 的条件判定属第 8 项。
- 被依赖方向：M02 的生成流程与事件刷新经 `API-M06-003`、`API-M06-001`、`API-M06-002` 取内容集合、解锁与封锁状态；M03 经 `API-M06-001`、`API-M06-002` 取呈现列表过滤依据；M09 的条件求值服务按引用侧登记读取节点与封锁状态；M10 的结算执行器经 `API-M06-004` 取组件清单并编排执行；M08 的线索树界面、剪枝界面与结算窗口只读取数（架构案 3.3 第 1 项）。
- 禁止方向：不得调用 M02 的事件池刷新、事件实例创建与结束；不得调用 M03 的呈现列表写入与区域能力；不得调用 M04 的对象与交易能力；不得调用 M05 的战斗能力；不得调用 M07 的队伍编制变更；不得调用 M08 的界面能力或持有界面对象（架构案 3.4 第 3、4 项）；不得被 M01 依赖；M09 的条件求值服务对本模块跨局数据只读快照（`CLS-M06-004`）的读取属同层只读查询，按架构案 8.1 第 2 条判定为允许，只读、不写入、不缓存（两侧口径在 REQ-M06-12 与 M09 的 REQ-M09-07 中一并收口）；不反向调用 M10 的阶段切换之外的能力（架构案 3.3 第 11 项）；不得持有他方可变对象（第 5 项）。
- 待架构登记：结局判定与结算执行的发起方为 M10（架构案 9.5.5、9.5.6 与 3.3 第 11 项），本模块只受理 M10 的判定请求与组件执行请求、不反向调用 M10 的三个执行入口；判定在整局存档快照收集后发起，该时点与输入口径需上游登记（见 REQ-M06-05）；M06 作为世界状态域池内容集合的写入方在 5.2.1 与 5.4 的变更入口清单中未列出（见 REQ-M06-02）；跨局数据切面的声明方是否含本模块（见 REQ-M06-07）。
- 环与例外：本模块与 M02、M03、M09 之间为单向只读或只读互查，与 M10 之间为编排与受理，与 M01 之间为基础设施使用，均不构成架构案 3.4 第 12 项的循环依赖；本模块无环、无未登记例外。

### 7.3 数据流

静态配置（节点类型表、节点关系表、传闻表、概率池表、结算组件表，启动加载只读）→ 解锁状态与封锁集合 → `API-M06-003` 计算全局事件池内容集合 → 写入世界状态域 → M02 的生成流程与事件刷新读取内容上界 → 当前事件池刷新集合（M02 持有）。

局内：M03 的呈现取数与 M08 的界面呈现经 `API-M06-001`、`API-M06-002` 读取跨局数据的只读快照；本局新解锁的内容在本局不写入跨局数据，只在结算提交后可见（07-10 §3.9、§3.10）。

局末：M10 的事件执行器收集整局存档快照并向本模块请求结局判定（`API-SETTLE-002`）→ 本模块判定结局类型与触发起因并返回 → M10 发布 结局成立 并经 `API-M10-005` 受理、落定结算阶段 → M10 经 `API-M06-004` 取组件清单 → `API-SETTLE-001` 按组件从快照取数产出写入项 → 写入节点、传闻与事件解锁状态以及达成记录与大关进度 → M10 经 `API-SAVE-007` 一次提交跨局存档 → 本模块经 `API-SETTLE-003` 登记提交结果 → M10 发布 结算完成 → 跨局只读快照刷新 → 结算窗口取数呈现。

局外：M08 的剪枝界面提交与撤销 → 剪枝提交受理入口（`API-PRUNE-001`、`API-PRUNE-002`）→ 封锁集合与节点标记更新 → 发布 封锁状态变化 → 下一局开新局时进入内容集合计算。

## 8. 核心流程

### 8.1 模块装配、初始化与销毁

- 触发：启动引导的服务容器装配流程，或进程正常退出。
- 参与者：M01（服务容器、配置服务、事件分发器）、M06 与其成员系统 07-10、07-20、07-30、07-40。
- 调用顺序：① 启动阶段 1 经 `API-M01-001` 登记本模块五项能力与依赖声明，服务容器校验依赖图（成环即中止）并按拓扑排序；② 阶段 2 配置装载完成后绑定节点类型表、节点关系表、传闻表、概率池表、结算组件表与大关清单标识；③ 阶段 3 由服务容器按依赖拓扑创建本模块常驻对象并注入引用（领域层中本模块位于 M05 之后，架构案 6.3 第 3 项）；④ 经 `API-SAVE-001` 声明跨局数据切面与池内容集合切面并登记重建步骤；⑤ 经 `API-M01-012` 订阅 配置加载完成、存档恢复完成；⑥ 读档路径在恢复完成后重建跨局只读快照，新开局路径在池内容集合首次计算时建立快照，装配标记为装配就绪；⑦ 销毁按创建逆序：先解除订阅并由 M10 停止流程，再释放快照与临时上下文，最后由服务容器销毁常驻对象；本模块无自有待提交的入档数据。
- 状态变化：模块能力登记项迁移；`CLS-M06-004` 建立与刷新；池内容集合按路径恢复或计算。
- 产生的事件：无（启动与销毁不发布跨模块事件）。
- 结束条件：装配达到装配就绪且跨局只读快照可用；销毁为订阅与常驻对象均已释放。

### 8.2 开新局的池内容集合计算与快照

- 触发：开新局路径上首次调用 `API-M06-003`（计算触发点与调用链见 REQ-M06-03）。
- 参与者：M10（局外流转）、M02（生成流程与事件刷新）、M06（计算与写入）、M01（配置服务、数据域与存档入口）。
- 调用顺序：① 调用方传入池标识；② 本模块校验本局装配已建立且池标识已登记；③ 读取节点与事件解锁状态（`API-M06-001`）、封锁集合（`API-M06-002`）与概率池表（`API-M01-003`），建立 `CLS-M06-003`；④ 确定内容集合与来源标记；⑤ 经 `API-SAVE-009` 向世界状态域提交一次变更，快照固定；⑥ 返回内容集合快照；⑦ 生成流程与当前事件池刷新按快照读取内容上界。
- 状态变化：池内容集合 未计算 → 计算中 → 已快照，本局内不再变化；`CLS-M06-003` 释放。
- 产生的事件：无（内容集合为生成输入，不作为跨模块广播事项）。
- 结束条件：快照可查询且本局内重复查询返回同一结果；读档路径按单局存档快照恢复，不重新计算。

### 8.3 局末结算与跨局写入的一次提交（编排归 M10）

- 触发：结局成立（真结局、隐藏关底事件通过，或未通关结局的三种收尾情形）。
- 参与者：M06（结局判定、组件清单与写入内容）、M10（结算执行器与阶段状态机）、M01（存档服务、数据域、日志）、M08（结算窗口）。
- 调用顺序：① 关底事件结算或终止情形产生事实；② M10 的事件执行器收集整局存档快照（架构案 9.5.6 第 1 步）并向本模块请求结局判定（REQ-M06-05、REQ-M10-03）；③ 本模块受理该请求，经 `API-SETTLE-002` 以该快照与终止情形判定结局类型与触发起因并返回；④ M10 发布 结局成立 并经 `API-M10-005` 受理、经 `API-M10-002` 落定结算阶段；⑤ M10 经 `API-M06-004` 取本次版本启用的组件清单与顺序；⑥ M10 按组件登记顺序逐项请求 `API-SETTLE-001` 执行组件：节点解锁检查组件产出节点、传闻与事件解锁写入项，写入经线索树写入接口（`API-CLUETREE-001`）；节点解锁写入完成后对锁定节点的下游执行一次开放阈值判定；达成记录与大关进度组件启用时写入结局类型、触发起因与大关进度；⑦ 本模块汇总写入项并校验组件之间不写入同一项数据；⑧ M10 经 `API-SAVE-007` 以一次提交写入跨局存档；⑨ M10 调用 `API-SETTLE-003` 登记提交结果，成功时由 M10 发布 结算完成，失败时回退为未结算并保留重试；⑩ 跨局只读快照刷新，M08 打开结算窗口取数。
- 状态变化：跨局数据按写入项更新；本局结算状态 未结算 → 结算中 → 已结算，或回退为未结算；`CLS-M06-002` 在回执登记后释放。
- 产生的事件：节点解锁与传闻解锁（由写入对象持有者在写入成功后发布）；结局成立与结算完成由 M10 发布（本模块提供判定取值与提交结果，REQ-M06-04）。
- 结束条件：跨局存档一次提交完成且本局结算状态为已结算，或整笔回滚后处于可重试的未结算状态；重试不产生重复写入（同一节点按内容标识去重，07-40 §3.4、§3.11）。
- 约束：结算阶段不接受任何改变局内状态的输入；结算的输入只有整份存档快照，本模块不回读任何模块的运行时状态（架构案 6.6、ARC-M06-001）。

### 8.4 剪枝提交与封锁标记重建（局外）

- 触发：玩家在局外经剪枝界面提交一次剪枝或按操作撤销（剪枝提交受理入口（`API-PRUNE-001`、`API-PRUNE-002`）；登记见 REQ-M06-01）。
- 参与者：M08（剪枝界面与编辑态提交）、M06（07-20 受理与标记重建，07-10 提供节点与关系）、M01（配置服务、数据域与存档入口、日志）。
- 调用顺序：① 界面经编辑态提交把请求交给剪枝提交受理入口；② 校验当前阶段为局外阶段且目标节点处于已解锁状态；③ 按节点关系图计算完整级联范围；④ 更新封锁集合（提交以单次操作为粒度记录归属，撤销按该次操作批量解除）；⑤ 重建节点封锁标记；⑥ 发布 封锁状态变化；⑦ 下一局开新局时经 `API-M06-003` 参与内容集合计算。
- 状态变化：封锁集合按操作增删；节点封锁标记重建；节点状态取值不变（已解锁节点只叠加封锁标注）。
- 产生的事件：封锁状态变化。
- 结束条件：封锁集合与节点标记一致，撤销后判定恢复；跨局存档的落库路径见 REQ-M06-06。

### 8.5 只读取数与界面呈现通道

- 触发：M03 的呈现列表取数、M02 的事件刷新过滤、M09 的条件引用取数、M08 的线索树界面与百科页呈现、M10 的结算前置查询。
- 参与者：调用方、M06（成员系统 07-10、07-20、07-40）。
- 调用顺序：① 调用方传入查询条件；② 本模块经 `CLS-M06-004` 读取跨局数据的已提交状态；③ 组装节点、传闻、事件解锁、封锁标注与触发方法揭示的只读视图，或按 `API-M06-005` 返回大关进度；④ 返回快照。
- 状态变化：无（只读查询不改变任何状态）。
- 产生的事件：无（架构案 4.5）。
- 结束条件：返回值给出；结果不含本局尚未提交结算的成果；快照不携带写入口。

## 9. 异常与边界情况

| 判定条件 | 期望结果 |
| --- | --- |
| 结算阶段内收到改变局内状态的请求 | 返回阶段封闭，不产生任何状态变化（架构案 6.6、8.3 第 5 条） |
| 已结算的本局重复受理组件执行 | 拒绝执行，不产生重复写入；重复达成同一结局只更新达成记录的次数与最近时间（07-40 §3.4） |
| 一次提交失败 | 整笔回滚，本局结算状态回退为未结算并保留重试能力，重试不产生重复写入（07-40 §3.4） |
| 结算组件标识未登记或组件未启用 | 未登记时拒绝并记内容日志；未启用时不参与本次结算、不产出写入项（07-40 §3.3） |
| 快照缺少某组件登记项所需的取数来源 | 该组件执行失败，不产生部分写入，失败原因写日志（07-40 §3.2） |
| 结局判定的事实缺失（无关底事件结果记录） | 判定不产出，返回失败原因并写内容日志（07-40 §3.13） |
| 终止情形不在三种收尾情形之内 | 拒绝执行，不产生结局成立（07-40 §3.13） |
| 节点标识不存在 | 查询返回未找到；写入项校验不通过时按整笔回滚处理并记内容日志 |
| 同一次结算内同一节点出现多条同内容标识的写入项 | 按内容标识去重，不产生重复条目（07-40 §3.11） |
| 写入项来源为场景变化包装事件且事件配置未声明写入标记 | 不产生节点解锁项（07-40 §3.10） |
| 写入项涉及封锁集合或节点封锁标记 | 不经结算组件，由剪枝系统自行维护（07-40 §3.6） |
| 写入项涉及未解锁传闻的空行占位 | 不作为独立写入项，数量按传闻表登记条数推导（07-40 §3.3） |
| 池内容集合重复查询 | 返回同一快照，不重新计算、不重新过滤（架构案 5.2.5 第 3 条） |
| 池标识未在概率池表登记 | 拒绝并记内容日志，不以空集合代替 |
| 本局装配未建立时查询池内容集合 | 拒绝并返回原因，不隐式创建世界状态域结构 |
| 计算输入缺失（解锁状态或封锁集合不可读） | 返回失败并标注缺失项，不以默认未封锁或空集合代替 |
| 无跨局存档（首次启动） | 大关进度返回初始进度（未解锁任何大关、无达成记录），不隐式写入跨局数据 |
| 节点标记与封锁集合不一致 | 以封锁集合为准返回并标注可重建；在开新局与撤销提交点各校验一次（07-20 §3.4） |
| 剪枝提交的目标节点不是已解锁状态，或当前阶段不是局外阶段 | 拒绝并记内容日志，封锁集合不变（07-20 §3.3） |
| 撤销一次封锁操作 | 只回退封锁状态，不回退解锁写入；封锁期间的解锁保留（07-20 §3.3） |
| 界面在结算前查询结算窗口数据 | 由 07-40 的结算窗口数据查询返回未结算标记与空清单（`API-SETTLE-004`） |
| 界面尝试经本模块改变跨局状态 | 本模块只提供只读查询；状态改变只经局末结算的一次提交与剪枝受理入口（架构案 3.4 第 3 项、07-10 §3.10） |
| 订阅方处理失败（M03、M08、M09） | 不回滚已提交的跨局数据（架构案 8.4 第 4 条） |
| 池内容集合写入的域变更入口未登记（REQ-M06-02） | 按 `API-SAVE-009` 提交，登记完成前按架构案 3.2 的写入授权使用，不自行落库 |
| 结算组件清单中物品池与商人经营池内容集合落点未定（REQ-M06-11） | 相关池的内容集合返回失败并标注，不以事件池集合代替 |

## 10. 实现约束

实现要求（编号前缀 `I-`）：

- I-M06-01 跨局数据由本模块独占持有与写入；除封锁集合与节点封锁标记按架构案 9.5.6 的约束不经结算组件外，全部写入只发生在局末结算的一次提交内，其他模块一律只读查询（架构案 5.4、3.2、ARC-M06-001）。
- I-M06-02 结算的输入只有整份存档快照；本模块不得向任何模块索取结算输入，不得回读 M02、M04、M05、M07 等模块的运行时状态，也不得要求它们在结算时另行上报（架构案 3.1 ARC-M06-001、3.3 第 7 项）。
- I-M06-03 结算流程的执行编排归 M10：快照收集、组件调度顺序、提交动作、阶段流转与失败重试的驱动不由本模块承担；本模块只提供组件清单与组件执行（架构案 3.3 第 11 项、9.5.6、`API-M10-005`）。
- I-M06-04 跨局数据必须可序列化，写入粒度是状态项目；切面声明、采集与装载、提交一律经存档服务，本模块不得自行序列化状态或读写存档文件（架构案 7.1、3.4 第 6 项）。
- I-M06-05 池内容集合的所有权归世界状态域，本模块是其写入方；内容集合在本局内保持静态并随单局存档入档，读档按快照恢复、不重新过滤、不重新抽取（架构案 3.2、5.2.5）。
- I-M06-06 内容集合的计算不引入随机量；本模块不得自行创建随机源，抽取执行一律归各内容系统（架构案 3.4 第 9 项、07-30 §1、§3.5）。
- I-M06-07 节点封锁标记随跨局存档入档，装载后按封锁集合校验、不一致时按封锁集合重建；`CLS-M06-004` 与空行占位数量为派生项：按来源重建、不入档；三者均不作为数据来源被缓存或反推来源状态（架构案 5.3、8.2 第 3 条、07-20 §3.4）。
- I-M06-08 界面只读：线索树界面、百科页、剪枝界面与结算窗口只经本模块与 07-40 的只读查询取数，界面不得直接修改跨局数据，也不得经界面改变解锁与封锁状态（架构案 3.4 第 3 项、07-10 §3.10）。
- I-M06-09 本模块不自行实现条件判定与效果叠加；写入项与查询结果涉及条件成立与否时经 `API-M09-004` 求值（架构案 7.11、3.4 第 8 项）。
- I-M06-10 跨模块事件一律经 `API-M01-011`、`API-M01-012` 发布与订阅，事件名取自架构案 3.1 的已登记词表，载荷只承载已发生的事实；只读查询不产生事件（架构案 8.4、4.5）。
- I-M06-11 常驻对象只能由服务容器按依赖拓扑创建与逆序销毁；结算阶段开始后本模块不得创建或销毁单局状态域内的对象（架构案 8.3 第 1、5 条、6.6）。
- I-M06-12 本模块不得重新定义成员系统 07-10、07-20、07-30、07-40 已登记的对象与接口；成员系统 ID 一律按对方代码设计案已分配的 ID 引用，仍未分配处（整局存档快照）按约定 §四.6 以「名称（单元码，ID 待补）」引用，收口时统一回填（NR-06 §八.2）。
- I-M06-13 大关进度不因剪枝改变；重复达成真结局只更新达成记录中的次数与最近时间，不重复发放跨局内容与大关进度（07-20 §3.2、07-40 §3.4、§3.8）。
- I-M06-14 一个结算组件只负责一类跨局数据，组件之间不得写入同一项数据；新增组件先在结算组件表登记再实现（架构案 8.5.5、07-40 §3.3）。
- I-M06-15 空行占位数量不作为独立写入项；场景变化包装事件默认不产生节点解锁项（07-40 §3.3、§3.10）。
