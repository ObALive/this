## 1. 系统定义
### 1.1 系统目的
`SYS-M07-001` 队伍与角色是架构案 ARC-M07-001 的模块级单元，承载「队里都有谁、谁是主角、成员的属性从哪取值」：持有本局队伍编制并每局重置，维护主角标识与主控位置规则，受理招募与剧情事件带来的成员变化，并为战斗、条件取数与界面提供角色属性取值。

### 1.2 系统职责
- 队伍成员集合的持有与按局重置：成员条目、顺序与锁定位置的唯一权威（架构案 ARC-M07-001、3.2、5.2.3、9.5.1 第 4 步）
- 主角标识的持有与主控位置规则：稳定角色标识的提供，锁定位置到当前主控单位的判定（架构案 ARC-M07-001、01-40 §3.1、决策 54）
- 招募与剧情事件对队伍成员的影响：成员加入、成员离队、顺序调整与主控位置变更的受理、校验与提交（架构案 ARC-M07-001、01-40 §3.2）
- 队伍成员变化时的重算触发：按架构案 3.3 第 5.2 项只读 M04 的对象实例与装备状态，重建可调取容器范围与属性取值的修正组成（架构案 ARC-M07-001、5.2.3 派生项）
- 角色属性的取值来源：按承载角色与场合组装五类属性取值，供战斗判定、条件取数与界面呈现取用（01-40 §3.5、06-10 §3.3）
- 模块级装配与模块级事件：向服务容器登记能力与依赖声明，按依赖拓扑参与初始化与销毁，发布与订阅本模块事件（架构案 6.3、6.4、8.5.1 第 4 步）
### 1.3 系统边界
本模块负责：本局队伍编制的成员条目、顺序与锁定位置；主角标识与由锁定位置判定的当前主控单位；成员加入、离队、顺序调整与主控位置变更的受理与提交；队伍成员变化后的派生项重建触发；五类角色属性取值的组装与返回。
本模块不负责：
- 角色属性的集合、含义与权威清单（归 06-10 战斗总览，`06-战斗/10-战斗总览/10_角色属性表.csv`；本模块只提供取值）
- 参战编成、初始站位、队伍顺序在战场上的排布，以及战斗内单位状态的判定与生命、伤势档位迁移（归 M05 的 06-30 与 06-10）
- 物品与容器、装备槽与遗物槽的对象侧规则、槽位适配与容器格位（归 M04 的 05-05、05-30、06-60、06-70；架构案 3.3 第 5.2 项只允许只读查询）
- 物品状态的最终落库与回滚、效果的叠加与同名判定、条件求值（分别归 M09 的物品与经济写入服务、元效果服务、条件求值服务，架构案 3.4 第 7、8 项与 7.11）
- 人物节点（节点类型之一，术语表 T-157）的结构、解锁判定与写入（归 M06 的 07-10；本模块只发布成员变化事件，写入由 M06 承担，写入路径待定：结算派生或订阅写入，见 REQ-M07-04）
- 事件生成、入池、窗口期与招募事件的解锁阈值判定（归 M02 的 02-30、02-30-10）
- 队伍在地图界面与战斗界面的呈现、主控单位选中与界面切换（归 M08 与 M05；界面不得直接修改队伍数据）
- 存档结构、切面采集与恢复顺序（归 01-50 与 M01）；世界时间推进（归 M01 的时间服务）
- 本局结束与结局判定：判定对象是整支队伍，归 M06 与 M05（决策 27）
### 1.4 上游需求
架构出处：架构案 3.1 ARC-M07-001（职责、不负责项、依赖、对外接口、事件、生命周期）、2.3（01-40 主模块为 M07，参战编成归 M05）、2.4、2.5.2、3.2（模块拥有的系统与数据）、3.3 第 5 项第 5.2 条（M07 只读查询 M04）与第 9、10、12 项、3.4 第 3、5、6、7、8、10、12 项、5.2.3（玩家状态域，ARC-GAP-014 每局重置）、5.3、5.4、6.3 至 6.5、7.1、7.11、8.2 至 8.4、9.5.1、第 10 章。

成员系统设计稿出处：01-40 §1（系统定位与属性权威清单的分工）、§3.1（主角与位置规则）、§3.2（队伍构成与来源、加入与离队写入人物节点）、§3.3（人物节点与角色信息的对应）、§3.4（地图界面与战斗界面的切换与单主控呈现）、§3.5（角色属性与装备槽）、§4（交互逻辑与细节注意点）；相邻设计稿 06-10 §3.3（属性定义与取值关系）、06-30 §3.3（参战编成与队伍顺序）、07-10 §3.2.1（人物节点由事件节点派生）、§3.6 与 §3.7（开放阈值与两步流程）；设计决策 27（结局判定对象是整支队伍）、决策 54（主角的定义与位置）。

功能要求（编号前缀 `F-`，来源为上游设计）：
- F-M07-01 主角（术语表 T-018）是队伍中带稳定角色标识的固定角色，队伍成员集合包含主角；一般情况下队伍中第一个单位的位置被锁定，该单位即当前主角（01-40 §3.1、决策 54）。
- F-M07-02 主角位置可随叙事变化；主角变化时改变的是队伍的锁定位置与主控单位，角色标识本身不变，已登记的线索树节点不因主角变化而失效（01-40 §3.1、决策 54）。
- F-M07-03 队伍是玩家在一局内携带的角色集合，成员来自招募；玩家在局内经历并完成招募事件（术语表 T-019）后该角色加入队伍（01-40 §3.2、决策 50）。
- F-M07-04 队友加入与离队都写入人物节点数据，队伍成员的变化可在线索树上回溯（01-40 §3.2、§4）。
- F-M07-05 招募事件的解锁受该角色人物节点的开放阈值约束，未被解锁的角色不会出现在当前事件池中（01-40 §3.2、§4、07-10 §3.6）。
- F-M07-06 地图界面下始终以单主控呈现，队伍其他角色不参与界面操作与结算；进入战斗时全员参战，队伍顺序在局外与局内均可查看与调整（01-40 §3.4、06-30 §3.3）。
- F-M07-07 角色的生命、伤势、行动力、力量与行动速度五类属性的取值由本系统提供，属性集合与含义的权威清单由战斗总览维护（01-40 §3.5、06-10 §3.3）。
- F-M07-08 装备槽的种类和数量由角色配置决定，角色配置声明自身拥有的槽位集合，槽位定义与角色配置解耦（01-40 §3.5、06-60 §2）。
- F-M07-09 队伍编制属每局重置的要素，随单局创建并重置；对队伍成员的构筑是玩家构筑的一部分（来源：架构案 5.2.3 与 ARC-GAP-014，属程序设计约束，非上游游戏设计稿）。
- F-M07-10 队伍规模与角色组合不受本系统额外限制，队友数量与具体角色由内容侧设计（01-40 §3.2）。
- F-M07-11 本局结束时触发结局的判定对象仍是整支队伍，不是主角一人（决策 27、01-40 §1）。

### 2.3 数据关系
- 包含关系：队伍编制与成员包含成员条目、成员顺序与锁定位置；成员条目引用角色配置中的角色标识，不复制角色配置内容。
- 判定关系：主控单位由队伍编制的锁定位置确定（01-40 §3.1）；主角标识是稳定标识，与主控单位分离持有。
- 变更关系：`API-M07-003` 是队伍编制与主角标识的全部变更入口；本局重置与读档恢复的编制初始化不经该能力，由内部功能承担（见 5.1）。
- 派生关系：可调取容器范围由成员条目与装备槽内的容器派生；属性取值的修正组装结果由角色配置基础值与装备、遗物、生效效果派生；两者按来源重建、不入档（架构案 8.2 第 3 条）。
- 跨单元引用：队伍编制、主角标识与角色属性取值的对象结构归成员系统 01-40，落玩家状态域由 M01 的数据域侧持有；本模块只登记归属与访问级别。
### 2.4 数据生命周期
按架构案 6.5 分类：
- 常驻对象：`CLS-M07-001` 与成员系统 01-40 的常驻系统对象，由服务容器按依赖拓扑创建与逆序销毁（架构案 6.3 第 3 项：领域层中本模块位于 M04 之后、M02 之前）。
- 数据域对象：队伍编制与成员、主角标识与主控位置、角色属性取值落玩家状态域，随单局创建并按局重置，容器常驻、内容按局重置（架构案 5.2.3、8.3 第 3 条）。
- 场景对象：无（地图界面与战斗界面的队伍呈现归 M08，战场单位对象归 M05）。
- 临时运行对象：`CLS-M07-002`、`CLS-M07-003` 与派生重建的中间结果，单次受理或单次取值内有效，不跨帧保留、不入档（架构案 8.3 第 4 条）。
- 存档对象：玩家状态域切面中本模块条目，只在采集与恢复期间存在，采集完成后即释放。
- 静态配置对象：角色配置与属性定义，启动阶段加载，运行期只读，进程退出前不销毁。
- 跨局边界：队伍编制属每局重置的要素，不进入跨局存档（架构案 5.3 第 1 条、ARC-GAP-014）；加入与离队的回溯记录落人物节点，属跨局数据并由 M06 持有与写入。
### 2.5 持久化要求

| 需入档的数据 | 切面归属 | 恢复时的重建步骤 |
| --- | --- | --- |
| 队伍编制与成员（成员条目、顺序、锁定位置） | 单局存档·玩家状态域切面 | 按域顺序（世界状态域 → 单局状态域 → 玩家状态域）恢复成员条目与顺序；不重新触发本局重置、不重新执行加入与离队（架构案 7.1） |
| 主角标识与主控位置 | 单局存档·玩家状态域切面 | 按快照恢复稳定主角标识与主控单位；不按锁定位置重新推断与快照不同的结果 |
| 角色属性取值 | 单局存档·玩家状态域切面 | 按存档恢复取值；战斗内产生的取值变化由 M05 提交、随本域一并恢复（架构案 5.2.3 更新时机：玩家数据在事件内实时结算） |

不入档项：`CLS-M07-001` 按启动引导阶段重新登记；`CLS-M07-002`、`CLS-M07-003` 不跨帧保留；可调取容器范围与属性取值的修正组装结果按来源重建，不作为数据来源（架构案 5.2.3、8.2 第 3 条）。切面登记与采集装载一律经 `API-SAVE-001`、`API-SAVE-008`、`API-SAVE-009`；本模块不自行序列化状态，也不自行读写存档文件（架构案 3.4 第 6 项、7.1）。

### 4.2 接口详细定义
本节按 NR-06 §六的契约模板逐项展开；输入与输出按参数输入／状态输入／数据输入／外部事件输入与返回值／状态输出／事件输出／外部系统调用四类分别记录（NR-06 §七）。
#### API-M07-001 队伍成员查询
职责：按查询条件返回本局队伍成员集合的只读快照，供参战编成、条件取数、界面呈现与队伍查看使用。
输入：参数输入：查询条件（成员标识集合、场合标识、是否含顺序）；状态输入：队伍编制与成员条目、主角标识与主控位置、当前阶段取值；数据输入：角色配置（成员标识与呈现用取数）；外部事件输入：无。
读取：队伍编制与成员（`CLS-PARTY-003`、`CLS-PARTY-004`）、主角标识与主控位置（`CLS-PARTY-003`）、局内阶段取值（`API-M10-001`）、角色配置（`API-M01-003`）。
输出：返回值：成员只读快照集合（成员标识、顺序位置、是否主角、是否主控单位），按成员标识查询时返回单一成员；状态输出：无；事件输出：无；外部系统调用：`API-M01-003`。
产生的状态变化：无。
前置条件：模块装配状态为已就绪；本局玩家状态域已建立。
后置条件：结果与已提交状态一致；返回快照不携带写入口，读取方不得缓存跨域结果（架构案 8.2 第 3 条）。
副作用：无。
异常情况：局外阶段或本局未建立时返回空集合，不隐式创建玩家状态域结构；成员标识不在集合内时返回未找到；查询条件为空时返回全部成员。
#### API-M07-002 主角查询
职责：返回主角标识、锁定位置与当前主控单位，作为地图界面单主控呈现、战斗默认选中单位、事件与文案引用、线索树人物节点取值的依据。
输入：参数输入：查询口径（稳定主角标识／当前主控单位／锁定位置）；状态输入：主角标识与主控位置、队伍编制的成员条目与顺序；数据输入：无；外部事件输入：无。
读取：主角标识与主控位置（`CLS-PARTY-003`）、队伍编制与成员（`CLS-PARTY-003`、`CLS-PARTY-004`）。
输出：返回值：主角标识、锁定位置与当前主控单位标识；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：模块装配状态为已就绪；本局玩家状态域已建立；队伍编制处于已建立或已重置。
后置条件：主角标识在主角变化前后保持稳定（01-40 §3.1）；返回的主控单位与当前锁定位置一致；快照不携带写入口。
副作用：无。
异常情况：队伍编制未建立或为空时返回未找到并记内容日志，不以默认角色代替；主控位置变更受理中读取时返回变更前的一致快照；稳定主角标识与主控单位的口径分离待上游补充（REQ-M07-05）。
#### API-M07-003 成员加入与离队
职责：受理一次队伍编制变更（成员加入、成员离队、顺序调整、主控位置变更），逐项校验后提交玩家状态域并触发受影响派生项的重建。
输入：参数输入：请求类别、成员标识或目标位置、变更来源（招募类事件结果、剧情类事件结果、本局失败处理）；状态输入：队伍编制与成员条目、主角标识与主控位置、该成员是否已在集合内、当前阶段取值；数据输入：角色配置（成员标识可解析性）、事件结果配置的结果标识；外部事件输入：无（本能力由调用方直接调用；本局重置与读档恢复的编制初始化不经此能力）。
读取：队伍编制与成员（`CLS-PARTY-003`、`CLS-PARTY-004`）、主角标识与主控位置（`CLS-PARTY-003`）、角色属性取值（`CLS-PARTY-005`）、局内阶段取值（`API-M10-001`）、对象实例与装备状态（`API-M04-001`、`API-M04-002`）、角色配置（`API-M01-003`）、`CLS-M07-002`。
输出：返回值：受理结果（已提交／已拒绝及原因）与变更后的成员集合摘要；状态输出：成员条目与顺序变化，主控位置变更时锁定位置与主控单位变化，可调取容器范围与属性取值修正组成按来源重建；事件输出：队伍成员加入（加入时）、队伍成员离队（离队时）、主角变化（主控单位变化时）；外部系统调用：`API-SAVE-009` 数据域变更提交、`API-M04-001`、`API-M04-002`、`API-M01-010` 日志服务.Write。
产生的状态变化：成员条目加入集合或移出集合；成员顺序按顺序调整请求变化；锁定位置与主控单位按主控位置变更请求变化；派生项重建；被拒绝时不产生任何状态变化。
前置条件：模块装配状态为已就绪；当前阶段允许改变局内状态（非结算阶段，架构案 6.6）；请求类别的变更项可解析；加入时该成员不在集合内，离队时该成员在集合内；主控位置变更后队伍编制仍有成员。
后置条件：成员条目、顺序与锁定位置与最近一次提交一致；加入与离队的记录可由订阅方写入人物节点（01-40 §3.2）；派生项已重建；重复请求不重复加入。
副作用：发布上述事件；订阅方处理失败不回滚该次变更（架构案 8.4 第 4 条）；落库被拒绝时经日志服务记录。
异常情况：结算阶段内收到请求时返回阶段封闭；加入已在集合内的成员时返回已加入、不重复加入；离队不在集合内的成员时返回未找到；离队导致队伍为空时拒绝并记内容日志（结局判定归 M06 与 M05，决策 27）；成员标识在角色配置中不可解析时拒绝；成员顺序目标位置非法时拒绝；落库提交被拒绝时该次变更不产生状态变化；同一成员的并发变更以后受理的请求以已提交状态为基准重新校验，不产生部分提交。
#### API-M07-004 属性取值
职责：按承载角色与场合组装五类属性取值（生命、伤势、行动力、力量、行动速度），作为战斗判定、条件取数与界面呈现的取值来源。
输入：参数输入：承载角色标识、属性标识集合、求值场合（战斗内／战斗外）、结算层与用途上下文；状态输入：角色属性取值条目、装备槽与遗物槽内的对象实例与组件状态、生效效果与求值结果、当前阶段取值；数据输入：角色配置（基础值与槽位集合）、属性定义清单（权威归 06-10）；外部事件输入：无。
读取：角色属性取值（`CLS-PARTY-005`）、队伍编制与成员（`CLS-PARTY-003`、`CLS-PARTY-004`）、对象实例与组件状态（`API-M04-001`、`API-M04-002`）、效果求值结果（`API-M09-003`）、属性定义与角色配置（`API-M01-003`）、局内阶段取值（`API-M10-001`）、`CLS-M07-003`。
输出：返回值：属性取值的只读结果（按属性标识组织的取值与来源构成、缺失项标注）；状态输出：无（本能力不改变任何状态）；事件输出：无（只读查询不产生事件，架构案 4.5）；外部系统调用：`API-M01-003`、`API-M04-001`、`API-M04-002`、`API-M09-003`、`API-M01-010`。
产生的状态变化：无；仅 `CLS-M07-003` 在单次取值内建立与释放。
前置条件：模块装配状态为已就绪；承载角色在本局队伍编制内；属性标识在属性定义清单内；求值场合与结算层已声明。
后置条件：同一次求值内同一属性只产生一个取值；结果由基础值与已生效修正按来源组装，不缓存跨域结果作为数据来源（架构案 8.2 第 3 条）；返回结果不携带写入口。
副作用：无。
异常情况：属性标识未在属性定义清单登记时拒绝并记内容日志；承载角色不在队伍编制内时返回未找到；装备或效果来源不可读时该修正项按缺失返回、不以默认值代替，并在结果中标注缺失项；结算阶段内受理只读取值，照常返回且不改变状态。

### 5.2 功能之间的关系
- 装配路径：模块装配登记与依赖声明 → 服务容器按依赖拓扑创建 → 订阅建立 → 装配就绪（架构案 6.3 第 3 项）。
- 本局路径：本局重置与编制初始化（`API-M07-003` 不被调用）→ 可调取容器范围重建与派生失效标记 → 发布 队伍重置。
- 变更路径：`API-M07-003` → 编制变更校验与提交组装 → `API-SAVE-009` → 成员顺序维护与锁定位置判定 → 主控单位判定与主角变化识别 → 派生重建。
- 取值路径：`API-M07-004` → 属性取值组装与修正合并（内部只读 `API-M04-001`、`API-M04-002`、`API-M09-003`）→ 返回结果；不改变任何状态。
- 查询路径：`API-M07-001`、`API-M07-002` 只读，不触发内部功能，不产生事件。
- 对外能力以 `API-M07-001` 至 `API-M07-004` 为跨模块入口；内部功能只在本模块内被调用，其中本局重置与派生重建由事件与存档恢复间接驱动。

## 8. 核心流程
### 8.1 开新局的队伍编制重置
- 触发：玩家在局外阶段选择开新局，M10 经 `API-M02-005` 完成生成后发布 本局生成完成。
- 参与者：M02（生成流程与事件发布）、M07（重置受理与派生重建）、M01（事件分发器、数据域、日志）、M05、M04、M08（订阅响应方）。
- 调用顺序：① M10 的局外流转经 `API-M02-005` 生成四项产物并发布 本局生成完成；② M07 经 `API-M01-012` 订阅收到该事件；③ 内部按重置输入建立成员条目、顺序与锁定位置（重置输入的字段与来源见 REQ-M07-01）；④ 经 `API-SAVE-009` 提交玩家状态域变更；⑤ 重建可调取容器范围与属性取值修正组成；⑥ 经 `API-M01-011` 发布 队伍重置；⑦ 订阅方按 7.2 的职责响应。
- 状态变化：队伍编制由未建立或上一局内容转为本局初始内容；主控位置重置；`CLS-M07-002` 受理结束即释放；派生项重建。
- 产生的事件：队伍重置（本局生成完成 由 M02 发布）。
- 结束条件：`API-M07-001`、`API-M07-002` 可返回本局队伍与主角；派生项已重建。
### 8.2 编制变更（成员加入、离队与主角变化）
- 触发：招募类或剧情类事件退出时由事件结果执行侧调用 `API-M07-003`（请求类别＝加入／离队／顺序调整／主控位置变更；调用链待上游补充，见 REQ-M07-02）。
- 参与者：事件结果执行侧（M10 的事件执行器）、M07、M01、M04、M05、M06（人物节点写入，路径见 REQ-M07-04）、M08。
- 调用顺序：① 事件结果执行侧调用 `API-M07-003`；② 内部校验阶段、成员标识可解析性、集合内存在性与离队后队伍非空，组装变更项；③ 经 `API-SAVE-009` 提交玩家状态域；④ 经 `API-M04-001`、`API-M04-002` 读取受影响角色的装备与容器能力，重建可调取容器范围与属性取值修正组成；⑤ 按变更类别经 `API-M01-011` 发布 队伍成员加入、队伍成员离队，主控单位变化时另发 主角变化；⑥ 订阅方按 7.2 的职责响应。
- 状态变化：成员条目进入集合或移出集合，成员顺序按请求变化；锁定位置与主控单位按规则更新；派生项重建；被拒绝时无状态变化。
- 产生的事件：队伍成员加入、队伍成员离队、主角变化（主控单位变化时）。
- 结束条件：提交完成且事件已发布；重复请求返回已加入或未找到；队伍编制仍有至少一个成员；稳定主角标识不因主控单位变化而改写（01-40 §3.1）。
### 8.3 属性取值
- 触发：M05 的战斗判定、M09 条件求值服务的属性引用项取数、M08 的界面呈现调用 `API-M07-004`。
- 参与者：调用方、M07、M01（配置、日志）、M04（装备与遗物取数）、M09（效果求值）。
- 调用顺序：① 调用方传入承载角色、属性标识集合、求值场合与结算层；② 内部建立 `CLS-M07-003`；③ 经 `API-M01-003` 读取角色配置基础值；④ 经 `API-M04-001`、`API-M04-002` 读取装备与遗物提供的修正；⑤ 经 `API-M09-003` 取按结算层组织的生效效果求值结果；⑥ 组装并返回只读结果，上下文释放。
- 状态变化：无（只读查询不改变任何状态）。
- 产生的事件：无（架构案 4.5）。
- 结束条件：返回值给出；来源不可读的修正项在结果中标注缺失，不以默认值代替。

- 触发：启动引导的服务容器装配流程，或进程正常退出。
- 参与者：M01（服务容器、配置服务、事件分发器、存档服务）、M07。
- 调用顺序：① 启动阶段 1 经 `API-M01-001` 登记本模块能力与依赖声明，服务容器校验依赖图（成环即中止）并按拓扑排序；② 阶段 2 配置装载后经 `API-M01-003` 绑定角色配置与属性定义标识；③ 阶段 3 由服务容器按依赖拓扑创建本模块常驻对象并注入引用（领域层中本模块位于 M04 之后、M02 之前，架构案 6.3 第 3 项）；④ 经 `API-SAVE-001` 声明玩家状态域内本模块条目的切面与重建步骤；⑤ 经 `API-M01-012` 订阅 本局生成完成 与 存档恢复完成；⑥ 读档路径按切面恢复后重建派生项，生成路径由 本局生成完成 触发重置，装配标记为已就绪；⑦ 销毁按创建逆序：先解除订阅，再由服务容器销毁常驻对象；本模块无自有入档数据待提交。
- 状态变化：模块装配状态迁移；队伍编制按局建立或恢复；派生项重建。
- 产生的事件：无（启动与销毁不发布跨模块事件）。
- 结束条件：装配达到已就绪且派生项已重建；销毁为订阅与常驻对象均已释放。
## 9. 异常与边界情况

| 判定条件 | 期望结果 |
| --- | --- |
| 结算阶段内收到编制变更请求 | 返回阶段封闭，不产生任何状态变化（架构案 6.6、8.3 第 5 条） |
| 加入已在集合内的成员（事件结果重复提交） | 返回已加入，不重复加入、不重复发布 队伍成员加入 |
| 离队不在集合内的成员 | 返回未找到并记内容日志，不改变集合 |
| 离队导致队伍编制为空 | 拒绝该次变更；本局结束与结局判定归 M06 与 M05，判定对象是整支队伍（决策 27） |
| 主控位置变更后无可用成员，或顺序目标位置非法 | 拒绝并记内容日志，锁定位置保持变更前内容 |
| 成员标识在角色配置中不可解析 | 拒绝并记内容日志，不隐式创建角色条目 |
| 属性标识未在 06-10 的属性定义清单登记，或装备与效果来源不可读 | 未登记时拒绝该次取值；来源不可读时该修正项按缺失返回并标注，不以默认值代替取值（01-40 §3.5） |
| 结算阶段内请求属性取值 | 只读取值照常返回，不改变状态、不创建单局状态域对象 |
| 局外阶段或本局未建立时查询队伍与主角 | 返回空集合或未找到，不隐式创建玩家状态域结构 |
| 读档恢复 | 队伍编制、主角标识与属性取值按玩家状态域切面恢复；可调取容器范围与属性取值修正组成按来源重建；不重新触发重置、不重复发布 队伍重置 |
| 同一成员的并发变更 | 后受理的请求以已提交状态为基准重新校验，不产生部分提交与部分事件 |
| 订阅方处理失败（M05、M06、M08） | 不回滚成员变更与主角变化（架构案 8.4 第 4 条） |
| 生成产物不含队伍清单（REQ-M07-01 未决） | 重置按 01-40 §3.1、§3.2 的固定主角与招募来源确定初始成员，不猜生成字段 |
| M05 对 `API-M07-004` 的读取尚未登记（REQ-BATTLE-06） | 契约照常定义，登记完成前按同层只读查询语义使用，不自行按依赖例外处理 |
| 人物节点写入路径未登记（REQ-M07-04） | 写入由 M06 承担，路径待定（结算派生或订阅写入）；本模块不调用 M06，未登记期间不阻塞成员变更 |
## 10. 实现约束
实现要求（编号前缀 `I-`）：
- I-M07-01 队伍编制与主角标识属玩家状态域，只能经 `API-M07-003` 变更，其他模块一律只读查询；本模块是架构案 5.4 登记的变更入口之一（另一入口 M05 负责战斗内取值变化）。
- I-M07-02 队伍编制随局重置，不得跨局保留、不得写入跨局存档；对队伍成员的构筑是玩家构筑的一部分（架构案 5.2.3、5.3 第 1 条、ARC-GAP-014）。
- I-M07-03 存档与数据域读写一律经 `API-SAVE-001`、`API-SAVE-008`、`API-SAVE-009`；本模块不得自行序列化状态或读写存档文件（架构案 3.4 第 6 项、7.1）。
- I-M07-04 效果一律经 `API-M09-003` 求值，本模块不得自行实现效果叠加、同名判定与强度方向解释（架构案 3.4 第 8 项、7.11）。
- I-M07-05 装备槽与遗物槽内的对象状态只读：本模块不得直接改对象实例、组件状态、容器格位与归属，物品写入一律经 M09 的写入服务（架构案 3.4 第 7 项、3.3 第 5.2 条）。
- I-M07-06 可调取容器范围与属性取值的修正组装结果为派生项：按来源重建、不入档、不作为数据来源被缓存或反推来源状态（架构案 5.2.3、8.2 第 3 条）。
- I-M07-07 跨模块状态广播一律经 `API-M01-011`；事件载荷只承载已发生的事实；订阅方处理失败不回滚发布方状态（架构案 8.4 第 1 至 4 条）。
- I-M07-08 界面不得直接修改队伍与角色数据：地图界面的单主控呈现与队伍查看只读，变更由事件结果侧经 `API-M07-003` 提交（架构案 3.4 第 3 项、8.4 第 5 条）。
- I-M07-09 常驻对象只能由服务容器按依赖拓扑创建与逆序销毁；本模块在领域层中位于 M04 之后、M02 之前装配；结算阶段不创建或销毁单局状态域内的对象（架构案 6.3、8.3 第 1、5 条）。
- I-M07-10 队伍规模与角色组合不受本模块额外限制；参战编成、初始站位与战场内单位集合归 M05 的 06-30，本模块只提供成员集合与顺序（01-40 §3.2、§3.4、06-30 §3.3）。
- I-M07-11 角色属性的集合与含义以 06-10 的属性定义清单为准，本模块只提供取值来源；装备槽位种类与数量由角色配置声明，槽位定义与角色配置解耦（01-40 §3.5、06-60 §2）。
