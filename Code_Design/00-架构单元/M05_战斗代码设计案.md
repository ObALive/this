## 1. 系统定义

### 1.1 系统目的

`SYS-M05-001` 战斗承载一场战斗从启动到收束：装配战场与参战方、按时间轴驱动轮次、受理行为提交、判定结束并把战斗结果交回事件侧。战斗内的单条规则由成员系统承载，本模块把它们装配成一次可运行、可入档、可重建的战斗（架构案 3.1 ARC-M05-001、3.2）。

### 1.2 系统职责

- 战斗的启动：受理 M10 的启动请求，按战斗配置装配战场、参战编成、初始站位、敌方波次与战斗目标（术语表 T-129）清单。
- 轮次推进：按时间轴（术语表 T-117）给出获得行动机会（术语表 T-118）的单位与本次机会的可用行为集合。
- 行为提交：受理当前行动者的唯一一项行为，确认后把结果落到战斗运行状态，取消不产生状态变化。
- 战斗内库存调取、投掷（术语表 T-146）与法术释放（术语表 T-150）的模块内受理口径。
- 战斗目标判定、战斗结果标识（术语表 T-131）与达成目标清单（术语表 T-130）的产出与交回；收尾窗口（术语表 T-123）的规则侧开启与结束受理。
- 战斗内结算时机的定义与驱动（成员系统与 M09 的效果服务按该时机取用，`API-M05-103`）。
- 战斗运行状态的持有、单局存档切面的声明，以及读档后战场与时间轴的重建。
- 战斗内净时长以秒为单位累计，战斗结束时给出按时间段（术语表 T-002）对齐的换算结果（架构案 7.5）。
- 模块级事件的发布与订阅。

### 1.3 系统边界

战斗不负责：

- 战斗事件的进入、退出与事件结算：编排归 M10 的事件执行器（`API-M10-003`），规则归 M02。
- 战斗界面的绘制与装配、战场场景的加载触发：归 M08 的界面栈；场景加载与资源装载由 M01 的资源服务与场景管理器执行（架构案 7.2、7.3）。
- 战斗内单条规则的对象与接口定义：归 9 个成员系统文档，本文档只登记模块级归属并引用其 ID。
- 敌方对象定义与实例持有（归 M04）、元效果的模型与叠加（归 M09）、物品与装备状态的写入（归 M09 的写入服务与装备系统）。
- 条件判定（归 `API-M09-004`）、结局判定与结局类型取值（归 M06）。
- 世界时间的推进：唯一受理入口是 `API-M01-005`，只在事件退出时由 M10 提交，本模块只提供以秒计的净时长（架构案 7.5、3.4 第 10 项）。
- 自动保存的提交：提交点由 M10 触发、由 M01 的存档服务执行，本模块只声明切面（架构案 5.3、7.1）。
- 队伍编制的来源与重置（归 M07）；技能与行为的内容清单与数值（归内容与数值设计）。

### 2.3 数据关系

- `CLS-M05-001` 是模块级聚合根，聚合成员系统持有的战场、时间轴、行动槽序列、单位状态与战斗结果；聚合只表示同属一次战斗，不表示持有成员系统的内部对象（架构案 3.4 第 5 项）。
- `CLS-M05-002` 由静态配置装载而来；`CLS-M05-003`、`CLS-M05-004` 从属 `CLS-M05-001`；`CLS-M05-005` 只登记装配顺序与依赖。
- 派生项：可调取容器范围、继承效果的求值结果、同名遗物效果、条件求值结果，由来源方维护并按来源重建，不作为数据来源（架构案 8.2 第 3 条）。

| 战斗实例 `CLS-M05-001` | 未建立、装配中、进行中、收束中、已收束 | 已收束覆盖结果已产出并交回事件侧的区间；收尾窗口阶段内保持已收束，窗口结束后释放 |
| 战斗净时长累计 `CLS-M05-003` | 累计中、已对齐 | 已对齐表示已按时间段口径换算出时间段数量，作为退出时的推进输入 |
| 收束上下文 `CLS-M05-004` | 判定中、已分派、已交回 | 分别覆盖目标判定、去向落定与结果被取走 |
| 单位行动机会状态 | 等待、机会开放、已确认 | 由 TIMELINE 与 BATTLEACT 定义并持有（`CLS-TIMELINE-003` 行动机会、`CLS-BATTLE-004` 单位状态），本文档按状态名引用 |

### 3.2 状态转换

```
战斗实例：未建立 → 装配中 → 进行中 → 收束中 → 已收束 → 未建立（释放）
                        └→ 未建立（装配失败）
净时长：累计中 → 已对齐
收束上下文：判定中 → 已分派 → 已交回
行动机会：等待 → 机会开放 → 已确认 → 等待（时间轴推进到下一个单位）
```

### 3.3 状态转换触发条件

| 转换 | 触发条件 | 经接口／事件 | 状态变化（与 4.1 一致） |
| --- | --- | --- | --- |
| 未建立 → 装配中 → 进行中 | M10 的战斗执行器受理战斗事件并调用 `API-M05-001` | `API-M05-001`（内部经 `API-M05-101`、`API-M05-102`） | 战斗实例建立；战场、参战编成、时间轴、行动槽序列与目标清单初始化；发布 战斗开始 |
| 进行中 → 收束中 → 已收束 | 任一目标达成、全部目标判定失败、撤退成功或全队失去行动能力（06-A0 §3.2、§3.4） | `API-M05-003` 提交后由 `API-M05-104` 判定 | 行动机会关闭；战斗结果产生；发布 单位状态变化、（撤退时）撤退发生 与 战斗结束 |
| 已收束 → 未建立 | 收尾窗口结束并完成事件退出，或读档丢弃未结状态 | `API-M10-002`（起因=窗口结束）或恢复流程 | 战斗实例释放；未结状态不再保留 |
| 累计中 → 已对齐 | 战斗结束时按 06-20 §3.3 的口径换算时间段数量 | `API-M05-105` | 换算结果写入 `CLS-M05-001` 与事件记账（架构案 7.5） |

### 4.2 接口详细定义

### API-M05-001 战斗启动

职责：受理一次战斗启动，装配战场与参战方，建立战斗运行状态并开放首个行动机会。
输入：
- 参数输入：事件实例标识、战斗配置标识。
- 状态输入：阶段取值、队伍编制与主角标识、角色属性取值、技能配置、装备槽与遗物槽。
- 数据输入：战斗配置与事件配置（战场标识、初始站位、波次、目标清单、收尾窗口声明）、技能与法术定义、属性定义、行为定义、敌方行为模板。
- 外部事件输入：无（由直接调用触发）。
读取：队伍成员与主角（`API-M07-001`、`API-M07-002`）、角色属性（`API-M07-004`）、技能配置（CLS-SKILL-003）、装备槽与法术书构成（CLS-EQUIP-004、CLS-EQUIP-009）、战斗配置与战场配置（`API-M01-003`）、阶段取值（`API-M10-001`）、存档内是否已有同一事件的未结战斗。
输出：
- 返回值：启动受理结果与战斗实例标识。
- 状态输出：战斗实例建立并进入进行中；参战编成、初始站位、时间轴排布与首个行动机会、行动槽序列、战场容器与场地道具、战斗目标清单、净时长归零。
- 事件输出：战斗开始。
- 外部系统调用：`API-M09-003` 效果求值（继承效果与装备、遗物提供的效果）、`API-M09-004` 条件判定（开局条件）、`API-M04-001`、`API-M04-002`、装备系统的装备槽查询与换装入口（API-EQUIP-001、API-EQUIP-003）。
产生的状态变化：战斗实例：未建立 → 进行中；时间轴已排布且首个行动机会的归属单位已确定；世界时间未推进。
前置条件：当前阶段为事件执行阶段，或由 M10 在地图阶段以战斗事件进入的编排点发起；事件实例处于进行中；队伍成员非空且主角标识存在；存档内无同一事件的未结战斗，或该未结战斗已声明可续战（REQ-M05-03）。
后置条件：战斗实例处于进行中；`CLS-M05-001` 的装配进度完成；尚未产生任何战斗结果。
副作用：发布 战斗开始；战斗界面与战场瓦片地图由 M08 订阅后装配与加载，本模块不发起界面、场景与资源调用（架构案 3.4 第 1、2 项）。
异常情况：战斗配置不存在或校验不通过、参战方为空、主角缺失 → 拒绝且不建立战斗运行状态；同一事件的未结战斗已存在且未声明续战 → 拒绝；进入战斗阶段前战场场景未就绪 → 拒绝并登记原因（REQ-M05-08）。

### API-M05-002 轮次推进

职责：推进时间轴到下一个行动机会，给出获得行动机会的单位与本次机会的可选范围。
输入：
- 参数输入：战斗实例标识。
- 状态输入：时间轴标记、各单位行动机会状态、单位状态、行动槽序列、战斗目标进度。
- 数据输入：行为定义与后摇（术语表 T-119）参数、技能后摇参数、行动速度属性的补正输入。
- 外部事件输入：无（由 M10 的轮次循环驱动）。
读取：时间轴（CLS-TIMELINE-001）、单位状态（CLS-BATTLE-004、CLS-BATTLEGOAL-002）、行动槽序列（CLS-ACTIONSLOT-001）、行为定义（`API-M01-003`）、属性取值（`API-M07-004`）。
输出：
- 返回值：获得行动机会的单位标识、该单位的单位状态与可用行为集合、预计下一次行动时机。
- 状态输出：时间轴标记推进；该单位的行动机会：等待 → 机会开放。
- 事件输出：轮次推进。
- 外部系统调用：`API-M09-003` 效果求值（行动开始时的生效项与属性取值）、`API-M01-004` 随机服务.Next（按本模块登记的消费点）。
产生的状态变化：时间轴推进一次；行动机会开放给返回的单位；世界时间未推进。
前置条件：战斗实例处于进行中；上一轮次的行为已确认提交或本次为进入战斗后的首次推进；不存在未确认的选择。
后置条件：时间轴已推进到该单位标记；该单位可经 `API-M05-003` 提交唯一一项行为。
副作用：发布 轮次推进；M10 订阅后触发战斗轮次推进节点的自动保存（架构案 5.3）。
异常情况：战斗实例不存在或已收束、上一轮次存在未确认提交 → 拒绝并登记原因；时间轴上无任何可行动单位 → 不返回行动机会，转由 `API-M05-104` 按全队失去行动能力判定收束。

### API-M05-003 行为提交

职责：受理当前行动者的唯一一项行为，校验前置条件，确认后把结果提交到战斗运行状态。
输入：
- 参数输入：战斗实例标识、行动者标识、行为标识（战斗行为表登记项）、目标选择、附带的物品或法术选择。
- 状态输入：行动机会归属、单位状态、行动槽序列、库存调取范围、战场空间判定输入、战斗目标进度。
- 数据输入：战斗行为表契约、技能定义与成本串（术语表 T-142）、投掷组件、元效果定义、地形与射程参数。
- 外部事件输入：无（由界面经意图与命令提交）。
读取：行为定义（`API-M01-003`）、技能配置（CLS-SKILL-003）、行动槽序列（CLS-ACTIONSLOT-001）、战场空间与容器（CLS-FIELD-001、CLS-FIELD-009）、调取范围内的对象实例与组件（`API-M04-001`、`API-M04-002`）、效果求值（`API-M09-003`）。
输出：
- 返回值：提交受理结果（受理／拒绝及原因）。
- 状态输出：行动槽序列追加与连携成本串删尾、单位状态与角色属性取值变化、物品堆叠与落地物变化、战场容器内容变化、下一次行动时机写回、战斗目标进度更新、净时长累加。
- 事件输出：行为提交完成；按结果发布 单位状态变化；撤退成功时发布 撤退发生。
- 外部系统调用：`API-M09-001`、`API-M09-002`、`API-M09-003`、`API-M09-005`、`API-M09-004`、`API-M04-006`、装备系统的换装入口（API-EQUIP-003）、`API-M01-004`。
产生的状态变化：该次行动机会由 机会开放 → 已确认；行为结果进入战斗运行状态；下一次行动时机写回时间轴。
前置条件：战斗实例处于进行中；行动者是当前行动机会的归属单位；行为标识已在战斗行为表登记；行为前置条件满足（射程、地形、成本串、库存与法术书内容等）。
后置条件：行为结果已提交；该次行动机会用尽并回到等待；未确认或取消的选择不产生任何状态变化（06-85 §3.4）。
副作用：确认后立即落库并在下一次自动保存节点写入存档；拒绝不消耗行动机会、行动槽字母与道具（06-85 §3.5）。
异常情况：前置条件不满足、非当前行动者提交、同一行动机会重复提交 → 拒绝且不产生状态变化（重复提交幂等拒绝）；收尾窗口阶段或结算阶段内会改变局内状态的提交 → 拒绝（架构案 6.6 硬规则 2）；依赖不可用（效果服务或写入服务拒绝）→ 整次提交不落库并登记原因。

### API-M05-004 战斗结果查询

职责：返回战斗结果标识、达成目标清单与净时长，供事件退出收束与结算取数。
输入：
- 参数输入：战斗实例标识或事件实例标识。
- 状态输入：收束上下文状态、战斗实例状态。
- 数据输入：无。
- 外部事件输入：无。
读取：战斗结果（CLS-BATTLEGOAL-004）、`CLS-M05-001`、`CLS-M05-003`、`CLS-M05-004`。
输出：
- 返回值：战斗结果标识、达成目标清单、战斗净时长（秒）与按时间段对齐的结果、结束方式（撤退／全队失去行动能力／常规）。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：无。
产生的状态变化：无。
前置条件：战斗实例已收束且结果已产生。
后置条件：返回值与 `CLS-M05-001` 内的收束状态一致；不改变任何状态，不携带写入口。
副作用：无。
异常情况：战斗尚未收束 → 返回未收束并拒绝取结果；结果标识缺失或收束中断 → 不返回结果并登记原因；同一事件重复取用 → 返回同一份结果（幂等）。

### API-M05-005 战斗状态切面

职责：提供战斗运行状态的只读切面，供界面呈现与编排侧重建设取数。
输入：
- 参数输入：战斗实例标识、切面范围（战场、时间轴、行动槽、单位状态、战斗目标与结果）。
- 状态输入：战斗实例状态。
- 数据输入：无。
- 外部事件输入：无。
读取：`CLS-M05-001` 及其聚合的成员数据（战场、时间轴、行动槽序列、单位状态、战斗结果）；呈现所需的有效值经 `API-M09-003` 求值。
输出：
- 返回值：按范围组织的只读切面。
- 状态输出：无。
- 事件输出：无。
- 外部系统调用：`API-M09-003` 效果求值（呈现所需的属性与状态生效值）。
产生的状态变化：无。
前置条件：战斗实例存在，或已收束且收尾窗口尚未结束。
后置条件：切面为只读快照，不携带写入口；读取方不得缓存为自身数据来源（架构案 4.4、8.2 第 3 条）。
副作用：无。
异常情况：战斗实例不存在 → 返回空切面；请求范围不在登记范围内 → 拒绝该范围；结算阶段内只返回只读内容。

## 5. 内部功能

### 5.1 功能列表

本节编号沿用编制初版并以 `API-` 前缀书写；按 NR-06 §九.1 与约定 §四.3，`API-` 前缀用于对外接口，下列六项均为**内部功能**（非跨模块接口，本表「是否对外暴露」列全部为「否」），对外能力仅以 `API-M05-001` 至 `API-M05-005` 为入口（约定 §三）。

| 功能 ID | 功能 | 职责、输入与输出 | 是否对外暴露 |
| --- | --- | --- | --- |
| API-M05-101（内部功能） | 模块内装配与初始化 | 按 `CLS-M05-005` 的顺序装配成员系统并建立一次战斗的装配进度；输入为启动引导上下文或 `API-M05-001` 请求，输出为装配结果 | 否（启动引导与 `API-M05-001` 间接触发） |
| API-M05-102（内部功能） | 参战编成 | 按队伍编制与主角标识形成参战名单、单位状态基线与默认选中单位；输入为队伍与属性取值，输出为参战名单 | 否（经 `API-M05-001` 触发；界面经 `API-M05-005` 读取） |
| API-M05-103（内部功能） | 战斗内结算时机 | 定义并驱动战斗内的结算时点序列（行为确认后、单位状态变化后、轮次推进前后、效果到期时），输出当前时点供成员系统与 `API-M09-003` 的调用方取用（06-75 引用本项） | 否（提交与推进路径调用） |
| API-M05-104（内部功能） | 战斗收束编排 | 判定结束方式、产出战斗结果、按撤退／全队失去行动能力／常规三类分派去向，并受理收尾窗口的结束；输入为战斗状态与目标进度 | 否（经 `API-M05-003`、`API-M05-004` 与阶段切换间接触发） |
| API-M05-105（内部功能） | 战斗净时长累计与对齐 | 按秒累加净时长，战斗结束时按 06-20 §3.3 的口径给出时间段数量 | 否（经 `API-M05-002`、`API-M05-003` 累加，经 `API-M05-004` 输出） |
| API-M05-106（内部功能） | 战斗切面采集与重建 | 声明可持久化切面；读档后按记录重建战场与时间轴并恢复派生缓存 | 否（恢复流程调用） |

### 5.2 功能之间的关系

- `API-M05-001` 依次调用 `API-M05-101`、`API-M05-102`，再由 `API-M05-103` 建立首个结算时点；装配失败时不进入进行中。
- `API-M05-002` 推进时间轴后由 `API-M05-103` 给出行动机会开放时点；`API-M05-003` 受理后由 `API-M05-103` 驱动结算时点，并由 `API-M05-105` 累加净时长（增量经 02-10 的 `API-TIME-003` 写入 `CLS-TIME-005`）。
- `API-M05-104` 由 `API-M05-003` 的结算结果或 `API-M05-002` 的无可用单位判定触发；结果经 `API-M05-004` 交回事件侧，并触发 `API-M05-105` 的对齐。
- `API-M05-106` 只服务启动与恢复路径，`API-M05-101` 只服务一次战斗的装配，两者互不调用；收尾窗口内 `API-M05-104` 只受理窗口结束，不重新产生战斗结果。

### 5.3 模块内装配与初始化顺序

1. 启动阶段（服务容器按依赖拓扑创建，架构案 6.3 第 3 项）：战斗总览（属性与行为登记）→ 技能系统（技能与法术定义、继承效果规则）→ 行动槽与连携（序列与匹配规则）→ 战场与战棋规则（空间与地形规则）→ 时间轴与行动顺序（推进与轮次口径）→ 技能与库存联动（调取范围规则）→ 战斗行为系统（行为表与契约）→ 敌人与AI（模板与波次）→ 战斗目标与结果（目标与结果口径）。本模块不新增自身常驻对象，只持有 `CLS-M05-005`。
2. 一次战斗的装配顺序（`API-M05-101` 驱动）：解析战斗配置 → 参战编成（`API-M05-102`）→ 技能配置与继承效果求值 → 行动槽序列初始化 → 战场装配（瓦片地图标识、初始站位、战场容器与场地道具）→ 时间轴排布与首个行动机会 → 库存调取范围 → 可用行为集合 → 敌方波次与行为模板绑定 → 战斗目标清单初始化 → 净时长归零。
3. 销毁按创建逆序执行（架构案 6.4）：战斗实例先释放，成员系统常驻对象按第 1 条逆序销毁；进程正常退出时的存档提交由数据域与存档服务执行，本模块不自行提交。

- 与 M10 的往来：M10 调用本模块的启动、推进与取数入口，本模块只调用 M10 的阶段查询（第 12 项）与阶段切换（第 11 项末句明确允许「阶段切换之外的能力」不得反向调用）；本模块不反向调用 M10 的事件执行入口，收尾窗口结束后由 M10 主动收束（轮询 `API-M05-004` 或订阅 战斗结束）；不属于未登记的依赖例外（8.1）；成员系统同样不得反向调用 M10 的执行入口（3.4 第 12 项）。
- 写入与同层：物品与装备状态的写入一律经 `API-M09-005` 与装备系统的写入入口，本模块不直接改对象字段（3.4 第 5、7 项、8.2 第 1、2 条）；9 个成员系统之间不互相持有对方的可变数据对象，跨成员取数经 `API-M05-005` 或成员自身入口。

## 8. 核心流程

### 8.1 战斗启动与装配

触发与参与：M10 的战斗执行器受理战斗事件后经 `API-M10-004` 调用 `API-M05-001`；参与方为 M05（装配路径与 9 个成员系统）、M10、M07、M09、M04、M01。
序：① `API-M05-101` 校验装配前置并解析战斗配置（`API-M01-003`）；② `API-M05-102` 经 `API-M07-001`、`API-M07-002`、`API-M07-004` 形成参战编成与单位状态基线；③ 技能配置与继承效果经 `API-M09-003` 求值，行动槽序列初始化；④ 战场装配（战场标识、初始站位、战场容器与场地道具），时间轴排布并开放首个行动机会；⑤ 库存调取范围、可用行为集合、敌方波次与行为模板绑定、战斗目标清单初始化；⑥ 战斗实例进入进行中，经 `API-M01-011` 发布 战斗开始，M10 落定战斗阶段。
状态变化：战斗实例 未建立 → 进行中；时间轴、行动槽、战场与目标清单就绪；世界时间未推进。
产生的事件：战斗开始（M05）；阶段切换（M10）。
结束条件：`API-M05-002` 可推出首个行动机会，战斗界面可交互。

### 8.2 轮次推进与行为提交

触发与参与：M10 的轮次循环调用 `API-M05-002`；玩家在战斗界面确认行为并经 `API-M05-003` 提交；参与方为 M05、M10、M08、M09、M04。
序：① `API-M05-002` 推进时间轴并返回获得行动机会的单位与可用行为集合，发布 轮次推进；② M10 按编排提交战斗轮次推进节点的单局存档（架构案 5.3）；③ 玩家确认行为，M08 经意图与命令调用 `API-M05-003`；④ `API-M05-103` 给出结算时点，经 `API-M09-001`／`002`／`003` 施加、移除与求值效果，经 `API-M09-005` 提交物品变化；⑤ 行动槽序列追加与连携删尾，下一次行动时机写回时间轴，目标进度更新；⑥ 发布 行为提交完成，单位状态档位变化时发布 单位状态变化，`API-M05-105` 累加净时长。
状态变化：行动机会 机会开放 → 已确认 → 等待；战斗运行状态与目标进度更新。
产生的事件：轮次推进、行为提交完成、单位状态变化（M05）；自动保存完成（M01）。
结束条件：行为结果已落库，时间轴已给出下一次行动时机。

### 8.3 战斗收束与三类分派

触发与参与：任一目标达成、全部目标判定失败、撤退成功或全队失去行动能力；参与方为 M05（收束编排）、M10、M02、M08。
序：① `API-M05-104` 确立结束方式并产出结果标识与达成目标清单，撤退成功时先发布 撤退发生；② `API-M05-105` 按 06-20 §3.3 的口径对齐净时长；③ 发布 战斗结束，战斗实例进入已收束；④ 分派：撤退 → 事件保持可进入、按 9.5.4 保留战斗内敌方状态与位置，窗口期延长与周边事件锁定由 M10 编排、M02 提交事件侧参数与锁定范围、M03 落库并发布（见 REQ-M02-10）；全队失去行动能力 → 走完收尾窗口与事件收束，结局成立由 M10 与 M06 处理（9.5.5）；常规 → 按事件配置经 `API-M10-002` 进入收尾窗口阶段或回到事件执行阶段。
状态变化：行动机会关闭；战斗结果产生；阶段取值按分派更新。
产生的事件：单位状态变化、撤退发生、战斗结束（M05）；阶段切换（M10）。
结束条件：结果标识与达成目标清单可经 `API-M05-004` 取用，阶段按分派落定。

### 8.4 读档后战斗状态重建

触发与参与：M01 发布 存档恢复完成 后由 `API-M05-106` 执行；参与方为 M05、M01、M09、M04。
序：① 经切面装载取得战斗未结状态（战场、时间轴、行动槽序列、单位状态、净时长）；② 重建战场与时间轴，恢复到最近一次行动机会开始的时刻；③ 重建派生缓存（继承效果求值结果、可调取容器范围、同名遗物效果，均按来源重建）；④ 该次行动机会内尚未确认的选择不恢复，战斗实例按存档取值置为进行中或已收束。
状态变化：战斗实例与成员数据回到存档记录的时刻；派生项按来源重建。
产生的事件：无（恢复流程只做重建）。
结束条件：`API-M05-002` 可继续推出下一个行动机会，或 `API-M05-004` 可取已收束结果。

### 8.5 收尾窗口与结束受理

触发与参与：战斗结束且事件配置声明收尾窗口；参与方为 M05（窗口规则侧）、M10、M04、M09、M08。
序：① 战斗以已收束状态进入收尾窗口阶段（M10 落定阶段，架构案 6.6）；② 窗口内搜刮战场容器与敌方遗体、治疗与整备，搜刮经 `API-M04-001` 与 `API-M04-006`，物品变化经 `API-M09-005`；③ 窗口内不推进世界时间、不消耗行动机会（06-30 §3.7），本模块只提供只读切面 `API-M05-005`；④ 玩家结束整备后本模块受理窗口结束并置本模块状态收束（战斗结束 已在收束时发布，不重复发布），阶段切换经 `API-M10-002` 提交；事件退出由 M10 轮询 `API-M05-004` 或订阅 战斗结束 后自行推进，本模块不反向调用 M10 的事件执行入口（架构案 3.3 第 11 项：被编排方不反向调用 M10 的阶段切换之外的能力）；⑤ 战斗实例释放，未结状态不再保留（REQ-M05-05）。
状态变化：战斗实例 已收束 → 未建立；收尾窗口阶段 → 事件执行阶段或地图阶段。
产生的事件：阶段切换（M10）；物品变更提交（M09）。
结束条件：回到地图界面，事件按结果标识完成退出结算。

## 9. 异常与边界情况

| 情形 | 判定条件 | 期望结果 |
| --- | --- | --- |
| 战斗配置缺失或校验不通过 | `API-M05-001` 解析不到战斗配置、战场标识或目标清单 | 拒绝启动，不建立战斗运行状态，登记原因 |
| 参战方为空 | 队伍成员集合为空或主角标识缺失 | 拒绝启动并登记原因 |
| 同一事件重复启动 | 存档内已存在同一事件的未结战斗且未声明续战 | 拒绝（续战口径见 REQ-M05-03） |
| 战场场景未就绪 | 进入战斗阶段前战场瓦片地图尚未加载完成 | 拒绝并登记原因（REQ-M05-08） |
| 实例不存在或已收束 | 对已释放或已收束实例请求推进或提交 | 拒绝，不改变任何状态 |
| 上一轮次未确认 | 存在未确认的选择而请求推进 | 拒绝；未确认的选择不产生状态变化（06-85 §3.4） |
| 行为前置条件不满足 | 超出射程、被地形阻挡、目标不合法、成本串不匹配、库存或法术书为空 | 拒绝并给出原因；不消耗行动机会、行动槽字母与道具 |
| 越权或重复提交 | 非当前行动者提交；同一行动机会重复提交 | 拒绝；重复提交幂等拒绝，不产生第二次状态变化 |
| 结算阶段内提交 | 阶段取值为结算阶段且请求会改变局内状态 | 拒绝（架构案 6.6 硬规则 2） |
| 无任何可行动单位 | 时间轴上全部我方单位处于失去行动能力状态 | 不由 `API-M05-002` 返回行动机会，转 全队失去行动能力 收束（架构案 9.5.5） |
| 收束期间依赖不可用 | 效果服务或物品写入服务拒绝 | 整次提交不落库，保持收束中并登记原因，可重试 |
| 读档时战斗状态缺失或损坏 | 切面装载失败或引用完整性校验不通过 | 按架构案 7.1 的失败语义处理，保留上一份有效存档并停在主界面 |
| 收尾窗口内的越界请求 | 阶段取值为收尾窗口阶段而请求推进世界时间或消耗行动机会 | 拒绝（06-30 §3.7） |
| 结果重复取用 | 同一事件多次调用 `API-M05-004` | 返回同一份结果，不重复产生事件 |

## 10. 实现约束

### 10.1 功能要求

- `F-M05-01` 一场战斗必须能按战斗配置完成战场装配、参战编成、初始站位、波次与目标清单的初始化，并开放首个行动机会。
- `F-M05-02` 敌我在一条时间轴上排队，行动结束后按行为后摇与属性补正写回下一次行动时机；行动越重，下一次行动越晚（06-20 §3.1）。
- `F-M05-03` 一次行动机会内只能执行一项行为且行为不能合并；取消不产生状态变化与资源消耗（06-85 §3.3、§3.4）。
- `F-M05-04` 行动槽按行为追加字母，连携以槽尾序列与成本串完全一致为释放条件，移动的字母与打断规则按 06-50 §3.1、§3.4 执行。
- `F-M05-05` 战斗内只能调取角色自身已装备且带即时取用（术语表 T-088）属性的容器内容；投掷与法术释放依附技能，不构成独立行为类型（06-80 §3、§4）。
- `F-M05-06` 任一战斗目标达成即结束战斗并进入结果结算；全部目标失败、全队无法继续行动、撤退成功三种情形以失败收场（06-A0 §3.2）。
- `F-M05-07` 战斗只输出结果标识与达成目标清单，不发放战利品；战利品由玩家在战斗中或收尾窗口内搜刮容器与敌方遗体取得（06-A0 §3.5）。
- `F-M05-08` 撤退成功后回到地图界面，事件保持可进入、已获得战利品保留、世界时间按实际战斗时长推进（06-A0 §3.3、架构案 9.5.4）。
- `F-M05-09` 全部我方单位同时处于失去行动能力状态时战斗立即结束并结束本局，该情形与战斗失败严格区分（06-A0 §3.4、架构案 9.5.5）。
- `F-M05-10` 战斗内以秒累计净时长，结束时不足十分钟的余量向上对齐到下一个时间段边界，日程按该结果回填（06-20 §3.3）。

### 10.2 实现要求

- `I-M05-01` 战斗运行状态必须可序列化并入单局存档的单局状态域切面；读档恢复到最近一次行动机会开始的时刻，该次行动机会内尚未确认的选择不恢复（架构案 5.2.2、9.3）。
- `I-M05-02` 战斗的启动与推进只能经 `API-M05-001`、`API-M05-002`、`API-M05-003` 受理；M10 的战斗执行器是唯一编排方，其他模块不得驱动轮次。
- `I-M05-03` 行为只有在玩家确认时才提交；确认后立即落库并在下一次自动保存节点写入存档，取消与未确认的选择不产生状态变化（06-85 §3.4）。
- `I-M05-04` 世界时间的推进只能经 `API-M01-005` 且只在事件退出时发生；本模块只提供以秒计的净时长与对齐结果（架构案 7.5、3.4 第 10 项）。
- `I-M05-05` 自动保存的提交点由 M10 触发、由 M01 的存档服务执行；本模块不自行序列化状态、不自行读写存档（架构案 7.1、3.4 第 6 项）。
- `I-M05-06` 效果一律经 `API-M09-001`、`API-M09-002`、`API-M09-003` 表达与求值，物品与装备状态变化一律经 `API-M09-005` 与装备系统的写入入口，不自行实现效果叠加或条件判定（架构案 3.4 第 7、8 项）。
- `I-M05-07` 随机判定必须经 `API-M01-004` 并按本模块登记的消费点分流，不自行创建随机源（架构案 7.10、3.4 第 9 项）。
- `I-M05-08` 战斗数据只写入单局状态域与玩家状态域，跨域变更经持有方入口，不持有他方可变对象与内部集合（架构案 8.2 第 1、2 条、3.4 第 5 项）。
- `I-M05-09` 派生项（继承效果求值结果、可调取容器范围、同名遗物效果、条件求值结果）只作派生缓存，不作为数据来源、不入档，按来源重建（架构案 8.2 第 3 条）。
- `I-M05-10` 本模块不得依赖 M08 与任何 L5 表现层对象；界面装配与战场场景加载由 M08 订阅 战斗开始 与 阶段切换 完成（架构案 3.4 第 1、2 项）。
- `I-M05-11` 跨模块事件名只能取自架构案 3.1 的 M05 事件栏六项，载荷字段类别与失败语义在 7.2 固定，不得自行新增事件或把「要求谁做什么」写进事件（架构案 8.4 第 2、3 条）。
- `I-M05-12` 常驻对象由服务容器按依赖拓扑创建与逆序销毁；战斗实例属数据域对象，随单局创建与释放，本模块不自行创建常驻对象（架构案 6.3、6.4、8.3）。

### 10.3 其他实现约束

- 模块内装配顺序以 5.3 为准，不由硬编码顺序决定；新增成员系统时按架构案 8.5.1 的接入步骤登记后并入顺序。
- 成员系统的对象与接口一律按其 ID 引用，本文档不重定义；成员系统之间不互相持有对方的可变数据对象。
- 战斗内结算时点由 `API-M05-103` 统一定义，成员系统与效果求值按其取用，不得各自另立时点；收尾窗口内的操作只改动物品与效果状态，不推进世界时间、不消耗行动机会、不重新产生战斗结果。
