## 1. 系统定义

### 1.1 系统目的

把线索树（术语表 T-153）的解锁进度与剪枝（术语表 T-154）封锁状态转换成三类概率池（术语表 T-172）在本局的内容集合与权重输入，作为本局生成流程与各内容系统抽取的内容范围；抽取本身留在各内容系统，本系统不执行抽取、不消费随机。

本系统的对象标识：`SYS-POOL-001 概率池联动`。

### 1.2 系统职责

- 提供概率池的池定义契约：池编号、池名、语义层级、承载内容、成分来源、内容集合决定方、权重调制方、抽取执行方、快照时点与是否可视，权威载体为 `30_概率池表.csv`；
- 在开新局时按当前节点解锁状态与封锁状态一次性计算各池的内容集合：解锁把内容加入对应池，剪枝把内容从对应池移除（设计稿 3.3）；
- 计算并固定事件池全局层的内容集合（全局事件池，术语表 T-169），向生成流程提供本局允许出现的事件标识上界；
- 计算并固定物品池（术语表 T-084）与商人经营池（术语表 T-173）在本局的内容集合；
- 登记权重输入：为每个池声明出现率权重的取值来源与调制方，本系统不计算出现率、不做权重调制；
- 把一次计算的池成分作为单局状态（术语表 T-051）写入世界状态域，随单局存档保存，读档按快照恢复；
- 受理池内容集合的只读查询，向生成流程与各内容系统返回内容标识集合与权重输入声明；
- 受理新增池的登记契约：新增池前先在概率池表中补齐成分来源、内容集合决定方、权重调制方与抽取执行方四项契约。

### 1.3 系统边界

本系统不负责：

- 抽取执行：事件抽取、变体抽取、物品选取与商人经营内容抽取归各内容系统（事件系统、物品系统、商人原型配置，设计稿 3.1 与决策 38）；
- 随机消费：随机源与确定性序列归 M01 的随机服务（引用 `API-M01-004 随机服务.Next`），本系统不申请随机序列、不消费随机；
- 当前事件池（术语表 T-170）的局内刷新：区域形态与事件属性配置的过滤、配额核算、按权重抽取与点位查重归 M02 的事件调度（引用 `API-M02-002 事件池刷新`），本系统只提供全局层内容集合；
- 区域形态（术语表 T-067）及其对刷新范围与窗口期长度的作用，归 M03 的探索系统（引用 `API-M03-002 区域形态查询`）；
- 难度体系的层权重调制：难度参数归后续数值设计阶段，本系统只登记权重输入与调制方，不实现调制（设计稿 3.5）；
- 稀释现象的处理：系统不做额外处理，也不引入分层加入或保底出现率（设计稿 3.6）；
- 池的可视化：全部池不可视，本系统不提供池内容集合、成分构成或抽取概率的呈现接口，不向 M08 提供任何取数能力（设计稿 3.8）；
- 线索树节点、关系、传闻、节点状态与封锁集合（术语表 T-167）与封锁标记（术语表 T-168）的持有与写入，归 07-10 与 07-20；
- 跨局数据的写入：节点解锁与封锁状态在局末结算写入，归 07-40 与 M10（引用 `API-M10-005 结算执行入口`）；
- 存档文件读写、切面提交与恢复顺序驱动，归 01-50 的存档服务（引用 `存档服务（CLS-SAVE-001）`）；
- 生成流程的其余三项产物：事件的窗口期与出现顺序、区域解锁状态、行情（术语表 T-094），归 09-20 局生成与种子（引用 `生成流程调用（GENERATE，ID 待补）`）；
- 池成分计算的写入口登记：本能力的调用方与登记位置见缺口申报 REQ-POOL-01；本系统按 M06 模块单元文档的口径取「首次受理查询即完成一次计算」，不另设独立的跨模块计算入口。

### 2.3 数据关系

- CLS-POOL-001 逐项决定 CLS-POOL-002 的池编号、承载内容、成分来源与抽取执行方；
- CLS-POOL-006 把内容侧配置的用途词条与主营词条解析为池编号，供 CLS-POOL-003 的所属池编号取值；
- CLS-POOL-003 汇集为 CLS-POOL-002，本局全部 CLS-POOL-002 汇总为 CLS-POOL-004；
- CLS-POOL-005 按池编号为 CLS-POOL-002 的每条内容声明权重取值来源与调制方，不改变权重数值；
- CLS-POOL-007 按 CLS-POOL-002 与 CLS-POOL-005 重建，不另存；
- 事件池的池成分与当前事件池是上界与刷新两层关系：本系统只产出全局层，当前层由 M02 按区域形态与事件属性配置过滤（架构案 5.2.5 第 1 条）。

## 3. 状态定义

### 3.1 状态

| 状态实体 | 取值 |
| --- | --- |
| CLS-POOL-004 建立状态 | 未计算／已计算／按快照恢复 |
| CLS-POOL-001 登记状态 | 已确认／待补充 |
| CLS-POOL-003 来源标记 | 内容侧声明／线索树解锁加入 |
| CLS-POOL-005 生效状态 | 已确认／待补充 |

### 3.2 状态转换

```
未计算 → 已计算（开新局计算）
未计算 → 按快照恢复（读档装载）
```

已计算与按快照恢复都是本局终态：本局内不重算（设计稿 3.3、3.7）。登记状态与生效状态由概率池表与内容侧配置的登记内容决定，运行期不转换；来源标记在计算时写入，运行期不转换。

### 3.3 状态转换触发条件

| 转换 | 触发行为或事件 | 执行接口 | 与接口表「状态变化」列一致 |
| --- | --- | --- | --- |
| 未计算 → 已计算 | 开新局时首次受理 `API-POOL-002 池内容集合查询`（对外即 M06 模块能力 `API-M06-003`），触发一次池成分计算 | API-POOL-002（内部经 API-POOL-001） | 一致 |
| 未计算 → 按快照恢复 | 读档路径经存档服务装载世界状态域切面 | API-POOL-003 | 一致 |
| 已计算 → 已计算 | 同一局内重复受理池内容集合查询 | API-POOL-002 | 不重算，返回已固定内容（见第 9 节） |
| 按快照恢复 → 按快照恢复 | 同一局内重复装载 | API-POOL-003 | 拒绝执行，状态不变 |
| 登记状态与生效状态 | 由概率池表与内容侧配置的登记内容决定 | `API-M01-003`（读取）、API-POOL-002（输出） | 一致 |
| 来源标记 | 由池成分计算按加入来源写入 | API-POOL-001（由 API-POOL-002 首次受理触发） | 一致 |

### 4.2 接口详细定义

#### API-POOL-001 池成分计算 ComputePoolComposition()

职责：
在开新局时按当前节点解锁状态与封锁状态一次性计算三类池的内容集合，把结果作为本局池成分写入世界状态域并固定为快照。本入口不对跨模块开放，由 `API-POOL-002` 池内容集合查询的首次受理触发（对外即 M06 模块能力 `API-M06-003`）。

输入：
- 参数输入：本局标识；池编号范围（默认取全部已登记且登记状态为已确认的池）
- 状态输入：CLS-POOL-004 建立状态；节点解锁状态；封锁状态
- 数据输入：CLS-POOL-001 池定义；CLS-POOL-005 权重输入声明；CLS-POOL-006 池划分映射；内容侧配置的池归属声明与权重字段
- 外部事件输入：无（本系统不订阅事件驱动计算）

读取：
- CLS-POOL-001、CLS-POOL-004、CLS-POOL-005、CLS-POOL-006
- 节点解锁状态与节点类型专属字段（经 `API-M06-001 节点与传闻查询`）
- 封锁状态（经 `API-M06-002 封锁状态查询`）
- 事件属性配置（CLS-EVENT-003）、物品词条与内容配置（ITEM，ID 待补）、商人原型配置（TRADE，ID 待补）的池归属与权重字段（经 `API-M01-003 配置服务.Query`）

输出：
- 返回值：池成分计算结论，含逐池的内容条数、跳过的池与失败原因
- 状态输出：CLS-POOL-004 由未计算转为已计算；CLS-POOL-002 与 CLS-POOL-003 按计算结论建立
- 事件输出：无
- 外部系统调用：`API-M01-003 配置服务.Query`、`API-M01-010 日志服务.Write`；池成分写入世界状态域经数据域持有方入口（M01，ID 待补；该入口未在 M01 与 01-50 登记，见缺口申报 REQ-POOL-03）

产生的状态变化：
- 各池的内容集合建立，事件池的池成分建立为本局允许出现的事件标识上界（全局事件池，术语表 T-169）
- CLS-POOL-004 建立状态由未计算转为已计算

前置条件：
- 由 `API-POOL-002` 池内容集合查询的首次受理触发，且 CLS-POOL-004 建立状态为未计算
- 节点解锁状态与封锁状态可读且为已提交状态
- 池定义已完成配置加载与校验

后置条件：
- 每个登记状态为已确认的池各有一份 CLS-POOL-002
- 同一池内按内容标识去重；同一内容出现在多个池时按池分别保留
- 解锁加入与封锁移除在该次计算中一次性应用，本局内保持不变
- 池成分随下一次单局存档提交采集入档

副作用：
- 池成分写入世界状态域
- 写运行日志：候选条数、加入与移除条数、跳过项与失败原因（架构案 7.7）
- 不执行抽取、不申请随机序列、不发布跨模块事件

异常情况：
- 建立状态不是未计算时拒绝执行并返回状态不允许
- 池定义的登记状态为待补充时跳过该池并写内容日志
- 节点解锁状态或封锁状态不可读时整笔失败、不产生部分池成分
- 内容侧配置缺少池归属声明或划分键未登记时，该内容不进入任何池并写内容日志
- 单池一致性校验不通过时该池不写入，其余池继续，失败原因记入计算结论

#### API-POOL-002 池内容集合查询 QueryPoolContents()

职责：
按池编号或划分键返回该池在本局的内容标识集合与权重输入声明，作为生成流程与抽取方的只读内容范围；本局尚未计算时，首次受理同时触发一次池成分计算（对外即 M06 模块能力 `API-M06-003`）。

输入：
- 参数输入：池编号或划分键（用途词条／商人主营词条）；查询范围
- 状态输入：CLS-POOL-004 建立状态
- 数据输入：CLS-POOL-001、CLS-POOL-005
- 外部事件输入：无

读取：
- CLS-POOL-002、CLS-POOL-003、CLS-POOL-004、CLS-POOL-005

输出：
- 返回值：CLS-POOL-007 池内容集合查询结果，含池编号、内容标识集合、内容条数与权重输入声明（权重取值来源与调制方）
- 状态输出：无
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 首次受理时由 `API-POOL-001` 完成一次池成分计算并写入世界状态域：CLS-POOL-004 由未计算转为已计算
- 本局已计算或按快照恢复时无状态变化

前置条件：
- 查询发生在开新局装配阶段或其后（架构案 9.5.1）
- 节点解锁状态与封锁状态可读且为已提交状态

后置条件：
- 返回内容与已固定的池成分一致；同一局内重复受理不重算、不改变任何数据
- 返回的只读快照不携带写入口；调用方不得把结果缓存为自身数据（架构案 4.2、8.2 第 3 条）

副作用：
- 首次受理时池成分写入世界状态域；其余受理无副作用

异常情况：
- 非开新局装配阶段且池成分未计算时返回不可用标记与空集合
- 节点解锁状态或封锁状态不可读时整笔失败，不产生部分池成分
- 池编号或划分键未知时返回空集合并写内容日志
- 同一内容出现在多个池时按池分别返回，不跨池合并

#### API-POOL-003 池成分快照装载 LoadPoolComposition()

职责：
在读档路径把单局存档中的池成分按快照装载为本局的世界状态域池成分，不重新计算。

输入：
- 参数输入：单局存档的世界状态域切面中的池成分记录
- 状态输入：CLS-POOL-004 建立状态
- 数据输入：CLS-POOL-001（校验池编号是否仍有效）
- 外部事件输入：无

读取：
- 存档中的池成分记录、CLS-POOL-001

输出：
- 返回值：装载结论，含逐池内容条数与不匹配项
- 状态输出：CLS-POOL-002、CLS-POOL-003 与 CLS-POOL-004 按快照恢复，建立状态置为按快照恢复
- 事件输出：无
- 外部系统调用：`API-M01-010 日志服务.Write`

产生的状态变化：
- 世界状态域的池成分由空转为快照内容

前置条件：
- 读档路径已按架构案 7.1 的恢复顺序完成世界状态域的装载
- CLS-POOL-004 建立状态为未计算

后置条件：
- 池成分与存档一致；不重算、不重新过滤、不重新抽取（架构案 9.3 约束）
- 池编号已不在池定义中的记录不进入查询结果

副作用：
- 无

异常情况：
- 存档缺少池成分记录时保持未计算并写内容日志
- 建立状态不是未计算时拒绝重复装载
- 池成分记录校验不通过时整笔装载失败，按读档失败语义处理（架构案 7.1）

#### 5.1.1 池定义读取 ListPoolDefinitions()

职责：经配置服务读取概率池表的池定义与权重输入声明，输出已确认池清单与待补充池清单。

输入：参数输入：无；状态输入：无；数据输入：CLS-POOL-001、CLS-POOL-005；外部事件输入：无。

读取：CLS-POOL-001、CLS-POOL-005。

输出：返回值：已确认池清单与待补充池清单；状态输出：无；事件输出：无；外部系统调用：`API-M01-003 配置服务.Query`。

产生的状态变化：无。

前置条件：配置服务已完成加载与校验。

后置条件：登记状态为待补充的池不参与内容集合计算，并被记入内容日志。

副作用：无。

异常情况：池定义校验不通过时按启动阶段 2 的失败处置中止启动（架构案 6.1）；池定义中出现未登记的成分来源或抽取执行方时按校验不通过处理。

#### 5.1.2 池划分解析 ResolvePoolPartition()

职责：按池划分映射把内容侧配置的划分键解析为池编号，供池成分项的所属池编号取值。

输入：参数输入：划分维度（用途词条／主营词条）、划分键；状态输入：无；数据输入：CLS-POOL-006、CLS-POOL-001；外部事件输入：无。

读取：CLS-POOL-006、CLS-POOL-001。

输出：返回值：池编号或未登记标记；状态输出：无；事件输出：无；外部系统调用：无。

产生的状态变化：无。

前置条件：池定义读取已完成。

后置条件：同一划分维度下的同一划分键只解析为一个池编号；解析结果与概率池表登记的池编号一致。

副作用：无。

异常情况：划分键无对应池编号时返回未登记并写内容日志；划分维度未在池定义中声明时该维度不参与解析。

#### 5.1.3 池内容集合计算 BuildPoolContents()

职责：按池的承载内容与成分来源汇集候选内容，按解锁状态加入、按封锁状态移除，产出内容标识去重后的池成分项。

输入：参数输入：池编号、本局标识；状态输入：节点解锁状态、封锁状态；数据输入：CLS-POOL-001、CLS-POOL-005、CLS-POOL-006、内容侧配置的池归属声明；外部事件输入：无。

读取：CLS-POOL-001、CLS-POOL-005、CLS-POOL-006、内容侧配置（EVENT／ITEM／TRADE，ID 待补）、节点解锁状态（经 `API-M06-001`）、封锁状态（经 `API-M06-002`）。

输出：返回值：池成分项集合与计算结论；状态输出：CLS-POOL-003 建立、CLS-POOL-002 汇总；事件输出：无；外部系统调用：`API-M01-003`、`API-M01-010`。

产生的状态变化：池成分项按内容标识建立；池成分汇总为该池的内容集合。

前置条件：该池登记状态为已确认；节点解锁状态与封锁状态为已提交状态。

后置条件：同一池内按内容标识去重；同一内容出现在多个池时按池分别保留；被封锁内容与未解锁内容同样不进入内容集合。

副作用：写内容日志（候选条数、加入条数、移除条数与未登记项）。

异常情况：节点解锁状态或封锁状态不可读时整笔失败；内容侧配置缺少池归属声明时该内容不进入任何池。

#### 5.1.4 池成分一致性校验 ValidatePoolComposition()

职责：校验一次计算的池成分在池内的唯一性、池间的独立性与快照完整性。

输入：参数输入：无；状态输入：CLS-POOL-004；数据输入：CLS-POOL-001；外部事件输入：无。

读取：CLS-POOL-001、CLS-POOL-002、CLS-POOL-003、CLS-POOL-004。

输出：返回值：校验结论；状态输出：无；事件输出：无；外部系统调用：`API-M01-010 日志服务.Write`。

产生的状态变化：无。

前置条件：本局池成分已计算完成。

后置条件：校验不通过的池标记为计算失败并记入计算结论，不产生部分写入；空内容集合是合法结果。

副作用：写内容日志。

异常情况：池编号在池成分与池定义之间不一致时该池校验不通过；同一池内出现重复内容标识时判定为校验不通过。

#### 5.1.5 池成分切面采集与装载 CollectAndLoadPoolSlice()

职责：向存档服务声明池成分所属的世界状态域切面，并按存档服务的驱动采集与装载池成分快照。

输入：参数输入：切面采集请求或装载请求；状态输入：CLS-POOL-004；数据输入：CLS-POOL-001；外部事件输入：无。

读取：CLS-POOL-001、CLS-POOL-002、CLS-POOL-003、CLS-POOL-004。

输出：返回值：切面数据或装载结论；状态输出：装载时 CLS-POOL-004 转为按快照恢复；事件输出：无；外部系统调用：`存档切面声明（API-SAVE-001）`、`存档服务采集与装载（API-SAVE-002、API-SAVE-003）`、`API-M01-010`。

产生的状态变化：采集不改变状态；装载把池成分由空转为快照内容。

前置条件：采集时本局池成分已计算；装载时世界状态域已按恢复顺序装载完成。

后置条件：本系统不自行序列化状态、不自行读写存档文件（架构案 7.1）。

副作用：无。

异常情况：采集时池成分未计算则切面为空并写内容日志；装载校验不通过时按读档失败语义处理。

#### 5.1.6 查询结果构造 BuildPoolQueryResult()

职责：按池编号或划分键构造内容集合与权重输入声明的只读快照。

输入：参数输入：池编号或划分键、查询范围；状态输入：CLS-POOL-004；数据输入：CLS-POOL-001、CLS-POOL-005；外部事件输入：无。

读取：CLS-POOL-001、CLS-POOL-002、CLS-POOL-003、CLS-POOL-004、CLS-POOL-005。

输出：返回值：CLS-POOL-007 池内容集合查询结果；状态输出：无；事件输出：无；外部系统调用：无。

产生的状态变化：无。

前置条件：CLS-POOL-004 建立状态为已计算或按快照恢复。

后置条件：快照不携带写入口；权重输入声明只返回取值来源与调制方，不返回调制后的权重数值。

副作用：无。

异常情况：建立状态为未计算时返回不可用标记与空集合；池编号未知时返回空集合并写内容日志。

### 5.2 功能之间的关系

- 开新局序（由 `API-POOL-002` 的首次受理触发）：池定义读取 → 池划分解析 → 池内容集合计算 → 池成分一致性校验 → 池成分切面采集（随下一次单局存档提交）；
- 查询序：查询结果构造只读取已固定的池成分与静态声明，除池定义读取外不触发任何计算，也不触发任何写入；
- 失败隔离：单池校验不通过时该池成分不写入，其余池照常完成，失败原因记入计算结论；
- 读档序：存档服务驱动池成分切面采集与装载 → 建立状态置为按快照恢复 → 查询结果构造可直接取数；
- 权重输入声明不参与内容集合计算，与池定义读取一并取得，随查询结果返回给抽取方。

- 禁止方向：不得持有 M02、M04 或同模块其他单元的可变对象（架构案 3.4 第 5 项）；不得被 M01 与 M09 依赖；不得依赖任何表现层对象（第 1、4 项）；
- 不绕过统一入口：不自行读写存档或序列化状态（第 6 项）；不自行创建随机源，本系统不消费随机（第 9 项与架构案 7.10）；不推进世界时间（第 10 项）；不自行实现条件判定与效果叠加（第 8 项与架构案 7.11）；
- 无循环依赖：本系统不调用任何模块的执行入口；本系统不发布跨模块事件，也不订阅事件，跨模块通知不适用于本系统（架构案 4.5）。

        M02：本局事件标识上界（全局事件池）      M04：物品池与商人经营池内容集合        M10：开新局与刷新核对
                        │
                        ▼
        M02 当前事件池刷新（区域形态与事件属性配置过滤，局内变化）

## 8. 核心流程

### 8.1 开新局的池成分计算与快照

触发：玩家在局外选择开新局，进入本局装配阶段（架构案 6.1 阶段 5、9.5.1 第 1、3 步）；由生成流程首次受理池内容集合查询触发计算。

参与者：M10 的开新局编排、本系统、07-10 线索树核心、07-20 剪枝系统、M01 的配置服务与数据域侧、01-50 存档服务。

调用顺序：
1. 开新局的生成流程（由 M10 的开新局编排经 `API-M02-005` 发起）首次受理 `API-POOL-002 池内容集合查询`（对外即 `API-M06-003`）；该次受理内触发一次池成分计算（内部入口 `API-POOL-001`），以下第 2 至 5 步在该次受理内完成；
2. 本系统经 `API-M06-001 节点与传闻查询` 读取节点解锁状态与节点类型专属字段，经 `API-M06-002 封锁状态查询` 读取封锁状态；
3. 本系统经 `API-M01-003 配置服务.Query` 读取池定义、权重输入声明、池划分映射与内容侧配置的池归属声明；
4. 本系统产出各池的池成分项与池成分，对每个池执行一次池成分一致性校验；
5. 本系统经世界状态域持有方入口写入池成分与池成分快照，置 CLS-POOL-004 为已计算，写运行日志并返回计算结论；
6. 生成流程在第 1 步的同一受理内取得内容集合，事件池的池成分作为本局事件标识上界；本局内其他模块与后续受理经 `API-POOL-002`（对外即 `API-M06-003`）只读取数；
7. 池成分随下一次单局存档提交采集入档（自动保存的两类节点，架构案 5.3）。

状态变化：CLS-POOL-004 由未计算转为已计算；各池的内容集合建立；本局事件标识上界建立。

产生的事件：无（本系统不发布事件；本局生成完成由 09-20 与 M02 侧发布）。

结束条件：全部登记状态为已确认的池各有一份内容集合，计算结论与日志可查，池内容集合查询可用。

### 8.2 内容系统读取池内容集合与权重输入

触发：生成流程需要本局事件内容范围，或物品系统与商人原型配置需要按划分键取得本局可用的产出与经营内容。

参与者：M02、M04、M10、本系统。

调用顺序：
1. 调用方在开新局读取生成输入，或在内容抽取前调用 `API-POOL-002 池内容集合查询`（其他模块经 `API-M06-003`）；
2. 本系统按池编号或划分键返回 CLS-POOL-007 池内容集合查询结果，含内容标识集合与权重输入声明；
3. 调用方在自己一侧申请确定性序列并执行抽取、变体抽取与点位查重，本系统不参与；
4. 抽取结果由各内容系统自行落库、固定与呈现，本系统不读取抽取结果。

状态变化：无（本流程为已计算后的只读取数；首次受理同时触发计算的路径见 8.1）。

产生的事件：无。

结束条件：调用方取得内容标识集合与权重输入声明。

### 8.3 读档按快照恢复池成分

触发：启动阶段的读档路径，或玩家在局外选择已有存档（架构案 9.3）。

参与者：01-50 存档服务、M01 的数据域侧、本系统。

调用顺序：
1. 存档服务按恢复顺序装载世界状态域切面（架构案 7.1、9.3 第 7 步）；
2. 存档服务调用 `API-POOL-003 池成分快照装载`；
3. 本系统按快照恢复池成分项、池成分与建立状态，并校验池编号在池定义中仍有效；
4. 后续池内容集合查询直接返回快照内容，不重算、不重新过滤、不重新抽取。

状态变化：CLS-POOL-004 由未计算转为按快照恢复；世界状态域的池成分由空转为快照内容。

产生的事件：无（存档恢复完成由 M01 发布）。

结束条件：池成分与存档一致且查询可用。

## 9. 异常与边界情况

| 情形 | 判定条件 | 期望结果 |
| --- | --- | --- |
| 同一局重复触发计算 | CLS-POOL-004 建立状态不是未计算时受理 `API-POOL-002`（内部触发 `API-POOL-001`） | 不重算，返回已固定内容与状态不允许的提示 |
| 同一内容被多个池承载 | 同一内容标识出现在多个池的成分中 | 按池分别保留，不跨池去重（设计稿 3.3） |
| 同一池内重复加入 | 同一池内出现重复内容标识 | 按内容标识去重，一条内容在一次抽取中只出现一次 |
| 内容同时处于解锁与封锁 | 内容对应节点已解锁且被封锁 | 封锁等同于未解锁，不进入内容集合（`07-20` 3.1） |
| 空池 | 某池的内容集合为空 | 查询返回空集合，抽取方按空集合处理，不视为错误，写内容日志 |
| 待补充池 | 池定义的登记状态为待补充 | 跳过该池，不参与计算，写内容日志 |
| 内容侧配置缺少池归属声明 | 内容未声明所属池，或划分键未登记 | 该内容不进入任何池，写内容日志（内容问题） |
| 解锁状态或封锁状态不可读 | `API-M06-001` 或 `API-M06-002` 返回不可用 | 整笔失败，不产生部分池成分 |
| 单池计算失败 | 该池一致性校验不通过 | 该池成分不写入，失败原因记入计算结论，其余池继续 |
| 建立状态为未计算时查询 | 非开新局装配阶段查询且池成分未计算 | 返回不可用标记与空集合；开新局装配阶段的首次受理按 3.3 触发一次计算 |
| 池编号未知 | 查询传入未登记的池编号或划分键 | 返回空集合并写内容日志 |
| 读档缺少池成分记录 | 存档的世界状态域切面不含池成分 | 保持未计算并写内容日志，查询返回不可用 |
| 存档池编号已失效 | 快照中的池编号不在当前池定义中 | 该池记录不进入查询结果并写内容日志 |
| 重复装载 | 建立状态不是未计算时调用 API-POOL-003 | 拒绝执行，状态不变 |
| 局内解锁写入 | 本局内节点解锁与传闻解锁经局末结算写入 | 不触发本系统重算；新解锁内容在下一局开新局时加入内容集合（设计稿 3.3） |
| 局内封锁提交 | 剪枝在局外提交后立即生效于下一局 | 同上；封锁内容在下一局计算时移除 |
| 区域形态转变 | 局内区域形态变化 | 不触发本系统重算；当前事件池由 M02 按新形态从全局层内容集合取子集（架构案 5.2.5 第 2 条） |
| 界面请求池数据 | 任何界面对象请求池内容集合、成分或概率 | 不提供该接口；全部池不可视（设计稿 3.8） |
| 难度参数缺失 | 权重调制方为后续数值设计阶段 | 权重输入声明只返回取值来源与调制方，不返回调制后的权重 |
| 抽取未中或稀释 | 抽取方未抽中目标，或事件总量随解锁增多 | 本系统不做补偿，不引入分层加入与保底出现率（设计稿 3.6） |
| 结算阶段内的写入请求 | 结算阶段（架构案 6.6 硬规则 2）内收到池成分写入请求 | 本系统不执行写入，不改变局内状态 |
| 新增池未登记四项契约 | 概率池表出现缺少成分来源、内容集合决定方、权重调制方或抽取执行方的记录 | 配置校验不通过，按启动阶段 2 的失败处置中止启动（架构案 6.1） |

## 10. 实现约束

| 编号 | 约束 | 依据 |
| --- | --- | --- |
| I-POOL-01 | 本系统只计算内容集合与提供权重输入，不执行任何抽取、不申请随机序列、不消费随机；抽取执行方保留在事件系统、物品系统与商人原型配置。 | 设计稿 1、3.1、决策 38、42 |
| I-POOL-02 | 全部池不可视：不提供池内容集合、成分构成或抽取概率的呈现接口，界面层不得经本系统取得池数据。 | 设计稿 3.8、架构案 3.4 第 3 项 |
| I-POOL-03 | 池成分在开新局时按当前解锁与封锁状态计算一次，局内保持不变；局内解锁与封锁变化只在下一局参与计算。 | 设计稿 3.3、3.7 |
| I-POOL-04 | 池成分作为单局状态写入世界状态域并随单局存档保存；读档按快照恢复，不重算、不重新过滤、不重新抽取。 | 设计稿 3.7、架构案 5.2.5、9.3 |
| I-POOL-05 | 同一池内按内容标识去重；同一内容出现在多个池时按池分别处理，不做跨池去重。 | 设计稿 3.3 |
| I-POOL-06 | 封锁内容等同于未解锁：不进入任何池的内容集合，不参与事件生成与内容抽取。 | `07-20` 3.1、设计稿 3.3 |
| I-POOL-07 | 线索树进度决定内容集合，难度只调整出现率权重、不改变内容集合；本系统不实现层权重调制。 | 设计稿 3.5、F-POOL-07 |
| I-POOL-08 | 本系统不对稀释做额外处理，不引入分层加入或保底出现率；重复体验需求由剪枝承担。 | 设计稿 3.6 |
| I-POOL-09 | 本系统不修改他方数据：解锁状态、封锁状态与内容侧配置只读；池成分的写入经世界状态域持有方入口，写入方登记见缺口申报 REQ-POOL-03。 | 架构案 8.2、3.2 |
| I-POOL-10 | 池成分的持久化一律经 01-50 的存档服务，不自行读写存档文件、不自行序列化状态。 | 架构案 7.1、3.4 第 6 项 |
| I-POOL-11 | 本系统不自行实现条件判定与效果叠加；内容与池的归属由内容侧配置声明与池定义决定。 | 架构案 7.11、3.4 第 8 项 |
| I-POOL-12 | 新增池先在 `30_概率池表.csv` 登记池编号、池名称、承载内容、成分来源、内容集合决定方、权重调制方与抽取执行方，再在本系统实现。 | 设计稿 3.1、架构案 8.5.4 |
| I-POOL-13 | 本系统不参与生成流程的其余三项产物，也不参与当前事件池的局内刷新与配额核算。 | 设计稿 3.4、架构案 5.2.5、ARC-M02-001 |
| I-POOL-14 | 池成分计算与查询不产生跨模块事件；跨模块通知一律经 M01 的事件分发器，本系统不自建观察者。 | 架构案 4.5、8.4 第 1、2 条 |
| I-POOL-15 | 本系统不依赖表现层、不持有界面对象，也不调用 M10 的阶段切换与执行器能力。 | 架构案 3.4 第 1、4 项 |
| I-POOL-16 | 池成分计算必须在不消费随机的前提下得到一致结果：同一解锁状态与同一封锁状态产生同一内容集合。 | 设计稿 3.7、架构案 7.10 |
