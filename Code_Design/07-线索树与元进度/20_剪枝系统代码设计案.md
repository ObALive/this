## 1. 系统定义

### 1.1 系统目的

以封锁集合为唯一权威，承载玩家在局外对已解锁内容的选择性暂时封锁与自由撤销：确定完整级联范围、写入封锁集合与节点封锁标记，并向开新局与内容可用性判定提供封锁状态。

本系统的对象标识：`SYS-PRUNE-001 剪枝系统`。

### 1.2 系统职责

- 维护封锁集合（术语表 T-167）：记录当前处于封锁状态的节点及其归属操作，作为封锁语义的唯一权威来源；
- 维护剪枝操作记录（撤销历史）：以单次操作为粒度登记剪枝操作的标识、范围、类型与撤销结果；
- 受理剪枝提交：按节点关系图确定完整级联范围，写入封锁集合并登记一次操作记录；
- 受理撤销：按被撤销操作的覆盖范围批量解除该次操作的封锁，并按重叠归属规则处理重叠部分；
- 写入与清除节点封锁标记（术语表 T-168）：提交与撤销时经线索树写入接口提交标记写入项；
- 提供 `API-M06-002 封锁状态查询` 的实现侧：按封锁集合重建只读封锁状态视图，供开新局、池内容集合计算与呈现列表取数使用；
- 提供提交前的受影响范围摘要，作为本版本封锁影响面可见性的承担方式之一；
- 校验封锁集合与节点封锁标记的一致性，并按封锁集合重建标记；
- 发布封锁状态变化事件；
- 向 M01 的存档服务声明封锁集合与操作记录的跨局切面；操作记录本身的跨局归属与写入时点待上游补充（REQ-PRUNE-01）。

### 1.3 系统边界

本系统不负责：

- 线索树节点、关系与传闻数据的持有与解锁写入，归 07-10 线索树核心（SYS-CLUETREE-001）；本系统只经其写入接口提交封锁标记写入项；
- 节点状态取值、事件解锁状态与传闻解锁状态的判定与写入，归 07-40 局末结算与写入（SYS-SETTLE-001）的节点解锁检查组件；
- 大关（术语表 T-008）推进与达成记录的写入，归 07-40；剪枝不改变大关进度标记；
- 下一局起始大关的确定与「从哪个大关开始游玩」的取值，归 09-20 局生成与种子（SYS-GENERATE-001）的生成流程；本系统只提供封锁状态与大关回退的操作记录；
- 内容可用性的下游计算：全局事件池（术语表 T-169）与各池内容集合的计算归 07-30 概率池联动（SYS-POOL-001），本局环境的生成归 09-20；本系统只提供封锁状态；
- 封锁对开放阈值（术语表 T-165）判定的影响计算：判定归 07-40 的事件解锁判定，本系统只提供未被封锁与否的状态；
- 事件的呈现列表取数与地图呈现，归 M03 与 M08；
- 封锁集合与节点封锁标记的结算写入路径：这两项不经结算组件写入（架构案 9.5.6、设计稿 3.4）；
- 剪枝界面的绘制、交互与编辑态持有，归 M08 的剪枝界面（M08，ID 待补）；
- 局内剪枝：剪枝只在局外阶段进行，本系统在局内不提供任何改变跨局状态的入口；
- 阶段推进与跨模块流程编排，归 M10；本系统只经 `API-M10-001 阶段查询` 判定受理条件；
- 存档文件与持久化结构的读写，归 01-50 的存档服务（CLS-SAVE-001）；
- 节点内容条目的隐藏与删除：封锁节点的百科页（术语表 T-176）内容保持可读，本系统不提供隐藏能力；
- 剪枝预览面板与自定义挑战模式：两项按上游结论挂起，本版本不提供对应接口。

### 2.3 数据关系

- CLS-PRUNE-002 按操作标识归属 CLS-PRUNE-001 的条目；撤销一条操作即解除其中归属该操作的条目；
- CLS-PRUNE-003 由选择集合与节点关系图重建，被 CLS-PRUNE-002 登记为覆盖范围，并决定 CLS-PRUNE-001 的写入条目；
- CLS-PRUNE-004 完全按 CLS-PRUNE-001 重建，是其他单元读取封锁状态的唯一形态；
- 节点封锁标记是 CLS-PRUNE-001 的派生结果，存储在线索树节点数据上，写入经线索树写入接口；
- CLS-PRUNE-001 与 CLS-PRUNE-002 的跨局属性与写入时点同源：封锁集合与封锁标记属架构案 9.5.6 的既定例外，剪枝操作记录是否列入跨局存档内容、是否同属该例外待上游补充（缺口申报 REQ-PRUNE-01，与 `01-50` 的 `REQ-SAVE-04` 合并）。

## 3. 状态定义

### 3.1 状态

| 状态实体 | 取值 |
| --- | --- |
| CLS-PRUNE-001 条目封锁状态 | 未封锁／已封锁 |
| CLS-PRUNE-002 操作状态 | 生效中／已撤销 |
| 节点封锁标记（外部数据） | 无标记／已封锁标注 |

CLS-PRUNE-002 的操作类型（玩家选择／大关回退预设）是记录的登记属性而非状态实体：取值随记录登记、运行期不转换，不进入本节的状态转换与状态转换触发条件两表，见 2.1 的字段说明。

节点状态取值（已解锁／锁定可见／隐藏）由 07-10 维护，封锁不改变节点状态取值，只在树上与百科页追加已封锁标注。

### 3.2 状态转换

```
未封锁 → 已封锁                     提交剪枝，条目按级联范围写入
已封锁 → 已封锁（归属改为最后一次操作）  重叠封锁，条目改归属而不解除
已封锁 → 未封锁                     撤销其归属操作
生效中 → 已撤销                     以单次操作为粒度撤销
无标记 → 已封锁标注                  提交剪枝或一致性重建写入标记
已封锁标注 → 无标记                  撤销或一致性重建清除标记
```

条目一旦解除封锁即从封锁集合移除，不作为历史保留；历史由 CLS-PRUNE-002 承载。

### 3.3 状态转换触发条件

| 转换 | 触发行为或事件 | 执行接口 | 与接口表「状态变化」列一致 |
| --- | --- | --- | --- |
| 未封锁 → 已封锁 | 剪枝界面确认提交，级联范围写入封锁集合 | API-PRUNE-001 | 一致 |
| 已封锁 → 已封锁（改归属） | 提交范围内包含已封锁节点，归属改为该次操作 | API-PRUNE-001 | 一致 |
| 已封锁 → 未封锁 | 撤销该条目归属的操作 | API-PRUNE-002 | 一致 |
| 生效中 → 已撤销 | 撤销该操作 | API-PRUNE-002 | 一致 |
| 无标记 → 已封锁标注 | 提交剪枝写入标记；或一致性校验发现标记缺失并按封锁集合重建 | API-PRUNE-001、API-PRUNE-005 | 一致 |
| 已封锁标注 → 无标记 | 撤销清除标记；或一致性校验发现多余标记并按封锁集合重建 | API-PRUNE-002、API-PRUNE-005 | 一致 |
| 封锁状态无转换 | 摘要查询、操作记录查询、封锁状态查询、提交被拒绝 | API-PRUNE-003、API-PRUNE-004、API-M06-002 | 一致（只读，不产生状态变化） |

### 4.2 接口详细定义

#### API-PRUNE-001 剪枝提交 SubmitPrune()

职责：
受理一次剪枝提交，按节点关系图确定完整级联范围，写入封锁集合、登记一次操作记录并写入节点封锁标记。

输入：
- 参数输入：节点标识集合；操作类型（玩家选择／大关回退预设）；操作类型为大关回退预设时携带目标大关标识
- 状态输入：CLS-PRUNE-001 当前封锁状态；CLS-PRUNE-002 已有操作记录；局内阶段取值（经 `API-M10-001`）
- 数据输入：节点关系图；节点类型与节点配置中的主干层级字段
- 外部事件输入：无

读取：
- CLS-PRUNE-001、CLS-PRUNE-002
- 节点解锁状态（经 `API-M06-001 节点与传闻查询`）
- 节点关系图与节点配置（经 `API-M01-003 配置服务.Query`）
- 局内阶段取值（经 `API-M10-001 阶段查询`）

输出：
- 返回值：提交结果，含操作标识、由 CLS-PRUNE-003 构造的受影响范围摘要、写入或改归属的封锁条目数
- 状态输出：CLS-PRUNE-001 按级联范围新增条目或改归属；CLS-PRUNE-002 新增一条生效中记录
- 事件输出：封锁状态变化
- 外部系统调用：线索树写入接口（API-CLUETREE-001）、`API-M01-010 日志服务.Write`、`API-M01-011 事件分发器.Publish`

产生的状态变化：
- 级联范围内的节点在封锁集合中由未封锁转为已封锁；已在封锁集合中的节点归属改为该次操作
- 剪枝操作记录新增一条，操作类型按输入登记，状态为生效中
- 节点封锁标记在级联范围内写入

前置条件：
- 局内阶段取值为局外阶段
- 节点标识集合非空，且其中每个节点都存在、处于已解锁状态（术语表 T-163）
- 操作类型为大关回退预设时，目标大关标识存在且提交范围是该大关的主干节点
- 调用方为剪枝界面，只提交节点标识与操作类型，不提交封锁结果

后置条件：
- 一次提交是原子操作：级联范围全部写入成功，或整次不产生任何写入
- 封锁集合中每个条目的归属操作标识是最后一次覆盖该节点的操作
- 提交不改变节点状态取值、不改变事件解锁状态、不改变大关进度

副作用：
- 发布封锁状态变化；经线索树写入接口提交标记写入项；写运行日志记录操作标识、类型与条目数

异常情况：
- 阶段不是局外阶段时拒绝执行，不产生状态变化
- 节点标识集合为空、含不存在的节点或含未解锁节点时拒绝执行
- 节点关系图缺失或存在无法确定覆盖范围的节点时整次失败，不产生部分写入
- 线索树写入接口校验不通过时整次失败，已写入的封锁条目回退
- 重复提交同一范围时按新的一次操作处理，重叠部分归属该次操作

#### API-PRUNE-002 剪枝撤销 RevokePrune()

职责：
以单次操作为粒度撤销一次剪枝操作，按该操作的覆盖范围批量解除归属它的封锁条目并清除对应节点封锁标记。

输入：
- 参数输入：操作标识
- 状态输入：CLS-PRUNE-002 中该操作的状态与覆盖范围；局内阶段取值（经 `API-M10-001`）
- 数据输入：无
- 外部事件输入：无

读取：
- CLS-PRUNE-001、CLS-PRUNE-002
- 局内阶段取值（经 `API-M10-001`）

输出：
- 返回值：撤销结果，含解除封锁的节点范围与条目数
- 状态输出：该操作由生效中转为已撤销；归属该操作的封锁条目由已封锁转为未封锁
- 事件输出：封锁状态变化
- 外部系统调用：线索树写入接口（API-CLUETREE-001）、`API-M01-010 日志服务.Write`、`API-M01-011 事件分发器.Publish`

产生的状态变化：
- 被撤销操作的状态转为已撤销并登记撤销时间
- 该操作覆盖节点中归属它的封锁条目解除；归属其他操作的条目不变
- 解除范围内的节点封锁标记清除

前置条件：
- 局内阶段取值为局外阶段
- 操作标识在 CLS-PRUNE-002 中存在且状态为生效中

后置条件：
- 撤销只回退封锁状态，不回退任何解锁写入；封锁期间产生的解锁记录保留
- 撤销完成后对封锁标记执行一次一致性校验，以封锁集合为准

副作用：
- 发布封锁状态变化；经线索树写入接口提交标记清除项；写运行日志

异常情况：
- 阶段不是局外阶段时拒绝执行
- 操作标识不存在或状态已是已撤销时拒绝执行，不产生状态变化
- 标记清除写入失败时整次失败，封锁集合的解除回退
- 撤销后仍有其他操作覆盖同一节点时，该节点保持已封锁并保留其后一次操作的归属；重叠归属的取值争议见缺口申报 REQ-PRUNE-02

#### API-PRUNE-003 剪枝影响范围摘要查询 QueryPruneImpact()

职责：
按节点关系图与当前封锁状态给出一次选择的受影响范围摘要，供剪枝界面在提交前呈现。

输入：
- 参数输入：节点标识集合
- 状态输入：CLS-PRUNE-001 当前封锁状态
- 数据输入：节点关系图；节点类型与节点配置中的主干层级字段
- 外部事件输入：无

读取：
- CLS-PRUNE-001
- 节点关系图、节点类型与节点配置（经 `API-M01-003 配置服务.Query`）
- 节点解锁状态（经 `API-M06-001`）

输出：
- 返回值：受影响范围摘要，含受影响节点总数、按节点类型的计数、是否包含主干节点、是否与已有封锁重叠
- 状态输出：无
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 无，只读查询不产生状态变化

前置条件：
- 节点标识集合非空

后置条件：
- 摘要不展开逐节点的完整影响清单；完整影响清单属挂起的预览面板范围，本版本不提供
- 同一选择集合在封锁状态不变时返回同一摘要

副作用：
- 无

异常情况：
- 节点标识不存在或关系图缺失时返回可判定的失败结果，不返回部分摘要
- 节点标识集合为空时返回空摘要，不拒绝查询

#### API-PRUNE-004 剪枝操作记录查询 QueryPruneOperations()

职责：
向剪枝界面提供剪枝操作记录清单，供呈现当前封锁与可撤销项。

输入：
- 参数输入：无
- 状态输入：CLS-PRUNE-002 全部记录
- 数据输入：无
- 外部事件输入：无

读取：
- CLS-PRUNE-001、CLS-PRUNE-002

输出：
- 返回值：操作记录清单，每条含操作标识、操作类型、操作状态、覆盖节点数与提交时间
- 状态输出：无
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 无，只读查询不产生状态变化

前置条件：
- 无

后置条件：
- 已撤销的操作按记录保留在清单中，供撤销历史呈现
- 清单只含操作级信息，不含逐节点内容

副作用：
- 无

异常情况：

- 在局内调用时返回同一清单，返回内容为历史封锁状态的只读快照

#### API-PRUNE-005 封锁标记校验与重建 ReconcileLockMarkers()

职责：
在开新局前校验节点封锁标记与封锁集合的一致性，不一致时按封锁集合重建标记。

输入：
- 参数输入：无
- 状态输入：CLS-PRUNE-001 当前封锁状态
- 数据输入：无
- 外部事件输入：无

读取：
- CLS-PRUNE-001
- 节点封锁标记（经 `API-M06-001 节点与传闻查询` 的节点字段只读取得）

输出：
- 返回值：校验结果，含是否一致与重建的标记条数
- 状态输出：节点封锁标记按封锁集合重建
- 事件输出：无
- 外部系统调用：线索树写入接口（API-CLUETREE-001）、`API-M01-010 日志服务.Write`

产生的状态变化：
- 缺失的封锁标记被补写、多余的封锁标记被清除；封锁集合本身不变

前置条件：
- 由开新局的生成流程在读取封锁状态之前调用

后置条件：
- 校验完成后，节点封锁标记与封锁集合一致；冲突一律以封锁集合为准
- 重建不改变封锁集合、不改变节点状态取值

副作用：
- 经线索树写入接口提交标记写入项；写内容日志记录不一致项数

异常情况：
- 标记不可读时返回失败结果，由生成流程决定是否继续；本系统不自行改写节点数据
- 标记写入失败时保留封锁集合并返回失败原因，封锁状态查询仍以封锁集合为准

#### 5.1.1 级联范围计算 ComputeCascadeScope()

职责：按选择集合在节点关系图上确定可达的下级节点范围，产出该次操作的覆盖节点集合。
输入：参数输入：节点标识集合、操作类型；状态输入：无；数据输入：节点关系图；外部事件输入：无。
读取：节点关系图（经 API-M01-003）。
输出：返回值：CLS-PRUNE-003 级联封锁范围；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：节点关系图已完成加载与校验。
后置条件：范围为完整级联，覆盖选择集合与其全部下级节点；范围以关系图为唯一依据，不引入内容依赖的额外计算。
副作用：无。
异常情况：关系图缺失、选择集合含未登记节点或覆盖范围无法确定时返回失败，不产出部分范围。

#### 5.1.2 提交前置校验 ValidatePruneRequest()

职责：在写入前校验一次提交的可受理性，产出校验结论与拒绝原因。
输入：参数输入：节点标识集合、操作类型、目标大关标识；状态输入：CLS-PRUNE-001、CLS-PRUNE-002、局内阶段取值；数据输入：节点配置中的主干层级字段；外部事件输入：无。
读取：CLS-PRUNE-001、节点解锁状态（经 API-M06-001）、局内阶段取值（经 API-M10-001）、节点配置。
输出：返回值：校验结论与拒绝原因；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：无。
后置条件：只接受处于局外阶段的提交；只接受已解锁且存在的节点；大关回退预设的范围限于目标大关的主干节点。
副作用：无。
异常情况：任一校验项不通过时整次拒绝，返回具体原因，不产生部分封锁。

#### 5.1.3 封锁集合与操作记录写入 ApplyPruneOperation()

职责：按级联范围写入封锁集合条目并登记一条生效中的操作记录。
输入：参数输入：CLS-PRUNE-003、操作类型；状态输入：CLS-PRUNE-001、CLS-PRUNE-002；数据输入：无；外部事件输入：无。
读取：CLS-PRUNE-001、CLS-PRUNE-002。
输出：返回值：操作标识与写入条目数；状态输出：CLS-PRUNE-001 与 CLS-PRUNE-002 更新；事件输出：无（由接口层发布封锁状态变化）；外部系统调用：无。
产生的状态变化：封锁集合新增或改归属条目；操作记录新增一条。
前置条件：提交前置校验通过。
后置条件：条目归属为最后一次覆盖该节点的操作；写入整体成功或整体不生效。
副作用：无。
异常情况：写入过程中失败时回退该次全部条目与记录，保持提交前状态。

#### 5.1.4 封锁标记写入 WriteLockMarkers()

职责：把级联范围内的节点封锁标记写入与清除项经线索树写入接口提交。
输入：参数输入：写入范围、写入方向（写入／清除）；状态输入：无；数据输入：无；外部事件输入：无。
读取：CLS-PRUNE-001（用于确认最终应标记的节点范围）。
输出：返回值：写入结果与条数；状态输出：节点封锁标记更新；事件输出：无；外部系统调用：线索树写入接口（API-CLUETREE-001）。
产生的状态变化：被封锁节点的标记写入，解除封锁节点的标记清除。
前置条件：封锁集合的写入已完成。
后置条件：标记范围与封锁集合一致；读取时按标记直接呈现，不重算级联范围。
副作用：无。
异常情况：写入接口校验不通过或部分失败时返回失败，由调用方决定整次回退；本系统不直接改写节点数据。

#### 5.1.5 重叠归属处理 ResolveLockOwnership()

职责：处理跨多次操作的重叠封锁，把重叠条目的归属改为最后一次操作。
输入：参数输入：该次操作的覆盖范围与操作标识；状态输入：CLS-PRUNE-001 现有条目的归属；数据输入：无；外部事件输入：无。
读取：CLS-PRUNE-001、CLS-PRUNE-002。
输出：返回值：改归属的条目数；状态输出：CLS-PRUNE-001 条目归属更新；事件输出：无；外部系统调用：无。
产生的状态变化：重叠条目的归属标识改为该次操作，封锁状态保持已封锁。
前置条件：该次操作的级联范围已确定。
后置条件：同一节点在任一时刻只有一个归属操作，即最后一次覆盖它的操作。
副作用：无。
异常情况：归属操作标识不存在时按该次操作重新归属并写内容日志。

#### 5.1.6 撤销范围回溯 ResolveRevokeScope()

职责：按被撤销操作的覆盖范围确定应解除的封锁条目，产出解除范围。
输入：参数输入：操作标识；状态输入：CLS-PRUNE-001、CLS-PRUNE-002 中该操作的记录；数据输入：无；外部事件输入：无。
读取：CLS-PRUNE-001、CLS-PRUNE-002。
输出：返回值：解除范围与条目数；状态输出：无（解除由接口层执行）；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：操作存在且状态为生效中。
后置条件：只解除归属该操作的条目；归属其他操作的条目保持已封锁。
副作用：无。
异常情况：操作记录缺少覆盖范围时按该操作范围不可解析处理，拒绝撤销并写内容日志。

#### 5.1.7 摘要构造 BuildImpactSummary()

职责：由级联范围与节点类型、主干层级构造受影响范围摘要。

输出：返回值：摘要；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：级联范围可确定。
后置条件：摘要粒度限于节点总数、类型计数、是否含主干节点与是否重叠；不展开逐节点清单。
副作用：无。
异常情况：节点类型或主干层级字段缺失时该项按缺省计数处理并写内容日志。

#### 5.1.8 封锁状态视图重建 BuildLockStateView()

职责：按封锁集合重建只读封锁状态视图，向开新局、池内容集合计算与呈现列表取数提供查询结果。
输入：参数输入：无；状态输入：CLS-PRUNE-001；数据输入：无；外部事件输入：无。
读取：CLS-PRUNE-001。
输出：返回值：CLS-PRUNE-004；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。

后置条件：视图与封锁集合一致，只读且不携带写入口；同一状态下重复查询返回同一内容。

#### 5.1.9 封锁标记一致性校验与重建 ReconcileMarkers()

职责：比对节点封锁标记与封锁集合，产出不一致项并按集合重建标记。
输入：参数输入：无；状态输入：CLS-PRUNE-001；数据输入：无；外部事件输入：无。

### 5.2 功能之间的关系

- 提交前置校验是 API-PRUNE-001 的第一道关口，先于全部写入动作；级联范围计算是提交与摘要共用的基础能力；
- API-PRUNE-001 依次使用提交前置校验、级联范围计算、重叠归属处理、封锁集合与操作记录写入、封锁标记写入；
- API-PRUNE-002 依次使用撤销范围回溯、封锁集合解除、封锁标记写入（清除方向），并在收尾处使用封锁标记一致性校验与重建；
- API-PRUNE-003 使用级联范围计算与摘要构造，只读，不触发任何写入；
- API-PRUNE-004 直接读取封锁集合与操作记录，不经其他内部功能；
- API-PRUNE-005 使用封锁标记一致性校验与重建；
- `API-M06-002 封锁状态查询` 由封锁状态视图重建提供，被开新局生成、池内容集合计算与呈现列表取数调用，只读；
- 封锁集合与操作记录写入是所有状态变化的唯一落点，除 API-PRUNE-001、API-PRUNE-002 之外无其他功能改变跨局数据。

本系统只发布封锁状态变化，不订阅其他事件：跨局数据的装载由存档服务按切面驱动，派生视图在每次查询时重建。节点解锁与传闻解锁由 07-10 线索树核心在结算写入成功后发布，与本系统无关；封锁状态变化只在提交与撤销成功后各发布一次。07-30 概率池联动与 M03 呈现侧不订阅本事件，两者在开新局与呈现取数时经 `API-M06-002 封锁状态查询` 只读取用封锁状态。

        │                        ├─▶ 封锁集合（CLS-PRUNE-001，跨局数据）
        │                        │        │

        │                        │        └─▶ 封锁标记写入项 ──线索树写入接口──▶ 线索树节点数据（07-10 持有）

## 8. 核心流程

### 8.1 剪枝提交

触发：玩家在剪枝界面（M08，ID 待补）选中若干已解锁节点并确认提交。

参与者：剪枝界面、本系统、07-10 线索树核心、M01 的配置服务与事件分发器、M10 的阶段状态机。

调用顺序：
1. 剪枝界面在玩家选择期间调用 API-PRUNE-003，取得受影响范围摘要并呈现，玩家据摘要确认或调整；
2. 剪枝界面调用 API-PRUNE-001，提交节点标识集合与操作类型；
3. 本系统经 `API-M10-001` 校验当前阶段为局外阶段，经 `API-M06-001` 校验提交对象为已解锁节点，经 `API-M01-003` 读取节点关系图与节点配置；
4. 本系统确定完整级联范围，处理重叠归属，写入封锁集合与剪枝操作记录；
5. 本系统经线索树写入接口提交封锁标记写入项；
6. 本系统发布封锁状态变化，并写运行日志。

状态变化：封锁集合新增条目或改归属；剪枝操作记录新增一条生效中记录；节点封锁标记写入。

产生的事件：封锁状态变化。

结束条件：提交是原子操作，级联范围全部写入成功；封锁状态在下一次开新局生效。

### 8.2 撤销剪枝

触发：玩家在剪枝界面选择一次操作并确认撤销。

参与者：剪枝界面、本系统、07-10 线索树核心、M01 的事件分发器与日志服务。

调用顺序：
1. 剪枝界面经 API-PRUNE-004 取得操作记录清单，确定待撤销的操作标识；
2. 剪枝界面调用 API-PRUNE-002，提交操作标识；
3. 本系统经 `API-M10-001` 校验阶段为局外阶段，并校验该操作存在且状态为生效中；
4. 本系统按该操作的覆盖范围确定应解除的条目，解除归属该操作的封锁条目，把操作状态置为已撤销；
5. 本系统经线索树写入接口提交标记清除项，并对封锁标记执行一次一致性校验；
6. 本系统发布封锁状态变化，并写运行日志。

状态变化：操作由生效中转为已撤销；归属该操作的条目由已封锁转为未封锁；对应节点封锁标记清除。

产生的事件：封锁状态变化。

结束条件：该操作覆盖范围内归属它的条目全部解除，且标记与封锁集合一致；解锁写入不回退。

### 8.3 开新局的封锁状态提供

触发：玩家在局外选择开新局，09-20 的生成流程开始执行。

参与者：局生成流程（09-20，经 `API-M02-005`）、本系统、07-10 线索树核心、07-30 概率池联动、M01。

调用顺序：
1. 生成流程调用 API-PRUNE-005，本系统校验节点封锁标记与封锁集合的一致性，不一致时按集合重建（待上游补充：生成侧尚未登记该调用点，见缺口申报 REQ-PRUNE-03）；
2. 生成流程与 07-30 概率池联动经 `API-M06-002 封锁状态查询` 读取封锁状态视图；
3. 07-30 按解锁与封锁状态计算各池的内容集合，生成流程据此生成本局环境；
4. 生成流程不写回封锁状态，本系统在本局内不改变跨局数据。

状态变化：标记按封锁集合重建（仅在需要时）；封锁集合自身不变；本局生成结果按封锁状态取值。

产生的事件：本流程不产生事件；后续由 M02 发布本局生成完成与当前事件池刷新完成。

结束条件：封锁状态视图可读且与封锁集合一致，本局生成结果就绪。

## 9. 异常与边界情况

| 情形 | 判定条件 | 期望结果 |
| --- | --- | --- |
| 局内提交剪枝 | 调用 API-PRUNE-001 时阶段不是局外阶段 | 拒绝执行，不产生状态变化 |
| 局内撤销剪枝 | 调用 API-PRUNE-002 时阶段不是局外阶段 | 拒绝执行，不产生状态变化 |
| 空选择 | 提交的节点标识集合为空 | 拒绝执行并返回原因；摘要查询返回空摘要，不拒绝 |
| 节点不存在 | 提交或摘要中的节点标识未在节点数据中登记 | 提交整次拒绝；摘要返回可判定的失败结果 |
| 选中未解锁节点 | 节点状态不是已解锁 | 整次拒绝，不产生部分封锁 |
| 重复选中已封锁节点 | 节点已在封锁集合中，归属为早先的操作 | 按重叠处理，归属改为该次操作，封锁状态保持已封锁 |
| 大关回退范围不符 | 操作类型为大关回退预设但提交范围不是该大关主干节点 | 拒绝执行并返回原因 |
| 关系图缺失 | 级联范围计算或摘要构造时关系图不可用 | 整次失败，不产生部分写入；写内容日志 |
| 范围不可确定 | 选择集合中存在无法确定覆盖范围的节点 | 整次失败，不产生部分写入 |
| 标记写入失败 | 线索树写入接口校验不通过或部分失败 | 整次失败并回退已写入的封锁条目，保持提交前状态 |
| 重复撤销 | 操作标识不存在或状态已是已撤销 | 拒绝执行，不产生状态变化 |
| 撤销后仍有其他操作覆盖 | 被撤销范围中的节点归属在其后的另一次操作 | 该节点保持已封锁，解除只发生在归属被撤销操作的条目上 |
| 撤销与解锁写入的关系 | 封锁期间该节点产生了新的解锁记录 | 撤销只回退封锁状态，解锁记录保留；界面对此给出说明，本系统不做丢弃 |
| 集合与标记不一致 | 一致性校验发现标记缺失或多出 | 以封锁集合为准重建标记，集合不变；写内容日志 |
| 封锁状态跨局恢复 | 读档或重启后装载跨局切面 | 封锁集合直接可用；操作记录的跨局归属待上游补充（REQ-PRUNE-01）：入档获准时装载后撤销能力随之恢复，未入档时撤销历史不随存档恢复；标记按集合校验 |
| 跨局提交失败 | 封锁状态变更与跨局存档的提交点不一致或提交返回失败 | 待上游补充：提交点与失败处置见缺口申报 REQ-PRUNE-01；本系统不自行读写存档、不自行序列化状态 |
| 查询产生状态变化 | 任何查询接口 | 查询不产生状态变化；封锁状态以只读快照返回，快照不携带写入口 |
| 剪枝影响解锁与结局 | 提交或撤销涉及节点状态、事件解锁状态与大关进度 | 均不改变；剪枝只影响内容可用性 |
| 预览面板与自定义挑战模式 | 调用方请求完整影响清单或挑战配置 | 本版本不提供对应接口，两项挂起 |
| 封锁节点的百科页 | 界面对已封锁节点取内容 | 内容保持可读，本系统不提供条目隐藏或删除能力 |

## 10. 实现约束

| 编号 | 约束 | 依据 |
| --- | --- | --- |
| I-PRUNE-01 | 封锁集合是封锁语义的唯一权威来源；节点封锁标记是派生结果，不一致时以封锁集合为准并按来源重建。 | 设计稿 3.4 |
| I-PRUNE-02 | 封锁集合与节点封锁标记不经结算组件写入；本系统在局外自行维护这两项，结算组件不得写入。 | 架构案 9.5.6、设计稿 3.4、`07-40` 3.3 |
| I-PRUNE-03 | 剪枝只在局外阶段受理；每次受理前经 `API-M10-001` 校验阶段，局内一律拒绝且不产生状态变化。 | 设计稿 3.3、架构案 6.6 |
| I-PRUNE-04 | 级联范围以节点关系图为唯一依据，不引入内容依赖的额外计算；范围为完整级联。 | 设计稿 3.2 |
| I-PRUNE-05 | 解锁记录单调：撤销只解除封锁，不回退或清除任何解锁写入；封锁期间的解锁照常保留。 | 设计稿 3.1、3.3 |
| I-PRUNE-06 | 封锁只影响内容可用性：不改变节点状态取值、不改变事件解锁状态与传闻解锁状态、不改变大关进度。 | 设计稿 3.1、3.2、`07-10` 3.5、`07-40` 3.8 |
| I-PRUNE-07 | 封锁节点的百科页内容必须保持可读；本系统不提供隐藏或删除条目的能力。 | 设计稿 3.5 |
| I-PRUNE-08 | 撤销以单次操作为粒度；跨多次操作的重叠部分归属最后一次操作。 | 设计稿 3.3 |
| I-PRUNE-09 | 封锁集合与操作记录必须可序列化，写入粒度是节点标识条目与单次操作；两类数据是否均入跨局存档待上游补充（REQ-PRUNE-01）；切面由本系统向存档服务声明，不自行读写存档或自行序列化状态。 | 架构案 7.1、3.4 第 6 项 |
| I-PRUNE-10 | 封锁标记的写入与清除经 07-10 的线索树写入接口提交，不直接改节点数据、不持有其可变引用。 | 架构案 8.2 第 1、2 条 |
| I-PRUNE-11 | 查询接口不产生状态变化；封锁状态以只读快照返回，快照不携带写入口，调用方不得缓存为自身数据。 | 架构案 4.2、8.2 第 3 条 |
| I-PRUNE-12 | 跨模块事件一律经 M01 的事件分发器发布与订阅，事件名取自已登记词表，发布方不感知订阅方，订阅方失败不回滚封锁状态。 | 架构案 8.4 第 1 至 4 条 |
| I-PRUNE-13 | 本系统不依赖表现层对象；界面只经 API-PRUNE-001 至 API-PRUNE-004 提交与查询，不得直接改封锁数据。 | 架构案 3.4 第 3、4 项 |
| I-PRUNE-14 | 本系统不自行实现条件判定、效果叠加、物品写入、随机、时间推进、资源加载与日志落盘等公共能力。 | 架构案第 7 章、3.4 第 7 至 10 项 |
| I-PRUNE-15 | 提交是原子操作：任一校验或写入失败时整次不生效，不产生部分封锁与部分标记。 | 设计稿 3.3 |
| I-PRUNE-16 | 本版本不提供预览面板与自定义挑战模式的接口；影响面可见由提交前摘要与树上视觉变化承担。 | 设计稿 3.6、3.7、3.8 |
| I-PRUNE-17 | 封锁状态是开新局生成的输入之一：生成流程只读封锁状态，不得在生成流程内改变封锁状态；同一种子、同一剪枝状态与同一玩家抉择序列产生一致结果。 | 设计稿 3.3、`09-20` §5、`07-30` 3.7 |
