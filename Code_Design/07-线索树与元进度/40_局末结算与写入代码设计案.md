## 1. 系统定义

### 1.1 系统目的

以整局存档快照为唯一输入完成一局游戏的收口：判定本局结局，按结算组件（术语表 T-177）的分工把本局解锁内容与达成记录写入跨局数据，并向局外循环交接。

本系统的对象标识：`SYS-SETTLE-001 局末结算与写入`。

### 1.2 系统职责

- 提供结算组件的定义清单契约：每个组件负责哪类跨局数据、取数来源、写入对象与生效时点；
- 按组件分工从整局存档快照取数，产出写入项并把跨局数据变更写入写入对象的持有者；
- 判定本局结局类型与未通关结局的触发起因（术语表 T-013），产出结局成立的事实；
- 执行节点解锁检查组件（术语表 T-179）：节点解锁（术语表 T-163）、传闻解锁与事件解锁状态（术语表 T-166）的判定与写入发起；
- 在节点解锁写入完成后对被解锁节点的下游中仍处于锁定状态的节点（术语表 T-164）执行一次开放阈值（术语表 T-165）判定；
- 在达成记录与大关进度组件（术语表 T-180）启用后写入达成记录与大关进度；
- 维护本局结算状态与结算执行记录，受理结算提交结果的登记；
- 向结算窗口提供本局写入的变更清单与结局数据。

### 1.3 系统边界

本系统不负责：

- 结算流程的执行编排：快照收集时点、组件调度顺序、提交动作与阶段流转，归 M10 的结算执行器（引用 `API-M10-005 结算执行入口`）；
- 存档文件与三份持久化结构的读写、提交点管理与失败处置，归 01-50 的存档服务（引用 `存档服务（CLS-SAVE-001）`）；
- 结局判定源的事实采集：关底事件（术语表 T-009）是否以额定条件通过由事件结算给出，全队失去行动能力由战斗侧即时判定（见设计稿 3.13 与 `系统设计文档/06-战斗/A0-战斗目标与结果/A0_战斗目标与结果设计.md` 的 3.4）；
- 线索树节点与关系、传闻文本、空行占位（术语表 T-161）数量的持有与推导，归 07-10 线索树核心；
- 剪枝封锁集合（术语表 T-167）与节点封锁标记（术语表 T-168）的写入，归 07-20 剪枝系统，不经结算组件；
- 全局事件池（术语表 T-169）与概率池内容集合的计算，归 07-30 概率池联动；
- 结算窗口的绘制、结局提示文案的投放与局外循环入口的交互，归 M08（引用 `结算窗口（M08，ID 待补）`）；
- 向其他模块索取结算输入：结算的输入只有整局存档快照，本系统不读取其他模块的运行时状态（架构案 3.1 ARC-M06-001）；
- 结算阶段的任何局内状态变更：结算阶段不接受改变局内状态的输入（架构案 6.6 第 2 条）。

### 2.3 数据关系

- CLS-SETTLE-001 逐项产生 CLS-SETTLE-002 中的组件执行结论；
- CLS-SETTLE-002 汇总 CLS-SETTLE-007，CLS-SETTLE-008 按 CLS-SETTLE-002 重建；
- CLS-SETTLE-007 提交给写入对象的持有者：线索树节点与传闻解锁数据、CLS-SETTLE-005、CLS-SETTLE-006；
- CLS-SETTLE-004 被 CLS-SETTLE-005 取值，两者的取值规则见设计稿 3.7；
- CLS-SETTLE-003 由提交结果更新，决定 CLS-SETTLE-001 各项的可执行性；
- CLS-SETTLE-005 与 CLS-SETTLE-006 同剪枝封锁集合互不影响。

## 3. 状态定义

### 3.1 状态

| 状态实体 | 取值 |
| --- | --- |
| CLS-SETTLE-003 本局结算状态 | 未结算／结算中／已结算 |
| CLS-SETTLE-001 组件生效状态 | 已确认／后续版本／待补充 |
| CLS-SETTLE-004 结局类型 | 真结局／隐藏关底事件／未通关结局 |
| CLS-SETTLE-004 触发起因 | 关底未达标／主线中断／全队失去行动能力 |
| CLS-SETTLE-002 执行结论 | 执行中／成功／失败 |

### 3.2 状态转换

```
未结算 → 结算中 → 已结算
              └→ 未结算（提交失败，整笔回滚）
执行中 → 成功／失败（组件执行返回时一次性置值）
```

已结算为本局的终态：已完成结算的本局不重复结算（设计稿 3.4）。组件生效状态由结算组件表的登记内容决定，运行期不转换；执行结论在组件执行返回时一次性置值，执行期间不存在中间取值。

### 3.3 状态转换触发条件

| 转换 | 触发行为或事件 | 执行接口 | 与接口表「状态变化」列一致 |
| --- | --- | --- | --- |
| 未结算 → 结算中 | 结局成立后 M10 的结算执行器首次调用组件执行 | API-SETTLE-001 | 一致 |
| 结算中 → 已结算 | 一次提交成功并由结算执行器登记提交结果 | API-SETTLE-003 | 一致 |
| 结算中 → 未结算 | 一次提交失败并由结算执行器登记提交结果 | API-SETTLE-003 | 一致 |
| 已结算 → 已结算 | 对本局重复调用组件执行 | API-SETTLE-001 | 拒绝执行，状态不变（见第 9 节） |
| 执行中 → 成功／失败 | 组件执行返回时一次性置值 | API-SETTLE-001 | 一致 |
| 组件生效状态 | 由结算组件表登记内容决定 | API-M06-004 | 一致 |

### 4.2 接口详细定义

### API-SETTLE-001 结算组件执行 ExecuteSettlementComponent()

职责：
按指定结算组件的取数来源从整局存档快照提取数据，产出写入项并把该组件负责的跨局数据变更写入写入对象的持有者。

输入：
- 参数输入：组件标识；整局存档快照（SAVE，ID 待补），只读传入
- 状态输入：CLS-SETTLE-003 本局结算状态；CLS-SETTLE-001 中该组件的生效状态
- 数据输入：CLS-SETTLE-001；节点关系表与传闻表
- 外部事件输入：无

读取：
- 整局存档快照（SAVE，ID 待补）中的事件实例结果（EVENT，ID 待补）与节点解锁结果
- CLS-SETTLE-001、CLS-SETTLE-003
- 节点解锁状态与传闻解锁状态（经 API-M06-001）、封锁状态（经 API-M06-002）

输出：
- 返回值：组件执行结果，含组件标识、执行结论、写入项条数与失败原因
- 状态输出：CLS-SETTLE-003 由未结算转为结算中；CLS-SETTLE-002 追加一条执行结论
- 事件输出：无：节点解锁与传闻解锁由线索树核心在写入成功后发布
- 外部系统调用：线索树写入接口（API-CLUETREE-001）、API-M01-010 日志服务.Write

产生的状态变化：
- 本局结算状态由未结算转为结算中
- 写入对象的跨局数据按写入项更新：节点解锁、传闻解锁、事件解锁状态
- 结算执行记录新增一条组件执行结论

前置条件：
- 本局结算状态为未结算
- 组件标识在 CLS-SETTLE-001 中登记且生效状态为已确认
- 传入的整局存档快照是本局的一份完整快照

后置条件：
- 组件执行结论已登记；成功时该组件负责的跨局数据与写入项一致
- 执行失败时不产生部分写入，本局结算状态可回退

副作用：
- 触发线索树核心发布节点解锁与传闻解锁
- 写运行日志，记录结算开始、组件结论与失败原因

异常情况：
- 组件标识未登记或生效状态不是已确认时拒绝执行
- 本局结算状态不是未结算时拒绝执行，不产生重复写入
- 快照缺少该组件所需数据时执行失败并返回失败原因
- 写入对象校验不通过（节点标识不存在）时该写入项失败，按整笔回滚处理
- 一次提交失败时由 API-SETTLE-003 回退本局结算状态

### API-SETTLE-002 结局判定执行 EvaluateOutcome()

职责：
按本局终止情形与整局存档快照中的事件实例结果判定结局类型与未通关结局的触发起因，产出结局成立的事实。

输入：
- 参数输入：整局存档快照（SAVE，ID 待补），只读传入；终止情形，取关底事件结算、主线中断、全队失去行动能力三者之一
- 状态输入：本局已解锁的节点与事件解锁状态（经 API-M06-001 只读查询）
- 数据输入：关底事件配置与节点关系表，经 API-M01-003 配置服务.Query 读取
- 外部事件输入：无

读取：
- 整局存档快照（SAVE，ID 待补）中的事件实例结果（EVENT，ID 待补）
- 节点解锁状态与事件解锁状态（经 API-M06-001）
- 关底事件配置中的额定条件与节点关系

输出：
- 返回值：结局判定结果，含结局类型、触发起因与大关推进标记
- 状态输出：CLS-SETTLE-004 生成并置值
- 事件输出：无：结局成立由 M10 的结算执行器发布（REQ-M06-04），本系统只提供判定取值
- 外部系统调用：无

产生的状态变化：
- 结局判定结果生成，本局进入结算阶段的事实就绪

前置条件：
- 终止情形取自设计稿 3.13 的三种收尾情形之一
- 传入的整局存档快照包含关底事件的结果记录

后置条件：
- 结局类型取真结局、隐藏关底事件、未通关结局三者之一
- 未通关结局的触发起因取关底未达标、主线中断、全队失去行动能力三者之一，且只有一个取值

副作用：
- 判定结果随返回值交回 M10 的结算执行器，由其发布 结局成立 并据阶段状态机切换阶段（REQ-M06-04）

异常情况：
- 快照缺少关底事件结果记录时判定不产出，返回失败原因并写内容日志
- 终止情形取值不在三者之内时拒绝执行
- 对本局重复调用时返回同一判定结果，不重复产生判定

### API-SETTLE-003 结算提交结果登记 RegisterSettlementCommit()

职责：
受理一次结算提交的结果，把本局结算状态置为已结算或回退为未结算。

输入：
- 参数输入：提交结果，取成功或失败；失败原因
- 状态输入：CLS-SETTLE-003 当前取值应为结算中
- 数据输入：无
- 外部事件输入：无

读取：
- CLS-SETTLE-002 本次结算的组件执行结论

输出：
- 返回值：登记后的本局结算状态
- 状态输出：结算中转为已结算，或结算中回退为未结算
- 事件输出：无：结算完成由 M10 的结算执行器在登记为成功后发布（REQ-M06-04），本系统只提供提交结果登记
- 外部系统调用：API-M01-010 日志服务.Write

产生的状态变化：
- 本局结算状态更新；失败时本局保持未结算并保留下一次启动重试的能力

前置条件：
- 本局结算状态为结算中
- 提交结果由 M10 的结算执行器按存档服务的回执给出

后置条件：
- 已结算时本局不重复结算
- 未结算时重试路径可用，重试不产生重复写入

副作用：
- 写运行日志；登记后的本局结算状态是 M10 的结算执行器发布 结算完成 的依据（REQ-M06-04）

异常情况：
- 本局结算状态不是结算中时拒绝登记
- 登记为成功但存在失败的组件执行结论时按失败处理并返回原因
- 重复登记同一提交结果时不改变状态，登记结果不重复交回调用方

### API-SETTLE-004 结算窗口数据查询 QuerySettlementWindow()

职责：
向结算窗口提供本局写入的变更清单、结局数据与本局结算状态，供界面呈现。

输入：
- 参数输入：无
- 状态输入：CLS-SETTLE-003 本局结算状态
- 数据输入：CLS-SETTLE-001 的组件清单，用于清单口径说明
- 外部事件输入：无

读取：
- CLS-SETTLE-002、CLS-SETTLE-008、CLS-SETTLE-004

输出：
- 返回值：结算窗口数据，含本局结算状态、变更清单条目、结局类型与触发起因、是否含大关进度项
- 状态输出：无
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 无，只读查询不产生状态变化

前置条件：
- 无；本局结算状态为未结算时返回未结算标记与空清单

后置条件：
- 返回的清单粒度是节点名与传闻条数，不展开条目内容

副作用：
- 无

异常情况：
- 未结算时返回未结算标记，不返回部分清单
- 在结算阶段之外查询时返回同一结果，不产生状态变化

#### 5.1.2 组件执行 RunSettlementComponent()

职责：按组件的取数来源从快照提取数据，构造写入项并写入写入对象，返回组件执行结果。
输入：参数输入：组件标识、整局存档快照（SAVE，ID 待补）；状态输入：CLS-SETTLE-003；数据输入：CLS-SETTLE-001；外部事件输入：无。
读取：整局存档快照（SAVE，ID 待补）、事件实例结果（EVENT，ID 待补）、CLS-SETTLE-001、CLS-SETTLE-003。
输出：返回值：组件执行结果；状态输出：CLS-SETTLE-002 追加结论；事件输出：无；外部系统调用：线索树写入接口（API-CLUETREE-001）。
产生的状态变化：写入对象的跨局数据按写入项更新；本局结算状态转为结算中。
前置条件：本局结算状态为未结算；组件生效状态为已确认。
后置条件：写入项与该组件负责的跨局数据类别一致，不写入其他组件负责的数据。
副作用：写运行日志。
异常情况：快照缺数据、组件未启用、写入对象校验不通过时返回失败并保持整笔回滚。

#### 5.1.3 事件解锁判定 EvaluateEventUnlock()

职责：在节点解锁写入完成后，对被解锁节点的下游中仍处于锁定状态的节点按开放阈值执行一次判定并产出事件解锁项。
输入：参数输入：无；状态输入：节点解锁状态与封锁状态；数据输入：节点关系表与节点配置中的开放阈值；外部事件输入：无。
读取：CLS-SETTLE-007、节点解锁状态与封锁状态（经 API-M06-001、API-M06-002）、节点关系表。
输出：返回值：事件解锁项；状态输出：事件解锁状态按写入项更新；事件输出：无；外部系统调用：线索树写入接口（API-CLUETREE-001）。
产生的状态变化：满足开放阈值的锁定节点其对应事件解除锁定。
前置条件：本轮节点解锁项已完成写入。
后置条件：同一节点在一次结算内只判定一次；判定只统计处于解锁状态且未被封锁的上游节点。
副作用：无。
异常情况：上游节点数据缺失时该项判定失败并记入组件执行结论。

#### 5.1.4 结局判定 EvaluateOutcomeInternal()

职责：按终止情形与快照中的关底事件结果取值，产出结局类型与触发起因。
输入：参数输入：终止情形、整局存档快照（SAVE，ID 待补）；状态输入：节点解锁状态与事件解锁状态；数据输入：关底事件配置；外部事件输入：无。
读取：事件实例结果（EVENT，ID 待补）、节点解锁状态与事件解锁状态（经 API-M06-001）、关底事件配置。
输出：返回值：结局判定结果；状态输出：CLS-SETTLE-004 置值；事件输出：无（结局成立由 M10 的结算执行器发布，REQ-M06-04）；外部系统调用：无。
产生的状态变化：结局判定结果生成。
前置条件：终止情形取三种收尾情形之一；快照含关底事件结果。
后置条件：结局类型与触发起因各有唯一取值，取值规则见设计稿 3.7 与 3.13。
副作用：无（判定结果随返回值交回 M10 的结算执行器）。
异常情况：快照缺少关底事件结果时判定不产出，返回失败原因。

#### 5.1.5 达成记录与大关进度写入 WriteAchievementAndProgress()

职责：按结局判定结果写入达成记录与大关进度两类跨局数据。
输入：参数输入：无；状态输入：CLS-SETTLE-004；数据输入：CLS-SETTLE-001 中该组件的登记项；外部事件输入：无。
读取：CLS-SETTLE-004、CLS-SETTLE-005、CLS-SETTLE-006。
输出：返回值：写入项；状态输出：CLS-SETTLE-005 与 CLS-SETTLE-006 按写入项更新；事件输出：无；外部系统调用：无。
产生的状态变化：达成记录按结局类型登记次数与最近达成时间；首次达成真结局时大关进度推进。
前置条件：该组件的生效状态为已确认。
后置条件：重复达成同一结局时只更新次数与最近时间，不重复推进大关进度；未通关结局不写入大关进度。
副作用：无。
异常情况：该组件生效状态不是已确认时不参与执行，本版本不产出该类写入项。

#### 5.1.6 结算状态维护 MaintainSettlementState()

职责：按提交结果更新本局结算状态，区分已结算与可重试两种结局。
输入：参数输入：提交结果与失败原因；状态输入：CLS-SETTLE-003、CLS-SETTLE-002；数据输入：无；外部事件输入：无。
读取：CLS-SETTLE-002、CLS-SETTLE-003。
输出：返回值：登记后的本局结算状态；状态输出：CLS-SETTLE-003 更新；事件输出：无（结算完成由 M10 的结算执行器发布，REQ-M06-04）；外部系统调用：无。
产生的状态变化：本局结算状态转为已结算或回退为未结算。
前置条件：本局结算状态为结算中。
后置条件：已结算的本局不重复结算；未结算的本局可重试且重试不产生重复写入。
副作用：写运行日志。
异常情况：状态不是结算中时拒绝登记；重复登记同一结果时不改变状态。

#### 5.1.7 结算窗口数据汇总 BuildSettlementWindowData()

职责：按结算执行记录重建变更清单，并汇总结局数据与本局结算状态。
输入：参数输入：无；状态输入：CLS-SETTLE-003；数据输入：CLS-SETTLE-001；外部事件输入：无。
读取：CLS-SETTLE-002、CLS-SETTLE-007、CLS-SETTLE-004。
输出：返回值：结算窗口数据；状态输出：无；事件输出：无；外部系统调用：无。
产生的状态变化：无。
前置条件：无。
后置条件：清单粒度为节点名与传闻条数；未通关结局的清单不含大关进度项。
副作用：无。
异常情况：本局未结算时返回未结算标记与空清单。

### 5.2 功能之间的关系

- 组件清单提供先于组件执行，为结算执行器提供调度依据；
- 组件执行由 API-SETTLE-001 触发，内部依次使用事件解锁判定；事件解锁判定在节点解锁写入完成后执行一次；
- 组件执行的结论汇入 CLS-SETTLE-002，结算窗口数据汇总按 CLS-SETTLE-002 重建 CLS-SETTLE-008；
- 结局判定由 API-SETTLE-002 触发，排在组件执行之前，其产出被达成记录与大关进度写入取用；
- 达成记录与大关进度写入经组件执行参与，调用位置与其他组件一致，生效状态为后续版本时跳过；
- 结算状态维护由 API-SETTLE-003 触发，在全部启用的组件执行完成并由 M10 完成一次提交之后调用；
- 结算窗口数据汇总由 API-SETTLE-004 触发，只读，不触发任何写入。

## 8. 核心流程

### 8.1 结局成立判定

触发：关底事件结算完成，或本局终止情形成立（主线中断、全队失去行动能力）。

参与者：M10 的事件执行器、本系统、01-50 存档服务。

调用顺序：
1. M10 收集本局终止事实并取得整局存档快照（SAVE，ID 待补）；
2. M10 调用 API-SETTLE-002 结局判定执行，传入快照与终止情形；
3. 本系统按快照中的事件实例结果（EVENT，ID 待补）与关底事件配置的额定条件判定结局类型与触发起因；
4. M10 的结算执行器受理判定结果并发布 结局成立（本系统只提供判定取值，REQ-M06-04）；
5. M10 的阶段状态机切换阶段（API-M10-002 阶段切换执行）。

状态变化：结局判定结果生成；本局进入结算阶段的事实就绪。

产生的事件：结局成立（由 M10 的结算执行器发布，REQ-M06-04）。

结束条件：结局成立由 M10 发布完成，阶段进入结算阶段。

### 8.2 局末结算与跨局写入

触发：结算阶段建立后，M10 的结算执行器调用 API-M10-005 结算执行入口。

参与者：M10、本系统、01-50 存档服务、07-10 线索树核心。

调用顺序：
1. M10 取得整局存档快照，并经 API-M06-004 取得本次版本启用的组件清单与顺序；
2. M10 对每个启用组件调用 API-SETTLE-001，传入组件标识与快照；
3. 本系统按组件登记的取数来源从快照提取数据，构造写入项，经线索树写入接口写入节点解锁与传闻解锁项；
4. 节点解锁写入完成后，本系统对被解锁节点的下游中仍处于锁定状态的节点执行一次事件解锁判定并写入事件解锁项；
5. 本系统返回组件执行结果，结算变更清单按结算执行记录重建；
6. M10 经存档服务以一次提交写入跨局存档（与最近一次自动保存的单局提交是两个独立提交点，架构案 5.3 边界规则第 2 条）；
7. M10 调用 API-SETTLE-003 登记提交结果。

状态变化：本局结算状态由未结算转为结算中再转为已结算；跨局数据按写入项更新。

产生的事件：节点解锁、传闻解锁（由线索树核心发布）、结算完成（登记为成功时由 M10 的结算执行器发布，REQ-M06-04）。

结束条件：本局结算状态为已结算，结算窗口数据可查询。

### 8.3 提交失败回滚与重试

触发：一次提交返回失败回执。

参与者：M10、本系统、01-50 存档服务、07-10 线索树核心。

调用顺序：
1. M10 收到失败回执并调用 API-SETTLE-003，传入失败结果与失败原因；
2. 本系统把本局结算状态回退为未结算，并在结算执行记录中保留失败原因；
3. 存档服务按失败语义保留上一份有效存档（架构案 7.1）；
4. 下一次启动或重试时，重新执行 8.2 的调用顺序。

状态变化：本局结算状态由结算中回退为未结算；跨局数据不产生部分写入。

产生的事件：无。

结束条件：本局结算状态回到未结算，重试路径可用且不产生重复写入。

## 9. 异常与边界情况

| 情形 | 判定条件 | 期望结果 |
| --- | --- | --- |
| 重复结算 | 本局结算状态为已结算时调用 API-SETTLE-001 | 拒绝执行，不产生重复写入 |
| 重复达成同一结局 | 达成记录中该结局类型已有条目 | 只更新次数与最近时间，不重复推进大关进度 |
| 提交失败 | 存档服务回执为失败 | 整笔回滚，本局结算状态回退为未结算，保留重试能力 |
| 组件标识未知 | 组件标识不在 CLS-SETTLE-001 中 | 拒绝执行并返回失败原因 |
| 组件未启用 | 组件生效状态不是已确认 | 该组件不参与本次结算，不产出写入项 |
| 快照数据缺失 | 快照缺少该组件登记项所需的取数来源 | 该组件执行失败，不产生部分写入 |
| 结局判定事实缺失 | 快照中缺少关底事件结果记录 | 判定不产出，返回失败原因并写内容日志 |
| 终止情形非法 | 终止情形不在三种收尾情形之内 | 拒绝执行 |
| 节点标识不存在 | 线索树写入接口校验不通过 | 该写入项失败，按整笔回滚处理 |
| 同一次结算内重复解锁项 | 同一节点出现多条同内容标识的写入项 | 按内容标识去重，不产生重复条目 |
| 场景变化包装事件 | 节点解锁项来源为包装事件且事件配置未声明写入标记 | 不产生写入项 |
| 剪枝封锁数据 | 写入项涉及封锁集合或节点封锁标记 | 不经结算组件，由剪枝系统自行维护 |
| 空行占位数量 | 写入项涉及未解锁传闻的空行占位 | 不作为独立写入项，数量按传闻表登记条数推导 |
| 结算阶段的局内输入 | 结算阶段内收到改变局内状态的请求 | 本系统不接受该输入，不产生状态变化 |
| 结算窗口超前查询 | 本局结算状态为未结算时调用 API-SETTLE-004 | 返回未结算标记与空清单 |

## 10. 实现约束

| 编号 | 约束 | 依据 |
| --- | --- | --- |
| I-SETTLE-01 | 结算的输入只有整局存档快照；本系统不得向任何模块索取结算输入，也不得读取其他模块的运行时状态。 | 架构案 3.1 ARC-M06-001 |
| I-SETTLE-02 | 跨局数据的写入只在局末结算的一次提交内发生；全部写入一次完成，失败整笔回滚，重试不产生重复写入。跨局提交与最近一次自动保存的单局提交不做同一次提交，是两个独立提交点，失败语义各自独立（架构案 5.3 边界规则第 2 条）。 | 设计稿 3.4、架构案 5.3 |
