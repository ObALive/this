# 代码设计案库

本目录是**按游戏系统编制、持续维护**的代码设计案库。代码设计案以 `Design/` 中的系统设计稿为输入，以伪代码设计与实际编码为下游目标。

本库文档的编制规则见 `Rules/06_代码设计案编辑规范.md`；目录组织与命名规则见 `Rules/05_文档库组织规范.md` 第七章。本文件只登记本库的定位、清单与当前状态，不承载规则条款。

## 一、本库承载的内容

本库对 `Design/` 中的每个系统，明确其在程序中的：

职责边界、所需数据、对外接口、输入输出、状态变化、依赖关系、调用关系与实现约束。

目标是让开发者在不重新阅读上层游戏设计案的情况下，可以据此完成该系统的伪代码设计与代码实现。

## 二、与相邻文档的分界

| 文档 | 回答的问题 |
| --- | --- |
| `Design/` 系统设计稿 | 玩家具体会怎么玩，游戏规则是什么 |
| 架构设计案 | 整个程序应该如何组织 |
| **代码设计案（本库）** | 某个游戏系统在程序里必须具备什么，与其他系统如何协作 |
| 伪代码 | 这些程序功能具体按什么步骤执行 |

架构设计案是代码设计案的上级约束，规定整个程序允许怎样组织；本库的每份代码设计案规定某个具体系统在架构允许的范围内需要怎样实现。两者是两个并列维度，不是同一维度的上下层。

六层文档的完整分工见 `Rules/03_文档编辑规范.md` 第七章。

## 三、目录结构

```
Code_Design/
├── README.md                    本文件：库定位、清单与当前状态
├── {域编号}-{域名}/              域目录，编号与命名沿用 Design/ 设计库
│   └── {系统编号}_{系统名}代码设计案.md
└── ...
```

域目录的编号与命名沿用 `Design/` 设计库的定义，不另立一套。域内不设系统子目录：一个系统一份代码设计案。

## 四、当前状态

**本库为空。** `Design/` 中的 32 个系统尚未编制代码设计案，域目录将在首个系统的编制任务开始时建立。

编制顺序由 `Design/` 的系统清单与优先级决定。系统清单见 `Design/00-总览/00_系统全景图.md`。

## 五、索引

各系统的编制状态与文件落点的索引，在首个系统的编制任务开始前确定落点与格式，确定后登记到 `Rules/06_代码设计案编辑规范.md` 第十二章。

在此之前，本库的文件清单以上文第三节的目录结构为准。
