## 1. 系统定义

### 1.1 系统目的

局生成与种子系统承载「种子 → 本局环境」的生成流程，是肉鸽主循环的生成层总负责：一局的世界线（术语表 T-007）起点、区域解锁状态、事件内容范围、事件出现的时间与顺序（以时间段（术语表 T-002）为刻度）、行情，由本系统在开新局时一次生成。

本系统的对象标识：`SYS-GENERATE-001 局生成与种子`。

### 1.2 系统职责

* 受理开新局请求，取得本次生成的输入集合；
* 定义并向调用方交付本局的四项生成产物：本局事件池快照（全局事件池（术语表 T-169）的内容集合）、事件的窗口期与出现顺序、区域解锁状态、行情；
* 管理种子：开新局时生成种子并交付存档侧，读档时按存档中的种子与序列位置恢复；
* 维护生成参数表：声明被种子扰动的项目清单与取值范围；
* 保证生成结果的可复现性：同一种子、同一剪枝状态、同一玩家抉择序列得到一致的生成结果。

### 1.3 系统边界

本系统不负责：

* 事件池的两层维护、刷新、过期剔除与抽取（归 02-30 事件系统与 M02 事件与生成）；
* 事件点位查重与重试（归 M02 事件调度）；
* 地图模板的内容：区域划分、区域连接与事件点位布局由内容侧一次性配置，每局沿用同一份模板；
* 随机源的实现与序列位置管理（归 M01 的随机服务）；
* 线索树（术语表 T-153）解锁状态、剪枝（术语表 T-154）封锁状态与大关进度的计算与持有（分别归 07-10、07-20、07-40）；
* 生成产物的持久化结构（归 01-50 存档与持久化）；
* 行情字段与影响公式的内容设计（当前版本不生成行情内容）。

### 1.5 功能要求

* `F-GENERATE-01` 一局的区域解锁状态、事件内容范围、事件出现的时间与顺序、行情由本系统在开新局时一次生成；生成必在开新局时完成，局内不重算（09-20 §1、§2.1，架构案 5.2.5、9.5.1）。
* `F-GENERATE-02` 本局事件池快照是全局事件池内容集合在开新局的一次快照；其内容集合由 M06 计算，本系统按 `API-M06-003` 的快照交付，不重算集合（架构案 3.1 ARC-M06-001、5.2.5）。
* `F-GENERATE-03` 生成结果必须可复现：同一种子、同一剪枝状态、同一玩家抉择序列得到一致的生成结果；地图模板完全固定，不参与随机生成（09-20 §5、§2.1）。
* 待上游补充：种子可见性（是否对玩家展示种子、是否允许玩家输入种子）与生成参数总表未在上游设计稿写明，承接方为系统设计文档 09-20 §4 与 §5（缺口 `REQ-GENERATE-02`）。

### 2.3 数据关系

生成输入集合按标识引用线索树解锁状态、剪枝封锁集合与大关进度；生成结果包含四项产物，各项按 2.1 的归属表交付对应数据域；种子作为随机服务的序列绑定输入，不参与生成结果的存储结构。

### 2.4 数据生命周期

生成参数表在启动阶段加载并常驻。种子在开新局时产生，随本局存档持久化，本局结束废弃。生成结果只在一次生成请求内存在，交付后由各域持有；生成失败时整次生成作废，不产生交付。

### 2.5 持久化要求

种子随单局存档保存与恢复，切面归属单局存档的世界状态域切面；全局事件池的内容集合、窗口期与出现顺序、区域解锁状态、行情按各自所属域随单局存档保存，读档时按快照恢复、不重新生成、不重新抽取（架构案 5.2.5、9.3）。

### 3.2 状态转换

```
无 → 生成成功
无 → 生成失败 → 无（重试）
```

### 3.3 状态转换触发条件

| 转换 | 触发条件 |
| --- | --- |
| 无 → 生成成功 | 四项产物全部产出且校验通过 |
| 无 → 生成失败 | 输入不可用、参数校验不通过，或生成过程中出现无法继续的条件 |
| 生成失败 → 无 | 调用方按架构案 6.1 的失败处置回到本局装配入口重试 |

### 4.1 接口列表

本系统的对外能力是 M02 模块能力「生成流程调用」（`API-M02-005`）在本系统内的落点——模块级契约与调用者由 `Code_Design/00-架构单元/M02_事件与生成代码设计案.md` 定义，本系统给出系统侧的逐项契约，接口 ID 由本单元分配。被本系统引用的其他单元对象按 ID 引用，不重定义。

| 接口 ID | 接口 | 调用者 | 输入 | 输出 | 状态变化 | 副作用 |
| --- | --- | --- | --- | --- | --- | --- |
| API-GENERATE-001 | 生成本局环境 | M02 事件与生成（开新局流程） | 种子请求、线索树与剪枝与大关状态、地图模板 | 四项产物与生成结果状态 | 生成结果由无转为生成成功或生成失败 | 产生本局生成完成事件；交付四项产物 |
| API-GENERATE-002 | 生成结果查询 | 01-50 存档与持久化、M02 | 无 | 四项产物与种子 | 无 | 无 |

### 4.2 接口详细定义

### API-GENERATE-001 生成本局环境

职责：
受理一次开新局的生成请求，产出本局的四项产物并交付给对应数据域。

输入：
- 参数输入：开新局请求与种子请求方式
- 状态输入：线索树节点解锁状态、剪枝封锁集合、大关进度
- 数据输入：生成参数表、地图模板、概率池成分
- 外部事件输入：无（由开新局流程直接调用）

读取：
- CLS-GENERATE-002 生成参数表
- 线索树节点解锁状态、剪枝封锁集合、大关进度、地图模板、概率池成分

输出：
- 返回值：生成结果状态与四项产物
- 状态输出：生成结果状态变化；四项产物就绪并交付世界状态域的对应持有方
- 事件输出：本局生成完成
- 外部系统调用：API-M01-004 随机服务.Next（申请本次生成使用的确定性序列）

产生的状态变化：
- 生成结果由无转为生成成功或生成失败
- 交付项：全局事件池的内容集合、事件的窗口期与出现顺序、区域解锁状态、行情

前置条件：
- 当前不存在进行中的本局，或上一次本局已完成结算
- 线索树解锁状态与剪枝封锁集合可用
- 生成参数表与地图模板已加载并通过校验

后置条件：
- 生成成功时，四项产物就绪且互相一致：事件池快照中的每个事件标识都能在窗口期与出现顺序表中找到对应项
- 生成失败时，不产生任何交付，世界状态域不被部分写入

副作用：
- 消耗随机服务的确定性序列位置
- 产生本局生成完成事件

异常情况：
- 输入状态不可用时判定为生成失败。
- 生成参数表校验不通过时判定为生成失败。
- 事件池快照为空时判定为生成失败（本局不存在可进入事件）。
- 生成过程中出现点位冲突时不由本接口处理，按调用顺序交由 M02 的事件调度在刷新阶段处理。

### API-GENERATE-002 生成结果查询

职责：
返回本次生成的四项产物与种子，供存档侧采集切面与流程编排读取。

输入：
- 参数输入：无
- 状态输入：生成结果状态
- 数据输入：无
- 外部事件输入：无

读取：
- CLS-GENERATE-003 种子
- CLS-GENERATE-004 生成结果

输出：
- 返回值：四项产物与种子
- 状态输出：无
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 无

前置条件：
- 生成结果状态为生成成功

后置条件：
- 返回内容与已交付产物一致

副作用：
- 无

异常情况：
- 生成未成功时判定为状态不允许，返回失败结果。

### API-GENERATE-003 生成参数查询

职责：
返回生成参数表登记的扰动项目与取值范围，供界面呈现与构建期的内容调试使用。

输入：
- 参数输入：生成参数项标识
- 状态输入：无
- 数据输入：生成参数表
- 外部事件输入：无

读取：
- CLS-GENERATE-002 生成参数表

输出：
- 返回值：参数取值范围与扰动方式
- 状态输出：无
- 事件输出：无
- 外部系统调用：无

产生的状态变化：
- 无

前置条件：
- 参数项标识已在生成参数表中登记

后置条件：
- 返回内容与生成参数表一致

副作用：
- 无

异常情况：
- 参数项标识未登记时判定为非法输入，返回失败结果。

## 5. 内部功能

### 5.1 功能列表

| 功能 | 职责 | 是否对外暴露 |
| --- | --- | --- |
| 输入收集 | 按生成请求收集线索树、剪枝、大关进度、地图模板与概率池成分五类输入 | 否，由 API-GENERATE-001 间接触发 |
| 种子确定 | 开新局时产生种子并绑定随机序列；读档时取得存档中的种子 | 否 |
| 四项产物产出 | 按生成参数表产出事件池快照（按 `API-M06-003` 的快照交付）、窗口期与出现顺序、区域解锁状态、行情 | 否 |
| 产物一致性校验 | 校验四项产物之间以及产物与输入之间的引用完整性 | 否 |
| 产物交付 | 把四项产物交给对应数据域的变更入口 | 否 |

### 5.2 功能之间的关系

输入收集先于种子确定与四项产物产出；种子确定先于四项产物产出中依赖随机序列的部分；产物一致性校验在产出之后、交付之前执行；校验不通过时不进入交付，整次生成判为失败。行情在当前版本只保留交付位，不产出内容。

### 6.4 使用方式

线索树、剪枝、概率池与大关进度四项输入在生成开始时一次性只读取得，生成过程中不重复查询；随机序列在需要随机结果的产出项上按消费点申请；地图模板与生成参数在启动阶段已由配置服务加载，生成时直接读取。本系统不新造事件，只发布 M02 已登记的「本局生成完成」。

### 6.5 依赖方向限制

本系统属 M02 事件与生成，层级 L3。允许依赖：M06 的只读查询与 M01 的基础设施，按 ARC-M02-001 的依赖栏（M01、M06、M09）成立；架构案 3.3 第 5 行的同层只读清单（M02 与 M03、M04、M07、M09）未含 M06，按架构案 8.1 属须登记的例外，登记事项见 02-30 的 `REQ-EVENT-08`；读取固定的地图模板经模块能力 `API-M03-001` 属第 5 项的同层只读（M02 与 M03）。不得依赖 M05 战斗、M08 界面与 M10 流程编排；不得被 M06 反向依赖其生成过程；不得自行创建随机源，也不得直接推进世界时间（架构案 3.4 第 9、10 项）。本系统的对外能力只经 M02 的模块能力 `API-M02-005` 的落点暴露，不另立跨模块入口。

## 8. 核心流程

### 8.1 开新局生成

| 项 | 内容 |
| --- | --- |
| 触发 | 玩家在局外选择开新局 |
| 参与者 | M10 流程编排、M02 事件与生成、本系统、M06 四个单元、M01 配置与随机服务、01-50 存档与持久化 |
| 调用顺序 | 流程编排请求开新局 → M02 调用 API-GENERATE-001 → 本系统经 API-M06-001、002、003、005 取得输入 → 确定种子并申请随机序列（API-M01-004）→ 产出四项产物 → 一致性校验 → 交付世界状态域 → 由事件调度执行一次刷新 → 界面栈切到地图界面 |
| 状态变化 | 生成结果由无转为生成成功；世界状态域由空转为初始状态 |
| 产生的事件 | 本局生成完成、当前事件池刷新完成 |
| 结束条件 | 地图界面可交互且存在可进入的事件 |

### 8.2 读档恢复

| 项 | 内容 |
| --- | --- |
| 触发 | 启动阶段的读档路径，或玩家在局外选择已有存档 |
| 参与者 | 01-50 存档与持久化、本系统、M02、M03、M04 |
| 调用顺序 | 存档服务按域恢复世界状态域 → 从存档取得种子与四项产物快照 → 经 API-GENERATE-002 校验与存档的一致性 → 交付位保持原值，不重新生成、不重新抽取 |
| 状态变化 | 生成结果按快照恢复 |
| 产生的事件 | 无（存档恢复完成由存档侧发布） |
| 结束条件 | 阶段状态机进入地图阶段或战斗阶段 |

## 9. 异常与边界情况

| 情形 | 判定条件 | 期望结果 |
| --- | --- | --- |
| 输入状态不可用 | 线索树、剪枝或大关进度查询返回失败 | 判定为生成失败，不产生交付，流程编排回到本局装配入口重试 |
| 生成参数表校验不通过 | 参数项缺项或取值域非法 | 判定为生成失败，记录内容日志 |
| 事件池快照为空 | 内容集合经剪枝与解锁过滤后无任何事件标识 | 判定为生成失败，本局不进入可玩状态 |
| 产物不一致 | 事件池快照存在无法在窗口期表中定位的事件标识 | 判定为一致性校验不通过，整次生成作废 |
| 重复生成 | 已存在进行中的本局时再次请求生成 | 判定为状态不允许，返回失败结果，当前本局不受影响 |
| 生成失败重试 | 调用方在本局装配入口重试 | 允许重试；重试产生新的种子，不残留上一次的部分结果 |
| 行情不产出 | 当前版本不生成行情内容 | 交付位留空，交易事件刷新按 `20_局生成与种子设计.md` §4.2 读取当时的行情数据 |
| 点位冲突 | 事件刷新时同一点位被占用 | 不由本系统处理，交 M02 事件调度在刷新阶段查重与重试 |

## 10. 实现约束

### 10.1 实现约束

- 生成结果必须可复现：同一种子、同一剪枝状态、同一玩家抉择序列产生一致的生成结果（`20_局生成与种子设计.md` §5）。
- 地图模板完全固定，不参与随机生成；被种子扰动的只有事件与行情两类内容。
- 全部随机结果必须经 M01 的随机服务取得，不得自行创建随机源（架构案 3.4 第 9 项）。
- 生成必在开新局时一次完成；局内不得重算全局事件池的内容集合（架构案 5.2.5）。
- 四项产物交付后由各数据域持有，本系统不留权威副本；查询返回只读结果（架构案 8.2 第 1、3 条）。
- 生成失败不得留下部分写入；世界状态域要么取得完整产物，要么保持不变。
- 行情在当前版本只保留交付位与读取接口，不定义行情字段与影响公式。

### 10.2 实现要求

- **I-GENERATE-01** 生成必在开新局时一次完成，本系统不得在局内重算全局事件池的内容集合或重算窗口期与出现顺序（架构案 5.2.5、9.5.1）。
- **I-GENERATE-02** 全部随机结果必须经 `API-M01-004` 随机服务按消费点申请确定性序列，不得自行创建随机源（架构案 3.4 第 9 项）。
- **I-GENERATE-03** 地图模板完全固定，本系统不得对区域划分、区域连接与事件点位布局做任何扰动（架构案 7.10）。
- **I-GENERATE-04** 生成失败不得留下部分写入；世界状态域要么取得完整产物，要么保持不变（架构案 6.1 阶段 5）。
- **I-GENERATE-05** 四项产物交付后由各数据域持有，本系统不留权威副本；`API-GENERATE-002` 只返回只读结果（架构案 8.2 第 1、3 条）。
- **I-GENERATE-06** 本系统不得推进世界时间、不得自行读写存档、不得自行创建日志与事件通道（架构案 3.4 第 6、9、10 项与 8.4 第 1 条）。
- **I-GENERATE-07** 对外能力经 M02 的模块能力 `API-M02-005` 的落点暴露；本系统不新造跨模块事件，只发布 M02 已登记的「本局生成完成」（约定 §五.2）。
- 待上游补充：生成参数总表与种子可见性未在上游写明，承接方为系统设计文档 09-20 §4、§5（缺口 `REQ-GENERATE-01` 至 `REQ-GENERATE-04`）。
