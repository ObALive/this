## 更新约定：默认不建新表

常规更新只维护已有表中的成员、解释、状态、证据和限制。是否值得单独建表，按“开发中是否会持续增加同级成员”判断；固定两向显示等封闭选项不纳入。

发现新的候选类别时，先记录类别、拟登记成员、扩展价值、已有表为何不足和拟用字段，向用户询问。未获明确同意前不新增分类、不执行建表；其余已有表与文档的更新可以继续。

更新代码说明文档时执行以下流程：

1. 对照源码检查本次变更是否影响现有目录成员、实现状态、限制、协议或位置。
2. 同步修改对应专题说明与 `seed.py`；新增成员归入既有表。需要新增表时按上述规则先询问。
3. 运行 `python .\catalog.py build`、`python .\catalog.py verify`。只修改维护备注时运行 `export` 后再核对。
4. 将数据库、`内容归纳.md`、`catalog.export.json`、涉及的工具/种子及验证记录作为同一次文档更新的一部分；无相关变化时记录“已核对，无需变更”。

`build` 在执行 DDL 前检查内容表是否已存在，默认拒绝创建新类别。用户明确批准后才可使用 `python .\catalog.py build --allow-new-table 已批准的表名`，多个表逐项指定；该参数是执行已取得授权的机制，不代替询问。数据库缺失时默认不自动初始化，应先核对路径并恢复现有库。

## 对开发最有影响的扩展边界

1. **元对象主要靠组件组合扩展。** `MetaObjectDefinition` 和 `MetaObjectInstance` 不为每种角色、物品另建枚举分支；新增组件要有定义工厂，并遵循对象侧/动作侧的挂载隔离。字典按具体类型检索，重复类型会替换旧组件。
2. **新效果是一条跨文件契约。** 构造器给出 `Operation`，同名执行器挂到 Router 同一物体；动作资产还要配置目标与后摇并接到持有槽。已有操作为 `Movement`、`Wait` 与 `FixedDamage`。仅增加动作资产不能产生新效果实现。
3. **固定属性目前不支持只追加枚举。** `CharacterAttribute` 与三个配置字段、构造参数和数组位置对应；归零检测也写死了三个下标。扩展时必须一起调整，并保留既有枚举数字值。
4. **多个量表用途尚不能在同一对象上并存。** 当前一个对象只保留一个 `MetaObjectMeterComponent`。现有用途标识只有 `Health`，生命摘要按名称精确筛选；已接固定伤害，治疗、死亡处理尚未实现。
5. **技术标识可写入不等于业务已识别。** 通用标签可以保存任意键值，但 `FactionTag` 只认可 `Ally/Enemy`。`TerrainId` 可以配置，但当前范围查询不使用它计算阻挡或成本。
6. **旧背包扩展链没有完成。** `Grid/Secure` 工厂构造仍被注释；`EquipmentSlot` 虽能创建，放置判断始终 false，快速放置抛异常。`ContainerType` 目前没有分类交互分支。
7. **请求契约仍是运行时字典。** `cause` 只有常量声明；其他多个身份字段仅随日志保留，没有参与路由校验。值类型、写入者、读取者和存在条件均已逐字段登记。

## 数据模型

每张内容表都有稳定 `id`、`code_name`、中文名称、职责、实现状态、扩展步骤、限制、源码证据、参考文档、核对提交、核对时间，以及 `notes/owner/priority` 维护字段。`priority` 为 0–3，数值越小优先级越高，默认 2。

各类另有专用列，例如组件的 `definition_type/dependencies`、请求字段的 `value_type/producer/consumer/requirement`、枚举的 `numeric_value`、操作的 `builder_id/executor_id/target_kind_id`。因此并非将所有内容塞入一张通用条目表。

- `evidence_json` 是证据数组，每条包含工程相对路径、行号、定位表达式、源码行和文件 SHA-256。它不是泛化的业务内容存储。
- 操作表通过外键关联构造器、执行器、目标类型；标记取值通过外键关联标记键。
- `_分类` 管理各表的纳入规则与扩展方式；`_构建信息` 保存基线；`_源码快照` 用于发现源码增加、删除或修改。
- `v_全部条目` 用于跨表搜索；`v_待办` 汇总未完成声明；`v_操作链` 联结操作的实现链。

### 标记键与标记取值

对象上的标记实际保存为 `Dictionary<string,string>`。**键是分类维度的名称，值是对象在该维度上的具体值**。例如 `SetTag("Faction", "Ally")` 中，`Faction` 是键，`Ally` 是值；另一个对象可以保存同一键而使用 `Enemy` 值。

| 目录表 | 当前记录 | 管理作用 |
| --- | --- | --- |
| 标记键 | Faction | 记录标记的名称、含义、当前值域和读取它的代码，便于新增其他标记维度 |
| 标记取值 | Faction.Ally、Faction.Enemy | 记录某个键下已命名的具体值、业务识别入口，通过外键关联所属标记键 |

同一个对象的同名键只保存一个值，重复 SetTag 会替换旧值。`MetaObjectTagComponent` 负责通用存储、查询、增删；`FactionTag` 负责阵营白名单、友敌关系和名称解释。新增一个字符串不会自动产生对应行为。库中两表只是开发规范目录，不会注册游戏运行能力，也不是两套标记系统。当前仅一个键，拆表的直接收益有限；它表达键与多个命名值的一对多关系。

## 查询与维护

在本目录打开 PowerShell，使用 Python 3.11 或以上版本，无额外依赖：

```powershell
python .\catalog.py tables
python .\catalog.py list 元对象组件
python .\catalog.py list 背包槽位 --status 部分实现
python .\catalog.py show 报文操作 Movement
python .\catalog.py verify
```

修改源码条目的维护信息：先保存 UTF-8 文件 `维护.json`，例如：

```json
{"notes":"扩展前先移除三项数组假设", "owner":"程序组", "priority":1}
```

```powershell
python .\catalog.py update 固定属性 ActionPoints --data .\维护.json
python .\catalog.py export
```

登记未来计划：保存 UTF-8 文件 `计划.json`，例如以下是**使用示例，当前库未把它冒充已实现内容**：

```json
{
  "display_name":"规划中的单位目标协议",
  "summary":"用于登记后续目标选取扩展需求",
  "status":"待实现",
  "enum_type":"ActionTargetKind",
  "notes":"需补目标 ID 编码、选择输入、范围查询和执行器解析"
}
```

```powershell
python .\catalog.py add 目标类型 Unit --data .\计划.json
python .\catalog.py export
```

源码变更后，先更新 `seed.py` 中的分类解释和定位规则，再运行：

```powershell
python .\catalog.py build
python .\catalog.py verify
```

`build` 重建源码事实，保留现有 `notes/owner/priority`、创建时间和人工条目；从种子中移除的源码记录保留并标为“已废弃”。人工条目与新源码条目发生同 ID 冲突时会停止，需先合并维护信息，再整理该人工条目。源码条目的事实列由 `seed.py` 维护；CLI 不允许直接改写这些事实，避免下次构建悄悄覆盖。

`verify` 检查数据库完整性、外键、源码快照与每行证据。发现新的组件、枚举、公共请求字段而缺少归纳时会失败。发现机制是当前工程适用的静态文本检查，**不能代替 C# 编译或语义分析，也不会自动推断新类型的职责**。新的字符串标识、普通消息与业务字段仍需人工补入种子。

数据库可直接使用 SQL 维护；连接时执行 `PRAGMA foreign_keys=ON`。修改后记得 `export`。例如：

```sql
SELECT * FROM v_操作链;
SELECT category,code_name,summary FROM v_全部条目 WHERE summary LIKE '%量表%';
SELECT category,code_name,status,notes FROM v_待办 ORDER BY priority,category;
SELECT code_name,numeric_value FROM 固定属性 ORDER BY numeric_value;
```

## 纳入与排除

纳入标准是“存在共同的扩展契约，并可以增加同级实现、协议成员或命名标识”。单例管理器、普通数据载体、固定四槽的四个位置、角色/技能/背包资产实例、数值常量、贴图和动画资源不逐个建表。第三方插件、TMP 示例及 Editor 验证工具不属于自研运行内容目录。普通委托事件不是 Owner 类型化消息，不混入对象消息表。

当前已实现固定伤害构造器和执行器，登记在既有表中；尚无伤害类型枚举，不虚构伤害类型记录。该数据库负责代码扩展目录管理；数据修改不会直接改变游戏行为。迁移与维护规则调整不修改游戏运行源码或场景。
