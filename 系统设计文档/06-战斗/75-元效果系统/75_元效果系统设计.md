## 1 系统定位

元效果系统定义全游戏统一的增益、减益与状态模型，回答"一个效果是什么、从哪里来、叠加时谁生效、什么时候消失"四个问题。它与物品系统的元物品（术语表 T-075）模型思路上一致：元物品把物品的识别信息与可配置属性集中管理，元效果（术语表 T-132）把效果的类型、来源、叠加与生命周期集中管理。

任何系统产生效果时都使用本模型，不再各自定义一套效果表达。元效果的登记清单是 `75_元效果表.csv`，该表是初始素材与迁移来源，运行期配置的权威内容以引擎编辑器内的配置资产为准（S02 裁定，见 `00-总览/03_设计决策记录.md` 决策 93）。

## 3 设计内容

### 3.1 元效果的构成

一个元效果由以下部分构成：

| 构成部分 | 含义 |
| --- | --- |
| 效果标识 | 判定同名效果的依据；两个效果标识相同的元效果视为同名 |
| 效果类别 | 表达效果作用于什么，例如属性修正、状态附加、持续影响与结算修正 |
| 作用对象 | 效果生效的目标，可以是装备者本人、全队、单个目标单位或者落点范围 |
| 生效方式 | 效果如何附加到角色身上并参与结算 |
| 叠加规则 | 多个元效果同时存在时如何合并 |
| 效果强度方向（术语表 T-112） | 数值大小与效果强弱的关系方向，由效果自身配置 |
| 来源组件 | 提供该效果的组件，例如装备组件、遗物效果组件、道具效果组件或技能配置 |
| 生命周期 | 效果的持续时间与移除条件 |

### 3.2 效果来源

道具、装备、遗物与技能产生的全部增益、状态与持续影响都以元效果表达。四类来源的区别只在于提供效果的组件不同，效果本身的表达与结算完全一致。

技能是唯一以配置而非物品组件（术语表 T-077）提供效果的来源。技能在释放时按其配置生成对应的元效果并附加到目标身上，其余过程与物品来源一致。

### 3.3 叠加与同名判定

多个元效果同时作用于同一单位时，按以下顺序处理：

1. 先按效果标识判定同名。效果标识相同的元效果互为同名效果；
2. 同名效果之间比较强度：先按各自的强度方向把数值解释为强度，再选出强度最高的一条生效，其余条目保留在角色状态中但不重复结算；
3. 不同名效果正常叠加，叠加层数由配置控制，系统层不设叠加上限；
4. 有效项被移除后立即重新计算，从剩余条目中启用强度最高的一条。

强度方向是每个元效果自身的配置项，数值越高效果越强或者数值越低效果越强两者都支持。缺少方向配置的效果按数值越高效果越强处理。该规则使增益型与减益型效果共用同一套判定逻辑，诅咒与普通负面词条因此不需要单独的判定通道。

### 3.4 结算分层

不同类别与不同来源的元效果在结算时按层处理，层的顺序与同层内的确定性顺序登记在元效果表（术语表 T-133）与战斗总览的伤害与结算条款中。前一层的结果确定后才进入下一层判定，被上层判定为无效或已被消耗的效果不再进入下层。

### 3.5 生命周期

元效果的生命周期由来源配置决定：随装备启停的效果在装备卸下时移除，限时效果在持续时间结束时移除，投掷（术语表 T-146）类效果在动作结算结束时一次性移除，技能继承效果（术语表 T-145）与技能配置同生命周期并在基础技能（术语表 T-144）被替换时同步重算。

需要在战斗外继续生效的效果在角色状态中保留，并随角色一起写入存档。

### 3.6 扩展方式

元效果表是元效果登记的初始素材与迁移来源，运行期配置的权威内容以引擎编辑器内的配置资产为准；新增元效果类型时在引擎内资产登记后回写表内记录作为对照素材，再在提供该效果的来源系统文档中补充规则。表中标记为待补充的记录不代表已经确认的设计。

## 4 交互逻辑与细节注意点

- 元效果是效果的唯一表达方式，任何系统不得另立效果表达机制；
- 同名效果只生效强度最高的一条，其余条目保留但不结算；
- 诅咒与负面词条语义一致，不做区分处理；
- 效果的作用对象可以是个体也可以是全队，全队效果随来源装备的启停同步生效与移除；
- 元效果的登记与维护由本系统负责，效果的数值由数值侧给出。
