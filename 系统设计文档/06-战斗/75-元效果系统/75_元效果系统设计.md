## 1 系统定位

元效果系统定义全游戏统一的增益、减益与状态模型，回答"一个效果是什么、从哪里来、叠加时谁生效、什么时候消失"四个问题。元效果是组件之间的管理调度约定：它把来源提供的一组组件封装为一个独立效果内容的外壳，效果的计算规则由被封装的组件决定。这里的统一指效果表达载体的统一：全部来源的效果都以元效果这一种模型登记、施加、移除与求值。它与物品系统的元物品（术语表 T-075）模型思路上一致：元物品把物品的识别信息与可配置属性集中管理，元效果（术语表 T-132）把效果的类型、来源、叠加与生命周期集中管理。

任何系统产生效果时都使用本模型。元效果的登记清单是 `75_元效果表.csv`，该表是初始素材与迁移来源，运行期配置的权威内容以引擎编辑器内的配置资产为准。

## 3 设计内容

### 3.1 元效果的构成

一个元效果由以下部分构成：

| 构成部分 | 含义 |
| --- | --- |
| 效果标识 | 元效果在元效果表中的唯一识别标识 |
| 效果类别 | 表达效果作用于什么，例如属性修正、状态附加、持续影响与结算修正 |
| 作用对象 | 效果生效的目标，可以是装备者本人、全队、单个目标单位或者落点范围 |
| 生效方式 | 效果如何附加到角色身上并参与结算 |
| 叠加规则 | 多个元效果同时存在时如何合并，逐条登记，不同效果可以采用不同的规则 |
| 来源组件 | 提供该效果的组件，例如装备组件、遗物效果组件、道具效果组件或技能配置 |
| 生命周期 | 效果的持续时间与移除条件 |

### 3.2 效果来源

道具、装备、遗物与技能产生的全部增益、状态与持续影响都以元效果表达。四类来源的区别只在于提供效果的组件不同，效果本身的表达与结算完全一致。

技能是唯一以配置而非物品组件（术语表 T-077）提供效果的来源。技能在释放时按其配置生成对应的元效果并附加到目标身上，其余过程与物品来源一致。

### 3.3 组件外壳与管理调度

元效果是组件之间的管理调度约定：它把来源提供的一组组件封装为一个独立效果内容的外壳，登记该外壳的效果标识、来源组件与生命周期，并在来源启停时施加或移除该外壳。效果的计算规则由被封装的组件决定。

### 3.4 结算分层

不同类别与不同来源的元效果在结算时按层处理，层的顺序与同层内的确定性顺序登记在元效果表（术语表 T-133）与战斗总览的伤害与结算条款中。前一层的结果确定后才进入下一层判定，上层判定为无效或已消耗的效果止于该层。

### 3.5 生命周期

元效果的生命周期由来源配置决定：随装备启停的效果在装备卸下时移除，限时效果在持续时间结束时移除，投掷（术语表 T-146）类效果在动作结算结束时一次性移除，技能继承效果（术语表 T-145）与技能配置同生命周期并在基础技能（术语表 T-144）被替换时同步重算。

需要在战斗外继续生效的效果在角色状态中保留，并随角色一起写入存档。

### 3.6 扩展方式

元效果表是元效果登记的初始素材与迁移来源，运行期配置的权威内容以引擎编辑器内的配置资产为准；新增元效果类型时在引擎内资产登记后回写表内记录作为对照素材，再在提供该效果的来源系统文档中补充规则。表中标记为待补充的记录不代表已经确认的设计。

## 4 交互逻辑与细节注意点

- 元效果是效果表达载体的唯一形态，任何系统不得另立效果表达机制；
- 效果的作用对象可以是个体也可以是全队，全队效果随来源装备的启停同步生效与移除；
- 元效果的登记与维护由本系统负责，效果的数值由数值侧给出。
