## 1 系统定位

战斗行为系统规范化管理战斗过程中玩家可控角色可以执行的全部行为，回答"玩家在战斗中能做什么、每个行为消耗什么、产生什么、如何存档"四个问题。

本系统维护战斗行为（术语表 T-135）的权威清单 `85_战斗行为表.csv`，并定义行为的通用契约。行为的具体效果由发起它的系统给出：技能效果归技能系统，搜刮与容器交互归战场与战棋规则，撤退的结果归战斗目标与结果，撤退引发的窗口期延长与周边事件锁定归事件配置声明。

## 3 设计内容

### 3.1 行为清单与扩展

Demo 阶段的战斗行为全集登记在 `85_战斗行为表.csv`，包含技能释放、移动、容器搜刮、场景交互、撤退与防御待机六项。潜行、喊话与投降一类行为不进入 Demo，需要时按本表的扩展契约补入。

表中保留一条待补充记录声明扩展契约。新增战斗行为时必须同时完成三件事：

1. 在战斗行为表内登记全部契约字段；
2. 在 `06-战斗/10-战斗总览/10_战斗总览设计.md` 的战斗行为条款中登记该行为的类别与职责；
3. 在发起该行为的子系统文档中补充其效果与时间口径。

### 3.2 行为契约字段

战斗行为表为每个行为登记以下字段，字段含义与取值规则以本表与战斗总览正文共同定义：

| 字段 | 含义 |
| --- | --- |
| 行为ID | 行为标识，格式为 `BHV-{类别}-{序号}` |
| 行为名称 | 界面与文档中使用的行为名 |
| 行动机会消耗 | 该行为是否占用行动机会，以及能否与其他行为合并 |
| 入口方式 | 玩家如何发起该行为 |
| 行动槽字母 | 该行为完成后向行动槽（术语表 T-139）追加的字母 |
| 目标选择 | 该行为需要选择的目标类型 |
| 时间与后摇（术语表 T-119） | 该行为的时间轴成本来源 |
| 成功结果 | 条件满足时产生的状态变化 |
| 失败与阻止 | 条件不满足时的处理与界面反馈 |
| 与其他行为的关系 | 与该行为互斥、可合并或共享规则的其他行为 |
| 存档要求 | 该行为需要保存的状态 |
| Demo 状态 | 已确认或待补充 |
| 扩展说明 | 配置与实现的注意事项 |
| 依据 | 该行为的裁定来源 |

### 3.3 行动机会与行为

一次行动机会是玩家在时间轴上获得的一次操作窗口。一次行动机会内只能执行一项行为，行为之间不能合并：

- 技能释放独立占用一次行动机会，一次行动机会内只能执行一项技能；
- 移动独立占用一次行动机会；
- 布置阶段的站位调整与战斗中的移动连续衔接并共用同一套行动机会，调整占用该单位一次行动机会并参与时间轴计算；
- 容器搜刮、场景交互与撤退各自独立占用一次行动机会；
- 防御待机在没有其他可用操作时作为兜底选项独立占用一次行动机会。

行为与物品操作总表的关系是明确的：物品操作总表登记界面交互操作，战斗行为表登记战斗过程中玩家可控角色的行为。同一次操作同时被两张表覆盖时，以战斗行为表为准。

### 3.4 行为的提交与取消

全部战斗行为在玩家确认时才提交。确认前可以自由查看、切换目标与更换选择；取消不产生任何状态变化，也不消耗行动机会、行动槽字母与道具。

已经确认的行为立即提交，并在下一次自动保存（术语表 T-016）节点写入存档。读档后恢复到最近一次行动机会开始的时刻，该次行动机会中尚未确认的选择不生效。

### 3.5 行为的失败处理

行为的前置条件不满足时，界面即时给出具体原因，例如超出射程、被地形阻挡、目标不合法、库存中没有可用物品或者撤退条件不满足。操作不提交，行动机会与行动槽都不产生变化。

行动槽内没有任何可用操作时，界面提供防御待机与撤退作为兜底选项，保证任何局面都能推进。

## 4 交互逻辑与细节注意点

- 战斗行为表是战斗行为的权威清单，物品操作总表不管理战斗内容；
- 新增行为必须同时更新表、战斗总览正文与发起系统文档三处；
- 行为的字母追加遵循行动槽与连携系统的统一规则，移动、布置阶段的站位调整、搜刮与场景交互追加字母 M；
- 行为的后摇由行为自身或发起它的技能配置提供，属性补正由行动速度提供；
- 行为的目标选择与射程判定归战场与战棋规则；
- 我方单位的初始站位由事件配置或战斗配置声明，布置阶段的站位调整与战斗中的移动共用同一套行动机会（R001 裁定 SMP-GAP-005、CBT2-GAP-008）。
