# 一、两个概念

## 1. 交互原语

**交互原语**是同一类交互共用的、与具体业务含义无关的表现与时序约定。它回答「这个控件长什么样、什么时候算被激活」，不回答「激活之后做什么」。

一份交互原语必须包含四项：

| # | 项 | 内容 |
| --- | --- | --- |
| 1 | 状态集 | 该控件存在哪些视觉与听觉状态。标准状态集为常态、悬停、按下、焦点、禁用五项；控件类别可以裁剪，裁剪必须逐类声明 |
| 2 | 激活时机 | 哪一个输入时刻判定为「激活」：按下、抬起、长按、双击，以及激活是否允许在抬起前取消 |
| 3 | 反馈通道与参数 | 每个状态切换时的反馈形式与时长。反馈形式取换图、动效、音效、触感四类通道 |
| 4 | 输入源一致性 | 鼠标、键盘、手柄三类输入源映射到同一个状态机的对应关系，以及三类输入源之间的互斥规则 |

交互原语按**控件类别**各写一份，例如按钮一份、列表项一份、格子一份、容器格一份。同一控件类别在全库共用一份原语。

## 2. 交互语义

**交互语义**是单条交互的业务含义。它回答「这一次激活在什么条件下意味着什么」，由三部分构成：

| # | 项 | 内容 |
| --- | --- | --- |
| 1 | 意图 | 该交互接收的输入语义类别。意图是设备无关的语义动作，不是物理按键 |
| 2 | 生效上下文 | 该意图在哪个界面、哪个阶段、哪个前提成立时才指向本条语义 |
| 3 | 命令与提交 | 该意图转成的目标命令、受理方接口、提交粒度，以及被拒绝时的反馈 |

交互语义按**逐条交互**各写一份，例如「返回按钮在界面栈非空时关闭栈顶」一份、「确认按钮在设置界面保存设置」一份。

## 3. 术语对照

| 中文 | 英文 | 定义要点 |
| --- | --- | --- |
| 交互原语 | interaction primitive | 同类交互共用的状态集与时序约定，与业务含义无关 |
| 交互语义 | interaction semantics | 单条交互的业务含义，由意图、生效上下文、命令与提交构成 |
| 控件状态 | control state / widget state | 原语的第一项，含常态、悬停、按下、焦点、禁用 |
| 激活时机 | activation timing | 原语的第二项，按下激活或抬起激活 |
| 绑定 | binding | 原语的激活事件指向哪一条语义的对应规则 |
| 修饰键 | modifier key | 不单独触发、只改变同一次控件激活指向哪条语义的输入，例如 Shift、Ctrl、Alt |
| 快捷键 | shortcut | 不依附任何控件、单独触发一条命令的输入，例如 Esc、功能键 |

## 4. 一句话分界

**原语管「怎么表现」，语义管「意味着什么」。** 一段内容只要能同时套用在两个业务含义完全不同的交互上，它属于原语；只要一改业务含义就要跟着改，它属于语义。

# 二、分层与作用域

## 1. 五层链路

交互从设备到状态变化经过五层，每层只把上一层的输出当作输入：

| 层 | 内容 | 输入 → 输出 | 归口 |
| --- | --- | --- | --- |
| L0 | 设备到动作 | 物理设备 → 动作 | 引擎的输入方案；本轮项目的设备到动作映射由引擎承担，见 `架构设计文档/架构设计案.md` §7.4 |
| L1 | 动作到意图 | 动作 → 语义意图 | M01 的输入服务；映射以 `CLS-M01-008` 输入映射表承载，分发以 `CLS-M01-009` 意图订阅表承载 |
| L2 | 交互原语 | 意图 → 激活事件 | 见第五章的落点对照 |
| L3 | 交互语义 | 意图与上下文 → 命令 | 界面侧经 `API-M08-105` 绑定上下文、经 `API-M08-003` 提交，落点为各持有方接口 |
| 桥 | 绑定 | 激活事件 → 该控件的哪一条语义 | 见第三章第 5 节 |

L1 与 L2 之间不得交换职责：**动作到意图的归一必须发生在 L1**，界面侧不得读取物理按键或修饰键的按下状态。

## 2. 三种作用域

交互按作用范围分三类，三类共用 L1 与 L3，差别在 L2 是否存在：

| 作用域 | 例子 | 是否存在 L2 状态机 | 反馈形式 |
| --- | --- | --- | --- |
| 控件级 | 按钮、列表项、格子、容器格 | 存在，状态集完整 | 换图、动效、音效、触感 |
| 界面级 | 返回、取消、切换焦点、翻页、滚动 | 不存在控件实体 | 快捷键提示文字、菜单项可用性置灰、界面转场 |
| 全局级 | 打开设置、退出游戏 | 不存在控件实体 | 同界面级 |

**禁止为界面级与全局级交互设定控件状态集。** 快捷键没有悬停态、没有按下态，把它按控件级填写会得出「每个快捷键需要一个纹理」的错误结论。

## 3. 分层与作用域的对应

| 作用域 | 是否经过 L2 | 归一位置 |
| --- | --- | --- |
| 控件级 | 经过 | 控件激活 ＋ 修饰键状态在 L1 归一到意图 |
| 界面级 | 不经过 | 输入在 L1 直接归一到一个界面级意图 |
| 全局级 | 不经过 | 输入在 L1 直接归一到一个全局意图 |

# 三、设计边界

## 1. 必须分开设计

| 项 | 内容 |
| --- | --- |
| 约束 | 交互原语与交互语义必须分开设计、分开成文，不得合并成一段描述 |
| 适用面 | 全部界面与交互规格的编写与评审 |
| 判据 | 任取一条交互，其原语部分可以原样搬到另一条业务含义完全不同的交互上而不改写；其语义部分脱离原语仍可读懂「在什么条件下提交什么命令」 |
| 越界处置 | 两者写在一段时按下表拆分：凡是能跨交互复用的句子归原语，凡是一改业务含义就要改的句子归语义 |

分开设计的五条判据：

| # | 判据 | 合并设计的后果 |
| --- | --- | --- |
| 1 | 变更频率不同：原语随平台、引擎与美术规范变化，语义随玩法内容变化 | 改一次手感要触碰全部交互条目 |
| 2 | 复用基数不同：原语按控件类别各一份，语义按逐条交互各一份 | 实现量变成控件类别数 × 交互条数 |
| 3 | 责任方不同：原语归表现侧，语义归界面业务与数据持有方 | 评审时找不到责任人 |
| 4 | 验收方式不同：原语按全局一致性验收，语义按逐条业务验收 | 一致性无法验收，只能逐条人工比对 |
| 5 | 失败模式不同：原语出错表现为全局手感不一致，语义出错表现为提交了错误的命令 | 两类缺陷混在同一份条目里，回归范围不可界定 |

## 2. 允许写进交互原语的内容

| 项 | 内容 |
| --- | --- |
| 约束 | 交互原语只写第一章第 1 节的四项：状态集、激活时机、反馈通道与参数、输入源一致性 |
| 适用面 | 按控件类别编写的原语条目 |
| 判据 | 条目内不出现任何业务对象标识、数据标识或接口标识 |
| 越界处置 | 出现业务标识时，把该标识移入交互语义条目，原语内只保留状态与时刻 |

## 3. 允许写进交互语义的内容

| 项 | 内容 |
| --- | --- |
| 约束 | 交互语义只写第一章第 2 节的三项：意图、生效上下文、命令与提交 |
| 适用面 | 按逐条交互编写的语义条目 |
| 判据 | 条目内不出现状态集、反馈参数与输入源映射的重复定义，只引用原语名 |
| 越界处置 | 出现状态或反馈参数时，把该内容上移到对应控件类别的原语条目，语义条目改为引用 |

## 4. 禁止事项

| # | 禁止 | 理由 |
| --- | --- | --- |
| 1 | 禁止把业务含义写进交互原语 | 原语一旦绑定业务，就无法跨交互复用，退化为逐条实现 |
| 2 | 禁止把状态集与反馈参数写进逐条交互语义 | 同一条反馈会被重复定义多次，一致性无法验收 |
| 3 | 禁止在界面层读取物理按键、修饰键或设备状态 | 违反 `架构设计文档/架构设计案.md` §8.6 第 12 条与 `I-M01-10`；界面只接收语义意图 |
| 4 | 禁止为界面级与全局级交互设定控件状态集 | 快捷键不存在悬停、按下与禁用以外的控件状态 |
| 5 | 禁止同一份内容在原语与语义两处各写一份 | 违反《规范目录维护规范》§一.3 的唯一事实来源要求 |
| 6 | 禁止用「按下时改变纹理、松开时触发逻辑」这类时序描述代替语义描述 | 时序属原语，语义必须写明意图、上下文与命令三要素 |

## 5. 绑定契约

| 项 | 内容 |
| --- | --- |
| 约束 | 原语与语义之间必须有一条显式绑定：写明「哪一类激活事件、在什么条件下，指向哪一条语义」 |
| 适用面 | 每一条控件级交互 |
| 判据 | 绑定条目能回答三问：激活事件来自哪份原语、生效上下文是什么、目标语义是哪一条 |
| 越界处置 | 缺少绑定时，界面会出现「反馈已播放但未提交」或「同一次激活提交两次」两类缺陷，必须在编写阶段补齐，不得留到实现阶段 |

# 四、修饰键与快捷键

## 1. 两者的区别

|  | 快捷键 | 修饰键 |
| --- | --- | --- |
| 学名 | 快捷键绑定 | 修饰键限定的激活 |
| 是否依附控件 | 不依附，单独触发 | 依附在一次控件激活上 |
| 作用域 | 界面级或全局级 | 控件级 |
| 归一位置 | 输入在 L1 直接归一到界面级意图 | 控件激活与修饰状态在 L1 归一到该控件的另一条意图 |

## 2. 修饰键的写法

| 项 | 内容 |
| --- | --- |
| 约束 | 带修饰键的输入必须在 L1 归一为独立意图类别，界面按意图类别选语义 |
| 适用面 | 全部使用修饰键的交互，例如「修饰键 ＋ 左键单击」 |
| 判据 | 界面侧不出现修饰键状态查询；`CLS-M01-008` 输入映射表内该类输入与不带修饰的同类输入登记为互不相同的意图类别 |
| 越界处置 | 已在界面层判断修饰键的实现按本节改写，并把该意图类别补入 L1 的输入映射表 |

## 3. 快捷键的写法

| 项 | 内容 |
| --- | --- |
| 约束 | 快捷键必须在 L1 归一为界面级或全局级意图，不得硬编码在界面逻辑内 |
| 适用面 | 全部快捷键交互，例如返回、取消、打开设置 |
| 判据 | 键位取值来自设置数据、可改键；界面侧只见意图类别，不见键位 |
| 越界处置 | 硬编码的键位按本节改为输入映射条目；改键即时生效的口径见 `架构设计文档/架构设计案.md` §7.4 与 §8.1 的登记例外 |

## 4. 隐藏交互的等价路径

| 项 | 内容 |
| --- | --- |
| 约束 | 只能用修饰键或快捷键触发的语义，必须同时存在一条不需要修饰键的等价路径 |
| 适用面 | 全部带修饰键的交互，以及全部快捷键交互 |
| 判据 | 每条语义至少有一条不依赖修饰键的触发方式，且该方式在界面上下文内可发现 |
| 越界处置 | 无等价路径时，该语义在只启用一套输入后端的场合不可达，须在编写阶段补出等价路径或降级为控件级显式操作 |

# 六、逐条交互的编写要求

## 1. 必须回答的五问

每条交互按下列五问逐项作答，缺项即为未写完：

| # | 问题 | 归属 |
| --- | --- | --- |
| 1 | 该控件有哪些状态，各状态怎么表现 | 原语 |
| 2 | 哪一个输入时刻判定为激活，激活是否可取消 | 原语 |
| 3 | 激活时发出哪一类意图，在哪个界面与阶段的上下文内有效 | 绑定 |
| 4 | 该意图转成哪条命令，以什么粒度提交给哪个受理方 | 语义 |
| 5 | 被拒绝或失败时，反馈走哪条通道、回到哪个状态 | 原语与语义交界 |

## 2. 语义条目的字段

| 字段 | 填写要求 |
| --- | --- |
| 作用域 | 控件级、界面级或全局级三者之一 |
| 绑定形式 | 无修饰、修饰键限定、快捷键三者之一 |
| 意图 | 意图类别取自 L1 的登记行 |
| 生效上下文 | 界面、阶段与前提条件 |
| 命令与受理方 | 目标接口 |
| 提交粒度 | 粗粒度、细粒度或复杂交互确认处三者之一 |
| 失败反馈 | 拒绝原因与呈现位置 |
| 原语引用 | 写明所用控件类别的原语条目，不重复其内容 |

## 3. 原语条目的字段

| 字段 | 填写要求 |
| --- | --- |
| 控件类别 | 一份原语对应一个控件类别 |
| 状态集 | 逐状态列出表现与切换条件 |
| 激活时机 | 按下、抬起、长按、双击，以及是否允许取消 |
| 反馈参数 | 通道、时长与曲线 |
| 输入源映射 | 鼠标、键盘、手柄三类输入源到状态的对应关系与互斥规则 |

# 七、验收标准

一条界面与交互规格写完后按下列各项核对，任一项不通过即为未写完：

| # | 检查项 |
| --- | --- |
| 1 | 原语与语义分开成文，未合并在同一段描述内 |
| 2 | 原语条目内不出现业务对象标识、数据标识与接口标识 |
| 3 | 语义条目内不重复定义状态集与反馈参数，只引用原语条目 |
| 4 | 每条交互的有五问答案齐备 |
| 5 | 界面侧不出现物理按键、修饰键与设备状态的读取 |
| 6 | 带修饰键的输入在 `CLS-M01-008` 有独立意图类别登记 |
| 7 | 界面级与全局级交互未被赋予控件状态集 |
| 8 | 每条语义至少有一条不依赖修饰键的等价路径 |
| 9 | 每条交互的 L1、L2、L3 三层落点齐全，或已按缺口流程登记缺失层 |
| 10 | 绑定条目能回答激活事件来源、生效上下文与目标语义三问 |
