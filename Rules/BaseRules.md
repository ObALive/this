# 规范入口

本工作区的全部规范以 `Rules/` 目录为唯一权威落点。本文件是入口指针，只列规范清单与读取顺序，条款内容一律以各规范文件为准。

## 一、接到任务后的读取顺序

1. 读 `Rules/README.md` 规范索引，按四步判定得出本次任务的规范适用清单；
2. 读 `Rules/01_规范总则.md` 与 `Rules/02_任务执行规范.md`，这两条为全部任务的必读项；
3. 任务涉及文档编写或修订时，读 `Rules/03_文档编辑规范.md`；
4. 任务涉及文档与目录的落点、命名或库级台账时，读 `Rules/05_文档库组织规范.md`；
5. 任务涉及 `Code_Design/` 下的代码设计案时，读 `Rules/06_代码设计案编辑规范.md`；
6. 任务涉及 `S_Design/` 下的架构设计案时，读 `Rules/07_架构设计案编辑规范.md`；
7. 任务要写入 `Rules/` 目录时，读 `Rules/04_规范目录维护规范.md`；
8. 判断存疑时取并集，宁可多读，不得凭印象跳过。

## 三、冲突时的执行顺序

```
1. 用户明确指令
2. 任务书授权
3. 规范目录（Rules/）
4. 目录内既有惯例
5. 智能体默认行为
```

任何低优先级规则不得覆盖高优先级要求。判定的附带规则见 `Rules/01_规范总则.md` 第三章。

## 四、本文件的历史

本文件早先名为 `BaseRules.md`，内容把智能体行为规范与文档编辑规范混在一起，且其中的 `Dsh/` 路径前缀与本工作区的实际结构不符。2026-10-05 的任务 05-任务规范整理把原文按适用面拆分重排为 `Rules/README.md` 与 NR-01 至 NR-04 四份规范文件；同日的收口轮次把 `Design/README.md` 与 C 系列任务通则中重复的规则条款一并收编，新增 NR-05。2026-10-06 的任务 06-任务规范增加为 `Code_Design/` 新增 NR-06，并把文档体系由四层扩为六层；同日任务 07-架构设计案规范为 `S_Design/` 新增 NR-07，并把架构设计案与代码设计案的关系定为两个并列维度。

至此本工作区的全部编辑规范以 `Rules/` 目录为唯一权威落点。原文完整留档于 `Output/05-任务规范整理/Rules_BaseRules_v0_20261005.md` 与 `Output/05-任务规范整理-收口/`，废弃登记见 `Rules/README.md` 第六章。本文件保留 `BaseRules.md` 这一路径，使此前任务报告中对它的引用继续有效。
