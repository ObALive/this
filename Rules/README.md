# 一、怎么用这份索引

智能体接到任务的第一个动作是读本文件，然后按四步走：

| 步 | 动作 | 产物 |
| --- | --- | --- |
| 1 | 读任务书，提取任务书里的信号词与产物要求 | 一组信号词 |
| 2 | 按第三节的任务类型表判断本次任务属于哪一类 | 任务类型 |
| 3 | 按任务类型取出需要执行的规范组 | 规范组清单 |
| 4 | 用信号词检索第四节的触发信号表，取出需要追加阅读的规范 | 追加清单 |

两步合并的结果就是**本次任务的规范适用清单**。清单写入任务报告，注明每条规范触发的依据。

四步做完再动手，不得边做边猜。判断结果为空时只说明无需追加阅读，不说明无需读规范：`NR-01`、`NR-02` 是全部任务的必读项。

## 读取顺序

四步中有一步需要先读别的文件，完整顺序如下：

1. 读 `Task/{任务编号}.md`，取信号词；
2. 读本文件，按四步得出适用清单；
3. 读 `Rules/BaseRules.md` 或直接读 `Rules/01_规范总则.md`，再读 `Rules/02_任务执行规范.md`；
4. 按适用清单读其余规范文件；
5. 开始执行。

第 1 步只读任务书，不先读别的文档，原因是信号词要从任务书原文取。第 3 步的两条规范是必读项，任何任务都不跳过。

# 三、任务类型到规范集

命中多类任务时取并集。例如一次任务既编写设计稿又要求把新规范落盘，则 `NR-01` 至 `NR-07` 全部适用。

| --- | --- | --- | --- | --- |

| C 代码改进类 | 任务针对代码、文件拆分、命名空间或序列化改动 | NR-01、NR-02 | NR-03、NR-04、NR-05 | NR-03 与 NR-05 只在其产物包含方案文档或任务书正文时适用 |

| I 架构设计案编制类 | 任务要把系统设计稿转换成架构设计案，或新建、修订 `S_Design/` 下的文档 | NR-01、NR-02、NR-03、NR-05、NR-07 | NR-04、NR-06 | NR-07 给出十章结构、验收标准与架构约束检查；文档落点由 NR-05 第八章约束；与代码设计案的分工见 NR-07 第六章 |
