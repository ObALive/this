## 三、核心链路（系统关系总览）

```
局外（持久）：
  线索树查看 / 剪枝调配 / 概率池 → 规划下一局 → 开新局（局生成与种子：事件池/窗口期/行情生成）
        ▲                                                          │
        │ 结算写入                                                  ▼
        │                                          局内（每局独立世界线）：
        │                                地图界面点选事件点（界面装饰对话，不耗时间）
        │                                                     │
        │                                                     ▼
        │                                事件信息面板 → 日程抉择（进入 / 放弃）
        │                                                     │
        │                                                     ▼ 点击进入按钮（时间推进）
        │                                         事件执行：战斗 / 贸易 / 委托 / 推进性事件
        │                                                     │
        │                                                     ▼
        │                                     收益：钱、货、装备、遗物（资源即战力）
        │                                                     │
        │                                                     ▼
        └────────────────────── 关底事件 → 结局 → 局末结算 ←──┘
```

三条系统耦合主线：

1. **时间链**：时间机制（02-10）→ 日程抉择（02-20）→ 事件执行（02-30）→ 世界线走向（07-40 的结局判定与结算）——"时间即路线"；空间侧由区域与位移（01-10）与探索系统（02-40）提供区域划分、事件点位与跨区域位移成本；
2. **资源链**：经营（05）与战斗（06）共享同一套资源与成长——"资源即战力"；战利品由搜刮战场容器取得，战斗结果决定事件分支与解锁内容；
3. **知识链**：局内解锁内容 → 结算写入线索树（07-40）→ 线索树/剪枝/概率池（术语表 T-172）（07）→ 经局生成（09-20）塑造下一局环境——"知识改变世界"。

- **02 域合并（C-02-bb-01）**：时间、日程、事件（术语表 T-001）、探索四个系统合并为 02-时间与事件域，理由是四者共用事件这一操作对象且相互耦合最密；原 04-探索与事件域的编号 04 停用不复用，指向旧域编号的引用一律改写为新域编号；
- **场景变化包装为事件（C-02-bb-01）**：世界场景的全部变化在程序上包装为事件执行，形式是没有流程、日程中不可见、没有投入产出、玩家不可感知的强制事件（术语表 T-066）；该机制使 02-30 事件系统成为世界状态变化的统一执行入口；
- **时间语义与强制事件（C-02-bb-01-fix，C-02-bb-02 更新）**：时间以时间段（术语表 T-002）为基本刻度、一个时间段的长度固定为 10 分钟；世界时间（术语表 T-015）只在玩家进行有效行为（术语表 T-014）时推进，是角色实力与玩家实力对齐的调整；非战斗事件按事件配置的持续时间一次性推进，战斗事件按战斗轮次推进并在退出时把余量向上对齐；强制事件本质是普通事件经属性组合包装而成，分三类：部分主线事件（日程提示窗口和位置）、场景变化包装事件（术语表 T-065）（不需提示）、由玩家其他游戏行为触发的强制事件（起因经过结果由线索树已解锁内容与事件结果记录承担），错过后果与失败进入属于第三类；
- **数据更新时机通则（C-02-bb-02）**：全局数据在局末更新结算，场景局内数据通常在事件结束后更新结算，玩家数据在事件内实时结算，特例在开发过程中确认；各系统涉及数据更新的部分按此规律标注更新时机；
- **甘特图悬置（C-02-bb-02）**：未来事件以甘特图方式展示、玩家在甘特图界面预编排后续事件参与计划；连同依赖未来事件展示的事件错过提示移入未来开发计划，demo 阶段只做已经历事件；
- **物品与运营闭环（C-05-bb-02）**：所有物品按组件组合功能；队伍已装备容器组成背包空间（术语表 T-086），嵌套容器不计入；交易与委托通过事件调用物品交付（术语表 T-090）和交换，所有物品获取共用自动装载（术语表 T-087）与落地溢出流程；
- **存档完整性（C-05-bb-02）**：当前游戏执行全量保存和全量恢复，当前事件与事件暂存结果、战斗撤退后的窗口期延长与周边事件锁定状态、物品归属与容器嵌套、行情数据、已刷新交易内容和持续委托均属于保存范围；
- **交易与商人闭环（C-05-bb-03）**：交易在一笔确认内原子提交，确认后不能撤回或退款，事件刷新时固定商品与定价并在事件存续期间内保持不变；商人按主营词条从对应物品池（术语表 T-084）随机选取经营内容，用规模基准值（术语表 T-099）衡量经营能力，回收商人反复收购同种物品消耗递增，批发回收商人（术语表 T-100）以较低价格换取消耗随量递减；
- **库存识别与存档时机（C-05-bb-03）**：物品识别范围由场合决定，战斗之外按全队识别、战斗过程中只调取自己身上的库存，装备栏槽位容器始终可识别；容器组件（术语表 T-078）通过即时取用（术语表 T-088）与嵌套调用许可（术语表 T-089）两个开关决定战斗取用资格与嵌套调用能力，嵌套容器以更零碎的空间换取携带容量；游戏只提供自动保存（术语表 T-016），在时间段推进与战斗轮次推进两类节点触发，局内进行中的交易、委托进度、押金（术语表 T-096）、落地物（术语表 T-106）与未领取奖励都不进入局末结算；

## 五、后续版本规划

本节是运营与经济域以及依赖其接口的系统的版本路线总表。规划的划分依据是 C-05-bb-01 信息缺口分析各版本中标记为延期的范围，以及 C-05-bb-02、C-05-bb-03 两轮裁定中明确暂不设计的部分。

### 5.1 阶段划分

| 阶段 | 包含内容 | 不包含内容 |
| --- | --- | --- |
| 当前版本 | 组件化物品与容器识别、单货币与付款、交易事件（术语表 T-097）的原子提交、商人供给与收购模型、委托生命周期、装备与遗物规则、全量保存与自动保存时机 | 行情内容与公式、仓库与银行、物品风险、复杂收纳 |
| 后续版本 | 行情字段与影响公式、商人原型与词条池的内容填充、装备获取的内容投放、委托完成率与星级评价的数值定义、市场行情的内容与公式 | 物品风险机制、复杂收纳玩法 |
| 远期版本 | 物品损坏与腐坏、耐久与偷窃、体积与重量、打捆与包扎与装瓶、塔科夫式空间管理、仓库与银行及支票存款 | 无 |

### 5.2 当前版本的完备范围

当前版本的运营闭环由以下已经定案的规则构成，可以作为功能需求拆分的依据：

- 所有物品共享元物品与组件架构，功能由组件提供，用途不互斥；
- 队伍已装备物品的容器组件构成背包空间，嵌套容器以更零碎的空间换取携带容量，装备栏槽位容器始终可识别；
- 物品识别范围按场合划分，战斗之外全队识别、战斗过程中只调取自己身上的库存，战斗取用由即时取用属性决定；
- 付款与交付按物品交付处理，交易在一笔确认内原子提交且不可撤回，事件内报价固定；
- 商人按主营词条从对应物品池选取经营内容，规模基准值逐次刷新浮动并因交易消耗；
- 委托以持续任务（术语表 T-095）承载，逾期与主动放弃同义，一次结算完成，奖励走统一装载与溢出流程；
- 装备由元物品加组件构建，获取途径归内容设计；遗物槽（术语表 T-111）可扩展，同名效果按效果强度方向（术语表 T-112）配置取最高；
- 存档执行全量保存与全量恢复，只在时间段推进与战斗轮次推进两类节点自动保存。

### 5.3 后续版本的开放条件

后续版本的每一项都有明确的开放条件，未满足条件前不进入设计：

| 项目 | 开放条件 |
| --- | --- |
| 行情内容 | 核心买卖闭环通过体验验证，需要行情为经营决策提供跨时间的变化依据；行情的生命周期与刷新接口已经在当前版本固定 |
| 商人原型内容 | 物品词条体系与物品池内容确定后填充 |
| 装备获取内容 | 关卡与内容策划确认投放边界后确定装备池与掉落路径 |
| 委托数值 | 数值模型完成完成率与报酬的数值定义 |
| 市场行情 | 行情字段与影响公式依赖体验验证；原市场情报接口随情报系统撤项一并取消，行情信息改由事件内的直接呈现承接 |
| 物品风险 | 体验测试确认需要提高损失感，并完成对应的内容量评估 |
| 复杂收纳 | 塔科夫式背包管理立项，与体积、重量、空间拼接一并设计 |
