## 1 系统定位

进度回溯机制：玩家在线索树（术语表 T-153）上对已解锁内容做选择性暂时封锁，自由调配与撤销，组合出想要的下一局游戏环境。与大关推进规则配合构成进度管理闭环。

## 2 设计依据（已确定内容摘录）

- 创意文档 §5.6：剪枝是对已解锁内容的选择性暂时封锁——选择节点剪除后，该节点及其全部下级节点、对应的道具、角色与支线进度一并进入封锁状态，下一局按这些内容未被解锁的状态开始；
- 创意文档 §5.6：剪枝过程可自由调配和撤销，可同时多处剪枝，组合出想要的下一局环境；
- 创意文档 §6.3：通过真结局（术语表 T-010）后新开一局默认以下一个大关（术语表 T-008）为起点，回顾更早进度通过剪枝系统定向回退；
- 创意文档 §11-5：剪枝是对已解锁内容的暂时封锁，可以自由撤销，可以多处同时进行；
- 交互逻辑 5：剪枝是对已解锁内容的暂时封锁，可以自由撤销，可以多处同时进行。

## 3 设计内容

### 3.1 封锁语义

被封锁的内容直接当作未解锁来处理，套用与未解锁完全相同的一套逻辑，因此剪枝在效果上等同于一次可撤回的进度回退。系统不为封锁单独定义一套不可用判定，避免逐类讨论带来的边界遗漏。

- 被封锁的节点在内容投放上等同于未解锁：不进入全局事件池（术语表 T-169）与物品池（术语表 T-084）的内容集合，不参与事件生成与内容抽取；
- 上游节点（术语表 T-159）被封锁后，下游节点的开放阈值判定按封锁后的状态重新计算，判定只统计处于解锁状态且未被封锁的上游节点；
- 已经解锁的下游节点保持已解锁状态，不回到锁定，解锁记录不被清除；
- 被封锁范围内的节点在树上与百科页（术语表 T-176）上标注为已封锁；
- 节点数据本身不被清除，解锁记录从不被剪枝删除，因此结构上不存在永久无法达成的节点；
- 剪枝可自由撤销，撤销后判定恢复，内容重新可用。

### 3.2 级联封锁范围

级联封锁取完整级联：封锁该节点及其在关系图上可达的全部下级节点，对应内容在本局一并不可用。级联范围以节点关系图为唯一依据，不引入内容依赖的额外计算。

大关回退是剪枝的一个预设组合：选择回退到大关起点等于对该大关的主干节点执行一次批量剪枝，回退同样可撤销，撤销后恢复原有封锁状态。主干节点可以被单独剪枝，单独剪枝主干节点时下游锁定节点（术语表 T-164）的判定按 3.1 的规则执行。大关进度标记不因剪枝改变，剪枝回答的是下一局从哪个大关开始游玩，不改变已经解锁到的大关记录。

### 3.3 操作规则

剪枝只在局外进行，操作对象是已解锁节点。玩家选中若干节点后一次性提交，提交前显示受影响范围摘要，确认后作为一次操作记录。

| 项目 | 规则 |
| --- | --- |
| 操作入口 | 线索树局外界面 |
| 可选对象 | 处于已解锁状态的节点 |
| 单次操作 | 一次操作可以包含多处剪枝，提交前显示受影响范围摘要，确认后作为一次操作记录 |
| 生效时点 | 提交后立即生效于下一局，局内不再改变跨局状态 |
| 生效内容 | 开新局时按当前封锁状态计算全局事件池的内容集合与内容可用范围 |
| 撤销粒度 | 以单次操作为粒度，撤销后恢复该次操作覆盖的全部节点 |
| 重叠封锁 | 跨多次操作出现重叠时，重叠部分的归属记为最后一次操作，撤销该次操作时重叠部分一并解除 |
| 封锁粒度 | 以节点为唯一粒度，不做内容级细粒度封锁 |
| 撤销的影响 | 撤销只回退封锁状态，不回退任何解锁写入 |

撤销剪枝不回退解锁写入的含义是：剪枝期间发生的解锁照常写入线索树，不因期间存在封锁而丢弃。存档保存封锁集合（术语表 T-167）与节点上的封锁标记（术语表 T-168），不需要支持任意节点的历史回退。玩家在封锁期间的解锁会保留，界面对此给出说明。

剪枝的写入与自动保存节点无耦合，因为剪枝不发生在局内；封锁状态属于跨局持久数据（术语表 T-052），随存档保存。

### 3.4 封锁标记的写入与一致性

提交剪枝时把封锁范围计算一次，结果作为节点的封锁标记写入线索树数据；撤销时按该次操作批量清除标记。打开线索树时按标记直接呈现，不需要重新计算级联范围。

同一份封锁语义存在两个来源：剪枝系统的封锁集合与节点上的封锁标记。两者不一致时以剪枝系统的封锁集合为准，节点标记按封锁集合重建。标记是封锁集合的派生结果，在开新局与撤销操作的提交点各校验一次，允许重建。

### 3.5 封锁状态的呈现

封锁状态下，节点的百科页内容保持可读，节点上标注为已封锁，条目不做隐藏。玩家可以继续查看已经获得的传闻（术语表 T-155），只是对应内容在本局不出现。封锁状态与文本库阅读状态互不影响，文本库（术语表 T-042）继续按全局范围判定阅读状态。

界面对"可读但不可用"这一状态给出明确表达，避免玩家误判为进度丢失。

### 3.6 剪枝预览面板

当前版本不设剪枝预览面板，只提供撤销能力。玩家通过尝试与撤销理解影响面，树上以视觉变化提示封锁范围。

操作前展示完整影响清单的预览面板列入后续版本开发。

### 3.7 自定义挑战模式

剪枝与种子组合的自定义挑战模式挂起，留到世界观定案与体验验证之后处理。当前版本剪枝只做进度回退与内容调控，种子只做本局环境扰动与一致性保证，两者不组合成可分享的挑战配置。

### 3.8 封锁影响面必须可见

封锁影响面必须在操作前或操作后可见，这是剪枝可用性的前提。当前版本以树上的视觉变化承担该要求，后续版本由预览面板承担。

## 4 交互逻辑与细节注意点

- 剪枝必须可自由撤销、多处同时进行（§11-5）；
- 被封锁的内容直接当作未解锁处理，套用同一套逻辑，剪枝等同于可撤回的进度回退，不设逐类不可用判定；
- 解锁记录单调递增，结构上不存在永久无法达成的节点；
- 级联封锁取完整级联，范围以节点关系图为唯一依据；
- 大关回退是剪枝的预设组合，可撤销，不改变大关进度标记；
- 剪枝只在局外进行，提交前显示受影响范围摘要，确认后立即生效于下一局；
- 撤销以单次操作为粒度，重叠封锁以最后一次操作为准；
- 撤销不回退解锁写入，封锁期间的解锁保留；
- 封锁标记在提交时写入节点数据，读取时不重算；标记与封锁集合不一致时以封锁集合为准；
- 封锁节点的百科页保持可读，条目隐藏属于越界做法；
- 当前版本不设预览面板，封锁影响面由树上视觉变化与提交前摘要共同承担。
