### 阻止完整通过的发现

**F1 / P2：Debug Panel“切换纹理”在当前角色结构中无实际切换效果。**

位置：`Assets/Script/Debug/DebugPanel.cs:229`。候选图仅来自当前 Player 及子对象的 SpriteRenderer；当前 Player 只有一个渲染器，无子对象，因此最多收集一张图。实测先赋 BodyWalkDown_0，再连续两次调用面板同一处理器，前后均为 BodyWalkDown_0。若在空纹理时先调用，还会缓存空候选数组。记录中“赋值后可用于切换”不能由当前实现满足。建议为面板提供至少两张明确候选图或可选择纹理的入口，并允许候选刷新。未自动化鼠标事件，本结论由实际面板处理器和候选采集源码共同支持。

**F2 / P2：重复 TryBind 会把组件设置的坐标退回过期的预置坐标。**

位置：`Assets/Script/MetaObjects/MetaObjectPreset.cs:191`。实测调用 `preset.SetCell((8,-4))`，再调用 `coordinate.SetCell((9,-4))`，此时已位于 `(9,-4)` 中心；随后调用公开入口 `preset.TryBind()`，坐标与位置退回 `(8,-4)`。原因是 `hasExplicitCell / explicitCell` 仍保存旧预置值，重复绑定又把它写入坐标组件。两个入口都在既有交付记录中被列为下游可用入口。建议首次绑定才消费暂存坐标，已绑定时保留组件当前状态。

**F3 / P2：自检对零个目标仍报告 PASS。**

位置：`Assets/Editor/MetaObjectVerification.cs:64`。运行时销毁唯一临时验收目标后再次自检，输出 `METAOBJECT_VERIFY PASS：共检查 0 个元对象预置，失败 0 项`。缺失目标无法形成任务功能通过的证据。建议零目标输出 FAIL / SKIP，或接受预期目标数量 / 标识并核对。

### 扩展边界风险

**R1：已绑定实例替换组件不会自动绑定新组件。** `MetaObjectInstance.AddComponent` 在替换时解除旧组件、只 Attach 新组件。实测 `preset.IsBound=True`、新坐标组件 `IsBound=False`，调用新组件 SetCell 不再移动对象。若该 API 只允许绑定前调用，应明确限制或拒绝；若允许运行时替换，需要同步新组件的场景绑定。当前初始配置流程无此问题，作为下游组合能力风险列出。

**R2：同一个组件对象可被两个实例同时收录。** A.AddComponent(c)，B.AddComponent(c)，随后 A.Dispose()；B 的字典仍含 c，但 c.Owner 已被清空。建议拒绝已归属其他实例的组件，或执行完整迁移协议。该用例不影响当前定义工厂每次创建新组件的成功路径，属于公共入口防错缺口。

**O1：禁用预置不会自动解除组件绑定。** 原始探针把“禁用即解绑”写为一个失败断言；复核后，现有契约没有明确要求禁用时解绑，故本报告将其归为观察项，不作为缺陷或验收阻断。原始探针及输出保持原样，避免改写证据。
