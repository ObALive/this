## 1. 任务目标

任务书三行要求：任务规范见 `Rules/` 目录；工作区已存在架构设计文档与系统设计文档；依据规则规范构建一版代码设计文档。

执行前向用户确认三项范围，构成本任务的实际目标：

1. **编制范围**取「已有架构设计文档与系统设计文档的并集」，即设计库 32 个系统加架构设计案 2.5.2 的 11 个架构新增单元；
2. **缺少上层指导或存在未解缺口的内容不自行补写**，编制需求申报文档交对应文档管理者补充；
3. **索引建在 `Code_Design/README.md`**，并授权本轮一并修订 `Rules/06_代码设计案编辑规范.md` 第十二章登记该格式。

## 5. 执行过程

### 5.1 规范适用清单

按 `Rules/README.md` 四步判定：任务书信号词为「代码设计文档」「架构设计文档」「系统设计文档」「规则规范」。

| 常需追加 | NR-07（架构约束与分工）、NR-04（`Rules/` 写入流程） |
| 追加阅读 | NR-06 §五、§六、§八、§九、§十一、§十二、§十三；NR-07 §六；NR-05 §七；NR-04 §三、§四 |

### 5.2 认识现有内容

通读 `架构设计文档/架构设计案.md` 全篇（1551 行）、架构设计决策记录、`系统设计文档/README.md` 与 `00-总览` 库级四表、样例系统设计稿（01-50、02-10、01-60、09-20、05-40）、`Code_Design/README.md`；核对 32 份上游设计稿全部存在、域目录命名与设计库一致。

### 5.3 范围落定

- **单元清单 43 个**：设计库 32 个系统（含 1 个远期占位）加架构案 2.5.2 的 11 个架构新增单元；服务容器是 M01 的模块成员，作为顶层对象载于 M01 文档，因此 43 个单元落在 **42 份文档**上。
- **落点**：设计库系统落 `Code_Design/{域编号}-{域名}/`，架构单元落 `Code_Design/00-架构单元/`，文件名与编号沿用设计库与架构案。
- **分工**：系统文档定义本系统的对象与接口；模块单元文档写模块级契约并引用成员系统的 ID，二者不重复定义同一对象。

### 5.4 约定与工具落盘

`Output/CO01-初步构建代码设计文档/` 下落盘编制约定（43 单元清单、单元码与 ID 命名空间、跨单元公共能力 ID 表 66 项、分工、事件词表、缺口八项格式）、三份执行体任务书（编制／核对／修订）、四支脚本（机械核对、索引生成、缺口抽取、ID 回填）。

### 5.5 规范登记

按 NR-04 流程：留档原件（`留档/06_代码设计案编辑规范_v0_2026-10-06.md`，校验值一致）→ 修订 `Rules/06` §十二（目录结构补 `00-架构单元/` 与子系统条款、元信息表补架构单元取值、第 5 节索引条改为指向新增第 7 节「索引」，索引落点定为 `Code_Design/README.md` 并给出七列与三条维护要求）→ 在 `Rules/README.md` 变更记录登记 v7。

### 5.6 编制波次

先编 M01 与 01-50 两份样例校准分工与写法，再按架构案 6.3 的初始化顺序分八波推进其余 40 个单元；每份落盘后跑一次机械核对，落盘即释放执行槽位并补发下一单元。42 份全部落盘，状态：草稿 39、占位 3（01-60、05-40、09-20 的上游设计稿为占位或远期占位）。

### 5.7 独立核对

按模块与域分八组只读核对，逐份出 findings（severity／location／problem／fix）。结论：无 fail 项遗留，must 项集中在跨文档口径冲突——行情写入方（M02 与 M04）、时间推进口径（02-30 自建记账与 02-10 冲突）、事件进入方向（M02 与 M10 相反）、结局成立与结算完成的发布方、元效果契约落点（06-75 与 M09）、物品变更事件发布方（06-80 与 M04）。

### 5.8 修订与回填

按同一分组派八个修订执行体落实 findings：跨文档冲突一律按架构案条文裁定，架构案未明确规定的把两侧改成一致表述并按约定 §八追加八项缺口条目，不两边各写一套。同步完成 ID 回填：`{名称}（{单元码}，ID 待补）` 形式的引用共回填 400 余处，残余为提供方尚未登记的能力（如表现通道、界面配置字段类读取），已列入需求申报。

### 5.9 收口核对

机械核对最终结果：42 份文档十节结构齐备、元信息八项齐备、无跨文档 ID 重复、**全部被引用 ID 都有定义方**；全库唯一 ID 合计 806 个（SYS 43、CLS 303、API 460），API 契约块 392 个，总行数 25,519 行。残余提示仅两类且属合规标注：17 份文档保留「ID 待补」（提供方未登记，共 60 余处）、3 份文档保留【待架构登记】事件（单位位置变化、事件内时间推进）。
