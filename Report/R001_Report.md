## 1. 任务目标

按任务书的核心指导理念与两条工作方向对现行系统设计做精简：把游戏过程中涉及剧情和演出的部分全部去除，专心设计肉鸽游戏玩法；彻底移除自由探索阶段的设计，事件之间的动作改为在地图上点击事件来开始；把事件由多个事件片段组合降维为一个独立单元，砍掉事件内的对话与交互环节并保留事件结果设计。

任务书同时限定交付方式：不改动任何设计文档，把发现的修改意见按 `Tool/缺口决策系统` 的规范呈报，并启动填写器供总监审阅。第一轮按此交付；第二轮由总监指令授权后，直接在 Design 文档中落实修改。

## 2. 任务书摘要

| 项目 | 内容 |
| --- | --- |
| 任务背景 | 游戏的系统设计过于复杂，需要精简 |
| 核心指导理念 | 去除剧情与演出部分，专心设计肉鸽玩法，简化游戏内容 |
| 工作方向一 | 彻底移除自由探索阶段的设计，事件之间的动作全部依靠在地图上点击事件来开始，节约场景设计开销 |
| 工作方向二 | 降维事件结构，一个事件就是一个独立单元，事件内的对话与交互环节砍掉，事件结果设计保留 |
| 工作方法一 | 详读 `Design/` 目录下的策划文档，对已有游戏内容有充分理解 |
| 工作方法二 | 任务中提到的术语在 Design 文档中找解释 |
| 工作方法三 | 不改动原文档，把修改意见按缺口决策系统的规范呈报，然后启动填写器供审阅 |
| 第二轮指令 | 本轮决策已落地，确认无误后直接在 Design 文档中落实修改；除回退操作外不要动 git |

## 5. 执行过程

1. 读取任务书与 `Rules.md`，确认授权范围为只读分析加缺口呈报，全过程未修改任何既有设计文档。

## 12. 文案复核（第三轮）

### 12.1 复核要求与范围

总监指令要求策划书直接陈述当前版本的设计状态，不出现表示版本沿革的措辞，并以 `00-总览/01_设计原则与跨系统交互逻辑.md` 中的「降维」一词为例。复核范围为第二轮改动的全部 55 份文件。

复核方式为逐份人工比对版本库基线与当前内容，先读改动内容再逐句判断语义，不依赖关键词检索定位问题；关键词扫描只用于最后确认有无遗漏。

### 12.2 判定标准

区分两类表述：

- 游戏内的状态变化属于设计内容，予以保留，例如区域形态随事件结果转变、事件状态迁移、物品归属改变、剪枝封锁与撤销、落地物随本局结束废弃、本次事件与本次战斗一类的当次实例指代；
- 设计本身的沿革不属于设计内容，予以清除，包括世界地图降维、系统更名、条款撤销或移除、结构升级、玩法退化、以「原」「本次」「不再」「取代」「修订」指代前后版本等写法。

来源标注属于库内既有惯例，予以保留，例如依据栏与设计依据中的任务编号与裁定编号引用。
