## 1. 任务目标

按任务书的核心指导理念与两条工作方向，对现行游戏系统设计做精简分析：把游戏过程中涉及剧情和演出的部分全部去除，专心设计肉鸽游戏玩法；彻底移除自由探索阶段的设计，事件之间的动作改为在地图上点击事件来开始；把事件由多个事件片段组合降维为一个独立单元，砍掉事件内的对话与交互环节并保留事件结果设计。

任务书同时限定交付方式：不改动任何设计文档，把发现的修改意见按 `Tool/缺口决策系统` 的规范呈报，并启动填写器供总监审阅。

## 2. 任务书摘要

| 项目 | 内容 |
| --- | --- |
| 任务背景 | 游戏的系统设计过于复杂，需要精简 |
| 核心指导理念 | 去除剧情与演出部分，专心设计肉鸽玩法，简化游戏内容 |
| 工作方向一 | 彻底移除自由探索阶段的设计，事件之间的动作全部依靠在地图上点击事件来开始，节约场景设计开销 |
| 工作方向二 | 降维事件结构，一个事件就是一个独立单元，事件内的对话与交互环节砍掉，事件结果设计保留 |
| 工作方法一 | 详读 `Design/` 目录下的策划文档，对已有游戏内容有充分理解 |
| 工作方法二 | 任务中提到的术语在 Design 文档中找解释 |
| 工作方法三 | 不改动原文档，把修改意见按缺口决策系统的规范呈报，然后启动填写器供审阅 |

## 5. 执行过程

### 5.1 任务启动与授权确认

读取任务书与 `Rules.md`，确认任务授权范围为只读分析加缺口呈报，未获得改写 `Design/` 的授权，因此全过程未修改任何既有设计文档。确认输出落点为 `Output/R001/` 与 `Report/R001_Report.md`。

### 5.2 阅读缺口决策系统的规范文档

读取 `建库说明.md`、`读库说明.md`、`迭代使用说明.md` 与 `Output/C-06-bb-01/决策库结构规范_v1.md`，确认四表一视图的数据契约、候选写法四条规则、每项缺口 2 至 3 条互斥候选的要求、填写器的接口约定，以及一轮提问到归档收口的五步流程。

### 5.3 详读现行设计文档

通读 `Design/` 下的四份总览文档、七个域的索引与 26 份系统设计文档、13 张扩展配置表。任务书提到的术语在 `00-总览/02_术语表.md` 中逐条查证，重点确认事件、时间段、入口开放窗口期、日程、日程表、事件状态、事件流程、事件属性配置、事件片段、即时反馈行动状态、战斗片段、片段类型表、触发方式、场景变化包装事件、强制事件、区域形态、事件内时间检查点、自由探图阶段、自由移动、基点、活动范围与信息揭露列表等术语的定义位置与现行取值。

### 5.4 判定改动面

按两条工作方向把全库命中项分为直接失效、需改写与需新增规则三档，并归并为三个受影响设计面。判定结果：直接失效约 60 条，需改写约 75 条，需新增规则约 35 条，分布在 7 个域 26 份设计文档与 6 张扩展配置表中。

判定中确认了三处传导最远的环节。其一，区域形态的定义在探索系统，职责在概率池联动与局生成，共九处引用，未裁定前概率池联动的整节与局生成的窗口期参数都无法改写。其二，事件片段被事件与战斗的接口、界面属性的挂载层、单局存档的状态项与交易委托的多轮操作四处借用，取消片段会同时打断四条链。其三，事件结果记录的字段必须在存档层先定义，否则节点解锁判定、委托完成率、隐藏关底事件阈值与剪枝支线进度四处无据可依。

### 5.5 归并缺口

把同类命中归并为 18 项缺口，分三轮组织。第一轮 7 项骨架缺口决定结构存废；第二轮 10 项配套规则缺口处理骨架确定后的规则重定义；第三轮 1 项治理缺口处理停用术语、交互逻辑条目与决策登记的同步方式与时机。每项缺口给出 2 至 3 条互斥候选，候选正文按规则是什么、适用范围、状态变化与既有系统衔接四件事撰写，并附代价与影响。

### 5.6 建库与校验

把缺口与候选写成 `Output/R001/R001_建库数据_v1.json`，用建库入口生成决策库。自检结果：必需表与视图齐备，引用完整性 ok，外键错误 0，缺口 18 项，候选 54 条，自定义预留行 18 条，裁定 18 条且全部为待裁定，候选数量异常 0 项，推荐数量异常 0 项，空正文 0 项，孤儿候选 0 项，problems 为空。随后用 `decision_db.py --check` 独立复核，结果一致。

### 5.7 导出与启动填写器

导出候选清单与作答模板两份只读派生文件。启动填写器并验证：首页、前端脚本与样式表均返回 200，`/api/questions` 返回 18 项缺口，`/api/export` 正常返回 Markdown 裁定结果。
