## 5. §5.3 类文件匹配与命名风格 —— 逐条方案（N 系列）

> 每条含：问题出处 / 改动内容（原名→新名、位置）/ 代码引用点 / 序列化资产影响与措施。资产级逐键核对单见附表 03。

### N-01（5.3-R6）`onDestroy` → `OnDestroy`（P0-1 必修）
- 位置：`Singleton.cs:20` 方法声明（含方法体 2 行）。子类（InventoryManager、ItemManager）均未重写，直接改名即可。
- 措施：改名 + 把 `instance == this` 修为 `instance == (T)this`（类型安全，不改行为）。建议同时采纳 N-10A。
- 影响：无序列化影响；修复"对象销毁后静态 instance 不置空"的运行时缺陷（P0-1 定性为拼写错误修复）。

### N-02（5.3-R2）`toDestory` → `toDestroy`
- 位置：`InventoryManager.cs:27` `AddItem(Item item, bool toDestory)` 参数及方法体 :31 判断。调用点 `ItemPickup.cs:16` 为位置实参，无需修改。

### N-03（5.3-R3）组件引用结构体整组改名
- 原状：`ItemDetails` 内嵌套 `struct component { int componentID; ScriptableObject componentConfigs; }`，字段 `componentConfigs: List<component>`（DataCollection.cs:34-37）。
- 新状：类型提级为同文件顶层 **`ComponentRef`**；成员 → **`ComponentID`**、**`ConfigAsset`**；ItemDetails 字段 → **`ComponentRefs`**；三处均加 `[FormerlySerializedAs]`（旧键 `componentConfigs`/`componentID`/`componentConfigs`）。
- 代码引用点（全部）：`InventoryManager.cs:80` 方法签名 `CreatInventory(List<component>)` → `List<ComponentRef>`；:84 `c.componentConfigs is InventoryComponentData_SO` → `c.ConfigAsset is ...`；:91 `targetComponent.componentID` → `targetComponent.ComponentID`；:43 `itemDetails.componentConfigs`（WearInventory 实参）随字段改名；注释版（:49-78）随 X-04。

## 6. §5.4 编码问题 —— 方案（E 系列）

## 10. 风险与注意事项

1. **不要**在资源管理器只移动文件/目录而不带 .meta；**不要**用文本编辑器改名后另存为其它编码（GBK 文件先转 E-01 再编辑）。
2. `[FormerlySerializedAs]` 只能迁移"直接序列化字段"，对 prefab 覆盖 propertyPath 不保证生效（N-05A 红色清单已单列措施）。
3. 枚举改名只允许改类型名/成员名，**严禁改值序**（资产以 int 存储）。
4. 采纳 N-05B（private 化）会立即击穿 ItemEditor 反射绑定，须与 §7.5 编辑器重做同批，否则编辑器不可用。
5. 类改名/文件改名后**立即编译**并抽查场景，发现 Missing Script 时先查 .meta 是否成对，勿手动改 GUID。
6. 本任务只产出方案文档；执行 Assets 改动前请先 `git commit` 存档（阶段 0 同款建议）。
