## 1. 任务目标

阅读并归纳 `Task/06-任务规范增加.md`，为 `Rules/` 目录新增一份代码设计案的编辑规范。代码设计案的位置为工作区根目录下的 `Code_Design/`。

## 2. 任务书摘要

任务书是一份 900 行的规范设计稿，给出代码设计案的完整定义与模板。归纳为十四节：

| 节 | 内容 |
| --- | --- |
| 一 | 各文档职责划分，重点是系统设计稿与代码设计案的分界 |
| 二 | 代码设计案的精确定义：以系统设计稿为输入、以伪代码与编码为下游的程序设计规格 |
| 三 | 真正功能边界：规定必须有什么、负责什么、接受什么、产生什么、依赖什么，不规定每一步怎么算 |
| 四 | 不负责什么：具体算法、具体语法、重新解释游戏规则 |
| 五 | 基本单位是系统而不是类 |
| 六 | 系统实现契约与系统章节的结构 |
| 七 | 外部依赖表 |
| 八 | 依赖对象索引与唯一 ID |
| 九 | 输入输出的四类划分 |
| 十 | 功能要求与程序实现要求分开 |
| 十一 | 标准章节模板 |
| 十二 | 验收标准：系统独立实现完备性 |
| 十三 | 与伪代码的分界 |
| 十四 | 整套文档体系的关系，架构设计稿是横向约束 |
