## 1. 怎么用这份清单

每条场景给出五项已定信息 + 一栏待补：

| 列 | 含义 |
| --- | --- |
| 编号 | 场景坐标。界面场景 `UI-{界面号}-{序号}`；跨界面通用层 `UX-{序号}`；系统→玩家 `SYS-{序号}` |
| 交互场景 | 玩家与系统之间发生了什么 |
| **详细操作序列（待补）** | **由你补齐**：点哪里、先后顺序、界面反馈与提示 |
| 提交点与粒度 | 该操作在什么时候、以什么粒度提交；空白表示不改变游戏状态、无提交点 |
| 系统侧落点 | 读/写经过的接口或对象；`→` 表示写入路径 |
| 依据 | 该场景的权威出处，补齐时按此列核对 |

**补齐时的两条硬约束**（架构案 §8.4 第 5 条、§3.4 第 3 项）：界面只读取状态、只提交意图与命令，不得直接修改数据；操作序列里出现的每一次状态变化都必须落到「系统侧落点」列已有的接口上，找不到接口即为缺口。
